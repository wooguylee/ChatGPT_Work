## 2. MNN-Pocket은 별도 소형 사전학습 계열

### Qwen 설계 재사용과 직접 checkpoint 파생을 구분

[공식 기술 보고서 pp.4–5](https://huggingface.co/taobao-mnn/MNN-Pocket-0.3B/resolve/main/MNN-Pocket-0.3B-Technical-Report.pdf)는 dense Qwen3 설계를 여러 깊이·폭으로 탐색해 **28층·hidden 896**을 선택하고, Qwen3 tokenizer를 약 151K에서 **65,536**으로 줄였다고 설명한다. Qwen3의 구조·tokenizer를 재사용한다는 점을 먼저 인정한다.

선정의 근거는 이름이 색인에 없다는 사실만이 아니다. 같은 보고서 **p.6 Figure 3·p.8 Table 1**에 별도 사전학습 **3T + 800B + 200B + 100B = 약 4.1T tokens**, 4,096→32,768 문맥 확장과 단계별 데이터 구성이 제시돼 있다. 기존 Qwen3.5·Qwen3.8 가중치의 포맷 변환이나 경미한 작업별 fine-tune으로 설명되는 배포가 아니다. 다만 **최초 가중치 초기화 경로는 명시적으로 확인하지 못했으므로 전 구성요소 from-scratch라고 주장하지 않는다.**

[공식 config](https://huggingface.co/taobao-mnn/MNN-Pocket-0.3B/blob/main/config.json)는 Qwen3ForCausalLM, 전층 full attention, query 14개/KV 2개, head dimension 64, FFN 2,560과 tied embeddings를 지정한다. Qwen 실행 구현과의 호환성을 Qwen의 새로운 공식 세대라는 뜻으로 바꾸지 않는다.

[Base 카드](https://huggingface.co/taobao-mnn/MNN-Pocket-0.3B-Base)는 분야·품질·난도·정보 밀도·문체를 함께 탐색하는 데이터 recipe를 설명한다. 기술 보고서 pp.8–10의 후학습은 약 **3.16M SFT 샘플**, 분야별 네 RL teacher, 라우팅 기반 on-policy distillation과 W4A16 QAT 자기 증류로 이어진다. 제작자가 보고한 학습 과정이며 독립 재현 결과는 아니다.

Base·SFT·일반 지시 모델·Dec·GGUF·MNN 양자화 배포를 **한 계열**로 묶는다. Dec의 LoRA·pointer head도 별도 신규 수로 세지 않는다.

**태그:** text-generation, small-language-model, on-device, GQA, pretraining, distillation, quantization-aware-training, en, zh.

### 활용 예와 장치 평가

[공식 카드](https://huggingface.co/taobao-mnn/MNN-Pocket-0.3B)의 Transformers 경로를 짧은 비민감 추출 작업으로 바꾼 **미실행 예시**다. 검토한 환경·의존성·가중치를 준비한 뒤 사용한다.

~~~python
from transformers import AutoTokenizer, AutoModelForCausalLM

model_id = "taobao-mnn/MNN-Pocket-0.3B"
revision = "e9c7adc23990ff3a0b3ff713c39470af40202d4a"
tokenizer = AutoTokenizer.from_pretrained(model_id, revision=revision)
model = AutoModelForCausalLM.from_pretrained(model_id, revision=revision)
messages = [{
    "role": "user",
    "content": 'Extract only item and quantity as JSON: "Please prepare three blue notebooks."'
}]
text = tokenizer.apply_chat_template(
    messages, tokenize=False, add_generation_prompt=True
)
inputs = tokenizer(text, return_tensors="pt")
outputs = model.generate(**inputs, max_new_tokens=128, do_sample=False)
print(tokenizer.decode(
    outputs[0, inputs["input_ids"].shape[1]:], skip_special_tokens=True
))
~~~

JSON 파싱 성공과 실제 item·quantity 정답을 따로 채점한다. 빠른 생성만으로 추출 정확성을 보장하지 않으며, 실제 구매·파일 변경 같은 행동은 연결하지 않는다.

공식 배포 문맥은 **32K**이며 config의 40,960 positions를 40K 품질 보증으로 확대하지 않는다. **INT4 173MB는 배포 크기이지 실행 RAM 총량이 아니다.** iPad M5 Metal의 466 tok/s는 짧은 512-token 조건의 제작자 측정이다. 장문 KV cache, 첫 토큰 지연, 배터리·발열, 다른 장치 성능은 별도 평가해야 한다. 중국어·영어 중심이며 한국어와 최소 RAM은 미검증이다.

## 3. LongCat-2.5는 텍스트 경량판의 크기 변형으로 세지 않음

### 기존 등록 계열과 달라진 시각 경로

색인에 있는 [LongCat-Flash-Lite-Sparse](https://huggingface.co/meituan-longcat/LongCat-Flash-Lite-Sparse)는 공식 69B/약 3B active의 텍스트 모델이며 Flash-Lite의 MLA를 sparse 경로로 바꾼 계열이다.

[11/02 Meituan 공식 발표](https://tech.meituan.com/2026/11/02/Meituan-LongCat-2.5.html)는 2.5가 LongCat-2.0을 기반으로 원해상도 시각 특징을 다층 이산 토큰으로 표현하고, SAE·RVQ 기반 시각 codebook embedding을 본체와 함께 학습한다고 설명한다. 장기 agent 궤적·대규모 RL·다중 전문 teacher 학습도 포함된다. 따라서 기존 텍스트 경량판의 단순 대형화·양자화가 아닌 **주요 시각 입력·학습 확장 분기**로 판정한다.

[실제 config](https://huggingface.co/meituan-longcat/LongCat-2.5/blob/main/config.json)에는 활성화된 visual encoder와 **8단계·codebook size 16,384·dimension 3,584**의 residual quantizer가 있다. **1.6T라는 크기나 새로운 버전명만을 신규성 근거로 삼지 않는다.** LongCat-2.0·Next에서 가져온 계보를 인정하며, 2.5 전체의 독립 from-scratch 사전학습이나 2.0 대비 모든 구조가 새롭다고 주장하지 않는다. 정확한 초기화 checkpoint·전체 학습 토큰 수는 미확인이다.

**태그:** image-text-to-text, multimodal, mixture-of-experts, discrete-visual-tokens, agentic-coding, long-context.

### 활용 예와 배포 한계

[공식 카드의 배포 절](https://huggingface.co/meituan-longcat/LongCat-2.5#deployment)은 NPU용 **SGLang-FluentLLM** 경로를 안내한다. 일반 개인 GPU에서 표준 Transformers 한 줄로 실행된다고 안내하지 않는다. 최소 장비·실제 메모리·한국어 품질은 이번에 검증하지 않았다.

활용 예는 직접 만든 비민감 UI 스크린샷과 짧은 코드에 **“화면의 버튼 배치와 코드의 차이를 근거 위치별로 적고, 파일을 변경하지 말고 수정안만 제안하세요”**라고 요청하는 것이다. 정답 화면·DOM과 대조해 시각 이해 오류와 코드 오류를 나누어 채점한다. 이것은 실행 결과가 아닌 평가 설계다.

공식 OpenAI 호환 요청 예시는 chat_template_kwargs의 **enable_thinking**과 **save_history_reasoning_content**를 사용한다. thinking 모드의 다중 턴에서는 공식 응답의 reasoning_content·tool_calls 보존 방법을 따른다. 도구 호출을 반환한다는 사실이 실제 외부 행동 권한을 의미하지는 않는다.

config의 max_position_embeddings는 **524,288**이며 일부 공식 benchmark는 1M 설정을 쓴다. 설정값·실험 문맥·실제 서비스 한도를 구분하고 모든 장문 입력에서의 정확성을 보증하지 않는다. 카드의 Terminal Bench v2.1 **88.4**는 제작자 평가이며 다른 출처의 점수와 harness가 섞인 표다. 같은 조건으로 검증한 독립 순위가 아니다.

## 4. 제외 및 보류 업데이트

아래는 오늘 신규 소개·색인 추가 대상이 아니다.

- **[S5-nano](https://huggingface.co/maritaca-ai/S5-nano): 직접 전문화 제외.** Maritaca AI 카드가 Qwen3.5-4B의 continued pretraining→post-training을 명시한다. 공식 4B·Apache-2.0 표기이며 브라질 포르투갈어 성능·Think/Instruct·MTP·FP8/GGUF만으로 독립 구조 세대로 세지 않는다. 정확한 전체 tensor 수·최초 가중치 공개일은 이번에 확정하지 않았다.
- **[Axion-1.0-35B](https://huggingface.co/Axion1-0/Axion-1.0-35B): 직접 후학습 파생 제외.** [공식 논문 §4.1](https://arxiv.org/html/2611.03233v2#S4.SS1)은 Qwen3.6-35B-A3B 초기화, 두 SFT 단계와 GRPO를 명시한다. 공개 recipe의 연구 가치와 별개로 주요 구조 변경 근거가 없어 신규 수에 넣지 않는다. 카드의 Apache-2.0·약 35B/3B active는 제작자 표기다.
- **[Sophon-Realtime](https://github.com/adventists-ai/sophon-realtime): 엄격한 계보 판정 보류.** Tag·Flash·E2E가 같은 32B thinker를 공유한다. [Tag NOTICE](https://github.com/adventists-ai/sophon-realtime/blob/main/tag/NOTICE)는 Qwen3-VL·Qwen3-ASR·DuplexJev와 CosyVoice3 파생·tag-writing adapter·flow 증류를 명시한다. Tag 결합·배포를 독립 새 백본으로 세지 않으며 E2E의 주요 구조·학습 차이는 추가 검증이 필요하다. 프로젝트의 Apache-2.0 표기와 [선행 DuplexJev-32B-Para 카드](https://huggingface.co/adventists-ai/DuplexJev-32B-Para)의 CC BY-NC 4.0 조건 관계도 독립 확인하지 못했다. 전체 파라미터 합계·최초 공개일 미확인이다.
- **[Underdog-Woof](https://huggingface.co/ConwayResearch/Underdog-Woof): 초기화 계보 보류 유지.** 영어 고정 2음성·공식 38.24M·Mimi decoder 재사용을 확인했다. 오늘은 [LICENSE 전문](https://huggingface.co/ConwayResearch/Underdog-Woof/blob/main/LICENSE)도 확보했다. 비상업 허가·표시 의무, 회사 내부 이용을 포함한 상업 사용의 별도 허가, 다른 음성 모델 학습 제한이 있다. 작은 다운로드와 제작자 WER만으로 독립 신규 계열 보류를 해제하지 않는다.
- **FLUX 3 Image Klein·P-H3-Image·Sulphur-3:** [11/07](2026-11-07.md)·[11/05](2026-11-05.md)의 동일 계열·직접 파생 제외를 유지한다. [FLUX Comfy 카드](https://huggingface.co/black-forest-labs/flux-3-image-klein-comfy)는 재포장을 명시하고, [P-H3 카드](https://huggingface.co/PrunaAI/P-H3-Image)·[Sulphur 모델 트리](https://huggingface.co/FusionCow/Sulphur-3)는 MiniMax-H3 계보를 보여준다. 조건 수락·gated 파일 접근은 하지 않았다.

어제 소개한 P-JiT·Mirage와 기존 Kimi·Ripple·ERNIE·Haas·RelayVSR·LFM3 등의 양자화·포맷 변형도 재등록하지 않는다. 위 후보의 오늘 수정 시각을 출시일로 대신 쓰지 않는다.
