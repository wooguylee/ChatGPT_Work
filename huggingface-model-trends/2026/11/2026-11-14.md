## 2. Haru는 단순 Qwen 대화 fine-tune과 무엇이 다른가

### 기존 가중치 계보를 인정한 신규성 판정

[공식 모델 카드](https://huggingface.co/higurashi-ai/Haru-4B/blob/8d6e83bcd3701a76fc27a764965665da1df7da78/README.md)는 **Qwen3.5-4B text backbone**과 **VibeVoice acoustic tokenizer** 재사용을 명시한다. 독립 from-scratch 언어 백본이나 Qwen의 새 공식 세대가 아니다. 기존 색인에 VibeVoice-ASR·여러 Qwen 파생 음성 모델이 있다는 사실도 무시하지 않는다.

선정 이유는 이름이 없어서가 아니라 **동기화된 음성 입출력 구조와 그 구조를 학습하는 방식의 큰 변경**이다. [배포 config](https://huggingface.co/higurashi-ai/Haru-4B/blob/8d6e83bcd3701a76fc27a764965665da1df7da78/config.json)와 [공식 모델 구현](https://github.com/higurashi-ai/Haru/blob/main/haru/haru/models/haru.py)을 확인했다.

- 언어 모델은 **32층·hidden 2,560**, linear/full attention 3:1 구성을 사용한다. 이 기존 Qwen 구성 자체를 신규성으로 세지는 않는다.
- 사용자 음성·모델 음성은 **각각 별도 AudioProjector**를 거쳐 텍스트 embedding과 같은 위치에서 더해진다. 말하기를 끝낸 뒤 듣는 ASR→LLM→TTS 직렬 호출이 아니다.
- 24kHz 음성 **3,200 samples = 약 133ms**를 64차원 연속 latent 한 개로 처리한다. 초당 **7.5개 frame**이며 이산 codebook 여러 개를 순서대로 생성하는 방식과 구분된다.
- [MeanFlow head 구현](https://github.com/higurashi-ai/Haru/blob/main/haru/haru/models/meanflow_head.py)은 LM hidden state를 조건으로 4층 MLP의 평균 속도를 예측한다. config 기본값은 **1 sampling step·guidance 1.5**다.
- 출력 텍스트는 공유 embedding으로 계산하고 음성은 별도 head·codec으로 복원한다. 전체 음성 파이프라인의 새 입력·출력 경로가 실제 공개 코드에 있다.

[11/13 공식 기술 글](https://blog.higurashi.ai/melte/haru4b/)은 **4천만 시간 이상 실제 음성**, ASR·음성/텍스트 이어쓰기·text rehearsal의 첫 단계와 **1,300만 시간 이상 분리된 duplex 대화**의 둘째 단계를 설명한다. 두 수치를 더해 5,300만 고유 시간이라고 쓰지 않는다. Flow Matching 후 MeanFlow 증류, 최대 60분 대화 학습도 설명한다. 이는 제작자 보고이며 데이터 권리·학습 실행을 독립 감사한 결과가 아니다. 상세 학습 코드·보고서는 향후 공개 계획이므로 완전 재현 가능하다고 주장하지 않는다.

이 근거에 따라 **주요 음성 모달리티·학습 확장 예외**로 한 계열을 소개한다. 기존 Realtime-Venus나 VibeVoice-ASR의 단순 양자화·크기 변경으로 판정하지 않는다. 같은 Haru 가중치의 PyTorch·MLX·vLLM-Omni 경로는 별도 신규 모델로 나누지 않는다.

**태그:** audio-to-audio, speech-to-speech, full-duplex, continuous-audio, MeanFlow, multilingual, base-model, research, ko.

## 3. 실무 활용 예: 한국어 대화의 끼어들기·응답 지연 평가

먼저 본인 또는 명시적으로 동의한 화자의 깨끗한 참조 녹음과 비민감 테스트 대화를 준비한다. 정해진 숫자·날짜·영문 혼합 문장을 읽고, 응답 중 짧게 끼어들거나 침묵을 둬 아래 항목을 따로 측정한다.

1. 발음·문장 누락·반복과 사실 오류.
2. 사용자가 말하는 동안 잘못 끼어드는 빈도, 종료 후 불필요한 대기.
3. 마이크 입력부터 실제 음성 출력까지의 지연, 장시간 메모리 증가.
4. 동일 음성·기기 조건에서의 재현성. 자연스러운 타이밍과 정답률을 한 점수로 섞지 않는다.

검토한 코드·의존성·가중치를 준비한 뒤의 **미실행 로컬 예시**다.

~~~bash
python -m haru.server --hf-repo higurashi-ai/Haru-4B
~~~

[공식 실행 안내](https://github.com/higurashi-ai/Haru#quick-start)에 따라 localhost:8998에서 테스트한다. **--share는 쓰지 않는다.** 공개 터널을 열면 링크 소지자가 접근하고 음성이 외부 중계 경로를 통과할 수 있으므로 로컬 평가와 다르다. 캐릭터 prompt는 임의 chat template 대신 공식 card 형식을 사용한다. 음성 참조 기본 샘플은 배포되지 않는다.

공식 NVIDIA 경로는 약 **12GB 메모리**를 안내하고 Apple Silicon MLX·macOS 앱도 제공한다. 이 수치를 모든 문맥 길이·장치의 최소 요구량으로 보증하지 않는다.

[공식 지연 측정](https://blog.higurashi.ai/melte/haru4b/)의 M1 Max **약 65ms**는 int8 가중치·유선 I/O 조건의 제작자 측정이며 **음성 framing 제외**다. 7.5Hz framing으로 최대 약 133ms가 추가될 수 있다. B300의 약 15ms는 codec와 LM 한 step 범위다. 두 수치를 사용자의 실제 첫 응답 시간과 동일시하지 않는다. 분리 음성의 오류·잡음과 작은 언어 백본의 응답 품질 한계도 있다. 향후 영상 입력 계획을 현재 기능으로 쓰지 않는다.

설치·가중치 다운로드·모델 실행·음성 청취·외부 추론 API 호출은 하지 않았다. 한국어 품질·사용자 장비 지연은 미검증이다.

## 4. 제외·보류 후보

다음은 오늘 신규 소개와 색인 추가 대상이 아니다.

- **[LiquidCodec](https://huggingface.co/LiquidAI/Liquid-Codec): 기존 출시 묶음의 구성요소로 보수적 제외.** Liquid AI 공식 카드는 이미 소개한 LFM3-Audio·Omni의 audio tokenizer라고 명시한다. 약 74M, 24kHz mono, 12.5Hz·12개 codebook, GFSQ·causal encoder/decoder·spectral 출력의 기술 가치는 있지만, 기존 LFM3 소개와 별개 신규 출시 계열로 중복 계산하지 않는다. LFM Open License v1.0이며 일반 Apache가 아니다. Q4 decoder 배포도 별도 계열로 세지 않는다.
- **[Edge0-145B-NVFP4](https://huggingface.co/Edge0/Edge0-145B-NVFP4): 엄격한 차세대 판정 보류.** 공식 카드가 Qwen3.8-Flash-Next 기반을 표시하고 145B/10.12B active, latent MoE·D/U projection·PLE와 메모리 계층을 설명한다. 그러나 이번 확인 범위에서 원천 대비 전체 초기화·재학습 recipe와 주요 세대 단절을 충분히 대조하지 못했다. 단순 양자화라고 단정하지도 않으며 145B 또는 저메모리 실행만으로 신규 등록하지 않는다. Edge0 Community Model License 1.0과 Qwen 원천 조건이 함께 적용된다. 상업 모델 서비스 등 별도 허가 조건을 무시한 자유 배포 추천은 하지 않는다.
- **KLM 1.5/1.6·Inkling 2 Small:** [어제 보고서](2026-11-13.md)에 이미 소개한 계열이다. 오늘 좋아요 증가·새 수정·저정밀 배포를 새 모델로 세지 않는다.
- PAN2·ZONOS3-Mini·MNN-Pocket·LongCat-2.5·P-JiT·Mirage·Ripple·Kimi·ERNIE·Haas·RelayVSR 및 단순 크기·양자화·포맷 변형도 재등록하지 않는다. [11/13](2026-11-13.md)의 Raon nano·Nex N2.6 직접 파생 제외, AREX-2 보류와 기존 Idol·Sophon·Underdog-Woof 보류는 새 충분한 근거 없이 해제하지 않는다.
