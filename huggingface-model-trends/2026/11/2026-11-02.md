### 보류를 해제한 근거

기존 Unlimited-OCR는 이미 색인에 있다. “2”라는 이름·새 benchmark 점수만으로 재소개하지 않았다. 이번에는 이전 논문과 새 기술보고서 본문을 대조해, **기존 공식 계열의 attention·학습·장문 실행 구조가 바뀐 주요 세대 예외**로 판정했다.

[기존 논문 §3.4](https://arxiv.org/html/2606.23050v1#S3.SS4)는 모든 시각·프롬프트 참조를 남기고 최근 출력만 고정 창에 유지한다. 출력이 길어져도 cache가 계속 늘지는 않지만, 원문 페이지 수에 따른 시각 참조 비용은 남는다. 따라서 기존 모델에도 sliding window와 긴 문서 처리 기능이 있었다는 점을 전제로 비교한다.

[새 공식 기술보고서 PDF, §3–4](https://github.com/baidu/Unlimited-OCR/blob/main/Unlimited-OCR-2.pdf)를 실제 내려받아 본문과 구조 그림을 확인했다. Page Gate는 페이지별 후보를 제한하고, Token Sieve는 고정 예산의 block을 선택한다. 선택 확률이 attention logit의 bias에 들어가 파싱 loss로 routing을 학습하며 별도 KL 증류에만 의존하지 않는다. 모든 decoder의 R-SWA를 이 SR-SWA로 바꾼다.

또한 겹치는 경계 페이지의 KV와 텍스트 tail을 재사용하고 비활성 chunk를 해제하는 실행 경로를 결합한다. **활성 참조 수 제한만으로 원본 전체 시각 cache가 사라지는 것은 아니므로**, 장문에서의 메모리 제한에는 chunk 처리가 함께 필요하다.

학습은 기존 Unlimited-OCR checkpoint에서 시작한다. 1,000만 단일 페이지·200만 다중 페이지 문서로 1 epoch, 64K 길이 후학습을 하며 DeepEncoder·aligner는 동결한다. from-scratch 계열로 표현하지 않는다. 단순 도메인 fine-tune·양자화와 달리 공식 후속 세대의 학습되는 sparse reference routing과 연속 KV 실행 변화가 확인되어 이전 보류를 해제했다. 동일 세대의 저정밀·크기·포맷·경미한 파생은 다시 세지 않는다.

### 설정과 논문을 구분

[공개 config](https://huggingface.co/baidu/Unlimited-OCR-2/blob/c14071b549f4fcab10909f3c4acc6a2edb366947/config.json)는 12층, 64 routed experts 중 top-6 및 shared experts 2개, sparse attention 활성화·page2d 위치 방식·entmax router를 포함한다. sparse block 32, local block 4, 여러 top-k 관련 설정이 있으므로 카드의 “512 working references”를 모든 경로의 정확한 고정 총 토큰 수라고 단정하지 않는다.

config의 131,072 max positions와 논문의 64K 학습 길이는 서로 다른 값이다. 어느 쪽도 수백 페이지 모든 텍스트의 정확도·총 GPU 메모리를 보증하지 않는다. tensor 값이나 router 구현 전체를 실행 검증하지 않았다.

## 2. 활용 예: 페이지 경계 오류를 먼저 측정

평가 제안: 직접 만든 비민감 한국어 문서 12쪽에 다음 페이지로 이어지는 표, 반복 머리말, 다른 문서와 같은 표 번호를 넣는다. 다음 항목을 정답과 비교한다.

1. 페이지 누락·중복, 숫자·한글 문자 오류.
2. 두 페이지에 걸친 표의 행 순서와 셀 결합.
3. 머리말을 본문에 끼워 넣는지, 근거 없이 누락 내용을 보완하는지.
4. 짧은 문서와 긴 문서의 실제 peak GPU memory, 전체 처리 시간, 페이지당 오류.
5. 단일 페이지 처리와 연속 처리의 차이. 모든 페이지를 합쳤다는 이유로 문서 전체 추론·요약까지 잘한다고 가정하지 않는다.

공식 환경을 준비한 뒤의 API 형태는 다음과 같다. 이번 조사에서는 실행하지 않았다.

```python
pages = [f"sample/page_{i:02d}.png" for i in range(1, 13)]
text, token_count = model.infer_multi(
    tokenizer,
    image_files=pages,
    output_path="output/sample",
    save_results=True,
)
```

[공식 모델 카드의 infer_multi 안내](https://huggingface.co/baidu/Unlimited-OCR-2#inference)는 페이지 순서대로 이미지를 입력하고 출력의 페이지 경계를 유지한다고 설명한다. 한국어 품질·손글씨·저해상도 팩스 성능은 별도 검증이 필요하다. 모델 자체의 평가 예를 제시할 뿐, 실제 문서를 외부 서버에 전송하지 않았다.

[공식 실행 README](https://github.com/baidu/Unlimited-OCR#inference)는 A800 80GB에서의 테스트와 전용 SGLang wheel을 안내한다. 일반 안정판에 모델 이름만 지정하면 전체 장문 경로가 재현된다고 가정하지 않는다. page window를 줄이면 peak memory는 낮아질 수 있지만 경계 구조 결합이 손상될 수 있다는 한계도 명시되어 있다. 설치 전에 custom code·revision·의존성을 검토한다. 테스트 장비가 최소 VRAM이라는 뜻은 아니다.

## 3. 성능·이용 조건의 한계

새 논문의 속도·benchmark는 **제작자 자체 평가**다. 수백 페이지에서의 고정적인 step 비용이라는 설명을 전체 처리 시간이 문서 길이와 무관하다는 뜻으로 바꾸지 않는다. 특정 benchmark 개선을 모든 OCR·문서 질의응답·한국어 품질의 우위로 일반화하지 않는다.

[코드 LICENSE 전문](https://github.com/baidu/Unlimited-OCR/blob/main/LICENSE)은 Baidu의 MIT이며 복사·재배포 시 저작권·허가 고지를 유지해야 한다. HF 카드의 MIT 표기를 확인했지만 HF 별도 LICENSE 직접 조회는 404였다. 코드 약관 확인을 모든 외부 구성요소·학습 데이터 권리 검토 완료로 표현하지 않는다. 실제 도입 시 DeepSeek 등 원천 구성요소 고지도 확인해야 한다. 약관 수락이나 모델 설치는 수행하지 않았다.

“무제한”은 설계 목표이며 임의 문서에 무한한 정확도·메모리·문맥을 보장하지 않는다. 개별 GPU의 최소 요구량, 한국어 품질, 실제 장문 안정성은 미확인이다.
