### 왜 단순 미세조정과 구분했나

기존 색인에는 Qwen 기반 모델이 다수 있다. Clover라는 이름이 없다는 사실만으로 새 계열로 인정하지 않았다. **Qwen3.6-35B-A3B에서 출발하고 기존 40층 hybrid GDN/full-attention MoE를 유지**한다는 점을 먼저 명시한다. 독립 from-scratch 언어 백본이나 Qwen의 공식 다음 세대를 뜻하지 않는다.

[개발사 구조 설명](https://diffuspace.ai/blog/clover-35b/)은 과거 prefix의 recurrent memory와 현재 noisy block의 양방향 softmax attention을 결합한다고 밝힌다. 과거 memory의 readout도 같은 softmax 선택에 참여하며, 학습 가능한 block-size 보정과 우측 문맥을 위한 zero-initialized convolution 분기가 추가된다. 토큰을 순서대로 하나씩만 내보내는 기존 경로와 다른 **학습된 양방향 연산 구조·블록 denoising**가 핵심이다. 단순 프롬프트, 양자화 또는 도메인 데이터만 바꾼 파생본으로 선정한 것이 아니다.

[공식 카드의 decoder 설명](https://huggingface.co/Diffuspace/Clover-35B-A3B-Preview#architecture-and-decoding)은 masked block에서 신뢰도가 높은 위치를 병렬로 채운 후 완성된 블록을 prefix에 붙이는 LowConfidence 경로를 제시한다. 기본 block size는 32, threshold는 0.95다. 이를 주요 구조·생성 방식 변경 예외로 판정했다. 기존 LLaDA2.2·ALoDLM과 diffusion이라는 큰 범주를 공유하지만, 이들의 checkpoint를 직접 미세조정했다는 근거는 확인되지 않았다.

전체 pretraining·후학습 데이터와 token 규모는 이번 자료에서 확인하지 못했다. 새 구조의 존재와 학습 전 과정을 재현했다는 주장은 다르다. 같은 Clover의 양자화·GGUF·크기·경미한 fine-tune·실행 backend를 별도 계열로 늘리지 않는다.

### 활용 예: 읽기 전용 코드 검토의 품질과 지연을 함께 측정

다음은 본 보고서의 평가 설계이며 실제 모델 출력이 아니다.

1. 직접 만든 짧은 JavaScript 함수 20개를 준비한다. 빈 배열, 음수, 중복 날짜처럼 확인 가능한 오류를 넣고 정답 테스트를 따로 보관한다.
2. 프롬프트: “코드를 실행하거나 파일을 바꾸지 말고, 버그 위치·재현 입력·최소 수정안을 제안하세요. 근거가 없으면 추측이라고 표시하세요.”
3. 공식 Hugging Face 경로의 기본 설정부터 시작해 출력 정확도, 반복 생성, 전체 응답 시간, GPU peak memory를 기록한다.
4. 같은 입력·출력 상한·하드웨어에서 비교 모델을 평가한다. tokens/s만 비교하지 않고 성공한 검토 1건당 시간과 사람이 수정해야 한 비율을 함께 본다.
5. 이후 sandbox 테스트를 붙이더라도 외부 네트워크·비밀정보·파일 쓰기 권한은 분리한다. 모델의 tool-call 형식 준수와 실제 권한 안전성은 별개다.

개발사 benchmark와 속도는 **자체 평가**다. [출시 발표](https://diffuspace.ai/blog/clover-35b/)의 GB300·H200 측정이나 INT4 개인 GPU 시연을 모든 문맥·장비의 속도 또는 최소 VRAM 보증으로 옮기지 않는다. 향후 decision 모델·멀티모달 확장은 현재 공개 text checkpoint와 구분한다.

### 실행 문서의 현재 범위

[공식 GitHub README](https://github.com/DiffuSpace/Clover-35B-A3B-Preview)는 Transformers 5.19.0·PyTorch 2.10 이상 예시와 BF16 가중치 약 69GB 외 추가 추론 상태를 안내한다. **3B active가 전체 가중치 메모리 3B라는 뜻은 아니다.** 실행 전 custom code와 revision을 검토·고정해야 한다.

README는 SGLang의 block diffusion/self-speculative, llama.cpp의 self-speculative 경로를 구분하면서 **backend 코드·setup guide는 추가 예정**, SFT도 coming soon으로 표시한다. 따라서 “일반 안정판 설치만으로 모든 가속 경로 사용 가능”이라고 쓰지 않는다. HF 페이지가 자동 표시한 일반 serving 명령보다 프로젝트별 지원 상태를 우선 확인해야 한다. 두 runtime은 수치 차이로 같은 설정에서도 출력이 달라질 수 있다.

라이선스는 같은 README와 카드의 Apache-2.0 안내·upstream 고지 설명을 확인했으나, 별도 LICENSE·config·modeling 파일의 직접 열람은 오류로 실패했다. 전체 자산 권리나 구현 tensor를 독립 검증했다고 주장하지 않는다. 한국어 품질·최소 VRAM·장문 안정성·학습량은 미확인이다. **모델 설치·다운로드·실행은 하지 않았다.**

## 2. 제외·보류 기록

다음은 신규 소개 수와 오늘 색인 추가 대상이 아니다.

- **[Carbon-X](https://huggingface.co/HuggingFaceBio/Carbon-X): 직접 도메인 파생 제외 유지.** 공식 카드가 Qwen3-14B 초기화, DNA 어휘 확장, 302B-token mid-training·SFT·RL을 명시한다. 유용한 생물학 연구 기능과 이번 아카이브의 엄격한 새 계열 기준은 다르다. [10/27의 제외 판단](../10/2026-10-27.md)을 뒤집을 독립 구조 세대 근거를 확보하지 않았다.
- **[Xiaomi-OCR-0](https://huggingface.co/xiaomi-research/Xiaomi-OCR-0): 이번 선정에서 제외.** 공식 model tree가 Qwen3.5-0.8B-Base fine-tune으로 표시한다. OCR 성능·새 제품명만으로 주요 구조 예외를 인정하지 않았으며, 상세 논문 비교는 완료하지 않았다.
- **[Mage-VL-Cowork](https://huggingface.co/microsoft/Mage-VL-Cowork): 보류.** 트렌딩 노출은 확인했지만 카드 열람 실패로 기존 Mage-VL 대비 구조·학습 변경을 확인하지 못했다.
- Nanbeige4.3·Spark-X2.6·MiniMax-M3.1·Unlimited-OCR-2·Idol은 [최근 보고서](../10/2026-10-31.md)의 계보·주요 세대 비교 보류를 해제할 충분한 검증을 이번에 완료하지 않았다.
- LFM3 modality·저정밀 변형, Mistral Large4, Nemotron Transcribe, SenseNova-Loop와 기존 Qwen/DeepSeek의 양자화·포맷·경미한 파생은 재소개하지 않는다.

## 3. 전주 비교·색인 점검

- 전주 같은 요일 [10/25](../10/2026-10-25.md)은 **Hy-Nomas 1계열**, 오늘은 **Clover 1계열**이다. 상호작용 영상 생성에서 블록 확산 언어 생성으로 선정 주제가 바뀌었다는 아카이브 비교다. 시장 전체 수요나 모델 간 성능 순위 비교가 아니다.
- 전체 **50,440자 introduced-models.md**와 [10/25](../10/2026-10-25.md)·[10/26](../10/2026-10-26.md)·[10/27](../10/2026-10-27.md)·[10/28](../10/2026-10-28.md)·[10/29](../10/2026-10-29.md)·[10/30](../10/2026-10-30.md)·[10/31](../10/2026-10-31.md)의 전체 본문을 조회했다. **7편·7개 소개 계열 모두 색인에 있어** 누락 복구 대상은 없다. 과거 전체 아카이브 재감사를 의미하지 않는다.
- 오늘 경로는 사전 main 조회에서 404였다. 오늘 보고서를 먼저 저장하고 전체 원문 일치를 확인한 뒤 최신 색인을 재조회해 한 계열만 추가한다. 누락된 과거 날짜는 만들지 않는다.
