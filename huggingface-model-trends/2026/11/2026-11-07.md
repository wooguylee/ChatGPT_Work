## 2. RelayVSR를 별도 구조 분기로 보는 이유

### Wan 계보를 인정하고 새로 학습한 경로를 구분

[논문 §3–4](https://arxiv.org/html/2609.37850v1)는 Wan2.2-TI2V-5B를 rank-512 LoRA로 적응하고 one-step GAN 증류를 수행하는 한편, **31.9M Dual-Memory 복원망을 처음부터 60K steps 학습**했다고 설명한다. VARO에서는 작은 망을 고정하고 최종 영상·참조 프레임의 보상으로 큰 망을 학습한다.

따라서 Wan 전체의 독립 from-scratch 사전학습이나 공식 차세대 Wan이라는 뜻은 아니다. 기존 색인의 Wan-Dancer·Wan2.2-Animate-2를 조금 미세조정한 영상 생성 checkpoint 또는 SeedVR2의 크기 변형으로 세지 않는다. **새로운 학습된 복원망·메모리 경로와 두 망 사이의 학습 목표 변화**를 확인한 주요 구조 분기로 판정한다.

[공개 구현](https://github.com/kopperx/RelayVSR/blob/e856773350f53036d825404c9ea9228e6dffadca/refvsr_inference/models/flash/model.py)에서도 다음을 확인했다.

- S 설정은 10개 블록, hidden 512, query head 8개와 KV group 2개를 사용한다.
- 고정 참조의 condition cache와 최근 영상의 video cache가 분리된다. 현재 저해상도 프레임이 양쪽 정보를 읽는다.
- 출력은 RGB residual을 PixelShuffle로 확대한 뒤 bicubic 입력에 더한다. 단순한 VAE 파일 교체나 모델 포맷 변환이 아니다.

[streaming 구현](https://github.com/kopperx/RelayVSR/blob/e856773350f53036d825404c9ea9228e6dffadca/refvsr_inference/runtime/streaming.py)은 기본 16프레임 창의 양 끝 참조를 만들고 끝점을 다음 창에서 재사용한다. 중첩 끝 프레임은 상태를 갱신하되 중복 출력하지 않는다. 기본 실행은 **미래 끝 프레임을 기다리는 bounded-lookahead** 방식이다. 논문의 first-keyframe 실험을 현재 CLI의 무대기 옵션으로 안내하지 않는다.

**주제 태그:** video-super-resolution, video-to-video, streaming, dual-memory, reference-guided, Wan, research. 원본 HF API에는 region:us 외 기술 태그가 없어, 위 목록은 보고서의 분류 태그다. Comfy 재포장의 실제 태그는 comfyui·diffusion-single-file이다.

### 라이선스와 실행 조건

[공식 코드 LICENSE](https://github.com/kopperx/RelayVSR/blob/e856773350f53036d825404c9ea9228e6dffadca/LICENSE)는 Apache-2.0이다. [공식 README](https://github.com/kopperx/RelayVSR/blob/e856773350f53036d825404c9ea9228e6dffadca/README.md)는 Wan의 원래 copyright notice를 유지한다고 명시한다. Comfy 카드에도 Apache-2.0이 표시돼 있다.

다만 **원본 HF 저장소에는 README·LICENSE가 없고 두 가중치 파일만 확인**됐다. 원본 가중치에 적용되는 별도 라이선스 문서는 독립 확인하지 못했다. 코드의 허가를 가중치 전체의 무조건적 상업 이용 허가로 확대하지 않으며, 배포 전 원저작자·원천 모델 조건을 확인해야 한다.

공식 실행 환경은 Linux, Python 3.11–3.13, NVIDIA GPU다. 원본의 flash.safetensors와 wan.safetensors를 사용하며, Comfy의 INT8 변환 파일을 원본 CLI에 그대로 넣는 예는 제공하지 않는다. 설치·가중치 다운로드·외부 코드 실행은 이번 조사에서 하지 않았다.

### 활용 예와 측정 시 주의점

공식 환경·원본 가중치를 준비하고 권리를 확인한 뒤, 직접 촬영한 짧은 무음 샘플로 시험할 수 있는 **미실행 예시**다.

~~~bash
python inference.py --input own_sample.mp4 --output relay_x4_test.mp4 --max-frames 100 --window-size 16 --dtype bf16
~~~

[공식 CLI](https://github.com/kopperx/RelayVSR/blob/e856773350f53036d825404c9ea9228e6dffadca/inference.py)에 맞췄다. 입력·출력 파일을 분리하고 --overwrite를 쓰지 않는다. 원본은 유지한다. **가로·세로 각각 4배**라 픽셀 수는 16배이며, FPS는 유지되지만 **오디오는 복사되지 않는다**.

비교는 bicubic 기준과 같은 프레임·크롭에서 수행한다. 글자, 얇은 선, 피부·천 질감의 변형과 프레임 간 깜빡임을 확인한다. 원래 해상도가 높은 자체 영상을 내려서 입력하면 출력과 실제 정답을 비교할 수 있다.

[논문 표 2·부록 D](https://arxiv.org/html/2609.37850v1)는 A100 80GB·1080p·201프레임 조건에서 29.29 FPS, peak allocated memory 13.82GB, 첫 출력 모델 계산 0.327초를 보고한다. **저자 자체 측정**이며 입력 대기·파일 입출력 등은 제외한다. 30FPS 입력에서 미래 참조 대기는 최대 0.5초가 추가될 수 있다. 소비자 GPU의 실시간 성능·최소 VRAM 보증이 아니며 참조의 색·질감 오류 전파도 한계다.

## 3. 제외와 보류 기록

다음은 신규 소개 수나 오늘 색인 추가 대상이 아니다.

- **[FLUX 3 Image Klein](https://huggingface.co/black-forest-labs/flux-3-image-klein): 동일 계열로 보수적 제외.** [BFL 공식 발표](https://bfl.ai/blog/flux-3-image-klein)가 10/15 출시를 Action에 이은 FLUX 3의 두 번째 공개 가중치로 설명한다. [공식 연구 글](https://bfl.ai/blog/flux-3)도 공유 멀티모달 학습 기반을 제시한다. 이미지 분기의 차이는 있으나 이미 소개한 FLUX 3 Action과 별개 신규 계보라는 근거는 충분하지 않다. distilled·Base·FP8·NVFP4를 나누지 않는다.
- **[Spark-X2.6-4B](https://huggingface.co/XHToken/Spark-X2.6-4B): 직접 후학습 파생 제외.** 최신 공식 카드가 Spark-X2.5-4B와 **정확히 같은 architecture**를 유지하며 향상은 post-training에서 얻었다고 명시한다. 이전 보류를 이번에 동일 백본 파생 제외로 정리한다. 추가 핵심 학습법의 세대 단절 근거는 확인하지 못했다.
- **[Xiaomi-OCR-0](https://huggingface.co/xiaomi-research/Xiaomi-OCR-0): 보수적 보류.** Qwen3.5-0.8B-Base에서 시작하는 Q-Mask·OCR CPT·Mix-RL과 9/30 가중치 공개를 카드에서 확인했다. 같은 계열 backbone의 직접 전문화보다 큰 구조·학습 세대 변화라는 추가 비교 근거는 이번에 확보하지 못해 신규 수에 넣지 않는다.
- **[Sulphur-3](https://huggingface.co/FusionCow/Sulphur-3): 직접 파생 제외.** 공개 모델 트리가 MiniMax-H3 fine-tune을 명시한다. gated early-access 조건을 수락하거나 파일 접근을 시도하지 않았다.
- **[MatterSeek](https://huggingface.co/YuyaoTechnology/MatterSeek): 검증 보류.** 공개 카드는 Yuyao Technology의 HNN·1,035개 descriptor·192개 하위 모델과 자체 실험을 설명하지만, 이번 확인 범위에서 상세 구조·가중치 계보·재현 가능한 공개 검증을 확보하지 못했다. 관심 수치를 기술적 신규성의 증거로 쓰지 않는다.
- Kimi-K3.1-Pro, Ripple, ERNIE 5.5 Base, Haas, LFM3, Nemotron Transcribe, RE-USE, SenseNova-Loop, Unlimited-OCR-2는 이미 등록돼 재소개하지 않는다. Nanbeige4.3 등 기존 보류를 해제할 추가 증거도 이번에 확인하지 못했다.

전주 같은 요일 [10/31](../10/2026-10-31.md)은 **SenseNova-Loop 1계열**, 오늘은 **RelayVSR 1계열**이다. 공유 가중치 반복 계산의 멀티모달 언어 모델에서 대형·소형 협업 영상 복원으로 선정 주제가 바뀌었다. 아카이브의 선정 비교이며 시장 수요·전체 출시량·품질의 증가나 감소를 뜻하지 않는다.
