## 2. Ripple은 처음부터 학습한 새 dense 계열

### 구조와 학습 근거

[공식 출시 글](https://www.ricursive.com/ripple)과 [모델 카드](https://huggingface.co/ricursiveAI/Ripple-65B-Preview/blob/main/README.md)는 **12조 토큰의 영어·코드 중심 텍스트로 처음부터 학습**했다고 명시한다. Olmo 3를 출발점으로 삼았다는 설명은 실험용 학습 recipe와 model ladder의 기준을 뜻한다. 최종 65B가 Olmo 가중치의 경미한 fine-tune이라고 기술된 것이 아니다. 기존 색인의 RecursiveSI/Flint와도 이름이 비슷하다는 이유로 같은 계열로 묶지 않는다.

현재 [config](https://huggingface.co/ricursiveAI/Ripple-65B-Preview/blob/e27e171792f303d74c048184e8259ba663cfa0d5/config.json)는 80층, hidden 5,120, 80 attention heads·8 KV heads, **64 sliding-attention + 16 full-attention**을 지정한다. sliding window는 1,024다. 공식 설명의 gated attention·global NoPE·value residual·FFN activation clipping과 함께, 새 백본을 확인한 근거로 사용했다. Gemma 3N 유사 설계를 참고했다는 말도 Gemma checkpoint 재사용과 구분한다.

카드는 8K 길이 사전학습 뒤 mid-training, long-context 학습, SFT와 mixed-domain RL을 설명한다. **Base Preview는 pretrain-only checkpoint**이고 instruct와 동일한 후학습 상태가 아니다. BF16 instruct·NVFP4·Base·DFlash2 보조 모델을 네 개 신규 계열로 세지 않는다.

**태그:** text-generation, dense-transformer, agentic-coding, reasoning, long-context, base-model, preview.

### 실행 예와 도입 조건

[공식 서버 README](https://huggingface.co/ricursiveAI/Ripple-65B-Preview/blob/e27e171792f303d74c048184e8259ba663cfa0d5/inference/server/README.md)는 **Linux·CUDA 13·SGLang 0.5.19·B200 두 장**, BF16 target와 일치하는 DFlash2 checkpoint를 안내한다. target 기본 문맥은 입력·출력 합산 **1,048,576**, draft attention window는 **16,384**다. config의 2,097,152 positions와 2M 학습 단계를 곧바로 2M 서비스 품질 보증으로 쓰지 않는다.

설치·코드 검토·revision 고정과 로컬 서버 준비가 끝난 뒤 사용할 요청 형태다. 이번 조사에서는 실행하지 않았다.

~~~bash
curl http://127.0.0.1:30000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"ripple","messages":[{"role":"user","content":"다음 함수의 빈 배열 처리 오류를 찾아 최소 수정안과 테스트를 제안하세요. 코드를 실행하거나 파일을 변경하지 마세요: def mean(xs): return sum(xs)/len(xs)"}],"max_tokens":2048}'
~~~

공식 서버는 reasoning·최종 응답·tool calls를 나누어 반환한다. **thinking on/off나 reasoning-effort 단계는 해당 템플릿에 구현돼 있지 않다.** 다른 모델의 옵션을 그대로 붙이지 않는다. 도구 호출을 반환하는 것과 앱이 실제 도구를 실행하는 권한은 분리해야 한다.

카드의 Terminal-Bench 2.1 80.5와 2×B200 batch=8에서 250 tok/s는 **제작자 자체 평가**다. 여러 모델의 공식 점수와 자체 측정이 섞이며 harness에 따라 달라질 수 있다는 원문 설명을 유지한다. DGX Spark 실행 언급을 BF16·장문·모든 consumer GPU의 최소 메모리 보증으로 확대하지 않는다.

[Apache-2.0 LICENSE 전문](https://huggingface.co/ricursiveAI/Ripple-65B-Preview/blob/main/LICENSE)을 확인했다. 배포 시 약관·고지·변경 표시 조건과 외부 의존성 조건을 확인해야 한다. 공개 모델이 비공개 칩 설계 모델의 일반 목적 변형이라는 설명만으로 내부 전용 기능까지 제공한다고 가정하지 않는다.

## 3. Kimi K3.1 Pro는 크기 대신 attention 세대 변경으로 선정

### 기존 K3와 달라진 부분

[K3 카드](https://huggingface.co/moonshotai/Kimi-K3)와 [K3.1 Pro 카드](https://huggingface.co/moonshotai/Kimi-K3.1-Pro)의 구조를 대조했다. **69 KDA + 24 Gated MLA**에서 **69 KDA + 24 Gated DSA**로 바뀐다. 개발사가 full-attention MLA 층을 sparse attention으로 교체했다고 직접 명시한다. [배포 config](https://huggingface.co/moonshotai/Kimi-K3.1-Pro/blob/main/config.json)도 24개 DSA 층과 index top-k 2,048, index head dimension 128·head 수 32를 포함한다.

총 2.8T·활성 104B, 93층, 896 routed experts 중 token당 16개 및 shared experts 2개, 1M 문맥이라는 규모 자체를 새로워진 항목으로 세지 않는다. MoonViT-V2 401M과 텍스트·이미지 입력도 기존 K3와의 공통점을 먼저 인정한다.

[공식 기술 글](https://www.kimi.com/en/blog/kimi-k3-1-pro)은 K3에서 출발한 후학습과 수백 개 분야의 대규모 공동 RL을 설명한다. 따라서 **독립 from-scratch 백본이 아니라, 기존 등록 계열의 주요 구조·후학습 변경 예외**로 선정했다. 단순 이름 변경·양자화·작업 특화 fine-tune을 예외로 인정한 것이 아니다. MXFP4 weights / MXFP8 activations QAT 배포와 Highspeed 서비스 표기를 별도 신규 계열로 세지 않는다.

**태그:** image-text-to-text, MoE, sparse-attention, multimodal, long-context, agentic-coding, tool-calling.

### 활용 예와 평가 한계

[공식 quickstart](https://platform.kimi.ai/docs/guide/kimi-k3-1-pro-quickstart)의 API model ID는 kimi-k3.1-pro이며 reasoning_effort는 low/high/max다. 예를 들어 **직접 만든 비민감 코드와 도표**에 “테스트 실패 원인을 근거와 함께 정리하고, 변경은 실행하지 말고 최소 수정안만 제안하세요”라고 요청한 후 정답 테스트와 비교할 수 있다. API는 별도 키·과금·전송 승인이 필요한 외부 서비스다. 여기서는 호출·가입·결제·데이터 업로드를 하지 않았다.

다중 턴·도구 사용에서는 공식 응답의 reasoning_content와 tool_calls를 포함한 assistant 메시지를 보존해야 한다. 오픈웨이트 self-hosting은 공식 vLLM·SGLang recipe의 전용 지원 상태를 확인해야 하며, 2.8T 모델을 개인 단일 GPU용으로 안내하지 않는다. 정확한 최소 메모리·한국어 정확도·실제 장문 지연은 미확인이다.

내부 Kimi Code Bench 3.0 Long-horizon의 K3 55.95% → K3.1 Pro 61.2%는 **개발사 내부 평가**다. Ripple의 Terminal-Bench 2.1과 benchmark·harness·추론 예산이 달라 직접 순위를 만들지 않는다. 3D 생성 사례도 도구를 통한 코드·자산 제작과 모델의 직접 영상 생성 능력을 구분해서 읽어야 한다.

## 4. 제외와 보류

아래는 신규 소개 수·색인 추가 대상이 아니다.

- **[P-H3-Image](https://huggingface.co/PrunaAI/P-H3-Image): 직접 파생 제외.** Pruna AI 카드의 base_model은 MiniMax-H3, 관계는 finetune이다. 이미지 생성·편집으로 쓰는 목적이나 8-step 배포만으로 기존 H3의 새 독립 계열로 세지 않는다. 생성 transformer 33.1B·text encoder 4B·VAE·prompt upsampler를 전체 33.1B로 합치지 않는다. MiniMax H3 Community License는 별도 계약 없는 한국·미국·영국·EU 이용 제외를 카드가 명시하므로 한국어 독자에게 무조건적인 상업 활용을 권하지 않는다. 정확한 최초 출시일은 미확인이다.
- **[Pika-H3-Flex](https://huggingface.co/Pika-Labs/Pika-H3-Flex): 기존 직접 파생 제외 유지.** 공식 카드의 H3 후학습·LoRA 관계를 재확인했다. native 480p/768p와 hosted API의 고해상도 기능은 구분한다.
- **[Xiaomi-OCR-0](https://huggingface.co/xiaomi-research/Xiaomi-OCR-0): 직접 파생 제외 유지.** Qwen3.5-0.8B-Base에서 출발하는 OCR CPT·Mix-RL이 명시돼 있다. 카드의 09/30 가중치 공개일을 오늘 출시로 바꾸지 않는다. 새 데이터 engine의 연구 가치만으로 기존 계보의 독립 차세대로 승격하지 않았다.
- LFM3 modality/정밀도 배포, Mistral Large4, Nemotron Transcribe, RE-USE, SenseNova-Loop, Unlimited-OCR-2는 이미 등록했다.
- Idol·Nanbeige4.3·Spark-X2.6·MiniMax-M3.1 등 기존 보류 후보는 이번에 충분한 새 계보 비교를 완료하지 않았다. 순위·좋아요만으로 보류를 해제하지 않는다.

## 5. 전주 비교와 색인 정합성

전주 같은 요일 [10/29](../10/2026-10-29.md)은 **Nemotron Transcribe 1계열**, 오늘은 **Ripple·Kimi K3.1 Pro 2계열**이다. 음성 입력 확장에서 텍스트 코딩 백본·대형 멀티모달 attention 후속 세대로 선정 주제가 바뀐 아카이브 비교다. 시장 성장률·품질 순위·수요가 두 배가 됐다는 뜻이 아니다.

전체 **51,711자 introduced-models.md**와 최근 [10/29](../10/2026-10-29.md)·[10/30](../10/2026-10-30.md)·[10/31](../10/2026-10-31.md)·[11/01](2026-11-01.md)·[11/02](2026-11-02.md)·[11/03](2026-11-03.md)·[11/04](2026-11-04.md)의 전체 본문을 대조했다. **7편·5개 소개 계열은 모두 색인에 있어** 이 범위의 누락 복구 대상은 없다.

추가로 날짜 절이 없는 과거 게시물의 정합성을 점검했다. 07/20–08/24의 게시된 34편은 기존 누적 마이그레이션 목록에 대응하며, 10/11은 신규 0개다. 과거 전 기간의 모든 내용·사실을 재감사했다는 뜻은 아니다. 누락된 과거 날짜 보고서는 생성하지 않는다.

오늘 경로는 사전 main 조회에서 404였다. 보고서를 먼저 저장하고 **main 전체 원문 일치**를 확인한 다음에만 최신 색인을 다시 읽어 두 계열을 추가한다. 기존 색인 전체를 보존하고 다른 작업 경로·예약 설정은 변경하지 않는다.
