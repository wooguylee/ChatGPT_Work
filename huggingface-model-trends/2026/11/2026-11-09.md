## 2. Pyramid-JiT 계열의 첫 소개

### 새로 확인한 생성 구조와 기존 계보

[공식 저장소](https://github.com/Linum-AI/pjit-21k)는 P-JiT 21K를 기존 Pyramid-JiT 구조를 더 오래 학습한 연구 checkpoint로 설명한다. **10/06의 P-JiT와 11/04의 21K를 한 계열로 묶는다.** 색인에 Linum/Pyramid-JiT가 없고, 현재 HF 트렌딩에 노출된 21K를 대표로 처음 기록한다.

[공개 구현](https://github.com/Linum-AI/pjit-21k/blob/main/pjit_21k/model.py)은 VAE 없이 RGB를 32×32 patch로 나누어 직접 깨끗한 픽셀을 예측한다. 이미지·텍스트 각각 2개 refiner를 지난 뒤 22개 single-stream DiT 블록에서 결합한다. [공식 설정 코드](https://github.com/Linum-AI/pjit-21k/blob/main/pjit_21k/config.py)는 폭 2,944, 23 heads, 256 text tokens와 1024px 단계의 RoPE 위치 보간을 명시한다.

Qwen3.5-4B는 동결된 조건 encoder로 사용한다. 이것을 Qwen 언어 가중치의 이미지 fine-tune이나 전체 시스템의 2.18B 규모라고 쓰지 않는다. Z-Image식 block 설계·JiT 아이디어 재사용도 원천 가중치의 직접 파생과 구분한다. 기존 색인의 Iris·PixelUMM와 픽셀 공간이라는 범주를 공유하지만, 그 checkpoint를 변환·미세조정한 모델로 소개된 것은 아니다. Linum의 별도 생성 학습 계열을 선정한 것이다.

[11/04 공식 학습 기록](https://www.linum.ai/field-notes/pjit-21k)은 512px 약 610M samples, 1024px 약 50M samples 뒤 FDFO 변형 후학습을 설명한다. 중간 저해상도 readout과 DINOv3를 목표로 하는 PixelREPA는 **학습용 보조 경로**이며 배포 sampling에는 포함되지 않는다. 약 660M은 학습에서 본 sample 수로, 서로 다른 이미지 660M장을 뜻한다고 단정하지 않는다.

**태그:** text-to-image, pixel-space, diffusion-transformer, multi-resolution-training, research. 영상 모델 개발을 위한 연구 단계지만 현재 공개물은 이미지 생성 모델이다.

### 활용 예와 실행 주의

[공식 README](https://github.com/Linum-AI/pjit-21k#your-own-prompts)는 약 50–80단어의 구체적 caption을 권한다. 기본 CLI는 OpenRouter를 통해 프롬프트를 다시 작성하므로, 로컬 생성 평가에서는 **--no_upsample**을 명시해 외부 재작성 호출을 끈다.

아래는 환경·코드·의존성·가중치 권리를 검토하고 준비한 뒤의 **미실행 예시**다.

~~~bash
python generate.py --no_upsample --aspect_ratio square --seeds 0 --out_dir outputs/pjit_20261109 \
  --prompt "A small blue ceramic cup sits on a pale wooden table beside a single yellow pear. Soft morning light enters from a window on the left and casts short shadows to the right. The plain cream wall behind them is softly blurred. The scene is photographed at table height, with both objects fully visible and no writing or logos."
~~~

[실제 CLI](https://github.com/Linum-AI/pjit-21k/blob/main/generate.py)와 맞춘 옵션이다. 첫 실행에는 모델·encoder 다운로드가 발생하며 기존 결과와 다른 출력 폴더를 사용한다. CUDA가 필요하고 생성부 FP32 가중치 약 8.7GB와 encoder BF16 약 8GB 외 activation 메모리가 필요하다. 이를 최소 VRAM 16.7GB 보증으로 안내하지 않는다.

공식 제한은 글자·포스터, 전신, 여러 개체·사람 상호작용, 사물의 세부 상식이다. 같은 caption·seed에서 객체 수·색상·위치와 실패율을 평가하고, 한국어 caption 품질은 별도 측정한다. [코드 LICENSE](https://github.com/Linum-AI/pjit-21k/blob/main/LICENSE)는 Apache-2.0이며 외부 구성요소 고지는 유지해야 한다.

## 3. Mirage는 작은 시각 인식 구조 분기

[11/06 공식 발표](https://cactuscompute.com/blog/mirage)는 51.3M Mirage를 장면 설명·검출·분할·OCR·제한된 선택을 결합한 모델로 공개했다. 2-bit Cactus Quants 파일은 약 21.6MB지만 임베딩·mHC 라우팅은 4-bit, HConvGLU band 등 일부는 FP16이다. **전 파라미터가 2-bit라는 뜻은 아니다.** 관찰·소개는 11/09이며 최초 public 전환 시각은 미확인이다.

### Needle와 공유하는 부분과 시각 전용 경로

공식 설명은 8층 decoder가 Needle·Whistle의 Simple Attention, Hadamard MLP, engram, 4-lane mHC 설계를 공유한다고 명시한다. 따라서 독립적인 새 언어 백본이라고 주장하지 않는다.

선정 근거는 **HConvGLU 기반 공유 이미지 encoder, 검출·마스크·문자 reader 및 region reference 연결**이다. [공개 config](https://huggingface.co/Cactus-Compute/mirage/blob/main/config.json)에서 512px canvas, 512차원, 4 register tokens, 별도 reader 설정을 확인했다. Needle의 layer 수·양자화 변형이나 Whistle의 음성 checkpoint 이름 변경으로 보기 어려운 입력·출력 구조 변화다. 이 주요 시각 분기를 한 계열로 등록하며 포맷별로 나누지 않는다.

[구조 상세](https://cactuscompute.com/blog/structured-perception)는 coarse memory와 fine feature에서 geometry를 예측하고, decoder는 객체 이름·속성과 region reference를 생성한다고 설명한다. 마스크는 공유 prototype 조합, OCR은 원본 이미지 crop의 CTC reader가 담당하며 런타임이 JSON으로 결합한다. 단순히 기존 언어 모델에 “JSON으로 답하라”고 프롬프트한 기능이 아니다.

**학습 초기화 checkpoint·데이터셋·증류 교사·전체 recipe는 미확인**이다. config의 training_step만으로 처음부터 학습한 전 구성요소나 특정 학습량을 주장하지 않는다.

**태그:** image-text-to-text, object-detection, image-segmentation, OCR, structured-perception, on-device.

### 활용 예와 한계

[공식 사용법](https://cactuscompute.com/blog/mirage#get-started)에 맞춘 미실행 예시다. 설치·엔진·가중치를 검토한 뒤 직접 촬영한 비민감 물체 사진으로 시작한다.

~~~python
import cactus

vision = cactus.Mirage()
result = vision.describe("own_objects.jpg")
print(result)
~~~

처음에는 엔진·가중치를 다운로드하고 이후 캐시를 사용한다. 공개 설명 언어는 영어·독일어·프랑스어·스페인어·이탈리아어·네덜란드어·폴란드어다. **한국어 설명·한글 OCR은 지원 또는 품질을 확인하지 못했다.** Galaxy S26 NPU 74ms·CPU 107ms는 제조사 측정이며 사용자 장비의 속도 보증이 아니다.

[구조 문서의 한계](https://cactuscompute.com/blog/structured-perception#reading-follows-the-text-region)에 따르면 OCR 문자열은 semantic decoder에 다시 입력되지 않고 form 경로는 reader를 실행하지 않는다. 정확한 표지 문구로 판단해야 한다면 앱이 OCR 출력을 별도로 사용해야 한다. 검출 점수도 객체 이름·마스크·속성 전체의 신뢰도는 아니다. 자동 안전 판단에 바로 연결하지 말고 누락·잘못된 이름·문자 오류를 각각 측정한다.

HF 카드 Apache-2.0 표기와 [공식 코드 LICENSE 전문](https://github.com/cactus-compute/cactus/blob/main/LICENSE)을 확인했다. 가중치 별도 LICENSE 전문은 독립 확인하지 못했다. 공개 README의 Needle·Whistle fine-tuning 안내를 Mirage 학습 지원으로 확대하지 않는다.

## 4. 제외 및 보류 업데이트

아래는 오늘 신규 수·색인 추가 대상이 아니다.

- **[HyperFlow H3 Flash](https://huggingface.co/VideoRebirthAI/hyperflow-h3-flash): 직접 압축·증류 파생 제외.** Video Rebirth 공식 카드가 MiniMax-H3의 compressed few-step 배포라고 명시한다. 13.7B/13.9B는 transformer 규모이며 외부 text encoder·VAE와 구분한다. MiniMax H3 Community License의 한국·미국·영국·EU 관련 제한을 확인했으며 조건 수락·설치·실행은 하지 않았다.
- **[Qwen3.8-27B-DSpine-b16](https://huggingface.co/tencent/Qwen3.8-27B-DSpine-b16): 보조 drafter로 분리.** Tencent의 5-layer·block 16·8,192-token window speculative draft model이다. 기존 Qwen3.8-27B의 새 독립 본체로 세지 않는다. 카드 Apache-2.0·HF 약 2B 표기, 정확한 정수 합계 미확인. 성능 표는 특정 SGLang replay 조건의 제작자 평가다.
- **[Underdog-Woof](https://huggingface.co/ConwayResearch/Underdog-Woof): 카드 확보, 계보 보류 유지.** ConwayResearch 카드에서 영어 고정 2음성 TTS, 총 약 38.24M, Mimi 개작 decoder, NumPy CPU 경로를 확인했다. Underdog Non-Commercial License 1.0 표기로 상업 이용은 별도 허가 대상이다. 다만 전체 학습 초기화·기존 TTS 파생 여부·LICENSE 전문·절대 공개일은 검증하지 못했다. Mimi 재사용을 Pocket TTS 직접 파생이라고 단정하지도 않는다.
- Arete, CCORE 3D Coder, Pika-H3-Flex, Viggle-Remake, TwIL-8B, Spark-X2.6 등의 최근 직접 파생 제외를 유지한다. Idol·Nanbeige4.3 등의 기존 보류도 새로운 차세대 근거 없이 해제하지 않는다.
- Ripple·Kimi-K3.1-Pro·ERNIE·Haas·RelayVSR·LFM3·Nemotron Transcribe 등 기존 등록 계열과 포맷·양자화 배포는 재소개하지 않는다.

일부 HF 본문·API 조회는 실패해 제작사 공식 발표·공식 GitHub 코드·확보 가능한 공식 카드로 보완했다. P-JiT의 HF 별도 설정·LICENSE 직접 열람과 Woof의 상세 계보·약관 원문 검증은 미완료다. **동일 조건의 전주 snapshot이 없어 좋아요·다운로드 증가율과 순위 상승폭은 미확인**이다.

가중치 다운로드·설치·모델 실행·benchmark 재현·GPU 측정·외부 추론 API 호출은 하지 않았다. 이번 검증 범위에서 선정한 계열이며 시장 전체에 신규 모델이 두 개뿐이라는 결론은 아니다. 게시 확인과 모델 품질 검증을 구분한다.
