## 1. 관찰 요약: 코드로 만드는 영상·3D도 계보 확인이 먼저

트렌딩 목록에서 코드 기반 시각 콘텐츠 제작과 소형 음성·decision 배포가 관찰됐다. 작업 목적이 흥미롭더라도 기존 가중치의 직접 미세조정, 같은 계열의 배포 형식 변경, 이미 묶어 소개한 제품은 새 계열로 세지 않는다.

### Code2Video: 영상 diffusion 모델로 오해하지 않기

[공식 카드](https://huggingface.co/sensenova/SenseNova-6.8-Code2Video#sensenova-68-code2video)는 Qwen3.8-27B 미세조정임을 명시한다. 핵심은 실행 가능한 코드를 작성하고 도구로 렌더링하는 영상 제작이다. 새로운 영상 생성 백본이나 SenseNova-Loop의 다음 구조 세대로 분류하지 않는다. 태그: code-generation, video-workflow, agent.

카드의 긴 실행·반복 제작 사례는 제작자 보고다. 이름의 Video를 가중치가 영상 프레임을 직접 생성한다는 의미로 바꾸지 않는다. 모델·harness·렌더러·외부 자산의 역할을 나눠 평가해야 한다. 관찰일은 11/04이며 최초 가중치 공개일은 이번에 확정하지 않았다.

### CCORE: 출력 파일 형식이 달라도 직접 파생

[기존 3D Coder 카드](https://huggingface.co/ccore/Qwen3.5-4B-3D-Coder#qwen35-4b-3d-coder)는 독립 제작자의 Qwen3.5-4B fine-tune임을 명시한다. 선택적 vision은 원래 projector 재사용이며 새로운 시각 encoder 세대로 세지 않는다.

[GLB 카드](https://huggingface.co/ccore/Qwen3.5-4B-GLB-3D-Coder#qwen35-4b-glb-3d-coder)는 Three.js HTML/JavaScript를 만들고 GLB로 내보내는 preview다. 출력 포맷 확장과 Godot 활용성만으로 새 모델 계열이 되지는 않는다. 태그: coding, Three.js, GLB, game-assets, preview.

기존 카드의 10/29 FP16·데이터 공개, 10/30 vision 안내, GLB 카드의 **11/02 04:50 UTC checkpoint 갱신**은 서로 다른 사건이다. 관찰 11/04와 구분하며 최초 공개일로 대체하지 않는다. 같은 파일명이 새 checkpoint를 가리킬 수 있으므로 실험에는 revision·파일 hash를 기록해야 한다.

### 소형·음성 후보와 접근 제한

[Audio8 Air 공식 설명](https://huggingface.co/Edge0/Audio8-TTS-Realistic-Air#highlights)은 Preview 구조와 인터페이스 유지, 다국어·자연스러움 개선을 설명한다. 23개 언어 확대는 유용하지만 이번 신규 계열 조건은 아니다. 태그: TTS, multilingual, voice-cloning. 최초 출시일은 이번에 별도 확정하지 않았다.

[Sulphur 공개 페이지](https://huggingface.co/FusionCow/Sulphur-3)는 H3 fine-tune 계보와 제한된 early access를 표시한다. 파일·상세 내용 접근을 위한 정보 공유/조건 수락은 수행하지 않았다. 확인하지 못한 약관·학습법·성능을 추정하지 않는다. 단순 접근 오류 때문에 새로운 계열이라고 가정하지 않는다.

[d1-2B 공식 카드](https://huggingface.co/LiquidAI/d1-2B#model-details)는 LFM3-VL 기반 단일 forward typed decision 모델로 설명한다. 이번엔 이미 소개된 묶음의 세부 제품으로만 확인했다. 일반 채팅 generate 예시와 전용 decision API를 혼동하지 않는다. 태그: decision, classification, extraction, multimodal. 정확한 출시일은 별도 미확인이다.

## 2. 실용 평가 예: 콘텐츠 생성 코드의 결과와 권한을 분리

다음은 이 보고서의 평가 설계이며 실제 실행 결과가 아니다. 제외 후보도 평가할 수 있지만 신규 계열로 등록했다는 뜻은 아니다.

1. 비민감 합성 과제 하나를 만든다. 예: “파란 상자 위로 작은 공이 이동하는 5초 장면의 HTML/JavaScript 코드만 작성하세요. 외부 URL·파일 읽기·네트워크 요청은 넣지 마세요.”
2. 출력 코드를 실행하기 전에 외부 import, 원격 자산, 파일·네트워크 접근을 검토한다. 모델이 안전하다고 설명한 것을 검사 결과로 대체하지 않는다.
3. 승인된 격리 환경에서만 렌더링하고 프레임 누락·오브젝트 수·색상·시간 길이를 정답과 비교한다. 도구 권한은 출력 코드의 내용과 별개로 제한한다.
4. GLB는 미리보기 화면뿐 아니라 별도 viewer/게임 엔진에서 열리는지, 애니메이션·재질·축/scale이 보존되는지도 측정한다.
5. 같은 과제를 원천 모델과 비교해 성공률·수정 횟수·시간을 기록한다. 좋은 시연 한 개를 일반 품질이나 새 아키텍처의 증거로 쓰지 않는다.
6. 음성은 동의받은 합성/본인 샘플로 숫자·고유명사·누락을 평가하고, decision 출력은 보류 임계값과 오분류를 검증한다. 생성·분류 결과가 자동 외부 행동을 승인하지 않도록 분리한다.

최소 VRAM·한국어 품질·실제 실행 속도는 이번에 검증하지 않았다. 카드의 장비·문맥 설정을 보편적인 최소 요구량으로 안내하지 않는다.
