## 1. tencent/Hy4-preview

- Hugging Face: https://huggingface.co/tencent/Hy4-preview
- 개발사/작성자: Tencent Hy Team / Tencent
- 공식 발표: https://www.tencent.com/tencent-releases-and-open-sources-tencent-hy4-preview/
- 공식 GitHub: https://github.com/Tencent-Hunyuan/Hy4-preview
- 분야: **Text LLM · Coding · Agent · Office/Productivity · Scientific Research**
- 라이선스: **Apache-2.0**

### 규모와 아키텍처

Tencent의 공식 모델 카드 기준으로 Hy4 preview의 backbone은 **770B total / 49B active parameters**의 Mixture-of-Experts 모델이다. 78개 backbone layer 중 첫 레이어는 dense FFN, 나머지 77개는 MoE이며 각 MoE layer는 **256 routed experts + 1 shared expert**, token당 top-8 routed experts와 shared expert를 활성화한다. backbone 외에 speculative decoding을 위한 **native MTP layer 1개(10B total / 0.7B active)**가 추가되어 Hugging Face UI에서는 전체 모델 크기가 약 780B로 표시된다.

핵심 구조는 다음과 같다.

- Attention: **Gated DeepSeek Sparse Attention (Gated DSA)**
- Sparse index 재사용: **IndexCache**로 여러 layer가 sparse index를 재사용
- Residual pathway: **iHC (identity Hyper-Connections)**, 4 residual streams
- Context length: **1M tokens**
- Vocabulary size: 120,832
- 기본 reasoning mode: `high`; 직접 응답은 `no_think` 설정 가능

### 오늘 주목할 근거

2026-08-28 Tencent가 Hy4 preview 가중치를 Hugging Face, ModelScope, GitCode, CNB에 공개했다. 조사 시점 Hugging Face 전체 Trending 페이지에서 **상위 약 13위권**에 있었고, repository snapshot은 **좋아요 236, Community 7개**, 업데이트는 약 9시간 전이었다. 공개 직후라 Hugging Face의 `Downloads last month`는 아직 `-`로 표시되어 월간 다운로드 통계가 형성되지 않은 상태다.

공식 GitHub `Tencent-Hunyuan/Hy4-preview` 역시 공개 직후 **205 stars, 8 forks, 5 commits** snapshot을 보였다. 수치는 모두 2026-08-29 09:00 KST 전후의 조사 시점 snapshot이며 이후 변동될 수 있다.

### 기존 Hy3와 무엇이 달라졌나

`introduced-models.md`에는 이미 `tencent/Hy3`가 존재하므로 단순 세대명 변경이면 제외해야 한다. 그러나 Hy4는 공식 사양상 핵심 architecture가 바뀌어 별도 차세대 모델로 판단했다.

기존 Hy3는 **295B total / 21B active**, 256K context, 80-layer MoE이며 attention은 **GQA(64 heads, 8 KV heads)** 기반이었다. Hy4는 단순히 파라미터 수만 늘린 것이 아니라 attention을 **Gated DSA**로 변경하고 **IndexCache**를 추가해 sparse attention index를 layer 간 재사용하며, residual 경로도 **iHC**로 확장했다. Context 역시 **256K → 1M**, expert 구성도 **192 routed experts → 256 routed experts**로 바뀌었다. 즉 크기 확대와 함께 attention, residual information flow, sparse-index 재사용 방식이 함께 바뀌었으므로 단순 3B→8B 같은 크기 변형으로 보지 않았다.

개발자 관점에서 특히 중요한 부분은 IndexCache다. sparse attention은 긴 context에서 모든 token을 전부 비교하는 비용을 줄일 수 있지만, 어떤 token을 볼지 선택하는 index 계산 자체도 비용이 된다. Hy4는 이 sparse index를 layer마다 다시 계산하지 않고 재사용하는 방향을 채택해 긴 context에서의 효율을 겨냥한다. Native MTP는 speculative decoding용 draft 역할을 모델 내부에 직접 포함해 serving stack에서 추론 가속을 활용할 수 있게 한다.

### 실제 활용 가능성과 제약

공식 문서는 **vLLM과 SGLang** serving을 모두 제공하며, 두 방식 모두 **OpenAI-compatible API**로 호출할 수 있다. 공식 vLLM/SGLang recipe는 tool-call parser와 reasoning parser를 제공하고 `--enable-auto-tool-choice`도 지원하므로 coding agent, tool-using agent, MCP 기반 애플리케이션의 LLM backend로 연결하기 쉽다. MCP 자체를 모델이 직접 지원하는 것은 아니지만, OpenAI-compatible endpoint와 tool calling을 통해 MCP host/agent 프레임워크의 추론 backend로 사용할 수 있다.

Tencent는 production 예제로 공식 **Hy4-preview-FP8** checkpoint와 **tensor parallel size 8** 구성을 제시한다. 770B backbone + MTP 규모이므로 일반 데스크톱이나 단일 소비자 GPU에서 원본 가중치를 직접 운용하는 모델은 아니다. 현재 공식 실무 경로는 multi-GPU 서버의 vLLM/SGLang 또는 Tencent/OpenRouter 등 hosted access 쪽이 현실적이다. Hugging Face snapshot에서는 아직 Inference Provider에 직접 배포되지 않은 것으로 표시됐다.

라이선스는 Apache-2.0으로 공개되어 상업 활용 측면의 제약이 비교적 적다. 다만 preview 모델이고, Tencent가 공식적으로 **복잡한 문제에서 필요 이상으로 오래 추론하거나 답을 과도하게 재검증하는 경향**을 known limitation으로 명시했다. 실제 agent 배포에서는 최대 reasoning budget, timeout, tool-call retry 정책을 별도로 두는 것이 좋다.

### Benchmark와 평가 해석

Tencent는 사내 전문가 163명이 203개 engineering task를 blind side-by-side로 평가한 결과 Hy4 preview 평균 2.99, GLM-5.3 2.92, Kimi K3 2.94라고 공개했다. 이는 **개발사 자체 평가**이며 독립 검증 결과로 해석하면 안 된다.

Hugging Face 모델 카드에는 GPQA Diamond 92.3, Deep SWE 64.3, SWE-bench Pro 65.7, SkillsBench v1 62.9, SWE-bench Multilingual 82.9 등의 evaluation result가 게시되어 있지만, 이 보고서에서는 해당 숫자를 **모델 카드에 게시된 평가 결과**로만 취급하며 별도의 독립 재현을 확인한 것으로 표현하지 않는다.
