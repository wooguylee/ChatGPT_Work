## 1. Qwen/Qwen3.8-Flash-Next

### 기본 정보

- Hugging Face: https://huggingface.co/Qwen/Qwen3.8-Flash-Next
- 개발사/작성자: **Qwen Team / Alibaba**
- 분야: **Image-Text-to-Text, Multimodal LLM, Coding, Agent**
- 라이선스: Hugging Face 표기 **Qwen Community License 1.0**. 상업 배포·재배포 전 라이선스 원문 확인 필요
- 모델 카드 기준 구조:
  - Causal Language Model + Vision Encoder
  - 언어 모델 본체 **125B parameters / 6B activated**
  - **51B N-gram embedding**, **4B MTP** 추가
  - 48 layers
  - 512 experts, routed 10 + shared 1 활성화
  - native context **262,144**, 카드상 최대 **1,000,000** 확장 가능

### 오늘 주목할 근거

- 2026-08-27 09:02 KST 기준 Hugging Face 전체 Trending 최상단에 노출됨.
- HF 표시상 약 **11시간 전 업데이트**, 약 **3.6k likes**, 최근 1개월 **2,551 downloads**, **Community 24**, **3 Spaces**, **47 quantizations**가 확인됨.
- 수치 자체보다 더 중요한 점은 Qwen이 이 모델을 단순한 Qwen3.8 파생본이 아니라 **향후 Qwen4의 기반이 될 실험적 architecture preview**라고 명시했다는 점이다.

### 기존 모델과의 기술적 차이

기존 `introduced-models.md`에는 `Qwen/Qwen3.8-27B`가 이미 있다. 하지만 Qwen 공식 카드가 Flash-Next를 “Qwen4를 뒷받침할 architecture의 experimental preview”로 설명하고, 핵심 구조 자체가 달라 별도 계열로 판단했다.

- **QSA hybrid attention**: Gated DeltaNet과 Qwen Sparse Attention을 섞어 긴 문맥에서 모든 token을 동일하게 full attention하는 비용을 줄인다. 특히 sparse attention을 micro-block 단위로 적용해 long-context latency를 낮추는 방향이다.
- **Gated Residual**: residual stream을 넓히면서도 정보 흐름을 gate로 제어한다. 단순 layer 수 증가가 아니라 residual 표현 용량을 확장하는 설계다.
- **N-gram Embedding**: 계산량을 같은 비율로 늘리지 않고 parameter capacity를 키우는 별도 embedding 구조를 둔다. offloading과 memory/computation 분리에 유리한 방향이다.
- **새 학습 recipe**: Muon/AdamW를 조합하고 scaling law를 다시 맞춘 학습법을 사용한다.
- **Multimodal**: vision encoder를 포함한 image-text-to-text 모델로 공개되었다.

즉 `Qwen3.8-27B → 더 큰 parameter 버전`이 아니라 attention, residual, embedding, training recipe를 동시에 바꾼 **차세대 실험 구조**라는 점이 중복 예외의 핵심이다.

### 실제 활용 가능성과 제약

- 모델 카드/Hub helper에서 **Transformers, vLLM, SGLang, TokenSpeed** 경로가 안내된다.
- vLLM/SGLang은 **OpenAI-compatible API server** 형태로 구성할 수 있어 기존 Agent/MCP backend에 붙이기 쉽다.
- Hugging Face에는 llama.cpp/Ollama/LM Studio 계열에서 사용할 수 있는 quantization 탐색 링크가 존재하지만, **총 weight 규모가 매우 크므로 일반 PC에 적합한 모델이라고 보기는 어렵다**. MoE의 활성 parameter가 6B라고 해서 저장해야 할 전체 weight가 6B가 되는 것은 아니다.
- Coding/Agent 실험, 긴 문맥 RAG, image+text agent 연구에는 특히 가치가 높다.
- 공식 카드의 DeepSWE, SWE-bench Pro 등 benchmark 결과는 **개발사 자체 평가**로 보아야 하며 독립 검증 결과로 해석하지 않았다.

### 기존 모델과의 기술적 차이

`introduced-models.md`에는 이미 `zai-org/GLM-5.2`가 있다. 그러나 GLM-5.3-Flash는 공식 카드에서 다음을 명시하고 있어 단순 minor version이나 크기 변형으로 보지 않았다.

- **새로 학습한 base model**에서 시작.
- GLM-5 계열 최초의 **native multimodal** 모델.
- GLM 시리즈 최초로 **hybrid sparse + linear attention**을 도입.
- **Manifold-Constrained Hyper-Connections (mHC)**를 채택.
- 최신 **30T-token multimodal pretraining corpus**를 사용했다고 개발사가 설명.

기존 dense/sparse attention의 긴 문맥 비용과 multimodal 분리 문제를 줄이면서, 하나의 foundation model에서 text·vision·agent task를 함께 다루려는 구조 변화다. 따라서 GLM-5.2의 단순 후속 checkpoint가 아니라 **architecture·modality·pretraining이 동시에 바뀐 별도 세대**로 판정했다.

### 실제 활용 가능성과 제약

- 공식 카드가 **SGLang, vLLM, TokenSpeed, KTransformers** local deployment를 안내한다.
- vLLM/SGLang으로 **OpenAI-compatible API**를 구성할 수 있어 coding agent, tool-use backend, MCP 연동 실험에 적합하다.
- 총 320B급 weight 때문에 일반 데스크톱 단독 구동은 현실적으로 매우 부담스럽다. KTransformers/offloading 또는 다중 GPU 서버를 고려해야 하는 급이다.
- HF에는 여러 quantization이 빠르게 생기고 있지만, quantization은 저장 용량을 줄여도 전체 parameter를 로드해야 한다는 근본 제약을 없애지는 못한다.
- 공식 카드의 TerminalBench 2.1, DeepSWE, HLE 등 수치는 **개발사 자체 평가**로 기록하며 독립 benchmark처럼 해석하지 않았다.

### 기존 방식과의 기술적 차이

기존 voice cloning TTS는 보통 reference audio가 있어야 원하는 화자의 목소리를 만들 수 있고, clone 후 감정·속도·발화 스타일을 바꾸면 speaker identity가 흔들리기 쉽다. Breeze-TTS-2는 이 문제를 세 가지 사용 모드로 분리해 다룬다.

- **Voice Clone**: reference audio에서 화자 특성을 복제.
- **Voice Design**: reference audio 없이 자연어 설명만으로 새로운 voice character를 생성.
- **Voice Direction**: 화자 정체성을 유지하면서 tone, emotion, pace, delivery를 자연어 지시로 조절.
- 웃음·기침 같은 **vocal event**도 지시할 수 있다.
- streaming을 전제로 설계되어 대화형 agent/voice UI에 직접 쓰기 쉽다.

이는 단순히 기존 TTS checkpoint를 더 크게 만든 것이 아니라, **voice identity와 style control을 자연어 instruction space로 끌어올린 것**이 핵심이다.

### 실제 활용 가능성과 제약

- 공식 환경: **Linux, Python 3.10+, NVIDIA CUDA GPU**.
- 공식 카드 측정 기준 warmed H100에서 **TTFA < 40 ms**, **RTF 0.32 (~3.1× realtime)**. 이 수치는 개발사 환경 측정값으로 hardware·batch·설정에 따라 달라질 수 있다.
- eager path는 약 **7.7 GiB GPU memory**, 최소 권장 **12GB GPU**. fast path는 약 **14.4 GiB**, 권장 **24GB GPU**로 안내된다.
- 공식 streaming API가 있고 24 kHz PCM 출력을 지원하므로 실시간 음성 agent, 게임 NPC, call assistant, dubbing prototype에 적합하다.
- vLLM/llama.cpp/Ollama용 범용 LLM 모델이 아니라 **공식 PyTorch inference/streaming stack**을 사용하는 것이 현재 가장 명확한 경로다.
- 가장 큰 제약은 **비상업 model license**다. 기업 서비스 적용 전 라이선스 허가가 필요하다.

### 기존 모델과의 기술적 차이

Thomson-1.0-Small은 Qwen3.6 architecture를 재사용하므로 완전히 새로운 transformer architecture는 아니다. 그러나 공식 카드가 단순 small-scale fine-tuning과 구분되는 **Continual Learning pipeline**을 핵심으로 설명한다.

- **Value realignment → continual pretraining → post-training**의 다단계 pipeline.
- mid-training용 데이터 pool이 **19T tokens 초과**, 그중 약 **200B tokens**를 선별해 사용했다고 카드가 설명.
- 구성은 proprietary professional documents, synthetic rephrasing, general capability replay를 대략 균형 있게 섞어 domain knowledge를 넣으면서 base capability forgetting을 억제하는 방식.
- post-training에서 **DPO + reinforcement learning**을 사용.
- Public AI Constitution과 **Constitutional DPO**로 professional-domain value alignment를 별도 수행.
- Agentic Deep Research harness를 함께 제공하는 방향이다.

따라서 “Qwen 계열의 작은 fine-tune”이라고만 보기보다, **전문지식 continual pretraining과 alignment를 대규모로 다시 수행한 전문 foundation model**로 보는 편이 정확하다. 다만 core architecture는 Qwen3.6 lineage임을 명시해 과장하지 않았다.

### 실제 활용 가능성과 제약

- Hugging Face helper에서 **vLLM, SGLang** 배포 경로와 OpenAI-compatible server 구성이 가능하다.
- 35B total MoE이므로 3B active만 보고 일반 PC 모델로 오해하면 안 된다. 실제 메모리 요구량은 전체 weights와 KV cache·quantization 방식에 좌우된다.
- HF에는 quantization이 있으나 공식 최소 VRAM 수치는 모델 카드에서 확인되지 않아 임의로 적지 않았다.
- 법률·세무·저널리즘 RAG/agent 연구에는 흥미롭지만, high-stakes domain에서는 생성 결과를 전문가 검토 없이 의사결정에 사용하면 안 된다.
- PolyForm Strict 1.0.0 라이선스이므로 상업적 제품화 가능 여부를 permissive license처럼 가정하지 말아야 한다.
- 모델 카드 benchmark는 **개발사 자체 평가**로 취급한다.

- 좋아요 절대수는 LLM보다 작지만 robotics/VLA는 사용자층 자체가 훨씬 좁다. 코드·weights·sample data를 동시에 공개했다는 점과 37,000시간 이상 embodied dataset을 활용한 architecture가 기술적으로 중요하다.

### 기존 방식과의 기술적 차이

GigaBrain-0.7의 핵심은 embodied AI를 `보고 이해하는 모델`, `다음 상태를 예측하는 모델`, `robot action을 생성하는 모델`로 따로 두는 대신 **three-system architecture**에서 연결한 점이다.

- **Understanding**: vision-language 정보 해석.
- **Prediction**: embodied/world dynamics 예측.
- **Action**: 여러 embodiment에 맞는 action generation.
- 공식 자료는 **37,000시간 이상 heterogeneous embodied data**로 pretraining했다고 설명한다.
- real robot, UMI, egocentric, simulation, world-model-generated data를 함께 다루며, one-stage alignment에서 **vision-language understanding과 multi-embodiment action generation을 공동 최적화**한다.

로봇마다 observation/action space가 달라 데이터와 policy를 따로 만드는 문제를 줄이고, 하나의 foundation model에서 여러 embodiment로 knowledge transfer를 시도하는 방향이다.

### 실제 활용 가능성과 제약

- 일반적인 chat LLM이 아니므로 **vLLM/Ollama/LM Studio/OpenAI-compatible API를 바로 붙이는 모델이 아니다**.
- 공식 GitHub가 `giga-datasets`, `giga-train`, `giga-models` 기반 Python 환경과 PaliGemma2 계열 stack을 안내한다.
- sample data는 **LeRobot format**으로 제공되고, robot별 embodiment/action projection이 필요하다.
- 실제 배포는 robot state/action schema, camera observation, control frequency, safety layer를 모델 주변에 추가해야 하므로 단순 local inference보다 시스템 통합 난도가 높다.
- 공식 자료에서 일반 PC 최소 VRAM을 명시하지 않아 임의 추정하지 않았다. Robotics post-training/inference는 CUDA GPU 환경을 염두에 두는 것이 현실적이지만 정확한 요구량은 공식 configuration으로 검증해야 한다.
- 논문/모델 카드의 성능 비교는 **개발사 자체 평가**로 기록한다.
