## 1. samuel-vitorino/sopro-v2-turbo

- Hugging Face: https://huggingface.co/samuel-vitorino/sopro-v2-turbo
- 개발/작성: Samuel Vitorino / HALO Research
- 분야: Text-to-Speech, Zero-shot Voice Cloning, Streaming Speech Synthesis, On-device Audio
- 규모: 120M parameters
- 지원 언어: English, European Portuguese, French, German
- 라이선스: Apache-2.0
- 공개: 공식 기술 글 기준 **2026-08-27**

### 오늘 주목할 근거

Sopro V2 Turbo는 2026-08-27 새로 공개된 Sopro V2 계열의 공개형 경량 모델이다. Hugging Face 공식 모델 카드는 노트북 CPU와 브라우저에서 실행 가능한 120M 모델로 소개하며, 5~20초 참조 음성 기반 zero-shot voice cloning과 streaming을 지원한다고 설명한다.

Hugging Face 공식 페이지의 다운로드 집계는 조사 시점 `Downloads are not tracked` 상태여서 다운로드 수를 임의 추정하지 않았다. 좋아요는 조사 시점 0으로 표시됐다. 절대 Hugging Face 반응 수보다 이번 선정에서 더 크게 본 신호는 **아주 최근 공개 + 기술적 세대 변화 + 실제 배포 가능성 + 공식 코드의 지속적인 후속 업데이트**다.

공식 GitHub `samuel-vitorino/sopro`는 2026-08-30 23:18 UTC(Asia/Seoul 2026-08-31 08:18)에도 버전 갱신 커밋이 있었고, 직전에도 reference normalization과 streaming output gain 관련 수정이 연속 반영됐다. 공개 직후 실제 추론 경로가 빠르게 다듬어지고 있는 상태다.

### 기존 모델과의 기술적 차이

Sopro V2는 단순히 Sopro V1의 weight를 더 학습하거나 크기를 줄인 버전이 아니다. 작성자의 공식 기술 글은 V1에서 사용하던 주요 구성 요소를 V2 개발 과정에서 모두 교체하거나 크게 개선했다고 설명한다.

V1은 Mimi codec, semantic code를 예측하는 autoregressive convolutional model, 나머지 acoustic codebook을 단계적으로 예측하는 non-autoregressive head를 중심으로 했다. V2에서는 큰 Llama tokenizer를 작은 **8,192-token SentencePiece unigram tokenizer**로 바꾸고, 반복 문제가 있던 convolutional AR backbone을 **Transformer decoder**로 교체했다.

또한 V2의 공개 구조는 텍스트와 참조 음성에서 semantic token을 생성하는 autoregressive transformer 뒤에 **flow-matching acoustic head**를 두고, 마지막에 streaming을 고려한 **causal vocoder**로 파형을 만든다. 즉 `텍스트 → discrete semantic token → continuous acoustic generation → causal waveform decoding`으로 역할을 분리한다.

Turbo 모델은 큰 teacher를 그대로 배포하지 않고 **500M teacher → 120M student distillation**을 거친 뒤, acoustic solver를 **reflow 기반 self-distillation으로 32 step에서 기본 2 step으로 줄이는 방향**을 택했다. 이 부분은 단순 ONNX/INT8 포맷 변환이 아니라 학습·생성 경로 자체를 경량/저지연 배포에 맞춰 바꾼 것이다.

따라서 오늘부터 Sopro V2 Turbo의 ONNX, INT8, browser용 변환본, 단순 포맷/양자화, 같은 checkpoint의 경미한 파생본은 모두 같은 Sopro V2 계열로 중복 제외한다.

### 실제 활용 가능성과 제약

- 공식 Python 패키지: `pip install -U sopro`
- CLI와 Python API 모두 제공하며 `--stream` streaming 경로가 있다.
- CPU int8 AR weight 옵션을 공식 CLI에서 제공한다.
- 브라우저에서는 ONNX runtime을 이용한 완전 로컬 데모를 제공한다.
- macOS에서는 기본 CPU를 사용하고 MPS도 선택할 수 있으며, CUDA도 자동 선택하는 실행 경로가 안내돼 있다.
- 공식 모델 카드 기준 M3 CPU에서 약 **300 ms time-to-first-audio**, offline 0.24 RTF, streaming 0.21 RTF, H100 0.07 RTF를 보고한다. 이 속도 수치는 **개발사 자체 평가**다.
- vLLM/SGLang/llama.cpp/Ollama/LM Studio용 LLM 모델은 아니다. 음성 합성 전용 Python/ONNX runtime으로 사용하는 것이 맞다.
- MCP/Agent에서 직접 MCP 서버 역할을 하는 모델은 아니지만, 음성 Agent의 TTS backend로 붙이기 쉽다. 특히 로컬 음성 비서, 전화/실시간 대화 UI, 개인정보를 클라우드에 보내기 어려운 환경에 실용성이 높다.
- 한국어는 공식 지원 언어가 아니다.
- 모델 카드가 명시한 약점은 mixed-language 문장, 숫자·기호·약어의 발음, streaming 경로와 offline 경로의 품질 차이 등이다.
- training code는 조사 시점 공개 계획이 없다고 안내돼 있다.
- watermark가 포함되지 않았으며 작성자도 타인 사칭에 사용하지 말 것을 명시한다. Voice cloning 서비스에는 별도의 동의·오용 방지 정책이 필요하다.

### Benchmark 주의

공식 기술 글의 Seed-TTS, LibriSpeech 및 latency/RTF 결과는 작성자가 공개한 **개발사 자체 평가**다. 동일 하드웨어·동일 코드베이스로 제3자가 재현한 독립 비교로 취급하지 않았다.

## 2. Muse-Ltd/Muse-Robotics-1

- Hugging Face: https://huggingface.co/Muse-Ltd/Muse-Robotics-1
- 개발/작성: Muse Ltd.
- 분야: Robotics, Vision-Language-Action (VLA), Language-conditioned Manipulation
- 규모: 모델 카드 기준 약 **120M parameters**; Hugging Face 표시는 0.1B
- 입력: 외부 카메라 + wrist camera + robot proprioceptive state + 자연어 instruction
- 출력: 16-step chunk의 연속 7D delta action
- 라이선스: MIT
- 언어 태그: English

### 오늘 주목할 근거

Hugging Face의 `vla` Trending 페이지에서 조사 시점 상위권에 새로 등장했고, **최근 2~3일 내 업데이트**, **23 downloads/month, 2 likes**가 표시됐다. 수치는 2026-08-31 조사 시점 스냅샷이다.

절대 다운로드 수는 아직 매우 작다. 따라서 인기 수치만 놓고 보면 대형 모델과 비교할 단계가 아니다. 그럼에도 이번에 선정한 이유는 최신 VLA들이 거대한 pretrained VLM을 동결하거나 개조해 사용하는 흐름과 달리, **약 120M 규모로 vision·language·fusion·deliberation·action generation 전부를 control objective에 맞춰 처음부터 공동 학습**하는 설계를 명시하고 있기 때문이다. 작은 embodied model 연구의 방향성 자체가 기술적으로 의미 있다.

### 기존 모델과의 기술적 차이

Muse-Robotics-1은 기존 공개 VLA checkpoint의 LoRA나 단순 fine-tune으로 설명되지 않는다. 모델 카드에 따르면 모든 구성 요소를 random initialization에서 end-to-end로 학습한다.

두 카메라 입력은 하나의 small ViT를 공유해 처리하고, 별도의 view-type embedding으로 외부 카메라와 wrist 카메라를 구별한다. 자연어는 **6-layer bidirectional transformer**, 그 뒤에는 vision/language/state token을 함께 처리하는 **12-layer perceive transformer stack**이 있다.

가장 눈에 띄는 부분은 바로 action을 디코딩하지 않고 **8개의 learned latent `plan` tokens**으로 정보를 압축한 뒤, 하나의 shared transformer block을 **3회 반복 적용**해 plan token을 갱신하는 `thinking` stage다. 각 반복에는 iteration embedding이 들어가므로 같은 block을 재사용하면서도 단계별 동작을 다르게 학습한다. 모델 카드가 말하는 `deliberation`은 별도의 텍스트 chain-of-thought가 아니라, action 전에 연속 latent 공간에서 계획 표현을 여러 번 정제하는 구조다.

마지막 action generator는 16개 미래 action chunk를 **rectified flow**로 생성한다. 학습 때 clean action과 Gaussian noise 사이의 velocity field를 학습하고, 추론 시 10 Euler steps로 noise에서 action을 복원한다. 또한 미래 proprioceptive state를 예측하는 작은 auxiliary objective로 plan latent가 단순 상수 표현으로 붕괴하지 않고 forward-looking information을 갖도록 유도한다.

이 구조적 조합은 `작은 fully-trainable VLA + 반복 latent plan refinement + rectified-flow action chunk generation`이라는 명확한 연구 목적을 갖는다. 따라서 기존 GigaBrain, Isaac, TurboVLA 등의 단순 파생본으로 보지 않고 별도 신규 계열로 판정했다.

### 실제 활용 가능성과 제약

- 모델은 Hugging Face Transformers/vLLM 계열 범용 LLM이 아니라 custom `nova_vla` PyTorch stack으로 로드한다.
- 공식 카드의 deployment 예시는 FastAPI `Policy` wrapper와 `device="cuda"`를 사용한다.
- 모델 자체는 약 120M으로 작지만, 실제 사용에는 카메라 전처리, robot state normalization, action safety layer, robot controller 연동이 필요하다. `120M이므로 일반 PC만 있으면 로봇 제어가 가능하다`고 단순 해석하면 안 된다.
- vLLM, SGLang, llama.cpp, Ollama, LM Studio, OpenAI-compatible API 지원은 공식 카드에서 확인되지 않았다.
- MCP를 네이티브로 지원하지 않는다. 다만 로봇 제어 서버를 MCP tool 뒤에 두는 상위 orchestration은 별도 구현 가능하다.
- 모델 카드는 장기 계획, contact-rich manipulation, 크게 새로운 scene에서 성능 저하 가능성을 직접 명시한다.
- uncertainty estimation, collision avoidance, high-level planning이 내장돼 있지 않으므로 실제 로봇에서는 workspace limit, velocity/force threshold, emergency stop, human supervision 같은 안전 계층이 필수다.
- 연구용 base에 가까우며, 특정 로봇 embodiment에 바로 범용 적용할 수 있는 완성형 controller로 보기는 어렵다.

### Benchmark 주의

공식 모델 카드는 held-out episode에서의 evaluation 구조를 설명하지만, 조사 시점 독립적인 공개 benchmark 결과나 대규모 제3자 검증 수치를 확인하지 못했다. 따라서 정량 성능 우위를 주장하지 않았다.

또한 `g-group-ai-lab/gipformer1.5-65M-rnnt`는 최근 공개된 65M Vietnamese ASR로 확인했지만 조사 시점 9 downloads/month, 0 likes 수준이고 핵심 구조가 Zipformer Transducer 기반이다. 지역 언어 edge ASR로 실용적이지만 오늘의 기술적 독창성·상승 신호 기준에서는 Sopro V2와 Muse-Robotics-1보다 우선순위가 낮아 선정하지 않았다.

## 오늘의 Top Pick

**samuel-vitorino/sopro-v2-turbo**

120M 규모에서 zero-shot voice cloning, CPU streaming, browser ONNX 실행을 동시에 겨냥하고 있고, Sopro V1의 핵심 구성요소를 단순 미세조정이 아니라 AR backbone·acoustic generation·vocoder 수준에서 재설계했다. 공개 직후 공식 GitHub가 2026-08-31 KST 오전까지 활발히 수정되고 있어 개발자가 바로 시험해 볼 수 있는 실사용성과 최근성이 가장 높다고 판단했다.
