## 1. kyutai/pocket-tts — 오늘의 Top Pick

### 기본 정보

- **Hugging Face:** https://huggingface.co/kyutai/pocket-tts
- **개발사/작성자:** Kyutai
- **분야:** Text-to-Speech, voice cloning, streaming audio
- **규모:** 공식 모델 카드 기준 **100M parameters**
- **HF 모델 라이선스 표시:** **CC-BY-4.0**. 다만 모델 파일 접근 시 연락처 공유 및 별도 금지 사용 조건 동의가 요구된다.
- **공식 코드:** https://github.com/kyutai-labs/pocket-tts — GitHub 저장소 코드는 MIT License로 공개되어 있어 모델 weights 조건과 구분해야 한다.

### 오늘 주목할 근거

Pocket TTS 자체는 Kyutai가 **2026-01-13** 공식 블로그에서 공개한 모델이므로 오늘 처음 등장한 모델은 아니다. 그러나 `introduced-models.md`에는 없고, 현재 Hugging Face Trending에 다시 노출되는 가운데 **2026년 8월 공식 GitHub에서 training code를 새로 공개**해 개발자 가치가 다시 크게 높아진 사례로 선정했다.

2026-08-28 KST 조사 시점 Hugging Face 모델 페이지 스냅샷은 다음과 같다.

- 좋아요: **852**
- 최근 1개월 다운로드: **1,282**
- 이 모델을 사용하는 Spaces: **100개**
- 공식 GitHub: **113 commits**, 약 **942 forks**가 페이지에 노출될 정도로 생태계 활동이 활발함
- ONNX Runtime Web, Candle/WASM, MLX, C++/ONNX Runtime, C# 등 여러 커뮤니티 포팅과 Home Assistant/Wyoming, OpenAI-compatible streaming server, Unity 통합 사례가 공식 README/모델 카드에 연결됨

### 기존 방식과 무엇이 다른가

많은 고품질 TTS 모델은 GPU 또는 원격 API를 전제로 한다. Pocket TTS의 핵심은 **작은 100M 모델을 CPU에서 streaming으로 실제 사용 가능한 속도로 돌리는 것**이다. 공식 자료는 MacBook Air M4 CPU에서 약 6× real-time, 약 200 ms first audio chunk, 2 CPU cores를 예시로 제시한다. 이 수치는 **개발사 자체 측정**이다.

또한 음성을 한 번에 모두 만든 뒤 재생하는 방식이 아니라 스트리밍 출력을 제공하고, 짧은 음성 샘플에서 voice state를 만들어 voice cloning에 사용할 수 있다. 모델이 작기 때문에 브라우저/WASM, embedded, C++/C#/Rust 같은 경량 런타임으로 포팅하기도 쉽다는 점이 대형 TTS와 실무적으로 가장 큰 차이다.

### 실제 활용 가능성과 제약

- `pip install pocket-tts`, CLI, Python API, 로컬 HTTP server를 공식 지원한다.
- 공식 HF 카드 기준 Python 3.10–3.14, PyTorch 2.5+를 사용하며 **GPU용 PyTorch가 필요하지 않다**.
- 일반 PC CPU에서 실행하는 것이 이 모델의 주 용도이므로 별도 고성능 GPU가 없는 로컬 Agent 음성 출력, Home Assistant, 게임/NPC, 데스크톱 앱 TTS에 특히 적합하다.
- 공식 모델 카드에서는 조사 시점 **English only**라고 적혀 있지만, 최신 공식 GitHub README는 English/French/German/Portuguese/Italian/Spanish 지원을 표시한다. 두 1차 출처가 서로 달라 **HF 체크포인트 자체의 확정 언어 범위는 English 기준으로 보수적으로 판단**하고, 다국어는 최신 코드/모델 패키지의 업데이트 사항으로 취급한다.
- HF Inference Providers에는 조사 시점 배포되어 있지 않다.
- voice cloning은 무단 사칭·기만 등에 대한 명시적 금지 조건이 있으므로 서비스 적용 전 모델 접근 조건을 확인해야 한다.

## 2. PerceptronAI/Isaac-0.5

### 기본 정보

- **Hugging Face:** https://huggingface.co/PerceptronAI/Isaac-0.5
- **개발사:** Perceptron AI
- **분야:** Robotics, Vision-Language Model, embodied reasoning, robot control
- **규모/구조:** **36B total parameters**, Qwen-family VLM backbone 기반 **sparse experts**
- **공식 코드:** https://github.com/perceptron-ai-inc/isaac
- **코드 라이선스:** Apache-2.0. 모델 weights/artifacts의 조건은 HF 저장소에 따르도록 명시되어 있으나, 조사 시점 weights가 아직 `COMING SOON` 상태이므로 weight license는 추측하지 않는다.

### 오늘 주목할 근거

Hugging Face Trending에 최근 업데이트 모델로 노출됐고, 조사 시점 HF 좋아요는 **21**이다. 다운로드는 아직 추적되지 않는다. 공식 GitHub는 조사 시점 **49 stars, 3 commits**의 매우 초기 상태다.

관심 수치 자체는 Pocket TTS보다 작지만, 새 모델이 다루는 범위가 넓다. 하나의 36B sparse model이 이미지·비디오·언어·robot state·과거 action을 받아 text, normalized coordinates, task state, discrete/continuous robot actions까지 출력하도록 설계됐다.

### 기존 방식과 무엇이 다른가

Isaac 0.5는 단순 VLM에 robot action head를 얹는 수준보다 더 통합적인 구조를 지향한다.

- text, vision, time, robot state, action history를 **하나의 shared sequence/backbone**으로 처리
- MoE layer마다 **256 learned experts + null route**를 두고 token별로 0–8 routed experts를 선택
- discrete action은 **2,048 FAST action vocabulary**로 autoregressive하게 생성
- continuous action은 backbone state가 별도 **Flow expert + 36-block diffusion transformer**를 조건화해 action chunk를 생성
- 현재 action chunk가 실행되는 동안 최신 관측을 이용해 다음 chunk를 예측하는 **real-time closed-loop control** 구조
- 일반 비디오에서도 미래의 motion/contact/grasp/task progress 같은 compact future percept를 예측하는 **semantic world modeling**을 통해 로봇 action label이 없는 영상도 control representation 학습에 활용

개발사는 35개 이상 robot systems, 100,000 hours robot experience, 1M hours general video, 3T multimodal tokens를 사용했다고 밝힌다. 또한 general video를 늘렸을 때 특정 held-out action-loss 목표에서 필요한 teleoperation 시간이 약 5,900h→28h로 줄었다고 주장한다. 이는 **개발사 자체 평가/학습 scaling 실험**이며 독립 검증 결과로 간주하지 않는다.

### 실제 활용 가능성과 제약

- 공식 코드는 Hugging Face LeRobot integration, fine-tuning/inference path, reference policy 구조를 제공한다.
- 모델 크기가 36B이고 multimodal sparse backbone + diffusion action head를 포함하므로 일반적인 저사양 PC용 모델이 아니다. 공식적인 최소 VRAM 수치는 확인되지 않아 임의로 추정하지 않는다.
- 가장 중요한 제약은 **2026-08-28 조사 시점 HF 페이지가 `Download the weights (COMING SOON)`이라고 명시**한다는 점이다. 따라서 지금 바로 로컬에서 checkpoint를 내려받아 재현하는 단계는 아직 열려 있지 않다.
- 공식 GitHub README 역시 mHarmony/TensorStream runtime이 별도 관리되고, clean checkout만으로 rendering/training/inference가 완전히 준비되는 것은 아니라고 안내한다.
- 따라서 오늘은 “즉시 배포 가능한 모델”보다 **새로운 embodied foundation model 구조를 추적할 가치가 큰 후보**로 본다.

## 3. briaai/Fibo-1.5

### 기본 정보

- **Hugging Face:** https://huggingface.co/briaai/Fibo-1.5
- **개발사:** BRIA AI
- **분야:** Text-to-Image, structured image generation
- **규모/구조:** **8B DiT**, flow-matching; SmolLM3-3B text encoder, DimFusion conditioning, Wan 2.2 VAE
- **언어 태그:** English
- **배포 형식:** Diffusers / BF16
- **라이선스:** HF에서 `bria-fibo`로 표시. weights는 **non-commercial use only**로 안내되며 상업 사용은 별도 Bria license가 필요하다.

### 오늘 주목할 근거

공식 모델 카드의 News에 **2026-08-24 Fibo 1.5 공개**가 명시되어 있다. 조사 시점 HF 스냅샷은 좋아요 **22**, 최근 1개월 다운로드 **378**, Community **2**다.

숫자만 보면 대형 LLM보다 작지만, image generation에서 실제 비용을 좌우하는 sampling step을 크게 줄인 최신 업데이트이고 Hugging Face Trending에 노출되고 있어 선정했다.

### 기존 모델과의 기술적 차이

중복 규칙상 중요한 점은 **Fibo 1.5가 FIBO 1.0과 완전히 다른 차세대 architecture는 아니라는 것**이다. `introduced-models.md`에 FIBO 계열 자체가 아직 없으므로 이번에 **FIBO 계열을 처음 소개하는 현재 대표 버전**으로 기록한다. 향후 같은 계열의 단순 버전·양자화·포맷 변형은 다시 소개하지 않는다.

FIBO의 핵심 차별점은 일반 자연어 prompt만 사용하는 대신, VLM이 짧은 user intent를 최대 1,000+ words 수준의 **structured JSON caption**으로 확장하고 lighting, camera, composition, depth 등 속성을 구조화해 image model에 전달한다는 점이다. 이 structured supervision은 한 속성만 바꿀 때 전체 장면이 흔들리는 prompt drift를 줄이고, iterative refinement를 더 예측 가능하게 만드는 것을 목표로 한다.

Fibo 1.5의 변화는 architecture를 바꾸는 것이 아니라 추론 방식을 바꾸는 post-training이다.

1. **DMD (Distribution Matching Distillation)**로 4–6 step student로 축약
2. **DMD-R** stage로 realism/textures를 추가 개선
3. 결과적으로 기존 FIBO의 50-step + CFG 방식 대신 **4–6 steps, no classifier-free guidance**로 동작

공식 문서가 명시하듯 8B DiT, SmolLM3-3B encoder, DimFusion, Wan 2.2 VAE, JSON prompting은 FIBO base와 동일하다. 따라서 이 보고서에서는 “FIBO 1.5를 독립 신계열”이라고 과장하지 않는다.

개발사가 제시한 247개 blind pairwise human comparison 결과는 **개발사 자체 평가**다.

### 실제 활용 가능성과 제약

- Hugging Face Diffusers로 BF16 local inference가 가능하고, CUDA 예제와 `enable_model_cpu_offload()` 옵션이 공식 카드에 제공된다.
- 8B image DiT이므로 작은 CPU-only 모델로 보기는 어렵다. 공식 minimum VRAM 수치는 확인되지 않아 숫자를 추정하지 않는다.
- source weights, ComfyUI, Bria API/Fal 등의 경로가 공식 카드에 연결되어 있다.
- Fibo 1.5 checkpoint는 few-step distillation에 특화되어 있어 **base FIBO용 fine-tuning code를 이 checkpoint에 그대로 적용하지 말라**고 공식 문서가 명시한다. fine-tune이 필요하면 base FIBO에서 시작해야 한다.
- 상업 서비스에는 일반 오픈소스 가중치처럼 바로 쓰면 안 되며 **별도 commercial license** 확인이 필요하다.

## 중복 검증 및 제외한 주요 후보

오늘 조사에서 `huggingface-model-trends/introduced-models.md`를 먼저 확인했다. 이미 등록된 **Qwen/Qwen3.8-Flash-Next, zai-org/GLM-5.3-Flash, BreezeBlue/Breeze-TTS-2** 등 현재 상위 Trending 모델은 중복으로 제외했다.

또한 다음 후보는 신규 계열로 기록하지 않았다.

- **kai-os/Carnice-V3:** 모델 카드가 Qwen/Qwen3.8-27B에 rank-64 rsLoRA를 merge한 checkpoint라고 명시하며, behavioral quality gate도 통과하지 못했다고 적고 있다. 기존 Qwen3.8 계열의 직접 파생본이므로 제외.
- **pipecat-ai/phonellm-alpha-1:** voice-agent/tool-calling 목적과 low-latency tuning은 흥미롭지만, 공식 카드가 NVIDIA Nemotron 3 Nano 30B-A3B를 full-parameter supervised fine-tuning한 모델이라고 명시한다. 이번 중복 규칙에서는 새로운 base architecture보다 **직접 파생·전문화 fine-tune** 성격이 강하다고 판단해 제외.

## 오늘의 Top Pick

### **kyutai/pocket-tts**

이유는 단순 benchmark 순위가 아니라 **일반 PC CPU에서 실제 서비스 가능한 100M streaming TTS**, voice cloning, 로컬 HTTP/Python/CLI, 100개 HF Spaces, 다양한 browser/embedded/C#/C++/Rust 생태계, 그리고 2026년 8월 training code 공개까지 이어졌기 때문이다. Agent가 음성을 출력해야 할 때 GPU를 별도 점유하지 않고 로컬에서 붙일 수 있다는 실무적 장점이 특히 크다.
