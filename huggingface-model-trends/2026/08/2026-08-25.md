# Hugging Face 주목 모델 — 2026-08-25

> 기존 ChatGPT 대화에서 마이그레이션한 보고서입니다. 수치성 지표는 조사 당시의 스냅샷이며 이후 변동될 수 있습니다.

## 1. FireRedTeam/FireRedAudio

- Hugging Face: https://huggingface.co/FireRedTeam/FireRedAudio
- 개발: FireRed Team
- 분야/규모: 범용 Audio Language Model, 공유 9B LLM backbone
- 주목 근거: 2026-08-21 코드와 모델 공개. 음성 인식, 오디오 이해, zero-shot/instruct TTS, 음성 편집, 최대 약 1시간 오디오의 temporal grounding을 한 모델에서 다룸.
- 기술적 차이: 이해용 Audio Encoder와 생성용 RedAE 표현을 분리하면서 동일한 언어·추론 backbone을 공유하는 구조. 기존의 STT+LLM+TTS+편집 모델 조합보다 통합도가 높음.
- 활용/제약: 회의·팟캐스트 검색/요약, 음성 에이전트, 음성 복제·편집에 활용 가능. 공식 생성·이해 지원은 주로 중국어/영어이며 CUDA 및 추가 오디오 의존성이 필요함.
- 비고: 개발팀이 제시한 벤치마크 수치는 자체 평가가 포함되어 있으므로 독립 검증값으로 보지 않음.

## 2. openbmb/MiniCPM5-1B

- Hugging Face: https://huggingface.co/openbmb/MiniCPM5-1B
- 개발: OpenBMB
- 분야/규모: 초경량 Text LLM, 약 1.08B, 131K context
- 주목 근거: 공개 후 다운로드와 좋아요가 빠르게 누적되고 다수의 양자화/파생 배포본이 생성됨. 1B급에서 reasoning과 tool calling을 함께 강조한 점이 눈에 띔.
- 기술적 차이: 동일 체크포인트에서 thinking/non-thinking 모드를 선택할 수 있고, SFT 이후 RL 및 On-Policy Distillation을 적용해 소형 모델의 추론·코딩·도구 호출 능력을 강화함.
- 활용/제약: 로컬 명령 해석, 소형 코딩/에이전트, MCP/tool calling, 사내 자동화에 적합. 영어·중국어 중심이며 대형 모델 수준의 복잡한 추론에는 한계가 있음.

## 3. TomoroAI/tomoro-colqwen3-embed-4b

- Hugging Face: https://huggingface.co/TomoroAI/tomoro-colqwen3-embed-4b
- 개발: Tomoro AI
- 분야/규모: Visual Document Retrieval / 멀티모달 RAG, 4B, 320차원 multi-vector
- 주목 근거: Visual Document Retrieval 계열에서 빠르게 채택되고 있으며 PDF/이미지뿐 아니라 짧은 영상 검색까지 하나의 retrieval 모델로 처리함.
- 기술적 차이: Qwen3-VL-4B 계열의 비전 기능과 Qwen3-Embedding 계열의 검색 능력을 결합하고, 문서/질의를 하나의 벡터로 과도하게 압축하지 않는 ColPali/ColBERT식 multi-vector MaxSim 검색을 사용함.
- 활용/제약: 계약서·팩스·보고서에서 관련 페이지 선검색, 표/차트 검색, 영상 장면 검색에 유용. custom code와 비교적 큰 GPU 메모리가 필요할 수 있으며 배포 환경에서 PyTorch/FlashAttention 버전 호환성을 확인해야 함.
- 비고: 개발팀이 제시한 검색 벤치마크는 자체 평가임.

## 4. ayousanz/kodama-ja-streaming-small

- Hugging Face: https://huggingface.co/ayousanz/kodama-ja-streaming-small
- 개발: ayousanz
- 분야/규모: 일본어 Streaming ASR, 약 0.1~0.14B, ONNX 배포 약 324MB
- 주목 근거: 신규 소형 모델임에도 ASR 트렌딩에서 빠르게 반응이 증가. ReazonSpeech v2 약 35,000시간 전체로 full fine-tuning하고 CPU/ONNX 스트리밍 배포 자산을 함께 제공함.
- 기술적 차이: 영어용 moonshine-streaming-small을 일본어 대규모 음성으로 전면 미세조정해 저지연 일본어 스트리밍 용도로 특화함.
- 활용/제약: GPU 없는 PC의 일본어 실시간 자막·받아쓰기·음성 명령에 적합. 개발자가 직접 밝힌 약점으로 잡음 민감도, streaming 시 정확도 하락, 일부 데이터셋의 hallucination이 있으며 한국어는 지원하지 않음.
- 비고: 성능 비교 수치는 모델 개발자의 자체 평가임.

## 5. ai-sage/Giga-Embeddings-instruct-10B-A1.8B-0826

- Hugging Face: https://huggingface.co/ai-sage/Giga-Embeddings-instruct-10B-A1.8B-0826
- 개발: ai-sage
- 분야/규모: Text Embedding / RAG, 총 10B급 MoE, 토큰당 약 1.8B 활성
- 주목 근거: 초기 다운로드/좋아요 규모보다 DeepSeek-V3 계열의 MLA+MoE 구조를 임베딩 인코더로 전환한 기술적 독창성이 주목 포인트.
- 기술적 차이: causal LLM 구조를 양방향 embedding encoder로 바꾸고 routed experts를 사용함. 검색 질의에는 instruction prefix를 붙이고 문서는 raw embedding하는 방식.
- 활용/제약: 영어·러시아어 중심 RAG, semantic search, deduplication에 활용 가능하며 vLLM/SGLang 기반 OpenAI 호환 embeddings API 구성이 가능. 한국어 품질과 독립 벤치마크 검증은 부족함.
- 비고: 모델 카드의 MTEB/throughput 수치는 개발팀 자체 측정임.
