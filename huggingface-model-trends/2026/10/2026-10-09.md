## 1. Perplexity pplx-embed-v2-late

**태그:** multimodal-retrieval, late-interaction, ColBERT, multi-vector, text-to-image-retrieval, visual-document-search, multilingual, representation-distillation.

### 신규 예외를 인정하는 근거

기존 [10/5 소개 모델](2026-10-05.md)인 **pplx-embed-v2-context-9b-preview**는 여러 문서 chunk를 함께 읽고 **chunk당 하나의 2,048차원 벡터**를 반환한다. 이번 late 분기는 **token별 128차원 벡터를 유지**하고 질의 token마다 가장 잘 맞는 문서 token을 찾아 점수를 합산하는 **MaxSim**을 사용한다. 문서를 미리 인코딩하되 검색 단계에서 여러 token 쌍을 비교하는 구조다. [기존 context 카드](https://huggingface.co/perplexity-ai/pplx-embed-v2-context-9b-preview), [공식 구조 설명](https://www.perplexity.ai/hub/blog/multimodal-embeddings-beyond-a-single-vector).

다음 세 변화가 함께 확인돼 단순 크기·포맷 변형을 넘는 **멀티모달 late-interaction 확장 분기**로 판정했다.

1. chunk-level 단일 벡터·cosine 검색에서 token-level multi-vector·MaxSim 검색으로 출력과 scoring 구조가 바뀐다.
2. 텍스트뿐 아니라 **이미지·렌더링된 PDF 페이지**를 직접 인코딩한다. 기존 context 모델의 텍스트 chunk 입력과 달리 OCR 결과로 바꾸지 않은 문서 이미지 검색이 가능하다.
3. 내부 18B ColBERT teacher에서 **token-level LEAF 방식 표현 정렬 증류**를 수행한다. 이전 context 모델의 context-compression teacher·chunk soft target 학습과 다른 목표이며, 0.6B와 9B가 같은 임베딩 공간을 공유한다.

공통 Qwen 기반과 내부 ColBERT 연구 계보를 인정하며 완전히 무관한 foundation model이라고 소개하지 않는다. 반대로 기존 context 모델이 내부 ColBERT에서 출발했다는 사실만으로 이번 공개 checkpoint의 이미지·multi-vector 인터페이스가 이미 제공됐다고 보지도 않는다. **두 크기, 양자화·포맷 배포, 경미한 후속 파생본은 한 계열**이다. [late 학습 카드](https://huggingface.co/perplexity-ai/pplx-embed-v2-late-0.6b#training), [공식 발표](https://www.perplexity.ai/hub/blog/multimodal-embeddings-beyond-a-single-vector).

### 구조·학습·규모를 읽는 법

공식 발표는 **186M query-document pairs, 594개 데이터셋, 46개 언어**를 밝힌다. 원래 pair 구성은 text-to-text 88.3%, text-to-image 8.3%, text-to-visual-document 3.4%이며 학습 sampling 비중은 각각 56.5%, 30.9%, 12.6%다. 원본 데이터 비율과 실제 학습 혼합 비율을 혼동하지 않는다. 0.6B는 전체 fine-tuning, 9B는 마지막 8개 Transformer 층 전체 학습과 나머지 층·vision encoder의 LoRA 적응을 사용했다. [학습 설명](https://www.perplexity.ai/hub/blog/multimodal-embeddings-beyond-a-single-vector), [9B 카드](https://huggingface.co/perplexity-ai/pplx-embed-v2-late-9b).

0.6B는 Qwen3.5-0.8B text tower를 24층에서 12층으로 줄인다. 공식 설명상 전체 약 594M 가운데 token embedding 약 254M, vision 약 100M, text 연산부 약 240M이다. 카드의 **active 340M**은 이미지 인코딩 기준이며 모델 전체가 340M이라는 뜻은 아니다. 공개 config의 12-layer text tower와 별도 vision tower, 128차원 projection, MultiVectorMask·Normalize 모듈도 확인했다. 이번 신규 선정의 근거는 작은 크기 자체가 아니라 앞의 검색 구조·모달리티·학습 목표 변화다. [config](https://huggingface.co/perplexity-ai/pplx-embed-v2-late-0.6b/blob/main/config.json), [모듈 목록](https://huggingface.co/perplexity-ai/pplx-embed-v2-late-0.6b/blob/main/modules.json), [projection](https://huggingface.co/perplexity-ai/pplx-embed-v2-late-0.6b/blob/main/1_Dense/config.json).

**집계 범위 주의:** 위 표는 HF API가 반환한 대표 tensor 집계다. 0.6B의 실제 파일 header를 대조하면 backbone 594,321,600개 외에 별도 Dense projection 131,072개가 있어 두 가중치 파일의 합은 **594,452,672개**다. 9B도 별도 projection을 포함하는 export이므로 API 숫자를 모든 파일의 완전한 총합이라고 단정하지 않았다.

### 실무 활용 예

- 스캔 문서·슬라이드·도표의 페이지를 이미지로 인덱싱하고 자연어 질의로 관련 페이지 찾기
- offline 문서 인덱스는 9B로 만들고 online 질의는 0.6B로 인코딩하는 비대칭 검색
- 기존 RAG의 후보 문서 검색 품질을 비교하되 multi-vector 인덱스의 저장 공간·scoring 비용도 함께 측정하기

공식 발표의 ViDoRe v3 image nDCG@10은 0.6B 양쪽 사용 62.3%, 0.6B 질의+9B 문서 63.5%, 9B 양쪽 사용 65.2%다. **개발사 평가**이며 한국어 사내 자료나 모든 시각 검색에서 같은 개선을 보증하지 않는다. 기존 context checkpoint와 통제된 동일 조건 비교를 제시하는 수치도 아니다. token별 벡터는 단일 벡터보다 저장량과 비교 비용이 늘어나므로 기존 ANN 인덱스에 그대로 교체하면 된다고 가정하지 않는다. [평가·비용 설명](https://www.perplexity.ai/hub/blog/multimodal-embeddings-beyond-a-single-vector).

### 실행 예와 주의점

**sentence-transformers >= 6.0.0, transformers >= 5.4.0**을 요구한다. 공식 카드의 전용 **MultiVectorEncoder** 경로를 사용한다. HF 페이지 상단의 자동 생성 SentenceTransformer 예시보다 본문의 multi-vector 사용법과 실제 배포 설정을 우선해야 한다.

```python
from PIL import Image
from sentence_transformers import MultiVectorEncoder

model = MultiVectorEncoder(
    "perplexity-ai/pplx-embed-v2-late-0.6b",
    revision="8fc2de24534aa3610d85fa59c463313a5f096455",
    device="cuda",
)
queries = model.encode_query(["Which page shows the quarterly revenue chart?"])
pages = model.encode_document([Image.open("page.png").convert("RGB")])
scores = model.similarity(queries, pages)  # MaxSim
print(scores)
```

공식 사용 흐름에 revision을 고정한 예이며 이번 조사에서는 실행하지 않았다. 실제 GPU 최소 메모리·지연시간·한국어 검색 정확도는 별도 검증이 필요하다. [사용법](https://huggingface.co/perplexity-ai/pplx-embed-v2-late-0.6b#usage-sentence-transformers).

- **질의와 문서는 encode_query / encode_document로 구분한다.** 배포 설정은 각각 `[Q]`·`[D]` prefix와 MaxSim을 지정한다. PyLate 기본 marker 위치와도 다르다. [설정](https://huggingface.co/perplexity-ai/pplx-embed-v2-late-0.6b/blob/main/config_sentence_transformers.json).
- 모델 카드가 지원한다고 밝힌 범위는 text-only 또는 image-only encoding batch다. **text+image 혼합 입력은 지원하지 않는다.** 설정 파일에 관련 modality 항목이 있다고 카드의 제한을 무시하지 않는다.
- 실제 export 설정은 **query 1,024 / document 4,096 tokens**다. 기반 config의 262,144 positional 한도를 그대로 검증된 검색 입력 한도라고 소개하지 않는다. [encoding 설정](https://huggingface.co/perplexity-ai/pplx-embed-v2-late-0.6b/blob/main/sentence_bert_config.json).
- 기존 context-9b-preview의 2,048차원 INT8 chunk 인덱스와 이번 token별 128차원 공간을 섞지 않는다. 공식 호환성 주장은 **late 0.6B와 late 9B 사이**에 적용된다.
- native Sentence Transformers 모듈을 사용하며 custom Python code는 필요하지 않다고 카드가 설명한다. 패키지 요구 버전과 checkpoint revision은 고정해 재현성을 확인한다.

- **Kandinsky 6.0·d1-omni**, **EmbeddingGemma 2·Prism·EMA**, **PixelUMM·UniMate**와 기존 Qwen·MiniMax·LTX 계열의 양자화·크기·LoRA·포맷 변형은 재소개하지 않았다.
