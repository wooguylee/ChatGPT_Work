## 1. Nemotron 3.5 Transcribe: 기존 Lightning의 주요 음성 확장

### 신규성 판단과 재사용 계보

인덱스의 Nemotron 3.5 Lightning 언어 모델, Nemotron 3.5 ASR Streaming, Nemotron 3 Diarization을 먼저 확인했다. 이름·파라미터 증가·성능표만으로 별도 계열을 만들지 않았다.

[NVIDIA 공식 연구 발표](https://research.nvidia.com/labs/nemotron/NVIDIA-Nemotron-3.5-Transcribe/)에 따르면 기존 **Lightning 30B-A3B hybrid Mamba–Transformer MoE**에 Transformer 음성 encoder와 동결된 Nemotron 3 Diarization을 결합한다. **Parallel Expert Encoder**가 화자 활동 정보를 ASR 표현에 주입하고 serialized output training으로 화자별 전사를 학습한다. **LLM 자체 아키텍처는 변경하지 않는다.** 독립 from-scratch 언어 계열이나 Lightning을 대체하는 새 언어 세대라고 주장하지 않는다.

같은 발표는 답변 토큰량에 따른 데이터 혼합, ASR 표본별 여러 작업 지시, 단일 SFT 뒤 전사 정확도 중심의 짧은 RL, 공동 MTP 학습을 설명한다. 새 음성 입력 경로·화자 정보 결합·학습 구성을 함께 확인했으므로 **주요 modality/구조 확장 예외**로 판단한다. 단순한 전사 프롬프트 fine-tune이나 저정밀 변환으로 인정한 것이 아니다. CTC adapter는 생성한 전사와 오디오를 사후 정렬해 단어 timestamp를 제공한다.

기존 Streaming은 [NeMo Speech 공식 README](https://github.com/NVIDIA-NeMo/Speech/blob/main/README.md)의 cache-aware FastConformer 기반 저지연 ASR 계열이다. 이번 offline SALM을 그 모델의 단순 대형 버전으로 묶거나, 반대로 streaming 지원이 자동 계승된다고 해석하지 않는다.

### 기능·실행 범위

[공식 모델 카드](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Transcribe-30B-A4B)는 **40개 언어·최대 1시간 녹음·65,536-token 문맥**, 오디오와 지시문에서 텍스트 응답을 만드는 offline 모델로 설명한다. 전사·번역·문맥 전사·오디오 질의응답을 지원한다. 화자 번호는 녹음 내부 구분이지 실명 식별이 아니다. 제품명의 30B-A4B를 전체 30B/활성 4B라는 정확한 수로 옮기지 않는다.

카드의 실행 예는 **vLLM 0.32.0 이상과 최신 NeMo Speech**, H100 80GB 한 장을 대상으로 한다. 이는 최소 VRAM 보증이 아니다. BF16·FP8·NVFP4·GGUF 및 DFlash2 보조 drafter를 따로 신규 소개하지 않는다. 상용 NIM의 처리량을 공개 vLLM 경로의 재현 성능으로 쓰지 않는다. 반복 생성·누락·환각 가능성이 있어 출력 검증이 필요하다.

[공식 PEE 학습 설정](https://github.com/NVIDIA-NeMo/Speech/blob/main/examples/speechlm2/conf/salm_automodel_pee.yaml)도 확인했다. 다만 이 파일은 Nano-v3·Canary 초기화와 별도 PEE checkpoint를 사용하는 일반 recipe다. **현재 출시 Transcribe의 정확한 학습 설정·동결 범위라고 대입하지 않는다.** 공개 구현의 예시 설정과 제품 카드의 실제 배포 설정은 구분해야 한다.

### 활용 예: 화자별 회의록의 오류를 먼저 측정

아래는 직접 설계한 시험 시나리오이며 실제 추론 결과가 아니다.

1. 참여자 동의를 받은 2분짜리 합성 회의 오디오를 준비한다. 두 사람이 겹쳐 말하는 구간과 가상의 프로젝트 용어를 넣는다.
2. 검토·고정한 모델 revision 및 공식 실행 환경에서 원문 전사와 화자별 전사를 각각 요청한다.
3. 지시문 예: “발화 내용을 화자별로 전사하세요. 예상 용어는 ‘다온봇’과 ‘누리랩’입니다. 들리지 않는 부분이나 화자를 추측하지 마세요.”
4. 별도로 사람이 만든 정답과 단어 오류율, 화자 귀속 오류, 용어 오인식, 누락, timestamp 편차를 비교한다. 용어 목록에 틀린 단어를 넣어 문맥 편향도 시험한다.
5. 전사와 요약을 분리하고, 요약에서 결정·제안·미정 상태를 섞지 않는지 확인한다. 자동 생성 결과만으로 메일 발송·인사 평가·외부 의사결정을 수행하지 않는다.

오디오 업로드 전 보관 위치와 접근 권한을 정하고, 식별정보를 최소화한다. remote code와 모델 revision을 검토한 뒤 실행한다. 이 보고서에서는 설치·가중치 다운로드·모델 실행을 하지 않았으며 한국어 정확도·사용자 장비 지연시간은 미확인이다.

## 2. 제외·보류 기록

다음은 검토 기록이며 신규 소개나 인덱스 추가 대상이 아니다.

- **[MiniCPM-OCR1.0](https://huggingface.co/openbmb/MiniCPM-OCR1.0): 직접 작업 특화 파생으로 제외.** [공식 Transformers 문서](https://huggingface.co/docs/transformers/main/en/model_doc/minicpm_ocr)가 MiniCPM-V4.6 아키텍처 유지와 OCR 학습을 설명한다. 새 OCR 이름·문서 점수만으로 기존 MiniCPM 계열의 새 세대를 인정하지 않는다.
- **[MiniCPM-OCR-Jev](https://huggingface.co/openbmb/MiniCPM-OCR-Jev): 제외.** 기존 Qwen3.5 시각·언어 백본의 출력 head를 이진 판정에 맞춘 작업 특화 모델로, 독립 계열 근거로 부족하다.
- **LFM3 text·VL·Audio·Omni·decision 및 저정밀 배포:** [어제 보고서](2026-10-28.md)에 공유 백본 한 계열로 이미 등록했다. modality별 제품을 다시 세지 않는다.
- Unlimited-OCR-2·Hy-SimulMT 등 최근 보류 후보는 기존 계보와의 차세대 비교를 해제할 추가 검증을 완료하지 않았다. 새 이름이 등장했다는 이유로 선정하지 않는다.
- Nemotron Transcribe의 BF16·FP8·NVFP4·GGUF·DFlash2는 이번 한 계열의 배포·보조 구성으로 묶는다. 기존 Lightning·Diarization 자체를 재소개하는 것도 아니다.
