## 1. Nemotron 3.5 Parse: 문서 인식기의 구조 변경

**태그:** image-to-text, OCR, document-parsing, multilingual, layout, GQA, MTP.

### 신규성 판정

이미 소개된 [Parse 2.0 공식 카드](https://huggingface.co/nvidia/NVIDIA-Nemotron-Parse-2.0)는 ViT-H C-RADIO와 10-block mBART를 사용한다. 보조 예측 head는 별도 파일에 보관되고 표준 생성에서는 불러오지 않는다. 차트 인식과 다국어 어휘 확장은 이미 2.0에 있었으므로 이번에 처음 생긴 기능으로 세지 않는다.

[3.5 공식 카드](https://huggingface.co/nvidia/Nemotron-3.5-Parse)는 **C-RADIOv4-SO400M·동적 직사각형 NaViT 전처리·causal visual-prefix decoder·16 query/8 KV GQA**를 명시한다. 학습된 one-step MTP head도 모델에 포함되어 vLLM plugin에서 사용된다. encoder·시각 조건 처리·추론 head 경로가 함께 달라 단순 크기 축소나 양자화·경미한 fine-tune과 구별되는 **주요 세대 변경 예외**로 판단했다. 전체 사전학습량과 가중치 초기화 계보는 미확인이다.

### 활용 예와 실행 조건

예: 공개 연차보고서 한 페이지를 RGB 이미지로 준비하고 공식 task prompt로 처리해, 읽기 순서·본문·표·영역 좌표를 추출한다. RAG에 넣기 전 표 병합·숫자·각주가 원본과 맞는지 사람이 대조한다. 개인 문서는 합성 샘플로 먼저 시험한다.

[공식 Quick Start](https://huggingface.co/nvidia/Nemotron-3.5-Parse#quick-start)의 Python 3.12 환경에서 Transformers 5.14.1·torchvision 0.26.0·timm 1.0.22를 준비한 뒤 AutoModel/AutoProcessor 경로를 따른다. 작업 prompt는 다음과 같다.

```text
</s><s><predict_bbox><predict_classes><output_markdown><predict_text_in_pic>
```

일반 Transformers 생성과 MTP가 활성화되는 전용 vLLM plugin을 혼동하지 않는다. 실행 전 remote code 검토·revision 고정이 필요하다. 자동 생성된 범용 서버 예보다 제작자 본문을 우선한다. 이번에 설치나 실행은 하지 않았다.

자체 ParseBench 수치는 triple-pass·region-union 조건이다. 단일 호출의 지연시간·정확도나 다른 모델의 별도 harness 점수와 직접 비교하지 않는다. 한국어 실제 스캔 품질·최소 VRAM은 미확인이다. 라이선스는 모델·tokenizer·외부 의존성을 나눠 확인해야 한다. [공식 모델·실행·평가 설명](https://huggingface.co/nvidia/Nemotron-3.5-Parse).

## 2. 제외·보류 기록

- **[OvisOCR3](https://huggingface.co/ATH-MaaS/OvisOCR3): 보류.** Qwen3.5-0.8B 기반 CPT·mid-training·on-policy distillation·RL과 구조화 OCR·페이지 간 표 연결을 확인했다. 그러나 기존 OvisOCR2·Qwen 계열 대비 이번 엄격한 신규성 기준을 충족하는 구조·학습 변화의 충분한 비교 검증을 마치지 못했다. 새 과업·번호·자체 점수만으로 새 계열로 등록하지 않는다. 기능이 무의미하다는 판정은 아니다.
- **[KittenTTS 2](https://huggingface.co/KittenML/kitten-tts-2/raw/main/README.md): 보류.** 1.7B speech LM·S3 token·다국어 음성 복제·ternary weight를 설명하지만 원천 백본과 학습 계보를 충분히 확인하지 못했다. packed·emb4·full은 같은 가중치의 배포 형태라 각각 세지 않는다. [공식 C++ 실행 저장소](https://github.com/KittenML/kitten-tts-2-cpp)의 GGUF 실행 경로 역시 독립 신규 계열 근거가 아니다.
- **HuggingFaceBio/Carbon-X: 보류.** 트렌딩 목록에서 관찰했지만 모델 본문을 정상 열람하지 못해 용도·라이선스·계보를 추정하지 않았다.
- **Flint·Raon-1 mini·MemT-1.0·Fibo 2.0 등 기존 소개 계열**, 그 GGUF·MLX·저정밀·크기 변형은 제외했다. Nemotron 3.5 Super VL과 Parse는 이름의 일부가 같아도 서로 다른 시각 언어/문서 인식 분기이며, 이번 판단은 이전 Parse와의 구조 비교에 근거한다.

보류 후보는 중복 인덱스에 신규 소개로 넣지 않는다.
