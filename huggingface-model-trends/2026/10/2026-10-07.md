## 1. Google EmbeddingGemma 2

**태그:** feature-extraction, multimodal-embedding, multilingual, sentence-transformers, code-search, audio, video.

### 신규 계열로 보는 이유

Gemma 4 계보를 공유하지만 답변을 토큰 단위로 생성하는 모델을 재포장한 것이 아니다. **전층 양방향 encoder**, mean pooling과 임베딩 projection, 모달리티 간 정렬 및 Matryoshka Representation Learning을 결합한 전용 검색 모델이다. 텍스트·코드·이미지·영상·음성과 혼합 입력을 공통 벡터 공간으로 표현한다. 기존 인덱스의 생성용 Gemma 4·DiffusionGemma와 입력·출력·학습 목적의 변화가 커 별도 멀티모달 임베딩 분기로 판정했다. 정확한 초기화·증류 recipe나 전체 학습 token 수는 확인하지 못했으며 from-scratch 모델이라고 주장하지 않는다. [공식 모델 카드](https://ai.google.dev/gemma/docs/embeddinggemma/model_card_2), [공식 Transformers 구현](https://github.com/huggingface/transformers/blob/main/src/transformers/models/embedding_gemma2/modeling_embedding_gemma2.py).

공식 규모는 text 270M + vision 170M + audio 300M이다. 필요한 모듈만 사용할 수 있으며 기본 출력은 **768차원**, 입력 한도는 **8,192 tokens**다. 이 길이는 모든 모달리티가 공유하므로 긴 음성·영상·텍스트를 각자 8K씩 넣을 수 있다는 뜻이 아니다. 지원 언어 100개 이상이라는 설명도 한국어의 모든 업무 검색 정확도를 보증하지 않는다. [Google 발표](https://blog.google/innovation-and-ai/technology/developers-tools/embeddinggemma-2/), [HF 카드](https://huggingface.co/google/embeddinggemma-2).

### 활용 예와 주의점

- 문서·화면 이미지·설명 영상·음성 기록을 한 인덱스에서 찾는 로컬 멀티모달 RAG, 자연어로 코드 검색, 음성 질의로 관련 영상 검색의 후보.
- SentenceTransformer 사용 시 **SearchQuery와 Document prompt를 구분**한다. 단순 문자열 encoding만으로 학습 때의 task 조건이 자동 충족된다고 가정하지 않는다.
- **BF16 또는 FP32를 사용한다. FP16은 NaN이나 드러나지 않는 벡터 품질 저하를 일으킬 수 있다.**
- MRL 차원 축소 후 L2 정규화하고 질의·문서 차원을 일치시킨다. 128차원은 멀티모달 품질 저하가 커 작은 저장 공간만 보고 선택하면 안 된다. 256차원 이상부터 업무 데이터로 비교하는 편이 보수적이다. [고정 revision 사용법·제약](https://huggingface.co/google/embeddinggemma-2/blob/914f7f89142e33e77833254d9c9b90c3cef7303b/README.md).

Google 공개 평가에서 MTEB Code는 전작 68.76에서 78.68로 높아졌지만 multilingual 점수는 61.15에서 61.36으로 소폭 변했다. **개발사 평가**이며 모든 언어·모달리티에서 같은 개선이 있다고 일반화하지 않는다. 임베딩 모델 자체를 콘텐츠 moderation이나 안전 필터로 취급해서도 안 된다. [공식 평가·제약](https://ai.google.dev/gemma/docs/embeddinggemma/model_card_2).

**날짜 구분:** Google 발표 페이지의 표기일은 10/6이고 게시 metadata의 16:00 UTC는 **10/7 01:00 KST**다. HF 저장소 생성은 **9/14 23:53 KST**, 마지막 수정은 **10/7 00:29 KST**다. 생성일을 출시일로 쓰지 않았다. 정리된 HF 커밋 이력만으로 최초 공개 시각을 독립 확정하기도 어렵다. [공식 발표](https://blog.google/innovation-and-ai/technology/developers-tools/embeddinggemma-2/), [HF 이력](https://huggingface.co/google/embeddinggemma-2/commits/main).

## 2. Prism

**태그:** image-to-video, joint-video-audio-generation, diffusion-transformer, sparse-attention, native-2K.

### 신규 계열로 보는 이유

MOVA DiT를 초기화에 사용하되 **video self-attention을 동적 sparse attention으로 교체**한다. 시공간 macro-zone별 영상 feature 변화와 audio-to-video 상호작용을 반영해 block 모양을 바꾸고, top-k/top-p 혼합 방식으로 query별 희소성을 조절한다. native 2K 영상·음성의 공동 학습에 맞춘 연산 구조 변화이며, 기존 비디오 모델의 단순 고해상도 업스케일러·LoRA·양자화본으로 보지 않았다. 공개 alpha·beta checkpoint는 한 계열로 묶는다. [논문 구조·학습](https://arxiv.org/html/2610.05416v1).

연구진은 100k 2K clips에서 5 epochs 학습했다고 보고한다. full attention 대비 2.5배 학습 속도와 생성 품질 개선은 **연구진 자체 비교**다. 일부 비교 모델도 같은 2K 데이터에 적응시킨 조건이고 상용 모델보다 시각적 사실감·음향 미감이 뒤지는 한계도 명시한다. 이를 모든 영상 생성 모델 대비 우위로 확대하지 않는다. [실험 설정·한계](https://arxiv.org/html/2610.05416v1).

### 활용 예와 실행 조건

- 참조 이미지·영상 prompt·audio prompt로 동작과 소리가 맞는 고해상도 짧은 clip을 만드는 연구, native 해상도별 attention 비용·영상 품질 비교에 적합하다.
- 공식 안내는 Python 3.10 이상, CUDA 12.4 이상, FlashAttention·ffmpeg 환경과 MOVA base 구성요소를 요구한다. 720p 추론은 **80GB NVIDIA GPU 1개**, 1080p·2K는 **80GB GPU 4개 이상**을 제시한다. 이는 제작자 안내이며 이번에 최소 메모리를 재현한 것은 아니다.
- `prism_infer.sh` 또는 FSDP용 `prism_infer_fsdp.sh`의 checkpoint·참조 이미지·출력 경로와 GPU 수·해상도를 먼저 수정해야 한다. 일반적인 자동 생성 Diffusers snippet을 검증된 실행 경로로 대신 제시하지 않는다. [공식 설치·실행 안내](https://github.com/Tencent-Hunyuan/Prism).

**실제 스크립트의 기본값이 다르다.** 조사 시 단일/DeepSpeed 예제 `prism_infer.sh`는 `ENABLE_IVPQ_DYNAMIC_BLOCK=false`, FSDP 예제는 `true`였다. 전자는 480×848, 후자는 1072×1920을 지정하고 둘 다 예시 경로·`sp_size=8`을 포함한다. 그대로 실행하면 원하는 2K/단일 GPU/동적 block 설정이 된다고 가정하면 안 된다. [단일/DeepSpeed 스크립트](https://github.com/Tencent-Hunyuan/Prism/blob/main/prism_infer.sh), [FSDP 스크립트](https://github.com/Tencent-Hunyuan/Prism/blob/main/prism_infer_fsdp.sh).

**규모·배포:** HF에는 alpha·beta 실제 safetensors와 MOVA 구성요소가 확인되지만 통합 parameter 집계는 없다. 논문은 MOVA-720p 초기화를, 배포 안내는 MOVA-360p 경로를 사용하므로 두 표기를 동일 snapshot이라고 단정하지 않았다. 정확한 구성·revision을 고정하고 사용 경로를 검토해야 한다.

**라이선스:** 공개 Prism 코드·parameter·가중치는 MIT다. 공식 LICENSE는 MOVA-360p 등 third-party 구성요소가 기존 조건을 유지한다고 명시하므로 패키지 전체가 조건 없이 하나의 MIT라는 해석은 피한다. [라이선스 원문](https://github.com/Tencent-Hunyuan/Prism/blob/main/LICENSE).

**날짜 구분:** 논문 제출은 10/4 17:58 UTC, 즉 **10/5 02:58 KST**다. HF 생성은 **9/24 18:58 KST**, 최근 수정은 **10/7 00:17 KST**다. 공식 README release 날짜가 아직 placeholder이므로 가중치 최초 출시일은 미확인으로 남긴다. [논문 이력](https://arxiv.org/abs/2610.05416), [HF metadata](https://huggingface.co/api/models/FrancisRing/Prism).

## 3. EMA 계열과 EMA Lightning

**태그:** text-to-speech, Turkish, flow-matching, DiT, streaming, on-device.

### 신규 계열로 보는 이유

이번 아카이브에서 처음 다루는 **EMA 음향 모델 계열**이다. Lightning은 글자 단위 text encoder·duration predictor·windowed aligner와 6-block DiT를 결합하고, 자체 5.6M flow-matching teacher를 같은 크기의 4-step DMD2 student로 만든다. 3M vocoder가 25Hz latent를 48kHz mono 음성으로 복원한다. 단순 배포 포맷이나 다른 소개 모델의 음성 adapter로 세지 않았다. [구조·학습 설명](https://huggingface.co/canberkkkkkk/ema-lightning).

과거 EMA-TTS는 별도 65M acoustic model과 동결 VoxCPM2 AudioVAE2를 사용한다. codec 재사용만으로 EMA acoustic model 전체가 기존 VoxCPM2 fine-tune이라고 단정하지 않는다. 반대로 모든 구성요소가 독자 개발됐다고 주장하지도 않는다. **EMA-TTS·EMA Lightning·동일 계열의 후속 경미한 변형은 모두 한 계열**로 묶고, Lightning을 65M EMA-TTS에서 직접 증류했다고 추정하지 않았다. [이전 EMA-TTS 카드](https://huggingface.co/canberkkkkkk/ema-tts).

### 활용 예와 제약

- 터키어 안내 음성·짧은 내레이션·로컬 음성 인터페이스의 후보. 한 개 음색만 지원하며 voice cloning·감정 조절·한국어 합성을 지원하지 않는다.
- 내부 약 1,000시간 단일 화자 터키어 corpus로 학습했다. 외래어는 터키어 발음 규칙으로 읽는다. 숫자·날짜·약어의 정규화 오류는 별도 확인해야 한다.
- 공식 package의 기본 흐름은 `EMA().say(text, path="speech.wav")`다. `stream()`은 chunk를 반환하고, NVIDIA 환경의 `.lightning()`은 compilation·CUDA graph 최적화 경로다. CPU/GPU에서 오프라인 실행할 수 있다. 이번 조사에서는 실제 합성을 실행하지 않았다. [공식 사용법](https://github.com/canberk7/ema-lightning).

### 성능 수치에서 특히 확인할 점

제작자가 내세운 **WER 0.92%**는 495개 Freya-TR-Eval 문장·3개 seed를 Whisper large-v3로 판정한 자체 측정이다. 그런데 공식 PERFORMANCE 문서는 이 평가가 **normalizer-tr로 전환하기 전 release candidate**에서 수행됐다고 밝힌다. 현재 배포 package가 같은 결과를 낸다고 확정하면 안 된다. 3.86ms first audio·440배 real-time 등도 warm-up 후 특정 RTX 4090 환경의 제작자 측정이다. 실제 서비스의 최초 로딩·동시 요청 지연시간을 보증하지 않는다. [측정 조건과 전처리 변경](https://github.com/canberk7/ema-lightning/blob/main/PERFORMANCE.md).

낮은 WER와 자연스러운 음색은 별개다. 카드 자체도 음질 한계를 밝히며 UTMOS 약 3.30을 제시한다. 모델 카드의 arXiv 2405.14867은 **DMD2 선행연구**이지 EMA의 2024년 발표 근거가 아니다. [카드·한계](https://huggingface.co/canberkkkkkk/ema-lightning).

**날짜 구분:** HF 저장소 생성은 **10/1 23:18 KST**, 마지막 수정은 **10/7 04:52 KST**다. package 1.0.0은 **10/6 06:44 KST**, 1.0.1은 **10/6 12:21 KST** 공개다. 오늘 처음 출시됐다는 표현 대신 최근 package 공개·업데이트와 오늘의 최초 아카이브 소개를 구분한다. [HF metadata](https://huggingface.co/api/models/canberkkkkkk/ema-lightning), [PyPI 이력](https://pypi.org/project/ema-lightning/#history).

## 제외 및 보류

- **EmbeddingGemma 2 GGUF·MLX 등**은 오늘의 원본과 같은 계열이다. Prism alpha/beta도 각각 새 모델로 추가 계산하지 않았다.
- **FRIDA-Decisions:** FRIDA T5 encoder에 rank-16 LoRA와 scalar head를 학습·병합한 계보가 명시돼 있다. 효율적인 packing·state cache는 유용하지만 이번에는 직접 fine-tune 예외를 인정할 만큼의 세대 전환 근거를 보수적으로 확정하지 않아 보류했다. [공식 학습 설명](https://huggingface.co/ai-forever/FRIDA-Decisions).
- **Index-Translate-2B:** Qwen3.5 기반 다국어 mid-training·전문가 SFT/RL·병합·MOPD가 공개돼 있다. 실용적인 번역 특화 모델이지만 원래 text-generation 구조의 직접 post-training 계보를 넘어서는 신규 계열 예외는 이번에 확정하지 않았다. 2B·9B·35B 크기를 따로 세지 않았다. [공식 카드](https://huggingface.co/IndexTeam/Index-Translate-2B).
- **Interfaze 1 Lite:** reasoning core와 OCR·ASR·분할·예측 등 specialist를 tool call로 묶는 시스템이다. 공개 카드만으로 기존 구성 모델에서 충분히 다른 공동 학습 모델 계열임을 검증하지 못해 별도 신규 모델 수에 넣지 않았다. 하나의 neural network라고 소개하면 부정확하다. [공식 설명](https://huggingface.co/interfaze-ai/interfaze-1-lite).
