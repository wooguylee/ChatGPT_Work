## 1. MemT-1.0: 언어 백본에 지속 상태를 읽고 쓰는 메모리 분기

**태그:** text-generation, native-memory, persistent-memory, long-interaction, MoE, custom-code.

### 신규성: 기존 가중치의 재사용과 새 연산을 구분

Nano는 **Qwen3.6-35B-A3B**, Flash는 **DeepSeek-V4-Flash**를 기반으로 한다. 따라서 처음부터 독립 사전학습한 언어 기반모델이라고 부르지 않는다. 두 크기를 동일 MemT-1.0 계열로 묶는다. [공식 저장소·모델 구성](https://github.com/MemTensor/MemT-1.0).

논문은 기존 attention과 병렬로 작동하는 **Local/Hyper Memory Block**, 읽은 메모리를 attention 출력과 결합하는 경로, **GDN-2 기반 토큰 단위 상태 갱신**을 제시한다. 기존 백본을 동결하고 새 메모리 분기를 **20B-token 연속 사전학습 + 14B-token 후학습**으로 학습한다. 외부 검색 결과를 프롬프트에 붙이는 wrapper나 기존 가중치의 경미한 대화 fine-tune만은 아니므로 주요 구조 변경 예외로 인정한다. 논문의 Mixture-of-Storage 분석을 모든 공개 checkpoint에 적용됐다는 주장으로 확대하지 않는다. [기술보고서 §2–3·부록 B](https://arxiv.org/html/2610.26825v1).

이 학습량은 제작자의 보고이며 이번에 재현하지 않았다. 메모리 압축이 원문 증거의 완전 보존을 의미하지 않으며, 세부 증거 재검색이 필요한 긴 이력에서는 강한 텍스트 메모리 시스템이 여전히 유리하다는 저자들의 한계 설명도 있다. 모든 장문 작업에서 RAG를 대체한다고 주장하지 않는다. [평가·한계](https://arxiv.org/html/2610.26825v1).

### 사용 예와 운영 주의

문서를 메모리 상태로 적재한 후 전체 문서를 매번 프롬프트에 다시 넣지 않고 질문하는 실험에 적합하다. 공식 inference 환경과 대응하는 BF16 checkpoint를 준비한 뒤, 해당 실행 디렉터리에서 사용하는 예다. 이번에는 실행하지 않았다.

```bash
sh start_memt_nano.sh /models/MemT-1.0-Nano
python examples/document_memory.py /models/MemT-1.0-Nano
```

[공식 inference 안내](https://github.com/MemTensor/MemT-1.0/blob/main/inference/README.md). 문서의 Nano 2 GPU·Flash 8 GPU 설정은 실행 예시이지 검증된 최소 GPU 수나 VRAM 요구량이 아니다. 표준 Qwen/DeepSeek 로더만으로 메모리 상태 연산이 구현된다고 가정하지 않는다. custom code와 revision을 검토해야 하며, 실사용에서는 사용자별 기억 격리·삭제·만료·민감정보 재노출을 별도로 검증해야 한다. 이는 본 보고서의 운영상 검토 제안이다.

## 2. Fibo 2.0: 생성 backbone과 멀티모달 조건 주입을 바꾼 차세대

**태그:** text-to-image, image-to-image, image-editing, flow-matching, DiT, structured-caption, multimodal-conditioning.

### FIBO·Fibo 1.5와 무엇이 다른가

기존 인덱스에 FIBO와 Fibo 1.5가 있으므로 이름의 2.0만으로 선정하지 않았다. [기존 FIBO](https://huggingface.co/briaai/FIBO)는 SmolLM3-3B·DimFusion·Wan2.2 VAE 구성이며, [Fibo 1.5](https://huggingface.co/briaai/Fibo-1.5)는 원본의 DMD/DMD-R 증류 계보다. [Fibo-Edit-1.5-base](https://huggingface.co/briaai/Fibo-Edit-1.5-base)도 이미 참조 이미지·mask 편집을 지원했다. 따라서 “편집 기능 최초 추가”를 이번 신규성으로 내세우지 않는다.

새 모델은 **Qwen3-VL-4B-Instruct + Perceiver의 gist token**, 이미지와 gist를 합친 **single-stream 생성 transformer**, 일부 블록의 **gated cross-attention**을 사용한다. 편집용 context latent도 공유 embedder를 거쳐 별도 RoPE 위치로 들어간다. 이는 단순 해상도·크기 변경이나 기존 checkpoint의 소폭 재학습을 넘어 조건 표현과 생성 연산의 변화다. [개발팀의 diffusers 지원 PR](https://github.com/huggingface/diffusers/pull/14991).

카드는 **FLUX.2 VAE latent**, 44블록 DiT·2층 Perceiver와 5개 cross-attention 블록을 설명한다. licensed dataset 기반 학습은 BRIA의 주장으로 기록하며 법적 무위험성 보장으로 바꾸지 않는다. 전체 학습 token·학습 step과 모든 구성요소를 처음부터 학습했는지는 미확인이다. [공식 모델 카드](https://huggingface.co/briaai/Fibo-2.0-dev).

### 사용 예

현재 main의 diffusers 문서는 생성 transformer를 **8.1B**로 설명한다. Qwen3-VL-4B·VAE 등을 포함한 전체 파이프라인 크기를 8B라고 부르지 않는다. 같은 dev checkpoint로 생성과 편집을 수행하고 edit-turbo는 편집용 증류본이다. 다음은 해당 지원 코드가 포함된 revision과 모델 접근 권한을 준비한 뒤의 예다.

```python
import json
import torch
from diffusers import BriaFibo2Pipeline

pipe = BriaFibo2Pipeline.from_pretrained(
    "briaai/Fibo-2.0-dev", dtype=torch.bfloat16
).to("cuda")

caption = {
    "short_description": "A blue ceramic cup on a wooden desk in morning light.",
    "text_render": []
}
image = pipe(
    json.dumps(caption),
    num_inference_steps=30,
    guidance_scale=5.0
).images[0]
image.save("cup.png")
```

짧은 description과 text_render의 조합은 공식 문서가 지원하는 prompt 형태다. 구조화된 전체 caption을 직접 작성해 더 많은 속성을 지정할 수도 있다. 이 예는 외부 Gemini prompt-expansion API를 호출하지 않는다. [공식 pipeline 문서](https://github.com/huggingface/diffusers/blob/main/docs/source/en/api/pipelines/bria_fibo2.md).

구현은 참조 이미지·mask와 문자 렌더링용 보조 이미지 조건을 다룬다. 다만 카드와 현재 구현 문서의 최대 참조 이미지 수가 **4장 대 5장**으로 달라, 동일 버전의 검증 없이 최대치를 보증하지 않는다. 카드의 50-step 예와 구현 기본값 30-step도 구분한다. 위 예는 최신 구현 문서의 30-step 설정이다. 한국어 글자 정확도·다중 참조 일관성·최소 VRAM·상업 디자인 품질은 이번에 검증하지 않았다.

### 라이선스와 날짜

모델 카드의 HF license 태그는 **bria-fibo**, 본문은 **CC BY-NC 4.0 비상업 이용과 별도 상업 계약**을 안내한다. gated 접근·약관을 확인해야 하며 이번 조사에서 접근 약관 수락이나 가중치 다운로드를 수행하지 않았다. 별도 LICENSE 파일 전체는 직접 확인하지 못했으므로 카드 안내를 법률 검토 완료로 표현하지 않는다. [모델 카드와 이용 안내](https://huggingface.co/briaai/Fibo-2.0-dev).

[HF 트렌딩 7페이지](https://huggingface.co/models?p=6&sort=trending)에서 **30 likes·35 downloads**가 표시됐다. 카드 검색 결과는 서로 다른 캐시의 수치이므로 이 차이를 시간별 증가로 계산하지 않았다. 오늘은 구조 변경·공개 구현 합류·트렌딩 노출을 함께 선정 근거로 삼았다.
