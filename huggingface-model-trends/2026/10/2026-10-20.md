## 1. Ming-3.0-audio: Ling V3에 음성 입력·생성 경로를 더한 분기

**태그:** audio-text-to-text, speech-to-speech, ASR, audio-understanding, MoE, Chinese, English, conditional-flow-matching. HF의 text-to-speech tag만으로 전체 기능을 좁혀 읽지 않는다.

### 기존 계열과 구별되는 구조

기존 인덱스에는 Ling-3.0 text와 Ling-3.0-flash-VL, Realtime-Venus, Ming-Image가 있다. 이번 모델은 **Ling V3 계열의 언어 백본을 재사용한 오디오 이해·생성 분기**다. 새로운 독립 언어 모델을 처음부터 사전학습했다고 소개하지 않는다. Flash와 [Tiny](https://huggingface.co/inclusionAI/Ming-3.0-audio-tiny)는 한 계열로 묶는다.

배포 클래스는 **BailingMoeV3AudioForConditionalGeneration**이다. 32층·width 1280의 Whisper 유래 음성 encoder와 세 단계 stride-2 convolutional projector가 음성 feature를 언어 모델에 연결한다. Flash 백본은 42층이며 KDA·gated MLA와 MoE를 사용한다. **KDA 자체의 최초 도입이나 단순 126B 크기 확대를 신규성으로 삼지 않는다.** [배포 config](https://huggingface.co/inclusionAI/Ming-3.0-audio-flash/blob/main/config.json), [실제 음성 입력 구현](https://huggingface.co/inclusionAI/Ming-3.0-audio-flash/blob/main/modeling_bailing_moe_v3_audio.py).

선택적 **Talker**에는 audio tokenizer·reference-voice 조건, aggregator, DiT patch head와 waveform decoder가 있다. 번들 구현에는 conditional flow-matching 학습 손실이 있다. 텍스트 답변의 문체를 바꾸는 SFT나 외부 ASR 전사문을 붙이는 wrapper에 그치지 않는 별도 음성 경로가 확인돼 주요 모달리티 분기로 인정한다. [공식 구조도](https://huggingface.co/inclusionAI/Ming-3.0-audio-flash/resolve/main/assets/ming-3.0-audio-flash-architecture.png), [Talker 학습 구현](https://huggingface.co/inclusionAI/Ming-3.0-audio-flash/blob/main/talker/talker_module/cfm.py).

다만 전체 학습 corpus·음성 시간·단계별 학습량과 audio 전용 기술논문은 확인하지 못했다. 코드에 손실 함수가 있다는 사실만으로 실제 모든 학습 단계를 재구성하지 않는다. 기존 Realtime-Venus의 full-duplex·중단 처리나 도구 위임까지 이번 모델이 동일하게 지원한다고 가정하지 않는다.

### 활용 예와 실행 조건

중국어·영어 녹음의 전사·요약, 음성 질문에 대한 답변, 환경음·음악 이해를 실험할 수 있다. 다음은 공식 저장소와 필요한 환경을 준비한 뒤의 ASR 예다. 이번에는 실행하지 않았다.

```bash
python examples/transformers_audio.py examples/audio/introduce_ant_group.wav \
  --model inclusionAI/Ming-3.0-audio-flash \
  --task asr --max-new-tokens 256 --no-repeat-ngram-size 10
```

[공식 예제 안내](https://github.com/inclusionAI/Ming-3.0-audio-flash/blob/main/examples/README.md). 외부 custom code를 사용하므로 실제 실행 전 검토하고 revision을 고정해야 한다. 음성 생성에서 reference WAV를 쓰려면 사용 권한·동의와 일치하는 transcript가 필요하다.

제작자가 확인한 SGLang 경로는 **4 GPU·텍스트 출력**, vLLM-Omni reference는 **8× H800 80GB·128K context** 구성이다. 이는 문서화된 예시이며 최소 하드웨어 요구량을 증명하지 않는다. config의 **131,072 tokens는 문맥 설정**으로, 같은 숫자의 초·최대 음성 길이를 뜻하지 않는다. 한국어 품질, 다화자 전사, 장문 음성의 누락·추론 오류는 별도 검증해야 한다. [공식 배포 가이드](https://github.com/inclusionAI/Ming-3.0-audio-flash#inference-options).

공식 benchmark는 제작자 보고이며 독립 재현 결과가 아니다. 일부 장문 음성·화자 구분 과제에서 비교 모델보다 낮은 결과도 있으므로 전체 음성 이해에서 일괄 우위라고 표현하지 않는다. [공식 평가 자료](https://huggingface.co/inclusionAI/Ming-3.0-audio-flash/blob/main/README.md).

## 2. UniForge3D: 복원과 생성을 같은 좌표계에서 공동 처리

**개발:** Wenjue Chen, Wenyue Chen, Heliang Zheng, Rongfei Jia, Yuan Liu, Meng Li; Peking University·Math Magic·HKUST. **태그:** image-to-3D, multi-view, unposed-images, 3d-reconstruction, 3d-generation, anchor-guided, view-routing. [공식 프로젝트](https://xishuxishu.github.io/uniforge3d-project/).

### 단순 VGGT fine-tune을 넘어서는 변경

기존 인덱스의 VGGT-Omega는 기하 복원 계열이다. UniForge3D는 **VGGT와 TRELLIS.2를 초기 가중치로 사용**하지만, 두 모델을 독립 호출한 뒤 결과를 단순 합치는 파이프라인이 아니다.

- 공개 **JointDiTVGGTStage1Model**은 VGGT→DiT residual과 timestep-gated 역방향 cross-attention을 두어 두 branch의 feature를 실제로 주고받는다.
- 설정은 **8개 양방향 상호작용 위치**를 지정한다.
- 세부 shape·texture denoiser는 일부 cross-attention을 **voxel마다 지정된 입력 시점을 읽는 routed attention**으로 교체한다. 각 모델에 10개 routed layers가 있으며 나머지 층의 all-view 정보와 결합한다.

[공동 모델 구현](https://github.com/xibushu/UniForge3D/blob/main/uniforge3d/models/joint_dit_vggt_stage1.py), [routed denoiser](https://github.com/xibushu/UniForge3D/blob/main/uniforge3d/models/structured_latent_flow.py), [전체 설정](https://github.com/xibushu/UniForge3D/blob/main/uniforge3d/configs/pipeline.json).

논문은 첫 입력 시점의 방위와 물체의 수직 방향을 기준으로 공유 좌표계를 잡고, **구조 flow matching과 point-map 예측을 공동 학습**한다. 기존 branch에는 LoRA를 사용하지만 새 interaction modules는 전체 학습하며, 별도의 구조 조건 VGGT도 fine-tuning한다. 관측되지 않은 부분의 3D 생성과 관측 geometry 보존을 연결하는 구조·학습 변화가 있어 **주요 공동 복원·생성 분기**로 인정한다. 모든 구성요소의 from-scratch 학습이나 VGGT-Omega의 새 크기라는 뜻은 아니다. [논문 §3·§4.1·Appendix A](https://arxiv.org/html/2610.15357v1).

### 활용 예·결과물·실행 한계

같은 물체를 여러 각도에서 찍은 이미지를 넣어 완성된 textured 3D asset의 초안을 만드는 연구 후보다. 카메라 pose 파일 없이 입력하지만 사진에 보이지 않는 면은 **모델이 생성한 추정**이므로 실제 측정값으로 취급하지 않는다.

공식 환경 설치 후 물체마다 별도 폴더에 이미지를 모은다. 예를 들어 assets/case01/에 네 장을 넣고 다음처럼 실행한다.

```bash
python infer.py --input assets --output outputs --low-vram
```

기본 결과는 **outputs/case01/prediction.glb**다. [공식 inference script](https://github.com/xibushu/UniForge3D/blob/main/infer.py). 이번에는 설치·모델 실행·3D 결과물 생성은 하지 않았다.

설치 예는 Python 3.10·PyTorch 2.6/CUDA 12.4와 별도 CUDA geometry 의존성을 사용한다. 파이프라인은 CUDA를 사용하며 low-VRAM mode는 비활성 구성요소를 CPU로 옮긴다. 이것만으로 8GB·16GB GPU에서 작동한다고 보증하지 않는다. **공식 최소 VRAM과 inference time은 미확인**이다. [설치 script](https://github.com/xibushu/UniForge3D/blob/main/setup.sh), [실행 파이프라인](https://github.com/xibushu/UniForge3D/blob/main/uniforge3d/pipelines/uniforge3d_image_to_3d.py).

HF의 .pt 파일 9개는 합계 약 **26.93GB**이며 외부 DINOv3·TRELLIS 계열 decoder·배경 제거 모델은 별도다. 이것은 다운로드 규모이지 전체 파라미터 수나 실행 VRAM이 아니다. **정확한 전체 모델 파라미터 합계는 미공개**로 남긴다. [HF 파일 metadata](https://huggingface.co/api/models/xibushu/UniForge3D/tree/main?recursive=true&expand=false).

논문의 성능은 Toys4K와 GSO 각 500개 객체, 네 장의 렌더링 입력과 geometry alignment를 사용하는 **연구진 평가**다. 합성 객체 중심 학습이며 가림·강한 반사·극단적 조명이 어렵다. 공개 샘플이나 자체 benchmark를 실제 상품 촬영 전반의 품질 보장으로 확대하지 않는다. [평가 조건·한계](https://arxiv.org/html/2610.15357v1).

## 3. 제외·보류 기록

다음은 검토 기록이며 신규 소개 수와 새 인덱스 항목에 포함하지 않는다.

- **[Matrix-Game 4.0](https://huggingface.co/Skywork/Matrix-Game-4.0):** Skywork AI의 Wan2.2-Fun-5B-Control 파생 게임 renderer다. 장면별 V2V 학습과 인과적 스트리밍 전환은 확인되지만, [논문 §4.3·§7.4](https://github.com/SkyworkAI/Matrix-Game/blob/main/Matrix-Game-4/docs/Matrix_Game_4_0.pdf)는 Causal Forcing++ 방법을 채택했다고 설명한다. 148 입력채널·30층·3072 폭도 [원본 config](https://huggingface.co/alibaba-pai/Wan2.2-Fun-5B-Control/raw/main/config.json)와 같다. 외부 엔진·실행 개선과 직접 재학습을 넘는 독립 신규 trainable architecture 근거가 충분하지 않아 이번에는 보류한다. [공개 runtime](https://github.com/SkyworkAI/Matrix-Game/blob/main/Matrix-Game-4/docs/architecture.md)의 shooter에는 연구 소개의 memory retrieval·dynamic prompt가 빠져 있어 기능도 확대 해석하지 않는다.
- **[Kromoss](https://huggingface.co/lodestones/Kromoss):** lodestones, HF 표시 5B, Apache-2.0. 공식 카드가 MOSS-Image-Base의 full fine-tune이며 같은 구조·Qwen3.5-9B encoder·FLUX.2 소형 VAE를 사용하는 교체 checkpoint라고 명시한다. blur 개선과 8-step DMD LoRA는 [10/17](2026-10-17.md)에 소개한 MOSS-Image의 직접 파생 범위다.
- **[QUAN-Transcribe-1.0](https://huggingface.co/qnguyen3/QUAN-Transcribe-1.0):** Quan Nguyen 배포, 제작자 총 356M, Gemma 약관. 기존 EmbeddingGemma 2 audio encoder 상위 2층 fine-tuning과 6층 CTC reader를 결합한 베트남어 ASR이다. 출력 용도는 달라졌지만 직접 task adaptation을 넘는 주요 세대 근거는 충분하지 않아 [10/18](2026-10-18.md)의 보류를 유지한다. HF의 0.1B는 별도로 내려받는 base encoder를 포함한 전체 크기가 아니다. [저자의 구현·제약](https://github.com/qnguyen3/QUAN-Transcribe).
- **[Granite Switch 4.1 8B](https://huggingface.co/ibm-granite/granite-switch-4.1-8b):** IBM, Apache-2.0, Granite 4.1 8B와 두 aLoRA·470M ASR을 결합한다. 음성은 기존 Granite Speech 5.0 TurboCTC로 전사한 뒤 텍스트를 LLM에 넣는 cascade이며, 카드가 encoder/LLM의 공동학습과 trained projection이 없다고 명시한다. 하나의 endpoint라는 배포 편의성을 새 공동학습 음성 모델로 세지 않는다. 공식 release 표기는 10/14다.
- **[anon-1b](https://huggingface.co/scratchyone/anon-1b/tree/main):** scratchyone의 Gemma 3 1B greentext fine-tune. 별도 이름·BF16 GGUF를 신규 계열로 세지 않는다.
- **[DeepSeek-V4.1-Flash-1017](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017):** 공식 카드가 기존 V4.1의 minor update라고 명시한다. 높은 트렌딩 노출·개발사 benchmark 향상만으로 이미 등록한 계열을 다시 소개하지 않는다.
- **FLUX 3 Image Klein·Ling-3.1-flash·d3·KittenTTS 2:** [10/16](2026-10-16.md)·[10/15](2026-10-15.md)·[10/19](2026-10-19.md)의 계보·구조 보류를 바꿀 추가 근거를 이번에 확보하지 못했다. 보류를 신규로 바꾸어 수를 채우지 않는다.
- TYGER·AuroraIMG는 [10/19](2026-10-19.md), Dory1.0·ALoDLM은 [10/18](2026-10-18.md), Beam·MOSS-Image·Timestral은 [10/17](2026-10-17.md)에 이미 소개했다. 나머지 기존 Qwen·Gemma·MiniMax·LFM2.5·MiniCPM·Nemotron 등의 단순 크기·양자화·포맷·직접 파생본도 전체 인덱스에 따라 제외한다.

## 4. 전주 비교와 인덱스 감사

- 전주 같은 요일 [2026-10-13](2026-10-13.md)은 **MiniCPM-V 4.7·LightOnOCR-3 두 계열**이었다. 오늘도 **두 계열**이며, 당시 시각 이해·문서 인식에서 오늘은 음성 이해·생성과 공동 3D 복원·생성으로 선정 주제가 달라졌다. 이는 아카이브 선정 수·구성 비교이며 시장 전체의 수요나 동등 조건 성능 비교가 아니다.
- main의 [10/13](2026-10-13.md)·[10/14](2026-10-14.md)·[10/15](2026-10-15.md)·[10/16](2026-10-16.md)·[10/17](2026-10-17.md)·[10/18](2026-10-18.md)·[10/19](2026-10-19.md) **전체 본문**과 **전체 41,200자 introduced-models.md**를 읽고 대조했다. **2+2+1+4+3+2+2=16개 소개 계열 모두 등록**돼 이 범위의 누락 복구 대상은 없다. 과거 전체 아카이브를 오늘 전수 감사했다는 뜻은 아니다.
- 조사 전 main의 전체 tree에는 기존 일일 보고서 **76개**가 있었고 오늘 경로는 없었다. 개별 조회도 404였다. 오늘 보고서만 작성하며 누락된 과거 날짜를 소급 생성하지 않는다.
- 보고서를 먼저 저장하고 **main의 범위 제한 없는 전체 본문 일치**를 확인한 다음, 최신 인덱스를 다시 읽어 기존 내용을 모두 보존하면서 오늘 확정한 두 계열만 추가한다. 실제 게시·재조회 결과는 확인 후 아래에 기록한다.
