## 1. WeVisOne-VL: 텍스트 좌표에서 실제 픽셀 출력으로

### 신규성의 범위

[공식 카드](https://huggingface.co/tencent/WeVisOne-VL-4B)는 Qwen3-VL 기반임을 명시한다. 따라서 새 독립 언어·시각 백본을 처음부터 사전학습한 계열이라고 부르지 않는다. 기존 Qwen의 크기 변경·양자화·문체 fine-tune이 아니라, **언어모델의 대상 표현을 시각 feature와 결합해 학습된 dense output으로 바꾸는 주요 구조 확장**을 선정 근거로 삼는다.

구체적으로 대상 box 뒤의 `<OBJ>` hidden state, box 위치, Qwen3-VL의 여러 pre-merging ViT feature를 새 pixel decoder가 받는다. 카드에 명시된 decoder는 9,609,764개 파라미터이고, 6개 deformable cross-attention block과 다단계 alpha refinement를 포함한다. SAM을 별도로 호출해 결과를 붙이는 외부 cascade가 아니다. 좌표·포인트·OCR token 자체만을 신규성 근거로 삼지 않는다. [공식 구조 설명](https://huggingface.co/tencent/WeVisOne-VL-4B#architecture--released-revision).

[논문 §4·부록 B](https://arxiv.org/html/2610.31329v1)는 Qwen3-VL에서 시작해 task alignment와 해상도 확대를 거친 뒤, 무작위 초기화 pixel decoder의 segmentation warm-up, **NTP와 pixel supervision을 1:1로 번갈아 수행하는 VLM–decoder 공동학습**, VLM 동결 상태의 matting 학습을 설명한다. 뒤따르는 RL은 객체 위치·문자 등 과제별 보상을 쓰며, mask/alpha 자체에 직접 RL 보상을 주는 것으로 확대 해석하지 않는다. 논문의 학습 설명은 제작자 보고이며 재현하지 않았다.

이처럼 새로운 trainable 경로와 출력 표현·학습 결합이 확인되어 주요 변경 예외로 인정했다. **Qwen 계보가 없다는 뜻이 아니며, 별도 브랜드라는 이유로 직접 파생 제외를 무시한 것도 아니다.** 2B·4B, 동일 checkpoint의 양자화·포맷·경미한 task adaptation은 향후 같은 한 계열로 제외한다.

### 실제 구현과 제한

[feature_bridge.py](https://github.com/Tencent/WeVisOne-VL/blob/main/wevisone_vl/feature_bridge.py)는 ViT 층 5/11/17/23의 merger 입력을 포착하고 patch 배치를 복구한다. 영상 grid의 시간 축이 1이 아니면 오류를 내므로, 기존 백본이 영상을 이해한다는 이유로 **pixel decoder의 영상 segmentation 지원을 가정하지 않는다**.

[mask_decoder.py](https://github.com/Tencent/WeVisOne-VL/blob/main/wevisone_vl/mask_decoder.py)는 `MaskQueryBuilder`에서 LM hidden state와 Fourier box 위치를 결합한다. 추가 decoder 파일 없이 표준 Qwen 생성 호출만 하는 것은 전체 matting pipeline이 아니다. 구조 연결을 코드에서도 확인했지만 가중치 값·실제 출력·속도는 검증하지 않았다.

### 활용 예

사용 권한이 있는 상품·인물 사진에서 텍스트로 지정한 대상만 추출하고, 이진 mask와 alpha 경계의 차이를 비교하는 실험에 적합하다. 공식 패키지·모델 환경을 준비한 뒤의 예이며 이번에는 실행하지 않았다.

```python
from PIL import Image
from wevisone_vl import WeVisOneVL
from wevisone_vl.visualization import save_result

model = WeVisOneVL("tencent/WeVisOne-VL-4B", backend="transformers")
image = Image.open("sample.jpg").convert("RGB")
result = model.predict(image, task="matting", query="person")
save_result("outputs/matting", image, result)
```

[공식 실행 안내](https://github.com/Tencent/WeVisOne-VL#quick-start). 이 예는 외부 hosted demo에 이미지를 업로드하지 않는다. 머리카락·유리·그림자·복잡한 가림을 포함한 합성 또는 공개 샘플로 먼저 점검하고, 대상이 없는 사진에서 거부되는지도 확인하는 것이 좋다. 실제 개인 식별·고영향 자동 결정 용도로 권장하지 않는다.

[공식 requirements](https://github.com/Tencent/WeVisOne-VL/blob/main/requirements.txt)는 Transformers 5.12.1·PyTorch 2.11.0 등을 고정하고 vLLM·Triton에는 Windows 제외 marker가 있다. 이것만으로 Windows 전체 미지원이나 특정 GPU의 성공을 단정하지 않는다. **최소 VRAM·CPU 속도·한국어 지시 품질은 미확인**이다. 코드·revision·의존성을 검토한 뒤 설치해야 하며 이번 조사에서는 설치하지 않았다.

### 평가·날짜·이용 조건

공식 표는 자체 benchmark이고 독립 검증 결과가 아니다. 예를 들어 객체 부재 거부도 특정 benchmark 조건의 결과이지 모든 사진의 hallucination 방지 보증이 아니다. 전체 tasks에서 4B가 2B를 항상 이긴다는 주장도 하지 않는다. [공식 평가 표](https://github.com/Tencent/WeVisOne-VL#performance-at-a-glance).

[논문 제출 기록](https://arxiv.org/abs/2610.31329)은 **2026-10-22**다. 공식 README의 release 뉴스는 2026년 10월까지만 표시한다. 이번 첫 소개일 10/27과 모델 최초 공개일을 구분한다. HF API 조회는 실패해 정확한 public 전환 시각·전체 tensor 합계를 추가 확인하지 못했다.

HF 카드에는 Apache-2.0 tag가 있다. [GitHub LICENSE](https://github.com/Tencent/WeVisOne-VL/blob/main/LICENSE)는 Tencent의 Apache-2.0 본문이며 README는 Tencent 작성 코드와 외부 구성요소의 조건을 구분한다. 이번에는 HF 가중치 저장소의 별도 LICENSE 전문을 독립 조회하지 않았으므로 **코드 약관 확인을 전체 자산 권리 검토 완료로 표현하지 않는다**. 배포 시 Qwen 및 제3자 고지를 확인해야 한다.

## 2. 제외·보류 기록

다음은 검토 기록이며 신규 소개 수·인덱스 추가 대상이 아니다.

- **[Nanbeige4.3-33B](https://huggingface.co/Nanbeige/Nanbeige4.3-33B): 보류 유지.** Nanbeige LLM Lab, 명칭 33B, 카드 Apache-2.0. 이번에는 본문을 읽어 teacher-agent 목적·512K·tool-use를 확인했다. 그러나 기존 Nanbeige4.2 대비 핵심 구조·학습 변경의 충분한 비교 근거는 확보하지 못했다. [Base 카드](https://huggingface.co/Nanbeige/Nanbeige4.3-33B-Base)와 크기 확대만으로 새 계열을 추가하지 않는다. 자체 benchmark 상승은 신규성 증거와 다르다.
- **[Carbon-X](https://huggingface.co/HuggingFaceBio/Carbon-X): 직접 도메인 파생 제외.** Hugging Face Biology Research, 14.8B, 카드 Apache-2.0. Qwen3-14B에 DNA tokenizer 확장·302B-token mid-training·SFT·RL을 적용한다. [10/24](2026-10-24.md)의 계보 판정을 유지하며 연구 가치와 아카이브 신규성 기준을 구분한다.
- **[elephant-1](https://huggingface.co/baselabs/elephant-1)·mammoth-1:** Base Labs의 decision 계열로 후보 확인했으나 기존 Qwen 기반 adaptation을 넘는 주요 세대 판정을 완료하지 않았다. 크기 두 개를 따로 세지 않으며 [10/24](2026-10-24.md)의 보류를 유지한다.
- **Spark-X2.6·MiniMax-M3.1·Sage-A1.5·Gradium Phonon·KittenTTS 2·OvisOCR3:** 이전 보고서의 구조·계보 보류를 뒤집을 비교 검증을 이번에 완료하지 않았다. 새 번호·다운로드·업데이트만으로 승격하지 않는다.
- **Hi3D/Sparc3D·Hy-Nomas·OXR·Nemotron Parse·Flint·Raon mini·MemT·Fibo2·MOSS-Image·Timestral** 및 기존 Qwen/DeepSeek 등의 크기·GGUF·MLX·ComfyUI·LoRA·양자화·포맷·경미한 fine-tune 배포는 제외한다.
