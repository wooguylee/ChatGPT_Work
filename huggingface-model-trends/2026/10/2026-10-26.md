## 1. 신규성 범위: 처음 소개하는 계보이지 Sparc3D의 독립 차세대가 아님

[공식 모델 카드](https://huggingface.co/hi3d-official/Hi3Dv1.0)는 Sparc3D 표현·정제 구조를 사용한다고 명시한다. 따라서 Hi3D라는 이름, 1536³ 설정, 모델 재배포만으로 Sparc3D 대비 새 architecture라고 주장하지 않는다. 전체 인덱스에 Hi3D·Sparc3D가 없으므로 **동일 정제 계보를 묶어 처음 소개**한다. 해상도별 transformer와 후속 양자화·포맷·경미한 fine-tune은 별도 신규 수로 세지 않는다.

[공식 pipeline 설명](https://github.com/hi3d-official/Hi3Dv1.0/blob/main/docs/pipeline.md)의 핵심은 입력 coarse mesh에서 희소 voxel 좌표를 얻고, 이미지 조건으로 32채널 latent를 생성한 다음, self-pruning VAE와 mesh extraction을 거쳐 다음 pass의 좌표를 다시 만드는 과정이다. 두 transformer는 각각 24블록·width 2,112·22 heads의 약 1.8B 모델이다. 기본 25회 Heun scheduler update를 사용하며 512³→1024³→1536³는 1~3회 pass의 **명목 추출 격자**를 뜻한다. 조밀한 1536³ latent tensor나 고정 삼각형 수가 아니다.

이미 소개한 [UniForge3D](2026-10-20.md)는 VGGT·TRELLIS.2를 연결하는 공동 복원·생성 계열이다. 이번 모델은 그것의 이름 변경·양자화나 checkpoint 미세조정이라고 확인된 것이 아니다. [NOTICE](https://github.com/hi3d-official/Hi3Dv1.0/blob/main/NOTICE)는 TRELLIS·Pointcept·O-CNN·FlexiCubes **코드 기여**를 보존한다. **코드만 재사용했다는 뜻은 아니다.** [원래 Sparc3D 논문 §3.3·§4.1](https://arxiv.org/html/2505.14521v3)은 새 Sparconv-VAE를 학습하고 그 latent에 TRELLIS의 사전학습 flow 모델을 fine-tuning했다고 명시한다. 따라서 TRELLIS 가중치 계보를 인정한다. 다만 SDF·deformation 표현을 직접 압축하는 새 VAE, self-pruning decoder와 geometry 정제 경로는 원래 latent 모델의 경미한 문체·도메인 미세조정과 구분되는 구조 변경이다. 이번에는 그 **Sparc3D 구조 분기 전체의 첫 소개**로 판정하며, UniForge3D·VGGT의 직접 파생으로 확인된 것은 아니다. 현재 Hi3D 배포 가중치의 정확한 초기화·추가 학습 계보는 미확인이고, 독립 from-scratch 모델이나 Sparc3D 이후의 별도 차세대라고 주장하지 않는다.

별도 DINOv2·CLIP encoder는 기존 구성요소이며 신규 소개 수에 포함하지 않는다. Hunyuan3D-2 mini는 선택적인 앞단 coarse-generation 예제에만 쓰인다. 직접 준비한 메시를 정제하는 핵심 경로에는 Hunyuan이 필요하지 않으므로 Hunyuan 모델의 새 크기 변형으로 세지 않는다. [구조·외부 모델 구분](https://github.com/hi3d-official/Hi3Dv1.0/blob/main/docs/pipeline.md).

## 2. 활용 예와 실행·평가 한계

예: 직접 제작한 장식품의 coarse.glb와 참조 이미지 input.png를 준비해 표면 홈·윤곽의 정제 전후 차이를 확인한다. 실제 물체 치수나 보이지 않는 면의 정확한 복원을 보증하는 용도가 아니다.

공식 환경과 모델 파일을 준비한 뒤의 실행 예다. 이번에 실행하지 않았다.

```bash
python demo/refine_mesh.py \
  --model hi3d-official/Hi3Dv1.0 \
  --image input.png --coarse-mesh coarse.glb --output refined.glb \
  --resolution 1024 --num-inference-steps 25 --seed 0
```

[공식 실행·검증 문서](https://github.com/hi3d-official/Hi3Dv1.0/blob/main/docs/reproduction.md). 동일 입력·seed로 두 번 실행해 finite vertices, 유효한 삼각형 인덱스, export/reload 성공 여부와 정규화된 geometry 차이를 점검하는 방식이 적절하다. GPU sparse 연산 때문에 동일 seed가 같은 파일 hash를 보장하지 않는다.

[공식 README](https://github.com/hi3d-official/Hi3Dv1.0#installation)는 Linux·Python 3.10·NVIDIA compute capability 8.0 이상과 CUDA 환경을 요구한다. CPU 추론 경로가 없고, 1536³ ladder의 검증 GPU는 **96GB H20**이다. 작은 GPU의 최소 VRAM·성공 여부는 미확인이다. CPU offload가 전체 sparse feature 메모리를 없애는 것은 아니다.

출력은 **geometry-only**이며 텍스처·재질·vertex color가 없다. 중심과 scale을 정규화하므로 입력 world 좌표·절대 크기를 그대로 보존하지 않는다. coarse mesh의 구조 오류가 남을 수 있다. 카드의 약 200만 3D asset 학습 설명은 제작자 주장으로 구분하며 독립 재현하지 않았다. [공식 모델 카드](https://huggingface.co/hi3d-official/Hi3Dv1.0).

공개 저장소는 학습 코드·평가 harness·benchmark object 목록을 포함하지 않는다. 제작자 비교 이미지를 동등 조건의 독립 성능 우위로 바꾸지 않는다. [재현 범위](https://github.com/hi3d-official/Hi3Dv1.0/blob/main/docs/reproduction.md).

## 3. 라이선스: 일반 Apache·MIT와 구분

[LICENSE 원문](https://github.com/hi3d-official/Hi3Dv1.0/blob/main/LICENSE)의 Schedule 2는 지정된 정제 코드·설정과 HF의 8개 모델 파일을 Hi3D 약관 적용 대상으로 명시한다. 관련 서비스가 직전 완결 월 **MAU 20만 초과** 또는 **월매출 USD 100만 이상**이면 60일 내 별도 라이선스 신청이 필요하다. 상업 통합에는 표시 의무, 재배포에는 고지·약관 전달 등 조건이 있다.

반면 코드·가중치를 포함하지 않는 단독 생성 결과물은 그 파일을 이용한다는 이유만으로 동일한 표시·규모 조건이 적용되지는 않는다고 구분한다. 외부 Hunyuan·DINOv2·CLIP와 기존 제3자 코드의 권리를 다시 허가하는 약관은 아니다. **무제한 상업 이용·전체 pipeline의 Apache-2.0이라고 요약하지 않는다.** 이는 원문 조건의 기술적 기록이며 개별 사업의 법률 적합성 판단이 아니다. 약관 수락·가중치 다운로드·배포는 수행하지 않았다.
