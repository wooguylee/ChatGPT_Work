## 1. Reflection Beam: 별도 사전학습한 텍스트 MoE

**태그:** text-generation, MoE, reasoning, coding, tool-use, long-context, asynchronous-RL. **개발:** Reflection AI.

### 신규 계열의 근거

전체 인덱스에 없던 Beam 계열의 첫 소개다. Reflection은 **23.8T tokens로 자체 사전학습**하고, 이어 장기 추론·도구 환경에서 비동기 RL을 수행했다고 설명한다. 구조는 52층(3 dense + 49 MoE), 256 experts, gated GQA와 sliding-window attention의 조합이며 최대 1M 문맥을 제공한다. 기존 Qwen·DeepSeek의 크기 변형이나 양자화본으로 판정할 근거가 없다. [사전학습·구조 설명](https://reflection.ai/blog/introducing-beam), [공식 카드](https://huggingface.co/reflection/Beam-1.0-501B-A23B).

학습에서는 expert-bias update의 cosine decay, depth 기반 residual scaling·SandwichNorm·FP32 residual 누적 등을 사용한다. 긴 rollout의 policy staleness를 다루는 비동기 학습과 길이 penalty, reasoning·safety teacher를 결합한 MOPD도 설명한다. 이는 개발사의 학습 보고이며 전 과정을 독립 재현한 것은 아니다. [학습 1차 자료](https://reflection.ai/blog/introducing-beam).

BF16·FP8·NVFP4는 같은 한 계열이다. DFlash2 speculative drafter와 GGUF도 별도 신규 소개 수로 세지 않는다. **입출력은 텍스트**다. 외부 OCR·브라우저 도구를 쓰는 사례를 모델 자체의 이미지·음성 입력 지원으로 확대하지 않는다. [가중치 공개 발표](https://reflection.ai/blog/beam-is-available).

### 활용 예와 실행 조건

격리한 작은 저장소에서 테스트 실패를 설명하고 수정안을 만드는 coding agent, 긴 기술문서 요약과 도구 호출 평가에 활용할 수 있다. vLLM 공식 recipe는 현재 일반 release 대신 전용 `vllm/vllm-openai:reflection-beam` 이미지와 `beam` reasoning/tool parser를 안내한다. 해당 환경에서 FP8의 대표 명령은 다음과 같다.

```bash
vllm serve reflection/Beam-1.0-501B-A23B-FP8 --tensor-parallel-size 8 --moe-backend triton --kv-cache-dtype fp8 --enable-auto-tool-choice --tool-call-parser beam --reasoning-parser beam
```

이후 로컬 chat-completions API에 실패 로그와 “원인과 최소 수정안을 설명하라”는 요청을 보낼 수 있다. [vLLM 공식 실행 recipe](https://recipes.vllm.ai/reflection/Beam-1.0-501B-A23B).

recipe의 권장 예는 FP8 **8× H200**, BF16 **8× B200/B300**, NVFP4 **4× B200/B300**이다. 23.4B active를 필요한 저장량으로 계산하지 않는다. GPU별 처리량·전체 1M 문맥에서의 동시 요청 수는 실제 배포 설정으로 시험해야 한다. 기본 reasoning effort가 최대이므로 짧은 업무에서도 비용을 따로 살펴야 한다. 이번에 설치·실행하지 않았다.

### 날짜·라이선스·평가 한계

**10/5는 사전 발표, 10/16은 가중치 공개**다. 오늘 관찰일 10/17과 각각 구분한다. [10/5 발표](https://reflection.ai/blog/introducing-beam), [10/16 출시](https://reflection.ai/blog/beam-is-available). 각 발표의 정확한 시간대와 HF 생성·수정 timestamp는 미확인이다.

공식 카드와 출시 발표는 **Apache-2.0**을 명시한다. 별도 LICENSE 파일 직접 열람은 실패해 원문 전문 검토를 완료했다고 주장하지 않는다. API 서비스 약관을 공개 가중치 라이선스와 혼동하지 않는다.

카드의 BF16 SWE-bench Verified 81.6%, Terminal-Bench 2.1 80.1%는 **개발사 평가**이며, 초기 발표와 최종 카드 수치도 일부 다르다. 다른 harness·정밀도·평가 버전의 수치와 섞지 않는다. 영어 중심 모델이므로 한국어 업무 성능과 도구 실행 안전성은 별도 검증 대상이다. [최종 카드의 평가 조건](https://huggingface.co/reflection/Beam-1.0-501B-A23B).

## 2. MOSS-Image: 텍스트·레이아웃을 조건으로 쓰는 이미지 생성 분기

**개발:** OpenMOSS Team. **규모:** 생성 DiT 약 **5B**, Qwen3.5-9B text encoder와 VAE는 별도다. **태그:** text-to-image, DiT, flow-matching, text-rendering, layout-control, Chinese, English.

### 신규성 근거와 재사용 범위

기존 MOSS 음성·전사·실시간 시각 모델과 달리, 별도 이미지 생성 Transformer가 텍스트와 이미지 토큰을 결합해 flow-matching으로 이미지를 생성한다. 공개 구현의 기본 구조는 **42층·hidden 3072·24 heads**다. 언어 모델의 답변을 조금 수정한 fine-tune이나 기존 이미지 checkpoint의 양자화 배포로 소개하는 것이 아니다. [공식 파이프라인 구현](https://huggingface.co/OpenMOSS-Team/MOSS-Image-Base/blob/main/pipeline_moss_image.py).

다만 **Qwen text encoder와 FLUX.2-klein-4B 계열 VAE를 재사용**한다. 따라서 모든 구성요소를 처음부터 학습한 독립 모델이라고 쓰지 않는다. DiT의 정확한 초기 가중치·전체 학습 데이터와 compute는 이번에 확정하지 못했다. 선정은 공식 Base 공개, 별도 생성 구조와 학습 대상이 있는 이미지 분기라는 근거에 따른다. 기존 MOSS 계열의 이름 변경만으로 판단하지 않았다.

공식 설명은 최대 4K prompt, 영문·중문 글자 렌더링과 **JSON layout 조건**을 제시한다. Base와 그 Base를 선별 데이터로 추가 학습한 **SFT를 한 계열**로 묶는다. ComfyUI plugin·포맷·LoRA 역시 별도 모델 수가 아니다. [공식 모델 구분·공개 기록](https://github.com/OpenMOSS/MOSS-Image).

### 활용 예와 한계

포스터의 제목·설명·그림 위치를 함께 지정하는 시안을 만들 수 있다. 예를 들어 1024×1024 캔버스에 “상단에는 EXPLORE, 하단에는 산 그림”이라는 장면을 자연어 또는 `summary/items` JSON으로 제공하고, 텍스트와 객체마다 bbox를 지정한다. 이 bbox는 일반적인 좌상단 기준과 달리 **캔버스 중앙 원점의 yxyx 좌표**이므로 UI 변환 때 주의한다. [공식 layout 예제](https://github.com/OpenMOSS/MOSS-Image#-layout-to-image-generation).

Python 실행 경로는 `DiffusionPipeline.from_pretrained`에 해당 모델과 `custom_pipeline="pipeline_moss_image"`를 지정하는 방식이다. 공식 예제는 BF16 생성부·FP32 VAE, 50 steps, CFG 3, negative branch의 layer 22 skipping을 사용한다. 실행 전 custom code를 검토하고 revision을 고정해야 한다. [공식 카드](https://huggingface.co/OpenMOSS-Team/MOSS-Image-Base).

**layout은 실험 기능**이며 글자·줄바꿈·위치 준수가 보장되지 않는다. Base는 CFG 증류 모델이 아니고 권장 품질에는 많은 sampling steps가 필요하다. 영어 비중이 높은 학습 자료와 영어·중문 예시를 한국어 렌더링 성능 보증으로 바꾸지 않는다. 권장 출력은 약 1M~2M pixels, 각 변은 16의 배수이며 정확한 최소 VRAM은 미확인이다. CPU offload는 선택지지만 속도와 메모리를 따로 측정해야 한다. [공식 사용자 가이드](https://github.com/OpenMOSS/MOSS-Image/blob/main/USERGUIDE.md).

### 라이선스·날짜·미확인 항목

카드는 가중치를 Apache-2.0으로 안내하며 standalone pipeline 코드도 Apache-2.0이다. 외부 encoder·VAE의 원래 고지는 별도 확인한다. **공식 공개 기록은 10/16**, 이번 관찰·소개는 10/17이다. 정확한 최초 공개 시각·HF timestamp는 미확인이다. [모델 카드](https://huggingface.co/OpenMOSS-Team/MOSS-Image-Base), [공식 저장소](https://github.com/OpenMOSS/MOSS-Image).

[기술보고서 PDF](https://github.com/OpenMOSS/MOSS-Image/blob/main/paper/MOSS_Image_Technical_Report.pdf)는 존재를 확인했지만 본문 파싱에 실패했다. 학습 초기화·학습량을 PDF에서 확인한 것처럼 쓰지 않는다. 공식 가이드의 샘플 이미지 prompt에 나온 학습 관련 문구도 모델의 실제 학습 사실로 채택하지 않았다.

## 3. Timestral: 역할별 attention과 분리된 예측 토큰

**개발:** Mistral AI. **규모:** 대표 **209M**, 5M·28M·123M도 같은 한 계열이다. **태그:** time-series, multivariate, probabilistic-forecasting, covariates, missing-values, CPU.

### 신규 계열의 근거

Mistral의 첫 시계열 기반 계열로, 기존 인덱스의 Shieldstral이나 다른 회사의 TimesFM 계열과 구분한다. 이름이 비슷한 시계열 모델의 단순 fine-tune이라고 볼 근거가 없으며, 공식 자료가 별도의 **순수 합성 사전학습→실제·합성 혼합 후속학습**을 설명한다. 무작위 초기화라는 명시적 고지까지 확인했다는 뜻은 아니다. [공식 공개·학습 설명](https://mistral.ai/news/timestral/).

핵심은 관측 이력을 지우지 않고 별도 forecast token으로 예측하는 **Decoupled Horizon Forecasting**, 그리고 target·과거 공변량·미래값을 아는 공변량의 역할별 attention이다. 미래 공변량은 활용하되 target의 미래값이 새어 들어가지 않게 한다. 8,192 시점의 합성 사전학습 뒤 문맥을 네 배로 늘리며 21개 quantile pinball loss를 사용한다. 이는 LLM을 숫자 prompt에 맞춰 경미하게 조정한 모델과 다른 구조·학습 경로다. [기술 개요](https://mistral.ai/news/timestral/).

209M은 **24층·embedding 768**, patch당 32시점을 처리한다. 과거 최대 32,768시점에서 한 번에 최대 1,024시점을 예측하고 결측은 NaN으로 표현한다. 여기서 길이의 단위는 텍스트 token이 아니라 **시계열 시점**이다. [공식 모델 카드](https://huggingface.co/mistralai/Timestral-209M).

### 활용 예와 검증 조건

설비 센서·서버 부하·재고 수요의 여러 관련 시계열을 함께 예측하는 baseline 후보이다. 미래에 이미 확정된 휴일·운영 일정만 공변량으로 넣고, 알 수 없는 실제 미래값을 넣지 않는다. 다음은 합성 시계열을 사용하는 작은 API 예시다.

```python
import numpy as np
from timestral import TimestralForecaster

forecaster = TimestralForecaster.from_pretrained("mistralai/Timestral-209M")
history = np.sin(np.arange(1000) / 24)
prediction = forecaster.forecast(history, prediction_length=96)
print(prediction.median)
```

[공식 코드·API 문서](https://github.com/mistralai/timestral/). Python 3.10 이상·PyTorch 2.4 이상을 안내하며 CPU/GPU 경로가 있다. 실제 업무에서는 시간 순서대로 나눈 검증, 단순 seasonal baseline과의 비교, 예측 구간의 coverage·결측·분포 변화를 따로 점검해야 한다.

1,024시점보다 긴 예측은 블록별 **중앙값을 문맥에 다시 넣어 반복**하므로 장기 오차 누적을 확인해야 한다. 21개 quantile 출력 자체가 업무 환경에서 잘 보정된 확률을 보증하지 않는다. 카드의 최대 문맥과 초과 입력을 자르는 실행 동작도 구분한다. [모델 한도](https://huggingface.co/mistralai/Timestral-209M), [실행 구현](https://github.com/mistralai/timestral/).

### 라이선스·날짜·평가

**가중치는 Modified MIT, 코드는 Apache-2.0**이다. 원문은 회사 또는 고용주의 **직전 월 글로벌 연결 매출이 USD 20M을 초과**하면 해당 라이선스 권리를 행사할 수 없다고 명시하며, 별도 상업 라이선스 요청 경로를 안내한다. 파생·수정·결합물에도 해당 조건이 적용된다. 연매출 조건으로 바꾸거나 일반 MIT·무제한 상업 이용으로 축약하지 않는다. [가중치 LICENSE](https://huggingface.co/mistralai/Timestral-209M/blob/main/LICENSE)를 확인해야 한다.

공식 발표는 **10/15**, 이번 관찰·소개는 **10/17**이다. 발표 시각의 시간대와 HF 생성·수정 timestamp는 미확인이다. [출시 발표](https://mistral.ai/news/timestral/).

GIFT-Eval·TIME·fev-bench 선두라는 설명은 **Mistral 자체 보고**다. 이번에 독립 재현하거나 모든 실제 데이터에서의 우위를 확인하지 않았다. 모델 카드가 안내하는 상세 technical report는 아직 예고 상태이므로 공개된 설명을 넘어 학습 데이터 구성·총량을 추정하지 않는다. [평가표·보고서 상태](https://huggingface.co/mistralai/Timestral-209M).
