## 1. SperidLabs Iris-3B

**태그:** text-to-image, pixel-space, rectified-flow, diffusion-transformer, depth-estimation, restoration, super-resolution.

### 신규 계열로 보는 이유

VAE latent를 생성한 뒤 복호화하는 대신 픽셀을 직접 예측하는 독립 학습 backbone이다. 8개 dual-stream + 16개 single-stream Transformer 뒤에 4-block PiT pixel head를 연결한다. Qwen3-VL-4B는 동결 텍스트 조건 인코더이며, Qwen 이미지 모델의 단순 fine-tune을 뜻하지 않는다. 256→512→1024 해상도 curriculum과 마지막 SFT를 포함한 665K-step 학습을 공개한다. 기존 PixelUMM·PixelModel-v5와 픽셀이라는 표현을 공유해도 같은 체크포인트가 아니다. [공식 코드·학습 recipe](https://github.com/speridlabs/iris-3b).

PixelDiT 설계에서 영향을 받은 독립 구현이다. 논문에는 별도로 FLUX.2 Klein을 픽셀 공간으로 바꾸는 실험도 있지만, **Iris 자체의 from-scratch 학습과 그 변환 실험을 구분**해야 한다. 생성·depth·upscaler checkpoint와 양자화본은 같은 한 계열로 계산한다. [논문](https://arxiv.org/abs/2610.09450).

### 활용 예와 실행 조건

광고·콘셉트 이미지 초안 생성, 사진의 상대 깊이 추정, 손상 이미지 복원·4배 확대의 연구 baseline으로 검토할 수 있다. 깊이와 복원은 **별도로 fine-tune된 가중치**를 사용하며, 생성 checkpoint 하나가 지시만 바꿔 모든 작업을 수행하는 것은 아니다.

공식 설치 후 생성 가중치를 내려받고 다음과 같이 실행한다. 예시는 이번 조사에서 실행하지 않았다.

```bash
python scripts/sample.py --checkpoint iris-3b --prompt "A ceramic cup beside a rainy window"
python scripts/depth.py sample.jpg --out depth_result
python scripts/upscale.py sample.jpg --out restored_result
```

Python 3.11 이상·PyTorch 2.7.1 이상·CUDA NVIDIA GPU가 필요하다. 생성 가중치 약 12GB에 text encoder가 추가되고 depth/upscaler도 각각 별도 약 12GB다. 기본 생성 설정은 1024×1024, 100 steps, CFG 3이다. 공식 데모는 세 모델 동시 상주 약 45GB, CPU offload 사용 시 GPU peak 약 20GB를 안내하지만 이는 제작자 설명이며 모든 환경의 최소 요구량은 아니다. [실행·메모리 안내](https://github.com/speridlabs/iris-3b#inference).

### 과장하면 안 되는 결론

논문은 동일한 과제 적응 조건에서 **픽셀 기반 사전학습의 depth·restoration 우위를 찾지 못했다**고 보고한다. depth는 상대값이며 실제 거리 측정으로 바로 사용할 수 없다. 텍스트 렌더링·정확한 객체 개수에도 한계가 있다. 성능은 연구진 자체 평가로 다룬다. [논문 결과](https://arxiv.org/abs/2610.09450), [모델 카드](https://huggingface.co/speridlabs/iris-3b).

논문 제출은 10/7 05:07 UTC이고 HF 저장소 생성은 10/5 23:51 KST다. 저장소 생성일을 실제 가중치 공개일로 확정하지 않았다. 코드와 가중치는 Apache-2.0이며 동결 text encoder 등 외부 자산의 조건은 별도 유지된다.

## 2. JetBrains Mellum2/2.1 계열

**태그:** text-generation, MoE, coding-agent, tool-calling, reasoning, long-context, reinforcement-learning.

### 첫 소개와 버전 업그레이드를 구분

전체 인덱스와 기존 66개 보고서에 Mellum 소개는 없었다. 이번에는 **Mellum2 계열 전체를 처음 소개**하면서 최근 공개된 2.1 Thinking을 대표로 삼는다. 2.1이 2.0과 다른 아키텍처라는 예외 판정은 하지 않는다. JetBrains도 구조가 그대로이고 개선이 주로 RL post-training에 있다고 명시한다. Base·Instruct·Thinking·2.1·GGUF·MLX 등 직접 변형은 한 계열로 묶는다. [2.1 공식 발표](https://blog.jetbrains.com/ai/2026/10/mellum2-1-gets-to-work-a-fast-open-model-for-coding-agents/).

기반 Mellum2는 약 10.6T tokens로 별도 사전학습한 12B MoE다. 64 experts 중 8개를 활성화하고 GQA, 3:1 sliding-window/full attention, 28 layers와 131,072-token 문맥을 사용한다. 기존 Qwen의 단순 fine-tune이 아니다. 기본 계열 논문은 **5월 29일**, 공개 발표는 **6월 1일**이므로 이를 10월 신규 foundation 출시로 바꾸어 적지 않는다. [기술 보고서](https://arxiv.org/abs/2605.31268), [Mellum2 공식 발표](https://huggingface.co/blog/jetbrains/mellum2-launch).

### 활용과 사용 예

독립 sandbox에서 작은 코드 수정안을 만들고 테스트하는 coding sub-agent 후보이다. 2.1은 실제 저장소·shell·파일 편집 환경의 RL을 확대했다. 서버 준비 후 다음처럼 공식 reasoning/tool parser를 붙일 수 있다.

```bash
vllm serve JetBrains/Mellum2.1-12B-A2.5B-Thinking --max-model-len 131072 --reasoning-parser qwen3 --enable-auto-tool-choice --tool-call-parser hermes
```

[공식 모델 카드·실행법](https://huggingface.co/JetBrains/Mellum2.1-12B-A2.5B-Thinking).

활성 2.5B는 저장해야 하는 가중치가 2.5B라는 뜻이 아니다. BF16 전체 가중치는 단순 산술로 약 24GB 규모이며 KV cache·runtime 여유가 추가된다. 정확한 최소 VRAM은 이번에 검증하지 않았다. 사용자 코드에서 도구 호출·오류 복구·수정 범위를 별도 검사하고, 모델이 만든 명령을 무제한으로 실행하지 않는다.

개발사 자체 평가에서 SWE-bench Verified 47.0%, Terminal-Bench 2.1 17.4%다. 성능 향상이 있어도 성공 보장은 아니며 harness·sampling 조건이 다른 수치와 섞지 않는다. 현재 모델 카드의 MTP 배포 예고와 발표의 MTP 속도 측정도 구분해야 한다. 제공되지 않은 head를 바로 사용할 수 있다고 가정하지 않는다. [평가·조건](https://huggingface.co/JetBrains/Mellum2.1-12B-A2.5B-Thinking#evaluation).

## 3. Tencent Youtu-Parsing-Omni

**태그:** document-parsing, OCR, omni-modal, audio-video, shared-encoder, structured-JSON, on-policy-distillation.

### 신규 계열로 보는 이유

이미지·음성을 각기 다른 대형 tower로 처리하는 대신 **공유 양방향 Youtu-Omni-Encoder**에 픽셀·log-mel용 stem을 연결한다. 영상 frame과 음성 chunk가 같은 시간 좌표를 쓰며 encoder 내부의 fusion layer에서 만난다. 이후 Youtu-LLM decoder가 문서·자연 이미지·도표·기하·음성·영상 내용을 공통 OmniSchema로 생성한다. 공개 설정은 28층 omni encoder, 40층 text decoder와 별도 modality merger를 보여 준다. 기존 OCR 모델의 포맷 변환이나 JSON prompt 변경만은 아니다. [공식 구조 설명](https://github.com/TencentCloudADP/youtu-parsing/tree/main/youtu_parsing_omni), [공개 config](https://huggingface.co/tencent/Youtu-Parsing-Omni/blob/main/config.json).

학습은 SFT·schema-routed RLVR 뒤에 **OSAD**를 사용한다. 학생의 parse를 JSON·schema·좌표 문법 등으로 검사하고, 정답 parse도 보는 frozen teacher로 content/structure token에 서로 다른 divergence 목표를 적용한다. text LM에서 encoder를 초기화하므로 모든 구성요소가 from scratch라고 소개하지 않는다. 기존 인덱스에 없는 별도 omni parsing 계열이며, 새 크기·포맷·경미한 task 변형은 추가 계열로 세지 않는다.

### 활용 예와 배포 주의

강의 영상의 화면 글자와 음성 구간을 함께 구조화하거나, 문서의 표·수식·reading order를 후속 검색에 넣는 전처리 후보다. 공식 Transformers 환경을 별도로 준비한 뒤의 예시:

```bash
python examples/infer_transformers.py --model tencent/Youtu-Parsing-Omni --task textrich_video --media ./lecture.mp4
```

[공식 실행 안내](https://github.com/TencentCloudADP/youtu-parsing/tree/main/youtu_parsing_omni#quick-start).

- vLLM과 Transformers 경로는 서로 다른 pinned Transformers 버전을 사용하므로 환경을 분리한다. CUDA GPU와 audio/video용 ffmpeg가 필요하다.
- custom code를 먼저 검토하고 revision을 고정한다. config의 1M position 값과 공식 serving script의 **65,536 context 설정**은 다르며 1M 실사용 검증으로 해석하지 않는다.
- parsing 모드·media-first 입력 순서·특수 coordinate token 보존이 중요하다. JSON을 반환해도 schema validation과 OCR·timestamp 정확도 검증은 필요하다.
- OmniDocBench 96.96, OmniParsingBench 75.08은 **Tencent 자체 보고**이며 공개 평가 코드는 아직 예고 상태다. 독립 재현 결과나 전 분야 최고 성능으로 확대하지 않는다.

**라이선스 주의:** 일반 Apache-2.0이 아닌 **Youtu-Parsing 약관**이다. 원문에 EU 내 사용을 대상으로 하지 않는다는 추가 지역 제한이 있다. 외부 구성요소만 Apache 등으로 표시된 부분을 전체 모델 라이선스로 오해하면 안 된다. [배포 라이선스](https://huggingface.co/tencent/Youtu-Parsing-Omni/blob/main/LICENSE).

공식 News는 공개를 2026-10로만 적고 있다. HF 생성·수정은 10/9 KST로 확인했지만 정확한 최초 대외 발표일은 미확인이다. README 상단의 technical report 예고와 하단 PDF 링크도 혼재하므로 이번 판단은 실제 확인한 카드·코드·설정에 근거한다.

## 4. Neuphonic NeuDecide

**태그:** speech-to-tool, voice-action, encoder-decoder, on-device, ONNX, English.

### 기존 Whistle·Needle과 다른 점

기존 Whistle→Needle3 경로는 음성을 먼저 **전사한 뒤 텍스트로 도구를 고른다**. NeuDecide는 사전학습 FastConformer와 Needle 초기 가중치를 사용하지만, audio latent와 tool-schema token을 tool encoder에 함께 넣고 **중간 전사 없이 tool call을 생성하도록 전체를 공동 학습**한다. 새 입력 경로·연산 그래프·학습 목적이 확인돼 별도 speech-to-tool 분기로 인정한다. 완전히 새 foundation model이라는 뜻은 아니다. [NeuDecide 구조](https://github.com/neuphonic/neudecide#how-it-works), [기존 Needle·Whistle 경로](https://github.com/cactus-compute/needle).

audio encoder 28.7M, tool encoder 11.8M, decoder 15M을 합쳐 55.5M이다. 12.5Hz audio latent와 cached decoder를 사용한다. 세 ONNX graph 및 q4 배포는 세 모델 계열로 세지 않는다. 상세 학습 corpus·전체 recipe와 논문은 이번 조사에서 확인하지 못했다.

### 활용 예와 실패를 막는 조건

집 안 기기의 상태 조회처럼 작고 명확한 영어 음성 명령을 로컬에서 처리하는 후보다. 공식 Python package의 API는 다음처럼 음성과 JSON schema를 받고 호출 후보를 반환한다. 실제 도구 실행은 별도 검증 후 처리해야 한다.

```python
from neudecide import NeuDecide

tools = [{
    "name": "getStatus",
    "description": "Read the device status.",
    "parameters": {"type": "object", "properties": {}}
}]
model = NeuDecide.from_pretrained()
calls = model.generate("status_request.wav", tools)
print(calls)
```

[공식 사용법](https://github.com/neuphonic/neudecide#quickstart).

Python 3.10~3.13, ONNX Runtime 경로다. 모델을 내려받은 후 offline 실행할 수 있지만 HF에는 **자동 승인형 접근 조건과 연락처 공유 동의**가 있다. 이번 조사에서 동의 제출이나 가중치 다운로드는 하지 않았다. [배포 페이지](https://huggingface.co/neuphonic/neudecide).

영어만 지원하며 음성 30초·tool description 1,536 tokens·출력 128 tokens 제한이다. 도구는 10개 이하를 권장하고, 고정 인자는 enum으로 제한하는 편이 낫다. 제작자는 잡음만으로도 호출이 발생하고 calibrated confidence가 없다고 명시한다. 따라서 VAD·명시적 no-action 경로·안전한 fallback 없이 잠금 해제나 결제 등 중요한 동작에 바로 연결하면 안 된다.

SLURP에서 tool accuracy 75.5%와 **인자까지 맞는 exact match 37.5%**는 다른 지표다. 자유형 인자에서는 전사 cascade가 더 나을 수 있다. 기기별 46~206ms도 제작자 자체 측정이며 한국어·다른 기기의 성능은 검증되지 않았다. [평가·한계](https://github.com/neuphonic/neudecide#limitations).

HF 생성은 10/6 18:17 KST다. package의 10/7 prerelease·10/8 stable 공개는 소프트웨어 날짜이며 HF 가중치 최초 공개 시각과 같다고 단정하지 않는다. [PyPI 이력](https://pypi.org/project/neudecide/#history).

## 제외·보류한 후보

- **Phocinae-Largha:** mmBERT-small 기반 typed-decision 미세조정과 순서 augmentation이다. 명백한 세대 전환으로 확정하지 않았으며 기존 decision 계열을 수량 채우기 위해 재포장하지 않았다. [공식 카드](https://huggingface.co/Phocinae/Phocinae-Largha-150M-v1).
- **LightOnOCR-3:** grounding·도표 추출·학습 개선은 확인했지만 1B는 기존 구조, 0.8B/4B는 Qwen3.5 VLM 기반이다. 이번에는 기존 LightOnOCR-2·Qwen 계보에서 직접 post-training을 넘어서는 차세대 예외를 보수적으로 확정하지 않았다. 새 버전명만으로 재소개하지 않는다. [공식 발표](https://huggingface.co/blog/lightonai/lightonocr-3).
- **FrogNano:** Qwen3.5-4B 구조를 유지한 coding RL 특화이다. TaskPilot 기반 학습은 흥미롭지만 이번 엄격한 기준에서는 기존 계열 직접 파생본으로 제외한다. [Microsoft 카드](https://huggingface.co/microsoft/FrogNano-4B-2609).
- **Paradee-8M:** Kokoro의 폭을 줄인 직접 증류·ONNX 배포다. 작은 용량만으로 독립 신규 계열을 인정하지 않았다. [제작자 카드](https://huggingface.co/sahilmahendrakar/Paradee-8M-v1.0).
- **KittenTTS 2:** speech LM·ternary 배포·voice cloning은 확인했으나 이번 조사에서 사전학습 계보와 기존 기반과의 차이를 충분히 검증하지 못해 보류한다. packed/emb4/full 파일을 서로 다른 모델로 세지 않는다. [공식 카드](https://huggingface.co/KittenML/kitten-tts-2).
- **pplx-embed-v2-late 0.6B/9B**는 10/9 소개한 한 계열이다. EmbeddingGemma 2·Clef·Kolibri·Prism·EMA·Kandinsky 6.0·d1-omni 및 Qwen·MiniMax·LTX의 크기·양자화·GGUF·MLX·LoRA 변형도 재소개하지 않는다.

보류·제외 후보는 오늘 소개 수와 새 인덱스 항목에 포함하지 않는다.
