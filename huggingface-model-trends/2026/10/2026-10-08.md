## 1. Kandinsky 6.0 Video

**태그:** text-to-audio-video, image-to-audio-video, CrossDiT, joint-generation, flow-matching, video-super-resolution.

### 신규 계열로 보는 이유

Kandinsky 5.0의 사전학습 영상 stream에 **새로 학습한 audio stream과 block별 양방향 cross-attention**을 연결한다. 음성 단독 사전학습 후 영상·음성을 공동 학습하므로 단순 포맷 변환이나 영상 LoRA 가속과 구별된다. Pro core는 영상 19B + 음성 5B + 연결부 5B, Lite는 2B + 0.6B + 0.4B로 설명한다. 기존 인덱스의 KVAE-Audio는 오디오 tokenizer 계열이고, 이번 것은 동기화된 영상·음성을 만드는 별도 생성 계열이다. 모든 구성요소를 처음부터 학습했다는 뜻은 아니다. [논문 구조·학습](https://arxiv.org/html/2610.05608v1#S3), [공개 Pro 설정](https://github.com/kandinskylab/kandinsky-6/blob/main/kandinsky/configs/modules/transformer_pro.json).

Pro·Lite, pretrain·post-trained·distill, 원래 배포·Diffusers 버전은 **한 계열**로 묶는다. 증류된 checkpoint의 수나 크기별로 신규 수를 늘리지 않는다.

### 활용과 실행 조건

- 텍스트 또는 참조 이미지에서 소리가 동기화된 짧은 영상 초안, 효과음·말소리와 입 움직임의 일치 실험에 적합하다.
- 기본 생성은 약 **5초·SD**, Full HD는 별도 super-resolution 단계로 만든다. native Full HD 생성이나 장편 영상 모델로 소개하면 부정확하다. 시각 품질과 전체 오디오 품질에는 최상위 비공개 모델과 차이가 남아 있다고 연구진도 밝힌다. 비교 평가는 **개발사 자체 평가**이며 독립 재현 결과가 아니다. [논문 한계·평가](https://arxiv.org/html/2610.05608v1#S10).
- 공식 저장소는 NVIDIA GPU, Python 3.13/3.14, uv·just를 안내한다. Hopper와 소비자 GPU에서 attention backend가 다르며 일부 경로는 CUDA compiler가 필요하다. [공식 실행 안내](https://github.com/kandinskylab/kandinsky-6#quick-start).
- 24GB RTX 4090 preset도 **block offload**를 사용한다. 16GB RTX 5060 Ti preset은 text encoder 양자화까지 사용한다. 작은 VRAM preset이 가중치 전체를 GPU에 올린다는 뜻은 아니다. 충분한 시스템 RAM·저장 공간과 데이터 이동 비용을 별도로 확인해야 한다. 이번 조사에서는 최소 시스템 RAM과 실제 실행 시간을 검증하지 않았다. [4090 설정](https://github.com/kandinskylab/kandinsky-6/blob/main/kandinsky/configs/devices/rtx-4090.yaml), [16GB 설정](https://github.com/kandinskylab/kandinsky-6/blob/main/kandinsky/configs/devices/rtx-5060-ti.yaml).

공식 native 설정은 **Pro-distill: PiflowScheduler, 10 steps, guidance 1.0**이고 일반 Lite는 **FlowMatchEulerDiscreteScheduler, 50 steps, guidance 5.0**이다. scheduler·guidance를 checkpoint 간에 그대로 섞지 않는다. [증류형 설정](https://github.com/kandinskylab/kandinsky-6/blob/main/kandinsky/configs/checkpoints/pro-distill.yaml), [일반형 설정](https://github.com/kandinskylab/kandinsky-6/blob/main/kandinsky/configs/checkpoints/lite.yaml).

환경과 HF 접근 권한을 준비한 뒤의 사용 흐름은 저장소 최상위에서 `just setup`, `just download pro-distill`, `just generate "A cat watches the rain, with soft rain sounds."` 순이다. README의 clone 명령은 기본적으로 `kandinsky-6` 폴더를 만들지만 다음 줄은 `cd k6_video`로 적혀 있으므로 **실제로 생성된 폴더에 들어가야 한다**. 예시는 이번에 실행하지 않았다. [확인한 README](https://github.com/kandinskylab/kandinsky-6/blob/main/README.md).

### 배포·날짜 주의

공개 API는 대표 Pro 저장소를 **gated: auto**로 표시했다. 비로그인 raw README·설정 조회는 HTTP 401이었으므로, HF 파일 본문을 모두 열람하거나 가중치를 다운로드했다고 주장하지 않는다. 기술 판단은 공개 논문·공식 GitHub 코드·HF 메타데이터를 교차 확인했다. 실제 사용 전 본인 계정으로 배포 페이지의 접근 조건을 확인해야 한다. 논문은 checkpoint·코드의 MIT 공개를 명시하고, GitHub에 MIT 원문이 있다. 외부 text encoder 등 구성요소의 고지와 생성물 관련 권리까지 자동 보장되는 것은 아니다. [HF 배포](https://huggingface.co/kandinskylab/Kandinsky-6.0-Pro-5s-Diffusers), [코드 라이선스](https://github.com/kandinskylab/kandinsky-6/blob/main/LICENSE).

논문 제출은 **10/4 23:19 UTC = 10/5 08:19 KST**이고 공식 공개 기록은 **10/6**이다. HF 대표 Pro 저장소 생성은 **9/9 19:55 KST**, 마지막 수정은 **10/7 17:37 KST**다. 사전 생성된 저장소 날짜를 출시일로 삼지 않았다. [논문 이력](https://arxiv.org/abs/2610.05608), [공식 공개 기록](https://github.com/kandinskylab/kandinsky-6#project-updates), [HF 메타데이터](https://huggingface.co/api/models/kandinskylab/Kandinsky-6.0-Pro-5s-Diffusers).

## 2. Liquid AI d1-omni-600M

**태그:** multimodal-decision, bidirectional-encoder, vision, audio, classification, option-scoring, edge.

### 신규 계열로 보는 이유

기존 LFM2.5-Encoder-350M의 텍스트 양방향 backbone에 **시각 encoder·음성 encoder·연결 adapter·decision head**를 통합한 멀티모달 분기다. 음성은 FastConformer를 학습하고, 시각은 기존 LFM2.5-VL-450M encoder를 가져와 adapter와 LoRA를 학습한 뒤 전체 모델 fine-tuning·병합을 수행했다. 독립 from-scratch backbone으로 소개하지 않는다. 분류라는 용도나 새 이름만이 아니라 **기존 텍스트 encoder에 없던 모달리티와 공동 입력 구조**를 신규 예외 근거로 삼았다. [공식 구조·학습 설명](https://www.liquid.ai/blog/d1-open).

공개 구현은 같은 trunk에 Vision·Audio 모듈과 별도 DecisionHead를 연결한다. config는 16-layer text trunk, 12-layer SigLIP2 vision tower, 17-layer audio encoder와 2-layer decision head를 확인해 준다. 공식 규모는 trunk·head 381M + vision 94M + audio 112M이다. [구현](https://huggingface.co/LiquidAI/d1-omni-600M/blob/main/modeling_d1.py), [설정](https://huggingface.co/LiquidAI/d1-omni-600M/blob/main/config.json), [모델 카드](https://huggingface.co/LiquidAI/d1-omni-600M).

### 활용과 중요한 한계

텍스트/JSON 상태와 이름 붙인 선택지를 넣어 라우팅·검사 결과를 확률로 받는다. 대화문·전사문을 생성하는 모델이 아니다. 같은 상태에서 여러 질문을 한 번에 처리하는 `system_one(state, questions, images=..., audio=...)` 경로가 제공된다. 이미지 또는 음성은 선택적으로 넣되 **한 요청에 둘을 동시에 넣을 수 없다**. 코드가 이를 오류로 거부한다. [공식 구현·인터페이스](https://huggingface.co/LiquidAI/d1-omni-600M/blob/main/modeling_d1.py).

- 전체 입력 상한은 **16,384 positions**이며 텍스트·이미지·음성이 공유한다. 이미지를 넣으면 상태·질문 텍스트는 **896 tokens**로 잘린다. 내부 RoPE의 128,000 설정을 지원 문맥 128K로 홍보하면 안 된다. [실제 config](https://huggingface.co/LiquidAI/d1-omni-600M/blob/main/config.json).
- 음성은 **16kHz mono**, 최대 30초다. 학습은 영어 화자와 assistant 사이의 요청 중심이므로 한국어 음성 의도 분류 성능을 가정할 수 없다.
- Transformers 5.15 이상과 custom code를 요구한다. 실행 전 코드를 검토하고 revision을 고정한다. 공식 예시는 CPU에서 FP32, GPU에서 FP16을 사용하며 BF16은 답 선택이 달라질 수 있어 피하라고 안내한다.
- text-only 출력에는 type별 temperature 보정이 있지만 이미지·음성은 학습된 softmax 출력이다. 모든 모달리티의 확률이 업무 데이터에서도 보정됐다고 주장하지 않는다. [사용법·제약](https://huggingface.co/LiquidAI/d1-omni-600M#-how-to-use).

개발사는 이 모델을 **초기 연구용 checkpoint**로 설명하며 추론 속도 수치를 제시하지 않는다. 같은 발표의 RTX 4090 8ms 등은 d1-3B 측정이므로 d1-omni에 옮기면 안 된다. Decision Index 15.95도 개발사 측정이며 공식 leaderboard 제출값이 아니다. 이미지·음성 판단은 자체 업무 표본에서 별도로 검증해야 한다. [공식 평가·속도 범위](https://www.liquid.ai/blog/d1-open#fast-inference-everywhere), [카드 평가 설명](https://huggingface.co/LiquidAI/d1-omni-600M#-performance).

### 라이선스와 날짜

**LFM Open License v1.0**이다. 연 매출 **US$10M** 기준의 상업 이용 제한과 재배포 고지 조건이 있으므로 Apache/MIT 또는 무제한 상업 이용이라고 요약하지 않는다. 상업 도입자는 원문의 Threshold 정의와 Section 5 적용 범위를 확인해야 한다. [라이선스 원문](https://huggingface.co/LiquidAI/d1-omni-600M/blob/main/LICENSE).

공식 발표일은 **10/7**이며 페이지가 정확한 시간대를 명시하지 않아 KST 출시 시각은 확정하지 않았다. HF 생성은 **10/6 02:18 KST**, 마지막 수정은 **10/8 05:22 KST**다. 카드의 2025년 LFM2 논문 태그는 기반 연구이지 이번 d1 공개일이 아니다. [공식 발표](https://www.liquid.ai/blog/d1-open), [HF 메타데이터](https://huggingface.co/api/models/LiquidAI/d1-omni-600M).

## 제외 및 보류

- **d1-3B:** 기존 LFM2.5-VL-3B와 LFM2.5-2.6B의 weight averaging·fine-tuning 계보를 유지한다. d1-omni의 새 encoder 경로와 구분하고, decision API만으로 기존 계열의 직접 파생 제외 예외를 인정하지 않았다. [공식 설명](https://www.liquid.ai/blog/d1-open).
- **DMAD:** MiniMax-H3 기반 rank-128 LoRA와 50→4-step 가속이라는 현재 카드 설명이 유지된다. 10/5의 직접 파생 제외 판단을 바꿀 근거를 확인하지 못했다. [현재 카드](https://huggingface.co/ZhengmingYu/DMAD).
- **AstaBrief-8B:** Qwen3-8B의 SFT·offline DPO 기반 과학 보고서 특화 모델이다. 실용성이 있어도 이번 엄격한 기준에서는 직접 미세조정 계열로 계속 보류했다. [Ai2 카드](https://huggingface.co/allenai/AstaBrief_8B).
- **FIBO Scene Analyzer:** Qwen3.6-35B-A3B 기반으로 구조화된 장면·OCR·객체 정보를 생성한다. 상세 schema·특수 token과 여러 기능은 확인했지만, 공개 자료에서 직접 task fine-tuning을 넘는 충분한 세대 전환 근거를 이번에 확정하지 못했다. 기존 FIBO 생성 모델과 이름이 같다는 이유만으로 제외한 것은 아니다. [BRIA 카드](https://huggingface.co/briaai/fibo-scene-analyzer).
- **EmbeddingGemma 2·Prism·EMA**는 10/7, **PixelUMM·UniMate**는 10/6 소개 계열이다. 10/5의 Whistle·Taiga-S1·pplx-embed-v2-context, 10/4의 Kolibri-1·Nanosaur2 및 기존 Qwen·LTX·MiniMax 등의 크기·양자화·GGUF/MLX·LoRA 변형도 재소개하지 않았다.

보류 후보는 오늘 신규 수나 중복 인덱스에 추가하지 않는다. 최대 5개를 채우기 위해 직접 파생본 제외 기준을 완화하지 않았다.
