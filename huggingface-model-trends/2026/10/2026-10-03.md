## 1. PSRben/VisionHOPE

### 무엇이 새로운가

Siran Peng 등 연구진의 범용 시각 backbone이다. self-referential nested learning을 이미지 처리에 적용해 내용, key, value, 학습률, 기억 유지에 관여하는 **5개 기억을 결합 갱신**한다. 이미지의 행·열에 맞춘 chunk를 네 방향으로 스캔하며 문맥을 쌓는다. 무제한 갱신의 불안정성을 줄이기 위해 soft injection cap과 spectral clamp를 도입하고, scan 내부 기억 동역학의 non-expansion을 분석했다. 지속적인 자율 자기개선이나 모든 이미지 사이의 영구 학습을 입증한 것으로 확대 해석해서는 안 된다. [논문](https://arxiv.org/abs/2609.33325).

### 사용·검증 포인트

- 공식 가중치는 ImageNet-1K 분류, COCO 객체 탐지·인스턴스 분할, ADE20K 의미 분할용 T/S/B를 제공한다. 같은 크기·task-head 변형은 한 계열로 묶었다. [모델 카드](https://huggingface.co/PSRben/VisionHOPE).
- 연구진 자체 평가에서 ImageNet-1K 224×224 single-crop top-1은 T 84.1%, S 85.2%, B 85.6%다. 분류 모델 파라미터는 각각 26.6M/52.9M/91.2M이며, 분할 모델 전체 크기와 혼동하면 안 된다.
- Linux·NVIDIA GPU·CUDA 확장 컴파일 환경이 필요하다. 공식 설치 경로는 CUDA 12.1/PyTorch 2.1.0이며, 모델 파라미터는 FP32로 두고 autocast를 사용하는 안내가 있다. **MIT 라이선스**와 third-party notices가 제공된다. [공식 코드·설치·평가표](https://github.com/PSRben/VisionHOPE).

**신규 판정:** 기존 인덱스의 MoEViE·TIPSv2·VGGT-Omega 등을 재포장한 모델이 아니라, SRNL 시각 연산자와 결합 기억 갱신을 핵심으로 하는 별도 backbone 계열이다. 실무에서는 기존 시각 backbone을 교체하는 연구·벤치마크 후보로 우선 검토할 만하다. 속도·GPU 메모리 및 실제 데이터 정확도는 별도 재현이 필요하다.

## 2. Cloudflare/Clef

### 무엇이 새로운가

Cloudflare가 10월 1일 발표한 decision 모델이다. 대표 Clef는 Qwen3.8-27B, Clef-flash는 Qwen3.5-9B를 기반으로 하지만, 상태와 여러 질문의 선택지를 **prefill-only forward pass**로 읽고 질문별 확률을 계산한다. 텍스트·JSON·이미지·비디오를 입력받으며 Jev/SystemOne API와 호환된다. [공식 발표](https://blog.cloudflare.com/clef-decision-models/), [모델 카드](https://huggingface.co/Cloudflare/clef).

단순 출력 형식 조정과 다른 점은 선택지별 evidence routing, field 간 joint attention, schema-bound scoring을 결합한 head다. 공식 설명상 backbone은 고정하고 rank-256 adapters와 routing head를 함께 학습했으며, label-smoothed cross-entropy·Brier loss와 RLCD를 사용해 확률 보정 및 완전한 record 판정을 최적화한다. 이 구조·학습 목적 변화가 기존 Qwen 계열 중복 제외의 예외 근거다. Clef-flash는 별도 1개로 세지 않는다. [학습 설명](https://blog.cloudflare.com/clef-decision-models/#how-we-trained-clef).

### 사용·검증 포인트

- 선택지가 정해진 고객 문의 라우팅, 문서 상태 판정, agent의 후보 행동 scoring 등에 적합하다. 선택지 설계와 오판 시 후속 동작 제한이 중요하다.
- HF 카드의 내부 Decision Index 평가에서 Clef는 BFCL case exact accuracy 98.5%, BANKING77 macro-F1 94.2%를 보고한다. **Cloudflare 자체 평가**이며 모든 과제에서 비교 모델보다 우수한 것은 아니다.
- 공개 구현은 단일 H200, torch 2.11, transformers 5.10.2에서 시험했다고 명시한다. 기본 record encoding 상한은 16,384 tokens다. 일반 chat generation 예시보다 모델 카드의 joint-schema 전용 사용법을 따라야 한다.
- **Apache-2.0**. 재배포 시 해당 라이선스·고지 조건을 확인한다. 제공 확률이 사용자 데이터에서도 보정됐다고 가정하지 말고 held-out 평가를 수행해야 한다. [가중치·사용법·평가표](https://huggingface.co/Cloudflare/clef).

## 3. NVIDIA Kumo-Tabular

### 무엇이 새로운가

라벨이 있는 표의 행을 context로 넣어 새 행의 분류 확률이나 회귀값을 예측하는 표 foundation model이다. 3개 크기(28M~215M)를 제공하며, 인공적으로 생성한 표만으로 사전학습했다고 밝힌다. 새 작업에서는 가중치를 다시 학습하지 않는 in-context prediction을 지향한다. [NVIDIA 발표](https://huggingface.co/blog/nvidia/kumo-tabular).

수치·범주형 cell의 Fourier 표현, 번갈아 적용하는 column/row attention, 4개 readout token의 행 압축, dataset-wise ICL Transformer를 사용한다. query는 context를 읽고 query끼리는 서로 의존하지 않으며 context KV를 재사용한다. 회귀에서는 **999개 quantile**을 출력한다. 길이에 따른 attention temperature와 Test-GQA도 설계에 포함된다. [공식 API 구조](https://nvidia.github.io/structured-data-models/api/generated/sdm.models.KumoTabular), [기술 설명](https://huggingface.co/blog/nvidia/kumo-tabular#how-kumo-tabular-works).

### 사용·검증 포인트

- 고객 이탈, 수요·가격 등 표 기반 예측의 baseline을 빠르게 만드는 후보로 적합하다. 분류·회귀 checkpoint와 Small/Medium/Large는 한 계열이다.
- NVIDIA 자체 평가의 TabArena ELO는 1950이다. 비교 결과를 독립 검증으로 표현하지 않으며, 실제 업무에서는 데이터 분할·누수·calibration을 재검증해야 한다.
- 원래 지원 데이터는 수치·범주형 열이다. 텍스트·이미지·timestamp는 전처리로 feature화한다. 한 번의 native forward는 최대 10개 class이고 더 많은 class는 라이브러리가 확장 처리한다. 학습 범위를 크게 벗어난 표나 분포 변화에서 정확도가 떨어질 수 있다. [평가·제약](https://huggingface.co/blog/nvidia/kumo-tabular#limitations).
- Python 3.11/PyTorch 2.7 이상을 사용하는 `structured-data-models`로 실행한다. NVIDIA 코드의 **Apache-2.0**과 가중치의 **OpenMDW-1.1**은 구분해야 한다. 모델 자료 재배포 시 계약 사본과 적용되는 원산지·저작권 고지를 유지해야 한다. [공식 라이브러리](https://github.com/NVIDIA/structured-data-models), [가중치](https://huggingface.co/nvidia/Kumo-Tabular), [OpenMDW-1.1](https://openmdw.ai/license/1-1/).

**신규 판정:** 기존 TabFM·LimiX-2와 활용 분야는 겹치지만 Kumo의 별도 가중치·구조·합성 표 학습 계열이다. 다른 표 모델의 단순 포맷 변환이나 크기 변경으로 보지 않는다.

## 4. NaiveAI/Naive-N0.5-Flash

### 무엇이 새로운가

9월 27일 발표된 309B MoE/15.5B active 코딩·AI 연구개발 모델이다. MiMo-V2.5 base를 출발점으로 **global attention을 lightweight DSA로 교체**했다. 48개 층은 39 SWA와 9 DSA로 구성되며, SWA window 128, DSA top-2,048 token 선택, GQA 4개 KV group을 사용한다. 공식 카드가 native 1M context를 명시한다. [모델 카드](https://huggingface.co/NaiveAI/Naive-N0.5-Flash).

이 구조에 맞추어 indexer warmup 50B, sparse-attention training 3T, learning-rate decay 200B 등 **총 3.25T tokens**의 다단계 추가 학습을 수행했다고 설명한다. 기존 MiMo 계열이 인덱스에 있어도 attention 구조 및 그 적응 학습의 변화가 명확하므로 독립 후보로 인정했다. FP8·GGUF 등은 같은 계열로 묶는다. [공식 기술 글](https://naive.ai/en/research/).

### 사용·검증 포인트

- 장문 코드베이스와 실험 로그를 다루는 coding/AI R&D agent 연구에 적합한 후보다.
- 개발사 발표는 SWE-bench Pro 73.6, Terminal-Bench 2.1 86.7 등을 제시한다. harness·시간 제한·비교 모델 출처가 섞인 **개발사 자체 평가**다. 최대 2,000 tokens/s 역시 특정 NaiveRT 환경의 주장으로, 일반 GPU의 체감 속도로 환산하지 않는다. [발표·평가 조건](https://naive.ai/en/research/).
- sparse attention이어도 indexer는 전체 이력을 훑고 전체 KV cache를 유지한다. 따라서 1M context의 메모리 비용이 사라지는 구조는 아니다.
- 공식 FP8 실행 안내는 가중치 약 **315GB**에 추가 inference memory를 요구한다. FP8 지원 NVIDIA GPU가 필요하며 사실상 서버급 배포 대상이다. 공개 카드가 사용하는 custom code는 실행 전에 검토해야 한다. **MIT 라이선스**. [배포 제약](https://huggingface.co/NaiveAI/Naive-N0.5-Flash#deployment).

## 5. IQuestLab/IQuest-Q1

### 무엇이 새로운가

IQuest의 text-only agentic coding·reasoning·multi-step tool-use 모델이다. 공개 사양은 320B total/약 15B active, 88 layers, 256 experts 중 8개 활성, 3 SWA + 1 full-attention 반복, 524,288-token context다. 학습 시 독립 MTP 2개 층, 추론 시 재귀 MTP 구성을 제시한다. **512K가 공개 context 한도**이며 CLI 설정에 붙는 `1m` 표기는 이를 늘리지 않는다. [모델 카드·사양](https://huggingface.co/IQuestLab/IQuest-Q1).

**신규 판정:** 기존 인덱스에 없는 IQuest-Q1 공개 계열이며, 별도 `iquest_q1` 구조·tool parser를 제공한다. 조사한 카드에서 기존 제외 모델의 단순 양자화·포맷 변환이라고 표시되지 않았다. 최초 공개일과 상세 사전학습 계보는 이번 조사에서 확정하지 않았으므로 from-scratch 학습을 주장하지 않는다.

### 사용·검증 포인트

- 공개 SGLang/vLLM 예시는 tensor parallel 8을 사용한다. BF16 320B 규모와 긴 context를 감안하면 단일 소비자 GPU용 후보로 보기 어렵다.
- 모델별 tool-call 및 reasoning parser가 필요하다. 이미지·음성·비디오를 직접 처리하지 않으며, 개발사는 실제 CLI 작업에서 제약 누락·실패 반복·미해결 문제가 남을 수 있다고 명시한다.
- 성능표는 개발사의 자체 측정과 다른 모델의 공개 점수를 함께 사용하는 방식이다. 본 보고서는 이를 독립적인 동조건 우열로 재해석하지 않는다.
- 카드의 Codex 설정 예시에는 승인 절차와 sandbox를 해제하는 부분이 있다. 도입 시 해당 예시를 그대로 복사하지 말고 작업 권한을 제한해야 한다. [배포·제약 설명](https://huggingface.co/IQuestLab/IQuest-Q1#limitations).
- **Modified MIT / `iquest-q1` 라이선스**다. 상용 제품·서비스에서 모델 또는 파생물을 사용하면 사용자 인터페이스에 **IQuest-Q1을 눈에 띄게 표시**하도록 요구한다. 일반 MIT와 동일하다고 안내하면 안 된다. [라이선스 원문](https://huggingface.co/IQuestLab/IQuest-Q1/blob/main/LICENSE).

## 중복 제외와 보류

- 9/26 소개된 **openjev, Jev-Omni, Meridian, Lumma-Fev, Von 1.x**를 인덱스 누락 여부와 무관하게 제외했다. 보완된 현재 인덱스에도 같은 5개 계열이 반영됐음을 재확인했다.
- 트렌딩의 Qwen3.8·Qwen-Image-2.1·MiMo-V2.6·MiniMax-H3·LTX-2.5·DeepSeek-V4.1·Nemotron-3-Diarization·Audio8-ASR-Infinite 및 단순 quantization/LoRA/uncensored/format 변형은 재소개하지 않았다.
- **Phonon-2:** 공식 카드가 Parakeet TDT teacher 기반 five-level 약 2.1-bit encoder 압축을 설명한다. 이번 선정에서는 기존 Phonon/Parakeet 파생 흐름을 넘어서는 비압축성 구조·목적 변화의 증거가 충분하지 않아 보류했다. 새 버전명이나 더 작은 다운로드만으로 예외를 인정하지 않았다. [모델 카드](https://huggingface.co/FermionResearch/Phonon-2).
- **Julia-1:** mmBERT-small encoder를 유지하면서 decision head와 decision-format 학습을 추가한 모델이다. 기존 typed-decision 흐름 대비 핵심 학습법·구조의 차이를 공개 자료만으로 충분히 검증하지 못해 이번 5개에서는 제외했다. 영구 중복 등록을 뜻하지 않는다. [모델 카드](https://huggingface.co/SupersonicLabs/Julia-1#from-mmbert-small-to-julia-1).

## 오늘의 Top Pick

**PSRben/VisionHOPE**를 선정한다. 추천 이유는 최대 다운로드가 아니라, 이미지 내부의 기억·갱신 규칙을 결합하는 기술 차이가 논문으로 설명되고 분류·탐지·분할용 코드와 가중치까지 공개됐다는 점이다. 즉시 업무 적용을 우선하면 Clef나 Kumo-Tabular가 더 직접적인 후보일 수 있지만, 오늘의 기술적 신규성을 가장 선명하게 보여주는 계열은 VisionHOPE다.

## 조사·해석 원칙

모든 benchmark·처리량·메모리 수치는 별도 재현하지 않은 **개발사 또는 연구진 자체 평가·측정**으로 다뤘다. 라이선스는 조사 시점 원문·모델 카드 기준이며 실제 도입 시 사용 버전의 조건을 확인해야 한다. 공개 자료가 확인해 주지 않는 출시일·순위 변화·증가율은 채우지 않았다. 보고서 저장 이후에만 당일 소개한 5개 계열을 중복 인덱스에 추가한다.
