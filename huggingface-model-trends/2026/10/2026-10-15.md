# 2026-10-15 Hugging Face 모델 트렌드

조사 기준: **2026-10-15 08:57~09:00 KST(Asia/Seoul)**. HF 트렌딩 상위 5페이지, 공식 발표·배포 설명·공개 구현, 전체 중복 인덱스와 최근 보고서를 대조했다. **신규 소개는 1개 계열, Indra OCR**이다. 최대 5개를 채우기 위해 기존 모델의 크기·양자화·직접 미세조정본을 추가하지 않았다.

**Top Pick: Indra OCR.** CPU 문서 전처리라는 활용 경로가 명확하다. 다만 **한국어 스캔 OCR은 지원하지 않으며**, 코드와 가중치의 라이선스도 다르다.

1M은 탐지·순서·방향·수식 등 모든 구성요소를 합한 값이 아니다. 약 18MB라는 기본 배포 용량도 실행 RAM 요구량으로 환산하지 않는다. 정확한 전체 tensor 수와 학습 데이터·초기 가중치 계보는 확인한 자료에 없었다. [공식 배포 설명](https://github.com/datalab-to/indra/blob/main/README.md), [다운로드 구성](https://github.com/datalab-to/indra/blob/main/indra_ocr/models.py).

## 1. Indra OCR: 작은 인식기와 문서 구조 파이프라인

**태그:** OCR, CPU, CTC, ONNX, document-parsing, PDF, layout, reading-order, Markdown, JSON.

### 신규 계열 판정

기존 전체 인덱스에 없는 Indra 계열의 첫 소개다. 공개 구현은 **줄 탐지 → CTC 줄 인식 → 읽기 순서·레이아웃 처리**를 분리한다. 중국어 줄을 별도 인식기로 보내는 경로, 방향 교정, 선택적 수식 인식도 있다. 확인한 구현은 전용 CTC 인식·문서 구조 파이프라인이며, 기존 소개 계열의 이름 변경이나 단순 ONNX 변환본이라는 근거는 찾지 못했다. ONNX라는 배포 형식 자체를 신규성 근거로 삼지 않았으며, 모든 하위 모델을 from scratch 학습했다고 주장하지도 않는다. [실제 추론 파이프라인](https://github.com/datalab-to/indra/blob/main/indra_ocr/pipeline.py).

공개 패키지는 HF 모델 tag **v3.1**을 고정해 가져온다. 기본 detector·recognizer·order와 선택적 math classifier·attention decoder 파일을 구분한다. 내부 v1/v2/v3, 수식 옵션, 정밀도·ONNX 변형은 **하나의 Indra 계열**로 묶는다. 소프트웨어 버전 0.3.1과 모델 tag v3.1도 같은 버전 체계가 아니다. [파일·revision 설정](https://github.com/datalab-to/indra/blob/main/indra_ocr/models.py), [변경 기록](https://github.com/datalab-to/indra/blob/main/CHANGELOG.md).

### 실무 활용 예

영어 등 지원 문자권의 깨끗한 인쇄 문서를 대량 분류하거나 검색용 텍스트·레이아웃을 먼저 추출하는 용도가 적합하다. 공식 CLI의 `indra-ocr paper.pdf`는 Markdown, `indra-ocr scan.png --format json`은 줄·블록 상자와 신뢰도 등을 반환한다. CPU 수를 제한하려면 `--cores 4`를 사용할 수 있다. Python 3.10 이상, ONNX Runtime·OpenCV·pypdfium2 경로이며 첫 실행 때 HF 가중치를 내려받는다. **설치·실행·문서 변환은 이번에 수행하지 않았다.** [공식 사용 안내](https://pypi.org/project/indra-ocr/).

도입 시험에서는 텍스트 레이어가 있는 PDF와 순수 스캔을 분리하고, 읽기 순서·숫자·표 구조와 실패 페이지 비율을 함께 검사하는 편이 좋다. 이는 활용 제안이며 실제 업무 성능 검증 결과는 아니다.

### “49 pages/s”의 범위

발표의 **49.4 pages/s**는 AMD EPYC **32 CPU cores**, 같은 300개 시험 페이지, 코어당 worker 하나, OCR mode에서의 **개발사 자체 측정**이다. 로딩·워밍업은 제외하며, 로딩을 포함한 300페이지 작업은 37.7 pages/s라고 별도로 보고한다. 단일 코어·노트북·모든 PDF의 처리량으로 일반화할 수 없다. [공식 발표의 측정 조건](https://www.datalab.to/blog/indra-ocr#throughput).

정확도에도 입력 경로 차이가 있다. 자체 OmniParseBench에서 기본 **텍스트 레이어+OCR**의 text 점수는 41.3이지만 **OCR-only는 33.5**다. 같은 표의 PaddleOCR PP-OCR text 모델은 35.8이다. 따라서 “스캔 글자 인식도 항상 PaddleOCR보다 정확하다”는 결론은 성립하지 않는다. 수식 옵션은 정확도·지연시간·표 오독의 절충이므로 별도 시험이 필요하다. [공식 결과](https://www.datalab.to/blog/indra-ocr#results).

### 한국어·복잡한 문서의 제약

- **한국어 Hangul과 일본어 kana는 스캔·이미지 OCR 지원 범위 밖**이다. 디지털 PDF의 기존 텍스트 레이어를 읽을 수 있다는 설명과 구분해야 한다.
- 필기, 심하게 손상된 스캔, 세로쓰기, 병합 셀·다중 헤더가 있는 복잡한 표에는 적합하지 않다.
- `--math`는 선택 사항이며 기본값은 꺼져 있다. 수식 인식 경로가 추가되고 처리량이 줄어들 수 있다.

지원 언어 개수나 “모든 script” 문구만 보고 한국어 스캔 전처리에 배치하지 않는 것이 중요하다. [제작자 제한 사항](https://github.com/datalab-to/indra#limitations), [수식 경로](https://github.com/datalab-to/indra/blob/main/indra_ocr/math.py).

### 라이선스·출시일·미확인 항목

**코드는 Apache-2.0, 가중치는 modified OpenRAIL-M**이다. 제작자의 README 요약은 연구·개인 사용과 **자금/매출 USD 20M 미만 스타트업**의 무상 사용, Datalab API와 경쟁하는 사용의 제한을 명시한다. 무제한 상업용 Apache 모델로 소개하면 부정확하다. 이번에는 **가중치 LICENSE 원문 열람이 실패**했으므로 세부 정의·예외를 독자적으로 확정하지 않는다. 실제 도입자는 원문과 사업 조건을 대조해야 한다. [공식 라이선스 요약](https://github.com/datalab-to/indra#commercial-usage), [가중치 약관 위치](https://huggingface.co/datalab-to/indra-ocr/blob/main/LICENSE).

공식 발표일은 **2026-10-13**이며 발표 페이지의 시간대까지는 확인하지 못했다. GitHub 저장소 생성 timestamp는 **10/13 11:07:11 UTC = 20:07:11 KST**지만 저장소 생성과 가중치 최초 공개는 동일한 사건이 아니다. HF 생성·최근 수정의 정확한 timestamp는 API 열람 실패로 미확인이다. [출시 발표](https://www.datalab.to/blog/indra-ocr), [공식 저장소 메타데이터](https://api.github.com/repos/datalab-to/indra).

## 관찰 수치와 선정 근거

08:57 KST 전후 열람한 [HF 트렌딩 3페이지](https://huggingface.co/models?p=2&sort=trending)에 Indra OCR이 노출됐고 **63 likes**로 표시됐다. 다운로드 수는 해당 목록에 표시되지 않아 미확인으로 둔다. 검색으로 읽은 모델 카드의 이전 캐시는 35 likes여서, 두 값을 같은 시각의 측정치나 정확한 일간 증가량으로 취급하지 않았다.

새 공식 공개, 트렌딩 노출, CPU 활용 경로, 기존 인덱스와 구별되는 모델 구성을 함께 고려했다. **동일 조건의 전주 likes·downloads 스냅샷이 없어 주간 증가율과 순위 상승폭은 계산하지 않는다.** 페이지별 캐시 시점과 경계 중복 때문에 상위 5페이지를 동시 순위표 또는 고유한 150개 모델이라고 부르지 않는다.

## 제외·보류 기록

아래 후보는 오늘 소개 수와 인덱스 추가에 포함하지 않는다.

- **[H2O-Lightning-4B](https://huggingface.co/h2oai/h2o-lightning-4b):** H2O.ai, Apache-2.0, 4B 명칭/HF 반올림 5B. Qwen3.5-4B의 3단계 fine-tuning과 LoRA 배포를 명시한다. 텍스트 중심 학습이며 기존 vision encoder는 변경하지 않았다. typed-decision API와 자체 점수만으로 직접 파생 제외의 차세대 예외를 인정하지 않는다.
- **[KittenTTS 2](https://huggingface.co/KittenML/kitten-tts-2):** Kitten ML, 1.7B speech LM, Stellon Labs Community License. Qwen3 구조의 LM 설정과 Chatterbox 음향 가중치 재사용을 확인했지만, 음성 LM의 초기화·학습 레시피는 미확인이다. Qwen 구조라는 사실만으로 Qwen 사전학습 가중치에서 시작했다고 단정하지 않는다. [최초 공개 설정](https://huggingface.co/KittenML/kitten-tts-2/commit/fa8ce5c7547e322a065cad9b813d27a78fad9640), [공식 vocoder](https://github.com/KittenML/KittenTTS/blob/main/kittenml/kittentts2/vocoder.py)의 Chatterbox-Turbo S3Gen 경로와 [음향 구현의 계보](https://github.com/KittenML/KittenTTS/blob/main/kittenml/kittentts2/s3gen.py)를 고려해 독립 신규 계열 판정을 보류했다. 새 명칭·음성 수·GGUF 배포만으로 수를 늘리지 않는다.
- **[d3 / Decision 3.0](https://huggingface.co/vllm-sr/d3):** 이미지·영상 선택 확률과 serving 개선은 확인했지만, 10/12 보류 판단을 바꿀 만큼 기존 계보 대비 핵심 학습·구조 변화의 근거를 이번에 확보하지 못했다. API 한 호출이 항상 한 번의 forward라는 뜻도 아니다.
- Drama 3·GPT-X3는 [10/14](2026-10-14.md), MiniCPM-V 4.7·LightOnOCR-3는 [10/13](2026-10-13.md)에 이미 소개했다. 다른 크기·GGUF·FP8·ONNX와 기존 Qwen·LTX·MiniMax·Clef·EmbeddingGemma 등의 직접 파생본도 전체 인덱스로 제외했다.

## 전주 비교와 인덱스 감사

- 전주 같은 요일 [2026-10-08](2026-10-08.md)은 **Kandinsky 6.0 Video·d1-omni-600M 2개**, 오늘은 **Indra OCR 1개**다. 당시 영상·음성 공동 생성과 소형 멀티모달 판단에서 오늘은 CPU 문서 인식으로 선정 주제가 달라졌다. 이는 아카이브의 선정 수·구성 비교이며 시장 수요 감소나 동등 조건 성능 비교가 아니다.
- main의 [10/8](2026-10-08.md)·[10/9](2026-10-09.md)·[10/10](2026-10-10.md)·[10/11](2026-10-11.md)·[10/12](2026-10-12.md)·[10/13](2026-10-13.md)·[10/14](2026-10-14.md) 전체 본문과 전체 인덱스를 대조했다. **2+1+4+0+1+2+2=12개 소개 계열이 모두 등록돼 이 범위의 누락은 0개**다. 과거 전체 아카이브를 다시 전수 감사했다는 뜻은 아니다.
- 당일 보고서는 main 전체 tree와 개별 경로 조회에서 없었다. 보고서를 먼저 main에 저장하고 **전체 본문 일치를 확인한 뒤에만**, 기존 인덱스 전체를 보존해 Indra OCR을 추가한다. 누락 날짜의 보고서나 소개일을 소급 생성하지 않는다.

## 결론과 조사 한계

**Top Pick: Indra OCR.** 지원 문자권의 깨끗한 인쇄 문서를 CPU에서 빠르게 처리하는 시험 후보이며, 한국어 스캔·복잡한 표·필기에는 범위를 잘못 적용하지 않아야 한다.

조사 범위: [HF 트렌딩 1페이지](https://huggingface.co/models?sort=trending), [2페이지](https://huggingface.co/models?p=1&sort=trending), [3페이지](https://huggingface.co/models?p=2&sort=trending), [4페이지](https://huggingface.co/models?p=3&sort=trending), [5페이지](https://huggingface.co/models?p=4&sort=trending), 위 공식 자료. 일부 HF 직접 페이지·raw·API·LICENSE 열람은 실패했으며, 검색에 노출된 공식 카드와 공식 GitHub·발표로 확인한 범위만 기록했다. 벤치마크 재현·메모리 측정·모델 실행·개별 사업의 라이선스 적합성은 보증하지 않는다.
