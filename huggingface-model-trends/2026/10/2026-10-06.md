## 1. NVIDIA PixelUMM

**태그:** multimodal, image-to-text, video-text-to-text, image-generation, video-generation, pixel-space, Mixture-of-Transformers.

### 신규 계열로 보는 이유

Qwen3-8B 언어 백본을 출발점으로 삼지만, 이미지는 16×16 pixel patch, 비디오는 4×16×16 tubelet로 표현해 단층 projection으로 넣는다. 이해·생성 expert는 normalization·QKV·FFN 등 task별 parameter를 갖고 attention을 공유한다. **자기회귀 텍스트 예측과 pixel-space flow matching·clean-pixel prediction**을 공동 학습하며, 별도 사전학습 비전 인코더·VAE·이산 시각 토크나이저를 쓰지 않는다. 이미지에서 비디오로 확장하는 다단계 학습도 공개했다. 단순 Qwen fine-tune·양자화가 아니라 새로운 시각 입출력·생성 경로와 목적 함수를 결합한 멀티모달 분기로 판정했다. 전부 from-scratch로 학습한 모델이라고 주장하지 않는다. [논문](https://arxiv.org/html/2609.38597v1), [공식 release config](https://github.com/nv-tlabs/PixelUMM/blob/main/experiments/s8_f22_r07/release.yaml).

### 활용 예와 한계

- 같은 기본 checkpoint인 **S8-F22-R05**로 이미지 설명, 짧은 비디오 요약, 텍스트 기반 이미지·비디오 생성을 비교 실험할 수 있다. 공식 예시는 이미지 질의에 `--task image-vlm`, 비디오 질의에 `--task video-vlm`, 생성에 `--task t2i`·`--task t2v`를 사용한다. 비디오 예시의 96 frames/24fps는 4초다. [실행 예](https://github.com/nv-tlabs/PixelUMM).
- S8-F18-R01은 다른 profile의 checkpoint이며 **video-vlm을 지원하지 않는다**. 이를 새 모델 1개로 추가 계산하거나 기본형과 기능이 같다고 안내하지 않는다. [checkpoint별 차이](https://github.com/nv-tlabs/PixelUMM/blob/main/CHECKPOINT.md).
- 공개 가중치는 linear pixel output head를 사용한다. 매끈한 배경에 격자 무늬가 나타날 수 있고 높은 CFG에서 심해질 수 있다. 논문의 convolutional decoder 실험을 현재 배포 가중치의 기능으로 취급하지 않는다. [공식 프로젝트](https://nv-tlabs.github.io/PixelUMM/).
- 논문은 GenEval 0.77(원본 prompt)/0.83(재작성 prompt), Video-MME 57.33(자막 없음) 등을 제시한다. **연구진 자체 평가**이며 prompt 처리·데이터·비교 조건이 다르므로 모든 이해·생성 모델을 능가한다는 결론으로 확대하지 않는다. [평가 설정·결과](https://arxiv.org/html/2609.38597v1).

Linux·NVIDIA GPU·CUDA/FlashAttention 등 공식 환경을 맞춰야 한다. 최소 추론 VRAM은 이번 조사에서 검증하지 않았다. T2V의 기본 guardrail을 사용하려면 별도 Cosmos guardrail 환경·접근 조건도 확인해야 한다. 실제 실행과 성능 재현은 수행하지 않았다. [환경 설정](https://github.com/nv-tlabs/PixelUMM/blob/main/ENVIRONMENT.md), [guardrail 안내](https://github.com/nv-tlabs/PixelUMM/blob/main/GUARDRAILS.md).

### 도입 전 확인할 배포 문제

공식 `CHECKPOINT.md`의 다운로드 예시는 revision `81d810cf5ba9cd7796079cd40ae32c677e34cd44`를 고정하지만, 조사 시 해당 HF revision은 **HTTP 404**였다. 현재 확인한 main revision은 **`b621a91463d8a438f64c5d0116f42fb13cf26ce7`**이다. 과거 snippet을 그대로 복사하지 말고 사용할 snapshot의 존재를 확인해 고정해야 한다. `__SAVE_COMPLETE`, 숨김 파일 `model/.metadata`와 모든 `.distcp` shard를 유지하고, Qwen 설정·tokenizer를 준비한 다음 제공 `check_checkpoint.py`로 파일·tensor 구조를 검사한다. 이 검사는 GPU에서의 실제 실행 성공을 보증하지 않는다. [공식 다운로드 안내](https://github.com/nv-tlabs/PixelUMM/blob/main/CHECKPOINT.md), [현재 metadata](https://huggingface.co/api/models/nvidia/PixelUMM).

**라이선스:** 가중치는 비상업적 연구·평가용이다. 저장소 코드의 Apache-2.0을 가중치 사용 허가로 혼동하면 안 된다. 코드에도 DiT 유래 파일 등 별도 조건이 있으므로 파일별 고지를 확인한다. [가중치 라이선스](https://developer.download.nvidia.com/licenses/NVIDIA-OneWay-Noncommercial-License-22Mar2022.pdf), [공식 라이선스 설명](https://github.com/nv-tlabs/PixelUMM#license).

**날짜 구분:** 논문 제출은 9/29 21:59 UTC, 즉 **9/30 06:59 KST**다. HF 저장소 생성은 **10/2 06:40 KST**다. API의 lastModified는 생성 시각보다 앞서고 HF 이력에는 저장소 재구성 기록이 있으므로, 이를 그대로 최초 가중치 출시일로 단정하지 않았다. [논문 이력](https://arxiv.org/abs/2609.38597), [HF 이력](https://huggingface.co/nvidia/PixelUMM/commits/main).

## 2. Linzhan UniMate

**태그:** text-to-motion, motion-generation, skeletal-animation, character-animation, flow-matching, topology-aware.

### 신규 계열로 보는 이유

텍스트와 rigged 3D asset의 T-pose·관절 계층·정리된 관절 이름을 받아 **관절별 움직임**을 생성한다. graph-aware attention bias, graph Laplacian 기반 spectral RoPE, rest-pose topology conditioning을 결합해 서로 다른 skeleton 구조를 처리한다. 동결 FLAN-T5-base는 텍스트 조건용이고, 별도의 motion denoiser를 학습한다. 기존 이미지·비디오 모델의 단순 LoRA나 포맷 변환이 아니며, 이번에 처음 소개하는 독립적인 skeletal-motion 계열이다. [논문](https://arxiv.org/abs/2609.05415), [공식 프로젝트](https://linzhanmou.com/unimate/).

현재 권장 v3는 10-layer, width 512, 8-head의 **74.1M denoiser**다. masked flow-matching loss에 회전·속도 보조 loss를 더하며, 출력은 30fps의 60 frames와 관절별 position·rotation·velocity다. v3·v2·preview·Mixamo/Truebones 전용 모델 및 cross-attention variant는 오늘 모두 **한 계열**로 묶는다. v3의 데이터·sampling 변경만으로 별도 차세대 1개를 추가하는 것이 아니다. [현재 카드](https://huggingface.co/Linzhan/UniMate/blob/main/README.md), [v3 config](https://huggingface.co/Linzhan/UniMate/blob/main/unimate_uniml3d_f60_v3/config.json).

### 활용 예와 한계

- 동물·사람·관절형 물체의 짧은 animation 초안, 고정 keyframe 사이의 연결, 일부 관절을 유지한 편집, 여러 짧은 motion의 확장을 연구하는 후보다.
- 10/5 공개된 **custom-rig 전처리**는 animation이 없는 GLB/glTF/FBX도 처리한다. LLM이 제안한 관절 이름과 방향을 사람이 검토한 뒤 feature를 만들고 sampler에 넣는다. 이전 문서의 “최소 한 개 animation clip 필요” 조건을 현재 코드에 그대로 적용하면 안 된다. [최신 사용법](https://github.com/Friedrich-M/UniMate), [custom-rig 안내](https://github.com/Friedrich-M/UniMate/tree/main/data_process/rig_preprocess).
- 예를 들어 공식 환경과 v3 checkpoint를 준비한 뒤, 제공 eagle asset에 짧은 동작 문장을 넣어 여러 결과를 생성하고 GLB/FBX로 내보내 검토할 수 있다. 한 번에 한 동작을 적고 캐릭터 외형보다 움직임을 묘사하는 편이 공개 학습 caption 방식과 맞는다.
- 기본 출력은 **2초**다. 장시간 motion은 expansion으로 연결해야 한다. 대표 v3는 학습 관절 수 5~70 범위이며, 별도 전용 모델의 범위를 일반형에 그대로 적용하면 안 된다.
- 발 미끄러짐·지면 관통·부유·접촉 오류와 드문 topology의 정지·떨림·prompt 불일치가 남아 있다. 물리적으로 정확한 animation이나 로봇 제어 policy로 검증된 모델이라고 보지 않는다. [제약](https://huggingface.co/Linzhan/UniMate/blob/main/README.md#limitations).

현재 공식 코드의 실행 경로를 따른 예다. 환경 설치와 `unimate_uniml3d_f60_v3/checkpoints/checkpoint_step_150000.pt` 등 관련 파일 준비가 먼저 필요하며, 이번 조사에서는 실행하지 않았다.

```bash
python -m unimate.inference.sample \
  --exp_dir outputs/unimate_uniml3d_f60_v3 \
  --asset assets/examples/eagle \
  --prompt "An object flaps its wings." \
  --num_repetitions 3 --output_dir outputs/samples/eagle
bash scripts/run_animate_motion.sh outputs/samples/eagle
```

[공식 다운로드·실행 안내](https://github.com/Friedrich-M/UniMate#-inference).

### 라이선스와 데이터 출처 주의

가중치는 **CC BY-NC 4.0**, 코드는 MIT다. 제작자는 현재 카드에서 Truebones 학습 자산의 출처에 관한 제3자 주장을 **자신들도 확인하지 못했다**고 밝히며, 해결 전 해당 학습 모델의 provenance를 불명확하게 취급하라고 안내한다. 이 보고서도 해당 주장을 사실로 확정하지 않는다. Mixamo 및 Objaverse-XL 자산에는 각각 별도 조건이 있고, 가중치 공개가 생성 motion의 제3자 권리까지 보장하지 않는다. 따라서 상업적 asset 제작 후보로 바로 채택하기보다 연구·평가와 권리 검토를 우선해야 한다. [제작자 라이선스·출처 경고](https://huggingface.co/Linzhan/UniMate/blob/main/README.md#license), [코드·데이터 조건](https://github.com/Friedrich-M/UniMate#%EF%B8%8F-license).

**날짜 구분:** 논문은 **9/4 UTC 제출**(9/5 KST)이고, 제작자 release note는 첫 checkpoint를 **9/27**, v3를 **10/5**로 기록한다. 해당 release note의 시간대는 명시되지 않았다. HF API 저장소 생성은 **9/28 04:24 KST**, 마지막 수정은 **10/6 05:28 KST**다. 논문·모델 버전·repository metadata·오늘의 관찰 날짜를 구분했다. [논문 이력](https://arxiv.org/abs/2609.05415), [버전 설명](https://huggingface.co/Linzhan/UniMate/blob/main/README.md#versions), [HF API](https://huggingface.co/api/models/Linzhan/UniMate).

## 제외 및 보류

- **Phonon-2:** Parakeet TDT 기반 five-level 약 2.1-bit encoder 압축이 핵심이다. 기존 Phonon 계열과 비교해 새 이름·작은 배포 크기만으로 예외를 인정하지 않았다. [공식 카드](https://huggingface.co/FermionResearch/Phonon-2).
- **FrogNano-4B-2609:** Qwen3.5-4B architecture를 유지하는 직접 post-training 모델이다. 기존 보류 판단을 바꿀 충분한 구조적 근거를 확인하지 못했다. HF metadata MIT와 본문 Apache-2.0 표기도 충돌한다. [Microsoft 카드](https://huggingface.co/microsoft/FrogNano-4B-2609).
- **AREX-2:** 장기 reflective-task 학습이 흥미롭지만 기존 AREX/Qwen 계열 대비 명백한 세대 전환의 근거를 이번에 충분히 확정하지 못해 계속 보류했다. [BAAI 카드](https://huggingface.co/BAAI/AREX-2).
- **Winnow-12B:** 공식 카드가 Gemma 4 12B IT의 rank-32 LoRA를 병합한 모델이라고 명시한다. GGUF·NVFP4·MTP assistant 배포를 별도 신규 계열로 세지 않았다. [제작자 학습 설명](https://huggingface.co/EldanRing/Winnow-12B#training).
- **Whistle·Taiga-S1·pplx-embed-v2-context**는 10/5 소개 계열이다. **Kolibri-1·Nanosaur2**, **VisionHOPE·Clef·Kumo-Tabular·Naive-N0.5-Flash·IQuest-Q1**, 기존 Qwen3.8·Qwen-Image-2.1·LTX-2.5·MiniMax-H3 등의 단순 크기·양자화·포맷·adapter 변형도 제외했다.

보류한 모델은 오늘의 신규 소개 수나 중복 인덱스에 추가하지 않는다. 최대 5개를 채우기 위해 직접 파생본 제외 기준을 완화하지 않았다.

## 전주 비교와 인덱스 점검

- 전주 같은 요일인 **2026-09-29 보고서는 main 조회에서 존재하지 않았다**. 따라서 전주 대비 소개 수·인기도 증가율은 비교할 수 없고 과거 날짜 보고서를 소급 작성하지 않았다.
