## 1. Vela 2.0: 라우팅과 근거 구간 추출을 결합

**태그:** typed-decision, semantic-routing, span-extraction, PII-detection, grounded-hallucination, multilingual, ModernBERT, hybrid-decoder, ONNX.

### 신규 계열 판정

기존 인덱스에는 Vela·Decision-Kai/Lux 계열이 없었다. 다만 Qwen 계보를 재사용하므로 무조건 신규로 세지 않았다. 공식 발표에서 확인한 변화는 다음과 같다.

- 기존 Vela 1.0의 신호별 개별 모델·고정 라벨에서, 요청 시 지정하는 Choice/Noul/Score와 **Span/Set**을 함께 다루는 모델로 확장한다.
- decoder는 단어×라벨 scorer와 **router/broad 두 span head**를 추가한다. 라벨 블록 뒤에 대상 문장을 다시 배치해 causal backbone에서도 단어가 전체 문맥·라벨을 보도록 한다.
- router 학습 후 backbone을 동결해 span head를 학습하고, 다시 앞선 구성요소를 동결해 open-extraction head를 학습한다. 0.3B는 Kai의 Choice trunk에서 공동 학습한다.

이는 새 prompt·양자화·경미한 SFT만 바꾼 배포보다 출력 구조와 학습 구성이 크게 달라진 별도 routing/span 분기로 판단했다. **새로운 from-scratch foundation 백본이라는 뜻은 아니다.** Qwen·mmBERT 계보와 Decision 초기 가중치 사용을 유지해 기록한다. [구조·학습 1차 설명](https://vllm-sr.ai/blog/vela-2-0-open-foundation-routing-models/).

### 작은 encoder와 큰 decoder의 차이

**0.3B:** 22-layer 양방향 ModernBERT, 8,192-token 입력 예산, decision용 cosine+MLP와 word-label span readout을 사용한다. CPU·GPU, Torch·ONNX 경로가 있고 router span head를 제공한다. tokenizer 조건은 모델 Apache-2.0과 구분해야 한다. [0.3B 공식 카드](https://huggingface.co/vllm-sr/Vela-2.0-0.3B).

**9B:** 실제 보고 규모는 7.9B다. 32-layer Qwen3.5 hybrid backbone, 16,384-token 입력 한도와 router/broad span head를 사용한다. FP32 parameter 메모리 약 32GB는 runtime 여유를 제외한 수치다. GPU에서 backbone bf16 autocast, head FP32가 평가 조건이며 fp16은 지원하지 않는다고 명시한다. “9B니까 18GB면 충분”처럼 계산하지 않는다. [9B 공식 카드](https://huggingface.co/vllm-sr/Vela-2.0-9B).

### 활용 예

고객 문의를 배송·결제·기술지원으로 나누면서 개인정보가 있는 구간을 표시하거나, RAG 답변에서 제공 문서로 뒷받침되지 않는 부분을 검토 대상으로 표시하는 후보이다. **발견되지 않았다는 결과가 개인정보 부재나 사실 정확성을 보증하지 않는다.**

0.3B 공식 인터페이스를 따른 짧은 예시다. 이번 조사에서는 실행하지 않았다.

```python
from transformers import AutoModel

# 실행 전에 저장소 custom code를 검토하고 revision을 고정한다.
m = AutoModel.from_pretrained("vllm-sr/Vela-2.0-0.3B", trust_remote_code=True)
result = m.system_one(
    state={"request": "The parcel arrived damaged."},
    questions={
        "route": {
            "type": "choice",
            "instructions": "Which team should handle this?",
            "criteria": {"returns": "Damaged deliveries", "other": "Other requests"},
            "over": "request",
        }
    },
)
print(result["answers"])
```

반환 확률의 업무별 calibration, 한국어·도메인별 오류율과 임계값을 자체 표본으로 점검해야 한다. 코드·가중치 실행이나 정확도 재현은 하지 않았다. [0.3B 사용법](https://huggingface.co/vllm-sr/Vela-2.0-0.3B).

### 평가를 읽을 때 주의할 점

- 0.3B 카드는 **최종 release 선택에 test 결과도 고려**했다고 공개한다. safety 학습 과제를 포함한 비교이므로 zero-shot 우위로 읽으면 안 된다. [평가 고지](https://huggingface.co/vllm-sr/Vela-2.0-0.3B).
- 9B의 Jev 41.63은 optional Noul calibration 사용값이며 기본값은 41.09다. 서로 다른 설정을 섞지 않는다. [9B 평가](https://huggingface.co/vllm-sr/Vela-2.0-9B).
- 한 API 호출이 항상 한 번의 forward라는 뜻은 아니다. decoder의 추가 span 질문·긴 문장은 별도 sequence/window가 생긴다. 제작자 수치를 독립 검증이나 실제 서비스 지연시간으로 보장하지 않는다. [실행 설명](https://vllm-sr.ai/blog/vela-2-0-open-foundation-routing-models/).
