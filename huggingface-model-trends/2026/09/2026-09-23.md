## 1. inclusionAI/Ming-Image-0.1-Design

- Hugging Face: https://huggingface.co/inclusionAI/Ming-Image-0.1-Design
- 개발사/작성자: **inclusionAI**
- 분야: **Text-to-Image / Graphic Design / UI·UX / Text Rendering / RGBA Generation**
- 규모: **6B parameters**
- 공개 정밀도: **BF16**
- 라이선스: **MIT**
- Hugging Face snapshot: **83 likes, Community 4, Space 1**, downloads는 아직 추적되지 않음

### 오늘 주목할 근거

Hugging Face Trending 목록에서 조사 시점 **약 8시간 내 업데이트** 모델로 노출됐고, inclusionAI 조직 활동 피드에서도 `Ming-Image-0.1-Design`이 당일 새로 공개된 모델로 확인됐다. 모델 페이지는 약 **83 likes**, Community 4, Space 1을 표시했다. 다운로드는 아직 `-`로 표시되므로 증가율은 추정하지 않는다.

### 기술적으로 무엇이 달라졌나

이 모델의 핵심은 일반적인 사진형 text-to-image보다 **텍스트가 많이 들어가는 완성형 그래픽 디자인**을 직접 생성하는 데 초점을 맞춘 점이다.

- 공식 카드가 주요 대상으로 **UI, infographics, posters, text-rich visual designs**를 명시한다.
- 단순 RGB 이미지뿐 아니라 **RGBA 출력과 투명 배경 생성**을 공식 기능으로 제공한다. 아이콘·배너·UI asset처럼 배경 제거가 필요한 제작 흐름에 바로 연결하기 쉽다.
- 권장 해상도는 **2048×2048**, 빠른 생성용으로 1024×1024도 지원하며, 공식 권장은 **12 sampling steps / CFG 1.0 / BF16**이다.
- prompt enhancement는 `Ling-3.0-flash-VL` 또는 `Qwen3.8-27B`를 사용할 수 있도록 공식 예시가 제공된다.

현재 공개 모델 카드가 구체적인 transformer block 구성, attention 구조, 학습 데이터 규모 등 내부 backbone 세부를 충분히 명시하지 않으므로 **확인되지 않은 architecture 세부는 추측하지 않는다.** 이번 별도 모델 판정은 공개된 목적·출력 형식·전용 inference/deployment 경로가 명확한 새로운 디자인 생성 checkpoint라는 점에 근거한다.

### 실제 활용 가능성과 제약

공식 Hugging Face 사용법은 `Diffusers`의 `DiffusionPipeline`을 제공하고, companion `Ming-Image` 저장소의 `infer.py`로 1024/2048 해상도 text-to-image와 transparent-background 생성을 실행할 수 있다. 서버 배포 경로로는 **vLLM-Omni**를 공식 권장한다.

다만 개발사가 검증한 하드웨어 구성은 **CUDA GPU 80 GiB 1장**이다. 따라서 6B라는 parameter 수만 보고 일반 게이밍 PC에서 원본 BF16을 손쉽게 돌릴 수 있다고 단정할 수 없다. 공식 카드에는 llama.cpp/Ollama/LM Studio용 경량 배포를 보장하는 설명도 없다. 현재 Hugging Face Inference Provider에도 직접 배포되어 있지 않다.

MIT 라이선스이므로 모델 카드에 적힌 범위에서는 상업적 활용 장벽이 비교적 낮지만, 실제 제품 적용 시 생성물·입력 데이터·브랜드/IP 관련 검토는 별도로 필요하다.

### Benchmark 주의

모델 카드에는 UI/UX Design leaderboard가 제시되어 있으나, 이는 **개발사 자체 평가/제시 자료**로 취급한다. 이번 보고서에서는 독립 검증 수치처럼 인용하지 않는다.

## 2. radar-generalist/RADAR

- Hugging Face: https://huggingface.co/radar-generalist/RADAR
- 개발/공개: **RADAR 연구팀 / Alibaba DAMO Academy 계열 공식 저장소**
- 분야: **Medical Vision-Language / Abdominal CT Diagnosis**
- 라이선스: **CC BY-NC-SA 4.0**
- Hugging Face snapshot: **76 likes, Community 2, Spaces 2**, downloads는 추적되지 않음
- Parameter 수: **공식 모델 카드에서 확인되지 않아 기재하지 않음**

### 오늘 주목할 근거

RADAR는 완전히 오늘 처음 나온 모델은 아니지만, 조사 시점 Hugging Face Trending 목록에서 **약 22시간 내 업데이트** 상태로 다시 노출됐고 모델 페이지는 **76 likes / Community 2 / Spaces 2**를 표시했다. 공식 GitHub `alibaba-damo-academy/damo-radar`도 2026-09-22 업데이트가 확인되어, 최근 코드/모델 정비와 함께 다시 관심을 받는 후보로 선정했다.

### 기술적으로 무엇이 달라졌나

RADAR의 핵심은 일반 이미지 VLM을 의료 영상 몇 장에 미세조정한 형태가 아니라, **대규모 복부 CT와 임상 보고서의 해부학적 대응 관계를 이용해 학습한 generalist CT vision-language framework**라는 점이다.

- 공식 카드 기준 **40만 건이 넘는 contrast-enhanced abdominal CT examinations**와 **1,500만 anatomy-aware image-text pairs**를 사용했다.
- 사람이 각 병변에 일일이 새 라벨을 붙이는 대신 **기존 임상 보고서에서 직접 학습**하는 방식을 사용한다.
- 공개 checkpoint에는 RAD-CT pretraining 모델뿐 아니라 `RADAR+`의 from-scratch Merlin-CT-Train 모델과 RAD-CT pretrain 후 Merlin으로 fine-tune한 모델도 포함된다.
- 모델 준비 파일에는 **UNet 기반 VisionBranch checkpoint**와 영어/중국어 BERT 구성요소가 명시되어 있다.

즉 일반적인 2D 사진 caption/VQA용 모델보다는 **3D CT 임상 문맥, 해부학 위치, radiology report 연결**을 핵심 문제로 삼는 의료 영상 전용 generalist 계열이다.

### 실제 활용 가능성과 제약

공식 GitHub는 Python 3.10 환경과 전용 dependency를 사용하며, CT 전처리·mask/auxiliary data·inference/evaluation 코드까지 제공한다. 따라서 일반적인 `ollama run`이나 OpenAI-compatible chat endpoint에 꽂는 LLM이 아니라 **의료 영상 파이프라인에 통합하는 연구 모델**로 보는 것이 맞다.

가장 중요한 제약은 라이선스와 의료 사용 범위다.

- 모델/프로젝트 라이선스는 **CC BY-NC-SA 4.0**으로 상업적 사용에 제한이 있다.
- 공식 모델 카드와 GitHub는 **research purposes only**이며, 직접 임상 배포 전에 추가 개선과 prospective clinical studies가 필요하다고 명시한다.
- 따라서 의료기관의 실제 진단 자동화에 바로 투입할 모델로 취급하면 안 된다.

### Benchmark 주의

논문과 모델 카드의 `expert-level` 표현 및 성능 결과는 **저자/개발팀이 수행한 평가**에 기반한다. Science 2026 논문으로 정식 출판되었지만, 이 보고서에서는 이를 독립적인 외부 재현 검증과 동일하게 표현하지 않는다. 실제 임상 적용에는 별도의 독립 검증과 규제·의료 안전 검토가 필요하다.

## 중복/제외 검증 메모

오늘 Trending 상위권과 최근 업데이트 후보를 `huggingface-model-trends/introduced-models.md`와 대조했다.

- `XiaomiMiMo/MiMo-V2.6-Pro-RL`, `MiMo-V2.6-Distill-Qwen-9B` 등은 2026-09-22에 소개한 **MiMo-V2.6 계열** variant/distillation이므로 제외.
- `Qwen/Qwen-Image-2.1`, `XingChen-AGI/Xing4.0-29B-A4B`, `deepseek-ai/DeepSeek-V4.1-Flash`, `m-a-p/YuE2-3B`, `netease-youdao/Confucius4-R2T2`, `TokenRhythm/NeoHorse-1-*`, `Cactus-Compute/needle3` 등은 이미 중복 인덱스에 등록된 계열이므로 재소개하지 않음.
- `Altworld/Hemmingway-1`은 모델 카드상 **Qwen3.8-27B의 finetuned derivative**이므로 이미 등록된 Qwen3.8-27B 계열의 직접 파생본으로 제외.
- `AikidoSec/altar-1`은 **GLM-5.3 기반 pruning + INT4 quantization** 성격이며 핵심 새 학습 없이 기존 GLM-5.3 계열의 직접 파생으로 판단해 제외.
- `moondream/parakeet-redux`는 기존 `parakeet-tdt-0.6b-v3`와 같은 architecture/tokenizer를 쓰는 ternary 파생으로 전일 검증에서 이미 제외 판정.
- `StarDoc-AI/TeleOCR`은 기존 `NaviDC-OCR` rename으로 확인되어 제외.
- `tencent/WeVisDoc-4B`는 Qwen3-VL 기반 document parsing fine-tune으로 전일과 동일하게 엄격한 직접 파생 규칙을 적용해 제외.
