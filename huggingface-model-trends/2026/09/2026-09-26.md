## 1. AlexWortega/openjev

Repository: https://huggingface.co/AlexWortega/openjev  
작성자/라이선스: AlexWortega, MIT.  
분야/규모: Qwen3.5 기반 sequence-classification 계열이며 0.8B·2B·4B 및 35B-A3B checkpoint가 공개돼 있다.  
기술 차이: next-token 답변 생성 대신 premise와 hypothesis를 cross-encoder로 읽어 contradiction·entailment·neutral 확률을 반환한다. 이를 reranking, grading, verification, closed-set decision에 사용하고 일부 계열은 image premise도 지원한다.  
별도 판정: 단순 대화 fine-tune과 달리 출력 구조와 목적이 generation에서 classification/ranking으로 크게 바뀌어 직접 파생 예외로 판단했다.  
실사용/제약: Transformers sequence classification과 공개 SGLang 확장 경로를 사용할 수 있다. 일반 chat completion 모델은 아니다. RAG verifier, 후보 순위화, workflow decision에 적합하다.  
Benchmark: 모델 카드의 JevBench, RAGTruth, HaluBench, LLMBar 수치는 **개발사 자체 평가**다.

## 2. akhilaaa3/Jev-Omni

Repository: https://huggingface.co/akhilaaa3/Jev-Omni  
작성자/라이선스: akhilaaa3, Apache-2.0.  
분야/규모: 12B multimodal decision classifier, Gemma 4 12B IT 기반.  
기술 차이: text·image·audio·video를 받아 자연어 대신 선택지별 probability를 반환한다. 모델 카드 기준 30,000-question fine-tuning.  
별도 판정: multimodal 입력을 하나의 decision interface로 통합하고 free-form generation을 closed-set scoring으로 바꿔 modality·생성 방식·목적 변화가 크다.  
실사용/제약: CUDA GPU 필요. FP32 weights는 runtime overhead 전 약 50GB이고 inference는 BF16. audio 30초, video 16 frames, 가장 잘 검증된 option 수는 20개 이하. multimodal routing과 agent candidate scoring에 활용 가능하다.  
Benchmark: DecisionBench, JevBench, MMAU, MVBench 및 latency 수치는 **개발사 자체 평가/측정**이다.

## 3. Viggle/Meridian

Repository: https://huggingface.co/Viggle/Meridian  
개발사/분야: Viggle AI, geometry-guided Video-to-Video / novel-view synthesis.  
구조: MiniMax-H3 transformer/VAE와 VGGT-Omega geometry를 결합하며 teacher LoRA 2.5 GiB와 turbo LoRA 2.5 GiB를 사용한다.  
기술 차이: 입력 video의 depth와 camera pose를 추정해 3D points를 만들고, 새 camera path에서 geometry reference를 렌더링한 뒤 원본 video와 함께 generation condition으로 사용한다.  
별도 판정: base transformer는 유지되지만 외부 3D geometry가 조건 구조에 들어가고 목적이 일반 video 생성에서 새로운 viewpoint authoring으로 바뀌어 단순 adapter보다 변화가 크다.  
실사용/제약: high-memory CUDA GPU 필요. 공식 scripts는 현재 quantization, CPU offload, multi-GPU sharding을 지원하지 않는다. ComfyUI workflow 제공. 개발사 자체 측정으로 B200에서 73 frames 약 36초, peak 88 GiB.  
라이선스: MiniMax H3 Community License와 VGGT-Omega 별도 라이선스를 확인해야 하며 모델 카드상 MiniMax H3 적용 지역에서 대한민국·미국·영국·EU가 제외된다.

## 4. FrontiersMind/Lumma-fev-0.6b

Repository: https://huggingface.co/FrontiersMind/Lumma-fev-0.6b  
개발사/라이선스: FrontiersMind, Apache-2.0.  
분야/규모: 649M typed-decision model. 자체 pretrain했다고 밝힌 Lumma-0.6B-Base 기반.  
기술 차이: causal transformer를 prefill-only로 쓰고 각 question이 state와 자기 token만 읽은 뒤 pointer head로 option probability를 반환한다. context 최대 8,192 state tokens.  
별도 판정: 자체 foundation base에 non-generative pointer decision interface를 결합해 inference 구조와 목적 변화가 크다. fine-tuning은 rank-16 LoRA 후 weights에 merge됐다.  
실사용/제약: 공식 package가 CUDA/MPS/CPU를 지원하고 TypeSafe-compatible API를 제공한다. 모델 카드 기준 English + 10 Indian languages. routing, ticket classification, RAG 후처리에 활용 가능하다.  
중복 범위: 4B/9B 등 같은 Lumma-Fev의 단순 크기 변형은 같은 계열이다.  
Benchmark: 모델 카드 수치는 **개발사 자체 평가**다.

## 5. wfzyx/von — Von 1.2

Repository: https://huggingface.co/wfzyx/von  
개발자/라이선스: Victor Hugo Panisa / wfzyx, Apache-2.0.  
분야/규모: 395M, ModernBERT-large + Option-Marker head, context 8,192.  
기술 차이: 각 option은 shared premise와 자기 option에만 attention하고 position id도 독립적으로 적용해 option 순서가 바뀌어도 점수 자체가 바뀌지 않도록 설계했다.  
별도 판정: Von 1.1 대비 attention mask와 position 처리 방식이 바뀌어 option-order invariance를 architecture 수준에서 구현했다.  
실사용/제약: Python/TypeScript SDK와 TypeSafe-compatible API 제공. English only이며 긴 multi-hop policy reasoning은 약점으로 명시돼 있다.  
중복 범위: 과거 wfzyx/von-1.0은 rename된 동일 계열이며 동일 Von 1.x의 단순 checkpoint·양자화·포맷 변형은 중복 처리한다.  
Benchmark와 calibration 수치는 **개발사 자체 평가**다.
