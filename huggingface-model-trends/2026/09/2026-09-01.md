## 1. deepseek-ai/DeepSeek-V4-Flash-Vision-Exp

- Hugging Face: https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash-Vision-Exp
- 개발사/작성자: **DeepSeek AI**
- 분야: **Multimodal / Image-Text-to-Text / Agent**
- 규모: Hugging Face 표시 기준 **약 305B parameters**
- 라이선스: Hugging Face 모델 카드 기준 **MIT**

### 오늘 주목할 근거

2026-09-01 오전 조사 시점 Hugging Face 전체 Trending에서 **상위 10위권**에 위치했고, 모델 페이지는 약 **12시간 내 업데이트**로 표시되었습니다. 좋아요는 약 **334개**, Community는 **11개**였으며 다운로드 수는 Hugging Face에서 별도로 집계되지 않았습니다.

단순히 DeepSeek-V4의 또 다른 크기 변형이 아니라, 공식 모델 카드가 이 모델을 **“DeepSeek-V4 family의 첫 experimental multimodal model”**이라고 명시하고 있습니다. 최근 빠르게 관심이 붙는 이유도 text-only agent 모델에 시각 입력을 추가한 정도가 아니라, 이미지 이해가 필요한 실제 Agent 작업까지 직접 겨냥하기 때문으로 볼 수 있습니다.

### 기존 모델과의 기술적 차이

`introduced-models.md`에는 이미 DeepSeek-V4 계열이 존재하므로 원칙상 중복 후보입니다. 다만 이번 모델은 공식 카드에서 **DeepSeek-V4-Flash architecture에 visual modules를 추가하고 continued training을 수행해 visual understanding을 활성화**했다고 설명합니다. 또한 공개 reference implementation에는 **vision encoder/aligner**, DFlash attention, MoE, Hyper-Connections, DSpark 경로가 함께 포함됩니다.

따라서 기존 text-only DeepSeek-V4와 비교해 **입력 modality와 agent 입력 구조가 근본적으로 확대**된 경우로 판단했습니다. 이번 보고서에서는 이를 단순 파생 checkpoint가 아니라 **DeepSeek-V4의 멀티모달 분기**로 별도 소개합니다. 이후 이 체크포인트의 단순 양자화·GGUF/FP8·포맷 변환·경미한 fine-tune은 같은 계열로 취급해야 합니다.

### 개발사 자체 평가

아래 수치는 독립 검증이 아니라 **DeepSeek 자체 평가**입니다. 공식 카드에서 DeepSeek-V4-Flash-0731과 비교했을 때 multimodal/agent 작업의 향상을 제시하며, 예를 들어 Toolathlon **75.9 vs 70.3**, ApexBench Pass@1 **36.5 vs 26.2**, Chartography **64.3** 등을 보고합니다. text-only agent 과제도 대체로 기존 Flash와 비슷하거나 일부 개선됐다고 설명합니다.

### 실제 활용 가능성과 제약

Hugging Face 페이지에는 **vLLM 및 SGLang 기반 serving 예시와 OpenAI-compatible API 형태**가 안내되어 있어 Agent나 MCP 도구 호출용 백엔드로 연결하기 좋은 형태입니다. 다만 전체 규모가 약 305B이므로 원본 체크포인트를 일반적인 단일 소비자 GPU/PC에서 직접 구동하기는 현실적으로 매우 부담스럽습니다. Hugging Face가 llama.cpp/Ollama/LM Studio 계열에서 사용할 수 있는 파생 포맷 탐색 경로를 제공하더라도, 양자화만으로 하드웨어 요구가 작아진다고 단정할 수는 없습니다.

현재 Hugging Face Inference Provider에 직접 배포된 모델은 아니므로, 실제 서비스에서는 자체 GPU 서버 또는 지원 런타임 환경이 필요합니다. MIT 라이선스로 표시되어 있지만 실제 제품 적용 시에는 함께 사용하는 코드·런타임·파생 체크포인트의 조건도 별도로 확인해야 합니다.

## 2. google/timesfm-3.0-pytorch

- Hugging Face: https://huggingface.co/google/timesfm-3.0-pytorch
- 개발사: **Google Research**
- 분야: **Time Series Foundation Model / Forecasting**
- 규모: Hugging Face 표시 기준 **0.3B parameters**
- 라이선스: **timesfm-non-commercial-license-v1.0**

### 오늘 주목할 근거

Hugging Face Trending 페이지에서 2026-09-01 오전 기준 새로 부상 중이며, 모델 페이지는 약 **7시간 내 업데이트**로 표시됐습니다. 좋아요는 약 **57개**, Community는 **1개**, 연결된 Space는 **1개(autogluon/fev-bench)**였고 최근 월 다운로드는 별도로 집계되지 않았습니다.

공식 GitHub `google-research/timesfm`도 TimesFM 3.0을 최신 모델로 명시하고 있습니다. 조사 시점 저장소는 약 **28.4k stars / 2.7k forks** 규모였고, 최근 push는 2026-08-28 UTC에 확인돼 모델 공개와 코드 업데이트가 매우 최근까지 이어지고 있습니다.

### 기존 모델과의 기술적 차이

TimesFM 2.x가 주로 univariate forecasting 중심이었다면, 공식 TimesFM 3.0 설명은 **native multivariate forecasting**과 **past-only / past-and-future covariate**의 직접 지원을 핵심 변화로 제시합니다.

Hugging Face 카드에 기재된 구조는 **Stacked Mixing Transformer with Variate Attention and CPM Iterative RevIN**입니다. 즉 단순히 기존 TimesFM의 parameter 수만 늘린 모델이 아니라, 여러 변수를 서로 연관 지어 예측하고 공변량을 모델 내부에서 다룰 수 있도록 forecasting 구조 자체가 확장됐습니다. 여러 센서·매출·재고·트래픽처럼 변수가 서로 영향을 주는 실제 시계열 문제에서 이전 세대보다 활용 범위가 넓어진 점이 핵심입니다.

공식 카드에는 20 Transformer layers, model dimension 1280, 16 heads, context patch length 32, horizon patch length 64가 명시되어 있습니다.

### 개발사 자체 평가

Google Research의 공식 README는 TimesFM 3.0이 **fev-bench, TIME Benchmark, GIFT-Eval**에서 최상위 성능을 기록했다고 주장합니다. 이는 **Google 자체 평가/공식 발표 기준**이며, 독립적인 재현 결과와 동일하게 취급해서는 안 됩니다.

### 실제 활용 가능성과 제약

모델 규모는 0.3B로 대형 LLM보다 작지만, 일반 PC에서 어느 정도 속도로 동작하는지는 공식 자료만으로 단정하기 어렵습니다. 공식 Python 예시는 `TimesFM3Evaluator`와 CUDA device를 사용하며, `timesfm` 패키지 기반 추론 흐름을 제공합니다. 이 모델은 LLM이 아니므로 vLLM/SGLang/llama.cpp/Ollama/OpenAI-compatible API가 주된 실행 경로가 아닙니다.

실무에서는 판매량·수요·센서·트래픽·재고 같은 수치 데이터를 zero-shot forecasting하거나, 여러 시계열과 외생 변수(covariate)를 함께 넣는 분석 파이프라인에 특히 유용합니다. 다만 가장 중요한 제약은 **TimesFM 3.0 pretrained weights가 현재 비상업·비프로덕션 용도로 제한**된다는 점입니다. 공식 GitHub는 소스 코드와 2.5 이하 weights의 Apache-2.0과 달리 3.0 weights는 별도 non-commercial license라고 명시합니다. 따라서 상용 서비스나 운영 시스템에 그대로 투입해서는 안 됩니다.

### 주요 1차 출처

- Hugging Face 모델 카드: https://huggingface.co/google/timesfm-3.0-pytorch
- Google Research 공식 GitHub: https://github.com/google-research/timesfm

## 3. darkps/ice-012-audio

- Hugging Face: https://huggingface.co/darkps/ice-012-audio
- 작성자: **DarkPs** (모델 카드에 FanuonAI 소유 조직으로 설명)
- 분야: **Text-to-Speech / Audio / Voice Cloning**
- 규모: Hugging Face 표시 기준 **0.6B parameters**
- 라이선스: Hugging Face 모델 카드 기준 **Apache-2.0**

### 오늘 주목할 근거

2026-09-01 오전 Hugging Face **Text-to-Speech Trending 상위권(약 4위)**에 위치했고, 약 **7시간 내 업데이트**로 표시됐습니다. 조사 시점 좋아요는 약 **57개**, 최근 월 다운로드는 **66회**, Community는 **1개**였습니다. 절대 다운로드 수는 아직 작지만, 공개 직후 TTS 카테고리에서 빠르게 상단으로 올라온 신규 모델이라는 점을 높게 평가했습니다.

### 기존 모델과의 기술적 차이

모델 소스는 단순한 텍스트 LLM fine-tune 형태가 아닙니다. 공개 `modeling_iceAudio.py`를 보면 내부 language model은 **Qwen3Model**을 기반으로 하면서, 별도의 **8-codebook audio token embedding/output heads**와 audio mask 기반 생성 경로를 추가합니다. 오디오 토크나이저는 **HiggsAudioV2TokenizerModel**을 사용합니다.

텍스트 토큰과 여러 codebook의 discrete audio token을 하나의 causal generation 흐름에 결합하고, audio 위치에 대해서는 다중 codebook 출력을 반복적으로 예측하는 구조입니다. 즉 Qwen3의 언어 능력을 그대로 쓰는 것에 그치지 않고 음성 토큰 생성 레이어와 tokenizer를 결합해 **streaming TTS와 voice cloning을 목적으로 재구성한 오디오 생성 모델**이라는 점이 핵심 차별점입니다.

공개 config에는 hidden size 1024, intermediate size 3072, 28 layers, 16 attention heads, 8 KV heads, max position embeddings 40,960, 8 audio codebooks가 기재되어 있습니다.

### 실제 활용 가능성과 제약

모델 카드는 **streaming output, voice cloning, multilingual TTS** 사용법을 제공하며 Transformers에서 `trust_remote_code=True`가 필요합니다. 400개가 넘는 언어명/변형 이름을 654개의 language ID로 매핑하는 설정도 공개돼 있지만, 이것이 모든 언어에서 동일한 품질이 검증됐다는 뜻은 아닙니다.

0.6B 규모라 대형 음성 모델보다 상대적으로 작지만, F32 checkpoint 파일과 별도 오디오 토크나이저가 필요하고 실제 realtime 성능은 하드웨어에 따라 달라집니다. 공식 자료에는 vLLM/SGLang/llama.cpp/Ollama/LM Studio 지원이 확인되지 않았으므로 해당 런타임 호환을 가정해서는 안 됩니다. 현재 Hugging Face Inference Provider에도 직접 배포돼 있지 않습니다.

모델 저장소는 Apache-2.0으로 표시되지만, 실제 상용 배포 전에는 연결되는 tokenizer 및 기타 dependency의 라이선스도 함께 검토하는 편이 안전합니다.
