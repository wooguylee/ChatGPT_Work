## 1. XingChen-AGI/Xing4.0-29B-A4B

- Hugging Face: https://huggingface.co/XingChen-AGI/Xing4.0-29B-A4B
- 개발사/작성자: **China Telecom Artificial Intelligence Technology Co., Ltd. / XingChen-AGI**
- 공식 GitHub: https://github.com/XingChen-AGI/Xing4.0-29B-A4B
- 분야: Text LLM, reasoning, coding, agent, tool calling, long-context engineering
- 규모: 개발사 모델 카드 기준 **29B total / 4B active**
- architecture: **MoE + MLA + mHC + MTP**, 40 layers, 64 routed experts, token당 4 experts + 1 shared expert
- context: **256K native**, 개발사 설명상 512K까지 확장 가능
- license: **Apache-2.0**

### 오늘 주목할 근거

공식 GitHub `News`가 **2026-09-17 Xing4.0-29B-A4B를 오픈소스 공개**했다고 명시한다. Hugging Face Trending에서는 조사 시점 2페이지 상위권에 있었고, HF 모델 페이지는 약 **18시간 내 업데이트**, **61 downloads/month**, **147 likes**를 표시했다. 다운로드 절대치는 아직 작지만 당일 공개 직후 좋아요가 빠르게 형성되고 Trending에 진입한 신생 release다.

같은 날 FP8과 GGUF 배포도 공식 공개되어, 원본 checkpoint와 단순 정밀도/포맷 변형을 함께 배포하는 형태다. 오늘의 신규 계열로는 원본 `Xing4.0-29B-A4B`만 기록하고 FP8/GGUF는 동일 계열로 묶는다.

### 기존 모델과의 기술적 차이

Xing4.0은 기존 TeleChat/Xing 계열의 최신 세대다. 핵심은 단순 Qwen 계열 fine-tune이 아니라 **mHC + MLA + MTP**를 사용하는 자체 MoE 구조와 agent-oriented serving path를 함께 공개했다는 점이다. 64개 routed expert 중 매 token에 4개를 선택하고 shared expert 1개를 사용한다.

개발사는 모델을 복잡한 engineering/agent task에 맞춰 설계했다고 설명하며, multi-step planning, tool calling, 긴 reasoning chain과 long context에서의 execution stability를 핵심 목표로 둔다. vLLM/SGLang용으로 별도 `reasoning-parser xing4`와 `tool-call-parser xing4`를 제공하고 MTP speculative decoding 설정도 문서화했다.

또 하나의 구조적 특징은 **Ascend 910C + MindSpore/MindFormers co-design**이다. 개발사는 mHC feature adaptation, MoE communication 최적화, selective recomputation, operator fusion 등을 통해 out-of-the-box 대비 training throughput을 약 96% 개선했다고 주장한다. 이 수치는 **개발사 자체 측정**이다.

### benchmark 해석

모델 카드에는 SWE-bench Verified 75.0, Terminal-Bench 2.1 57.5, Claw-Eval 76.55, DeepresearchBII 60.80 등의 결과가 제시되어 있다. 이는 공식 harness를 사용했다고 설명하지만 별도 독립 재현을 이번 조사에서 확인하지 않았으므로 **개발사 자체 평가**로 기록한다.

### 실제 활용 가능성과 제약

- **vLLM**: 공식 serving 예시와 OpenAI-compatible `/v1` endpoint 제공.
- **SGLang**: 공식 serving 예시와 OpenAI-compatible endpoint 제공.
- **KTransformers**: GPU/CPU heterogeneous inference 예시 제공. 제한된 GPU 환경에서 MoE expert 일부를 CPU로 넘기는 경로가 문서화되어 있다.
- **Agent 연동**: 공식 문서는 OpenCode, Claude Code, OpenClaw, Hermes에 맞춘 adaptation/format alignment를 명시한다. OpenAI-compatible API를 통해 일반 agent framework와도 연결 가능하다.
- **로컬 PC**: 29B total MoE이므로 BF16 원본을 일반 저사양 PC에서 가볍게 돌리기는 어렵다. 다만 같은 날 공식 GGUF가 공개됐고 KTransformers CPU/GPU co-processing 경로도 있어 충분한 RAM/VRAM을 가진 로컬 환경에서는 선택지가 있다.
- **llama.cpp/Ollama/LM Studio**: HF 페이지가 quantization 탐색 링크를 제공하며 공식 GGUF도 공개됐다. 다만 개발사 main serving 문서는 vLLM/SGLang/KTransformers 중심이므로 각 앱의 실제 호환성은 사용하는 GGUF와 runtime 버전을 별도로 확인해야 한다.
- **라이선스**: Apache-2.0. 다만 개발사 disclaimer에는 사용 지역의 법·규정 및 필요한 security review/filing 준수를 요구하는 문구가 있어 서비스 배포 전 원문 확인이 필요하다.

## 2. zeroweight-ai/ZeroTTS

- Hugging Face: https://huggingface.co/zeroweight-ai/ZeroTTS
- 개발사/작성자: **ZeroWeight AI**
- 공식 GitHub: https://github.com/zeroweight-ai/ZeroTTS
- 분야: Text-to-Speech, Vietnamese TTS, streaming speech synthesis, speaker-conditioned speech
- 규모: **202M parameters**
- runtime: **ONNX / ONNX Runtime 중심**, CPU streaming 지원
- speech codec: **MOSS-Audio-Tokenizer-Nano decoder** 사용
- license: **MIT**

### 오늘 주목할 근거

조사 시 Hugging Face Trending 5페이지에 노출됐고, Trending 페이지는 약 **2일 내 업데이트**를 표시했다. 모델 페이지는 **2,205 downloads/month**, **40 likes**, **Community 24**, **Spaces 2**를 표시한다. 좋아요 절대치는 대형 LLM보다 작지만, 202M 규모의 언어 특화 TTS가 CPU 실시간 streaming을 전면에 내세우고 있고 Community 활동도 높은 편이라 실무 가치 기준으로 선정했다.

### 기존 모델과의 기술적 차이

ZeroTTS는 대형 GPU TTS가 아니라 **CPU에서 실제 streaming latency를 낮추는 것**을 핵심 목표로 한다. 공개 모델은 202M parameters이며 ONNX Runtime 경로를 제공하고, MOSS-Audio-Tokenizer-Nano의 decoder graph를 함께 배포해 외부 codec runtime 의존성을 줄였다.

Speaker conditioning은 `voice.npz`에 저장되는 작은 latent array로 처리한다. 즉 reference audio 자체를 매 생성마다 길게 prompt로 넣는 구조가 아니라 speaker latent를 전달하는 형태다. 다만 **현재 공개 repository에는 reference audio에서 새 speaker latent를 만드는 voice encoder가 포함되어 있지 않다.** 따라서 모델 카드 상단의 voice-cloning 설명과 달리, 이번 공개본만으로 사용자가 임의 음성 파일을 넣어 새 voice를 직접 cloning하는 기능은 제공되지 않는다. 기본 제공 voice 또는 외부에서 얻은 speaker latent를 사용해야 한다.

정확한 전체 backbone topology는 모델 카드에 충분히 공개되어 있지 않아 추정하지 않는다.

### benchmark 해석

ZeroBench-TTS에서 모델 카드는 WER 1.03%, UTMOS 2.91, CPU RTF 0.50x, first audio 약 70ms를 제시한다. HF evaluation result 자체도 `self-reported`로 표시하므로 모두 **개발사 자체 평가**로 취급한다.

특히 CPU latency 수치는 8 inference threads를 사용한 전용 CPU core pool에서 측정한 것으로 설명되어 있어 다른 노트북/서버에서 동일 수치를 보장하지 않는다.

### 실제 활용 가능성과 제약

- **일반 PC 실행**: 모델 카드가 GPU 없이 CPU에서 faster-than-real-time streaming을 목표로 하며 `pip install zerotts` 사용법을 제공한다. 202M 규모라 오늘 선정 모델 중 로컬 접근성이 매우 높다.
- **GPU 요구**: 필수로 명시되지 않았다. CPU inference가 핵심 경로다.
- **vLLM/SGLang / OpenAI-compatible API**: 해당 LLM serving stack용 모델이 아니며 공식 지원이 확인되지 않았다. Python package 또는 직접 streaming service wrapper를 만드는 방식이 적합하다.
- **llama.cpp/Ollama/LM Studio**: TTS ONNX 모델이므로 해당 LLM runtime 대상이 아니다.
- **언어**: Vietnamese 중심. Vietnamese 문장 안의 English code-switch는 다루지만 English TTS로 평가된 모델은 아니다.
- **voice cloning 제약**: 공개본에는 voice encoder가 없으므로 임의 reference audio로 새 voice latent를 생성할 수 없다. 제공 voice 또는 별도 경로에서 얻은 latent만 사용 가능하다.
- **라이선스**: weights와 code는 MIT. 단, benchmark dataset `ZeroBench-TTS`는 CC-BY-NC-4.0이며 이 비상업 조건은 benchmark dataset에 적용되고 모델 weights에는 적용되지 않는다고 카드가 구분한다.

- `Edge0/Edge0-*`는 이전 보고서에서 Qwen3.5-MoE int4 + Recover-LoRA/prerouter adapter 기반 직접 파생 시스템으로 이미 제외 판정되어 재선정하지 않았다.
- `AlexWortega/openjev`는 Qwen3.5-4B / 35B backbone을 NLI cross-encoder로 재목적화한 흥미로운 fine-tune이지만 model tree상 Qwen3.5 직접 fine-tune이고 task별 MLP head를 얹는 구조이므로 오늘의 엄격한 직접 파생 규칙에서는 신규 base 계열로 세지 않았다.
- `AlicanKiraz0/Kizagan-TTS-v1.0`은 공식 카드가 VoxCPM2 기반 LoRA rank-64를 병합한 checkpoint라고 명시하므로 직접 fine-tune/adapter 파생 규칙에 따라 제외했다.
- 다수 Qwen/DeepSeek abliterated·uncensored·GGUF·FP8/NVFP4 checkpoint, ComfyUI port, LoRA는 직접 파생/양자화/포맷 규칙에 따라 제외했다.

## 오늘의 Top Pick

**XingChen-AGI/Xing4.0-29B-A4B**

당일 신규 공개라는 시의성, 29B total / 4B active MoE의 실용적 규모, mHC + MLA + MTP 구조, 256K long context, vLLM/SGLang/KTransformers 및 OpenAI-compatible serving, OpenCode/Claude Code/OpenClaw/Hermes 연동 문서까지 한 번에 갖춘 점에서 오늘 개발자가 바로 추적할 가치가 가장 큰 모델로 선정한다. 개발사 benchmark는 자체 평가이지만, 공개 직후 agent/coding 배포 경로가 구체적으로 제공된 점은 실무 관점에서 특히 강하다.
