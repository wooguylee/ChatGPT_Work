## 1. Qwen/Qwen-Image-2.1 — 오늘의 Top Pick

- **Hugging Face:** https://huggingface.co/Qwen/Qwen-Image-2.1
- **개발사/작성자:** Qwen Team / Alibaba
- **분야/규모:** Text-to-Image + Image Editing, visual generation component **7B**, **32-layer Single-Stream DiT**
- **라이선스:** Qwen Research License Agreement (`qwen-research`)

### 오늘 주목할 근거

공식 GitHub는 **2026-09-20** Qwen-Image-2.1 공개를 명시한다. 조사 시점 Hugging Face snapshot은 약 **722 likes, Community 12, 183 downloads/month, 15 Spaces**다. 공개 직후부터 Diffusers demo와 다수 Space가 붙고 있어 단순 모델 카드 공개보다 실제 사용 확산 속도가 빠르다.

### 기존 모델과의 기술적 차이와 별도 계열 판정

`introduced-models.md`에는 `nvidia/Qwen-Image-Flash`가 이미 있으므로 이름만 보고 새 모델로 세지 않았다. 이번 2.1은 Qwen 공식 1차 출처에서 **새로운 7B single-stream DiT**, **mixed-granularity attention**, **prefix KV cache reuse**, **Qwen3-VL 8B text/image condition encoder**, **64-channel RGBA VAE**, **flow-matching scheduler**를 공개했다. 특히 생성과 편집을 한 모델로 통합하고 native transparent RGBA 생성/편집, 최대 10장 reference image, native 2K를 지원한다.

따라서 기존 Qwen-Image 파생의 단순 속도 최적화·양자화·포맷 변환이 아니라 architecture와 생성/편집 범위가 함께 바뀐 **명백한 차세대 image foundation 계열**로 판정했다.

### 실제 활용 가능성과 제약

- `QwenImage21Pipeline`으로 Diffusers에서 BF16 실행 가능하며 `enable_model_cpu_offload()` 메모리 절감 경로가 공식 카드에 있다.
- 공식 저장소는 Diffusers/ComfyUI와 함께 **SGLang-Diffusion**, **vLLM-Omni** 지원을 안내한다. vLLM-Omni는 OpenAI-like image generation endpoint를 제공한다.
- 일반 LLM용 llama.cpp/Ollama chat model이 아니라 diffusion image pipeline이다.
- 7B visual generator라 해도 native 2K 이미지 생성은 VRAM/연산 요구가 작지 않다. 일반 저사양 PC에서의 실시간 운용을 가정하면 안 된다.
- Hugging Face Inference Provider에는 조사 시점 직접 배포되어 있지 않다.
- 라이선스가 Apache/MIT가 아니라 **Qwen Research License**이므로 상업 배포 전 라이선스 원문 확인이 필요하다.

### Benchmark 주의

공식 showcase와 품질 주장은 **개발사 자체 자료**다. 오늘 선정은 공개 직후 사용 확산, 구조 변화, native RGBA·multi-reference 편집과 배포 생태계를 중심으로 판단했으며 이를 독립 성능 검증으로 표현하지 않는다.

### 주요 1차 출처

- Hugging Face: https://huggingface.co/Qwen/Qwen-Image-2.1
- Official GitHub: https://github.com/QwenLM/Qwen-Image-2.1

## 2. yandex/AliceAI-Foundation-80B-A3B-Base

- **Hugging Face:** https://huggingface.co/yandex/AliceAI-Foundation-80B-A3B-Base
- **개발사/작성자:** Yandex
- **분야/규모:** Text LLM / Foundation / Sparse MoE, **80B total / 3B active per token**, 48 layers
- **지원 언어:** Russian, English
- **Context:** **262,144 tokens**
- **라이선스:** Apache-2.0

### 오늘 주목할 근거

조사 시점 snapshot은 약 **56 likes, 597 downloads/month, Community 1**이며 최근 공개된 base model이다. Yandex는 training corpus, architecture, hyperparameters를 다시 설계하고 **완전히 처음부터 학습(from scratch)**했다고 명시했다. 핵심 결정을 검증하기 위해 별도의 2T-token from-scratch training run들을 수행했다고 공개했다.

### 기존 모델과의 기술적 차이와 별도 계열 판정

`introduced-models.md`에는 `yandex/AliceAI-T5-35B-A0.6B`가 있다. 하지만 그 모델은 **encoder-decoder sparse MoE** 계열이다. 이번 Foundation 80B는 **autoregressive decoder-only foundation model**이며 구조가 다음과 같이 다르다.

- 12 × [3 × (`KDA → MoE`) + 1 × (`Gated Attention → MoE`)]의 hybrid sequence stack
- KDA 32 query/32 KV heads와 convolution kernel 4
- Gated Attention 16 query/2 KV heads
- MoE는 **512 experts, top-10 + 1 shared expert**
- MTP 1 layer

동일 회사의 이름만 이어지는 크기 변형이 아니라 backbone, attention/linear-recurrence 혼합 방식, MoE 구성, decoder-only 목적이 달라 **별도 foundation 계열**로 판정했다.

### 실제 활용 가능성과 제약

- Transformers에서 `trust_remote_code=True`로 실행 가능.
- Hugging Face 페이지에 **vLLM** 및 **SGLang** OpenAI-compatible completion server 예시가 제공된다.
- 공식 vLLM 예시는 GPU 4개 tensor parallel을 사용한다. 이것을 절대 최소 요구사항으로 단정할 수는 없지만, 80B BF16 모델이라 일반 PC 단일 GPU용으로 보기 어렵다.
- LoRA 예제도 80GB GPU 4장 + FSDP2를 기준으로 제시한다.
- 아직 **pretrained base model**이고 post-training/alignment가 끝난 최종 대화형 제품이 아니라고 개발사가 명시한다. production에 바로 넣기보다는 fine-tuning/behavior control이 필요하다.

### Benchmark 주의

모델 카드의 WikiWebFacts 86.5, HardMultiQA 67.9, MATH-500 91.1, LiveCodeBench 등의 수치는 Yandex가 **내부 평가 인프라에서 측정한 개발사 자체 평가**다. 독립 재현 결과로 간주하지 않는다.

### 주요 1차 출처

- Hugging Face model card: https://huggingface.co/yandex/AliceAI-Foundation-80B-A3B-Base

## 3. Mapika/decider-2b

- **Hugging Face:** https://huggingface.co/Mapika/decider-2b
- **개발사/작성자:** Mapika
- **분야/규모:** Decision Model / Classification / Agent Routing, **2B**
- **기반:** `Qwen/Qwen3.5-2B-Base` (1.9B)
- **언어:** English
- **라이선스:** Apache-2.0

### 오늘 주목할 근거

조사 시점 snapshot은 **20,024 downloads/month, 54 likes, Community 1, 2 Spaces**다. 현재 Hub weights인 **v10은 2026-09-19** 공개됐으며 v8에서 384 step의 **calibration-aware RL**을 추가했다. 최근 다운로드 규모와 업데이트 시점, Agent routing에 바로 사용할 수 있는 명확한 API 형태가 함께 나타난다.

### 기존 모델과의 기술적 차이와 별도 계열 판정

Qwen3.5-2B-Base를 유지하므로 base architecture 자체가 새로운 것은 아니다. 그러나 일반 autoregressive LLM처럼 문장을 생성하지 않고, `state + typed question + option list`를 받아 **한 번의 forward pass에서 모든 option의 확률 분포를 반환**한다. output-token decoding, JSON parsing, schema violation 경로가 없다.

v1~v8은 약 95개 공개 decision dataset, agent trajectory, web element choice, game state 등을 proper-scoring 기반 supervised training에 사용했다. v10은 실제 browser task checker와 game의 exact probability law 같은 **결과(outcome)만 reward로 쓰는 calibration-aware RL**과 hard KL constraint를 더한다.

즉 동일 Qwen checkpoint의 단순 도메인 fine-tune이 아니라 **생성 방식과 근본 목적을 language generation → calibrated software decision primitive로 변경**하고, Agent/browser outcome RL까지 추가했으므로 사용자 중복 규칙의 예외에 해당하는 별도 post-trained decision 계열로 판정했다.

### 실제 활용 가능성과 제약

- 2B BF16 weights는 카드 기준 약 3.5GB이고 `POST /v1/systemone` 형태의 전용 interface를 제공한다.
- routing, classification, judgment, browser agent의 다음 행동 선택처럼 확률 기반 판단에 적합하다.
- 일반 chat-completion LLM이 아니므로 Ollama/llama.cpp에 넣어 채팅하는 용도와는 다르다.
- Hugging Face Inference Provider에는 조사 시점 배포되지 않았다.
- 현재 browser 평가는 **22개 click-only MiniWoB++ synthetic task** 중심이다. typing, scrolling, 실제 웹사이트는 검증되지 않았다고 카드가 명시한다.

### Benchmark 주의

v10의 sampled MiniWoB++ success 93.2%, Mind2Web 82.7% 등은 **개발자 자체 평가**다. 카드가 같은 row/seed 비교와 confidence interval을 공개하지만 독립 벤치마크 검증으로 취급하지 않는다.

### 주요 1차 출처

- Hugging Face model card: https://huggingface.co/Mapika/decider-2b
- Official GitHub: https://github.com/Mapika/decider

## 4. cua-ai/cua-s1-forms

- **Hugging Face:** https://huggingface.co/cua-ai/cua-s1-forms
- **개발사/작성자:** Cua AI
- **분야/규모:** Computer Use / Form Filling / Decision Model, **706,048 trainable parameters**, **2.8MB checkpoint**
- **라이선스:** MIT

### 오늘 주목할 근거

조사 시점 Hugging Face snapshot은 약 **82 likes, 1 Space**이며 다운로드 수는 추적되지 않는다. 대형 VLM을 GUI form 하나마다 호출하는 대신 sub-megabyte급 전문 decision layer를 Cua Driver에 붙이는 설계가 Agent 실무 관점에서 눈에 띈다.

### 기존 방식과 무엇이 다른가

이 모델은 LLM을 축소한 autoregressive generator가 아니다. context와 option text를 각각 **byte-level embedding + 2-layer Transformer(width 128, 4 heads)**로 인코딩하고, Jev-like AttentionHead가 각 option을 context에 query해 logit을 만든 뒤 live option set 위에서 softmax한다.

입력은 form element와 문서에서 찾은 candidate entities이고, 출력은 `fill <entity>`, `check`, `click`, `skip` 같은 option 확률이다. 각 actionable element를 독립적으로 병렬 scoring하고, 실제 실행 순서는 downstream code가 결정한다. **GUI Agent의 perception/decision/action 중 decision을 아주 작은 전문 모델로 떼어낸 구조**라는 점이 핵심이다.

### 실제 활용 가능성과 제약

- `safetensors + JSON sidecar` 형식이 권장되며 loader가 tensor signature를 검증한다.
- `select_device("auto")` 경로가 있어 CUDA 전용 배포로 고정되지 않는다.
- Cua Driver의 form filling pipeline과 직접 연결할 수 있다.
- vLLM/Ollama/llama.cpp chat API 대상은 아니다.
- 모델은 PDF/document extractor가 이미 찾아준 entity 중 하나만 고른다. 값을 새로 생성하지 못한다.
- 학습은 10,000 synthetic episodes 중심이며 실문서 평가는 3 form + 3 PDF, 196 decisions로 작다. 영어 중심 label vocabulary도 제약이다.

### Benchmark 주의

synthetic test 99.95%, 196-decision real demo 100%, hosted Jev 대비 수치는 모두 **개발자 자체 평가**다. 특히 실문서 표본이 작으므로 일반적인 업무 자동화 정확도로 확대 해석하지 않는다.

### 주요 1차 출처

- Hugging Face model card: https://huggingface.co/cua-ai/cua-s1-forms
- Official source / Cua integration: https://github.com/trycua/cua/tree/main/libs/cua-s1

## 5. C-Tianyu/NanoJev

- **Hugging Face:** https://huggingface.co/C-Tianyu/NanoJev
- **개발사/작성자:** C-Tianyu
- **분야/규모:** Agent Decision / Navigation / Game Action Selection, **0.6B**
- **기반:** `Qwen/Qwen3-0.6B-Base`
- **언어:** English 중심
- **라이선스:** inference/training source는 MIT; **Qwen base weights는 upstream license 유지**

### 오늘 주목할 근거

조사 시점 snapshot은 약 **63 likes, 1,267 downloads/month, 1 Space**다. current unified step-400 checkpoint, exact training initialization, full inference source를 함께 공개하며 Jev/System-One 형태의 작은 decision model 재현 흐름에서 빠르게 관심을 얻고 있다.

### 기존 모델과의 기술적 차이와 별도 계열 판정

Qwen3-0.6B backbone을 사용하므로 일반적인 Qwen fine-tune이라면 제외해야 한다. NanoJev는 각 candidate를 state/question과 함께 encode한 후 shared Qwen backbone의 EOS representation과 **attention-based Choice head**로 후보 집합 전체를 scoring한다. softmax가 모든 candidate probability를 동시에 반환하며 **output-token decoding을 하지 않는다**.

또한 Maze, Snake, ViZDoom Basic, Predict Position의 여러 환경을 한 모델에서 mixed-task supervised cross-entropy로 학습하고, 동일 structured decision interface에서 boolean/ordered score/action distribution을 처리한다. 따라서 backbone은 유지하지만 **출력 구조·생성 방식·Agent 행동 선택이라는 근본 목적**이 크게 바뀌어 별도 post-trained decision 계열로 판정했다.

### 실제 활용 가능성과 제약

- 공식 예시는 `DecisionPredictor`를 CUDA BF16으로 로드한다.
- Maze/game/navigation처럼 후보 action set이 명확한 Agent component에 적합하다.
- 일반 chat model이나 OpenAI-compatible text-generation server가 아니다. vLLM/Ollama/llama.cpp 지원도 모델 카드에서 확인되지 않는다.
- Hugging Face Inference Provider에는 조사 시점 배포되지 않았다.
- source code MIT와 base model license가 다르므로 재배포 시 **Qwen upstream license**까지 확인해야 한다.

### Benchmark 주의

Maze/Snake/ViZDoom/Predict Position 결과는 **작성자 자체 평가**다. frozen case와 seed, dataset/replay 자료가 공개되어 있으나 독립기관의 일반 Agent benchmark 검증으로 표현하지 않는다.

### 주요 1차 출처

- Hugging Face model card: https://huggingface.co/C-Tianyu/NanoJev

## 오늘의 Top Pick

**Qwen/Qwen-Image-2.1**

공개 하루 만에 높은 HF 반응과 Spaces 확산이 나타났고, 7B single-stream DiT로 생성+편집을 통합하면서 native RGBA, 10-reference editing, 2K, prefix KV cache reuse까지 한 번에 제공한다. Diffusers/ComfyUI뿐 아니라 SGLang-Diffusion·vLLM-Omni 지원 경로까지 빠르게 붙어 있어 **기술적 변화와 개발 실사용성의 균형이 오늘 후보 중 가장 좋다**.
