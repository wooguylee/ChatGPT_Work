## 1. XHToken/Spark-X2.5-4B

- Hugging Face: https://huggingface.co/XHToken/Spark-X2.5-4B
- 개발사/작성자: **SparkLLM / XHToken**
- 분야: **Text LLM / Coding / Agent / Tool Use / Reasoning**
- 규모: **4B parameters, BF16**
- 라이선스: **Apache-2.0**

### 오늘 주목할 근거

2026-09-07 조사 시점 Hugging Face 전체 Trending에서 **3위권**에 위치했습니다. Hugging Face 표시는 **Updated 4 days ago**, 최근 월 다운로드 **5,477회**, 좋아요 **약 599~601개**, Community **9개**, 연결 Space **2개**였습니다. Spark-X2.5 Collection도 조사 시점 약 16시간 내 업데이트된 상태였습니다.

절대 규모가 4B로 작으면서도 coding·tool use·agent workflow를 전면에 내세우고, 공개 직후 대형 모델과 양자화 파생본 사이에서 전체 Trending 상단까지 올라온 점을 높게 평가했습니다.

### 기존 모델과의 기술적 차이

Spark-X2.5는 **full attention 1개 층 + sliding-window attention 3개 층**을 반복하는 hybrid attention 구조를 사용합니다. 모든 층에서 긴 문맥 전체를 보는 대신 일부 층만 전역 attention을 수행해 KV cache와 long-context 계산 부담을 낮추면서, 공식 카드 기준 **native 1M-token context**를 학습 단계부터 지원합니다.

학습 측면에서는 약 **20T tokens**의 사전학습 뒤 수백억~수천억 토큰 규모의 별도 long-context stage를 거쳤고, SFT와 대규모 RL로 얻은 domain-specialized teacher policies를 **MOPD**로 하나의 배포 모델에 통합했다고 설명합니다. 단순히 기존 4B 모델의 instruction tuning만 한 형태가 아니라, long-context 효율과 agent/coding post-training을 함께 설계한 점이 핵심입니다.

### 개발사 자체 평가

모델 카드의 BFCL-V4, tau2/tau3-bench, MCP-Atlas, MCP-Mark, Workspace Bench, BrowseComp, SWE-Bench Pro/Verified/Multilingual, SciCode, AIME 등의 수치는 **개발사 자체 평가**입니다. 예를 들어 Spark-X2.5-4B는 개발사 표에서 MCP-Atlas 54.6, SWE-Bench Pro 44.4, SWE-Bench Multilingual 53.3을 보고하지만 독립 재현 결과와 동일하게 취급하면 안 됩니다.

### 실제 활용 가능성과 제약

공식 자료에 **vLLM, SGLang, llama.cpp, MLX, Ollama, LM Studio, Llama-Factory** 경로가 안내되어 있고 vLLM/SGLang은 OpenAI-compatible API로 바로 서비스할 수 있습니다. 또한 Codex, Claude Code, OpenClaw, Hermes 같은 agent harness와의 통합을 직접 강조합니다. 4B급이라 오늘 후보 중 일반 개발 PC에서 실험하기 가장 현실적인 편이며, 양자화 배포 경로도 제공됩니다.

다만 **1M context를 실제로 쓰는 것은 별개의 문제**입니다. 공식 SGLang 예제도 1,048,576 context 설정에는 충분한 device memory가 필요하며 부족하면 context length를 낮추라고 명시합니다. Ollama/LM Studio 경로 역시 조사 시점에는 Spark용 llama.cpp 빌드를 사용하는 절차가 안내되어 있어, 모든 기존 설치에서 무수정으로 동작한다고 단정할 수 없습니다.

## 2. IFM/K2-Horizon-MoVA-36B-A4B

- Hugging Face: https://huggingface.co/IFM/K2-Horizon-MoVA-36B-A4B
- 개발사: **Institute of Foundation Models (IFM)**
- 분야: **Text LLM / Reasoning / Agent / Tool Use**
- 규모: 공식 설명 **36B stored parameters / 4B active parameters per token**, Hugging Face 파일 메타데이터는 약 **37B**
- 라이선스: **Apache-2.0**

### 오늘 주목할 근거

2026-09-07 조사 시점 Hugging Face 전체 Trending 첫 페이지에 올라와 있었고, 표시는 **Updated 3 days ago**, 최근 월 다운로드 **1,723회**, 좋아요 **186개**, Community **6개**였습니다. K2 Horizon Collection은 약 **1일 내 업데이트**되었고 0.9B·7B·36B-A4B·375B-A23B 등 여러 크기의 공식 계열이 동시에 공개되고 있습니다.

오늘은 단순 크기 변형을 여러 개 소개하지 않고, 구조적으로 가장 흥미로운 **MoVA-36B-A4B를 K2-Horizon 계열 대표**로 선정했습니다.

### 기존 모델과의 기술적 차이

이 모델은 sparse **Mixture-of-Experts(MoE)**에 **Mixture-of-Values attention(MoVA)**을 결합합니다. 총 36B weight를 저장하지만 토큰당 약 4B만 활성화해 계산량을 줄이는 방향이며, mid-training부터 **524,288-token(512K) native context**를 학습했다고 공식 카드가 설명합니다.

일반 MoE는 주로 FFN expert 선택에 초점을 맞추지만 K2-Horizon-MoVA는 attention의 value 경로까지 mixture 구조로 확장한 것이 차별점입니다. 또한 chat reasoning과 tool calling을 위해 `k2_horizon` reasoning parser와 tool-call parser를 공식 serving recipe에 포함해, 단순 대화 모델보다 agent 실행을 명시적으로 배포 시나리오에 넣고 있습니다.

### 개발사 자체 평가

공식 카드가 공개한 agent·reasoning·coding benchmark 비교는 **IFM 자체 평가**입니다. 카드에서는 4B active parameter 수준에서 훨씬 큰 open-weight 모델과 경쟁한다고 주장하지만, 이 표현은 독립 검증 결과가 아닙니다. 보고된 benchmark 표의 수치는 조사 시점 개발사 자료의 snapshot으로만 봐야 합니다.

### 실제 활용 가능성과 제약

공식 vLLM recipe는 tensor parallel 2와 expert parallel을 사용하며, SGLang recipe는 **2× H200, BF16** 환경에서 검증됐다고 명시합니다. OpenAI-compatible API와 reasoning/tool-call parser가 제공되어 MCP/Agent 서버 backend로 붙이기 좋은 구조입니다.

중요한 점은 **4B active라고 해서 4B 모델처럼 메모리를 쓰는 것은 아니라는 것**입니다. 원본 BF16 serving에는 전체 36B급 weights를 보관해야 하므로 일반 소비자 GPU 한 장에서 원본을 운용하기는 어렵습니다. Hugging Face에는 GGUF 등 양자화 파생본이 이미 존재하지만, 그것은 오늘의 신규 모델로 별도 집계하지 않았으며 실제 속도·메모리는 양자화 방식과 context 길이에 따라 달라집니다.

## 3. Qwen/Qwen-Drive-1.0-4B

- Hugging Face: https://huggingface.co/Qwen/Qwen-Drive-1.0-4B
- 개발사: **Qwen / Alibaba Cloud**
- 분야: **Autonomous Driving / Multimodal VLM / 3D Perception / VQA / Motion Planning**
- 규모: repository 명칭은 4B이며 Hugging Face checkpoint 메타데이터 표시는 **약 5B parameters**
- 라이선스: **Apache-2.0**

### 오늘 주목할 근거

Hugging Face Trending의 2026-09-07 snapshot에서 **Updated 5 days ago**, 최근 월 다운로드 **851회**, 좋아요 **57개**, Community **1개**, 연결 Space **1개**로 확인됐습니다. Qwen 조직 활동에도 모델 공개와 기술 보고서 제출이 최근 며칠 내 활동으로 잡혀 있습니다.

다운로드 절대량은 아직 크지 않지만, 범용 VLM의 출력에 단순 텍스트 설명만 추가한 것이 아니라 3D perception과 실제 ego trajectory planning까지 한 checkpoint family에 연결했다는 점에서 개발자 관점의 기술적 가치가 높습니다.

### 기존 모델과의 기술적 차이 및 별도 계열 판정

Qwen-Drive-1.0은 **Qwen3.5-4B VLM backbone 자체는 유지**하지만, 그 위에 두 가지 외부 모듈을 추가합니다.

1. **BEV perception head**: 3D object detection, semantic occupancy prediction, BEV map segmentation을 함께 수행합니다.
2. **Planning Expert**: 공유 VLM representation을 받아 **flow matching**으로 미래 ego trajectory를 생성합니다.

또한 driving supervision과 일반 vision-language 데이터를 섞는 staged training으로 범용 시각 이해의 catastrophic forgetting을 줄이도록 설계했고, `planner-sft`와 reward-optimized `planner-rl`을 별도 공개합니다.

따라서 backbone lineage만 보면 Qwen3.5 파생이지만, **모델의 근본 목적과 출력 구조가 VQA에서 3D 인지·연속 주행 계획으로 확대되고 별도 BEV/Planning 모듈이 추가**되었습니다. 이번 중복 규칙의 예외인 명백한 modality/output/purpose 확장으로 판단해 **Qwen-Drive-1.0을 별도 계열**로 소개합니다. 이후 동일 checkpoint의 양자화·포맷 변환·경미한 driving fine-tune은 같은 계열로 제외해야 합니다.

### 개발사 자체 평가

모델 카드의 NAVSIM, WOD-E2E, PAI-AV, AlpaSim, LingoQA, Ego3D 등 수치는 **Qwen 개발사 자체 평가**입니다. 예를 들어 NAVSIM PDMS에서 RL variant 90.7, best-of-6 91.4, LingoQA에서 SFT 77.8을 보고하지만 독립 검증처럼 표현해서는 안 됩니다.

### 실제 활용 가능성과 제약

Hugging Face가 기본 VLM용 vLLM/SGLang OpenAI-compatible serving 예시를 제공하지만, **Qwen-Drive의 핵심인 perception과 planning은 공식 `QwenLM/Qwen-Drive-1.0` 코드와 추가 module을 사용**해야 합니다. 공식 planning 예제는 BF16, `flash_attention_2`, CUDA에서 `planner-rl` 또는 `planner-sft`를 attach하는 방식입니다.

따라서 일반 사진 VQA처럼 표준 llama.cpp/Ollama 모델 하나로 전체 자율주행 stack을 재현하는 모델이 아닙니다. 연구·시뮬레이션·자율주행 perception/planning 실험에는 흥미롭지만, 실제 차량 제어에 사용하려면 센서 동기화·안전 검증·실시간성·규제 등 모델 카드 밖의 시스템 요구사항이 큽니다.

## 4. inclusionAI/LLaDA-Image

- Hugging Face: https://huggingface.co/inclusionAI/LLaDA-Image
- 개발사: **inclusionAI**
- 분야: **Text-to-Image / Image Editing / Diffusion**
- 규모: 공식 카드에서는 **6B family**로 설명하며 Hugging Face checkpoint 메타데이터는 **약 7B parameters**로 표시
- 지원 언어 표기: **English, Chinese**
- 라이선스: **Apache-2.0**

### 오늘 주목할 근거

공식 카드에 **2026-09-04 Base와 Turbo checkpoint 및 inference code 공개**가 명시되어 있습니다. 2026-09-07 Hugging Face Trending snapshot에서는 **Updated 3 days ago**, 최근 월 다운로드 **228회**, 좋아요 **38개**, Community **1개**, 연결 Space **3개**였습니다. 동반 논문도 Hugging Face에서 며칠 내 공개된 신규 작업입니다.

### 기존 모델과의 기술적 차이 및 별도 계열 판정

`introduced-models.md`에는 이미 **LLaDA2.2**가 존재하지만 LLaDA-Image는 단순 parameter 크기 변경이나 이미지 adapter가 아닙니다. 공식 설명상 **고품질 이미지 생성과 instruction-guided image editing을 하나의 checkpoint에서 수행하는 diffusion image model family**입니다.

핵심 변화는 다음과 같습니다.

- generation과 reference-preserving editing을 별도 backbone 없이 **단일 checkpoint**로 통합
- backbone과 DiT가 모두 diffusion인 **unified diffusion framework**
- paired language supervision 전에 **image-only pretraining + midtraining**으로 visual prior를 먼저 학습
- Base는 50-step, Turbo는 **Twin-DMD distillation**으로 2~4 step 생성·편집
- text-to-image, VQ-conditioned generation, reference image editing, 중국어·영어 text rendering 지원

즉 기존 LLaDA text diffusion LM 계열과 이름·연구 lineage가 연결되더라도 **modality, 생성 방식, 모델의 근본 목적이 이미지 생성/편집으로 크게 바뀐 차세대 분기**이므로 별도 계열로 판정했습니다. Base/Turbo/FP8은 앞으로 같은 LLaDA-Image 계열로 중복 처리합니다.

### 개발사 자체 평가

Qwen-Image-Bench에서 English 53.53, Chinese 53.38을 기록했다는 주장은 **inclusionAI 자체 평가**입니다. 독립적인 재현·비교 평가가 아닙니다.

### 실제 활용 가능성과 제약

공식 inference는 **Diffusers**, Python 3.11, PyTorch 2.8, Transformers 4.57.6, Diffusers 0.39.0 조합을 안내하고 Base 예제는 CUDA BF16에서 1024×1024, 50 steps를 사용합니다. Hugging Face 기본 UI는 Apple MPS 경로도 안내하지만, 공식 프로젝트의 주된 quickstart는 CUDA이므로 특정 Mac/PC에서의 속도나 메모리 요구량을 추측하지 않습니다.

LLM이 아니므로 vLLM/SGLang/OpenAI-compatible chat API나 llama.cpp/Ollama가 주 실행 경로가 아닙니다. 이미지 생성 API를 만들려면 Diffusers pipeline을 별도 HTTP 서비스로 감싸는 방식이 현실적입니다. 조사 시점에는 **weights와 inference code는 공개됐지만 training code는 `coming soon`**으로 표시되어 있습니다.

### 기존 모델과의 기술적 차이 및 별도 계열 판정

LightNav-0은 Qwen3-VL-4B-Instruct 기반 fine-tune이지만, 단순한 VQA instruction tuning이 아닙니다. 모델은 다음 두 계층의 출력을 일반 token sequence처럼 생성합니다.

- **dual-channel pointing tokens**: task/scene/embodiment와 분리된 spatial intent 표현
- **3단계 RVQ action tokens**: residual vector-quantized action tokenizer가 3개의 action token을 실제 **10-step robot-local waypoint chunk**로 복호화

이 하나의 interface로 instruction following, open-vocabulary object navigation, visual tracking을 통합하며 별도 task-specific prediction head를 사용하지 않습니다. 입력은 SlowFast-compressed first-person RGB history와 자연어 instruction, 출력은 pointing tokens + RVQ action tokens입니다.

따라서 Qwen3-VL backbone을 그대로 사용하는 lineage는 분명하지만 **행동 modality와 trajectory tokenization, embodied navigation 목적이 새로 추가**되어 경미한 fine-tuning 범위를 넘어선다고 판단했습니다. 이번 보고서부터 **LightNav-0 계열**의 직접 양자화·포맷·경미한 파생본은 중복으로 제외합니다.

### 실제 활용 가능성과 제약

공식 패키지는 `lightnav[vllm,video]` 설치와 `vllm_local` backend를 지원합니다. `lightnav-predict`로 video clip에 대해 offline action 예측을 할 수 있고, `lightnav-serve` + WebSocket client 형태로 tracking/navigation 서버를 구성할 수 있습니다. 공식 저장소에는 Habitat 평가, WebSocket protocol, real-robot deployment guide가 안내되어 있습니다.

5B급이라 대형 VLA보다 작지만 실제 로봇 적용에서는 GPU 추론뿐 아니라 카메라 frame rate, video preprocessing, waypoint controller, 안전 계층이 필요합니다. Hugging Face 카드만으로 특정 일반 PC의 실시간 fps나 최소 VRAM을 확인할 수 없으므로 수치를 추측하지 않습니다.
