## 1. XiaomiMiMo/MiMo-V2.6-Flash-RL

- Hugging Face: https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Flash-RL
- 개발사: **Xiaomi MiMo Team**
- 분야: **Omnimodal Text Generation / Coding / Agent / Vision-Language / Audio / Video Understanding**
- 라이선스: **MIT**
- 규모: 모델 카드 기준 **Sparse MoE, 309B total / 15B activated parameters**
- Context: **1M tokens**
- 입력 modality: **Text, Image, Video, Audio**

### 오늘 주목할 근거

조사 시점 Hugging Face 모델 페이지는 약 **151 likes**를 표시했고, MiMo-V2.6 collection은 약 3시간 전 갱신으로 표시됐다. 월간 다운로드 수치는 아직 `-`로 표시되어 다운로드 증가율은 정량화하지 않았다. 새 시리즈 공개 직후이므로 단순 누적 다운로드보다 공개 시점과 빠른 관심 증가를 더 크게 반영했다.

### 기술적으로 무엇이 달라졌나

MiMo-V2.6은 단순한 대화형 LLM 업데이트가 아니라 **RL을 여러 agent domain에 한 번에 확장하는 학습 구조**가 핵심이다.

- **Native omnimodal + long horizon**: text/image/video/audio를 하나의 모델에서 처리하고 1M context를 제공한다.
- **You Only RL Once**: coding, general agent, visual, cybersecurity를 각각 따로 RL하지 않고 여러 harness와 task를 같은 batch에 섞어 하나의 mixed RL run으로 학습한다.
- **Fully asynchronous GRPO**: 모델 카드 기준 한 step에 1,568 prompts × 16 rollouts를 사용하는 대규모 비동기 RL 구성이다.
- **Groupwise Reward Synthesis (GRS) + Groupwise Advantage Redistribution (GAR)**: 단순 pass/fail reward만 쓰지 않고 동일 group 안의 trajectory를 비교해 더 좋은 성공 경로를 구분한다.
- **MOPD2**: teacher trajectory의 prefix와 SFT demonstration을 재사용해 어려운 decision point를 효율적으로 학습한다.
- Backbone은 48 layers(39 SWA / 9 global attention), 256 routed experts 중 8개 활성, 5-layer speculative MTP decoder를 사용한다.
- Vision은 681M MiMo ViT, audio는 308M AudioTokenizer + 127M audio patch encoder를 사용한다.

HF 우측 metadata panel의 parameter 표기와 모델 카드 본문의 total/active parameter 설명이 서로 다르게 보이는 부분이 있어, 이 보고서는 **개발사 모델 카드의 309B total / 15B activated** 표기를 기준으로 기록한다.

### 실제 활용 가능성과 제약

공식 페이지가 **Transformers, SGLang, vLLM** 실행법을 제공하고, SGLang/vLLM 모두 OpenAI-compatible endpoint로 서비스할 수 있다. reasoning parser와 tool-call parser도 공식 예시에 포함되어 있어 MCP나 자체 Agent orchestration의 backend로 연결하기 좋다. HF는 llama.cpp/Ollama/LM Studio 호환 quantization 탐색 링크도 제공한다.

다만 309B total sparse MoE라는 규모와 공식 SGLang 예시가 tensor/data parallel 구성을 전제로 하는 점을 보면 **일반 PC에서 원본 checkpoint를 실용적으로 운용하기보다는 멀티-GPU 서버/클라우드가 주 대상**이다. 양자화는 저장·메모리 부담을 낮출 수 있지만, 일반 데스크톱에서의 실제 속도·메모리 요구를 공식 자료가 보장하지는 않는다.

### Benchmark 주의

모델 카드의 DeepSWE, AutomationBench, Toolathlon, OSWorld, CyberGym, VisualCoding 등의 수치는 **개발사 자체 평가**로 공개된 결과다. 독립 검증 결과처럼 해석하지 않는다.

- Hugging Face: https://huggingface.co/XiaomiMiMo/MiMo-V2.6-Flash-RL
- Xiaomi 공식 소개: https://mimo.xiaomi.com/mimo-v2-6
- 모델 카드에 연결된 Technical Report 참조

## 2. inclusionAI/Realtime-Venus

- Hugging Face: https://huggingface.co/inclusionAI/Realtime-Venus
- 개발: **Venus Team (Ant Group) + Tsinghua University**
- 분야: **Any-to-Any / Multimodal / Audio / Video / Streaming / Full-Duplex Agent**
- 라이선스: **Apache-2.0**
- 체크포인트: **Realtime-Venus-Omni 9B**, **Realtime-Venus-Audio 9B**
- Context: **40,960 tokens**
- 언어 표기: **English, Chinese**

### 오늘 주목할 근거

Hugging Face에서 최근 공개·업데이트된 모델로 조사 시점 약 **55 likes, Community 3**를 표시했다. 공식 GitHub 저장소는 약 **37 stars / 4 forks**를 표시했고, 모델뿐 아니라 실제 비동기 Harness와 브라우저 demo 코드까지 공개되어 있어 단순 checkpoint 공개보다 실사용 검증 범위가 넓다.

### 기술적으로 무엇이 달라졌나

기반은 이미 중복 인덱스에 있는 **MiniCPM-o 4.5 / Omni-Flow** 계열이지만, 이번 후보는 단순 fine-tuning이나 양자화로 보지 않았다. 이유는 **interaction 방식과 agent/tool 실행 구조 자체가 크게 바뀌었기 때문**이다.

- **Native full-duplex**: 모델이 말하는 동안에도 계속 듣고 보며 backchannel, interruption, correction, redirection을 구분한다.
- **Omni-Proactive interaction**: 사용자 prompt가 올 때까지 기다리는 구조가 아니라 streaming video/audio를 계속 보고 스스로 응답 시점을 판단한다.
- **Asynchronous delegation**: 대화 중 `<delegate>` 요청을 같은 causal timeline에 내보내고, 별도 Harness가 background task/tool 실행을 처리한다. 그동안 live conversation은 멈추지 않는다.
- **Training-free long-video memory**: 중요한 visual moment를 저장하고 query 관련 evidence를 비중복으로 회수해 AV context를 재조립한다.
- Omni는 SigLIP2 vision encoder, Whisper-Medium audio encoder, Qwen3-8B language backbone, discrete S3 speech token + streaming flow-matching decoder를 사용한다.

즉 기존 MiniCPM-o 4.5의 checkpoint 포맷만 바꾼 것이 아니라, **proactive full-duplex perception + interruption handling + async tool delegation + long-video memory**를 하나의 실시간 agent system으로 만든 점을 별도 계열로 판단한 근거로 삼았다.

### 실제 활용 가능성과 제약

공식 사용법은 Python 3.10, **CUDA, FFmpeg**를 요구하며 `trust_remote_code` 기반 custom Transformers code를 사용한다. 공식 GitHub의 online duplex demo는 최소 **NVIDIA A100 1장 이상**을 요구한다고 명시한다. 따라서 일반 CPU PC나 가벼운 Ollama/LM Studio 용도로 보는 모델은 아니다.

대신 Realtime-Venus-Harness는 외부 tool 작업을 대화와 분리해 비동기로 처리하는 구조라서 **MCP/Agent, Codex형 task backend, 음성·영상 assistant, 장시간 영상 monitoring** 같은 use case에 특히 의미가 있다. 공식 demo에는 Codex task backend 연동도 포함된다.

### Benchmark 주의

모델 카드의 video/audio understanding 및 full-duplex 결과는 모두 **Realtime-Venus 기술 보고서의 개발팀 자체 평가**다. 독립 검증 결과로 표현하지 않는다.

### 주요 1차 출처

- Hugging Face: https://huggingface.co/inclusionAI/Realtime-Venus
- 공식 GitHub/Harness: https://github.com/inclusionAI/Realtime-Venus
- Technical Report: https://arxiv.org/abs/2609.13814

## 3. SupraLabs/Supra2-IMG

- Hugging Face: https://huggingface.co/SupraLabs/Supra2-IMG
- 개발사: **SupraLabs**
- 분야: **Text-to-Image / Diffusion Transformer (DiT)**
- 라이선스: **Apache-2.0**
- 규모: **104.1M parameters**
- 출력 해상도: **256×256**

### 오늘 주목할 근거

Hugging Face Trending에서 당일 갱신 모델로 관찰됐고, 직접 모델 페이지는 조사 시점 약 **65 likes, Community 2**를 표시했다. 기존 대형 이미지 생성 모델과 반대로 100M급을 목표로 한 작은 from-scratch DiT라는 점에서 개발자 실험 가치가 높아 선정했다.

### 기존 Supra2-100M과 별도 모델로 판단한 이유

중복 인덱스에는 이미 `SupraLabs/Supra2-100M` text model 계열이 있다. 하지만 Supra2-IMG는 단순 parameter 크기 변형이나 fine-tune이 아니다.

- 모델 카드는 **from scratch로 학습한 text-to-image diffusion transformer**라고 명시한다.
- architecture는 약 104.1M의 **SupraDiT**, frozen **Flan-T5-Base** text encoder, **SD-VAE-FT-MSE** VAE를 결합한다.
- 생성 방식과 modality가 text autoregressive LM에서 **latent image diffusion/flow sampling**으로 완전히 바뀌었다.
- 모델의 근본 목적도 언어 생성에서 **text-to-image generation**으로 바뀌었다.

따라서 사용자 중복 규칙의 예외인 **modality·architecture·생성 방식·근본 목적의 큰 변화**에 해당한다고 판단했다.

### 학습과 구조

공식 카드 기준 14-layer DiT, `d_model=576`, 9 attention heads, latent 32×32, patch size 2, Flan-T5 context 128을 사용한다. FLUX-Reason-6M에서 5.6M images를 사용해 10 epochs 학습했으며, 작성자는 단일 NVIDIA H100 SXM 80GB에서 data preparation 포함 약 9시간이 걸렸다고 설명한다.

### 실제 활용 가능성과 제약

104.1M parameter라 대형 T2I 모델보다 훨씬 작은 편이지만, **공식 카드가 일반 PC CPU/저사양 GPU의 최소 메모리나 속도를 측정해 공개하지는 않았다.** 따라서 “일반 PC에서 빠르게 동작한다”고 단정하지 않는다.

실행은 제공된 `inference.py`를 사용하며 권장 sampling은 Euler flow 50 steps다. 현재 공개 자료 기준 vLLM/SGLang/OpenAI-compatible API가 핵심 배포 경로인 모델이 아니라 이미지 생성용 custom inference pipeline에 가깝다. RAG/MCP용 LLM backend보다는 로컬 이미지 기능, UI prototype, 작은 T2I 연구용이 더 적합하다.

### Benchmark 주의

모델 페이지의 “SOTA quality for its size” 표현은 **개발사/작성자 주장**이다. 카드에 독립 평가 기관의 검증 결과가 함께 제시된 것은 아니므로 독립 benchmark처럼 기록하지 않는다.

## 중복·파생본 검토에서 제외한 주요 후보

- `XiaomiMiMo/MiMo-V2.6-Pro-RL`, `MiMo-V2.6-Distill-Qwen-9B`: 오늘 소개한 MiMo-V2.6 계열의 variant/distillation로 별도 카운트하지 않음.
- `StarDoc-AI/TeleOCR`: 공식 카드가 기존 **NaviDC-OCR의 rename**이라고 명시하며, `StarDoc-AI/NaviDC-OCR`은 이미 중복 인덱스에 있으므로 제외.
- `moondream/parakeet-redux`: 공식 카드가 `parakeet-tdt-0.6b-v3`와 **same architecture, same tokenizer**인 1.58-bit ternary version이라고 명시하므로 양자화/직접 파생 규칙에 따라 제외.
- `bespokelabs/Bespoke-Nimble-9B`: Qwen3.5-9B 기반 **LoRA adapter** 공개이므로 adapter 제외 규칙 적용.
- `TaoLiveAIGC/TaoMate-H3`: MiniMax-H3 기반 LoRA 공개이므로 직접 adapter 파생본으로 제외.
- `thesysdev/OUI-1`: DiffusionGemma 26B-A4B 기반 LoRA merged model. UI 생성 목적은 흥미롭지만 이미 인덱스에 있는 DiffusionGemma의 직접 LoRA 파생 성격이 강해 이번에는 신규 계열 예외를 적용하지 않음.
- `tencent/WeVisDoc-4B`: Qwen3-VL 기반 document parsing fine-tune으로 판단되어 엄격한 파생본 필터에 따라 제외.

## 오늘의 Top Pick

**XiaomiMiMo/MiMo-V2.6-Flash-RL**

선정 이유는 단순 성능표가 아니라 **1M long context + text/image/video/audio native omnimodal + mixed-domain asynchronous agent RL + groupwise grading + MOPD2 + 공식 SGLang/vLLM/tool-call serving 경로**가 동시에 공개됐기 때문이다. 실제 agent backend를 구축하는 개발자 관점에서 오늘 후보 중 활용 범위와 기술 변화가 가장 크다.
