## 1. nex-agi/Nex-N2.5-mini

- Hugging Face: https://huggingface.co/nex-agi/Nex-N2.5-mini
- 개발사: **Nex AGI**
- 분야: Agent, multimodal reasoning, computer use, browser use, coding/tool use
- 규모: Hugging Face 표시 **35B parameters**, `qwen3_5_moe` 계열 태그
- 라이선스: **Apache-2.0**

### 오늘 주목할 근거

조사 시점 Hugging Face 전체 Trending 첫 페이지에 위치했고 **Updated 1 day ago**, 최근 월 다운로드 **2회**, 좋아요 **204개**, Community **3개**로 표시됐다. 다운로드 수가 매우 작은 것은 공개 직후라는 점을 감안해야 하며, 반대로 좋아요와 Trending 진입 속도는 초기 관심도가 빠르게 형성되고 있음을 보여주는 snapshot이다. 공식 Nex-N2.5 Collection도 약 1일 내 업데이트된 상태다.

### 기존 모델과의 기술적 차이

Nex-N2.5는 mini·Pro·Max의 세 크기로 동시에 공개된 하나의 계열이며 오늘은 **mini를 대표 모델로만 집계**한다. 공식 설명에 따르면 mini와 Pro는 Nex-N2의 multimodal foundation을 이어가면서 computer use, web browsing, visually grounded agentic capability를 강화했다. 특히 vision을 단순 입력 modality가 아니라, Agent가 화면 상태를 관찰하고 작업 결과를 검증한 뒤 다음 행동을 수정하는 **feedback interface**로 사용한다. 컴퓨터와 브라우저를 조작하고 프로그램을 실행·테스트하며 장기 작업 중 결과를 스스로 확인하는 구성이 핵심이다.

Max는 1.6T 규모의 text-only MoE로 별도 기반을 사용하지만 같은 Nex-N2.5 제품군의 동시 공개 모델이므로 오늘 별도 항목으로 중복 집계하지 않는다.

### 실제 활용 가능성과 제약

Hugging Face가 vLLM과 SGLang의 **OpenAI-compatible API** 예제를 제공한다. `qwen3_coder` tool-call parser와 reasoning parser를 사용할 수 있고, `reasoning_effort`를 `none`·`medium`·`high`로 조절하는 공식 예시도 있다. Hugging Face의 quantization 경로를 통해 llama.cpp·Ollama·LM Studio 호환 파생본을 찾을 수 있다.

반면 원본 mini의 공식 SGLang 배포 예시는 **2× H100** 단일 노드를 사용한다. 따라서 이름에 `mini`가 붙더라도 원본 정밀도 모델을 일반 PC에서 편하게 구동하는 급은 아니다. 로컬 PC에서는 별도 양자화본의 품질·메모리 요구를 개별 검증해야 한다.

### benchmark 주의

Terminal-Bench, SWE-Bench Pro, BrowseComp, OSWorld 등 공식 카드의 Nex-N2.5 비교표는 일부 외부 leaderboard 값을 섞어 사용하지만 Nex 자체 harness 평가도 포함한다. 따라서 Nex-N2.5 성능 수치는 이 보고서에서 **개발사 자체 평가/개발사 집계 평가**로 취급하며 독립 검증 결과로 표현하지 않는다.

### 주요 1차 출처

- HF 모델 카드: https://huggingface.co/nex-agi/Nex-N2.5-mini
- 공식 GitHub: https://github.com/nex-agi/Nex-N2.5

## 2. inclusionAI/Ling-3.0-flash-VL

- Hugging Face: https://huggingface.co/inclusionAI/Ling-3.0-flash-VL
- 개발사: **inclusionAI**
- 분야: Native multimodal LLM, image/video understanding, reasoning, Agent
- 규모: 공식 카드 **124B total / 5.5B active per token**; Hugging Face 메타데이터 표시는 약 125B
- 라이선스: **MIT**

### 오늘 주목할 근거

조사 시점 Hugging Face Trending의 앞쪽 페이지에 진입했으며 **Updated about 8 hours ago**, 최근 월 다운로드 **42회**, 좋아요 **38개**, Community **2개**로 표시됐다. 절대 다운로드는 아직 작지만 공개 직후 모델이고, text-only Ling 계열에 native image/video를 추가한 차세대 분기라는 신규성이 크다.

### 기존 계열과의 기술적 차이 및 별도 모델 판정

`introduced-models.md`의 과거 기록에는 **inclusionAI/Ling-3.0-flash**가 이미 존재한다. 따라서 이름만 보면 중복 제외 대상이다. 그러나 이번 VL은 단순 크기 변경이나 adapter가 아니라 공식 카드에서 다음 구조적 변화를 명시한다.

- image/video feature를 추출하는 **ViT visual encoder**와 2-layer MLP projector 추가
- 공간 위치와 시간 순서를 함께 표현하는 **VideoRoPE** 도입
- 42-layer backbone에서 **KDA와 Gated MLA를 5:1로 교대**
- sparse MoE로 124B 총량 중 token당 5.5B 활성화
- vision을 perception에만 쓰지 않고 reasoning·planning·acting·verification의 전체 Agent loop에 통합

즉 기존 Ling-3.0-flash의 텍스트 모델에 단순 시각 adapter 하나만 붙인 수준이 아니라 **modality와 architecture, Agent 동작 경로가 명백하게 확대**됐으므로 이번 중복 규칙의 차세대 예외로 별도 계열로 판정한다. 이후 Ling-3.0-flash-VL의 양자화·포맷·경미한 파생본은 같은 계열로 제외한다.

### context length 표기 주의

공식 카드 내부에 서로 다른 표기가 있다. Introduction은 **up to 256K**, Model Overview는 **up to 1M**이라고 적는다. 반면 실제 SGLang 검증 recipe는 YaRN을 사용한 **262,144 tokens(256K)** 설정을 명시한다. 숫자를 임의 해석하지 않고, 이 보고서에서는 카드 내부 표기 불일치를 그대로 기록하며 실무 배포 기준으로는 공식 검증 recipe의 256K 설정을 우선 참고한다.

### 실제 활용 가능성과 제약

SGLang 공식 recipe는 256K 기준 **4× 141GB-class GPU(H20-3e/H200)** 또는 4-GPU Blackwell 노드를 권장하고, 80GB H100/H800에서는 `tp=8` 확장을 안내한다. vLLM은 inclusionAI의 별도 `vllm-ling-v3` fork를 사용하며 OpenAI-compatible `/v1/chat/completions`와 `ling3` reasoning/tool parser를 제공한다. Hugging Face에는 quantization 경로와 Novita inference provider도 연결되어 있다.

따라서 기능은 Agent/VLM backend에 매우 적합하지만 원본 weight를 일반 PC에서 돌리는 모델은 아니다.

### benchmark 주의

모델 카드의 multimodal·Agent benchmark와 Artificial Analysis 관련 비교는 모델 제공사가 카드에서 취합·보고한 값이다. 이 보고서에서는 **개발사 자체 평가 또는 개발사 보고 평가**로 표시하며 독립 재현 결과와 동일시하지 않는다.

### 주요 1차 출처

- HF 모델 카드: https://huggingface.co/inclusionAI/Ling-3.0-flash-VL
- vLLM fork: https://github.com/inclusionAI/vllm-ling-v3
- SGLang recipe: https://docs.sglang.io/cookbook/autoregressive/InclusionAI/Ling-3.0-flash-VL

## 3. OrionLLM/OxCoder-9B

- Hugging Face: https://huggingface.co/OrionLLM/OxCoder-9B
- 개발사: **Orion LLM Labs**
- 분야: Coding, Agentic Coding, Agentic Reasoning
- 규모: **9B**, BF16
- 기반: `Qwen/Qwen3.5-9B`
- 라이선스: **Apache-2.0**
- native context: 공식 카드 **262,144 tokens**

### 오늘 주목할 근거

조사 시점 Hugging Face Trending 5번째 페이지 안에 있었고 **Updated 1 day ago**, 최근 월 다운로드 **357회**, 좋아요 **28개**, Community **3개**로 표시됐다. `introduced-models.md` 및 기존 일일 보고서 검색에서는 OxCoder-9B와 `Qwen/Qwen3.5-9B` 자체가 기존 소개 계열로 확인되지 않았다.

### 기존 방식과의 기술적 차이

OxCoder는 Qwen3.5-9B를 기반으로 하지만, 핵심은 일반 instruction SFT보다 **Agent 실행 trajectory 증류**에 있다. 공식 카드는 Fable-5.1과 GLM-5.3이 Claude Code·OpenCode·Codex 환경에서 수행한 agentic coding trajectory를 `Frontier Agent Traces`로 구성해 증류했다고 설명한다.

그 결과 모델이 코드 생성만 하는 것이 아니라 **read-before-write**, LSP diagnostics에 반응, 전체 파일 재작성 대신 minimal edit diff 적용 같은 장기 software-engineering 행동 패턴을 학습한 것을 핵심 특징으로 내세운다. 262K native context 역시 여러 파일과 긴 Agent history를 한 세션에서 유지하려는 목적과 직접 연결된다.

### 실제 활용 가능성과 제약

Hugging Face에서 vLLM과 SGLang의 OpenAI-compatible API 예제를 제공하고 Docker Model Runner도 연결한다. quantization 경로가 있어 llama.cpp·Ollama·LM Studio용 파생본을 사용할 수 있다. 9B라는 크기는 오늘의 대형 MoE 후보보다 로컬 개발 장비에 현실적이지만, 원본 BF16의 실제 GPU 메모리·속도는 카드에서 소비자 GPU 기준으로 보장하지 않으므로 특정 VRAM 요구량을 추측해 적지 않는다.

### benchmark 주의

공식 카드의 Terminal-Bench, SWE-Bench 계열 수치는 **개발사 자체 평가**이며, 일부 baseline은 Ornith 모델 카드에서 가져와 평가 설정이 서로 다르다고 개발사 스스로 주석을 달았다. 따라서 숫자를 직접 동급 비교로 해석하는 데 주의가 필요하다.

### 주요 1차 출처

- HF 모델 카드: https://huggingface.co/OrionLLM/OxCoder-9B

## 4. Extropic-AI/Z1T-0

- Hugging Face: https://huggingface.co/Extropic-AI/Z1T-0
- 개발사: **Extropic Corp.**
- 분야: Experimental Text Generation, sparse Transformer-like architecture, probabilistic-hardware co-design
- 규모: 공식 HF 모델 카드에 전체 parameter 수가 명시되어 있지 않아 이 보고서에서는 숫자를 추정하지 않음
- 모델 weight 라이선스: 공식 HF 카드에 명시적 license field가 없어 추정하지 않음. 공식 연구 코드 저장소는 Apache-2.0

### 오늘 주목할 근거

Extropic은 **2026-09-04** Z1T 연구 글과 open weight를 공개했다. 조사 시점 Hugging Face Trending 5번째 페이지 안에 있었고 Z1T-0는 최근 월 다운로드 **445회**, 좋아요 **29개**, Community **1개**로 표시됐다. Extropic 공식 GitHub의 sparse-transformers 저장소도 최근 활동이 이어지고 있다.

### 기존 모델과의 기술적 차이

Z1T의 핵심은 기존 Transformer를 작은 크기로 축소한 것이 아니라 **하드웨어의 물리적 연결 제약에서 아키텍처를 역으로 설계**했다는 점이다. Extropic의 Z1은 fixed-degree sparse coupling graph를 가진 probabilistic hardware이며, Z1T는 이에 맞춰 4-bit weight와 output node당 4개의 incoming edge를 사용하는 고정 희소 연산을 학습 시작부터 적용한다.

일반 softmax self-attention 대신 sparse tanh-linear projection을 사용하는 **Gated Convolutional Attention(GCA)** 변형을 사용하고, RMSNorm은 **Dynamic Tanh(DyT)** 기반으로 대체해 Z1에 직접 매핑하기 쉽게 만든다. Z1에서 처리하기 어려운 pooling·positional/residual·vocabulary readout 등의 연산은 FPGA/XPU와 분담하는 heterogeneous decoding 구조도 연구한다.

이는 parameter 크기나 quantization만 바꾼 파생형이 아니라, dense GPU에 맞춰진 Transformer primitive 자체를 확률적·in-memory sparse hardware에 맞게 변경한 신규 architecture 계열로 본다.

### 실제 활용 가능성과 제약

현재는 **연구용 성격이 매우 강하다**. 공식 HF에는 inference provider가 없고, 공식 GitHub는 JAX 기반 sparse/Z1T 연구 코드를 제공한다. 일반적인 vLLM·SGLang·Ollama backend와 동일한 방식의 production deployment를 공식 지원하는 모델이 아니다. Extropic의 Z1 Stick/Card는 공식 hardware 페이지 기준 **early access 2027** 예정이므로, 2026-09-10 현재 실제 Z1 하드웨어에서 일반 개발자가 즉시 self-host하는 단계도 아니다.

### benchmark/효율 주장 주의

Extropic은 Z1T의 에너지 효율이 GPU 대비 큰 폭으로 향상될 수 있다고 보고하지만, 공식 글이 명시하듯 핵심 에너지/latency 수치는 **Z1의 이론적 칩 소비전력 추정과 X0 실험을 바탕으로 한 개발사 자체 projection**이다. 최종 production Z1 시스템의 독립 측정값으로 해석하면 안 된다.

### 주요 1차 출처

- HF 모델 카드: https://huggingface.co/Extropic-AI/Z1T-0
- 공식 연구 글: https://extropic.ai/writing/z1t
- 공식 GitHub: https://github.com/extropic-ai/sparse-transformers
- 공식 하드웨어 페이지: https://extropic.ai/hardware

## 5. ibm-granite/granite-timeseries-patchtst-fm-r2

- Hugging Face: https://huggingface.co/ibm-granite/granite-timeseries-patchtst-fm-r2
- 개발사: **IBM Granite / IBM Research**
- 분야: Time Series Foundation Model, zero-shot forecasting, probabilistic forecasting
- 규모: 공식 카드 **약 385M parameters**; HF 메타데이터 약 0.4B
- context: **8192 time steps**
- 라이선스: **Apache-2.0 또는 OpenMDW-1.0 중 선택 가능한 dual license**

### 오늘 주목할 근거

IBM은 **2026-09-09** Hugging Face 공식 블로그를 통해 PatchTST-FM-r2를 공개 소개했다. 조사 시점 모델 페이지는 최근 월 다운로드 **2,396회**, 좋아요 **5개**를 표시했다. 좋아요 수보다 이미 형성된 다운로드와 공식 release, 그리고 r1 대비 architecture 변화가 의미 있는 후보로 판단한 이유다.

### 기존 모델과의 기술적 차이

r2는 PatchTST-FM-r1의 단순 재학습이 아니라 backbone을 명시적으로 바꿨다.

- 표준 Transformer block을 두 half-step FFN 사이에 MHSA와 temporal convolution을 둔 **Conformer-style block**으로 교체
- convolution kernel을 3과 5로 교대해 local temporal pattern을 convolution이 맡고 attention이 장기 관계에 집중하도록 설계
- patch size 16, stride 8의 **50% overlapping patch** 사용
- training에서 Hamming-window loss weighting, inference에서 **overlap-and-add forecasting** 사용
- block 수 20 → 30 증가, pre-head layer norm 추가
- 99개 quantile을 출력하는 head로 point forecast와 uncertainty interval을 함께 지원
- CauKer synthetic data를 포함한 pretraining 확장

따라서 r1과 호환성을 유지하더라도 핵심 backbone과 forecasting 생성 방식이 의미 있게 변경된 차세대 모델로 볼 수 있다. `introduced-models.md` 검색에서도 PatchTST-FM 계열의 기존 소개 기록은 확인되지 않았다.

### 실제 활용 가능성과 제약

`granite-tsfm>=0.3.9` 패키지의 `TimeSeriesForecastingPipeline`으로 Hugging Face checkpoint를 직접 불러와 **fine-tuning 없이 zero-shot forecasting**을 수행할 수 있다. 수요·센서·CPU utilization·에너지·거래량·traffic·가격 등 정규 시계열에 적용할 수 있고 missing-value imputation과 quantile forecast도 지원한다.

이 모델은 LLM이 아니므로 vLLM/SGLang/OpenAI-compatible API나 MCP tool-calling의 대상이 아니다. 공식 카드가 특정 소비자 GPU 최소 사양을 제시하지 않으므로 이 보고서에서는 GPU 요구량을 추측하지 않는다. 상업 활용 관점에서는 Apache-2.0/OpenMDW-1.0의 permissive dual-license가 장점이다.

### benchmark 주의

IBM은 9월 8일 기준 GIFT-Eval의 replicable zero-shot 모델 가운데 전체 2위이며 permissive commercial-friendly license 모델 중 최고라고 보고한다. 공개 leaderboard와 재현 코드가 있지만 이 문구와 수치의 제시 주체는 IBM이므로 여기서는 **개발사 자체 보고/평가**로 명시한다.
