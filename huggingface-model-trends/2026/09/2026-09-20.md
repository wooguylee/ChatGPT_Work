## 1. convaiinnovations/laya — 오늘의 Top Pick

- **Hugging Face:** https://huggingface.co/convaiinnovations/laya
- **개발사/작성자:** Convai Innovations
- **분야/규모:** Text Classification, Decision/Routing/Guardrail. 기본 English checkpoint는 **421M**, multilingual은 **322M**, typed-decisions는 **421M**.
- **라이선스:** Apache-2.0

### 오늘 주목할 근거

조사 시점 모델 페이지는 **515 likes**, Community 2를 표시하고 있으며 Hugging Face Trending 상위권에서 관찰됐다. 다운로드 수는 해당 저장소에서 추적되지 않는다. 모델 카드가 하나의 repository 안에서 English, 100+ language multilingual, typed-decisions의 세 checkpoint를 명확히 묶어 관리하고 있어 실사용 경로도 비교적 분명하다.

### 기존 방식과 무엇이 다른가

Laya는 다음 토큰을 생성하는 autoregressive LLM이 아니라 **상태(state) + 사용자가 정의한 typed question/schema를 입력받아 확률 분포를 한 번의 forward pass로 계산하는 비생성형 decision model**이다. 기본 모델은 ModernBERT-large 395M을 전체 fine-tune하고, 그 위에 2-layer decision head와 option-marker scorer, act/escalate head를 붙여 총 421M이 된다. 각 선택지는 `[MASK]` marker 위치에서 점수를 받고 같은 질문의 후보끼리 softmax된다.

핵심 학습법은 모델 카드가 **RLCD(Reinforcement Learning for Calibrated Decisions)**라고 부르는 방식이다. 확률 분포 자체를 policy output으로 보고, proper scoring rule(log score + spherical score, ordinal에는 ranked probability score)을 reward로 사용한다. 즉 단순히 정답 class만 맞히는 것이 아니라 **확률의 calibration 자체를 학습 목표에 넣었다**는 점이 일반 classifier나 생성형 LLM 라우터와 다르다.

### 실제 활용 가능성과 제약

- `pip install laya` 또는 Transformers로 로컬 self-host 가능.
- 이메일 triage, 고객문의 라우팅, moderation, guardrail, escalation 여부, 위험 점수처럼 **출력 schema가 고정되고 확률이 중요한 Agent 앞단/뒷단**에 특히 적합하다.
- 생성형 모델이 아니므로 vLLM/llama.cpp/Ollama의 chat-completion 모델로 쓰는 유형은 아니다. MCP/Agent에서는 tool 호출 전 routing/scoring component로 조합하는 편이 자연스럽다.
- 기본 English 모델은 context 512, multilingual은 1024. 긴 문서 전체를 한 번에 판정하는 RAG/장문 모델로 보기는 어렵다.
- 모델 카드 자체도 새 업무 분포에서는 calibration을 다시 확인하고, 산술·날짜 비교·multi-hop lookup은 deterministic code에 맡길 것을 권한다.

### Benchmark 주의

모델 카드의 T4 latency 및 정확도 수치는 **개발사 자체 평가**다. 예를 들어 기본/다국어 checkpoint에서 1문항 처리 시간을 각각 39.5 ms / 32.8 ms로 제시하지만, 동일 환경의 독립 검증으로 간주하지 않는다.

### 주요 1차 출처

- Hugging Face model card: https://huggingface.co/convaiinnovations/laya
- Official GitHub: https://github.com/NandhaKishorM/laya

## 2. m-a-p/SheetSage2

- **Hugging Face:** https://huggingface.co/m-a-p/SheetSage2
- **개발사/작성자:** Multimodal Art Projection (m-a-p)
- **분야/규모:** Audio / Music Transcription / Feature Extraction, **57.2M parameters**
- **기반:** `m-a-p/MERT-v2-FullSong` + 자동 merge되는 adapters
- **라이선스:** CC BY-NC 4.0

### 오늘 주목할 근거

조사 시점 snapshot은 **10,290 downloads/month, 109 likes, 27 Spaces**다. 모델 카드의 benchmark 섹션도 2026-09-14, 09-15, 09-16에 연속 갱신됐다. 단순 모델 공개 직후 반짝 노출이 아니라 음악 생성 생태계, 특히 YuE2와 연결되는 실사용 흐름이 나타나고 있다.

### 기존 모델과의 기술적 차이

`introduced-models.md`에는 이미 **m-a-p/YuE2-3B**가 있지만 SheetSage2는 같은 모델의 크기/포맷/양자화가 아니다. YuE2가 symbolic score와 audio를 이용해 음악을 **생성·편집**하는 방향이라면, SheetSage2는 실제 음악 녹음을 받아 **melody, chords, beats, key, structure를 분석해 editable ABC/MIDI와 시간 annotation으로 역변환**한다.

MERT-v2-FullSong 표현 위에서 음악 분석 task를 통합하고, 결과를 `score.abc`, `transcription.mid`, melody/chord 분리 MIDI, `events.json`, `.lab`로 내보낸다. 결과 ABC를 다시 YuE2에 symbolic conditioning으로 넣을 수도 있어 `audio → structured score → generative editing` 파이프라인을 만들기 좋다.

### 실제 활용 가능성과 제약

- Python 3.10/3.11, FFmpeg 6.1을 요구한다.
- 코드 자체가 `cuda if available else cpu` 경로를 제공하므로 GPU가 없어도 실행 경로는 존재한다. 다만 CPU 속도는 별도 확인이 필요하다.
- 57.2M으로 비교적 작고, 긴 곡은 overlapping window 처리한다.
- Hugging Face Inference Provider에는 현재 배포되지 않아 직접 실행이 기본이다.
- **CC BY-NC 4.0**이므로 상업 서비스에 바로 넣는 용도로는 적합하지 않다.

### Benchmark 주의

모델 카드가 14개 benchmark/metric pair 중 11개에서 최고 point estimate라고 밝히지만 이는 **작성자 자체 평가**다. 카드도 point estimate가 통계적 유의성을 의미하지 않는다고 명시한다.

### 주요 1차 출처

- Hugging Face model card: https://huggingface.co/m-a-p/SheetSage2
- YuE2 project: https://map-yue2.github.io/

## 3. XGENlabs/XGEN-JING

- **Hugging Face:** https://huggingface.co/XGENlabs/XGEN-JING
- **개발사/작성자:** XGEN Team / XGEN Labs
- **분야:** Interactive World Model, Image/Text-to-Video, joint Video+Audio, Egocentric Experience
- **기반:** MiniMax-H3 Ref2VA + FlashGen
- **라이선스:** MiniMax H3 Community License Agreement

### 오늘 주목할 근거

Hugging Face Trending에서 최근 갱신 모델로 관찰됐고, 조사 시점 모델 페이지는 44 likes, downloads/month 2로 아직 매우 초기 단계다. 다운로드 규모보다 **행동 입력이 포함된 interactive world-model interface를 실제 코드와 weights로 공개했다는 기술적 신선함** 때문에 선정했다.

### 기존 모델과의 기술적 차이와 별도 계열 판정

`introduced-models.md`에는 MiniMax-H3 계열이 이미 제외 대상이므로, 단순 H3 fine-tune이라면 재소개하지 않아야 한다. 다만 JING은 공개 카드가 명시적으로 **action + reference images + observation history → first-person video+audio**라는 새로운 입출력 목적을 둔다. `w/s/a/d` 행동을 시간 slice별 control로 받아 navigation, object interaction, character conversation을 생성하며 최대 5장의 reference image conditioning도 지원한다.

따라서 이번에는 단순 quality fine-tune이 아니라 **행동 modality와 interactive experience/world-model 목적이 추가된 별도 post-trained 계열**로 판정했다. 다만 모델 tree 상 MiniMax-H3의 fine-tune이며, 현재 공개본은 4-step bidirectional JING-Flash-v1이다. **causal model과 기술 보고서는 아직 공개 예정**이므로 새로운 backbone architecture가 검증됐다고 표현하지 않는다.

### 실제 활용 가능성과 제약

- 공식 demo는 **H100 6장**에서 검증: text encoder 1장, video/audio VAE 1장, DiT sequence parallel 4장.
- Python 3.12, CUDA 13 계열, pinned SGLang commit, FlashAttention-4, Diffusers 조합을 사용한다.
- 일반 PC/Ollama/llama.cpp 대상 모델이 아니다.
- SGLang을 쓰지만 일반 LLM OpenAI-compatible chat server와 같은 용도는 아니다. Prompt skills는 configurable Chat Completions API를 이용해 inference case JSON을 만드는 보조 경로다.
- 실험 비용이 높고 다운로드가 아직 2건 수준이라 **트렌드 후보로서는 기술 선행성은 높지만 실사용 성숙도는 낮다**.

### 주요 1차 출처

- Hugging Face model card: https://huggingface.co/XGENlabs/XGEN-JING
- Official GitHub: https://github.com/XGEN-Labs/XGEN-JING

## 4. Linkup-Platform/linkup-sparseup-embed-v1

- **Hugging Face:** https://huggingface.co/Linkup-Platform/linkup-sparseup-embed-v1
- **개발사/작성자:** Linkup
- **분야/규모:** Sparse Embedding / RAG / Retrieval, **약 149M parameters** (HF 표시 0.2B)
- **기반:** `lightonai/LateOn-unsupervised` + ModernBERT MLM head
- **언어:** English
- **라이선스:** Apache-2.0

### 오늘 주목할 근거

조사 시점 snapshot은 **454 downloads/month, 43 likes**이며 공개 직후 Hugging Face Trending에서 상승 중인 learned sparse retriever다. 대규모 다운로드 모델은 아니지만, RAG에서 dense/late-interaction과 별개로 사용할 수 있는 sparse vocabulary representation을 비교적 작은 공개 모델로 제공한다는 실무 가치가 크다.

### 기존 모델과의 기술적 차이와 별도 계열 판정

`introduced-models.md`에는 `lightonai/mDenseOn·mLateOn`이 이미 있다. SPARSEUP은 그 lineage를 활용하지만 단순 크기/양자화/포맷 변형은 아니다. 출력 표현 자체를 late interaction/dense vector가 아닌 **learned vocabulary-sparse vector**로 바꾼다.

모델 카드의 sparse 변환은 대략 `MLM logits → log(1 + ReLU(x - 15)) → 위치별 top-12 vocab 유지 → sequence max-pool → case/space vocab folding` 순서다. vocabulary folding으로 약 50k vocabulary를 약 34k sparse dimension으로 줄인다. 즉 검색 결과에 기여한 token weight를 사람이 읽을 수 있는 점도 dense embedding과 다른 장점이다.

동일 backbone/data lineage를 유지하면서 **retrieval representation architecture와 index 형태가 구조적으로 바뀌었기 때문에** 이번에는 별도 sparse-retrieval 계열로 판정했다.

### 실제 활용 가능성과 제약

- SentenceTransformers의 `SparseEncoder(..., trust_remote_code=True)`로 query/document encoding 가능.
- inverted sparse index와 조합하면 lexical+semantic expansion을 동시에 쓰는 RAG 검색기에 적합하다.
- Apache-2.0이라 상업 활용 측면의 제약이 낮다.
- 모델 카드 metadata에 `text-embeddings-inference` tag가 있지만 조사 시점 Hugging Face hosted Inference Provider에는 배포되어 있지 않다.
- English 모델이며 multilingual sparse retrieval로 추정 확대하지 않는다.

### Benchmark 주의

모델 카드가 BEIR-13에서 56.4 nDCG@10(일부 표 구성 기준) 등 비교 수치를 제시하지만 이는 **개발사 자체 평가**다. independent leaderboard 결과처럼 표현하지 않는다.

### 주요 1차 출처

- Hugging Face model card: https://huggingface.co/Linkup-Platform/linkup-sparseup-embed-v1
- Linkup technical blog: https://www.linkup.so/blog/introducing-sparseup-by-linkup

## 5. facebook/VGGT-Omega

- **Hugging Face:** https://huggingface.co/facebook/VGGT-Omega
- **개발:** Meta AI + University of Oxford Visual Geometry Group
- **분야/규모:** Vision / Feed-forward 3D Reconstruction, 공개 checkpoint 명칭 기준 **1B**
- **라이선스:** `fair-noncommercial-research-license`
- **접근:** Hugging Face checkpoint 접근 시 contact information 동의가 필요한 gated model

### 오늘 주목할 근거

조사 시점 Hugging Face는 **338 likes, Community 15, 10 Spaces**를 표시한다. 원 모델은 2026년 5월 공개됐지만 최근 공식 저장소가 재현성 관련 핵심 자산을 연속 공개했다. 공식 GitHub에는 9월에 training code, 추가 reproduction checkpoint, data preparation/cleaning 도구, supervised geometric filtering, 8개 training dataset sequence list 공개가 기록돼 있다. 즉 단순 오래된 모델 재소개가 아니라 **최근 meaningful update로 개발자 실사용·재현성 가치가 크게 올라간 사례**다.

### 기존 VGGT와의 기술적 차이

VGGT-Ω는 기존 VGGT의 high-resolution convolutional dense heads를 줄이고 **single dense prediction head + multi-task supervision**으로 단순화한다. 또 scene 정보를 register에 모으고, frame 간 정보 교환을 register로 제한하는 **register attention**을 사용해 전 프레임 global interaction 비용을 줄인다.

공식 프로젝트 설명은 이 변경으로 predecessor 대비 training GPU memory를 약 30% 수준으로 낮추고, supervised data를 15배 더 활용하며 unlabeled video self-supervision까지 확장했다고 밝힌다. 이 수치는 논문/개발팀 자체 주장으로 취급한다.

### 실제 활용 가능성과 제약

- 이미지/비디오로부터 camera extrinsics/intrinsics, depth, register/camera token을 내어 point cloud와 camera reconstruction 파이프라인에 사용할 수 있다.
- 공식 GitHub가 A100에서 end-to-end peak memory를 공개: 1 frame 6.02 GB, 50 frames 9.66 GB, 100 frames 13.37 GB, 500 frames 43.15 GB. **공식 자체 측정**이며 다른 GPU/해상도에서 동일하다고 가정하면 안 된다.
- vLLM/Ollama/llama.cpp 대상 LLM이 아니며 PyTorch 기반 vision geometry workflow다.
- license가 **non-commercial research**이고 checkpoint가 gated이므로 상용 제품 투입에는 부적합하다.

### Benchmark 주의

프로젝트 페이지가 Sintel camera estimation에서 이전 최고 대비 77% 개선 등을 제시하지만 이는 **저자/개발팀 자체 평가**다. 독립 검증 결과로 표현하지 않는다.

### 주요 1차 출처

- Hugging Face: https://huggingface.co/facebook/VGGT-Omega
- Official GitHub: https://github.com/facebookresearch/vggt-omega
- Official project page: https://vggt-omega.github.io/

## 중복 검증에서 제외한 주요 후보

오늘 Trending에서 보였지만 source-of-truth 규칙에 따라 다음 후보는 선정하지 않았다.

- `prism-ml/Ternary-Bonsai-2-27B-gguf`: 기존 Bonsai 계열이 이미 인덱스에 있고 GGUF/ternary 변환 성격이 강해 동일 계열 처리.
- `TaoLiveAIGC/TaoMate-H3`: MiniMax-H3 기반 LoRA/가속 배포 성격으로, 이미 소개된 H3 계열의 직접 adapter 파생으로 판단.
