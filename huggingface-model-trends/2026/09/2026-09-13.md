## 1. nasa-ibm-ai4science/NASA-IBM-Lunar-Foundation-Model

- Hugging Face: https://huggingface.co/nasa-ibm-ai4science/NASA-IBM-Lunar-Foundation-Model
- 개발: **NASA / IBM Research 및 협력 연구기관**
- 분야: Vision, multimodal remote sensing, scientific foundation model, feature extraction
- architecture: **ViT-B encoder-decoder** — encoder 768 dim / 12 layers / 12 heads, decoder 12-layer Transformer
- 입력/patch: pretraining 기준 **256×256 / 16×16**, FlexiViT로 다른 patch size에 적응 가능
- modality: **11개** — 9개 dense image-like modality + optical metadata + static-map context
- 라이선스: **Apache-2.0**

### 오늘 주목할 근거

NASA와 IBM은 **2026-09-10** 이 모델의 오픈소스 공개를 공식 발표했다. NASA 설명에 따르면 Lunar Reconnaissance Orbiter 중심의 달 관측 데이터를 기반으로 약 **200만 개 image tile**을 사용했으며, 1 m급 고해상도 카메라 영상 100만 개 이상과 약 96.4만 개의 100 m급 multispectral tile을 포함한다.

조사 시점 Hugging Face snapshot은 **최근 월 다운로드 500회, 좋아요 23개, Community 1개, 사용 Space 1개**였다. 절대적인 다운로드 수보다 NASA·IBM의 공식 공개 직후라는 최신성, 새로운 과학 foundation model이라는 기술적 차별성, 공개 dataset·benchmark·TerraTorch integration을 함께 제공한다는 점을 더 중요하게 평가했다.

### 기존 모델과의 기술적 차이

이 모델의 핵심은 일반 자연 이미지용 ViT를 단순 fine-tuning한 것이 아니라 **달 원격탐사 데이터를 대상으로 처음부터 학습한 multimodal·multi-resolution foundation model**이라는 점이다.

- **약 200만 개 co-registered lunar tile bundle**을 11개 modality로 구성해 사전학습
- LROC NAC 약 **1 m/px**와 LROC WAC 약 **100 m/px**라는 약 100× 해상도 차이를 하나의 mixed-batch pretraining loop에서 공동 학습
- 달 표면은 조명 조건에 따라 외형이 크게 바뀌므로 solar incidence, emission, phase/azimuth angle, sub-solar coordinate, tile-center coordinate, ground sampling distance 등의 **acquisition geometry를 별도 sequence context token으로 명시적으로 입력**
- 각 modality를 별도 VQ-VAE/FSQ 기반 discrete token vocabulary로 변환하고, sampled target position의 token을 맞히는 masked-token 계열 objective를 사용
- **FlexiViT patch embedding**으로 downstream task에서 patch size를 바꾸더라도 backbone 전체를 처음부터 다시 학습하지 않고 적응 가능
- modality-wise tokenization이라 downstream에서 일부 modality만 사용하거나 새 modality를 추가하는 구조를 지원

즉 단순한 사진 분류 모델이 아니라, 서로 해상도와 물리적 의미가 다른 달 관측 데이터를 공통 representation으로 연결하면서 **관측 당시의 조명·기하 조건까지 모델 입력으로 취급**한 점이 구조적 차별점이다.

### 학습 규모와 실제 활용 가능성

공식 모델 카드의 pretraining 설정은 **16× H100, 150k steps, global batch 1,536, bf16, 약 1.1k GPU-hours**다. 이는 사전학습 비용이지 downstream inference의 최소 GPU 요구사항을 의미하지 않는다.

실제 활용은 Hugging Face의 일반 LLM serving보다 **TerraTorch/PyTorch workflow**가 중심이다. 공식 repository는 crater detection, segmentation, dense regression, polar ice prospectivity 등의 fine-tuning 경로를 제공하고, 공식 카드에서는 LoRA(rank 16, alpha 32)를 실용적인 기본 adaptation 방법으로 권장한다.

- **vLLM/SGLang:** 언어 생성 모델이 아니므로 대상 runtime이 아님
- **llama.cpp/Ollama/LM Studio:** 일반 LLM runtime 대상 모델이 아니며 공식 지원을 확인하지 못함
- **OpenAI-compatible API:** 공식 제공 없음
- **RAG/MCP/Agent:** 직접적인 text-generation/RAG backend는 아니지만, 달 표면 이미지·다중 센서 데이터를 해석하는 별도 vision/science tool로 감싸 Agent가 호출하는 방식은 가능
- **일반 PC:** 공식적으로 간단한 CPU/일반 PC용 turnkey 실행 경로는 제시되지 않는다. 다만 downstream에서는 전체 pretraining을 반복하는 대신 frozen encoder·LoRA·fine-tuning을 선택할 수 있다.
- **Inference Provider:** 조사 시점 Hugging Face의 hosted inference provider 배포는 없음

### 활용 분야와 제약

공식 자료가 제시하는 주요 downstream 예시는 다음과 같다.

- crater detection / mapping
- irregular mare patch 등 젊은 화산 지형 segmentation
- 극지방 ice prospectivity 추정
- multimodal lunar feature representation
- 새로운 관측 modality와의 fine-tuning

다만 이 모델은 **과학적 측정 장비나 geodetic solution을 대체하는 생성 모델이 아니다.** 공식 카드는 생성한 latitude/longitude가 수십 도까지 어긋날 수 있고, 절대 고도도 offset이 발생할 수 있다고 경고한다. 또한 landing-site certification이나 hazard clearance 같은 운영 의사결정에는 검증되지 않았으며, ice prospectivity도 실제 얼음 측정치가 아니라 기존 knowledge-driven prospectivity map을 회귀한 것이다.

### benchmark 주의 — 개발팀 자체 평가

아래 결과는 공식 모델 카드와 NASA/IBM 발표가 제공한 **개발팀 자체 평가**이며 독립 검증 결과로 간주하지 않는다.

| Benchmark | NASA-IBM LFM | Best baseline | 해석 |
|---|---:|---:|---|
| Robbins craters, WAC, 100% data (mAP ↑) | 0.2581 ± 0.0017 | 0.2420 ± 0.0047 | 개발팀 평가에서 우위 |
| NAC craters, meter scale (mAP ↑) | 0.1543 ± 0.0098 | 0.1552 ± 0.0086 | seed spread를 고려하면 사실상 비슷함 |
| Irregular Mare Patches (IoU₁ ↑) | 0.5709 ± 0.0114 | 0.5687 ± 0.0181 | 차이가 작아 비교 가능 수준 |
| Polar ice prospectivity (RMSE ↓) | 0.0293 ± 0.0013 | 0.0377 ± 0.0004 | 개발팀 평가에서 가장 뚜렷한 개선 |

공식 카드 자체도 NAC crater와 IMP segmentation의 작은 차이는 seed spread보다 작으므로 leader를 과도하게 해석하지 말라고 명시한다.
