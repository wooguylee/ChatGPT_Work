## 1. Edge0/Edge0-35B-A3B-preview

- **Repository:** https://huggingface.co/Edge0/Edge0-35B-A3B-preview
- **개발사/작성자:** Edge0
- **분야:** Text Generation, edge/on-device serving, local OpenAI-compatible inference
- **규모/구조:** 35B-class sparse MoE. 모델 카드 기준 40 layers, hidden size 2048, 256 experts 중 token당 4개 활성. Base는 `Qwen3.6-35B-A3B`이며 4-bit checkpoint + Recover-LoRA + trained prerouter adapter로 구성.
- **라이선스:** Apache-2.0

### 오늘 주목할 근거

조사 시점 Hugging Face Trending 최상단에 노출되어 있으며, HF 검색 snapshot에서 **최근 1일 내 업데이트**, 모델 페이지 기준 **52,519 downloads/month, 약 3.4k likes, Community 11, Spaces 2**를 확인했다. 관련 논문 arXiv `2609.18063`도 최근 공개됐다.

### 기존 모델과 무엇이 다른가

이 모델은 단순히 Qwen 계열을 4-bit로 변환한 파일로만 보기 어렵다. 핵심 변화는 **모델 전체를 RAM/VRAM에 상주시킨다는 전제를 깨고 SSD에서 선택된 expert만 실시간으로 스트리밍**하는 serving 구조다.

1. **SSD expert offload**: 토큰마다 라우팅된 expert weight만 저장장치에서 읽어 active memory를 parameter 전체 크기와 분리한다.
2. **trained prerouter**: 다음 단계에서 필요한 expert를 한 단계 미리 예측해 SSD I/O를 forward pass와 겹친다.
3. **Recover-LoRA**: 4-bit quantization으로 잃은 품질을 FP teacher distillation으로 복구하는 adapter를 함께 제공한다.

따라서 원본 checkpoint의 단순 GGUF/정밀도 변환과 달리, **trained routing prediction + storage-aware serving + distillation adapter를 하나의 inference architecture로 묶은 edge-serving 계열**로 보아 별도 후보로 판단했다.

### 실제 활용과 제약

- 모델 카드의 실측 환경은 **Mac mini M4 Pro 24GB**이며 short-context 기준 약 **14.9–17.7 tok/s**, peak active memory 약 **2.9 GiB**를 보고한다. 이 수치는 **개발사 자체 평가**다.
- 현재 주력 backend는 **Apple Silicon용 MLX**다. 일반 NVIDIA/Windows용 backend는 아직 동일 수준의 공식 경로가 아니다.
- `mlx_lm.server` 또는 Edge0 자체 `edge0 serve`로 **OpenAI-compatible HTTP API**를 열 수 있다.
- Pi, Hermes Agent, OpenClaw 등 OpenAI-compatible endpoint를 받는 Agent 도구에 연결 가능하다.
- 개발사도 현재 Preview의 **tool use·장기 Agent 능력은 약하다**고 명시한다. 즉 현재 강점은 Agent reasoning 자체보다 대형 MoE를 제한된 메모리에서 돌리는 serving 기술이다.
- checkpoint 전체 파일 크기는 HF 페이지 기준 약 19.6GB이며, 긴 context에서는 KV cache가 추가되므로 “3GiB”를 전체 저장공간 요구량으로 오해하면 안 된다.

### 개발사 자체 평가

모델 카드의 OpenCompass 비교에서 int4 Edge0 평균 79.2, FP16 base 평균 83.2를 제시하며, M4 Pro에서의 처리속도·메모리 수치도 개발사가 직접 측정한 결과다. 독립 benchmark로 해석하지 않는다.

## 2. Cactus-Compute/needle3

- **Repository:** https://huggingface.co/Cactus-Compute/needle3
- **개발사/작성자:** Cactus Compute, Inc.
- **분야:** Tool Calling, structured extraction, embedding, on-device/edge Agent
- **규모/구조:** 121M total parameter, 개발사 설명상 arithmetic cost는 약 50M급. `Laddered Simple Attention Network`
- **라이선스:** Apache-2.0

### 오늘 주목할 근거

Cactus 공식 HF 활동에서 **2026-09-19 조사 시점 수시간 내 공개·업데이트**가 확인되며, 모델 페이지 snapshot은 **4,353 downloads/month, 58 likes**다. 작은 모델임에도 모바일·브라우저·WASI·microcontroller를 직접 목표로 하고 있어 실사용 관점의 기술적 가치가 높다.

### 기존 needle/needle2와 중복이 아닌 이유

`introduced-models.md`에는 이미 `Cactus-Compute/needle·needle2`가 존재하므로 원칙적으로 같은 계열은 제외 대상이다. 다만 Needle 3는 개발사가 공개한 구조 기준으로 다음 변화가 커서 **명백한 차세대 architecture 예외**로 판단했다.

- FFN 대신 **Monarch Hadamard MLP**
- causal convolution tap을 결합한 **GQA attention**
- gather 기반 **engram n-gram memory**
- **multi-lane hyper-connections**
- 한 번 학습한 모델에서 **2~20 layer 어느 depth도 배포 가능한 laddered training**
- schema에서 compile한 byte-level grammar로 tool/extraction 출력을 강제하고 learned confidence head를 제공

즉 단순 “Needle 2의 더 큰/더 작은 버전”이 아니라, 모델 내부 연산·메모리·배포 단위를 재구성한 새 세대다.

### 실제 활용과 제약

- 배포 artifact는 depth에 따라 대략 **8–29MB** 수준으로 안내되며, `.cact` runtime과 `safetensors` fine-tuning checkpoint를 제공한다.
- 브라우저/WASI, air-gapped 환경, 모바일, microcontroller까지 배포 경로를 제공한다.
- 같은 모델로 tool calling, structured extraction, sentence embedding을 처리할 수 있어 **로컬 MCP/Agent front-end의 action router**나 개인정보를 외부로 보내기 어려운 앱에 적합하다.
- 범용 chat 모델이 목적이 아니며, 개발사도 일반 대화 능력을 희생하고 tool/extraction에 집중했다고 명시한다.
- HF Inference Provider에는 현재 배포되어 있지 않다.

### 개발사 자체 평가

모바일 tool calling·extraction에서 더 큰 모델과 비교한 성능, fine-tuning 후의 향상 수치는 Cactus가 공개한 **개발사 자체 평가**로 취급한다.

## 3. stable-ai/LimiX-2

- **Repository:** https://huggingface.co/stable-ai/LimiX-2
- **개발사/작성자:** Stable AI
- **분야:** Structured Data / Tabular Foundation Model
- **규모/구조:** 400M parameters, Contextual Mechanism Network(CMN), Context-Conditional Masked Modeling(CCMM)
- **공개일:** 2026-09-16
- **라이선스:** `StableAI LimiX Non-Commercial License` — 상업 사용 전 별도 조건 확인 필요

### 오늘 주목할 근거

2026-09-16 공개된 새 세대 모델이며 조사 시점 HF snapshot은 **348 downloads/month, 41 likes, Community 2, Space 1**이다. LLM·Vision 중심 트렌드와 달리 structured data에서 한 모델이 classification·regression·missing-value imputation을 함께 처리하는 방향이라 기술적 차별성이 크다.

### 기존 방식과 기술적 차이

기존 tabular PFN류가 보통 context dataset `D`에서 특정 target의 `p(y|x,D)`를 예측하도록 설계되는 데 비해, LimiX-2의 CMN은 **`p(x,y|D)` 형태의 context-dependent joint mechanism**을 학습하도록 방향을 바꾼다. Pretraining도 다양한 graph·function·observation process를 가진 **structural causal model(SCM) synthetic data**로 수행하며, CCMM을 사용한다.

이 변화의 핵심은 “표의 한 열을 잘 맞추는 모델”에서 **데이터가 만들어지는 변수 간 구조 자체를 context에서 추론하려는 foundation model**로 목표를 확장했다는 점이다.

### 실제 활용과 제약

- classification, regression, missing-value imputation을 **task별 parameter update 없이** 같은 pretrained model로 처리하도록 설계됐다.
- Hugging Face Transformers loader 예시와 공식 inference CLI를 제공한다.
- 일반 OpenAI-compatible chat API나 llama.cpp/Ollama 계열 모델은 아니다. 전형적인 LLM serving stack보다 Python/PyTorch 기반 tabular inference가 맞다.
- 모델 가중치가 **Non-Commercial License**이므로 기업 서비스 적용 시 특히 주의해야 한다.
- 공식 설치 문서는 PyTorch/flash-attn 환경을 중심으로 하므로 일반 CPU-only PC에서의 효율을 추측해서 보장하면 안 된다.

### 개발사 자체 평가

TabArena, TALENT, BCCO 및 causal skeleton recovery 관련 수치는 공식 기술 보고서·모델 카드의 **개발사 자체 평가**다.

## 4. jinaai/jina-ocr-v1

- **Repository:** https://huggingface.co/jinaai/jina-ocr-v1
- **개발사/작성자:** Jina AI
- **분야:** OCR / Document Intelligence / Image-Text-to-Text
- **규모/구조:** 3B MoE decoder, 약 570M active/token. DeepSeek-OCR backbone + FastMTP speculative decoding
- **라이선스:** CC BY-NC 4.0 — 모델 카드에 commercial use는 별도 문의로 명시

### 오늘 주목할 근거

Jina 공식 HF 모델 목록에서 조사 시점 최근 업데이트가 확인됐고, 현재 모델 페이지 snapshot은 **595 downloads/month, 85 likes, Community 3, Space 1**이다. OCR 정확도뿐 아니라 실제 serving 속도를 architecture 수준에서 다루는 점이 개발자에게 특히 유용하다.

### 기존 모델과 기술적 차이

DeepSeek-OCR의 `DeepEncoder + 3B MoE` backbone을 사용하지만, 그 위에 **FastMTP speculative decoding head**를 추가한다. 하나의 dense draft block을 K=3 prediction step에 재귀적으로 공유하며, verifier와 동일한 greedy 결과를 유지하도록 longest token-equality prefix만 accept한다.

또한 OCR post-training에서 reward-dense/dense verifiable reward를 사용하는 것이 핵심이다. 따라서 단순 OCR fine-tune보다 **문서 인식 + speculative serving을 공동 설계한 OCR 계열**로 판단했다.

### 실제 활용과 제약

- Transformers로 바로 실행할 수 있지만 FastMTP 가속은 제공되지 않는다.
- **vLLM**에서는 custom architecture registration 후 FastMTP를 사용할 수 있다.
- Jina hosted endpoint는 **OpenAI-compatible `/v1/chat/completions`** 형식을 제공한다.
- 문서 OCR, 표/수식 Markdown 변환, RAG ingestion 전처리 등에 적합하다.
- 3B MoE와 BF16 기반 로컬 실행 예시가 CUDA 경로를 전제로 하므로, 일반 저사양 PC에서 빠르게 동작한다고 가정하면 안 된다.
- CC BY-NC 4.0이므로 상업적 자체 호스팅에는 라이선스 확인이 필요하다.

### 개발사 자체 평가

모델 카드에 공개된 OmniDocBench v1.6, olmOCR Bench, 처리량 등의 핵심 수치는 **개발사 자체 평가** 또는 모델 카드 자체 보고값으로 명시한다. 일부 HF evaluation result가 연결되어 있어도 개발사가 제시한 전체 성능 주장을 독립 검증 결과처럼 표현하지 않는다.

## 5. netease-youdao/Confucius4-R2T2

- **Repository:** https://huggingface.co/netease-youdao/Confucius4-R2T2
- **개발사/작성자:** NetEase Youdao
- **분야:** Streaming ASR / Real-time transcription
- **규모/구조:** 2B, BF16, `Qwen3-ASR-1.7B` 기반
- **라이선스:** source code Apache-2.0 / model weights `NetEase Model Use License Agreement`

### 오늘 주목할 근거

최근 Hugging Face Trending에 노출되고 있으며 조사 시점 모델 페이지 snapshot은 **253 downloads/month, 71 likes, Community 1, Space 1**이다. 단순 “빠른 ASR”이 아니라 이미 출력한 문장을 다시 고치지 않는 **append-only true streaming**을 목표로 한다는 점이 실시간 Agent 파이프라인에서 의미가 크다.

### 기존 Confucius4-TTS와 중복이 아닌 이유

`introduced-models.md`에는 `netease-youdao/Confucius4-TTS`가 이미 있지만, R2T2는 **TTS가 아니라 ASR**이며 Qwen3-ASR-1.7B를 기반으로 한다. 입력/출력 modality와 근본 목적이 반대 방향이므로 이름만 같은 Confucius4 브랜드이지 동일 모델 계열로 보지 않았다.

R2T2의 핵심은 stable-prefix data, forced time-alignment, token-level audio segmentation과 **Longest Stable Prefix(LSP) learning**을 결합해 “지금 확정해서 내보내도 되는 prefix”를 학습하는 방식이다. 80ms~2s 범위의 configurable chunk를 처리하면서 이전 transcript를 rewrite하지 않는 것이 구조적 목표다.

### 실제 활용과 제약

- **vLLM backend**, Transformers, 공식 Qwen3-ASR Docker image 기반 실행 경로가 제공된다.
- WebSocket 기반 streaming service를 구성하기 쉬워 live caption, 회의 자막, 통화 transcription, 음성 Agent의 upstream ASR에 적합하다.
- 개발사 설명상 중국어/영어 중심 최적화이며 다국어 streaming도 지원한다고 하나, 각 언어의 실제 품질은 별도 검증이 필요하다.
- 모델 가중치는 Apache-2.0이 아니며 **NetEase Model Use License Agreement**가 적용된다. 상업 서비스 전 약관 검토가 필요하다.
- HF Inference Provider에는 현재 배포되어 있지 않다.

### 개발사 자체 평가

평균 latency 200~600ms, offline 수준에 근접한 accuracy 및 언어별 WER/CER 비교는 현재 모델 카드가 제시한 **개발사 자체 평가**다.

## 중복/제외 검증 메모

- `openbmb/MiniCPM5-2B`: 이미 `MiniCPM5-1B` 계열이 index에 있으며 단순 규모 변형에 해당하므로 제외.
- `prism-ml/Ternary-Bonsai-2-27B-gguf`: 현재 Trending 신호는 매우 강하지만 기존 index에 Bonsai 계열이 있고, 공개 자료상 Qwen 계열의 ternary compression/serving 변형 성격이 강해 이번 규칙에서는 새 모델로 재소개하지 않음.
- `TaoLiveAIGC/TaoMate-H3`: MiniMax-H3 기반 LoRA/direct derivative이므로 제외.
- `Viggle/Viggle-Animate`: MiniMax-H3 기반 full fine-tune + distillation으로 용도 변화는 크지만 직접 checkpoint derivative라는 엄격한 중복 규칙 때문에 이번 선정에서는 제외.
- `m-a-p/SheetSage2`: 음악 score transcription 실용성은 높지만 현재 공개 정보상 MERT-v2 adapter lineage이고 기술 보고서가 아직 충분히 공개되지 않아, 엄격한 신규 계열 판정을 보류.
- `DeepSeek-V4.1-Flash`, `YuE2`, `AuK`, `Xing4.0`, `Agnes-3.0-Flash`, `Taichu5.0` 등은 이미 `introduced-models.md`에 기록되어 제외.
