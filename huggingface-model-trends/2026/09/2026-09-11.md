## 1. deepseek-ai/DeepSeek-V4.1-Flash

- Hugging Face: https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash
- 개발사: **DeepSeek**
- 분야: **Image-Text-to-Text / Text LLM / Agent / Coding / Multimodal**
- 라이선스: **MIT**
- 규모: Hugging Face metadata 기준 **763B params**. 기술 보고서는 **552B backbone**, prefill 시 **8B active**, decode 시 **16B active**라고 설명한다.
- Context: **최대 1M tokens**

### 오늘 주목할 근거

DeepSeek가 **2026-09-10** 공식 출시했다. 2026-09-11 조사 시점 Hugging Face Trending 목록의 최상단에 있었고, 모델 페이지 snapshot은 약 **75,774 downloads/month**, **1.78K likes**, **Community 39**, **Spaces 6**이다.

기존 `DeepSeek-V4` 및 `DeepSeek-V4-Flash-Vision-Exp` 계열은 중복 인덱스에 이미 있지만, 이번 V4.1은 단순 버전명 변경이 아니다. 공식 자료가 새 architecture family라고 명시하며 V4-Flash/V4-Flash-Vision-Exp를 대체하는 후속 세대로 소개하므로 별도 모델로 판정했다.

### 기존 모델과의 기술적 차이

핵심은 **Causal Encoder-Decoder(CED)** 구조다. 40-layer Transformer를 20-layer causal encoder + 20-layer decoder로 나누고, decoder의 global KV cache를 각 decoder layer 내부 상태에서 따로 만들지 않고 encoder 최종 hidden state에서 투영한다. 입력이 긴 Agent workload에서 prefill 활성 파라미터를 8B로 낮추고 decode는 16B로 운용하는 비대칭 구조다.

또한 **CSA2(Compressed Sparse Attention 2)**로 Full/Reindex/Reuse 세 가지 고정 attention mode를 배치하고, layer 간 main KV·indexer K와 sparse index를 재사용한다. **FP4 main KV caching**과 결합해 공식 설명 기준 global KV cache를 **890 bytes/token**까지 줄였고, 이전 V4-Flash 대비 HBM KV footprint는 약 1/4, SSD persistent cache는 약 1/8 수준을 목표로 한다.

그 밖에 Single-Pass mHC, 196B Engram conditional memory, DSpark speculative decoding, 자체 DeepSeek-ViT + projector를 이용한 native image/text 공동처리가 포함된다. 즉 기존 V4의 단순 parameter·serving variation이 아니라 장기 context/agent 비용을 줄이기 위한 핵심 attention·cache·encoder/decoder 구조가 변경되었다.

### 실제 활용 가능성과 제약

- **vLLM** 및 **SGLang**에서 직접 serving 예제가 제공되며 둘 다 OpenAI-compatible HTTP API로 노출 가능하다.
- Hugging Face는 quantization 탐색 링크를 제공하고 llama.cpp/Ollama/LM Studio 호환 변형을 안내하지만, 원본 모델 자체가 매우 크므로 일반 PC에서 원본 전체를 로컬로 돌리는 모델은 아니다.
- DeepSeek 공식 페이지는 대규모 self-hosting을 위해 다수 GPU와 storage cluster가 필요한 배포를 별도로 언급한다.
- tool calling, multi-turn, thinking mode, numeric reasoning effort, image interleave를 처리하는 별도 `encoding` reference와 `deepseek-recipe`를 제공한다.
- Agent 관점에서는 긴 repository/context를 반복 참조하는 coding·tool workload에서 KV cache 절감이 직접적인 운영비·메모리 이점으로 이어질 수 있다.

### Benchmark 주의

모델 카드의 GPQA, Terminal-Bench, DeepSWE, CyberGym, AutomationBench 등의 수치는 **개발사 자체 평가**다. 예를 들어 DeepSWE v1.1 74.2, Terminal-Bench 2.1 90.6 등의 수치가 공개되어 있지만 독립 검증 결과로 취급하지 않는다.

## 2. m-a-p/YuE2-3B

- Hugging Face: https://huggingface.co/m-a-p/YuE2-3B
- 개발사/작성자: **Multimodal Art Projection (m-a-p)**
- 분야: **Text-to-Audio / Music Generation / Cover / Agentic Music Editing**
- 규모: 공식 프로젝트 설명 기준 약 **3.59B parameters, 28 layers**. Hugging Face metadata는 반올림해 약 **4B params**로 표시한다.
- 라이선스: **CC BY-NC 4.0** — 상업 이용 제한이 중요한 제약이다.

### 오늘 주목할 근거

2026-09-11 조사 시점 Hugging Face Trending 첫 페이지에 노출됐고 약 **226 likes**, **971 downloads/month**, **Community 6**이었다. Trending snapshot에서는 약 **6시간 내 업데이트** 상태였다. 프로젝트 공식 페이지는 2026년 9월 연구·데모 릴리스로 YuE2를 공개하고 있다.

`introduced-models.md` 및 저장소 검색에서 YuE2 계열의 기존 소개 기록은 확인되지 않았다.

### 기존 방식과의 기술적 차이

일반적인 text-to-music 모델처럼 바로 acoustic token만 생성하는 대신 먼저 **편집 가능한 symbolic score**를 만든다. melody/chord를 ABC 형태의 계획으로 만든 뒤 semantic music token과 acoustic latent를 생성하고, 마지막에 VAE가 **48 kHz stereo audio**로 복원한다.

backbone은 하나의 **AR–NAR Mixture-of-Transformers** 구조로, AR/NAR expert가 attention 계산은 공유하면서 normalization·projection·MLP는 분리한다. 이후 acoustic latent 생성에 **flow matching**을 사용한다. 이 구조의 실질적인 장점은 생성 결과를 단순 waveform으로만 끝내지 않고, 중간 score를 사람이 직접 수정하거나 Agent가 음악적 피드백을 score/style/lyrics 수정으로 변환해 반복 편집할 수 있다는 점이다.

### 실제 활용 가능성과 제약

- 공식 quick start 기준 **Linux, Python 3.10+, 24GB NVIDIA GPU, BF16** 환경에서 로컬 실행 가능하다.
- 별도 `yue2_infer` package와 `YuE2Pipeline`을 사용한다.
- `cot=full`은 melody+chord planning, `cot=melody`는 melody-only planning, `cot=off`는 symbolic plan 없이 생성한다.
- cover workflow는 외부 score transcription이나 lyric transcription 도구와 결합할 수 있고, Agent가 ABC score와 lyrics를 수정하는 반복 편집 workflow가 가능하다.
- 표준 vLLM/SGLang/llama.cpp serving 모델은 아니며 Hugging Face Inference Provider 배포도 조사 시점에는 확인되지 않았다.
- **CC BY-NC 4.0**이라 상업 서비스에 바로 넣는 용도에는 적합하지 않다.

### Benchmark 주의

WildSongBench/SongBench에서 YuE2 best-of-8이 높은 점수를 기록했다는 수치는 **개발사 자체 평가**다. Suno 등 proprietary system과의 비교 역시 동일한 자체 평가 framework 결과이므로 독립 검증처럼 해석하지 않는다.

- 공식 프로젝트/데모: https://map-yue2.github.io/

## 3. tencent/AuK

- Hugging Face: https://huggingface.co/tencent/AuK
- 개발사: **Tencent / Tencent Hunyuan 연구진**
- 분야: **Speech Generation / TTS / Audio Editing / Enhancement / Separation**
- 규모: **1.5B foundation model**
- 라이선스: **MIT**

### 오늘 주목할 근거

공식 모델 카드에 **2026-09-09 open-source 공개**가 명시되어 있고, 관련 기술 보고서는 2026-09-08 공개됐다. 2026-09-11 조사 시점 Hugging Face snapshot은 약 **100 likes**, **554 downloads/month**, **Community 2**, **Spaces 3**이며 Trending 두 번째 페이지 상위권에 노출됐다.

`introduced-models.md` 및 저장소 검색에서 `tencent/AuK` 계열의 기존 소개 기록은 확인되지 않았다.

### 기존 방식과의 기술적 차이

AuK의 가장 큰 특징은 TTS, speech editing, enhancement, separation을 별도 모델로 쪼개지 않고 **자연어 instruction + audio context**라는 하나의 인터페이스로 통합한 것이다.

기술 보고서에 따르면 semantic conditioning에는 **multimodal LLM**, acoustic conditioning에는 speech/general audio/music를 함께 학습한 **joint VAE**를 사용한다. 생성 backbone은 **hybrid rectified-flow Transformer**로, 먼저 dual-stream MMDiT block을 거친 뒤 unified single-stream DiT block으로 합쳐 생성한다.

학습은 generation-only warm-up → generation/editing joint pretraining 순으로 진행하고, open-ended editing에는 human-feedback preference optimization, speech generation에는 reward-based RL을 적용한다. 별도 AuK-Flash는 consistency initialization + task-routed Decoupled DMD로 4-step inference를 지원한다.

### 실제 활용 가능성과 제약

- zero-shot TTS, instruction TTS, speech content edit, lyric edit, pitch/speed/volume edit, emotion/timbre/de-accent/nonverbal edit, whisper conversion, enhancement, speech/music separation, target speaker extraction을 같은 instruction interface에서 다룬다.
- 공식 배포는 AuK checkpoint만으로 끝나지 않고 runtime에서 **Qwen2.5-Omni-3B MLLM encoder**와 별도 **VAE**를 함께 로드하도록 안내한다. 따라서 1.5B라는 숫자만 보고 전체 runtime footprint를 판단하면 안 된다.
- **SGLang-Omni Day-0 support**가 제공되며 `sglang_omni.cli serve --model-path tencent/AuK` 형태로 serving 가능하다.
- GitHub에 CLI/Python cookbook, Gradio, ComfyUI, fine-tuning 자료가 제공된다.
- 조사 시점 Hugging Face Inference Provider에는 직접 배포되어 있지 않았다.
- 공식 카드에는 최소 VRAM 수치가 고정값으로 제시되지 않아 임의 추정하지 않았다.

### Benchmark 주의

기술 보고서가 zero-shot/instruction-controlled speech generation과 instruction-guided editing에서 leading performance를 주장하지만 이는 **개발사 자체 평가**다. 독립 benchmark 검증 결과와 동일하게 취급하지 않는다.

## 🏆 오늘의 Top Pick

### deepseek-ai/DeepSeek-V4.1-Flash

오늘 후보 중 가장 큰 변화는 단순 benchmark 상승보다 **장기-context Agent의 KV cache 구조 자체를 재설계했다는 점**이다. CED + CSA2 + FP4 KV cache로 입력이 큰 Agent/Coding workload의 memory·storage·throughput 병목을 직접 겨냥했고, native multimodal과 1M context, vLLM/SGLang/OpenAI-compatible serving까지 실무 연결성이 가장 높다.

다만 원본 크기는 일반 PC용이 아니며, benchmark는 개발사 자체 평가라는 점을 분리해서 봐야 한다.
