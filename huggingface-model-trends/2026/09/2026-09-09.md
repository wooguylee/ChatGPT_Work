## 1. TokenRhythm/NeoHorse-1-4B

- Hugging Face: https://huggingface.co/TokenRhythm/NeoHorse-1-4B
- 개발사/작성자: TokenRhythm / NeoHorse Team
- 분야/규모: Agent, Coding, reasoning, tool-use용 causal LLM, 약 4B parameters
- 기반 모델: `Qwen/Qwen3.5-4B`
- 라이선스: Apache-2.0
- context length: 모델 카드 기준 native 262,144 tokens, 최대 1,010,000까지 확장 가능하다고 명시

### 오늘 주목할 근거
Hugging Face Trending 목록 조사 시점에 약 1.77k downloads/month, 217 likes를 기록했고 약 11시간 내 업데이트가 확인됐다. 4B급에서 vLLM/SGLang, tool-call parser, reasoning parser를 공식 사용 예제로 제공해 Agent 개발자가 바로 self-host하기 쉬운 점도 강하다.

### 기존 모델과의 기술적 차이
이 모델은 Qwen3.5-4B를 기반으로 하므로 단순 fine-tune이라면 신규 계열에서 제외해야 한다. 그러나 공식 모델 카드와 기술 보고서는 학습의 핵심을 **routing-guided agentic post-training**으로 설명한다. heterogeneous model pool이 작업을 라우팅하고 tool interaction·결과·capability demand를 기록한 뒤, 이 피드백을 다음 training mixture에 반영하는 harness를 사용한다. 또한 routing-guided curriculum SFT와 routing-guided on-policy distillation을 결합한다.

따라서 본 보고서에서는 단순 명칭 변경이나 경미한 SFT가 아니라, 학습 방법과 Agent/tool execution 구조가 핵심적으로 바뀐 예외 사례로 별도 계열로 판정한다. 다만 base architecture 자체는 Qwen3.5-4B 계열을 유지한다.

### 실제 활용 가능성과 제약
공식 카드가 vLLM과 SGLang 서버 예제를 제공하며 둘 다 OpenAI-compatible `/v1/chat/completions` 인터페이스로 사용할 수 있다. Hugging Face에는 quantization 항목도 연결되어 있어 llama.cpp/Ollama/LM Studio 계열로 전환 가능한 배포 경로가 존재한다. 4B급이라 대형 MoE보다 로컬 배포 현실성이 높지만, 262K 이상의 긴 context는 KV cache 때문에 GPU 메모리 요구가 크게 증가할 수 있다.

### benchmark 주의
모델 카드의 10개 benchmark 평균 64.87 및 Qwen3.5-4B 대비 +5.93 등은 **개발사 자체 평가**다. 공식 카드에 평가 protocol과 SGLang 버전, sampling 조건이 공개되어 있으나 독립 검증 결과로 보아서는 안 된다.

주요 1차 출처:
- HF: https://huggingface.co/TokenRhythm/NeoHorse-1-4B
- 공식 기술 보고서 저장소: https://github.com/TokenRhythm/NeoHorse

## 2. ampixa/sanoTTS

- Hugging Face: https://huggingface.co/ampixa/sanoTTS
- 개발사/작성자: Ampixa Labs
- 분야/규모: 초소형 neural TTS, 계열 전체 약 294k~2.27M parameters
- 언어: English, Nepali, Hindi, Vietnamese, Indonesian, Chinese
- 라이선스: GPL-3.0

### 오늘 주목할 근거
조사 시점 HF 모델 페이지에서 약 4.16k downloads/month, 32 likes를 기록했고 Trending 페이지에서 약 3시간 내 업데이트로 확인됐다. 절대 규모보다 중요한 점은 브라우저 WASM뿐 아니라 약 $3 수준 ESP32-S3에서 real-time neural TTS를 목표로 한다는 것이다.

### 기존 방식과의 기술적 차이
일반적인 오픈 TTS가 수십M~수B parameter와 GPU/CPU inference를 전제로 하는 반면 sanoTTS는 distillation을 극단적으로 밀어 작은 runtime graph를 만든다. `piperlite` 계열은 Piper/VITS teacher를, `nano` 계열은 Kokoro teacher를 사용하며, nano 계열은 `mel-100 → ConvNeXt1D → iSTFT` 구조와 INT8 배포를 사용한다. G2P는 espeak-ng를 포함하며 browser와 microcontroller까지 동일 프로젝트에서 배포하는 것이 특징이다.

### 실제 활용 가능성과 제약
Python package는 pure NumPy inference를 지원하며 PyTorch/ONNX Runtime 없이 사용할 수 있다고 모델 카드가 명시한다. `sanotts-web`은 WASM, Arduino/PlatformIO 경로도 제공한다. MCU·브라우저·오프라인 device에 특히 유리하다. 반면 최고 음질의 대형 TTS를 대체하는 모델은 아니며, GPL-3.0이므로 제품에 통합할 때 소스 공개 의무 등 라이선스 조건을 반드시 검토해야 한다.

### benchmark 주의
SCOREQ/UTMOS/DNSMOS 비교와 ESP32 성능 수치는 프로젝트가 자체 재현 자료와 스크립트를 공개했지만 **개발사 자체 평가**다. 독립 benchmark로 표현하지 않는다.

주요 1차 출처:
- HF: https://huggingface.co/ampixa/sanoTTS
- 공식 GitHub: https://github.com/Ampixa/sanoTTS

## 3. rumik-ai/rumik-oss-1

- Hugging Face: https://huggingface.co/rumik-ai/rumik-oss-1
- 개발사/작성자: Rumik Intelligence Private Limited
- 분야/규모: multilingual TTS, 3B parameters
- 출력: 24 kHz audio
- 지원: 22개 Indic language 계열 + English, native script/romanized 및 code-switching
- 라이선스: CC-BY-NC-4.0 계열 + acceptable-use addendum, 상업적 사용 불가

### 오늘 주목할 근거
신규 공개 직후 HF Trending 하위권에 진입했고 조사 시점 32 likes, 약 10시간 내 업데이트가 확인됐다. downloads/month는 아직 12로 적지만 이는 공개 직후 snapshot으로 보인다. 신규성, 22개 언어 지원, code-switching과 감정/속도/억양 제어를 한 모델에 묶었다는 점을 기술적 가치로 높게 평가했다.

### 기존 방식과의 기술적 차이
Tiny Aya Fire를 확장하고 Mimi codec의 discrete speech token을 사용한다. text conditioning과 audio generation을 하나의 autoregressive sequence로 합치며, 각 audio frame마다 8개 codebook token을 순차 예측한 뒤 Mimi decoder가 waveform을 복원한다. `<description="...">` prefix로 tone/accent/pace를 제어하고 `<laugh>`, `<chuckle>`, `<sigh>` 같은 inline vocalization token을 직접 제어한다.

### 실제 활용 가능성과 제약
공식 inference는 Transformers + Mimi decoder이며 NVIDIA CUDA GPU를 요구한다. 선택적으로 FastAPI server도 제공한다. 3B라 edge CPU용은 아니며, 모델 카드가 30초 이하 training utterance를 기반으로 해 35초를 넘는 long-form 생성을 권장하지 않는다. 가장 큰 실무 제약은 라이선스다. 연구·비상업적 사용은 가능하지만 유료 서비스나 상업 제품 self-host에는 별도 허가가 필요하다.

### benchmark 주의
IndicEmo, NoVA, WER/CER 결과는 프로젝트가 자체 benchmark와 평가 pipeline을 공개했지만 **개발사 자체 평가**다. 특히 자동 judge와 별도 ASR verifier를 사용하므로 독립 human evaluation과 동일하게 해석하면 안 된다.

주요 1차 출처:
- HF: https://huggingface.co/rumik-ai/rumik-oss-1

## 4. perplexity-ai/pplx-pii-masking

- Hugging Face: https://huggingface.co/perplexity-ai/pplx-pii-masking
- 개발사/작성자: Perplexity
- 분야/규모: Privacy / PII masking / Token Classification, 약 600M parameters
- 기반: `perplexity-ai/pplx-embed-v1-0.6b`의 bidirectional Qwen3 encoder
- 라이선스: MIT
- 최대 입력: model card 기준 4096 tokens

### 오늘 주목할 근거
조사 시점 약 1.1k downloads/month와 56 likes, 최근 6일 내 업데이트가 확인됐다. 범용 생성 모델이 아니라 실제 운영 로그·대화 데이터의 개인정보 비식별화에 바로 연결되는 모델이라는 점에서 실무 가치가 높다.

### 기존 방식과의 기술적 차이
단순 NER head 하나가 아니라 두 출력을 동시에 둔다. 첫 번째 head는 9개 PII category를 37개 BIOES tag로 분류하고 constrained Viterbi로 span을 디코딩한다. 두 번째 sensitivity head는 mean-pooled hidden state에서 conversation-level 민감도를 별도로 추정한다. 즉 token-level masking과 document-level sensitivity 판단을 하나의 encoder에서 함께 처리한다.

### 실제 활용 가능성과 제약
PyTorch/Transformers에서 `trust_remote_code=True`로 직접 사용할 수 있고 `predict`/`mask` helper를 제공한다. MIT라 상업 활용 제약이 적다. Inference Provider 배포는 조사 시점 제공되지 않았다. 4096 token을 넘는 문서는 직접 chunking해야 하며, 모델 카드가 CPU latency나 운영 throughput을 보장하지는 않는다.

주요 1차 출처:
- HF: https://huggingface.co/perplexity-ai/pplx-pii-masking

## 5. Hcompany/NeoMME-800M

- Hugging Face: https://huggingface.co/Hcompany/NeoMME-800M
- 개발사/작성자: H company / Aurélien Lac, Tony Wu
- 분야/규모: Multimodal-native multilingual encoder, 800M parameters
- context length: 16,384 tokens
- image input: raw image patches, 기본 longest side 최대 2,048px
- 라이선스: Apache-2.0

### 오늘 주목할 근거
최근 arXiv `2609.01657` 공개와 함께 NeoMME collection이 최근 며칠간 업데이트됐고, 조사 시점 106 downloads/month가 확인됐다. LLM 생성 경쟁과 다른 축에서 multimodal encoder/RAG/document understanding을 노리는 신생 모델이라는 점을 선정 이유로 삼았다.

### 기존 방식과의 기술적 차이
가장 중요한 차이는 **별도 vision encoder를 두지 않는 single-tower 구조**다. text token과 raw image patch가 동일한 Transformer encoder를 통과한다. causal LLM을 붙인 VLM이 아니라 encoder backbone이며, masked discrete-diffusion objective로 text token 복원을 학습한다. 문서 이미지 학습에서는 image patch를 visible 상태로 두고 pixel reconstruction loss를 사용하지 않는다.

이 설계는 RAG/문서 검색에서 text와 scanned document image를 별도 tower로 처리하고 alignment하는 전통적인 dual-encoder/vision-language pipeline과 다른 선택이다.

### 실제 활용 가능성과 제약
Transformers `AutoModel`/`AutoProcessor`로 feature extraction이 가능하고 800M 규모라 대형 VLM보다 상대적으로 가볍다. 그러나 base checkpoint 자체는 retrieval 결과를 바로 내는 완제품이 아니라 downstream head fine-tuning이 필요한 encoder backbone이다. 문서 검색에는 별도 `NeoMME-800M-Retriever` 사용을 모델 카드가 권장한다. Inference Provider는 조사 시점 제공되지 않았다.

주요 1차 출처:
- HF: https://huggingface.co/Hcompany/NeoMME-800M
- arXiv: https://arxiv.org/abs/2609.01657
