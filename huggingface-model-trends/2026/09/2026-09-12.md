## 1. Agnes-AI/Agnes-3.0-Flash

- Hugging Face: https://huggingface.co/Agnes-AI/Agnes-3.0-Flash
- 개발사: **Agnes AI**
- 분야: Multimodal LLM, reasoning, coding, tool use, Agent
- 규모: **33B**
- context: 공개 weight인 **Agnes 3.0 Flash Preview 기준 262,144 tokens**
- 라이선스: **Apache-2.0**

### 오늘 주목할 근거

조사 시점 Hugging Face 전체 Trending의 앞쪽 페이지에 위치했고, 약 **10시간 내 업데이트**, 최근 월 다운로드 **34회**, 좋아요 **116개**, Community **5개**로 표시됐다. 다운로드 절대치는 공개 직후라 작지만 좋아요와 Trending 진입 속도는 초기 관심이 빠르게 형성되고 있음을 보여주는 snapshot이다.

공식 카드가 중요한 구분도 명시한다. 이 repository의 open weight는 **Agnes 3.0 Flash Preview**이며, 현재 API에서 제공하는 production Agnes 3.0 Flash는 별도 checkpoint다. 따라서 production API의 1M context나 production benchmark를 이 공개 checkpoint에 그대로 귀속하지 않는다.

### 기존 방식과의 기술적 차이

Agnes 3.0 Flash Preview는 일반적인 모든-layer full attention decoder 대신 **hybrid-attention decoder**를 사용한다.

- 총 72개 transformer layer 중 **54개는 delta-rule recurrent layer**, **18개는 global attention layer**로 3:1 비율 구성
- global layer에만 sequence 길이에 비례하는 KV cache가 증가하므로 모든 layer가 full attention인 구조보다 장문 serving 메모리를 줄이는 방향
- recurrent layer에 causal convolution, gated RMSNorm, FP32 recurrent state를 사용
- global attention은 GQA를 사용
- parallel SwiGLU branch와 3-axis rotary position 표현을 사용
- 별도 vision tower(27 layers, hidden 1152)를 5120 차원으로 projection해 image/video 입력을 처리

즉 긴 context 효율을 위해 recurrent/linear 계열 연산을 섞으면서도 필요한 지점에서는 global attention을 유지하고, 그 위에 vision·reasoning·tool use를 통합한 구조다. reasoning은 high/medium/low와 thinking-off 같은 수준 제어를 지원한다.

### 실제 활용 가능성과 제약

공식 카드와 Hugging Face integration은 Transformers뿐 아니라 vLLM/SGLang 기반 serving 경로를 제시하고 OpenAI client 예시를 제공한다. 다만 custom implementation 때문에 `trust_remote_code=True`가 필요하며, SGLang은 카드가 지정한 nightly/patch 조합을 요구하는 경로가 있어 production 투입 전 버전 고정과 재현 테스트가 필요하다.

공식 BF16 하드웨어 예시는 **1× H200 141GB 또는 1× H100 80GB급**이며 약 **66GB weight storage**, **128GB 이상 host RAM**을 제시한다. 따라서 원본 BF16은 일반 PC용 모델로 보기 어렵다. Hugging Face에는 별도 quantization 경로가 있으므로 llama.cpp/Ollama/LM Studio 계열 로컬 사용은 양자화 파생본의 실제 호환성과 품질을 개별 확인해야 한다.

Agent 관점에서는 vision을 화면 상태 확인에 쓰고 tool calling과 reasoning 수준 제어를 함께 사용할 수 있어 브라우저/컴퓨터 조작, coding agent, 멀티모달 workflow backend 후보로 의미가 있다.

### benchmark 주의

공식 카드의 비교표는 서로 다른 source/harness의 수치를 함께 제시하며 controlled head-to-head가 아니라고 명시한다. 따라서 Agnes 관련 성능 수치는 이 보고서에서 **개발사 자체 평가 또는 개발사 제공 참고 평가**로 취급하며 독립 검증 결과처럼 표현하지 않는다.

### 주요 1차 출처

- HF 모델 카드: https://huggingface.co/Agnes-AI/Agnes-3.0-Flash
- 개발사 사이트: https://agnes-ai.com/

## 2. ai-sage/GigaChat3.5-432B-A28B-Reasoning

- Hugging Face: https://huggingface.co/ai-sage/GigaChat3.5-432B-A28B-Reasoning
- 개발사/작성자: **ai-sage / GigaChat 계열**
- 분야: Reasoning LLM, coding, structured output, Agent/tool use
- 규모: 공식 카드 **432B total / 28B active**; Hugging Face metadata는 약 438B로 표시될 수 있음
- context: **262K**
- 라이선스: **MIT**

### 오늘 주목할 근거

조사 시점 Hugging Face Trending 상위 수 페이지 안에 있었고 **약 3일 내 업데이트**, 최근 월 다운로드 **235회**, 좋아요 **31개**, Community **1개** 수준으로 표시됐다. 절대 사용량보다 신규 reasoning checkpoint와 독특한 post-training recipe 때문에 기술적으로 주목할 가치가 높다.

### 기존 모델과의 기술적 차이

공식 카드는 이 모델을 **full reasoning을 도입한 첫 GigaChat 모델**로 설명한다. 핵심은 하나의 reward로 전체 능력을 동시에 RL하는 대신 다음처럼 분리한 뒤 다시 합치는 학습법이다.

1. SFT checkpoint에서 시작
2. STEM, Code, Code Agent, General Agent, Dialogue, Soft Skills의 **6개 domain expert**를 각각 online RL로 학습
3. 각 domain에 맞는 reward와 curriculum을 사용하고, 이미 75% 이상 해결되는 쉬운 task를 점차 제거
4. 마지막에는 **on-policy distillation(OPD)** 으로 6개 expert의 행동을 하나의 release model에 합침
5. student가 자기 trajectory를 생성하고 expert가 token-level supervision을 주는 방식으로 domain 능력을 병합

architecture도 단순 dense decoder와 다르다. 공식 카드는 **Multi-head Latent Attention(MLA) + GatedDeltaNet linear attention** 하이브리드, GatedNorm, 그리고 **3개 MTP heads**를 사용한다고 설명한다. 즉 long-context 효율과 speculative decoding을 고려한 architecture와 domain-specialized online RL을 함께 적용한 것이 핵심 차이다.

### 실제 활용 가능성과 제약

공식 serving 예시는 SGLang과 vLLM 모두 **8× H100** 수준을 사용한다. tensor/expert parallel과 reasoning/tool parser, MTP 기반 speculative decoding 설정을 함께 제시하며 OpenAI-compatible `/v1/chat/completions` 형태로 호출할 수 있다.

다만 현재 공식 예시는 upstream stable release가 아니라 특정 SGLang/vLLM PR을 요구하는 경로가 포함되어 있어 배포 환경 고정이 필요하다. 432B total weight이므로 일반 PC나 단일 소비자 GPU에서 원본을 운영하는 모델은 아니다. 이 모델은 개인 로컬 LLM보다 대형 Agent backend, 코드/도구 실행 서버, 연구용 multi-GPU cluster에 더 적합하다.

모델 repository는 FP8 inference weight를 제공하고, fine-tuning/자체 quantization을 위한 BF16 weight를 별도 안내한다. llama.cpp/Ollama/LM Studio의 공식 turnkey 지원은 모델 카드에서 확인하지 못했으므로 지원된다고 가정하지 않는다.

### benchmark 주의

공식 카드의 benchmark와 reasoning token 감소 등 성능 주장은 **개발사 자체 평가**다. 일부 비교 대상과 judge/harness 조건이 함께 제시되지만 독립 재현으로 보지 않는다.

### 주요 1차 출처

- HF 모델 카드: https://huggingface.co/ai-sage/GigaChat3.5-432B-A28B-Reasoning

## 3. yandex/AliceAI-T5-35B-A0.6B

- Hugging Face: https://huggingface.co/yandex/AliceAI-T5-35B-A0.6B
- 개발사: **Yandex**
- 분야: Text-to-Text LLM, encoder-decoder, sparse MoE, base model
- 규모: Hugging Face 약 **35B**, 공식 카드 **34.35B unique parameters**
- context: **128K**
- 라이선스: 조사 시점 모델 카드/metadata에서 명시를 확인하지 못했으므로 **추정하지 않음**

### 오늘 주목할 근거

조사 시점 Hugging Face Trending 상위 수 페이지 안에 위치했고 **약 1일 내 업데이트**, 최근 월 다운로드 **118회**, 좋아요 **약 60개**로 표시됐다. 공개 초기 단계지만 최근 대형 공개 모델의 대부분이 decoder-only인 상황에서 대형 encoder-decoder sparse-MoE라는 구조 자체가 차별적이다.

### 기존 방식과의 기술적 차이

공식 카드는 AliceAI-T5를 encoder-decoder 기반 sparse MoE로 설명한다.

- **34.35B unique parameters**
- MoE layer마다 **512 experts**, token당 **top-8 experts** routing
- encoder **16 layers / 12 attention heads**
- decoder **12 layers / 12 query heads / 4 KV heads**
- expert intermediate size 512
- SiLU, RMSNorm
- RoPE + YaRN으로 **128K context**
- input/output embedding과 LM head 공유

이는 일반적인 decoder-only autoregressive chat model보다 입력 encoding과 출력 decoding을 명시적으로 분리한 T5 계열 구조다. 문서 변환, 요약·추출, 조건부 text-to-text task처럼 입력 전체를 먼저 읽고 출력하는 작업에서 연구 가치가 있다. 동시에 512-expert MoE로 총 parameter 수를 늘리면서 token별 계산은 일부 expert로 제한한다.

모델명에 `A0.6B`가 포함되어 있지만 카드에서 active parameter 수를 명시적으로 확인한 근거 없이 그 숫자를 active parameter라고 단정하지 않는다.

### 실제 활용 가능성과 제약

공식 예시는 Transformers의 `AutoModelForSeq2SeqLM`과 `trust_remote_code=True`, BF16을 사용하며 필요 시 `flash_attention_2`를 적용한다. LoRA fine-tuning 예시도 제공한다.

반면 조사 시점 카드에서는 vLLM 또는 SGLang의 공식 serving recipe를 확인하지 못했다. OpenAI-compatible API, llama.cpp, Ollama, LM Studio 호환도 공식 자료에서 확인되지 않았으므로 지원한다고 가정하지 않는다. 약 35B의 원본 BF16이 일반 PC에서 편하게 동작한다고 보기 어렵지만, 카드가 소비자 GPU 기준 VRAM 요구량을 명시하지 않으므로 임의 숫자는 쓰지 않는다.

라이선스가 명확히 표시되지 않은 상태이므로 상업 서비스에 사용하려면 repository의 최신 license/terms를 별도로 확인해야 한다.

### benchmark 주의

공식 카드가 benchmark 계산을 내부 infrastructure에서 수행했다고 명시하므로 해당 수치는 **개발사 자체 평가**다.

## 4. CohereLabs/North-Small-Translate-1.0

- Hugging Face: https://huggingface.co/CohereLabs/North-Small-Translate-1.0
- 개발사: **Cohere Labs**
- 분야: Machine Translation, multilingual text generation
- 규모: **218B total / 25B active**
- context: **16K input + 16K output**
- 언어: 공식 카드는 **50개 언어** 번역을 설명하며, 조사 시점 HF metadata는 49개 language tag를 표시함
- 라이선스: **CC BY-NC 4.0 + Cohere Labs Acceptable Use Policy**

### 오늘 주목할 근거

조사 시점 Hugging Face Trending 상위 수 페이지 내에 있었고 **약 2일 내 업데이트**, 최근 월 다운로드 **78회**, 좋아요 **38개**, Community **2개**로 표시됐다. 범용 chat model이 아니라 번역 자체에 대형 sparse MoE를 전용 post-training한 점이 기술적으로 뚜렷하다.

### 기존 모델과의 기술적 차이

공식 카드 기준 North Small Translate는 decoder-only sparse MoE이며 다음 구성을 사용한다.

- 총 **128 experts** 중 token마다 **8 experts** 활성
- 별도의 **shared experts** 포함
- attention은 **4096-token sliding-window attention**과 **global non-positional attention**을 **3:1** 비율로 교대
- sigmoid router의 top-k expert score를 정규화해 routing
- 번역 task를 위해 별도 post-training

`introduced-models.md`에는 과거 `CohereLabs/North-Micro-Vision-Instruct`가 존재하지만, 이번 모델은 vision instruction variant의 단순 크기 변경이 아니라 218B/25B sparse-MoE 번역 전용 architecture/목적의 별도 공개다. 따라서 이름의 `North`만 같다는 이유로 같은 직접 파생 계열로 처리하지 않았다.

### 실제 활용 가능성과 제약

공식 카드의 최소 예시 hardware는 대형 서버급이다.

- BF16: **4× B200 또는 8× H100**
- FP8: **2× B200 또는 4× H100**
- NVFP4 W4A16: **1× B200 또는 2× H100**

따라서 일반 PC용 모델이 아니다. 공식 concrete loading 예시는 Transformers를 중심으로 제공되며 Cohere의 `melody` parser와 vLLM에서 사용하는 structured marker parser가 언급된다. 그러나 조사 시점 카드에서 SGLang의 공식 turnkey recipe는 확인하지 못했으므로 임의로 호환을 가정하지 않는다.

Hugging Face Space가 연결되어 있어 hosted demo 형태의 검증은 가능하다. 상업적 사용에는 특히 주의가 필요하다. **CC BY-NC 4.0**이므로 기본 공개 license 조건상 비상업 용도이며, 상업적 사용은 Cohere에 별도 문의가 필요하다고 카드가 안내한다.

### benchmark 주의

모델 카드에 제시된 번역 품질 평가는 제공사가 수행·정리한 결과이므로 이 보고서에서는 **개발사 자체 평가/개발사 보고 평가**로 취급한다.
