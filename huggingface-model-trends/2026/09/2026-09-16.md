## 1. TaichuAI/ZDTaichu5.0-9B

- Hugging Face: https://huggingface.co/TaichuAI/ZDTaichu5.0-9B
- 개발사/작성자: TaichuAI / ZDTaichu5.0-9B Contributors
- 공식 GitHub: https://github.com/Taichu-AI/ZDTaichu5.0-9B
- 분야: Multimodal causal LM, VLM, spatial reasoning, embodied AI, agentic tool use, OCR/document/chart understanding
- 규모: HF 모델 페이지 기준 **10B parameters**, BF16
- 언어: 모델 페이지 태그 기준 English, Chinese
- 입력: text, single/multiple images, video
- context: 모델 카드 기준 **최대 128K tokens**

### 오늘 주목할 근거

2026-09-16 조사 시 Hugging Face Trending 2페이지 상위권에 있었고, 모델 페이지는 약 **17시간 내 업데이트**, **12 downloads/month**, **136 likes**, **Community 2**, **Space 1**을 표시했다. 다운로드 절대치는 아직 작지만 좋아요와 Trending 노출이 빠르게 형성된 신생 release다.

### 기존 모델과의 기술적 차이

언어 backbone은 Qwen3.5-9B, vision backbone은 C-RADIOv4-H다. 단순 VLM 결합만이 아니라 **Entropy-Gated Adaptive Recurrent Reasoning**을 도입해 쉬운 token은 기본 경로로 처리하고, 불확실하거나 어려운 token에는 latent space recurrent refinement step을 추가로 배정한다. 즉 모든 token에 똑같이 계산량을 쓰지 않고 어려운 부분에만 계산 depth를 늘리는 방식이다.

또한 일반 이미지 VQA뿐 아니라 2D/3D 공간 관계, multi-view association, camera pose/depth ordering, perspective taking, affordance, manipulation semantics, high-level action planning까지 학습 범위를 넓혔다. text/image/video와 tool-use를 한 checkpoint에서 연결하므로 기존 Qwen3.5-9B 자체와 비교해 **vision modality + spatial/embodied reasoning + agent 활용 경로**가 구조적으로 확장됐다.

### benchmark 해석

모델 카드가 TAU2-Bench 87.7, Claw-Eval general 71.4, IFEval 93.7 및 여러 spatial benchmark 결과를 제시한다. 이는 **개발사 자체 평가**이며 독립 검증 점수로 취급하지 않는다. 모델 카드 자체도 일부 agent 평가에서 DeepSeek-V4-Flash-0731을 simulated user/judge로 사용했다고 명시한다.

### 실제 활용 가능성과 제약

- Transformers offline inference를 제공하지만 `trust_remote_code=True`와 최신 의존성이 필요하다.
- 공식 online serving 경로는 ZDTaichu용으로 수정된 **vLLM v0.26.0 branch**다.
- Docker 예시는 **CUDA ≥ 12.9, NVIDIA Driver ≥ 575.51.03**을 요구하며 OpenAI-compatible `/v1` endpoint를 제공한다.
- tool calling/reasoning parser를 vLLM launch option으로 지원한다.
- 10B BF16급 VLM이므로 일반 저사양 PC CPU만으로 가볍게 쓰는 모델은 아니다. 모델 카드에는 llama.cpp/Ollama/LM Studio 공식 지원이 확인되지 않았다.
- 라이선스: 모델 weights는 **NVIDIA Open Model License Agreement**, Qwen3.5의 Apache-2.0 및 제3자 notices를 함께 유지한다. 상업적 사용은 실제 배포 전 LICENSE/NOTICE를 직접 확인해야 한다.
- Hugging Face Inference Provider에는 조사 시점 배포되지 않았다.

## 2. Accio-Lab/occamy-1.0

- Hugging Face: https://huggingface.co/Accio-Lab/occamy-1.0
- 개발사/작성자: Accio-Lab
- Paper: https://huggingface.co/papers/2609.11977
- Open training framework: https://github.com/Accio-Lab/Dressage
- 분야: Agent, coding, long-horizon co-work, tool use, multimodal
- 규모: **35B total / 3B active**, 256 experts 중 8 routed + 1 shared
- starting checkpoint: `Qwen3.6-35B-A3B`
- base architecture context: **262,144 tokens**
- SFT sequence length: **131,072 tokens**
- license: **Apache-2.0**

### 오늘 주목할 근거

2026-09-16 조사 시 Hugging Face Trending 3페이지에 있었고 약 **4시간 내 업데이트**, **973 downloads/month**, **81 likes**, **Community 5**를 표시했다. 논문은 12일 전에 공개됐지만 오늘 checkpoint 업데이트와 Trending 노출이 이어져 관심 증가 후보로 선정했다.

### 기존 모델과의 기술적 차이

Occamy는 Qwen3.6-35B-A3B의 architecture를 바꾸지 않는다. 따라서 단순 architecture 관점에서는 새 base model이 아니다. 다만 공식 모델 카드가 명시한 post-training은 **full-parameter SFT + HDPO + 두 expert의 parameter-space merge + SAO**로 구성된다.

`Marathon Expert`는 긴 작업 지속성과 accuracy-conditioned efficiency를, `Sprint Expert`는 더 넓은 agentic capability를 학습한 뒤 두 모델을 병합하고, 마지막에 **Single-Rollout Asynchronous Optimization**으로 co-work policy를 다시 다듬는다. 학습 데이터도 general agentic, long-horizon interactive agents, terminal/software engineering, tool-call grounding을 합쳐 14,998 trajectories / 403.3M tokens로 설명된다.

따라서 `introduced-models.md`의 규칙상 **경미한 fine-tune**으로 보지 않았다. base architecture는 같지만 학습 방법, agent/tool 운용 구조, 모델의 근본 목적이 장시간 상태 유지형 co-work로 크게 달라진 별도 post-trained 계열로 판정한다.

### benchmark 해석

Claw-Eval, WildClawBench, CommerceAgentBench, AutomationBench, Terminal-Bench 등 광범위한 표가 공개되어 있다. 별도 독립 재현을 확인하지 않았으므로 모델 카드가 제시한 결과는 **개발사 자체 평가**로 취급한다. 모델 카드 일부 비교값은 official model-card/Artificial Analysis 값을 사용했다고 구분한다.

### 실제 활용 가능성과 제약

- 공식 HF 페이지에서 **vLLM**, **SGLang**, Transformers 사용법을 제공한다.
- vLLM/SGLang 모두 OpenAI-compatible `/v1/chat/completions` endpoint로 제공 가능하다.
- Q4_K_M/Q8_0 GGUF와 NVFP4 checkpoint가 공식 배포되어 있고 HF가 llama.cpp/Ollama/LM Studio용 quantization 탐색 링크를 제공한다.
- 기본 serving 예시는 8-way tensor parallelism과 262K context를 사용한다. 35B total 모델이라 일반 저사양 PC에 가볍게 올리기는 어렵고, GGUF/짧은 context/충분한 RAM 또는 VRAM을 전제로 하는 편이 현실적이다.
- 모델 카드에 **OpenClaw, Hermes Agent, Accio Work**에서 학습·평가했다고 명시되어 있어 MCP/Agent류 workflow와의 연결성이 높다. 다른 agent framework도 OpenAI-compatible API로 연결할 수 있다.
- 현재 co-work training interface에는 native browser/desktop visual interaction이 포함되지 않았다고 모델 카드가 명시한다.
- Apache-2.0으로 공개됐지만 실제 사용 시 upstream Qwen 조건과 데이터/도구 사용 조건도 함께 점검하는 것이 안전하다.

## 3. knowledgator/gliformer-large-v1

- Hugging Face: https://huggingface.co/knowledgator/gliformer-large-v1
- 개발사/작성자: Knowledgator Engineering
- 공식 GitHub: https://github.com/Knowledgator/GLiFormer
- 분야: NER, text classification, joint relation extraction, structured extraction, embeddings, document/layout understanding
- 규모: **575.6M parameters**
- backbone: DeBERTa 기반 shared encoder + task heads
- license: **Apache-2.0**

### 오늘 주목할 근거

Hugging Face Trending 5페이지에 노출됐고 조사 시점 **약 1일 내 업데이트**, **41 likes**, **Community 2**, **Space 1**을 표시했다. Hugging Face는 이 모델의 downloads를 추적하지 않는다고 명시한다. 대형 LLM이 아닌 575.6M encoder로 여러 정보추출 task를 한 모델에서 처리한다는 실무적 차별성이 커 선정했다.

### 기존 모델과의 기술적 차이

GLiFormer는 생성형 LLM처럼 prompt로 임의 JSON을 만들어내는 방식과 다르게, **추론 시 task label과 extraction schema를 입력하고 공유 encoder + 전용 task head가 source-grounded span/class/relation/record를 예측**한다.

한 checkpoint에서 NER, classification, joint relation extraction, nested structured extraction, text embedding을 처리할 수 있고 layout-aware architecture도 갖는다. 특히 Pydantic schema를 이용한 nested record extraction과 한 번의 `inference()` 호출에서 여러 task를 동시에 수행하는 interface가 실무에서 문서/RAG 전처리 pipeline을 단순화할 수 있다.

### benchmark 해석

모델 카드에는 NER 26개 dataset 평균 strict entity F1 50.91, classification 13개 dataset 평균 macro-F1 75.03, multilevel structuring F1 91.10 등 결과가 있다. 이 수치는 공식 모델 카드/개발사 evaluation entry point에서 제공되는 **개발사 자체 평가**이며 독립 benchmark로 표현하지 않는다. 모델 카드도 relation evaluation subset과 structuring metric의 세부 제약을 명시한다.

### 실제 활용 가능성과 제약

- `pip install gliformer -U`로 사용할 수 있고 Python 3.10+ 소스 설치도 제공한다.
- CUDA용 optional attention kernel이 있지만 **CPU inference도 eager attention으로 지원**한다. 575.6M 규모라 오늘 선정 모델 중 로컬 PC 접근성이 가장 높다.
- 사용 사례: 문서에서 entity/관계/구조화 record 추출, 분류, embedding 생성, PDF layout processing.
- 모델 카드의 품질 표는 주로 **English text tasks** 기준이다. 다른 언어, layout input, embedding benchmark 품질은 아직 표로 확립되지 않았다고 명시한다.
- Pydantic validation은 schema 형식만 검증하며 추출 내용의 사실성까지 보장하지 않는다.
- 전용 vision/audio 모델은 아니고 open relation head도 없다고 명시한다.
- vLLM/SGLang/OpenAI-compatible generative serving이 핵심인 모델이 아니라 전용 `gliformer` Python runtime 중심이다.

## 중복·파생 후보 검증 메모

오늘 Trending 상단에서 함께 확인한 주요 후보를 `introduced-models.md`와 대조했다.

- `deepseek-ai/DeepSeek-V4.1-Flash`, `Qwen/Qwen3.8-*`, `nex-agi/Nex-N2.5-*`, `m-a-p/YuE2-3B`, `tencent/AuK*`, `Agnes-AI/Agnes-3.0-Flash`, `IFM/K2-Horizon-*`, `internlm/Atria-Dawn-Preview`, `oruk/orukeet`, `google/timesfm-3.0-pytorch`, `CohereLabs/North-Small-Translate-1.0` 등은 이미 중복 제외 인덱스에 존재해 재선정하지 않았다.
- `openbmb/MiniCPM5-2B`는 기존 `MiniCPM5-1B` 계열의 단순 scale-up으로 제외했다.
- `Edge0/Edge0-*`는 이전 보고서에서 Qwen3.5-MoE int4 + Recover-LoRA/prerouter adapter 기반 직접 파생 시스템으로 판정되어 제외했다.
- 다수 Qwen/DeepSeek abliterated·uncensored·GGUF·FP8/NVFP4 checkpoint, ComfyUI port, LoRA는 직접 파생/양자화/포맷 규칙에 따라 제외했다.
- `Accio-Lab/occamy-1.0`은 architecture 자체는 Qwen3.6-35B-A3B 그대로지만, 단순 경미한 fine-tuning을 넘어서는 staged post-training과 장기 co-work 목적 변화가 공식 자료로 확인돼 예외적으로 별도 계열로 인정했다.
