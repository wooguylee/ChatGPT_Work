## 1. harness-writing

**퍼저가 실제 코드 경로를 검사하도록 하네스부터 설계하기**

- 출처: Trail of Bits testing-handbook-skills
- 태그: 퍼징 · C/C++ · Rust · 구조화 입력 · 결정성
- 난이도: 중상급. 대상 API의 입력 계약과 상태·메모리 수명을 이해해야 한다.

### 무엇을 해주나

퍼저가 만든 바이트를 대상 함수의 인자로 바꾸고, 각 실행이 독립적으로 재현되도록 하네스를 구성한다. 구조화 입력, 전역 상태 초기화, 자원 정리, I/O 대체와 타깃 분리 기준을 다룬다. 첫 하네스를 만들 때뿐 아니라 커버리지가 늘지 않거나 같은 입력으로 크래시를 재현할 수 없을 때 유용하다. 이미 소개한 property-based-testing이 속성·불변식 설계를 넓게 다뤘다면, 여기서는 **퍼저와 실제 대상 코드 사이의 연결**에 집중한다. [SKILL.md](https://github.com/trailofbits/skills/blob/a3131740a39291e42fd15b9eac07e0b393ad71b1/plugins/testing-handbook-skills/skills/harness-writing/SKILL.md)

실무에서는 에이전트가 생성한 파일 파서·도구 응답 디코더를 좁은 함수부터 검토하는 데 쓸 수 있다. 실행 횟수만 보지 말고 목표 분기에 도달했는지, 정상 입력 거절과 하네스 자체 오류를 구분했는지 확인한다. 퍼징은 소유하거나 시험 권한이 있는 코드를 대상으로 하며, 크래시가 없는 한 번의 실행으로 전체 안전성을 보증하지 않는다. [공식 Testing Handbook의 범위와 한계](https://appsec.guide/docs/fuzzing/)

### 실전 프롬프트

“harness-writing으로 제공한 로컬 바이너리 파서의 하네스 초안을 읽기 전용으로 검토해줘. 빈 입력·잘린 입력·최대 길이의 처리, 상태 초기화·자원 해제·재현성을 확인해줘. 정수 포인터 강제 변환 없이 값을 읽는 대안을 제시하고, 파서가 처리해야 하는 잘못된 입력을 하네스에서 미리 전부 버리지 마. 실제 대상 함수와 중요한 분기에 도달했는지 확인할 체크리스트도 줘. 설치·실행·네트워크 접근·파일 수정은 하지 마.”

### 설치·주의

원문 C++ 예시의 `*(uint32_t*)data`는 길이 검사만으로 정렬·객체 접근 문제를 모두 해결하지 못한다. 명시적 바이트 디코딩, 계약에 맞는 `memcpy`, FuzzedDataProvider 같은 대안을 검토하고 바이트 순서를 정한다. 다른 예시의 `&str1[0]`·`&str2[0]`도 빈 벡터일 수 있으므로 그대로 복사하지 않는다. 빈 버퍼의 포인터·길이를 대상 API가 어떻게 받는지 확인해야 한다. 이는 예제에 대한 정적 검토이며 특정 제품의 취약점을 재현한 결과가 아니다. [Clang의 정렬 등 UB 검사](https://clang.llvm.org/docs/UndefinedBehaviorSanitizer.html#available-checks)

입력 크기를 제한할 때 하네스 자체의 잘못된 메모리 접근을 막는 것과 대상 파서의 경계 처리를 검사에서 제외하는 것을 구분한다. 네트워크·파일 쓰기를 포함한 타깃은 격리하고, 퍼징 전 CPU·메모리·시간·출력 크기 한도를 정한다. 코퍼스와 크래시 파일에는 원래 입력 데이터가 남을 수 있다.

## 2. cargo-fuzz

**Rust 파서의 실패를 재현 가능한 퍼즈 타깃으로 남기기**

- 출처: Trail of Bits testing-handbook-skills
- 태그: Rust · libFuzzer · sanitizer · 크래시 재현 · 커버리지
- 난이도: 중상급. nightly 도구 체인과 대상 라이브러리·의존성을 함께 확인해야 한다.

### 무엇을 해주나

Cargo 프로젝트에 `fuzz_target!` 기반 타깃을 구성하고 코퍼스·실행·발견 입력 재현·커버리지 확인으로 이어지는 절차를 제공한다. `arbitrary`를 이용한 구조화 입력도 다룬다. 에이전트가 만든 Rust 파서나 네이티브 도구 어댑터를 작은 라이브러리 함수부터 시험하는 데 적합하다. 앞의 harness-writing이 연결 설계를 맡는다면 이 스킬은 Rust 도구 체인에 적용하는 역할이다. [SKILL.md](https://github.com/trailofbits/skills/blob/a3131740a39291e42fd15b9eac07e0b393ad71b1/plugins/testing-handbook-skills/skills/cargo-fuzz/SKILL.md)

정상적인 `Result::Err`는 입력 거절일 수 있으므로 무조건 `unwrap()`해 가짜 크래시를 만들지 않는다. 반대로 예상치 못한 panic·메모리 오류·불변식 위반은 보존하고, 발견 입력을 최소화해 회귀 테스트로 연결하는 계획이 유용하다. 코드 생성·컴파일 성공·퍼징 수행·실패 재현은 별도 상태로 기록한다.

### 실전 프롬프트

“cargo-fuzz를 참고해 우리 Rust 라이브러리의 parse 함수용 타깃과 60초짜리 로컬 시험 계획을 제안해줘. 현재 Cargo.lock·Rust 버전·unsafe/FFI 의존성을 먼저 확인해줘. 문서화된 Result::Err는 허용하되 예상 밖 panic은 숨기지 말고, ASan을 유지해줘. 입력 크기·메모리 한도·산출물 위치·크래시 재현 방법을 명시해줘. 지금은 패키지 설치·도구 체인 변경·빌드·실행·운영 코드 수정 없이 검토안만 보여줘.”

### 설치·주의

현행 upstream README는 nightly Rust, C++11 지원 컴파일러, **x86-64/AArch64의 Unix 계열 환경**을 요구한다. Windows 네이티브 지원을 가정하지 않는다. 검사한 엔진 기준은 **bf2fc668dafda5295aa6fd01825ee67b885f0f2b**이며, 엔진 라이선스는 MIT OR Apache-2.0이다. Skill 문서의 라이선스와는 별개다. [현재 요구사항](https://github.com/rust-fuzz/cargo-fuzz/blob/bf2fc668dafda5295aa6fd01825ee67b885f0f2b/README.md) · [Cargo.toml](https://github.com/rust-fuzz/cargo-fuzz/blob/bf2fc668dafda5295aa6fd01825ee67b885f0f2b/Cargo.toml)

원문의 sanitizer 비활성화와 “2배” 속도 설명을 일반적인 성능 보장으로 쓰지 않는다. 본문 코드가 safe Rust여도 의존성·FFI에 unsafe가 있을 수 있다. 먼저 검사 목적과 해당 sanitizer가 찾는 결함을 확인한다. 예제의 고정된 오래된 nightly 날짜·부속 커버리지 도구·외부 seed 다운로드도 현재 환경에 맞춰 재검토한다. `cargo fuzz init`과 `add`는 파일을 만들고, 빌드와 퍼징은 실제 대상 코드를 실행한다. 설치 지침을 읽었다는 이유로 이 작업들이 승인되는 것은 아니다.

## 3. atheris

**Python 입력 처리 코드의 경계 조건을 커버리지로 탐색하기**

- 출처: Trail of Bits testing-handbook-skills
- 태그: Python · CPython 확장 · 커버리지 · 입력 검증 · ASan
- 난이도: 순수 Python은 중급, C/C++ 확장은 상급.

### 무엇을 해주나

Python 함수와 네이티브 확장에 Atheris를 적용하는 절차다. `TestOneInput`, import 시점 계측, `FuzzedDataProvider`의 타입별 값 추출과 코퍼스 관리가 핵심이다. 문자열·바이트·도구 응답 파서의 예외 처리가 일관적인지 살피는 데 쓸 수 있다. 하네스만 계측하고 실제 대상 모듈을 놓치지 않는 것이 중요하다. [SKILL.md](https://github.com/trailofbits/skills/blob/a3131740a39291e42fd15b9eac07e0b393ad71b1/plugins/testing-handbook-skills/skills/atheris/SKILL.md)

여러 인자를 만들 때는 값을 소비하는 순서를 안정적으로 유지하고, 입력이 소진됐을 때 나오는 기본값도 고려한다. 구조화 입력 도우미를 쓰는 것만으로 실제 업무 불변식이 검증되는 것은 아니다. 대상 함수·예상 오류·실패 조건을 먼저 정의한다. [구조화 입력 참고](https://github.com/trailofbits/skills/blob/a3131740a39291e42fd15b9eac07e0b393ad71b1/plugins/testing-handbook-skills/skills/atheris/structured-input.md)

### 실전 프롬프트

“atheris를 참고해 제공한 Python 파서의 하네스 설계안을 만들어줘. 대상 모듈은 instrument_imports 범위에서 불러오고, 문서화된 입력 오류만 처리해줘. 예상 밖 예외는 숨기지 말고, 빈 입력·잘린 UTF-8·중첩 구조를 고려해줘. 최대 입력 1KB·60초·별도 임시 출력 디렉터리의 시험 계획을 보여줘. 현재 Python·Atheris 배포 버전과 호환성을 먼저 확인하고 지금은 설치·빌드·실행·외부 업로드를 하지 마.”

### 설치·주의

Skill은 Python 3.7 이상이라고 적지만, 확인한 upstream master **e36da74cf42b5834c4e31d7cabb58d796695d29f**는 **Python 3.11–3.14**와 Linux/macOS를 명시한다. 이는 확인한 소스 기준이며 모든 과거 PyPI 배포의 지원 범위를 뜻하지 않는다. 실제 설치할 릴리스·Python·플랫폼의 호환성을 별도로 확인한다. 엔진 라이선스는 Apache-2.0이다. [현행 README](https://github.com/google/atheris/blob/e36da74cf42b5834c4e31d7cabb58d796695d29f/README.md) · [엔진 LICENSE](https://github.com/google/atheris/blob/e36da74cf42b5834c4e31d7cabb58d796695d29f/LICENSE)

순수 Python용 wheel의 libFuzzer 포함과 네이티브 확장의 계측은 다르다. C 확장은 호환되는 Clang·sanitizer 플래그와 재빌드가 필요할 수 있고, 재동기화 중 비계측 wheel로 바뀌지 않았는지도 확인한다. `LD_PRELOAD`·컴파일러 환경 변수는 격리한 시험 프로세스에 한정한다. [네이티브 확장 공식 안내](https://github.com/google/atheris/blob/e36da74cf42b5834c4e31d7cabb58d796695d29f/native_extension_fuzzing.md)

부속 HTTP 예제의 넓은 `except Exception`을 일반 파서 검사에 그대로 쓰면 실제 오류를 숨길 수 있다. 네이티브 메모리 오류만 찾는 실험과 Python 논리 오류 검사에서 예외 정책을 다르게 정한다. 원문의 `detect_leaks=0` 설정 역시 누수 검사를 끄므로, 누수까지 확인했다고 보고하면 안 된다. [부속 예제와 경고](https://github.com/trailofbits/skills/blob/a3131740a39291e42fd15b9eac07e0b393ad71b1/plugins/testing-handbook-skills/skills/atheris/examples.md)

## 4. azure-ai-contentsafety-py

**텍스트 검사 결과와 서비스 실패를 구분하는 안전성 계층 설계하기**

- 출처: Microsoft 공식 azure-sdk-python 묶음
- 태그: 콘텐츠 검사 · Python · moderation · 한국어 평가 · 오류 처리
- 난이도: 중급. 서비스의 판정 범위와 자체 업무 정책을 구분해야 한다.
- SKILL metadata 버전: **1.0.0**. SDK 패키지 버전 고정을 뜻하지 않는다.

### 무엇을 해주나

ContentSafetyClient를 이용한 텍스트·이미지 분석과 사용자 blocklist 관리를 설명한다. 텍스트의 네 가지 유해성 범주, 4단계·8단계 severity 표현을 업무 흐름에 연결하는 참고 자료다. 에이전트의 입력·출력 검사를 설계할 때 범주별 점수, 사람이 정한 처리 기준, 서비스 호출 실패를 별도 상태로 남기는 데 활용할 수 있다. 이번 추천 범위는 **텍스트 검사 어댑터와 테스트 설계**이며 이미지 예제의 무검증 실행은 권하지 않는다. [SKILL.md](https://github.com/microsoft/skills/blob/28bd7424998a963f07122c5dea91fc02ca443831/.github/plugins/azure-sdk-python/skills/azure-ai-contentsafety-py/SKILL.md)

네 범주 점수는 정확성·개인정보 보호·프롬프트 인젝션 방어를 모두 포괄하는 단일 안전 판정이 아니다. 점수 0을 모든 위험이 없다는 뜻으로 해석하지 않고, timeout·429·불완전 응답을 “안전”으로 바꾸지 않는 테스트가 필요하다. 네 가지 유해 범주의 텍스트 분류기에 대해 공식 문서가 명시한 학습·시험 언어 8개에는 한국어가 포함되지 않는다. 한국어 사용 불가라는 뜻은 아니지만, 한국어 평가 세트와 사람 검토 없이 성능을 가정하면 안 된다. [공식 분류 범위·언어·판정 한계](https://learn.microsoft.com/en-us/azure/ai-services/content-safety/concepts/harm-categories)

### 실전 프롬프트

“azure-ai-contentsafety-py를 참고해 개인정보 없는 합성 텍스트용 moderation adapter와 모의 단위 테스트를 설계해줘. 범주별 severity와 업무 정책을 분리하고 허용·보류·사람 검토 분기를 명시해줘. timeout·429·응답 누락을 안전으로 처리하지 마. 한국어 오탐·미탐 검토 항목과 검증 담당자도 정리하되 담당자를 임의로 확정하지 마. 패키지 설치·Azure 호출·로그인·실제 문장 전송·blocklist 변경은 하지 마.”

### 설치·주의

실제 호출에는 기존 Content Safety 리소스·endpoint와 승인된 인증·권한이 필요하다. 설치 안내의 azure-ai-contentsafety 외에 Entra 인증 예제를 쓰면 azure-identity도 필요하다. 원문의 `DefaultAzureCredential(require_envvar=True)`는 `AZURE_TOKEN_CREDENTIALS`가 없으면 실패하므로, “production에서만 필요한 변수”라는 설명을 local 예제에 그대로 적용하지 않는다. 자격 증명·토큰을 프롬프트나 로그에 붙이지 않고 지원되는 인증 경로를 사용한다. [공식 credential 설명](https://learn.microsoft.com/en-us/python/api/azure-identity/azure.identity.defaultazurecredential?view=azure-python)

이미지 예제는 직접 base64 인코딩한 문자열을 `ImageData.content`에 넣지만, 공식 Python 예제는 파일의 bytes를 전달한다. SDK가 요구하는 타입·직렬화를 확인하고 이미지 경로는 수정·검증 전까지 사용하지 않는 편이 낫다. [공식 SDK 이미지 예제](https://learn.microsoft.com/en-us/python/api/overview/azure/ai-contentsafety-readme?view=azure-python#analyze-image)

분석 요청은 콘텐츠를 Azure로 전송하며, blocklist 생성·갱신은 별도 쓰기 작업이다. 테스트 데이터·전송 대상·보존 정책·사용량·요금을 확인한다. SKILL 1.0.0, SDK stable/preview 버전, 서비스 API 버전은 구분하고 실제 프로젝트에 설치된 버전의 문서를 우선한다. [SDK 변경 이력](https://github.com/Azure/azure-sdk-for-python/blob/main/sdk/contentsafety/azure-ai-contentsafety/CHANGELOG.md)

## 5. azure-search-documents-py

**RAG 검색 코드의 질의 계약과 권한 경계를 검토하기**

- 출처: Microsoft 공식 azure-sdk-python 묶음
- 태그: RAG · Azure AI Search · 벡터 검색 · 하이브리드 검색 · OData

### 무엇을 해주나

SearchClient, SearchIndexClient, SearchIndexerClient의 역할과 키워드·벡터·하이브리드·semantic 검색 패턴을 설명한다. HNSW·벡터화·semantic captions/answers와 agentic retrieval 참고 문서도 있다. 첫 적용은 **기존 테스트 인덱스의 검색 질의 설계**로 범위를 좁히는 편이 적절하다. 관련 문서가 상위 결과에 들어오는지 비교하고 빈 결과·잘못된 필드·서비스 오류를 분리하는 데 유용하다. [SKILL.md](https://github.com/microsoft/skills/blob/28bd7424998a963f07122c5dea91fc02ca443831/.github/plugins/azure-sdk-python/skills/azure-search-documents-py/SKILL.md)

검색 점수가 높다고 최종 답변이 사실에 맞거나 사용자가 그 문서를 볼 권한이 있다는 뜻은 아니다. 모델 생성 질의와 접근 제어 필터를 분리하고, 읽기 전용 앱에는 가능한 최소 범위의 Search Index Data Reader 권한을 검토한다. 인덱스·문서 변경 권한은 별도다. [공식 RBAC 구분](https://learn.microsoft.com/en-us/azure/search/search-security-rbac)

### 실전 프롬프트

“azure-search-documents-py를 참고해 keyword·vector·hybrid query builder와 mock 테스트 설계안을 만들어줘. 현재 SDK 버전·인덱스 필드·벡터 차원을 확인하고, category의 타입 검사·OData 문자열 escaping·빈 결과·429·timeout·잘못된 필드 테스트를 포함해줘. tenant/ACL 필터는 모델이 임의로 변경하지 못하도록 별도 계약으로 정리해줘. 실제 검색·임베딩 호출·업로드·인덱스 생성·setup 스크립트 실행·권한 변경은 하지 마.”

### 설치·주의

`references/vector-search.md`의 `async_vector_search`에는 `client.search(...)` 앞의 `await`가 빠져 있다. 공식 async API에 맞게 결과를 얻은 뒤 비동기로 순회하도록 검토해야 한다. 같은 참조의 category f-string 직접 보간도 임의 사용자 값에 그대로 적용하지 않는다. OData 문자열의 작은따옴표 escaping, 허용값·타입 검증을 적용하고, 접근 제어 필터 자체를 사용자 질의로 대체하지 않는다. [원본 참조](https://github.com/microsoft/skills/blob/28bd7424998a963f07122c5dea91fc02ca443831/.github/plugins/azure-sdk-python/skills/azure-search-documents-py/references/vector-search.md) · [공식 async API](https://learn.microsoft.com/en-us/python/api/azure-search-documents/azure.search.documents.aio.searchclient?view=azure-python#search) · [OData 문자열 문법](https://learn.microsoft.com/en-us/azure/search/search-query-odata-syntax-reference)

[벡터 인덱스 스크립트](https://github.com/microsoft/skills/blob/28bd7424998a963f07122c5dea91fc02ca443831/.github/plugins/azure-sdk-python/skills/azure-search-documents-py/scripts/setup_vector_index.py) · [agentic retrieval 스크립트](https://github.com/microsoft/skills/blob/28bd7424998a963f07122c5dea91fc02ca443831/.github/plugins/azure-sdk-python/skills/azure-search-documents-py/scripts/setup_agentic_retrieval.py)
