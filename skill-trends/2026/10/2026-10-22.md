## 1. wiki-researcher

**“아마 이렇게 동작할 것”을 실제 코드 경로와 미확인 목록으로 바꾸기**

- 출처·조직: Microsoft / microsoft/skills, Deep Wiki
- 라이선스: MIT
- 태그: 코드 조사 · 데이터 흐름 · 의존성 · 근거 추적 · 확신도
- 난이도: 중상급. 소스 전체를 읽을 수 있는 환경과 조사 범위를 먼저 정해야 한다.

### 무엇을 해주나

구조, 데이터·상태 흐름, 통합·의존성, 패턴·위험, 최종 종합의 **5회 조사**를 진행한다. 이름이나 디렉터리 배치로 아키텍처를 추측하지 않고 실제 구현과 호출 체인을 읽도록 요구한다. 중요한 발견마다 근거·의미·확신도·남은 질문을 붙이고, 각 단계의 도표도 읽은 코드에 연결한다. [SKILL.md](https://github.com/microsoft/skills/blob/bd924c165294e72356fdd19260ac81e5a968d889/.github/plugins/deep-wiki/skills/wiki-researcher/SKILL.md)

명령 문서는 조사한 영역, 일부만 본 영역, 아직 보지 않은 영역을 계속 갱신하는 지식 지도를 제공한다. “설명은 그럴듯하지만 인증 분기나 재시도 경로를 보지 않은 상태”를 드러내기에 유용하다. [research 명령](https://github.com/microsoft/skills/blob/bd924c165294e72356fdd19260ac81e5a968d889/.github/plugins/deep-wiki/commands/research.md)

### 실전 프롬프트

“wiki-researcher로 현재 체크아웃한 커밋의 주문 취소 흐름을 조사해줘. 저장소 URL과 커밋 SHA를 먼저 확인하고, API 진입점부터 권한 확인·상태 변경·결제 취소 요청까지 실제 호출을 추적해. 구조, 데이터 흐름, 외부 의존성, 실패 패턴, 종합의 다섯 관점으로 나눠 발견마다 파일·함수·라인과 확신도를 붙여줘. 테스트나 외부 API는 실행하지 말고, 아직 읽지 않은 분기는 미확인으로 남겨줘. 결과는 검토용 문서로만 작성해줘.”

### 설치·주의

기존 [10월 18일 wiki-qa](2026-10-18.md)는 개별 질문에 대한 코드 기반 답변이고, 오늘 후보는 **여러 단계에 걸친 심층 조사와 지식 지도**가 중심이다. 기존 [audit-context-building](2026-10-10.md)의 보안 감사 준비와도 목적을 구분했다.

원문의 “호출 지점 없음”은 동적 로딩·리플렉션·플러그인 등록까지 조사해야 판단할 수 있다. 검색 결과가 없다는 이유만으로 dead code라 확정하지 않는 것이 안전하다. 또한 HIGH는 “코드를 읽었다”는 자체 분류이지 런타임 검증이나 무결점 보증이 아니다. 다섯 단계와 매 단계 도표 요구는 비용이 있으므로 좁은 주제를 정하고, 도표 개수보다 실제 근거의 완결성을 검토한다.

## 2. wiki-architect

**본문부터 길게 쓰기 전에, 근거가 연결된 문서 설계도 만들기**

- 출처·조직: Microsoft / microsoft/skills, Deep Wiki
- 라이선스: MIT
- 태그: 문서 구조 · 코드베이스 지도 · JSON 목차 · 정보 설계
- 난이도: 중급. 프로젝트 유형과 독자별 문서 범위를 확인할 사람이 필요하다.

### 무엇을 해주나

파일 트리와 README를 읽고 언어·프레임워크·계층·주요 구성요소를 찾아, 각 노드에 `title`, `name`, `prompt`, `children`을 가진 JSON 목차를 만든다. 각 본문 작성 프롬프트에는 실제 파일을 인용하도록 한다. 최대 깊이 4단계, 섹션당 자식 8개라는 제한이 있어 대규모 코드베이스의 목차가 끝없이 늘어나는 것을 제어한다. [SKILL.md](https://github.com/microsoft/skills/blob/bd924c165294e72356fdd19260ac81e5a968d889/.github/plugins/deep-wiki/skills/wiki-architect/SKILL.md)

산출물은 완성된 위키나 검증된 아키텍처가 아니라 **후속 문서 작성을 위한 구조**다. 이미 소개한 `wiki-onboarding`이 독자별 안내문을 만드는 데 집중했다면, 이 Skill은 전체 위키의 목차와 각 페이지의 근거·작성 범위를 먼저 정한다.

### 실전 프롬프트

“wiki-architect로 이 저장소의 문서 목차만 JSON 초안으로 만들어줘. 실제 파일과 README를 근거로 계층을 나누고, 각 노드의 prompt에 확인한 파일 링크를 넣어줘. 기여자·운영 담당자·PM이 무엇을 읽어야 하는지 구분하되, 존재하지 않는 서비스나 배포 환경을 가정하지 마. 아직 본문·VitePress·CI 파일은 만들지 말고 현재 문서와 겹치는 항목을 표시해줘.”

### 설치·주의

**Skill과 slash command의 범위가 완전히 같지 않다.** Skill은 온보딩 섹션을 첫머리에 두고 작은 저장소에도 포함하라고 하지만, `/deep-wiki:catalogue` 명령은 Getting Started·Deep Dive 중심의 예시와 “10개 이하 파일이면 Getting Started만” 규칙을 제시한다. 호출 방법에 따라 산출물 기대가 달라질 수 있으므로 목차 전용인지 온보딩까지 포함하는지 프롬프트로 명시한다. [catalogue 명령](https://github.com/microsoft/skills/blob/bd924c165294e72356fdd19260ac81e5a968d889/.github/plugins/deep-wiki/commands/catalogue.md)

또한 여러 Deep Wiki 원문은 `git rev-parse --abbrev-ref HEAD`를 “default branch 확인”이라고 적는다. 이 명령으로 확인하는 체크아웃 참조를 원격 기본 브랜치와 동일시하면 안 된다. 실제 분석 커밋을 고정하고 그 커밋으로 링크를 만드는 편이 재현성에 유리하다. [Git rev-parse 문서](https://git-scm.com/docs/git-rev-parse)

## 3. wiki-changelog

**커밋 제목을 복사하지 않고 사용자에게 달라진 점을 정리하기**

- 출처·조직: Microsoft / microsoft/skills, Deep Wiki
- 라이선스: MIT
- 태그: Git 이력 · 변경 기록 · 릴리스 노트 초안 · 마이그레이션
- 난이도: 초중급. 분석할 브랜치·기간·기준 버전을 정해야 한다.

### 무엇을 해주나

Git의 커밋 메시지·날짜·작성자를 살피고 기능, 버그 수정, 리팩터링, 문서, 설정, 의존성, 호환성 파괴 변경으로 분류한다. 최근 7일은 일별, 그 이전은 주별로 묶고 관련 커밋을 하나의 사용자 관점 설명으로 합친다. 호환성 파괴 변경은 눈에 띄게 표시하고 마이그레이션 안내를 붙인다. [SKILL.md](https://github.com/microsoft/skills/blob/bd924c165294e72356fdd19260ac81e5a968d889/.github/plugins/deep-wiki/skills/wiki-changelog/SKILL.md) · [명령 문서](https://github.com/microsoft/skills/blob/bd924c165294e72356fdd19260ac81e5a968d889/.github/plugins/deep-wiki/commands/changelog.md)

특정 프로젝트의 변경 로그 편집 규칙에 맞추던 기존 `openclaw-changelog-update`와 달리, 임의 저장소의 이력을 읽고 링크가 있는 요약 초안을 만드는 용도다. 단, 커밋 기록은 배포·출시 증명이 아니므로 “사용자가 이미 이 기능을 쓸 수 있다”는 표현은 별도 근거가 필요하다.

### 실전 프롬프트

“wiki-changelog로 내가 지정한 BASE와 HEAD 커밋 사이의 사용자 영향만 정리해줘. 기능·수정·호환성 변경을 나누고, 관련 커밋은 중복 없이 묶어 링크를 달아줘. BREAKING 키워드만 믿지 말고 관련 diff와 API 변경을 확인해. 릴리스 태그나 배포 기록이 없으면 미출시 여부 미확인으로 적고, 마이그레이션 방법을 확인하지 못했으면 추측하지 마. 기존 CHANGELOG 수정·태그 생성·게시 없이 초안만 줘.”

### 설치·주의

원문 명령의 키워드 표는 분류 보조이지 의미 검증기가 아니다. `fix` 제목이 달려 있어도 호환성을 깨뜨릴 수 있고 revert가 이전 기능을 취소했을 수 있다. 분석 범위와 시간대를 기록하고, shallow clone으로 이력이 빠졌는지 확인해야 한다. `--first-parent`는 병합된 가지의 개별 커밋을 건너뛰는 관점을 제공하므로 전체 변경 내역과 같은 것으로 오해하지 않는다. [Git log 문서](https://git-scm.com/docs/git-log)

## 4. wiki-llms-txt

**에이전트가 문서 전체를 무작정 읽기 전에 사용할 작은 안내 파일 만들기**

- 출처·조직: Microsoft / microsoft/skills, Deep Wiki
- 라이선스: MIT
- 태그: llms.txt · 문서 탐색 · 컨텍스트 관리 · 링크 검증
- 난이도: 중급. 기존 위키의 정확성, 경로, 공개 범위를 검토해야 한다.

### 무엇을 해주나

기존 위키에서 프로젝트 설명과 중요한 문서 링크를 추려 `./llms.txt`, `wiki/llms.txt`, `wiki/llms-full.txt`를 만든다. 루트 파일은 `wiki/` 아래로 연결하고 위키 내부 파일은 위키 기준 상대경로를 사용한다. 전체 버전은 페이지를 인라인으로 넣되 YAML frontmatter를 제거하고 코드 인용·표·Mermaid와 출처 주석을 보존하도록 한다. [SKILL.md](https://github.com/microsoft/skills/blob/bd924c165294e72356fdd19260ac81e5a968d889/.github/plugins/deep-wiki/skills/wiki-llms-txt/SKILL.md)

외부 도구가 파일을 읽는다고 자동으로 문서의 정확성이나 검색 노출이 보장되는 것은 아니다. 이 Skill의 직접 가치는 **문서 접근용 산출물과 경로 검증**이며, 기존 `docs-sync`의 코드·문서 불일치 수정이나 `agents-md`의 행동 지시 파일 작성과는 구분된다.

### 실전 프롬프트

“wiki-llms-txt로 승인된 wiki 문서만 대상으로 탐색 색인 초안을 만들어줘. 루트·위키 기준 상대경로를 각각 검사하고, 링크 대상 파일 존재와 중복 항목을 확인해. 내가 만든 기존 루트 llms.txt는 덮어쓰지 마. 내부 주소·개인정보가 포함된 문서는 제외 목록에 남겨줘. 전체 인라인 파일은 용량·토큰 부담을 먼저 알려주고 공개 사이트 배포는 하지 마. 최신 llms.txt v2와 Skill 자체 규칙이 다른 부분도 적어줘.”

### 설치·주의

**현재 제안서와 Skill의 규칙을 구분해야 한다.** 공식 llms.txt v2는 사이트 하위 경로도 다루며, `Optional`은 부차적 링크를 두는 관례이지 자동 생략을 보장하는 기계적 의미가 아니다. Skill이 정한 필수 요약문·1–5KB 목표·전체 인라인 파일 형식을 모두 v2의 필수 요건으로 일반화하지 않는다. 특히 v2 변경 기록은 전체 컨텍스트 확장 도구를 제안 범위에서 제거했다고 설명한다. [현행 제안](https://llmstxt.org/) · [v2 변경 기록](https://llmstxt.org/changes.html)

원문은 Deep Wiki가 만들지 않은 기존 루트 파일을 덮어쓰지 않도록 한다. 기존 위키가 없으면 README·소스에서 최소 파일을 만들거나 위키 생성부터 제안한다. 링크 목록이 올바르더라도 원문이 오래되면 오래된 내용을 전달한다. 전 문서 인라인은 비용·민감정보 노출을 늘릴 수 있으므로 공개 대상만 포함하고, 결과를 소비할 클라이언트가 실제로 어떤 파일을 읽는지 별도로 확인한다. ## 5. microsoft-docs

**모델 기억 대신 Microsoft 공식 문서를 검색하고 전문까지 확인하기**

- 출처·조직: Microsoft / microsoft/skills
- 라이선스: 저장소 MIT. Learn 콘텐츠·서비스에는 별도 이용 조건이 적용된다.
- 태그: Microsoft Learn · MCP · 문서 grounding · 설정·한도 확인
- 난이도: 초중급. Learn MCP를 지원하는 클라이언트의 연결 설정이 필요하다.

### 무엇을 해주나

개념·튜토리얼·설정·한도·권장 사항 질문을 Microsoft Learn 문서 검색으로 연결한다. 버전, 운영체제, 작업 목적을 질문에 넣어 검색을 구체화하고, 검색 발췌만으로 단계나 설정을 다 알 수 없으면 문서 전체를 가져오도록 한다. 원문의 주 도구는 `microsoft_docs_search`와 `microsoft_docs_fetch`다. [SKILL.md](https://github.com/microsoft/skills/blob/bd924c165294e72356fdd19260ac81e5a968d889/.github/skills/microsoft-docs/SKILL.md)

기존 `documentation-lookup`은 Context7의 라이브러리 식별·버전별 코드 문서 조회에 초점이 있었다. 이 Skill은 Microsoft Learn의 개념·운영 설정·한도 같은 질문과 전체 공식 페이지 조회에 초점을 둔다. 같은 “문서로 근거 보강” 계열이지만 제공자·도구·대상 문서가 다르며, 완전히 새로운 검색 방식이라고 주장하지 않는다.

### 실전 프롬프트

“microsoft-docs로 Azure Functions Python v2 앱의 실행 시간 제한을 확인해줘. 사용 플랜과 OS가 결과에 영향을 주면 구분하고, 검색 결과에서 관련 공식 문서 전체를 읽어 근거 URL과 확인일을 남겨줘. 문서가 말하는 범위와 내 설정에서 실제 확인한 값을 분리해줘. 계정이나 구독 정보를 검색어에 넣지 말고 Azure 리소스 조회·설정 변경은 하지 마.”

### 설치·주의

Learn MCP의 공식 엔드포인트는 `https://learn.microsoft.com/api/mcp`이며 Streamable HTTP 기반이다. 공식 안내상 인증 없이 무료로 공개 문서를 조회하지만, 클라이언트·모델 사용료까지 무료라는 뜻은 아니다. 서비스 이용 조건을 확인해야 하며, 문서 검색은 구독별 실제 잔여 할당량이나 비공개 설정 조회가 아니다. [공식 개요](https://learn.microsoft.com/en-us/training/support/mcp)

도구 인터페이스를 고정된 REST API처럼 하드코딩하지 말고 초기화할 때 도구 목록을 확인하라는 개발자 안내가 있다. 현재 공식 목록에는 코드 예제 검색 도구도 있지만 오늘 Skill의 주요 절차는 검색·전문 조회 두 도구다. [개발자 문서](https://learn.microsoft.com/en-us/training/support/mcp-developer-reference)

원문은 MCP가 없을 때 `npx @microsoft/learn-cli` 대안도 제시한다. 이번 조사에서는 해당 CLI 패키지의 배포본·실행 동작을 별도로 검증하지 않아 설치 명령을 권장 경로로 제시하지 않는다. `npx` 실행은 패키지 다운로드·코드 실행을 수반할 수 있어 “아무 준비나 승인도 필요 없다”로 읽으면 안 된다.

## 공통 설치 경로와 이용 조건

Deep Wiki의 공식 README는 **GitHub Copilot CLI 플러그인** 설치를 다음처럼 안내한다. 아래는 문서에 있는 사용 경로이며 이번 조사에서 실행하지 않았다.

```text
/plugin marketplace add microsoft/skills
/plugin install deep-wiki@skills
```

설치 후 해당 클라이언트에서는 `/deep-wiki:research <주제>`, `/deep-wiki:catalogue`, `/deep-wiki:changelog`, `/deep-wiki:llms`를 사용할 수 있다. 이 slash command들을 Codex에서도 그대로 쓸 수 있다고 단정하지 않는다. 전체 `generate`·`deploy` 대신 필요한 단계만 선택하면 의도하지 않은 대규모 파일 생성이나 배포를 줄일 수 있다. [Deep Wiki README](https://github.com/microsoft/skills/blob/bd924c165294e72356fdd19260ac81e5a968d889/.github/plugins/deep-wiki/README.md)

저장소 공통 README는 `npx skills add microsoft/skills` 선택형 설치도 안내한다. 실제 클라이언트의 Skill 탐색 경로와 지원 메타데이터를 확인하고 필요한 폴더만 검토한다. 플러그인 명령·에이전트까지 필요한 작업은 단일 SKILL.md 복사만으로 동일하게 동작한다고 보장할 수 없다. 원문이 Work in Progress인 만큼 설치 시점 변경사항도 재확인한다. [공통 README](https://github.com/microsoft/skills/blob/bd924c165294e72356fdd19260ac81e5a968d889/README.md)
