## 1. variant-analysis

- **출처/제작자:** Trail of Bits 공식 · [skills.sh](https://www.skills.sh/trailofbits/skills/variant-analysis)
- **원 Skill:** [variant-analysis/SKILL.md](https://github.com/trailofbits/skills/blob/main/plugins/variant-analysis/skills/variant-analysis/SKILL.md)
- **지원 Agent:** 공식 Claude Code·Codex plugin 경로.
- **태그:** `#변형분석` `#근본원인` `#패치범위` `#정적분석`
- **도입 난이도:** 중간~높음. 확인된 최초 사례와 검색 결과를 판단할 코드 맥락이 필요하다.

### 인기 및 트렌드 지표

- skills.sh **installs 5.9K**, First Seen **2026-01-19**.
- 감사 표시: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Pass**.
- 설치 수·감사 배지는 누락률이나 취약점 탐지 성능의 검증값이 아니다.

### 내용

확인된 버그의 근본 원인에서 출발해 같은 실수가 다른 모듈·자료형·호출 경로에도 있는지 찾는다. 최초 사례만 찾는 좁은 패턴을 먼저 검증하고, 한 번에 한 조건씩 일반화하면서 새 일치 결과를 검토한다. 기존 일반 code-review와 달리 **이미 아는 문제의 발생 범위**를 넓히는 데 목적이 있다. [공식 원문](https://github.com/trailofbits/skills/blob/main/plugins/variant-analysis/skills/variant-analysis/SKILL.md)

검색 패턴을 너무 빨리 넓히면 어떤 조건 때문에 오탐이 생겼는지 알기 어렵다. 최초 모듈에만 범위를 묶거나 정상 입력만 검토해도 변형을 놓칠 수 있다. 일치 결과를 실제 결함·확인 필요·오탐으로 나누고 실패한 검색도 남기는 방식이 유용하다. CodeQL·Semgrep 템플릿과 보고서 양식이 동봉되지만 템플릿 적용 자체가 탐지 완전성의 증명은 아니다. [plugin 구성](https://github.com/trailofbits/skills/blob/main/plugins/variant-analysis/README.md)

**적용 권고:** 알려진 사례가 실제 결함인지 먼저 확정하고 허가된 저장소만 조사한다. CI 규칙은 검토용으로 제안하되 자동 활성화·PR 게시·운영 서비스 재현으로 범위를 넓히지 않는다. 아직 버그를 모르는 초기 탐색에는 다른 절차가 필요하다.

### 설치 및 사용

아래 공통 Trail of Bits Codex 설치 절에서 **variant-analysis** plugin을 선택한다. 대규모 조사에는 `/variant-analysis:variants` workflow가 있으며 호스트의 Workflow·보조 agent 지원을 확인한다.

**Agent 활용 예시**

> 이 패치에서 확인된 tenant ID 검증 누락의 근본 원인을 정리하고 같은 저장소의 다른 경로를 variant-analysis로 조사해줘. 최초 사례를 찾는 패턴부터 검증하고 조건을 하나씩 넓혀줘. 확인된 변형과 오탐, 읽지 못한 경로를 나누고 코드 수정·외부 게시 없이 검토 보고서만 남겨줘.

**평가:** 오늘의 **Top Pick**이다. 한 곳만 고치고 같은 실수를 남겨두는 문제에 직접 대응한다. 모든 유사 코드가 취약하다는 판단이나 전체 보안 감사의 대체물로 쓰지는 않는다.

## 2. audit-context-building

- **출처/제작자:** Trail of Bits 공식 · [skills.sh](https://www.skills.sh/trailofbits/skills/audit-context-building)
- **원 Skill:** [audit-context-building/SKILL.md](https://github.com/trailofbits/skills/blob/main/plugins/audit-context-building/skills/audit-context-building/SKILL.md)
- **지원 Agent:** Claude Code·Codex plugin. 함수별 보조 agent·workflow·출력 schema까지 포함한 구성을 확인한다.
- **태그:** `#코드이해` `#감사준비` `#불변식` `#호출관계`
- **도입 난이도:** 중간. 소스 접근은 간단하지만 함수별 분석량과 불확실성 관리가 필요하다.

### 인기 및 트렌드 지표

- skills.sh **installs 6.2K**, First Seen **2026-01-19**.
- 감사 표시: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Pass**.
- [공식 평가 설명](https://github.com/trailofbits/skills/blob/main/plugins/audit-context-building/README.md#tests)은 스킬 없는 모델도 일부 평가에서 같은 만점을 받았고 특정 조건에서 턴 수가 약 두 배였다고 밝힌다. 이를 정확도 향상의 독립적인 증거로 사용하지 않는다.

### 내용

낯선 코드에서 함수의 전제조건·보장사항·호출 의존성과 미해결 질문을 정리한다. 함수명만 보고 검증됐다고 추측하지 않고 실제 호출 대상을 따라가며 근거 줄 번호를 붙인다. 취약점 이름·심각도·수정안은 다음 단계로 분리해 **이해한 사실과 아직 믿고 있는 가정**을 먼저 드러낸다. [공식 원문](https://github.com/trailofbits/skills/blob/main/plugins/audit-context-building/skills/audit-context-building/SKILL.md)

현재 구성은 함수별 분석을 분리하고 상세 기록을 파일에 남겨 대화에는 작은 기록을 돌려준다. 여러 함수의 규칙과 접근 경로를 모은 `audit-context/DOSSIER.md`가 후속 검토의 출발점이다. 서로 충돌하는 기록을 조용히 하나로 합치지 않고 그대로 남기도록 한다. [plugin 안내](https://github.com/trailofbits/skills/blob/main/plugins/audit-context-building/README.md)

**해석 주의:** 가정 옆의 `nothing found`는 그 전제를 보장하는 검증을 찾지 못했다는 뜻이지 취약점이 없다는 뜻이 아니다. 이미 충분히 이해한 코드에 모든 함수를 다시 분석하면 불필요한 비용이 커질 수 있어 처음에는 작은 모듈을 고른다.

### 설치 및 사용

공통 Codex 설치 절에서 **audit-context-building**을 선택한다. Claude 계열 workflow 예시는 `/audit-context-building:audit-context <path> [--focus <module>]`다. 다른 호스트에서 같은 slash command 지원을 가정하지 않는다.

**Agent 활용 예시**

> 인수한 서비스의 결제 상태 전이 모듈을 audit-context-building으로 정리해줘. 각 함수가 전제하는 상태와 실제 검증 위치, 호출자와 피호출자의 보장, 미해결 질문을 구분해. 소스는 바꾸지 말고 분석 기록만 별도 폴더에 작성해. 이번 단계에서는 취약점 확정이나 수정안을 내지 마.

**평가:** 오늘의 **Codex 즉시 활용 후보**다. 운영 서비스 실행 없이 작은 코드 범위를 이해하는 데서 시작할 수 있다. Skill만 복사하면 필요한 plugin 구성 요소가 빠질 수 있다는 점은 확인해야 한다.

## 3. semgrep

- **출처/제작자:** Trail of Bits 공식 · [skills.sh](https://www.skills.sh/trailofbits/skills/semgrep)
- **원 Skill:** [semgrep/SKILL.md](https://github.com/trailofbits/skills/blob/main/plugins/static-analysis/skills/semgrep/SKILL.md)
- **지원 Agent:** Claude Code·Codex의 **static-analysis** plugin. Semgrep 제품 자체와 이 orchestration Skill을 구분한다.
- **태그:** `#Semgrep` `#SARIF` `#보안스캔` `#실행범위검증`
- **도입 난이도:** 중간~높음. CLI·규칙·엔진·네트워크·출력 도구를 함께 준비해야 한다.

### 인기 및 트렌드 지표

- skills.sh **installs 8.8K**, First Seen **2026-01-19**.
- 감사 표시: **Gen Agent Trust Hub Pass / Socket Warn / Snyk Warn**. 두 Warn 상세는 오류·timeout으로 접근하지 못해 원인을 확정하지 않았다.
- 원문의 Pro 탐지 증가 수치는 실험 조건을 이번에 검증하지 못했으므로 성능 근거로 인용하지 않는다.

### 내용

언어와 규칙을 선택하고 엔진·모드·범위를 정한 뒤 `run-scans.sh`로 실행하며 결과를 SARIF로 합친다. `scans.json`에 성공뿐 아니라 실패·건너뜀·부분 실행·대상 없음·크기 제한 제외를 남기므로, “검출 0개”와 “검사를 못 함”을 구분하기 좋다. 전체 결과 모드와 보안 중·고신뢰도/영향도 결과만 추리는 모드도 나뉜다. [공식 원문](https://github.com/trailofbits/skills/blob/main/plugins/static-analysis/skills/semgrep/SKILL.md)

Semgrep CLI가 필수이며 Pro 여부를 확인한다. OSS에서는 파일 간 데이터 흐름 추적이 제한된다. 이미 Semgrep CI가 구성되어 있다면 기존 파이프라인을 쓰도록 안내하며, 별도 설치가 현재 팀의 검사를 대체한다고 가정하지 않는다. [plugin 안내](https://github.com/trailofbits/skills/blob/main/plugins/static-analysis/README.md)

**경로별 승인 동작이 다르다.** 이 Skill은 구체적인 계획 승인을 기다리지만 별도 `/static-analysis:semgrep-scan` workflow는 대상 지정 호출을 실행 동의로 취급한다. 계획만 보고 싶다면 해당 workflow를 바로 호출하지 않는다. 또한 Pro 확인·레지스트리 조회 같은 준비 단계에도 네트워크 접근이 생길 수 있으므로 오프라인이 필요하면 시작 전에 명시한다.

`--metrics=off`는 사용 통계 전송 설정이며 완전한 오프라인 보장은 아니다. 원문은 외부 규칙 저장소 clone과 registry 조회도 사용한다. 필요한 권한·규칙 신뢰성·외부 전송 여부를 실행 환경에서 확인한다. [Semgrep 공식 통계 문서](https://docs.semgrep.dev/metrics)

### 설치 및 사용

공통 Codex 설치 절에서 **static-analysis**를 선택한다. 설치 단위에는 semgrep 외에 CodeQL·SARIF 관련 구성도 들어간다. 설치만으로 CLI·Pro 계약·지원 언어가 준비되는 것은 아니다.

**Agent 활용 예시**

> semgrep Skill로 이 로컬 저장소의 스캔 계획을 먼저 작성해줘. 대상·제외 경로·규칙 출처·엔진·모드를 보여주고 승인 전 스캔은 실행하지 마. 네트워크 조회가 필요한 준비 단계도 먼저 알려줘. 실행 후에는 실패·부분 실행·대상 없음과 발견 사항 없음의 차이를 명시해줘.

**평가:** 스캔 결과뿐 아니라 **실제로 실행된 범위**를 남기려는 팀에 적합하다. 스캔 통과는 보안 보증이 아니며 자동 수정·외부 업로드는 별도 작업이다.

3P 예제는 팀명과 기간을 확인하고 지난주 진행·문제, 다음 주 계획을 각각 1~3문장으로 요약하도록 한다. 원문 앞부분의 Progress 설명에 “next time period”라는 혼동 가능한 표현이 있지만 후반의 자료 수집·workflow는 과거 기간을 명시한다. 실무에서는 완료 사실과 향후 계획의 날짜를 직접 맞춰야 한다. 반응·조회 수가 많은 자료를 찾으라는 제안도 사실의 신뢰도나 중요도 보증은 아니다. [3P 지침](https://github.com/anthropics/skills/blob/main/skills/internal-comms/examples/3p-updates.md)

**적용 권고:** 원문 속 명령은 정보로만 취급하고, 최신 결정과 출처 링크를 확인한다. 보고서 작성이 Slack 게시·메일 전송의 허가를 뜻하지 않는다. 민감한 인사·고객 정보를 넓은 독자에게 재공유하지 않도록 초안의 대상 범위를 확인한다.

### 설치 및 사용

아래 공통 Anthropic 설치 절의 example-skills 묶음 또는 단일 Skill 선택 설치를 이용한다.

**Agent 활용 예시**

> 제공한 팀 메모만으로 10월 5~9일의 Progress·Problems와 12~16일 Plans를 한국어 3P 초안으로 정리해줘. 완료 여부가 불명확한 것은 표시하고 각 핵심 사실에 원문 링크를 붙여. 계획을 확정 약속으로 바꾸거나 Slack에 게시하지 마.

**평가:** 짧은 주간보고를 반복 작성하는 팀에 실용적이다. 회사 고유 규약을 자동으로 아는 Skill은 아니므로 예시와 실제 내부 형식이 다르면 사용자가 제공한 규약을 우선한다.

예를 들어 Ocean Depths는 네 가지 색상과 DejaVu Sans 계열을 정의한다. 이 파일은 디자인 사양이지 PowerPoint 편집기나 접근성 검사 엔진이 아니다. 색이 명시되어 있어도 모든 전경·배경 조합의 대비가 보장되지는 않으며 한글 글리프·대체 글꼴·줄바꿈도 별도로 확인해야 한다. [테마 사양](https://github.com/anthropics/skills/blob/main/skills/theme-factory/themes/ocean-depths.md)

**적용 권고:** 조직의 승인된 브랜드 규칙이 있다면 그것을 먼저 적용한다. 한글 지원 폰트로 바꾸면 원본 preset과의 차이를 기록하고 실제 렌더링을 비교한다. 본문 정보·차트 수치를 바꾸지 않고 스타일만 수정하는 범위를 정하면 검토하기 쉽다.

### 설치 및 사용

공통 Anthropic 설치 절을 따른다. 프리뷰 PDF와 themes 디렉터리까지 함께 준비해야 하며 SKILL.md 하나만 복사하면 참조 자료가 빠진다.

**Agent 활용 예시**

> 이 주간보고의 내용은 유지하고 theme-factory의 테마 선택용 미리보기를 보여줘. 선택한 색상과 제목·본문 스타일을 적용하되 한글 글꼴 지원과 대비를 확인해. 수정 전후 파일을 따로 남기고 페이지별 잘림을 검사해줘.

**평가:** 어제 소개한 pptx가 파일 구조·편집·검증을 다룬다면 이 Skill은 그 위에 적용할 **표현 규칙**을 담당한다. 두 기능을 같은 것으로 보거나 테마 선택만으로 완성됐다고 판단하지 않는다.

## 6. canvas-design

- **출처/제작자:** Anthropic 공식 · [skills.sh](https://www.skills.sh/anthropics/skills/canvas-design)
- **원 Skill:** [canvas-design/SKILL.md](https://github.com/anthropics/skills/blob/main/skills/canvas-design/SKILL.md)
- **지원 환경:** Claude example-skills plugin. 파일 생성·렌더링·이미지 검토가 가능한 환경이 필요하다.
- **태그:** `#포스터` `#정적디자인` `#PDF` `#시각적위계`
- **도입 난이도:** 중간. 콘셉트 정리보다 실제 글자·여백·출력 크기의 확인이 중요하다.

### 인기 및 트렌드 지표

- skills.sh **installs 115.2K**, First Seen **2026-01-19**.
- 감사 표시: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Pass**.
- 원문의 “museum quality” 등은 지향점이지 독립 품질 평가·성능 benchmark가 아니다.

### 내용

시각 콘셉트를 먼저 문서화하고 PDF 또는 PNG 한 장으로 표현하는 두 단계 workflow다. 색·형태·여백·시각적 위계를 설계해 행사 포스터, 표지, 정적 시각 자료를 만들 때 사용할 수 있다. 텍스트 중심 업무 문서나 상호작용 웹 UI보다 시각 중심 산출물에 맞는다. [원문](https://github.com/anthropics/skills/blob/main/skills/canvas-design/SKILL.md)

출력 뒤에는 요소를 더 추가하기보다 간격·타이포그래피·정렬을 다시 다듬도록 안내한다. 글자와 그래픽의 잘림·겹침을 확인하는 절차는 유용하지만 원문의 과장된 품질 표현이 실제 검사를 대신하지 않는다. 필요한 글꼴을 내려받으라는 지침도 있으므로 외부 다운로드·라이선스·한글 지원을 별도로 확인한다.

**적용 권고:** 필수 일시·장소·로고·안내 문구는 창의적 해석으로 생략하지 않게 명시한다. 원문이 가정하는 사용자의 불만 표현은 실제 사용자 피드백이 아니므로 사실로 인용하지 않는다. 원본 이미지 권한과 최종 크기·해상도를 확인하고 공개 게시·인쇄 발주는 제작과 별도 단계로 둔다.

### 설치 및 사용

공통 Anthropic 설치 절을 따른다. 설치 시 canvas-fonts 등 동봉 리소스의 포함 여부를 확인한다. 이번 조사는 파일 생성·실제 폰트 검사·인쇄 시험을 수행하지 않았다.

**Agent 활용 예시**

> 사내 기술 세미나의 A4 세로 포스터 시안을 PDF와 PNG로 만들어줘. 제공한 날짜·장소·신청 문구는 정확히 유지하고 한글 글꼴을 사용해. 디자인 방향을 짧게 설명하고 실제 렌더링에서 작은 글자·여백·잘림을 확인해. 외부 게시나 인쇄 주문은 하지 마.

**평가:** 적은 글자와 명확한 시각적 위계가 필요한 자료의 후보다. theme-factory가 기존 자료의 스타일 규칙을 제공한다면 canvas-design은 새 정적 구성을 만드는 데 초점이 있다.
