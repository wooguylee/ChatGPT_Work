### 내용

터미널 Agent가 모델·데이터셋·논문을 찾고, 파일·캐시·저장소·Spaces·Jobs 등을 다룰 때 실제 `hf` 하위 명령을 선택하도록 돕는다. JSON 출력과 상태 조회를 쓸 수 있어 shell workflow에 붙이기 좋다. 앞서 소개한 `hf-mcp`와 일부 기능은 겹치지만, 이번 항목은 **설치된 CLI 명령을 사용하는 별도 Skill**이다. 이전 보고서의 설치 설명에서 언급된 적은 있어도 독립 소개 항목으로는 처음이다. [현재 명령 목록](https://github.com/huggingface/skills/blob/main/skills/hf-cli/SKILL.md)

이름이 고정된 정적 문서만 배포하는 방식도 아니다. 현재 구현은 로컬 CLI 정의에서 기본 `hf-cli` 문서를 생성하고, 다른 전문 Skill은 marketplace에서 가져온다. 따라서 설치된 CLI와 Skill 내용의 버전을 맞추는 것이 중요하다. 과거의 호스트별 플래그를 복사하기보다 현행 `--global`·`--dest`와 설치 위치를 확인한다. [생성·설치 구현](https://github.com/huggingface/huggingface_hub/blob/main/src/huggingface_hub/cli/skills.py), [설치 도우미](https://github.com/huggingface/huggingface_hub/blob/main/src/huggingface_hub/cli/_skills.py)

검색만 하는 Skill은 아니다. 업로드·삭제·계정 인증·유료 원격 실행도 다루므로 사용 범위를 좁혀 시작한다. 특히 Jobs 로그에서 **Ctrl+C를 눌러도 원격 작업은 계속**되며 별도 취소가 필요하다. 현재 Jobs 조건은 양수의 크레딧 잔액이고 Starting/Running 동안 분 단위로 과금된다. 오래된 PRO 필수 설명을 재사용하지 않는다. [Jobs quickstart](https://huggingface.co/docs/hub/jobs-quickstart), [현재 과금 조건](https://huggingface.co/docs/hub/jobs-pricing)

### 설치 및 사용

`hf` CLI가 준비된 프로젝트에서 기본 Skill 설치:

```bash
hf skills add
```

사용자 전역 설치는 `hf skills add --global`이다. 공식 standalone 설치기는 CLI와 전역 Skill을 함께 설치하지만 pip/Homebrew 경로는 Skill 추가가 별도일 수 있다. Python 패키지 경로의 현재 요구사항은 **Python 3.10 이상**이다. 이미 설치된 CLI·환경을 확인하고 필요한 범위만 선택한다. [Agent 설치 안내](https://huggingface.co/docs/hub/agents-cli), [CLI 설치 문서](https://huggingface.co/docs/huggingface_hub/guides/cli), [Python 요구사항](https://github.com/huggingface/huggingface_hub/blob/main/setup.py)

공개 모델 목록을 JSON으로 조회하는 예:

```bash
hf models list --pipeline-tag text-generation --limit 5 --format json
```

**전제조건:** Agent가 shell과 `hf`에 접근할 수 있어야 한다. 공개 조회에 불필요한 토큰을 요구하지 않는다. private 자료·쓰기 작업은 승인된 인증 경로를 사용하며 토큰을 프롬프트·예제·로그에 노출하지 않는다. `hf auth login`은 인증 정보를 저장하는 단계이므로 일반 검색과 구분한다. [인증 문서](https://huggingface.co/docs/huggingface_hub/package_reference/authentication)

**Agent 활용 예시**

> hf-cli로 공개 텍스트 생성 모델 5개를 찾고 카드·라이선스·필요 메모리를 비교해줘. 다운로드·업로드·유료 작업은 실행하지 말고, 실제로 확인한 값과 카드에 없는 내용을 구분해줘.

**평가:** 오늘의 Top Pick이다. 기본 검색부터 시작해 다운로드 준비·작업 상태 조회로 확장하기 쉽고, 현재 CLI와 동기화되는 경로가 명확하다. 인기도보다 **명령·권한·실행 결과를 구분하기 쉬운 점**을 기준으로 골랐다.

### 내용

provider·버전 제약부터 시작해 입력 변수, 의존 관계, 출력과 파일 구성을 정리하는 HCL 작성 지침이다. 이름·타입·설명·검증 조건을 일관되게 남기고 formatter와 구성 검증을 연결한다. 어제 소개한 `refactor-module`의 state 주소 이전보다 **일상적인 작성·검토 규약**에 초점이 있다. [공식 Skill](https://github.com/hashicorp/agent-skills/blob/main/plugins/terraform/skills/terraform-style-guide/SKILL.md)

스타일 개선 요청을 dependency upgrade나 자원 재생성으로 확대하지 않는 것이 중요하다. 원문의 Terraform·AWS provider 버전과 region·AMI는 예시이며 기존 lockfile과 호환 조건을 우선한다. `count`를 `for_each`로 바꾸거나 이름을 통일하면 자원 주소도 달라질 수 있으므로 단순 서식 변경과 나눠 검토한다. 실제 적용 여부는 plan과 migration 검토로 판단한다. [공식 스타일 가이드](https://developer.hashicorp.com/terraform/language/style)

`sensitive = true` 역시 출력 가림과 저장 방지를 구분해야 한다. plan·state에 값이 남을 수 있으므로 해당 파일을 공개 저장소나 로그에 올리지 않는다. 자격증명은 필요한 환경의 보안 설계와 값의 생명주기에 맞게 다룬다. [민감 데이터 공식 안내](https://developer.hashicorp.com/terraform/language/manage-sensitive-data)

### 설치 및 사용

현재 product plugin 디렉터리를 지정한 개별 설치:

```bash
npx skills add hashicorp/agent-skills/plugins/terraform/skills/terraform-style-guide --agent codex
```

이미 초기화된 프로젝트에서 변경 없이 서식을 검사하는 예:

```bash
terraform fmt -check -recursive
terraform validate
```

**전제조건:** Terraform과 필요한 module/provider가 준비되어 있어야 한다. `fmt -check`와 실제 파일을 바꾸는 `fmt`를 구분한다. `validate`는 구성의 내부 일관성을 검사하며 계정 권한·실제 인프라 변경의 성공까지 증명하지 않는다. 초기화가 필요하면 다운로드·lockfile·backend 영향을 먼저 검토한다. [fmt 문서](https://developer.hashicorp.com/terraform/cli/commands/fmt), [validate 문서](https://developer.hashicorp.com/terraform/cli/commands/validate)

**Agent 활용 예시**

> 이 모듈을 공식 Terraform 스타일과 비교해줘. 먼저 서식 검사와 변수·출력 설명의 누락을 보고해. provider 버전, lockfile, 자원 이름과 count/for_each는 유지하고, 주소나 동작이 바뀌는 제안은 별도 목록으로 분리해줘.

**평가:** 작은 팀이 생성형 AI의 Terraform 출력에 공통 규약을 적용하기 좋은 후보다. 스타일·정적 검증·인프라 plan의 역할을 구분할 때 효과적이다.

### 인기 및 트렌드 지표

- skills.sh의 `www` 상세 페이지: **installs 5.4K**, First Seen **2026-01-26**, 검색 도구에는 **당일 크롤링**으로 표시됐다.
- 감사 표시: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Pass**
- HashiCorp Agent Skills 모음 전체: **887 stars / 130 forks**
- 현재 metadata는 lifecycle **active**, Skill version **0.0.1**이다. Terraform CLI·Stacks plugin 버전과 다른 값이다.
- 다른 URL에서 조회된 지난달 캐시의 5.0K·Snyk Warn은 현재 상세 페이지 표시와 달라 최신값으로 합치지 않았다. 이것만으로 감사 상태가 실제 개선됐다고 단정하지 않는다.

### 내용

여러 module을 component로 묶고 dev·staging·production 또는 region별 deployment에 입력을 연결하는 지침이다. `.tfcomponent.hcl`과 `.tfdeploy.hcl`은 일반 `.tf` 파일과 문법이 다르다. provider 구성, component 출력, OIDC identity, 배포 간 연결과 상태 관찰을 함께 다룬다. 기존 Terraform 테스트·import·module 분리 Skill과는 **여러 배포 단위를 조율하는 층**이 다르다. [공식 Skill](https://github.com/hashicorp/agent-skills/blob/main/plugins/terraform/skills/terraform-stacks/SKILL.md)

**예제를 그대로 적용하기 전에 현재 제품 문서로 교정해야 한다.** SKILL.md와 deployment reference의 group 연결 방식이 서로 다르다. 현재 문서는 deployment의 `deployment_group`과 group의 `auto_approve_checks`로 연결하며, reference의 `group.deployments`나 auto-approve 블록 안의 group 지정 예시를 복사하면 안 된다. 요금제도 Skill은 Premium, 현재 orchestration 문서는 **Plus Edition**으로 표시한다. 실제 계정 자격은 별도 확인한다. [공식 배포 조건 문서](https://developer.hashicorp.com/terraform/language/stacks/deploy/conditions), [검토한 reference](https://github.com/hashicorp/agent-skills/blob/main/plugins/terraform/skills/terraform-stacks/references/deployment-blocks.md)

또한 일반 `terraform plan/apply`처럼 생각하면 위험하다. **구성 업로드가 deployment run을 촉발**할 수 있다. 현재 CLI는 `configuration upload -speculative`로 deployment를 촉발하지 않는 검증용 업로드를 지원하지만 여전히 외부 전송이다. 로컬 검증, 검증용 업로드, 실행되는 업로드와 승인·파괴를 각각 구분한다. [현재 upload 옵션](https://developer.hashicorp.com/terraform/cli/commands/stacks/configuration/upload)

### 설치 및 사용

```bash
npx skills add hashicorp/agent-skills/plugins/terraform/skills/terraform-stacks --agent codex
```

module/provider와 lockfile을 준비한 Stack의 로컬 확인:

```bash
terraform stacks validate
```

**전제조건:** 공식 Skill은 **Terraform 1.13 이상**과 Stacks CLI 경로를 요구한다. `stacks init`·`providers-lock` 등의 준비는 의존성 다운로드와 로컬 파일 변경을 수반한다. 준비된 구성의 `stacks validate`는 원격 state·provider API와 상호작용하지 않고 검사한다. 원격 실행에는 대상 HCP Terraform 또는 지원되는 Terraform Enterprise 환경의 조직·프로젝트·Stack 접근과 필요한 cloud 권한이 별도로 필요하다. OIDC 구성도 신뢰·접근 권한 변경이므로 검토 없이 자동 설정하지 않는다. [validate 문서](https://developer.hashicorp.com/terraform/cli/commands/stacks/validate)

**Agent 활용 예시**

> 기존 네트워크와 앱 module을 두 region의 Stack으로 구성하는 초안을 만들어줘. 현재 Stack 문법과 module 호환성을 확인하고 로컬 검증 결과를 정리해. upload, auto-approval, OIDC 신뢰 설정과 실제 배포는 실행하지 말고 검토할 변경안으로 남겨줘.

**평가:** 여러 환경을 운영하는 팀의 **검토형 후보**다. 구성 구조를 이해하는 데 유용하지만 오래된 문법·요금제·업로드 부작용을 현재 제품 문서로 보완해야 한다.

## 4. find-bugs

- **출처/제작자:** [Sentry 공식 Skills](https://github.com/getsentry/skills), [skills.sh 항목](https://www.skills.sh/getsentry/skills/find-bugs)

- **태그:** `#코드리뷰` `#브랜치검증` `#변경범위` `#보안점검`
- **도입 난이도:** 낮음~중간. 저장소·비교 기준에 접근할 수 있어야 하며 큰 diff의 검토 비용이 늘어난다.

### 인기 및 트렌드 지표

- skills.sh: **installs 6.5K**, First Seen **2026-01-20**, 검색 도구에는 **당일 크롤링**으로 표시됐다.
- 감사 표시: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Pass**
- Sentry Skills 모음 전체: **1,038 stars / 53 forks**
- 버그 탐지율·오탐률·독립 품질점수는 확인하지 못했다. 감사 배지는 검토 결과의 정확성을 보장하지 않는다.

### 내용

브랜치 변경 전체를 읽고 입력·데이터베이스·권한·상태·외부 호출을 확인한 뒤, 의심되는 문제를 주변 코드와 테스트로 검증하는 절차다. 보고서에는 위치·심각도·근거·수정 제안을 남기며 스타일 지적은 제외한다. 끝내 확인하지 못한 범위도 적고, 실제 문제가 없으면 억지로 만들지 않는다. 원문은 **코드를 수정하지 않고 발견 사항만 보고**하게 한다. [공식 Skill](https://github.com/getsentry/skills/blob/main/skills/find-bugs/SKILL.md)

**검토 범위는 실행 전에 보완해야 한다.** 원문의 `기본브랜치...HEAD` 명령은 merge-base 이후 커밋된 변경을 비교하므로, 수정 중인 파일·staged 변경·untracked 파일까지 자동 포함하지 않는다. GitHub에서 기본 브랜치 이름을 조회하는 것만으로 로컬 기준 ref가 최신이 되는 것도 아니다. PR의 실제 base와 현재 작업 상태를 먼저 확인하고, 미커밋 변경을 포함할지는 명시한다. [Git diff 공식 문서](https://git-scm.com/docs/git-diff)

기존 `code-review`가 일반적인 설계·품질 검토에 가깝다면, 이번 항목은 **브랜치 diff의 빠진 부분과 검토 증거**를 관리하는 데 유용하다. 체크리스트를 모두 읽었다는 사실만으로 안전성이 증명되는 것은 아니다. 방어 코드·실제 입력 경로를 확인하지 못하면 결론의 범위를 좁혀야 한다.

### 설치 및 사용

```bash
npx skills add getsentry/skills --skill find-bugs --agent codex
```

**전제조건:** 로컬 Git 저장소와 비교할 ref, 파일 읽기·검색 도구가 필요하다. 원문의 기본 브랜치 자동 조회에는 GitHub CLI와 해당 저장소 조회 접근이 필요하지만, 검증된 base ref를 직접 지정하는 방식으로 적용할 수 있다. Skill 설치가 저장소 쓰기나 Sentry 프로젝트 접근 권한을 만들지는 않는다. [공식 설치 안내](https://github.com/getsentry/skills/blob/main/README.md)

**Agent 활용 예시**

> 이번 브랜치를 find-bugs 절차로 검토해줘. 먼저 실제 PR base와 미커밋·미추적 파일 유무를 확인하고 검토 범위를 적어줘. 변경 파일 전체와 관련 호출 경로를 읽고, 근거가 있는 문제·확인하지 못한 부분을 구분해. 코드 수정과 리뷰 게시 없이 결과만 보여줘.

**평가:** 오늘의 Codex 즉시 활용 후보다. 별도 서비스 설치보다 **무엇을 읽었는지 확인하는 습관**을 추가하기 쉽다. 리뷰 범위와 실제 테스트 결과를 함께 기록하는 조건으로 추천한다.

## 5. secret-serialization

- **출처/제작자:** [Sentry 공식 Skills](https://github.com/getsentry/skills)
- **원 Skill:** [secret-serialization/SKILL.md](https://github.com/getsentry/skills/blob/main/skills/secret-serialization/SKILL.md)
- **지원 Agent:** Sentry Warden의 선택적 검토와 표준 Skill 호스트. 원문의 도구 범위는 `Read Grep Glob`이며 실제 적용은 호스트의 권한 체계를 따른다.
- **태그:** `#비밀정보보호` `#직렬화` `#로그` `#관측데이터`
- **도입 난이도:** 중간. 언어·serializer별 동작과 전체 호출 경로를 읽어야 한다.

### 인기 및 트렌드 지표

- Sentry Skills 모음 전체: **1,038 stars / 53 forks**
- 개별 installs·skills.sh First Seen·감사 상태: **미확인**. 상세 페이지 접근 및 검색으로 확인하지 못했으며 0으로 간주하지 않았다.
- 공식 Git 이력에서는 **2026-09-25 20:53 UTC(9월 26일 05:53 KST)**의 추가 커밋과 **9월 28일 UTC**의 후속 수정이 확인된다. 이는 저장소 변경 이력이며 제품 출시일·보급 증가율은 아니다. [추가 커밋](https://github.com/getsentry/skills/commit/bdf13570f7ff87af59cfd8d640422370f671c6b9), [후속 수정](https://github.com/getsentry/skills/commit/473d2594cd91c96ac8348f297e016b631e842487)

### 내용

키 문자열을 직접 출력하는 코드만 찾는 대신, **자격증명을 가진 객체와 객체 전체를 기록하는 지점**을 연결해 조사한다. 새 config 필드가 오래된 로깅·tracing 코드로 흘러갈 수 있으므로 diff 밖의 생성자·호출자까지 추적한다. 도달 경로가 확인된 경우와 잠재적 노출 가능성을 구분한다. 하드코딩된 키·커밋된 `.env`를 찾는 일반 secret scanner와 범위가 다르다. [공식 Skill](https://github.com/getsentry/skills/blob/main/skills/secret-serialization/SKILL.md)

Python reference의 핵심은 `repr=False`만으로 `asdict()`나 다른 serializer까지 막았다고 판단하지 않는 것이다. Pydantic의 표시 제외와 dump 제외, raw attribute 접근도 따로 본다. 테스트에서는 운영 키 대신 가짜 표식 문자열을 쓰고 **실제 출력 지점이 사용하는 serializer**로 누출 여부를 검사한다. [Python reference](https://github.com/getsentry/skills/blob/main/skills/secret-serialization/references/python.md)

**JavaScript reference에는 대조가 필요한 설명이 있다.** 원문은 Sentry normalizer가 `toJSON()`을 무시한다고 적지만, 이번에 읽은 Sentry JavaScript `develop` 구현은 해당 메서드를 호출한다. 이를 모든 배포 버전의 동작으로 일반화하지 말고 프로젝트의 정확한 SDK 버전·경로로 확인한다. 또한 `enumerable: false`는 Node의 `util.inspect(..., { showHidden: true })`까지 막지 않는다. 원문의 “모든 경로 제외”를 절대적인 보안 보장으로 읽으면 안 된다. [Skill JS reference](https://github.com/getsentry/skills/blob/main/skills/secret-serialization/references/javascript-typescript.md), [조회한 SDK 구현](https://github.com/getsentry/sentry-javascript/blob/ca05d2de8d698310757d51030789a5c01fdf5132/packages/core/src/utils/normalize.ts), [Node 공식 옵션](https://nodejs.org/api/util.html#utilinspectobject-options)

### 설치 및 사용

```bash
npx skills add getsentry/skills --skill secret-serialization --agent codex
```

**전제조건:** 변경 코드와 주변 호출자를 읽을 수 있어야 한다. 기본 검토에는 운영 자격증명·로그 다운로드·외부 전송이 필요하지 않다. 원문의 유지보수 사양도 이를 **선택적으로 쓰는 전문 검토**로 분류한다. credential 이름·타입·출처가 불명확하면 놓칠 수 있고 언어별 reference는 Python과 JS/TS 중심이다. [SPEC와 제한](https://github.com/getsentry/skills/blob/main/skills/secret-serialization/SPEC.md)

**Agent 활용 예시**

> config에 추가한 credential 필드가 repr, asdict, model_dump, JSON.stringify 또는 로그·span으로 나갈 수 있는지 조사해줘. diff 밖의 기존 출력 지점도 추적해. 실제 키는 읽거나 출력하지 말고 가짜 표식으로 만들 회귀 테스트를 제안해. serializer 버전과 옵션이 불명확하면 확인 필요로 남겨줘.

**평가:** AI 도구 인자와 config 객체를 통째로 관측 시스템에 넣는 코드의 **집중 검토 후보**다. 방법론은 유용하지만 현재 reference의 일반화를 교정해야 하므로 자동 보안 인증처럼 사용하지 않는다.
