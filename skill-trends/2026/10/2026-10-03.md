### 지표를 읽는 방법

- **Installs는 skills.sh가 표시한 값**이다. 독립적으로 검증한 사용자 수·활성 사용량·고유 설치 수가 아니며, 설치 성공을 직접 재현한 것도 아니다.
- **GitHub stars/forks는 저장소 전체 지표**다. 여러 Skill을 가진 저장소에서는 해당 Skill 하나의 인기와 동일하지 않다. 표의 정확한 숫자는 조사 중 GitHub API에서 조회했다.
- skills.sh의 **Trending(24h)**는 화면의 분류와 표시값을 그대로 인용했다. 이전 시점과 같은 조건의 비교 자료가 없으므로 순위 상승이나 증가율은 계산하지 않았다.
- **Pass/Warn은 디렉터리 감사 상태**일 뿐 안전성 보증이 아니다. 감사 범위·날짜·실제 설치할 revision을 별도로 확인해야 한다.
- 아래 “지원 Agent”에서 **설치 대상**과 **제작자가 명시한 지원**을 구분했다. `skills` CLI는 Codex, Claude Code, Cursor, GitHub Copilot 등으로 설치할 수 있지만, shell context 주입·hooks 같은 기능이 모든 호스트에서 똑같이 작동한다고 보장하지 않는다. [CLI 원문 및 호환성](https://github.com/vercel-labs/skills#compatibility)

## 1. vgpu

- **출처:** [skills.sh](https://www.skills.sh/vercel-labs/vgpu/vgpu), [SkillsMP 커뮤니티 발견 경로](https://skillsmp.com/)
- **GitHub:** [vercel-labs/vgpu](https://github.com/vercel-labs/vgpu)
- **원 Skill:** [skills/vgpu/SKILL.md](https://github.com/vercel-labs/vgpu/blob/canary/skills/vgpu/SKILL.md)
- **제작자/조직:** Vercel Labs
- **지원 Agent:** 공식 README는 Skill을 지원하는 coding agent를 대상으로 안내한다. `skills` CLI 설치 대상에는 Codex, Claude Code, Cursor, GitHub Copilot 등이 포함된다. 특정 호스트만의 전용 통합을 전제로 하는 Skill은 아니다.

### 인기 및 트렌드 지표

- skills.sh 표시 **installs 1.3K**, First Seen **2026-07-23**
- GitHub API 조회 **2,405 stars / 120 forks**
- skills.sh 감사 표시: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Pass**
- SkillsMP 첫 화면에서 vgpu의 Blender·베이킹 관련 커뮤니티 소개를 확인했다. 이는 **발견 신호**이며 Skill 최초 출시일이나 채택 증가의 증거로 사용하지 않았다.
- 확정된 24시간 설치 증가 / 순위 상승 / 좋아요 / 독립 품질점수: **미확인**

### 내용

vgpu는 TypeScript에서 WebGPU를 다루는 라이브러리이며, Skill의 핵심은 API를 기억해 두는 대신 **현재 프로젝트에 설치된 패키지의 문서를 읽는 절차**다. manifest와 lockfile을 먼저 확인하고, 패키지를 새로 내려받지 않는 방식으로 로컬 CLI 버전을 식별한다. 이어 `docs ls`, `docs find`, `docs cat`으로 필요한 문서만 읽는다. 저장소 기본 브랜치가 `canary`여도 프로젝트를 prerelease로 바꾸지 않으며, 원격 최신 문서를 설치 버전의 근거로 대신 쓰지 않는다. [공식 Skill](https://github.com/vercel-labs/vgpu/blob/canary/skills/vgpu/SKILL.md)

특히 [Blender 자산 가이드](https://github.com/vercel-labs/vgpu/blob/canary/skills/vgpu/blender/index.md)는 모델링에서 끝나지 않는다. 원본·HIGH·LOW·베이킹 결과를 같은 카메라와 조명으로 비교하고, 실루엣·UV·normal/AO·LOD·runtime material을 확인한다. 삼각형 수가 줄었다는 이유만으로 FPS 개선을 주장하지 않고, 다운로드 크기·GPU 메모리·draw call·실제 frame timing을 구분하도록 한다. 생성한 참고 이미지를 구현 결과의 검증 자료로 대신 쓰지 않는 점도 실무적이다.

### 설치 및 사용

```bash
npx skills add vercel-labs/vgpu --skill vgpu --agent codex
```

**전제조건:** Skill 설치와 실제 렌더링 환경 준비는 별개다. 런타임 구현에는 프로젝트가 선택한 `vgpu` 패키지와 JavaScript/TypeScript 도구 환경이 필요하다. 브라우저 렌더링은 WebGPU 지원 환경, Blender 자산 작업은 Blender와 대상 프로젝트의 export/import 규칙이 필요하다. 일반 문서 조회 자체에 별도 API Key는 명시돼 있지 않다. 로컬 mock 테스트가 실제 GPU 성능을 증명하지는 않는다. [공식 README](https://github.com/vercel-labs/vgpu/blob/canary/README.md)

기존 프로젝트에서는 먼저 로컬 버전을 확인한다.

```bash
npm exec --no -- vgpu --version
npm exec --no -- vgpu docs --help
npm exec --no -- vgpu docs cat getting-started.md
```

**Agent 활용 예시**

> 이 프로젝트에 설치된 vgpu 버전을 유지해. Blender로 만든 제품 모델을 웹에 넣기 전에 원본과 LOW 자산을 같은 카메라에서 비교하고, normal/AO와 LOD를 점검해줘. 실제 브라우저 캡처와 전후 메모리·파일 크기를 남기고, 측정하지 않은 FPS 개선은 주장하지 마.

**평가:** 시각 결과와 비용을 실제로 검증하는 절차가 강점이다. 특히 3D 자산을 웹 제품에 넣는 팀에 가치가 높다. 반면 일반 CRUD 앱에는 활용 범위가 좁으며, Skill을 설치한다고 Blender·GPU·렌더러 설정까지 자동으로 준비되지는 않는다.

## 2. shadcn

- **출처:** [skills.sh의 shadcn-ui/ui 항목](https://www.skills.sh/shadcn-ui/ui/shadcn), [공식 Skills 문서](https://ui.shadcn.com/docs/skills)
- **GitHub:** [shadcn-ui/ui](https://github.com/shadcn-ui/ui)
- **원 Skill:** [skills/shadcn/SKILL.md](https://github.com/shadcn-ui/ui/blob/main/skills/shadcn/SKILL.md)
- **제작자/조직:** shadcn/ui
- **지원 Agent:** 공식 문서는 Claude Code 같은 AI assistant를 예로 든다. Codex·Cursor 등에는 `skills` CLI로 설치할 수 있다. 다만 `!` shell context 주입이 실제 사용하는 호스트에서 자동 실행되는지는 별도 확인이 필요하다. 자동 주입을 확인할 수 없으면 프로젝트 설정을 CLI로 명시적으로 읽어야 한다.

### 인기 및 트렌드 지표

- canonical 저장소 이름에 해당하는 skills.sh 항목: **installs 86.4K**, First Seen **2026-03-06**
- GitHub API 조회 **125,028 stars / 11,959 forks**
- skills.sh 감사 표시: **Gen Agent Trust Hub Pass / Socket Warn / Snyk Pass**
- 해당 페이지는 shell command directive 포함 경고도 표시한다. **Socket 상세 사유는 이번 조회에서 확인되지 않아 추정하지 않았다.**
- `shadcn/ui` 별도 목록과 `shadcn-ui/ui` 목록의 수치를 합산하지 않았다.
- 확정된 24시간 증가 / 순위 변화 / 좋아요 / 독립 품질점수: **미확인**

### 내용

이 Skill은 컴포넌트 이름만 알고 코드를 만들어내는 대신, `shadcn info --json`을 통해 **현재 프로젝트의 framework, Tailwind 버전, alias, primitive base, icon library, 설치된 컴포넌트**를 먼저 읽게 한다. 그 다음 registry 검색과 `shadcn docs`로 실제 사용법을 확인한다. 예를 들어 Radix의 `asChild`와 Base UI의 `render`를 섞거나, 설치하지 않은 컴포넌트를 import하는 오류를 줄이는 방식이다. [공식 안내](https://ui.shadcn.com/docs/skills)

원문에는 form의 Field 구성, dialog title 접근성, semantic color, chat UI 조립 같은 구체적 규칙이 있다. 기존 컴포넌트를 갱신할 때는 `--dry-run`과 `--diff`로 사용자 수정을 비교하고, 명시적 동의 없이 `--overwrite`를 사용하지 않도록 한다. registry가 불분명할 때 임의 선택하지 않는 점도 중요하다. 미관 지침보다 **현재 프로젝트와 upstream 컴포넌트 사이의 계약을 유지하는 도구**에 가깝다. [공식 Skill](https://github.com/shadcn-ui/ui/blob/main/skills/shadcn/SKILL.md)

### 설치 및 사용

canonical GitHub 저장소를 지정한 개별 설치:

```bash
npx skills add https://github.com/shadcn-ui/ui --skill shadcn --agent codex
```

공식 웹 문서는 `pnpm dlx skills add shadcn/ui` 형태도 안내한다. 위 명령은 확인한 canonical 저장소의 개별 Skill을 지정한 것이다.

**전제조건:** Node.js와 프로젝트에 맞는 package runner가 필요하다. 기존 프로젝트는 `components.json` 등 실제 설정이 있어야 맥락을 읽을 수 있다. CLI가 registry·문서를 조회할 수 있어야 하며, 일반 공개 컴포넌트 작업에는 별도 AI API Key나 MCP 서버가 필수는 아니다. 외부 registry의 코드는 설치 전에 검토하고, `@latest` CLI 실행을 허용하는 범위를 확인하는 것이 좋다.

```bash
npx shadcn@latest info --json
npx shadcn@latest docs dialog select
npx shadcn@latest add dialog --dry-run
```

**Agent 활용 예시**

> 이 프로젝트의 components.json과 실제 base library부터 확인해. @shadcn 컴포넌트로 설정 페이지를 만들되, 현재 아이콘·색상 토큰·alias를 유지해줘. 기존 dialog 수정은 dry-run과 diff를 먼저 확인하고 내 변경을 보존해.

**평가:** shadcn 기반 프런트엔드에는 적용 효과가 구체적이고, 잘못된 API 조합과 스타일 이탈을 함께 줄일 수 있다. 다만 shell 실행 지침과 Socket Warn을 무시한 무조건 설치는 권하지 않는다. host별 자동 context 주입 차이와 프로젝트의 오래된 컴포넌트도 점검해야 한다.

## 3. prisma-orm-setup

- **출처:** [Prisma Skills 공식 README](https://github.com/prisma/skills), [기존 이름의 skills.sh 항목](https://www.skills.sh/prisma/skills/prisma-database-setup)
- **원 Skill:** [prisma-orm-setup/SKILL.md](https://github.com/prisma/skills/blob/main/prisma-orm-setup/SKILL.md)
- **제작자/조직:** Prisma
- **지원 Agent:** 공식 저장소가 Agent Skills 형식과 `npx skills add` 호환을 명시한다. Codex, Claude Code, Cursor, GitHub Copilot 등 설치 대상에서 지침을 사용할 수 있지만, 실제 DB 접근에는 각 호스트의 shell·환경변수·네트워크 권한이 필요하다.

### 인기 및 트렌드 지표

- GitHub API 조회: `prisma/skills` **68 stars / 7 forks**
- Skill metadata: **author prisma / version 1.0.0 / MIT**
- 새 이름 `prisma-orm-setup`의 개별 installs / First Seen / 순위 / 보안점수: **미확인**
- **기존 `prisma-database-setup`의 설치 수를 새 이름으로 이전해 계산하지 않았다.** 기존 항목의 현재 `SKILL.md`는 deprecated 안내와 새 Skill로의 연결만 담고 있다.

### 내용

오늘 중요한 발견은 디렉터리의 기존 요약과 원문 사이의 차이다. `prisma-database-setup` 페이지의 설명은 과거 설정 지침을 보여주지만, 실제 Skill 본문은 `prisma-orm-setup`을 읽으라고 안내한다. 새 Skill은 **신규 앱은 Prisma ORM 8 경로로 안내하면서, 기존 Prisma 6/7 앱의 연결 수리는 현재 버전에서 수행**하도록 구분한다. 최신이라는 이유만으로 기존 프로젝트를 major upgrade하지 않는 것이 핵심이다. [현재 공식 README](https://github.com/prisma/skills/blob/main/README.md)

CLI 버전 하나만 보지 않고 lockfile·client package·schema·설정·import를 함께 확인한다. Prisma 8은 `prisma skills sync`로 설치 패키지가 제공하는 `prisma-8` 지침을 동기화한 뒤 실제로 읽게 하며, 지원 provider와 runtime 요구사항을 선택한 release 기준으로 확인한다. 끝에는 패키지 설치 성공이 아니라 **앱의 client를 통한 대상 DB의 read-only query**와 프로젝트 검사를 요구한다. 기존 schema·migration은 작업에 필요하지 않으면 건드리지 않는다. [원 Skill](https://github.com/prisma/skills/blob/main/prisma-orm-setup/SKILL.md)

### 설치 및 사용

```bash
npx skills add prisma/skills --skill prisma-orm-setup --agent codex
```

**전제조건:** Prisma 버전에 맞는 runtime·package manager와 접근 가능한 DB가 필요하다. DB credential은 별도로 안전하게 제공해야 하며 로그에 출력하지 않는다. 신규 Prisma 8 설정은 선택한 release의 provider 지원과 runtime 요구사항을 먼저 확인하고 정확한 release를 고정한다. 기존 6/7 연결 오류를 고치는 데 8 설치나 새 DB provisioning이 필수인 것은 아니다.

Prisma 8 프로젝트에서 지침을 가져오는 단계는 다음과 같으며, 프로젝트에 설치된 CLI를 package manager로 실행한다.

```bash
prisma skills sync
# 이후 동기화된 prisma-8/SKILL.md를 실제로 읽는다.
```

**Agent 활용 예시**

> 이 앱의 Prisma 연결 오류를 고쳐줘. CLI와 client 버전을 따로 확인하고 현재 major version과 DB를 유지해. schema 변경이나 새 DB 생성은 하지 말고, 앱이 실제 사용하는 환경을 확인한 뒤 read-only query로 연결 성공을 증명해.

**평가:** 여러 Prisma 세대가 공존하는 환경에서 오래된 recipe를 섞는 문제를 줄여준다. 설치 수가 검증되지 않아 인기 급상승 후보로 평가할 수는 없지만, **deprecated 이름을 걸러내고 설치 버전의 공식 지침으로 연결한다는 실용성**은 높다. DB 연결 수리와 migration 승인을 분리해서 사용하는 것이 좋다.

## 6. verification-before-completion

- **출처:** [skills.sh](https://www.skills.sh/obra/superpowers/verification-before-completion)
- **GitHub:** [obra/superpowers](https://github.com/obra/superpowers)

### 인기 및 트렌드 지표

- skills.sh **installs 228.8K**, First Seen **2026-01-19**
- GitHub API 조회 **294,681 stars / 26,336 forks**. 모두 Superpowers 모음 전체 지표다.
- 감사 표시: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Pass**
- AgentSkill.sh 검색에는 다른 계정이 수록한 같은 이름의 사본이 보였다. 해당 사본의 별점·보안점수는 **obra 원본의 지표로 가져오지 않았다.**
- 원본의 독립 품질점수 / 좋아요 / 확정된 순위 변화·24시간 증가: **미확인**

### 내용

핵심은 완료 주장 전에 **무엇이 증거인지 정하고 → 전체 명령을 새로 실행하고 → 출력·exit code·실패 수를 읽고 → 증거가 뒷받침하는 만큼만 말하는 것**이다. lint 성공은 build 성공이 아니며, 파일 수정은 버그 재현 테스트 통과가 아니고, 다른 Agent의 “완료” 보고도 독립 검증을 대신하지 못한다. [원 Skill](https://github.com/obra/superpowers/blob/main/skills/verification-before-completion/SKILL.md)

테스트·빌드·회귀 검증·요구사항 확인을 서로 다른 주장으로 취급하는 점이 유용하다. 예를 들어 bug fix라면 원래 증상에 대한 검증이 필요하고, 회귀 테스트라면 수정 전 실패와 수정 후 통과가 실제로 성립하는지 확인한다. 요구사항은 체크리스트로 다시 읽는다. 검증 도구 자체를 제공하는 것이 아니라, 기존 도구를 **정직하게 사용하는 행동 규칙**이다.

### 설치 및 사용

개별 Skill을 Codex 프로젝트에 설치:

```bash
npx skills add obra/superpowers --skill verification-before-completion --agent codex
```

원 저장소는 Codex App/CLI의 공식 plugin marketplace에서 **Superpowers 전체 plugin**을 설치하는 방법도 안내한다. 이미 Superpowers를 사용 중이면 동일 Skill을 중복 설치하기보다 현재 버전과 로딩 상태를 먼저 확인한다. [제작자 설치 안내](https://github.com/obra/superpowers#installation)

**전제조건:** 별도 API Key·SaaS·MCP 서버는 필요하지 않다. 대신 검증할 repository와 실제 실행 가능한 테스트·빌드 명령이 있어야 한다. dependency나 secret 부족으로 검사할 수 없다면 그 한계를 보고해야 한다. “검증 규칙을 설치했다”는 사실만으로 프로젝트의 테스트 coverage가 좋아지는 것은 아니다.

**Agent 활용 예시**

> 이 수정이 끝났다고 보고하기 전에 변경 diff를 확인하고 관련 회귀 테스트, 전체 테스트, build를 각각 실행해줘. 실행 명령과 결과를 구분해서 알려주고, 환경 때문에 못 돌린 항목은 통과했다고 표현하지 마.

**평가:** 특정 stack에 묶이지 않고 Codex가 만드는 결과물의 신뢰도를 높이는 데 바로 적용할 수 있다. 단점은 검증 비용과 실행 시간이 늘 수 있다는 점이다. 변경 위험에 맞는 검증 범위를 정하되, 하지 않은 검사를 했다고 넓혀 말하지 않는 원칙을 유지하는 것이 중요하다.

### 🏆 오늘의 Top Pick

**vgpu**

선정 이유는 설치 수가 가장 많아서가 아니라 **버전 정합성과 실제 시각 검증을 하나의 절차로 묶은 설계**다. 빠르게 변하는 WebGPU API는 설치된 패키지 문서로 확인하고, Blender 결과는 실제 runtime 캡처와 비용 측정으로 검증한다. “코드는 생성됐지만 화면이 다르다”, “폴리곤은 줄었지만 실제로 빨라졌는지는 모른다” 같은 3D Agent 작업의 빈틈을 구체적으로 다룬다. WebGPU·3D 프로젝트를 시작하거나 운영하는 경우 우선 검토할 만하다.

### 오늘 보이는 공통 흐름

오늘 선정한 원문들을 비교하면 **정적인 정답 모음보다 현재 프로젝트의 사실을 확인하는 Skill**이 눈에 띈다. vgpu는 설치 패키지 문서를, shadcn은 프로젝트 설정과 컴포넌트를, Prisma는 실제 ORM 세대와 DB를 확인한다. Remotion은 작업에 맞는 전문 지침과 실행 중인 preview로 연결하고, React Native는 병목의 우선순위를 제공하며, verification-before-completion은 모든 결과 주장에 근거를 요구한다.

이는 이번 6개 후보에서 관찰한 설계상의 공통점이다. 전체 생태계의 시장점유율 변화나 채택 증가를 입증하는 통계로 확대하지 않는다. 도입할 때는 **정확한 source·호스트 호환성·실행 권한·검증 가능한 결과**를 함께 확인하는 편이 좋다.
