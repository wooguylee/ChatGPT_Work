## 1. hf-mem

- **출처/제작자:** [Hugging Face 공식 Skills](https://github.com/huggingface/skills)
- **원 Skill:** [skills/hf-mem/SKILL.md](https://github.com/huggingface/skills/blob/main/skills/hf-mem/SKILL.md)
- **지원 Agent:** 공식 모음은 Claude Code, Codex, Gemini CLI, Cursor 호환을 명시한다. 실행에는 shell과 네트워크가 필요하다.
- **태그:** `#로컬LLM` `#메모리추정` `#GGUF` `#배포준비`
- **도입 난이도:** 낮음. 추정 결과를 실제 서빙 용량으로 해석하는 단계는 중간.

### 인기 및 트렌드 지표

- GitHub 모음 전체: **11,133 stars / 756 forks**
- skills.sh 개별 페이지는 이번 조회에서 접근되지 않아 installs / First Seen / 감사 상태: **미확인**
- 공식 저장소에서 실제 Skill 파일과 CLI 사용법을 확인했다. 인기 급상승이나 당일 출시로 분류하지 않는다.

### 내용

`hf_mem`은 Hub의 Safetensors·GGUF 메타데이터를 HTTP Range 요청으로 읽어 **가중치를 전부 다운로드하거나 로드하지 않고** 메모리를 추정한다. 큰 모델을 먼저 받아 본 뒤 공간 부족을 발견하는 시행착오를 줄이는 준비 도구다. GGUF 저장소에 여러 quant가 있으면 각 파일 추정을 구분하고, 실제로 사용할 파일 또는 shard 경로를 `--gguf-file`로 지정하게 한다. [공식 Skill](https://github.com/huggingface/skills/blob/main/skills/hf-mem/SKILL.md)

`--experimental`은 지원 모델의 KV cache 추정을 추가하고 context length·batch size·cache dtype을 조정한다. **가중치 크기와 긴 문맥에서의 cache 비용을 분리**해서 비교할 수 있다는 점이 유용하다. 다만 추정치는 실제 runtime의 peak allocation·workspace·다른 프로세스 사용량을 측정한 값이 아니므로 “이 GPU에서 반드시 실행된다”는 보증으로 사용하지 않는 것이 좋다.

### 설치 및 사용

```bash
npx skills add huggingface/skills --skill hf-mem --agent codex
```

공식 Hugging Face README는 추가 workflow Skill을 `hf skills add <skill-name>`으로 설치하는 경로도 제공한다. 위 명령은 Agent Skills CLI로 개별 원문을 설치하는 방식이다.

**전제조건:** 실제 추정에는 `uv`/`uvx`와 Hub 접근이 필요하다. 공개 모델은 별도 token이 필요하지 않으며, private/gated 모델은 접근 권한과 안전하게 제공한 인증이 필요하다. token을 프롬프트·로그에 적지 않는다.

```bash
uvx hf-mem --model-id <MODEL_ID> --json-output
uvx hf-mem --model-id <MODEL_ID> --experimental \
  --max-model-len 8192 --batch-size 1 --json-output
```

**Agent 활용 예시**

> 이 공개 모델을 다운로드하기 전에 메모리를 추정해줘. 4K와 8K context에서 가중치와 KV cache를 구분하고, 내 GPU의 다른 사용량을 위한 여유도 남겨. 추정 결과와 실제 실행 검증은 따로 표시해.

**평가:** 오늘의 가장 작은 도입 단위다. 특히 대형 모델 조사·GPU 선택·로컬 실험 전에 가치가 있다. 학습 메모리 계산기나 성능 benchmark로 확대해서 쓰지 않는 것이 핵심이다.

### 내용

Hub에서 `apps=llama.cpp` 조건으로 모델을 찾고, 모델의 local-app 안내와 tree API로 **정확한 GGUF 파일명**을 확인한 뒤 실행한다. `UD-Q4_K_M` 같은 저장소 고유 quant 이름을 임의로 바꾸지 않으며, `mmproj-*.gguf`를 본체 checkpoint와 구분한다. 이미 GGUF가 있다면 불필요한 Transformers→GGUF 변환부터 시작하지 않는다. [공식 Skill](https://github.com/huggingface/skills/blob/main/skills/huggingface-local-models/SKILL.md)

CPU·Metal·CUDA·ROCm 관련 reference와 quant 선택 지침도 연결한다. 중요한 실무 효과는 그럴듯한 모델 이름만 추천하는 데서 멈추지 않고 **실제로 존재하는 artifact와 로컬 실행 명령 사이를 잇는 것**이다. quant 품질은 작업과 모델에 따라 달라지므로 일반적인 Q4/Q5/Q6 권장값이 자신의 한국어·코딩 task에서 최선이라는 뜻은 아니다.

### 설치 및 사용

```bash
npx skills add huggingface/skills --skill huggingface-local-models --agent codex
```

**전제조건:** 하드웨어에 맞게 설치한 llama.cpp, 모델 파일을 담을 저장공간, 충분한 RAM/VRAM이 필요하다. gated 모델은 별도 권한이 필요하다. 원문에 있는 빌드 예제를 무조건 복사하지 말고 사용 중인 llama.cpp revision의 공식 빌드 안내를 확인한다.

파일과 quant를 실제로 확인한 뒤 다음 틀을 사용한다.

```bash
llama-server --hf-repo <GGUF_REPO> --hf-file <EXACT_GGUF_FILE> -c 4096
```

**Agent 활용 예시**

> 내 하드웨어에서 실행할 한국어 요약 모델 후보를 찾아줘. 정확한 GGUF 파일과 quant, 라이선스를 확인하고 hf-mem 추정도 붙여. 내가 다운로드를 승인하면 localhost 서버로 띄워 짧은 한국어 입력과 긴 입력을 각각 검증해.

**평가:** 모델 탐색에서 로컬 smoke test까지 연결하기 좋다. Snyk Warn과 실행 명령을 검토하고, 서버를 외부 네트워크에 공개하지 않는 범위부터 시작하는 편이 안전하다. Skill 설치는 llama.cpp·GPU driver 설치를 대신하지 않는다.

- **도입 난이도:** 중간~높음. 상태 모델과 재시도·복구 테스트가 중요하다.

### 인기 및 트렌드 지표

- skills.sh **installs 89.5K**, First Seen **2026-01-19**
- 감사 표시: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Pass**
- GitHub 모음 전체: **2,975 stars / 300 forks**

### 내용

기존 소개한 `cloudflare`가 제품 선택용 라우터였다면, 이 Skill은 **별도의 Durable Objects 구현 지침**이다. 채팅방·게임·사용자 등 조정이 필요한 단위마다 object를 두고, 모든 요청을 하나의 전역 object에 몰지 않도록 한다. 결정적 이름 기반 routing, SQLite migration, RPC, persistent storage와 메모리 cache의 순서, object마다 하나인 alarm을 다룬다. [공식 Skill](https://github.com/cloudflare/skills/blob/main/skills/durable-objects/SKILL.md)

상태를 메모리에만 두거나, 매 요청마다 `blockConcurrencyWhile()`로 전체를 묶거나, 외부 I/O 동안 동시성을 막는 패턴을 경고한다. API·권한·test setup은 관련 최신 문서를 조회하도록 연결한다. “Agent 대화를 저장한다” 같은 요구를 실제 영속 상태와 조정 경계로 바꾸는 데 적합하지만, stateless 처리까지 모두 Durable Objects로 바꿀 이유는 없다.

### 설치 및 사용

```bash
npx skills add cloudflare/skills --skill durable-objects --agent codex
```

**전제조건:** Workers/TypeScript 프로젝트, Wrangler와 관련 테스트 환경이 필요하다. 지침을 읽거나 코드 리뷰하는 데 계정 권한은 필수가 아니지만 실제 배포·데이터 접근은 Cloudflare 인증과 해당 Worker 권한이 필요하다. Skill 설치는 배포·migration 승인이 아니다.

**Agent 활용 예시**

> 공동 편집 세션을 room별 Durable Object로 설계해줘. 재시작 후 복구할 상태와 일시적인 cache를 나누고, 중복 요청·동시 변경·alarm 재설정을 테스트해. 먼저 로컬 구현과 검증만 하고 운영 migration은 별도로 검토하자.

**평가:** 상태 유지 Agent나 실시간 서비스를 만드는 경우 구체적인 실패 패턴을 줄일 수 있다. 전역 분산·고성능을 자동 보장하는 도구는 아니며 sharding과 부하 특성은 프로젝트에서 확인해야 한다.

- **태그:** `#코드리뷰` `#서버리스` `#스트리밍` `#관측성`
- **도입 난이도:** 중간. 기존 Workers 프로젝트의 리뷰부터 적용하기 좋다.

### 인기 및 트렌드 지표

- skills.sh **installs 98.4K**, First Seen **2026-02-12**
- 감사 표시: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Pass**
- GitHub 모음 전체: **2,975 stars / 300 forks**

### 내용

현재 프로젝트의 설치 버전·생성된 binding type·compatibility date/flags를 기준으로 판단하게 한다. 새로운 type package에 어떤 API가 있다고 해서 기존 runtime target에서도 된다고 단정하지 않는다. 큰 응답을 `response.text()`로 모두 버퍼링하는 코드, 연결되지 않은 비동기 작업, module-level 가변 request state, 하드코딩한 secret 등 Workers에서 실제 장애를 일으키는 패턴을 점검한다. [공식 Skill](https://github.com/cloudflare/skills/blob/main/skills/workers-best-practices/SKILL.md)

Logs와 Traces 설정을 구분하고 구조화된 logging과 workload에 맞는 sampling을 안내한다. 검증도 변경의 성격에 맞춰 type-check와 runtime test를 선택한다. 작은 수정마다 전체 플랫폼 audit를 강제하지 않는다는 점이 일상적인 코드 리뷰에 잘 맞는다.

### 설치 및 사용

```bash
npx skills add cloudflare/skills --skill workers-best-practices --agent codex
```

**전제조건:** 기존 Wrangler 설정·lockfile·test command를 읽을 수 있어야 한다. 계정 조작 없이 로컬 리뷰부터 가능하다. 관측성 설정을 켤 때는 로그에 개인정보·secret이 포함되지 않게 하고 데이터 보존·비용도 별도 확인한다. 기존 compatibility date 갱신은 회귀 테스트와 함께 계획한다.

**Agent 활용 예시**

> 이 Worker의 스트리밍 LLM 응답이 중간에 끊기는 원인을 조사해줘. 현재 compatibility 설정은 유지하고 응답 buffering, promise 수명, request 간 공유 state부터 확인해. 변경한 동작의 runtime test와 재현 결과를 남겨줘.

**평가:** Cloudflare에서 LLM gateway나 webhook handler를 운영할 때 실용적이다. 일반 JavaScript 스타일 규칙보다 runtime 특유의 오류를 찾는 데 강하며, 다른 serverless platform에 그대로 적용할 수는 없다.

- skills.sh **installs 881.2K**, First Seen **2026-04-28**
- Trending(24h) 조회 화면: **#61 / 4.1K 표시**

- 감사 표시: **Gen Agent Trust Hub Warn / Socket Pass / Snyk Warn**. 두 Warn의 상세 사유는 미확인.

### 내용

이슈를 bug/enhancement 중 하나의 범주와 다섯 가지 진행 상태 중 하나로 나누는 상태 기반 workflow다. 이전 논의를 읽고 이미 구현된 기능이나 기존 거절 사유를 확인한 다음, bug는 재현하고 PR은 diff와 검사를 통해 주장부터 확인한다. 그 뒤 추가 정보 요청, Agent 실행 지시서, 사람 판단이 필요한 작업으로 이어간다. [원 Skill](https://github.com/mattpocock/skills/blob/main/skills/engineering/triage/SKILL.md)

단순 label 분류보다 **다음 작업자가 다시 조사하지 않아도 되는 맥락**을 남기는 것이 장점이다. 외부 PR 검색 범위와 명시적으로 지정한 PR을 구분하고, 기존에 답한 질문을 반복하지 않는다. tracker에 게시하는 내용에는 AI 작성 고지를 요구한다. 실제 적용에는 댓글·label 변경·close가 포함되므로 읽기 전용 요약과 외부 mutation을 구분해야 한다.

### 설치 및 사용

```bash
npx skills add mattpocock/skills --skill triage --agent codex
```

**전제조건:** 제작자 README가 안내하는 `setup-matt-pocock-skills`로 tracker와 label mapping을 준비한다. 필요한 경우 설치 목록에서 setup 및 관련 의존 Skill도 선택한다. GitHub·Linear·local files 중 프로젝트가 사용하는 대상을 확인하고, hosted tracker 쓰기에는 인증이 필요하다. plugin과 복사 설치를 중복 적용하지 않는다.

**Agent 활용 예시**

> 이 저장소에서 오래된 needs-triage 이슈 세 개만 읽고 재현 여부와 권장 상태를 알려줘. 기존 답변과 구현도 확인해. 댓글·label·close는 바꾸지 말고, 내가 선택한 이슈에 대해서만 다음 단계 초안을 준비해.

**평가:** backlog를 Agent 작업으로 넘기는 팀에 가치가 높다. 설치 수가 크더라도 자동 close를 포괄적으로 허용할 이유는 없으며, 감사 경고와 실제 쓰기 동작을 검토해야 한다.

## 6. to-spec

- **출처:** [skills.sh](https://www.skills.sh/mattpocock/skills/to-spec)
- **원 Skill:** [Matt Pocock 원문](https://github.com/mattpocock/skills/blob/main/skills/engineering/to-spec/SKILL.md)
- **제작자/지원 Agent:** Matt Pocock. Claude Code plugin·Codex 등 Skills CLI 대상. 사용자 호출형 `disable-model-invocation: true`.
- **태그:** `#명세` `#요구사항` `#테스트설계` `#개발계획`
- **도입 난이도:** 낮음~중간. 좋은 대화 맥락과 tracker 설정이 전제다.

### 인기 및 트렌드 지표

- skills.sh **installs 602.2K**, First Seen **2026-07-02**
- Trending(24h) 조회 화면: **#64 / 4.0K 표시**
- GitHub 모음 전체: **275,356 stars / 23,104 forks**
- 감사 표시: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Pass**

### 내용

이미 나눈 대화와 코드베이스 이해를 문제·해결책·user stories·구현 결정·테스트 결정·범위 밖 항목으로 합성한다. 새로운 인터뷰를 시작하는 대신 기존 합의를 사용하되, 기능을 검증할 **테스트 경계(test seam)**는 사용자와 확인한다. 기존의 높은 수준 경계를 선호하고 구현 세부사항에 과도하게 결합한 검증을 피한다. [원 Skill](https://github.com/mattpocock/skills/blob/main/skills/engineering/to-spec/SKILL.md)

현재 원문은 쉽게 낡는 파일 경로와 코드 조각을 명세에서 피하도록 하지만, prototype이 결정을 더 정확히 표현한 경우 핵심 부분을 포함할 수 있다. 최종 단계는 tracker 게시와 `ready-for-agent` label 적용이다. 따라서 단순한 채팅 요약기로 생각하고 호출하기보다는 **명세 작성과 발행 범위**를 먼저 정해야 한다.

### 설치 및 사용

```bash
npx skills add mattpocock/skills --skill to-spec --agent codex
```

**전제조건:** setup으로 tracker·label을 정하고 프로젝트 glossary·ADR·기존 test 구조를 확인한다. 문서 작성만 하는 동안 별도 모델 API key는 필요하지 않지만 hosted tracker 게시에는 권한이 필요하다. 초안만 원한다면 게시하지 말라는 범위를 명시한다.

**Agent 활용 예시**

> 방금 합의한 검색 필터 개선안을 to-spec 방식으로 정리해줘. 기존 API 경계에서 테스트할 수 있는지 먼저 확인하고, 합의하지 않은 기능은 범위 밖에 둬. 로컬 초안을 검토한 뒤 지정한 tracker에 게시하자.

**평가:** 이미 요구사항 대화를 충분히 마친 팀에 바로 적용하기 좋다. 아직 결정되지 않은 제품 방향을 긴 user story 목록으로 채우면 잘못된 확신이 생길 수 있으므로, 미결정 항목은 미결정으로 남겨야 한다.

### 오늘 보이는 공통 흐름

오늘 후보들은 **실행 전에 조건을 확인하고, 실행 후 무엇으로 검증할지 정하는 절차**를 강조한다. Hugging Face의 두 Skill은 메모리와 실제 모델 artifact를 확인하고, Cloudflare의 두 Skill은 runtime·영속 상태·비동기 수명을 다룬다. triage와 to-spec은 요구사항을 검증 가능한 작업 단위로 바꾼다.

이는 이번 여섯 원문을 비교한 관찰이다. 생태계 전체의 채택 증가나 시장 점유율 변화라는 통계적 결론으로 확대하지 않는다. 과거의 상위 라우터 Skill과 같은 저장소에 있어도 오늘 선정한 파일은 각각 별도 이름·목적·절차를 갖는 독립 Skill이다.
