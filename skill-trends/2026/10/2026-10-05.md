### 내용

데이터셋을 전부 내려받기 전에 Dataset Viewer API로 구조와 내용을 확인하는 Skill이다. subset/config와 split을 찾고, 첫 행을 미리 본 다음 offset 기반으로 페이지를 이어 읽는다. 문자열 검색·조건 필터·Parquet shard 목록·용량·열 통계까지 연결하므로, 데이터 후보가 실제 작업에 맞는지 작은 비용으로 살피기 좋다. [공식 Skill](https://github.com/huggingface/skills/blob/main/skills/huggingface-datasets/SKILL.md)

행 조회의 `length`는 최대 100이며, 일부 응답만 받은 경우 총 행 수와 partial 정보를 확인한다. 첫 페이지를 전체 분포로 오해하지 않는 것이 핵심이다. SQL 기반 작업은 별도 `hf-cli` 경로로 안내한다. [Dataset Viewer 행 조회 문서](https://huggingface.co/docs/dataset-viewer/en/rows)

원문 뒤쪽에는 데이터 업로드와 Agent trace 게시 절차도 있다. 읽기 전용 탐색을 요청했다고 해서 업로드까지 허용된 것은 아니다. 세션 원문에는 개인정보·비밀·도구 출력이 섞일 수 있으므로 private 설정만으로 충분하다고 생각하지 말고, 필요한 범위와 전송 내용을 별도로 검토해야 한다.

### 설치 및 사용

```bash
npx skills add huggingface/skills --skill huggingface-datasets --agent codex
```

**전제조건:** 공개 데이터 탐색은 일반적인 HTTP 접근으로 시작할 수 있다. gated/private 데이터는 접근 권한과 안전한 인증이 필요하다. 토큰을 프롬프트·URL·로그에 넣지 않는다. 도구를 사용할 수 있다고 해서 데이터셋의 라이선스나 재배포 권한까지 확보한 것은 아니다.

**Agent 활용 예시**

> 한국어 분류 실험에 쓸 데이터 후보의 config와 split을 확인해줘. 각 split에서 페이지를 나눠 표본을 읽고 label 분포·결측·텍스트 길이를 점검하자. 확인한 범위와 아직 읽지 않은 범위를 구분하고, 데이터 업로드는 하지 마.

**평가:** 모델 학습·평가 전 데이터 실사를 작게 시작하기 좋다. 전체 corpus 품질을 자동 보장하는 검사기는 아니므로 표본 기반 관찰과 전수 집계를 구분해야 한다.

### 내용

TRL의 SFT·DPO·GRPO·reward modeling을 Hugging Face Jobs에서 수행하는 절차와 예제 스크립트를 묶었다. 학습법에 맞는 데이터 형식을 점검하고, hardware와 timeout을 정한 뒤 Trackio 기록·checkpoint·Hub 저장을 준비한다. 학습 후 GGUF 변환도 별도 reference로 연결한다. 로컬 GPU가 없는 환경에서 실험 계획을 구체화하는 데 유용하다. [공식 Skill](https://github.com/huggingface/skills/blob/main/skills/huggingface-llm-trainer/SKILL.md)

**현행 서비스 문서와 다른 부분이 있다.** Skill은 Pro/Team/Enterprise 요금제가 필요하다고 적지만, 현재 Jobs 공식 안내는 **양의 credit 잔액이 있는 사용자·조직이 이용할 수 있다**고 설명한다. Skill의 예시 시간당 요금·속도 개선율도 오늘 검증한 실제 견적이나 benchmark로 제시하지 않는다. 비용은 실행 시점의 hardware 목록과 billing 조건으로 다시 계산해야 한다. [현재 Jobs 문서](https://huggingface.co/docs/huggingface_hub/guides/jobs)

또한 원문은 학습 요청 후 즉시 job을 제출하는 흐름을 포함한다. 실제 사용에서는 비용 상한, 외부로 보낼 데이터, 저장 대상과 공개 범위를 먼저 확정해야 한다. 제출 성공은 학습 성공이나 품질 개선의 증거가 아니다.

### 설치 및 사용

```bash
npx skills add huggingface/skills --skill huggingface-llm-trainer --agent codex
```

**전제조건:** Jobs 인증·잔액·모델 접근 권한과 승인된 데이터가 필요하다. 산출물은 Hub 등 허용된 영속 저장소에 보존하고 최종 artifact가 실제로 존재하는지 확인한다. 기본 timeout은 현재 Jobs 문서상 30분이므로 작업 규모에 맞게 조정한다. 모델 품질 확인용 평가셋도 별도로 준비한다.

비용을 확정하기 전에 현재 hardware 정보를 확인하는 명령:

```bash
hf jobs hardware
```

**Agent 활용 예시**

> 공개 한국어 데이터로 소형 모델 SFT 실험을 계획해줘. 데이터 형식과 라이선스, 평가 분리, 현재 GPU 요금, timeout, checkpoint 저장 위치를 먼저 확인해. 작은 smoke run과 본 실험 비용을 나누고, 내가 예산과 제출 내용을 승인한 뒤에만 job을 실행해.

**평가:** 학습 운영 체크리스트로는 실용적이지만 **최신 서비스 문서와 대조하며 쓰는 검토형 후보**다. 샘플 코드를 그대로 실행하기보다 설치된 TRL 버전·현재 Jobs API와의 정합성을 먼저 확인하는 편이 좋다.

### 내용

기존에 소개한 `cloudflare`의 제품 선택이나 `workers-best-practices`의 코드 리뷰와 달리, 이 Skill은 **프로젝트의 Wrangler 명령·설정·대상 환경을 정확히 다루는 절차**에 집중한다. lockfile·설치 버전·package scripts·실제 config를 확인하고 현재 CLI 도움말과 schema로 문법을 검증한다. 문서 예제를 맞추려고 dependency를 조용히 올리지 않는다. [공식 Skill](https://github.com/cloudflare/skills/blob/main/skills/wrangler/SKILL.md)

실무적으로 중요한 구분이 많다. 로컬 Worker도 remote binding을 통해 실제 데이터에 접근할 수 있고, Preview 이름만으로 운영 리소스와 격리됐다고 판단할 수 없다. `secret put/delete`가 바로 배포를 일으킬 수 있으며, 코드 rollback은 연결된 리소스 데이터를 되돌리지 않는다. dry-run 역시 build와 packaging 검사 범위이며 운영 동작 검증을 대신하지 않는다.

`cloudflare.config.ts`가 있거나 사용자가 `cf` CLI를 지정했다면 이 Skill 대신 현재 Cloudflare CLI 문서로 가도록 명시한다. 같은 공급자의 도구라고 해서 Wrangler 설정을 다른 CLI에 그대로 적용하지 않는 것이 유용하다.

### 설치 및 사용

```bash
npx skills add cloudflare/skills --skill wrangler --agent codex
```

**전제조건:** 프로젝트에 고정된 Wrangler와 package manager를 사용한다. 계정·Worker·environment·resource를 원격 변경 전에 확인한다. plugin 전체 설치는 MCP 연동도 포함할 수 있으므로 개별 Skill 설치와 필요한 권한을 구분한다. secret 값은 chat·명령 인수·로그에 남기지 않는다.

**Agent 활용 예시**

> 이 Worker의 staging 배포 설정을 검토해줘. 프로젝트에 설치된 Wrangler 기준으로 config와 binding을 확인하고, 로컬 테스트가 운영 DB에 쓰지 않는지 점검해. build·dry-run 결과와 미검증한 원격 동작을 나눠 알려줘. 실제 배포는 검토 후 진행하자.

**평가:** 배포 대상이나 resource가 뒤섞이는 실수를 줄이는 데 특히 좋다. 모든 Cloudflare 프로젝트에 적용하는 범용 명령 모음으로 쓰기보다는 현재 CLI와 프로젝트 상태를 확인하는 운영 지침으로 사용하는 것이 적절하다.

## 4. mcp-builder

- **출처/제작자:** [Anthropic 공식 Skills](https://github.com/anthropics/skills), [skills.sh 항목](https://www.skills.sh/anthropics/skills/mcp-builder)

- **태그:** `#MCP` `#도구설계` `#API연동` `#평가`
- **도입 난이도:** 중간~높음. TypeScript 또는 Python API 개발 경험이 필요하다.

### 인기 및 트렌드 지표

- skills.sh: **installs 122.3K**, First Seen **2026-01-19**
- 감사 표시: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Warn**. Warn 상세 사유·대상 revision은 미확인.
- GitHub 모음 전체: **179,651 stars / 21,247 forks**
- 이 수치로 현재 Skill의 보안성이나 배포 준비 상태를 판정하지 않았다.

### 내용

외부 서비스를 연결하는 MCP 서버를 설계·구현·검증하는 지침이다. API 범위를 조사하고 자주 쓰는 작업부터 도구로 만든 뒤 입력 schema, 응답 형식, pagination과 오류 메시지를 점검한다. 단순히 endpoint를 감싸는 것에 그치지 않고, Agent가 도구를 발견하고 필요한 정보를 적당한 크기로 받을 수 있는지를 다룬다. [공식 Skill](https://github.com/anthropics/skills/blob/main/skills/mcp-builder/SKILL.md)

완료 단계에는 실제 업무를 닮은 **읽기 전용 평가 질문 10개**를 만드는 절차가 있다. 정답이 명확하고 변하지 않는 질문을 설계하고, 직접 도구를 사용해 답을 검증한다. 빌드 성공과 “Agent가 이 도구로 업무를 해결한다”는 주장을 분리하는 점이 강점이다. [평가 가이드](https://github.com/anthropics/skills/blob/main/skills/mcp-builder/reference/evaluation.md)

완성된 MCP 서비스나 credential을 제공하는 Skill은 아니다. 저장소는 예제를 자체 환경에서 시험하도록 안내하며, 실제 SDK와 protocol의 최신 문서도 확인해야 한다. 원문의 API 범위 확대 지침을 모든 쓰기 권한을 한꺼번에 허용하라는 뜻으로 해석하지 않는다.

### 설치 및 사용

Codex에 개별 Skill을 설치하는 방법:

```bash
npx skills add anthropics/skills --skill mcp-builder --agent codex
```

Claude Code의 공식 plugin 경로는 다음과 같다. 이 방식은 mcp-builder 하나가 아닌 **example-skills 묶음**을 설치한다.

```text
/plugin marketplace add anthropics/skills
/plugin install example-skills@anthropic-agent-skills
```

**전제조건:** 대상 서비스의 API 문서·인증·권한과 개발 환경이 필요하다. 원문의 SDK 가이드를 읽고 Inspector·빌드·평가를 각각 수행한다. Snyk Warn은 설치 전에 상세 내용을 추가 확인할 사유이며, 이번 보고서는 안전성 감사를 수행하지 않았다.

**Agent 활용 예시**

> 사내 티켓 API를 위한 TypeScript MCP 서버를 설계해줘. 첫 버전은 검색과 상세 조회만 제공하고, pagination·입력 검증·권한 오류를 명확히 다뤄. 실제 업무 질문 10개와 검증된 답을 만들어 Agent가 여러 도구를 연결해 해결할 수 있는지 시험하자.

**평가:** 사내 도구를 Agent용 인터페이스로 바꾸려는 팀에 실용적이다. 이전에 소개한 MCP 앱 UI 제작이나 서버 관리와 달리, 이번 후보의 중심은 **서버 도구의 사용성과 평가 설계**다.

### 내용

화면 전환 때 동적 데이터가 늦어도 의미 있는 정적 화면 골격이 먼저 표시되는지 검사한다. `@next/playwright`의 `instant()`로 실패하는 테스트를 만든 뒤 Suspense와 캐시 경계를 조정하고 통과시킨다. 수정 제거 시 다시 실패하는지 확인해 형식적인 테스트 통과도 걸러낸다. [공식 Skill](https://github.com/vercel/next.js/blob/canary/skills/next-cache-components-optimizer/SKILL.md)

첫 진입과 링크 기반 이동은 다른 경로이므로 따로 검증한다. 빈 fallback만 빠르게 표시되는 경우를 좋은 결과로 취급하지 않으며, 데스크톱·모바일의 실제 내용, 인증 redirect, state 보존도 확인한다. 통과는 shell 준비를 증명하며 변경된 데이터가 다음 조회에 반영되는지는 별도 mutation test가 필요하다. [실제 앱 패턴](https://github.com/vercel/next.js/blob/canary/skills/next-cache-components-optimizer/reference/real-app-patterns.md)

**기존 `next-best-practices`를 새로 설치하는 대신 현재 경로를 확인해야 한다.** 공식 이전 안내에 따르면 해당 참조 지식은 Next.js 16.3+ 번들 문서와 생성된 Agent 규칙으로 전달되며 독립 Skill로 배포되지 않는다. optimizer는 남아 있는 별도의 실행 workflow다. [공식 이전 안내](https://github.com/vercel-labs/next-skills)

### 설치 및 사용

```bash
npx skills add vercel/next.js --skill next-cache-components-optimizer --agent codex
```

**전제조건:** Next.js **16.3+**, `cacheComponents: true`, Next.js와 같은 릴리스 계열의 `@next/playwright`가 필요하다. 기존 앱이 조건을 충족하지 않으면 설치만으로 적용된다고 설명하지 말고 upgrade 범위를 먼저 검토한다.

```bash
npm ls next @next/playwright
```

검증에는 production에 가까운 build를 사용하며 `next dev`를 최종 근거로 삼지 않는다. `exposeTestingApiInProductionBuild`는 검증용 build에만 켜고 실제 운영에서는 비활성화해야 한다. 테스트 rig와 스크립트는 기존 프로젝트에 맞춰 구성한다. [Rig template](https://github.com/vercel/next.js/blob/canary/skills/next-cache-components-optimizer/rig-template.md)

**Agent 활용 예시**

> 대시보드 이동 때 차트 응답을 기다리느라 빈 화면이 보여. 제목·탭·기존 로딩 UI는 즉시 보이고 차트만 나중에 채워지도록 개선해줘. 첫 진입과 링크 이동 모두 실패→통과를 검증하고 인증 redirect·데이터 갱신 동작도 유지해.

**평가:** 이번 후보 중 “빨라 보인다”는 인상을 재현 가능한 검증으로 바꾸는 과정이 가장 구체적이다. 모든 앱에 무조건 cache를 늘리는 처방으로 사용하면 안 되며 실제 데이터의 freshness 요구가 우선이다.

## 6. jupyter-notebooks

- **출처/제작자:** OpenAI / [Data Analytics plugin](https://github.com/openai/plugins/blob/main/plugins/data-analytics/README.md)
- **원 Skill:** [jupyter-notebooks/SKILL.md](https://github.com/openai/plugins/blob/main/plugins/data-analytics/skills/jupyter-notebooks/SKILL.md)
- **지원 환경:** ChatGPT·Codex의 plugin 지원 환경. Python/SQL 실행에는 실제 kernel·dependency·데이터 접근 도구가 필요하다.
- **태그:** `#Jupyter` `#데이터분석` `#재현성` `#인수인계`
- **도입 난이도:** 중간. CSV로 시작하기 쉽고 warehouse 연동은 별도 접근 설정이 필요하다.

### 인기 및 트렌드 지표

- OpenAI Plugins 전체 저장소: **7,300 stars / 947 forks**
- 개별 Skill installs·좋아요·감사 상태·독립 품질점수: **미확인**
- 과거 `openai/skills` 저장소는 현재 deprecated 안내를 표시한다. 오늘은 그 저장소의 구형 항목 대신 **현행 plugins의 복수형 `jupyter-notebooks`**를 확인했다. [이전 안내](https://github.com/openai/skills)

### 내용

SQL/Python 분석을 다른 사람이 읽고 재실행할 수 있는 notebook으로 만드는 지침이다. 먼저 분석 보고서·실험 기록·진단·튜토리얼 중 목적을 정하고, 데이터 출처·기간·필터·가정을 명시한다. raw JSON 편집보다 notebook에 맞는 도구를 사용하고 기존 문서의 의도를 보존한다. [공식 Skill](https://github.com/openai/plugins/blob/main/plugins/data-analytics/skills/jupyter-notebooks/SKILL.md)

핵심은 요약을 계산 결과보다 먼저 확정하지 않는 것이다. 셀을 위에서 아래로 실행해 숫자·차트·결론이 실제 출력과 맞는지 확인하고, 설명되지 않은 cache나 순서가 뒤섞인 숨은 상태를 줄인다. 권한·kernel·dependency 부족으로 실행하지 못했다면 정확한 검증 공백을 밝혀야 한다.

Data Analytics의 데이터 소스 및 검증 workflow와 연결되어 있다. Skill 파일만 복사했다고 warehouse connector나 인증까지 설치되는 것은 아니다. 운영 테이블을 조회할 때는 필요한 기간·partition·행 수로 범위를 제한하고 결과에 출처를 남기는 방식이 적합하다. [Plugin workflow](https://github.com/openai/plugins/blob/main/plugins/data-analytics/README.md)

### 설치 및 사용

지원되는 앱의 **Plugins → Data Analytics 검색 → 상세 화면에서 설치 → 새 채팅** 순서로 시작한다. Codex CLI에서는 `/plugins`로 설정된 marketplace를 열고 해당 plugin을 설치한 뒤 새 session을 시작한다. 계정·workspace에 표시되는 설치 가능 여부와 필요한 연결을 확인한다. [공식 설치 안내](https://learn.chatgpt.com/docs/plugins#install-and-use-a-plugin)

준비된 notebook을 전체 실행하는 원문 예시:

```bash
python -m jupyter nbconvert --execute --to notebook --inplace path/to/notebook.ipynb
```

**전제조건:** 이 명령은 실제 셀을 실행하고 원본 notebook에 결과를 기록한다. 신뢰할 수 있는 notebook인지 확인하고, 필요한 kernel·nbconvert·패키지·입력 파일을 준비한다. 실행 권한이나 데이터 연결이 없으면 그 항목을 구체적으로 보고한다.

**Agent 활용 예시**

> 제공한 실험 결과 CSV로 재현 가능한 Python notebook을 만들어줘. 기간·제외 조건·세그먼트 정의를 앞에 적고, 전환율 계산과 표본 수를 검증해. 전체 셀을 순서대로 실행한 뒤 출력과 일치하는 요약·차트·한계를 남겨줘.

**평가:** 실험·분석 결과를 넘겨줘야 하는 Codex 작업에 바로 적용하기 좋다. notebook 실행 성공만으로 연구 설계나 인과적 결론까지 검증되는 것은 아니므로, 분석 가정과 데이터 품질은 따로 살펴야 한다.
