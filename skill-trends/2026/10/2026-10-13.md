## 1. django-access-review

**다른 사용자의 데이터까지 열리는지 추적하는 Django 권한 리뷰**

- 출처: Sentry 공식 조직의 getsentry/skills
- 태그: Django, DRF, 보안, IDOR, 객체 권한, 멀티테넌트
- 난이도: 중상. 프로젝트의 권한 상속 구조와 데이터 소유권 모델을 읽을 수 있어야 한다.

**무엇을 해 주나**

사용자 A가 사용자 B의 자료를 읽거나 바꾸거나 지울 수 있는지를 코드 흐름으로 조사한다. 먼저 데코레이터·미들웨어·기반 뷰·권한 클래스·커스텀 매니저에 분산된 권한 처리를 파악하고, URL이나 요청 본문의 ID가 ORM 조회에 도달하는 경로를 따라간다. 목록·조회·생성·수정·삭제·벌크 작업과 조직 간 접근까지 살펴보도록 설계되어 있다. `objects.all()`이라는 문자열만 보고 취약점으로 단정하지 않고, 자동 테넌트 필터나 상위 클래스의 보호 장치를 다시 확인하는 점이 강점이다. [공식 SKILL.md](https://github.com/getsentry/skills/blob/main/skills/django-access-review/SKILL.md)

**어떻게 활용하면 좋나**

멀티테넌트 SaaS의 새 API나 DRF 커스텀 액션을 배포하기 전에 유용하다. 결과는 권한 모델 요약, 파일·줄 위치, 조사 경로, 근거, 영향, 실제 권한 검사 코드를 포함한 수정안으로 정리한다. 확신이 부족한 항목은 수동 검증으로 분리하고, 확인하지 않은 범위도 밝히게 한다. 주석으로 “호출자가 검사해야 한다”고 적는 식의 수정은 해결책으로 인정하지 않는다. [공식 SKILL.md](https://github.com/getsentry/skills/blob/main/skills/django-access-review/SKILL.md)

**실전 프롬프트**

“django-access-review로 주문 API의 목록·조회·일괄 취소 권한을 검토해 줘. 조직 A의 일반 사용자가 조직 B의 주문 ID를 넣었을 때 차단되는지 URL → ViewSet → 권한 클래스 → QuerySet 순서로 추적하고, 확정 문제와 수동 검증 항목을 나눠 줘.”

“새로 만든 export 액션을 검토해 줘. 기본 get_object()를 거치지 않는 직접 ORM 조회, 생성 시 클라이언트가 지정하는 owner, 테넌트 전환 경로를 확인해 줘. 수정은 적용하지 말고 근거와 회귀 테스트 제안을 보여 줘.”

**주의할 점**

- 인증 여부와 객체 소유권 검사는 다르다. DRF의 기본 객체 권한 검사는 목록의 각 항목이나 생성 작업에 자동 적용되지 않으므로, QuerySet 필터와 Serializer·perform_create()까지 확인해야 한다. 커스텀 뷰는 객체 권한 검사를 명시적으로 호출할 수도 있으므로 실제 구현을 끝까지 읽어야 한다. [DRF 공식 권한 문서](https://www.django-rest-framework.org/api-guide/permissions/#limitations-of-object-level-permissions)
- 코드 조사 결과는 실제 사용자·조직 조합의 접근 테스트를 대신하지 않는다. 소스가 일부만 주어지거나 외부 권한 시스템이 있으면 확정 판단의 범위가 좁아진다. 이는 스킬의 조사·신뢰도 정책에 따른 활용상 한계다.

**설치·검증 정보**

설치 안내: `npx skills add https://github.com/getsentry/skills --skill django-access-review`

[skills.sh 페이지](https://www.skills.sh/getsentry/skills/django-access-review)에 이 설치 경로와 Gen Agent Trust Hub·Socket·Snyk의 Pass 배지가 표시된다. 이번 조회에서 감사 상세 페이지는 열리지 않아 세부 근거·검사 대상 버전까지 확인하지 못했다. 배지는 해당 검사 결과이며 안전성 보증은 아니다.

## 2. django-perf-review

**실제 영향이 있는 ORM 병목에 집중하는 성능 리뷰**

- 출처: Sentry 공식 조직의 getsentry/skills
- 태그: Django, ORM, N+1, 데이터베이스, 성능, 코드 리뷰
- 난이도: 중상. ORM뿐 아니라 데이터 규모와 자주 실행되는 경로를 확인할 자료가 필요하다.

**무엇을 해 주나**

Django 코드의 N+1 조회, 제한 없는 QuerySet 평가, 대형 테이블의 인덱스 누락, 반복문 안의 쓰기 작업을 우선 검토한다. View → QuerySet → Template/Serializer → 반복 접근을 따라가며 기존 select_related·prefetch_related·페이지네이션·캐시가 문제를 이미 막고 있는지 확인한다. 단일 객체에서 쿼리 두 번이 발생한 것을 N+1로 과장하거나, 변수 할당 방식 같은 스타일 차이를 성능 결함으로 보고하지 않도록 명시한다. [공식 SKILL.md](https://github.com/getsentry/skills/blob/main/skills/django-perf-review/SKILL.md)

**어떻게 활용하면 좋나**

목록 API가 느려지거나 Serializer 변경 뒤 쿼리 수가 늘어난 상황에 적합하다. 중요한 특징은 “패턴 발견”보다 데이터 건수·실행 빈도·기존 완화책까지 검증한 문제를 요구한다는 것이다. 결과에는 위치, 흐름, 검증 근거, 심각도, 수정 예시를 붙인다. 관리자 전용 화면, 관리 명령, 마이그레이션, 일회성 스크립트, 작은 고정 테이블, 드물게 실행되는 경로는 기본 보고 대상에서 제외한다. [공식 SKILL.md](https://github.com/getsentry/skills/blob/main/skills/django-perf-review/SKILL.md)

**실전 프롬프트**

“django-perf-review로 고객 목록 API와 UserSerializer를 검토해 줘. 첨부한 쿼리 로그와 데이터 건수 자료를 근거로 N+1·페이지네이션·인덱스를 확인하고, 기존 prefetch와 캐시를 먼저 찾아 줘. 확인되지 않은 건수나 지연 시간은 추정해서 채우지 마.”

“이 PR의 주문 상태 일괄 변경 경로를 검토해 줘. 요청 한 번에 처리하는 개수와 실제 호출 빈도를 확인하고, bulk_update로 바꿀 때 save()와 시그널의 동작이 달라지는지도 설명해 줘. 코드는 아직 변경하지 마.”

**주의할 점**

- 데이터 규모나 실행 빈도를 확인할 수 없으면 스킬 정책상 확정 문제로 보고하지 않는다. “발견 0건”은 성능 문제가 없다는 보증이 아니며, 무엇을 검증했고 어떤 자료가 없었는지 함께 읽어야 한다. 원문에 나오는 행 수 기준은 이 스킬의 선별 규칙이지 모든 서비스에 적용되는 성능 법칙은 아니다.
- 제안된 벌크 쓰기를 기계적으로 적용하면 동작이 바뀔 수 있다. Django의 bulk_create·bulk_update·QuerySet.update는 개별 save()를 호출하거나 pre_save·post_save 시그널을 보내지 않는다. [Django 공식 QuerySet 문서](https://docs.djangoproject.com/en/5.2/ref/models/querysets/#bulk-create)
- QuerySet.delete도 모델별 delete() 오버라이드는 호출하지 않지만 pre_delete·post_delete 시그널은 보낸다. 연쇄 삭제와 시그널 때문에 단순히 “SQL 한 번”이라고 보장할 수도 없다. 기존 부수 효과와 사용 중인 Django·DB 버전을 확인한 뒤 변경해야 한다. [Django 공식 delete 문서](https://docs.djangoproject.com/en/5.2/ref/models/querysets/#delete)

## 3. prompt-optimizer

**프롬프트 개선을 평가 실험으로 바꾸기**

- 태그: 프롬프트 엔지니어링 · 평가 설계 · 모델 이식 · 에이전트 운영
- 난이도: 중급. 문장을 고치는 것보다 성공 기준과 대표 평가 사례를 준비하는 일이 중요하다.
- 추천 대상: 시스템·개발자 프롬프트, 도구를 쓰는 에이전트, 재사용 템플릿을 관리하는 개발자.
- 확인한 지표: skills.sh 설치 수 2.1K, 최초 등재 2026-04-19. 세 감사기관의 Pass 배지가 표시된다. 설치 수는 조회 시점의 표시값이며 성능·안전 보증은 아니다. [skills.sh](https://www.skills.sh/getsentry/skills/prompt-optimizer)

### 무엇을 해주나

Sentry 공식 저장소의 프롬프트 최적화 워크플로다. 처음부터 문장을 다시 쓰지 않고 대상 모델·지시 계층·입출력·성공 기준·지연·비용·안전 제약을 먼저 기록한다. AGENTS.md, API 명세, 보안 정책 같은 외부 문서는 정확한 저장소 상대 경로와 함께 ‘읽음/참조/범위 밖’으로 구분한다. 안정적인 정책과 현재 작업의 데이터가 섞이거나 여러 계층에 같은 규칙이 반복되는 문제를 정리하는 데 유용하다. [공식 SKILL.md](https://github.com/getsentry/skills/blob/main/skills/prompt-optimizer/SKILL.md)

기존 프롬프트를 동일한 평가 입력으로 먼저 측정하고, 실패 원인을 묶은 뒤 최소 수정안·구조 재작성안·예제 또는 도구 규칙 개선안 등 2~4개 후보를 비교한다. 빠른 검토의 기본값은 사례 5~10개와 별도 홀드아웃 최소 1개다. 최종 결과에는 개선 프롬프트뿐 아니라 모델별 조정 메모, 평가 세트, 수정 기록, 남은 위험이 포함된다. 모델 계열이나 스냅샷을 바꿨을 때도 같은 평가를 다시 하도록 설계되어 있다. [평가 반복 절차](https://github.com/getsentry/skills/blob/main/skills/prompt-optimizer/references/meta-optimization-loop.md) · [모델별 참고사항](https://github.com/getsentry/skills/blob/main/skills/prompt-optimizer/references/model-family-notes.md)

### 바로 써볼 요청

“prompt-optimizer로 고객지원 에이전트의 developer 프롬프트를 개선해줘. 목표는 JSON 형식 준수와 근거 없는 답변 감소야. 현재 프롬프트와 실패 사례 8개를 기준선으로 삼고, 별도 2개는 홀드아웃으로 남겨줘. 최소 수정안과 구조 재작성안을 비교하고, 실행할 평가 환경이 없으면 측정 결과를 만들지 말고 평가 계획으로 구분해줘.”

비-www skills.sh의 오래된 검색 캐시는 Gen Pass / Socket Warn / Snyk Fail을 표시했지만, 더 최근의 www 페이지와 날짜가 있는 감사 상세는 위 결과를 표시했다. 따라서 “현재 Snyk Fail”이라고 적으면 부정확하다. 감사 대상과 현재 GitHub 원문의 버전 일치도 입증되지 않았다. 설치 경로는 [공식 디렉터리 페이지](https://www.skills.sh/getsentry/skills/gha-security-review)에 있으며, 저장소 기본 라이선스는 [Apache-2.0](https://github.com/getsentry/skills/blob/main/LICENSE)이다.


## 공통 설치 경로와 이용 조건

**이번 보고서는 위 다섯 항목의 개별 `--skill` 설치 경로를 우선한다.** [Sentry 공식 README](https://github.com/getsentry/skills/blob/main/README.md)의 `sentry-skills` 전체 플러그인 경로는 이번에 제외한 `gha-security-review`도 포함하므로, 오늘의 추천 다섯 항목만 설치하는 방법으로 권하지 않는다. 전체 플러그인의 존재와 구조는 출처·호환성 확인용 정보다.

[marketplace manifest](https://github.com/getsentry/skills/blob/main/.claude-plugin/marketplace.json)는 저장소 루트를 plugin source로 지정한다. 전체 묶음의 sparse 설치에는 `.claude-plugin`뿐 아니라 `skills`·`agents`가 필요하지만, 여기서는 항목별 설치 안내를 사용해 선택 범위를 확인하는 편이 적절하다. 설치 명령을 실행하기 전에 CLI가 선택한 Skill 목록과 가져올 파일을 검토한다.

필요한 항목의 참조 파일·보조 스크립트를 함께 보존한다. Codex에서 사용할 때는 설치된 호스트의 Skill 검색 경로·실행 도구·하위 에이전트 지원을 먼저 확인한다. Claude 전용 plugin 기능과 일반 Skill 지침의 호환성을 동일하게 보지 않는다. 이번 조사에서는 어느 경로도 설치하거나 실행하지 않았다.

저장소는 Sentry 직원의 개발 업무를 위한 공개 Skill 모음이며, Sentry SDK 설정·운영 이슈 디버깅용 `sentry-for-ai`와 목적이 다르다. 사내 명명·프로젝트 가정은 자체 저장소 규칙에 맞춰 검토한다. 저장소 [LICENSE](https://github.com/getsentry/skills/blob/main/LICENSE)는 Apache-2.0이며 외부 도구·서비스의 이용 조건은 별도다.
