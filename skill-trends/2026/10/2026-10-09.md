- 감사 표시: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Pass**.

### 내용

몇 개의 예상 입력·출력만 나열하는 대신 직렬화 왕복, 정규화의 멱등성, 정렬 조건, 자료구조 불변식처럼 **여러 입력에 성립해야 하는 성질**을 고른다. 기존 Hypothesis·fast-check·proptest 등의 환경에서 새 테스트 작성, 의미 없는 테스트 검토, 축소된 반례 분석까지 연결한다. 이미 소개한 일반 테스트 패턴과 달리 생성 전략과 검증 명제의 적절성을 함께 다룬다. [공식 Skill](https://github.com/trailofbits/skills/blob/main/plugins/property-based-testing/skills/property-based-testing/SKILL.md)

구현식을 그대로 베끼는 assertion은 같은 실수를 반복할 수 있고, 대부분의 입력을 필터링하면 실질적으로 검사하지 않은 테스트가 된다. 조건은 가능한 한 생성 전략에 넣고 경계 사례를 별도로 보존한다. 성질이 보이지 않을 때는 I/O와 계산이 섞여 있는지 살피되, 테스트를 넣기 위해 무조건 구조를 바꾸지는 않는다. [생성 전략](https://github.com/trailofbits/skills/blob/main/plugins/property-based-testing/skills/property-based-testing/references/generating.md), [검증 가능한 구조](https://github.com/trailofbits/skills/blob/main/plugins/property-based-testing/skills/property-based-testing/references/refactoring.md)

실패는 제품 버그뿐 아니라 잘못된 성질·입력 전제에서도 발생한다. 최소 반례를 곧바로 수정 요구로 바꾸지 않고 명세와 대조한다. 또한 표본 생성으로 통과한 결과는 입력 전체에 대한 수학적 증명이 아니다. [실패 해석](https://github.com/trailofbits/skills/blob/main/plugins/property-based-testing/skills/property-based-testing/references/interpreting-failures.md)

**Agent 활용 예시**

**평가:** 오늘의 **Top Pick**이다. “많이 돌렸다”보다 “무엇을 검증했는가”를 개선하는 데 초점이 명확하다. 바이너리 퍼징·성능 benchmark·UI E2E를 대신하는 도구는 아니다.

## 2. differential-review

- **출처/제작자:** [Trail of Bits 공식](https://github.com/trailofbits/skills), [skills.sh 항목](https://www.skills.sh/trailofbits/skills/differential-review)

- **지원 Agent:** Claude Code·Codex plugin. plugin 전용 보조 agent와 명령은 단일 SKILL.md 복사와 구분한다.
- **태그:** `#보안리뷰` `#변경이력` `#영향범위` `#테스트누락`
- **도입 난이도:** 중간~높음. 비교 기준·Git 이력·호출 경로와 검증 범위를 확보해야 한다.

### 인기 및 트렌드 지표

- skills.sh: **installs 7.5K**, First Seen **2026-01-19**.
- 감사 표시: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Pass**.
- 현재 [plugin metadata](https://github.com/trailofbits/skills/blob/main/plugins/differential-review/.claude-plugin/plugin.json)는 **v1.1.4**다. 원문의 예시 소요시간은 실측 성능 보장으로 인용하지 않는다.

### 내용

PR·커밋·diff를 기준으로 삭제된 검증 로직의 Git 이력, 변경 함수의 호출자, 테스트 누락을 조사하고 근거가 있는 결과를 보고서로 남긴다. 인증·인가·외부 호출처럼 영향이 큰 변경을 우선한다. 어제의 find-bugs가 변경분 전반의 발견 사항에 초점을 둔다면 이번에는 **보안 회귀와 과거 수정 의도**를 더 깊게 살피는 별도 Skill이다. [공식 Skill](https://github.com/trailofbits/skills/blob/main/plugins/differential-review/skills/differential-review/SKILL.md)

호출자 수는 우선순위 참고값이지 실제 악용 가능성 점수가 아니다. 큰 저장소에서 중요한 경로에 집중했다면 읽지 않은 파일을 명시한다. 원문의 “모든 변경 파일” 체크리스트와 저위험 파일 생략 예시를 동시에 전수검토 주장에 사용하면 안 된다. logging·UI도 민감 데이터나 권한과 연결되면 위험도가 높아질 수 있어 예시 분류를 절대 규칙으로 쓰지 않는다.

보조 방법론에는 baseline으로 checkout하는 단계가 있어 현재 작업 트리의 미커밋 변경을 먼저 확인해야 한다. 별도 worktree 또는 변경 없는 조회 방식으로 원본을 보존한다. 보안 시나리오는 허가된 코드와 로컬 재현 범위에서 검토하고 운영 서비스 공격·외부 게시로 확대하지 않는다. [방법론](https://github.com/trailofbits/skills/blob/main/plugins/differential-review/skills/differential-review/methodology.md), [보고 방식](https://github.com/trailofbits/skills/blob/main/plugins/differential-review/skills/differential-review/reporting.md)

### 설치 및 사용

marketplace가 준비된 Codex에서:

```bash
codex plugin add differential-review@trailofbits
```

Claude Code plugin의 현행 명령은 `/differential-review:diff-review <pr-url|commit-sha|diff-path> [--baseline <ref>]`다. 다른 호스트에서 같은 slash command가 보장되는 것은 아니다. [명령 원문](https://github.com/trailofbits/skills/blob/main/plugins/differential-review/commands/diff-review.md)

**전제조건:** 기준 ref와 Git 이력, 관련 파일을 읽을 수 있어야 한다. 얕은 clone·누락된 ref·미커밋 변경은 검토 한계에 기록한다. Bash·Write를 사용하는 workflow이며 보고서 작성과 코드 수정·PR 게시를 별도로 다룬다.

**Agent 활용 예시**

> 실제 PR base 대비 인증 변경을 differential-review로 검토해줘. 미커밋 작업을 보존하고 제거된 검사 이력·호출자·누락 테스트를 조사해. 확인한 경로와 미검증 범위를 보고서로 남기되, 코드 수정이나 외부 리뷰 게시 없이 결과만 보여줘.

**평가:** 보안 민감 리팩터링의 검토 후보로 좋다. 전체 저장소 보안 인증이나 취약점 부재의 증명이 아니라 비교 범위에 대한 근거 있는 리뷰로 활용한다.

### 인기 및 트렌드 지표

- skills.sh: **installs 6.2K**, First Seen **2026-01-19**.
- 감사 표시: **Gen Agent Trust Hub Pass / Socket Warn / Snyk Pass**.
- 현재 [plugin metadata](https://github.com/trailofbits/skills/blob/main/plugins/sharp-edges/.claude-plugin/plugin.json)는 **v1.1.3**다.
- [Socket 상세](https://www.skills.sh/trailofbits/skills/sharp-edges/security/socket)는 **2026-09-17** 감사로, auth-patterns 참고문서의 위험한 인증·인가 설계 예시를 지적한다. 상세 자체는 **4일 전 크롤링**이다. 해당 표시를 악성 코드 확정이나 최신 revision의 안전성 판정으로 확대하지 않는다.

### 내용

안전하게 쓸 수는 있지만 쉽게 잘못 쓰게 되는 API를 찾는다. 0·빈 문자열·음수·null의 의미가 모호한 설정, 같은 타입으로 섞기 쉬운 보안 인자, 검증 실패를 조용히 무시하는 인터페이스가 대상이다. 좋은 기본값뿐 아니라 호출자가 위험한 값으로 덮어쓸 때도 제한되는지 확인한다. [공식 Skill](https://github.com/trailofbits/skills/blob/main/plugins/sharp-edges/skills/sharp-edges/SKILL.md)

설정 표면을 찾고 경계 입력을 검토한 뒤 가능한 오용과 실제 보안 영향을 구분한다. 문서에 경고가 있다는 사실만으로 안전한 설계라고 보지 않지만, 호환성 변경이나 기능 제거를 자동 적용해서도 안 된다. 공격자의 통제 범위와 현실적인 호출 경로가 확인되지 않으면 잠재적 위험으로 남긴다. [설정 패턴](https://github.com/trailofbits/skills/blob/main/plugins/sharp-edges/skills/sharp-edges/references/config-patterns.md)

원문의 allowed-tools는 Read·Grep·Glob이지만 후반 절차에는 최소 재현·완화 검증도 있다. 읽기 전용으로 사용했다면 실행 검증을 했다고 주장하지 않는다. 별도 plugin agent가 필요한 경우 그 구성까지 설치되어 있는지도 확인한다.

### 설치 및 사용

marketplace가 준비된 Codex에서:

```bash
codex plugin add sharp-edges@trailofbits
```

**전제조건:** API·설정 schema·주요 호출자를 읽을 수 있어야 한다. 실제 키나 운영 계정 없이 먼저 정적 검토할 수 있다. 일반 구현 버그·업무 규칙·성능 최적화는 다른 검토 범위다. [plugin 안내](https://github.com/trailofbits/skills/blob/main/plugins/sharp-edges/README.md)

**Agent 활용 예시**

> AuthConfig를 sharp-edges로 읽기 전용 검토해줘. otpLifetime=0, 음수 재시도 횟수, 빈 키와 TLS 검증 비활성화 조합이 어떻게 처리되는지 추적해. 확인된 문제와 실행 검증이 필요한 가설을 나누고, 설정 변경은 하지 마.

**평가:** 오늘의 **Codex 즉시 활용 후보**다. 공통 SDK나 설정 스키마의 작은 범위를 정해 읽기 전용으로 시작하기 좋다.

- **도입 난이도:** 낮음~중간. 텍스트 PDF는 시작하기 쉽지만 OCR·복잡한 양식은 검증이 늘어난다.

### 인기 및 트렌드 지표

### 내용

텍스트·표 추출, 병합·분리, 회전, 이미지 추출, PDF 생성과 양식 작성, 스캔 OCR에 맞는 도구를 선택하게 한다. pypdf·pdfplumber·ReportLab과 Poppler·qpdf 등의 역할을 나누어 안내한다. 하나의 추출 결과를 모든 페이지에 그대로 적용하기보다 입력 파일의 성격을 먼저 확인하는 데 유용하다. [공식 Skill](https://github.com/anthropics/skills/blob/main/skills/pdf/SKILL.md)

양식은 입력 가능한 필드가 있는지 확인한 뒤 구조·좌표·이미지를 이용한다. 원형 체크박스와 복잡한 그래픽을 구조 추출이 놓칠 수 있으므로 실제 페이지를 검토한다. OCR 결과도 숫자·표·읽기 순서의 정확성을 자동 보장하지 않는다. 한국어 자료는 글꼴과 OCR 언어 준비를 별도로 확인해야 하며, 이는 적용 권고이지 이번 조사에서 측정한 성능이 아니다. [양식 안내](https://github.com/anthropics/skills/blob/main/skills/pdf/forms.md)

**현재 원문의 경로 표기에 주의한다.** SKILL.md는 FORMS.md·REFERENCE.md를 안내하지만 실제 파일은 소문자 `forms.md`·`reference.md`다. 대문자 FORMS.md 주소는 조회 시 404였다. 대소문자를 구분하는 환경에서는 현재 실제 경로를 따른다. [현재 reference](https://github.com/anthropics/skills/blob/main/skills/pdf/reference.md)

### 설치 및 사용

아래 공통 **Anthropic 문서 Skill 설치·라이선스** 절의 공식 Claude 경로를 따른다. `npx skills`에 Codex 설치 명령이 표시되더라도 외부 사용 허락의 근거로 보지 않는다.

**전제조건:** 선택한 작업에 맞는 Python library·Poppler·OCR 실행 환경이 필요하다. 파일을 외부 서비스에 업로드하는 작업과 로컬 추출을 구분하고, 원본 보존·민감 정보·제출 권한을 먼저 확인한다.

**Agent 활용 예시**

> PDF 매뉴얼 세 개에서 모델별 사양표를 출처 페이지와 함께 정리해줘. 스캔 페이지는 OCR로 읽고 불확실한 숫자를 표시해. 원본은 유지하고, 양식 제출이나 외부 업로드 없이 검토용 요약을 만들어줘.

**평가:** 반복되는 PDF 업무의 작업 경로를 정하는 데 유용하다. 정확도가 중요한 숫자·서명·제출용 양식은 사람이 확인할 검토 단계를 남긴다.

## 5. docx

### 인기 및 트렌드 지표

### 내용

새 Word 문서는 npm의 docx로 작성하고 기존 문서는 압축을 풀어 OOXML을 편집하는 경로를 구분한다. docx-js가 기존 파일을 그대로 열어 수정하는 도구라는 가정을 피한다. 제목·표·목차 같은 서식뿐 아니라 변경 내용 추적과 주석을 다루는 데 유용하다. [공식 Skill](https://github.com/anthropics/skills/blob/main/skills/docx/SKILL.md)

문장이 여러 XML run으로 나뉠 수 있고, 주석 본문을 만들었다고 연결 지점까지 생기는 것은 아니다. 변경 전후 텍스트와 관계를 검사하고 마지막에는 렌더링 결과도 확인해야 한다. 유효한 XML과 원하는 Word 화면은 서로 다른 검증 대상이다.

원문에서 도구가 “이미 설치되어 있다”고 말하는 부분은 특정 실행 환경의 전제다. 다른 환경에 docx·pandoc·LibreOffice·Poppler가 준비됐다고 가정하지 않는다. 변환 도구에서 추적된 문단 삭제를 처리할 때 빈 문단·글머리표가 남아 보일 수 있는 제한도 있으므로 원본 Word 동작과 같다고 단정하지 않는다. [현재 편집·검증 지침](https://github.com/anthropics/skills/blob/main/skills/docx/SKILL.md)

### 설치 및 사용

공통 설치 절의 **Claude document-skills 묶음**을 사용한다. 기존 문서의 수정을 요청할 때는 원본 파일·수정할 내용·변경 이력 보존 여부를 명확히 지정한다.

**Agent 활용 예시**

> 기존 제안서의 제목·표·머리말을 유지하면서 제공한 새 일정만 반영해줘. 수정은 변경 내용 추적으로 남기고 확인할 문장은 주석으로 표시해. 원본 대비 구조 검증과 렌더링을 확인하고, 기존 변경 내용은 임의로 수락하지 마.

**평가:** 기존 제안서·검토 문서처럼 변경 이력을 보존해야 하는 업무의 후보다. 계약 내용 판단·서명·배포는 파일 편집과 별도 단계로 다룬다.

### 내용

새 덱은 PptxGenJS, 기존 덱·템플릿은 OOXML 편집, 내용 추출은 markitdown, 배치 확인은 thumbnail 도구로 역할을 나눈다. 반복 보고서를 만들 때 기존 구조를 확인하고 슬라이드 순서·추가·삭제를 정한 뒤 내용을 편집하는 흐름이 유용하다. 지원되는 차트는 네이티브 객체로 만들어 편집 가능성을 유지하도록 한다. [공식 Skill](https://github.com/anthropics/skills/blob/main/skills/pptx/SKILL.md)

내용 검토에서는 순서·누락·플레이스홀더를 보고, 파일 검토에서는 스키마·관계·차트를 확인하며, 시각 검토에서는 전체 슬라이드를 렌더링해 잘림·겹침·대비를 살핀다. 이미지가 잘 보인다는 사실만으로 실제 PowerPoint에서 문제없이 열린다고 확정할 수 없다.

슬라이드를 복제하면 차트·SmartArt·임베디드 객체가 원본과 공유될 수 있어 한쪽 수정의 영향 범위를 확인해야 한다. 렌더링 환경의 대체 글꼴과 발표할 컴퓨터의 글꼴이 다르면 줄바꿈이 달라질 수 있다. 한국어 덱도 실제 사용할 글꼴과 앱에서 마지막 확인을 하는 편이 좋다. [현재 편집·QA 지침](https://github.com/anthropics/skills/blob/main/skills/pptx/SKILL.md)

공통 설치 절의 Claude 문서 Skill 묶음에서 사용한다. 템플릿과 최신 데이터의 출처·기간을 제공하고 편집 가능해야 할 요소를 미리 지정한다.

**Agent 활용 예시**

> 지난달 템플릿으로 이번 달 자료를 8장으로 정리해줘. 매출 차트는 편집 가능하게 유지하고 발표자 노트를 넣어. 이전 달 수치·플레이스홀더·공유 차트 영향이 남지 않았는지 확인하고 모든 슬라이드를 렌더링해 검토해줘.

**평가:** 자료 작성보다 수정·검증 과정까지 묶고 싶을 때 적합하다. 실제 글꼴·원본 객체·발표 앱 검증이 빠지면 외형만 보고 완성이라고 판단하지 않는다.

### 오늘 보이는 공통 흐름

오늘 확인한 원문들은 **검증 대상과 완료 근거를 분리**하는 데 가치가 있었다. 속성 테스트의 실행 횟수와 성질의 타당성, 호출자 수와 악용 가능성, 안전한 기본값과 위험한 덮어쓰기, 유효한 XML과 실제 렌더링은 각각 다른 확인 대상이다.

배포 형태와 이용 조건도 추천에 직접 영향을 준다. insecure-defaults는 현재 명령·workflow plugin으로 바뀌었고, 공개 문서 Skill은 제한적 라이선스를 갖는다. 디렉터리의 이름·설치 수·명령만 보고 현재 설치 가능한 동일 Skill이나 자유로운 이용 권한으로 해석하면 안 된다. 이는 이번 조사에서 확인한 사례이며 생태계 전체의 성장 통계로 확대하지 않는다.

- **Skills CLI 참고:** 이번 보고서는 설치를 실행하지 않았다. `npx skills`를 별도로 사용할 경우 패키지 다운로드·실행과 파일 변경이 발생할 수 있다. 조회한 [main의 package.json](https://github.com/vercel-labs/skills/blob/main/package.json)은 Node **22.20.0 이상**을 요구한다. CLI README의 `DISABLE_TELEMETRY=1` 또는 `DO_NOT_TRACK=1`은 사용량 전송과 감사 요청을 끄는 옵션이며 라이선스 제약을 바꾸지 않는다.
- pdf·docx·pptx의 감사 Warn 상세는 접근 실패로 사유를 확정하지 않았다. sharp-edges 감사는 날짜가 있는 과거 결과이며 현재 revision 전체와의 동일성을 검증한 것은 아니다.
