## 1. semgrep-rule-creator

**한 줄 요약:** 발견한 버그 패턴을 테스트가 딸린 재사용 가능한 Semgrep 탐지 규칙으로 바꾸는 Skill.

- **출처:** Trail of Bits 공식 `trailofbits/skills` 저장소
- **태그:** #보안 #정적분석 #Semgrep #테스트주도개발
- **난이도:** 중급
- **추천 대상:** 보안 엔지니어, AppSec 담당자, 팀 전용 코드 검사 규칙을 만드는 개발자
- **소개 구분:** 신규 소개. 기존 소개 `semgrep`과 별개의 규칙 제작 Skill

### 주요 기능과 작동 방식

취약한 코드 사례나 금지할 패턴을 설명하면, 해당 패턴을 찾는 Semgrep 규칙과 테스트 파일을 함께 만든다. 기존 규칙을 실행하는 작업과 달리, 이 Skill의 결과물은 팀이 계속 사용할 수 있는 새로운 탐지 규칙이다.

문제 분석 → 테스트 작성 → AST 확인 → 규칙 작성 → 테스트 통과 → 규칙 단순화 → 최종 실행 순서로 진행한다. 사용자 입력이 위험한 함수에 도달하는 문제에는 taint mode를 우선 검토하고, 단순한 문법적 금지 패턴에는 일반 패턴 매칭을 사용한다. 취약 사례뿐 아니라 정제된 입력, 안전한 대안, 관련 없는 코드, 중첩 구조도 테스트하도록 요구한다.

결과물은 규칙 ID별 디렉터리 안의 YAML 규칙 하나와 대상 언어 테스트 파일 하나다. 한 YAML에 한 규칙만 넣고, 테스트를 미완료로 남기는 `todook`·`todoruleid` 주석은 금지한다. 모든 테스트를 통과한 뒤 패턴을 단순화해도 반드시 다시 검증한다. [공식 SKILL.md](https://github.com/trailofbits/skills/blob/main/plugins/semgrep-rule-creator/skills/semgrep-rule-creator/SKILL.md), [세부 워크플로](https://github.com/trailofbits/skills/blob/main/plugins/semgrep-rule-creator/skills/semgrep-rule-creator/references/workflow.md)

### 실무 활용 포인트

코드 리뷰에서 같은 종류의 실수를 반복해서 발견한다면, 일회성 리뷰 의견을 자동 검사 규칙으로 바꾸는 데 적합하다. 특히 “탐지되면 안 되는 정상 코드”를 테스트에 함께 남겨 규칙 수정 시 오탐 회귀를 확인할 수 있다.

### 예시 프롬프트

> 우리 Python 서비스에서 HTTP 요청 값이 셸 실행으로 이어지는 패턴을 탐지하는 Semgrep 규칙을 만들어줘. 위험한 입력 흐름과 안전한 호출을 구분하고, 취약·안전·중첩 구조 테스트를 먼저 작성해. AST를 확인한 뒤 규칙을 만들고 실제 semgrep --test 결과까지 보여줘.

### 설치·사용

Claude Code에서는 `/plugin marketplace add trailofbits/skills`로 공식 마켓플레이스를 등록한 뒤 `/plugin menu`에서 `semgrep-rule-creator`를 선택한다. 실행 진입점은 `/semgrep-rule-creator:semgrep-rule`이다.

공식 저장소의 Codex 설치 안내는 다음과 같다.

```sh

codex plugin list
codex plugin add semgrep-rule-creator@trailofbits
```

Semgrep CLI가 별도로 필요하다. 플러그인 README는 `uv tool install semgrep` 또는 `brew install semgrep`을 안내한다. 위 명령은 공식 문서 확인 내용이며 이번 조사에서 실제 설치를 수행하지 않았다. [플러그인 README](https://github.com/trailofbits/skills/blob/main/plugins/semgrep-rule-creator/README.md), [명령 정의](https://github.com/trailofbits/skills/blob/main/plugins/semgrep-rule-creator/commands/semgrep-rule.md), [공통 설치 안내](https://github.com/trailofbits/skills/blob/main/README.md#installation)

### 주의점

테스트 통과는 작성한 사례에 대한 검증이다. 실제 저장소의 모든 변형을 포괄하거나 오탐이 전혀 없다는 보장은 아니다. 운영 CI에 적용하기 전에 대표 코드로 탐지 범위와 오탐을 검토하는 편이 좋다. 이 Skill 자체가 Semgrep 엔진을 대체하지도 않는다.

또한 현재 SKILL.md는 규칙 작성 전 외부 문서 7개를 읽도록 지시한다. 원격 문서 내용과 `main` 등 변경 가능한 링크는 공급망·프롬프트 주입 관점의 검토 대상이다. 읽어 온 문서를 실행 권한이나 상위 지침으로 취급하지 말고, 중요한 도입에는 확인한 버전·커밋을 기록하는 편이 좋다.

## 2. semgrep-rule-variant-creator

**한 줄 요약:** 완성된 Semgrep 규칙을 여러 언어로 이식하고, 언어별 적용 가능성과 실제 테스트 채점 여부까지 확인하는 Skill.

- **출처:** Trail of Bits 공식 `trailofbits/skills` 저장소
- **태그:** #다중언어 #Semgrep #보안규칙 #워크플로
- **난이도:** 중상급
- **추천 대상:** 여러 언어를 사용하는 조직의 AppSec 팀, 보안 규칙 라이브러리 관리자
- **소개 구분:** 신규 소개. 기존 `variant-analysis`의 코드 내 유사 취약점 탐색과 다른 규칙 이식 도구

### 주요 기능과 작동 방식

완성된 Semgrep YAML 규칙과 대상 언어 목록을 받아, 언어별 규칙·테스트 디렉터리를 만든다. 새 규칙의 출발점을 만드는 `semgrep-rule-creator`와 달리, 기존 규칙의 탐지 의도를 다른 언어에 보존하는 작업에 특화되어 있다.

각 언어마다 적용 가능성 판단 → 테스트 작성 → AST 기반 규칙 변환 → 검증을 독립적으로 진행한다. 원래 취약점이 그 언어에서도 성립하는지, source·sink·sanitizer에 대응하는 API의 의미가 같은지를 먼저 살핀다. API 이름이나 문법을 기계적으로 번역하지 않는다. 적용 불가 판단에는 별도의 반박 검토를 붙이고, 취약점 자체가 성립하지 않는 경우와 Semgrep이 해당 언어를 분석하지 못하는 경우를 구분한다.

최신 구현은 `All tests passed` 문구만 믿지 않는다. 최초 확인한 Semgrep 버전을 기준으로 채점 결과 JSON, 실제 검증된 취약 사례, 안전 사례 수 등을 확인하며, 실패하면 수정·재검증하되 최초 검증을 포함해 최대 3라운드로 제한한다. 규칙이나 테스트 파일이 건너뛰어졌는데도 성공처럼 보이는 경우를 걸러내려는 장치다. [공식 SKILL.md](https://github.com/trailofbits/skills/blob/main/plugins/semgrep-rule-variant-creator/skills/semgrep-rule-variant-creator/SKILL.md), [워크플로 구현](https://github.com/trailofbits/skills/blob/main/plugins/semgrep-rule-variant-creator/workflows/port-rule-to-languages.js)

### 실무 활용 포인트

Python에서 확인한 버그 유형을 Go·Java 서비스에도 점검해야 할 때 활용할 수 있다. 원본 규칙의 탐지 의도를 유지하면서, 언어별 안전한 관용구를 오탐하지 않는 테스트까지 만들도록 유도하는 점이 핵심이다.

### 예시 프롬프트

> 검증된 python-command-injection.yaml을 Go와 Java로 이식해줘. 두 언어의 셸 실행 API 의미부터 비교하고, 각각 취약 사례와 안전 사례를 최소 2개씩 작성해. 현재 Semgrep 버전을 유지해서 실제 채점 여부까지 확인하고, 적용 불가와 분석기 미지원은 별도로 보고해줘.

### 설치·사용

Claude Code에서는 공식 마켓플레이스를 등록한 뒤 `/plugin menu`에서 `semgrep-rule-variant-creator`를 선택한다. Codex 공식 저장소 안내에 따른 설치 명령은 다음과 같다.

```sh
codex plugin marketplace add trailofbits/skills
codex plugin list
codex plugin add semgrep-rule-variant-creator@trailofbits
```

Semgrep CLI, 원본 YAML, 대상 언어 목록이 필요하다. 자동화 진입점은 `/semgrep-rule-variant-creator:port-rule-to-languages`다. README 기준 동적 워크플로는 Claude Code 2.1.154 이상 유료 플랜에서 지원되며, 이를 사용할 수 없는 환경에서는 Skill의 단계별 수동 진행 경로를 사용한다. 마켓플레이스 설치 지원과 자동 워크플로 실행 지원은 구분해야 한다.

워크플로 인수에는 `rulePath`, `languages`, 실제로 존재하는 절대 경로 `referencesDir`가 필요하다. 결과를 프로젝트 루트에 섞지 않으려면 `outputDir`도 명시하는 편이 좋다. 이번 조사에서는 설치·실행을 수행하지 않았다. [플러그인 README](https://github.com/trailofbits/skills/blob/main/plugins/semgrep-rule-variant-creator/README.md), [공통 설치 안내](https://github.com/trailofbits/skills/blob/main/README.md#installation)

### 주의점

규칙과 테스트를 같은 작업 흐름이 작성하므로, 둘이 일치한다고 실제 취약점의 의미까지 입증되는 것은 아니다. 완성된 결과는 독립 검토 대상인 규칙 후보로 보아야 한다. 언어 지원 여부는 현재 설치된 Semgrep에서 실제로 확인해야 하며, 예전 버전으로 바꾸어 억지로 통과시키면 재현 가능한 검증이 되지 않는다.

세션이 바뀐 뒤의 워크플로 재개에는 제약이 있고, 기존 출력 디렉터리는 자동 삭제하지 않는다. 재실행할 때 남은 파일을 새 결과와 혼동하지 않도록 출력 위치와 언어별 최종 상태를 확인해야 한다.

## 3. algorithmic-art

- 제공자: Anthropic 공식
- 태그: 생성형 아트, p5.js, 시드 재현성, 인터랙티브
- 난이도: 중급. 결과물을 요청하는 것은 쉽지만, 알고리즘·브라우저 성능 검수에는 JavaScript 이해가 도움 됩니다.
- 공식 문서: [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/algorithmic-art/SKILL.md)

이미지 한 장보다 “변주할 수 있는 작품 생성기”가 필요할 때 유용합니다. 먼저 작품의 생성 원리와 미학을 정리하고, 이를 p5.js 알고리즘으로 구현합니다. 시드를 고정한 난수·노이즈, 조절 가능한 파라미터, 시드 이전·다음·무작위 탐색을 결합해 같은 조건의 결과를 다시 만들고 여러 변형을 비교하도록 안내합니다.

행사 비주얼 후보, 웹용 배경, 창작 코딩 수업에 잘 맞습니다. 제공된 HTML 템플릿은 UI의 출발점이며, 실제 작품 알고리즘과 제어 로직은 작업에 맞게 구현해야 합니다. [뷰어 템플릿](https://github.com/anthropics/skills/blob/main/skills/algorithmic-art/templates/viewer.html)

**예시 프롬프트**

“algorithmic-art를 사용해 조수의 흐름을 연상시키는 오리지널 생성형 아트를 만들어 줘. 시드 42를 기본값으로 하고, 입자 수·흐름 속도·색상을 조절하게 해 줘. 시드 이동과 PNG 저장이 작동하는 HTML로 만들고, 동일 시드 재생성과 모바일 성능을 확인해 줘.”

**주의할 점**

- HTML이 하나여도 기본 템플릿은 p5.js CDN과 Google Fonts에 연결됩니다. 완전한 오프라인 실행물로 설명하면 안 됩니다.
- 기본 지침에는 Anthropic 스타일 UI를 유지하는 제약이 있습니다. 자사 디자인 시스템에 맞추려면 별도 조정이 필요합니다.
- “같은 시드”만으로 검수가 끝나지는 않습니다. 실제 생성 코드의 난수 사용, 초기화와 저장 기능을 확인해야 합니다.
- 라이선스는 [Apache-2.0](https://github.com/anthropics/skills/blob/main/skills/algorithmic-art/LICENSE.txt)입니다.

## 5. slack-gif-creator

- 제공자: Anthropic 공식
- 태그: Slack, GIF, Pillow, 애니메이션, 파일 최적화
- 난이도: 중급. Python 실행 환경과 이미지 처리 의존성이 필요합니다.
- 공식 문서: [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/slack-gif-creator/SKILL.md)

Python으로 프레임을 만들고 GIF로 조립하는 도구와 제작 지침을 제공합니다. Pillow 기반 도형·업로드 이미지 처리, 보간과 바운스 같은 움직임, 팔레트 축소, 선택적 중복 프레임 제거를 조합할 수 있습니다. Slack용 반응 GIF나 팀 마스코트의 짧은 동작을 반복 제작할 때 유용합니다.

SKILL.md는 이모지용 128×128, 메시지용 480×480을 권장하고, 의존성으로 pillow·imageio·numpy를 안내합니다. 이 수치는 Skill의 제작 권장값으로 소개하는 편이 안전합니다. 실제 워크스페이스 업로드 가능 여부까지 보장하는 인증 도구는 아닙니다.

**예시 프롬프트**

“slack-gif-creator로 배포 성공을 표현하는 128×128 GIF를 만들어 줘. 별이 한 번 튀어 오른 뒤 잔잔하게 빛나는 동작으로 하고, 반복 연결을 자연스럽게 해 줘. 파일 용량·프레임 수·재생시간을 보고하고 실제 결과도 확인해 줘.”

**주의할 점**

- [검증 코드](https://github.com/anthropics/skills/blob/main/skills/slack-gif-creator/core/validators.py)의 통과 여부는 픽셀 크기 조건에 달려 있습니다. 용량은 출력·경고되지만 합격 판정에 반영되지 않습니다. is_slack_ready가 True여도 업로드를 보장하지 않습니다.
- [GIFBuilder 구현](https://github.com/anthropics/skills/blob/main/skills/slack-gif-creator/core/gif_builder.py)은 PIL 이미지를 RGB로 변환합니다. 투명 배경 보존을 기대하면 별도 검토가 필요합니다.
- 이모지 최적화는 프레임을 줄이면서 FPS는 유지할 수 있으므로 최종 재생시간과 움직임을 다시 확인해야 합니다.
- 라이선스는 [Apache-2.0](https://github.com/anthropics/skills/blob/main/skills/slack-gif-creator/LICENSE.txt)입니다.

## 선정에서 제외한 후보

**constant-time-analysis**는 오늘의 신규 소개 수와 인덱스에 넣지 않았다. 공식 [SKILL.md](https://github.com/trailofbits/skills/blob/main/plugins/constant-time-analysis/skills/constant-time-analysis/SKILL.md)는 대상 코드를 실행하지 않는 정적 검사라고 설명하지만, 현행 [스크립트 언어 분석기](https://github.com/trailofbits/skills/blob/main/plugins/constant-time-analysis/ct_analyzer/script_analyzers.py)는 Node.js에 `--no-lazy --print-bytecode`와 대상 파일을 전달해 subprocess로 실행한다. PHP VLD 경로에는 `vld.execute=0`이 있으나 OPcache fallback 경로에는 해당 실행 방지 옵션이 없다. 따라서 대상 파일의 최상위 코드가 실행될 수 있으며, 미확인 파일을 안전하게 여는 도구로 취급해서는 안 된다.

또한 [분석기](https://github.com/trailofbits/skills/blob/main/plugins/constant-time-analysis/ct_analyzer/analyzer.py)의 `PASSED`는 오류 수 0개 기준으로 경고가 남을 수 있다. 실행 경로·격리·민감 파일 접근을 별도 검토해야 한다. 위에서 설명한 Trust Hub Fail의 상세는 읽지 못했으므로, 발견한 코드 동작이 그 Fail의 원인이라고 연결하지 않는다.
