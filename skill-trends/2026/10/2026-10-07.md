### 내용

React 코드에서 보안·성능·정확성·아키텍처 문제를 찾아 변경 후 다시 점검하는 Skill이다. 변경분은 `--scope changed`, 전체 점검은 기본 full scope, 디자인은 `design`, 실제 느린 상호작용은 `scan <url>`로 구분한다. 기존 React 모범 사례 Skill이 지침 중심이었다면 이번 항목은 **CLI 진단과 재검사**가 핵심이다. [공식 Skill](https://github.com/millionco/react-doctor/blob/main/skills/react-doctor/SKILL.md)

변경분 판정은 파일·규칙별 진단 수 증가를 중심으로 한다. 같은 그룹에서 문제 하나를 없애고 다른 문제 하나를 추가하면 새 문제로 잡히지 않을 수 있다. 점수가 유지됐다고 회귀가 없다고 단정하지 말고 전체 검사·테스트와 함께 본다. baseline을 비교할 때도 도구 버전·규칙·필터 설정을 맞춘다.

`/doctor` 전체 정리는 원격 playbook과 규칙별 지침을 가져온 뒤 작업 트리를 수정하는 흐름이다. 설치한 Skill 버전을 고정해도 원격 지침이 달라질 수 있다. 이번에는 playbook URL은 확인했지만 본문 접근은 실패했으므로 그 전체 수정 workflow를 실행 검증한 것으로 보지 않는다.

### 설치 및 사용

Skill만 개별 설치하는 예:

```bash
npx skills add https://github.com/millionco/react-doctor --skill react-doctor --agent codex
```

공식 README의 `npx react-doctor@latest install`은 **프로젝트 통합 설정**이다. dev dependency·스크립트를 추가하고 선택에 따라 Git hook·Agent hook·GitHub Actions도 설정하므로 위 단일 Skill 설치와 범위가 다르다. 자동 승인 옵션을 붙이기 전에 변경 범위를 확인한다. [실제 설치 구현](https://github.com/millionco/react-doctor/blob/main/packages/react-doctor/src/cli/utils/install-react-doctor.ts)

이미 도구 사용을 승인한 프로젝트에서 변경분 진단을 시작하는 예:

```bash
npx react-doctor@latest --verbose --scope changed --no-telemetry
```

**전제조건:** 현재 Node 요구사항은 **`^20.19.0 || >=22.13.0`**이다. `npx ...@latest`는 패키지를 내려받아 실행할 수 있으며 버전도 바뀐다. 재현 가능한 비교에는 실제 실행 버전을 기록한다. 런타임 기록에는 시스템 Chrome과 실행 중인 앱이 필요하다. [패키지 요구사항](https://github.com/millionco/react-doctor/blob/main/packages/react-doctor/package.json)

CLI는 기본 telemetry를 보내므로 위 예시는 `--no-telemetry`를 명시했다. 이 옵션을 쓴다고 npm 다운로드나 원격 playbook까지 없어지는 것은 아니다. browser trace에는 URL·소스 경로·앱 정보가 들어갈 수 있으므로 업로드 전에 검토한다. [README](https://github.com/millionco/react-doctor/blob/main/README.md), [telemetry 제어](https://github.com/millionco/react-doctor/blob/main/packages/react-doctor/src/cli/utils/is-telemetry-enabled.ts)

**Agent 활용 예시**

> 이번 브랜치를 react-doctor의 변경분 범위와 --no-telemetry로 점검해줘. 파일·행별 오류와 경고, 비교 기준을 정리하고 수정 계획부터 보여줘. 승인한 수정 뒤 같은 조건으로 재검사하고 기존 테스트도 실행해줘.

**평가:** 오늘의 Codex 즉시 활용 후보다. 먼저 진단만 실행하고, 전체 자동 정리·hook 설정·browser 기록은 별도 단계로 확장하는 방식이 적합하다.

## 2. upgrade-stripe

- **출처/제작자:** [Stripe 공식 AI 저장소](https://github.com/stripe/ai), [현재 설치 문서](https://docs.stripe.com/skills)
- **원 Skill:** [upgrade-stripe/SKILL.md](https://github.com/stripe/ai/blob/main/skills/upgrade-stripe/SKILL.md)
- **지원 Agent:** 공식 Codex·Claude Code·Cursor plugin과 표준 Skill 설치 경로. plugin과 Skill 단독의 기능·접근 범위를 구분한다.
- **태그:** `#Stripe` `#API버전` `#Webhook` `#호환성검증`
- **도입 난이도:** 중간~높음. 실제 운영 결제 흐름과 이벤트 처리의 회귀 검증이 필요하다.

### 인기 및 트렌드 지표

- [skills.sh](https://www.skills.sh/stripe/ai/upgrade-stripe): **57.4K installs**는 **지난달 크롤링된 페이지의 표시값**이다. 당일 설치량이나 현행 최신 지침으로 사용하지 않았다.
- 같은 캐시의 감사 표시: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Fail**
- [Snyk 상세](https://www.skills.sh/stripe/ai/upgrade-stripe/security/snyk)는 **2026-05-29**자로 키 예제와 결제 API 접근 가능성을 지적한다. 현재 파일 전체에 대한 최신 판정으로 해석하지 않는다.
- Stripe AI 모음 전체: **1,858 stars / 353 forks**
- 현재 Skill에는 **2026-10-06 생성**된 fallback API 버전 **`2026-09-30.endive`**가 적혀 있다.

### 내용

기존 연동의 서버 SDK, API pin, 요청별 override, Stripe.js·모바일 SDK와 webhook 버전을 함께 점검한다. 사용자가 정한 목표가 없으면 현재 공식 문서에서 대상 버전을 확인하며, 명시적 요청 없이 다운그레이드하거나 stable을 preview로 바꾸지 않는다. 기존 `stripe-best-practices`가 통합 설계 지침이라면 이번 항목은 **이미 사용하는 연동의 버전 이동**이다. [공식 Skill](https://github.com/stripe/ai/blob/main/skills/upgrade-stripe/SKILL.md)

이번 조회에서 공식 API 문서도 **`2026-09-30.endive`**를 현재 버전으로 표시했다. 그러나 예제에 적힌 값을 영구적인 최신값처럼 복사하지 않는다. 실행 시 다시 확인하고 라이브 조회가 안 되면 “최신 미확인”으로 남긴다. Java·Go·.NET은 임의 API override보다 해당 API를 대상으로 하는 SDK 릴리스 선택이 필요하다. [API versioning](https://docs.stripe.com/api/versioning.md)

Webhook에서는 snapshot과 thin event를 구분한다. thin payload가 unversioned여도 관련 자원을 가져오는 API 호출은 버전 영향을 받는다. 변경할 수 없는 버전의 v2 snapshot destination은 대체 대상을 만들고 시험해야 하므로, signing secret·중복 수신·전환 순서까지 고려한다. 단순 package update로 끝나는 작업이 아니다.

### 설치 및 사용

현재 공식 문서의 Skill 수동 설치 경로:

```bash
npx skills add https://docs.stripe.com
```

선택 단계에서 필요한 Skill과 사용할 Agent만 고른다. 수동 설치본은 자동 갱신되지 않으므로 변경 전 원문과 버전을 다시 확인한다. 공식 권장 `stripe agent setup`/plugin 경로는 MCP 구성과 추가 기능까지 포함해 범위가 더 넓다. **Skill 설치만으로 계정 접근이 생기지는 않는다.** [공식 설치 문서](https://docs.stripe.com/skills)

**전제조건:** 코드·dependency manifest·버전 pin을 읽을 수 있어야 한다. 계정 기본값과 webhook 설정 조회에는 별도 승인된 접근이 필요하다. 실제 키를 예제 코드·프롬프트·shell 기록에 넣지 않고 승인된 secret 관리 방식을 쓴다. 분석과 패치 초안부터 시작하고, 운영 계정 버전 변경·destination 교체·실제 결제 요청은 별도로 승인·검증한다.

**Agent 활용 예시**

> 서버 SDK, API pin, 요청별 override와 webhook 버전을 목록화해줘. 공식 문서로 목표 안정 버전을 확인하고 breaking change·테스트 계획·패치 초안을 준비해. 계정 기본 버전과 운영 webhook은 변경하지 마.

**평가:** 오늘의 Top Pick이다. “최신으로 올리기”를 하나의 명령으로 취급하지 않고 **목표 확인 → 전체 pin 대조 → 호환성 검사 → 테스트 전환**으로 나눈다. 오래된 디렉터리 캐시와 실제 최신 원문의 차이가 큰 만큼 원문 재확인이 필수다.

## 3. terraform-search-import

- **출처/제작자:** [HashiCorp 공식 Agent Skills](https://github.com/hashicorp/agent-skills), [skills.sh 항목](https://www.skills.sh/hashicorp/agent-skills/terraform-search-import)
- **원 Skill:** [terraform-search-import/SKILL.md](https://github.com/hashicorp/agent-skills/blob/main/plugins/terraform/skills/terraform-search-import/SKILL.md)
- **지원 Agent:** Codex·Claude Code plugin 및 표준 Skill 호스트.
- **태그:** `#Terraform` `#기존인프라` `#리소스검색` `#Import`
- **도입 난이도:** 높음. 계정·region·provider 지원과 기존 state 소유 관계를 확인해야 한다.

### 인기 및 트렌드 지표

- skills.sh: **installs 4.7K**, First Seen **2026-03-03**. 검색 도구에는 **6일 전 크롤링**으로 표시됐다.
- 감사 표시: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Pass**
- HashiCorp Agent Skills 모음 전체: **885 stars / 130 forks**
- 현재 Skill metadata는 `active`·version **0.1.0**이며 Terraform **1.14 이상**과 list resource 지원 provider를 요구한다.

### 내용

이미 만들어진 cloud 자원을 찾아 Terraform 관리 대상으로 가져오는 workflow다. 설치된 provider가 대상 자원의 목록 조회를 지원하는지 확인한 다음 `.tfquery.hcl`의 `list`로 범위를 정하고, `terraform query`로 조회하며 `resource`·`import` 블록을 생성한다. 미지원 유형은 별도 수동 발견 경로로 분기한다. [공식 Skill](https://github.com/hashicorp/agent-skills/blob/main/plugins/terraform/skills/terraform-search-import/SKILL.md)

**조회용 helper도 무조건 읽기 전용은 아니다.** 현재 `list_resources.sh`는 `.terraform` 디렉터리가 없으면 `terraform init -upgrade`를 실행한다. 이 옵션은 lockfile의 기존 provider 선택 대신 허용 범위 내 새 버전을 검토하므로, 단순 지원 여부 조사 중 dependency가 바뀔 수 있다. 기존 초기화 상태와 lockfile을 먼저 확인하고 업그레이드를 별도로 결정한다. [실제 스크립트](https://github.com/hashicorp/agent-skills/blob/main/plugins/terraform/skills/terraform-search-import/scripts/list_resources.sh), [init 공식 문서](https://developer.hashicorp.com/terraform/cli/commands/init)

검색·구성 생성과 state 편입은 별개다. 생성 파일을 검토한 뒤 plan에서 예상한 import 외의 변경·재생성이 없는지 확인해야 한다. 다른 workspace가 이미 관리하는 자원을 중복 편입하지 않는다. 공식 bulk 문서의 resource identity 관련 **1.12** 설명을 이 Skill의 **1.14+** 실행 조건과 혼동하지 않는다. [Bulk import 안내](https://developer.hashicorp.com/terraform/language/import/bulk)

### 설치 및 사용

```bash
npx skills add hashicorp/agent-skills/plugins/terraform/skills/terraform-search-import --agent codex
```

### 내용

`moved`는 주소 변경으로 인한 불필요한 재생성을 피하도록 돕지만 다른 속성 변경까지 무효화하지 않는다. Terraform **1.1+**에서 지원하며, 이동 이력을 성급히 제거하면 이전 버전 사용자의 업그레이드 경로를 깨뜨릴 수 있다. 기존 CIDR·태그·자원 수·provider를 보존하고 실제 plan을 확인해야 한다. [공식 refactoring 안내](https://developer.hashicorp.com/terraform/language/modules/develop/refactoring)

```bash

```

**평가:** 어제의 `terraform-test`가 동작 검증이라면, 이번 항목은 **기존 자원의 정체성을 유지하며 구조를 바꾸는 과정**이다. 좋은 체크리스트이지만 예제의 정확성을 별도로 검증해야 하는 검토형 후보로 분류한다.

- **중복 확인:** [누적 인덱스](https://github.com/wooguylee/ChatGPT_Work/blob/main/skill-trends/introduced-skills.md) 전체와 기존 날짜별 보고서 **33개·소개 198개**를 조회해 이름·최초 소개일을 대조했다. 누락은 없었다. 기존 `Octocode / octocode-install` 표기도 같은 항목으로 처리했다. 오늘 6개는 기존 소개와 별도 Skill이며, 단순 개명·재등장으로 세지 않았다.
- **기존 형식:** [10월 6일 보고서](2026-10-06.md), [10월 5일 보고서](2026-10-05.md), [CHANGELOG](../../CHANGELOG.md)를 확인했다. 기존 인덱스·최초 소개일·재등장 규칙을 보존하며 과거 날짜 보고서는 새로 만들지 않는다.
- **기능·설치 원천:** [React Doctor README](https://github.com/millionco/react-doctor), [Stripe README](https://github.com/stripe/ai), [Stripe Skills](https://docs.stripe.com/skills), [HashiCorp README](https://github.com/hashicorp/agent-skills), [Anthropic README](https://github.com/anthropics/skills), [Skills CLI](https://github.com/vercel-labs/skills). `--agent codex`는 현행 CLI 문법을 적용한 예이며 설치·실행 호환성을 모두 실험한 것은 아니다.
- **저장소 지표 원천:** [React Doctor API](https://api.github.com/repos/millionco/react-doctor), [Stripe API](https://api.github.com/repos/stripe/ai), [HashiCorp API](https://api.github.com/repos/hashicorp/agent-skills), [Anthropic API](https://api.github.com/repos/anthropics/skills). 개별 설치·감사 표시의 출처는 각 항목에 연결했다.
- **선정 제외:** `huggingface-paper-publisher`도 조사했으나 [현재 paper_manager.py](https://github.com/huggingface/skills/blob/main/skills/huggingface-paper-publisher/scripts/paper_manager.py)의 `link_paper_to_repo()`는 `create_pr=True`여도 PR 미구현 안내 뒤 README를 직접 업로드한다. `--create-pr`를 검토용 안전장치로 소개할 수 없어 이번 추천에서 제외했다.
- 공식 제작자의 원문·실제 helper·현행 제품 문서를 우선했다. 접근하지 못한 React Doctor 원격 playbook과 일부 감사 상세는 검증된 것으로 주장하지 않았다.

> 이번 조사는 원문·문서·공개 지표를 확인한 보고서다. Skill 설치, CLI 진단, 결제 API 요청, Terraform 검색·apply·state 이전, workbook 재계산이나 대화 실험은 수행하지 않았다. 실제 적용 시 코드 실행·계정 권한·데이터 전송·과금·라이선스와 변경 범위를 별도로 확인해야 한다.
