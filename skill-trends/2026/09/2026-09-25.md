### 내용

이 Skill은 중요한 기술 결정을 ADR(Architecture Decision Record)로 남길 때 맥락, 선택지, 근거, 결과까지 구조적으로 기록하게 한다. MADR, lightweight, Y-statement, deprecation, RFC-style의 여러 형식을 제공하고, `proposed → accepted → deprecated/superseded` 같은 생명주기와 인덱싱/자동화까지 다룬다. 즉 “문서 하나 써줘”가 아니라, 시간이 지나도 왜 그 결정을 했는지 Agent와 사람이 다시 추적할 수 있는 의사결정 시스템을 만든다는 점이 핵심이다.

### 설치 및 사용

```bash
npx skills add https://github.com/wshobson/agents --skill architecture-decision-records
```

별도 API Key나 MCP는 필요하지 않다. ADR 자동화에 `adr-tools`를 함께 쓰는 패턴은 Skill 내부에서 안내하지만 필수 전제는 아니다.

**Agent 활용 예시**

> 현재 Node.js 백엔드를 PostgreSQL 단일 DB에서 primary/standby 구조로 바꾸려 해. 후보 구조와 trade-off를 검토하고 MADR 형식의 ADR을 작성한 뒤, 나중에 supersede할 수 있도록 상태와 결정 근거까지 남겨줘.

**평가:** 설치 즉시 코드베이스의 “왜 이렇게 설계했는가”를 남기는 데 쓸 수 있고 특정 벤더에 묶이지 않아 실무 적용성이 높다. 다만 ADR을 너무 사소한 결정까지 남기면 문서 부채가 생기므로 “중대한 결정”의 기준을 팀에서 정하는 것이 좋다.

### 내용

이 Skill은 Markdown 지침만 만드는 것이 아니라 three.ws Agent가 실제로 실행할 수 있는 네 파일 구조—`manifest.json`, `SKILL.md`, `tools.json`, `handlers.js`—를 설계하게 한다. runtime은 Skill을 URL에서 가져와 지침을 system prompt에 주입하고 tool schema를 노출하며, handler는 기본적으로 Web Worker sandbox에서 실행된다. 외부 접근은 `ctx.fetch`, `ctx.memory`, `ctx.viewer`, `ctx.call` 같은 제한된 context API를 통하게 하며, author whitelist와 integrity hash 같은 trust 제약도 다룬다.

### 설치 및 사용

외부 coding Agent에 제작 지침 Skill을 설치:

```bash
npx skills add https://github.com/nirholas/three.ws --skill build-an-agent-skill
```

three.ws용 결과 bundle은 HTTPS/IPFS/Arweave 등에 호스팅한 뒤 agent manifest의 `skills`에 URI를 넣거나 `<agent-3d skills="...">`로 로드한다. 로컬 테스트는 정적 서버가 필요할 수 있다.

**Agent 활용 예시**

> three.ws 아바타가 “현재 서울 날씨를 읽고 날씨에 맞는 표정과 제스처를 하는” Skill을 만들어줘. manifest, tool schema, sandboxed handler, 실패 처리와 로컬 테스트 페이지까지 모두 작성해.

**평가:** Skill을 “프롬프트 파일”에서 “sandbox에서 실행되는 배포 가능한 기능 패키지”로 확장한 구조가 독창적이다. 반면 three.ws라는 특정 runtime에 종속되므로 일반 Codex 개발 workflow보다는 3D/아바타 Agent를 만들 때 가치가 크다.

### 내용

xint는 X/Twitter를 Agent가 조사 대상으로 사용할 수 있도록 검색, thread/profile/trend 조회, 실시간 watch/stream, follower diff, bookmark/like/follow 등의 OAuth 작업, Grok 기반 분석, JSON/JSONL/CSV/Markdown export를 한 CLI에 묶는다. scraping이 아니라 공식 X/xAI API를 사용하고, cache·snapshot·report는 기본적으로 로컬에 남긴다. `xint mcp`를 통해 같은 기능을 MCP tool로 노출할 수 있어 “웹 검색”과 별개로 X의 실시간 담론을 Agent 연구 workflow에 넣기 쉽다.

### 설치 및 사용

Skill 설치:

```bash
npx skills add https://github.com/0xNyk/xint --skill xint
```

실행 환경에는 **Bun 1.0+**과 최소 **`X_BEARER_TOKEN`**이 필요하다. Grok 분석은 `XAI_API_KEY`, 사용자 계정 작업은 `X_CLIENT_ID` OAuth가 추가로 필요하다.

```bash
export X_BEARER_TOKEN="..."
xint search "AI agents" --since 1d --sort likes --limit 20
xint mcp
```

**Agent 활용 예시**

> 최근 24시간 X에서 “Codex plugins”에 대한 개발자 반응을 검색해. 광고성/반복 글은 제외하고, 많이 언급되는 장점·문제·새 기능을 근거 tweet과 함께 요약해줘.

**평가:** 일반 웹 검색이 놓치기 쉬운 “지금 커뮤니티가 무엇을 말하는가”를 Agent에 공급하는 도구로 유용하다. 단, X API 접근 비용/정책과 credential 관리가 필요하고, OAuth 쓰기 권한은 read-only 조사보다 훨씬 조심해서 허용해야 한다.

### 내용

`track-findings`는 취약점을 “찾는” Skill이 아니라, 이미 sealed Codex Security scan에서 검증된 finding을 실제 업무 시스템에 안전하게 넘기는 마지막 단계다. Linear/Jira/GitHub issue 또는 GitHub draft security advisory를 대상으로 duplicate check → 정확한 payload preview → 사용자 승인 → write → readback 순서를 강제한다. 소스 finding은 `validate_tracking_source.py`로 검증하고 scan 문자열 자체를 명령으로 신뢰하지 않으며, 최대 25개 batch 제한과 provider별 visibility 검증 등 공격 표면을 줄이는 제약이 촘촘하다.

### 설치 및 사용

이 Skill은 standalone `npx skills add`보다 **Codex Security plugin의 bundled skill**로 사용하는 것이 공식 구조다. Codex/ChatGPT 데스크톱의 Plugins 화면에서 OpenAI가 제공하는 **Codex Security**를 설치해 사용하고, 자체 marketplace를 다룰 때는 공식 Codex plugin 명령인 다음 구조를 사용한다.

```bash
codex plugin marketplace list
# 사용자/조직 marketplace를 추가할 때:
codex plugin marketplace add owner/repo
```

`track-findings` 실행 전에는 Codex Security scan 결과가 필요하다. GitHub 경로에는 native GitHub app 또는 사용자가 명시적으로 선택한 authenticated `gh` identity가 필요하고, Linear/Jira는 해당 native app 연결과 쓰기 권한이 필요하다.

**Agent 활용 예시**

> 방금 완료한 Codex Security scan에서 finding SEC-014 하나만 GitHub issue로 추적해줘. 먼저 중복 issue를 찾고, 생성될 제목/본문/노출 범위를 정확히 preview한 뒤 내가 승인하기 전에는 쓰지 마.

**평가:** Agent가 보안 finding을 외부 시스템에 기록하는 순간 생기는 중복·오발행·민감정보 노출 위험을 workflow 자체로 통제한다는 점에서 오늘 후보 중 기술적 완성도가 가장 높다. 단점은 독립적인 범용 Skill이 아니라 Codex Security 및 연결된 이슈 트래커 생태계에 의존한다는 점이다.

### 🏆 오늘의 Top Pick

**track-findings**

Agent 생태계가 단순 “코드를 생성하는 지식 Skill”에서 실제 조직 시스템에 쓰기 작업을 수행하는 방향으로 이동할수록, 승인 경계와 출처 검증이 더 중요해진다. `track-findings`는 sealed scan 검증, duplicate discovery, 정확한 preview, 승인 후 mutation, readback을 하나의 상태 기계처럼 묶어 실제 Agent 운영에서 필요한 안전장치를 보여준다. OpenAI 공식 Codex plugin의 일부라는 점과, 바로 전날까지 `openai/plugins` 저장소가 활발히 갱신되고 있다는 점도 선정 이유다.

### 오늘 보이는 공통 흐름

오늘 후보들은 **Skill이 단순 프롬프트 묶음에서 “검증 가능한 실행 workflow”로 이동하는 흐름**을 공통으로 보여준다. Mastra는 설치된 버전의 문서를 직접 확인하고, three.ws는 sandbox와 trust policy를 가진 실행 bundle을 만들며, xint/WorkIQ는 API·MCP로 실시간 외부 context를 가져오고, track-findings는 외부 시스템 write에 승인·중복검사·readback을 붙인다. 앞으로 Agent Skill의 경쟁력은 지식량보다 **최신성 검증, 권한 경계, 재현 가능한 절차, 외부 도구 연결을 얼마나 안전하게 설계했는가**에서 더 크게 갈릴 가능성이 높다.
