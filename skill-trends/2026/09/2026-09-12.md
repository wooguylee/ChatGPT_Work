## 1. google-agents-cli-scaffold

- **출처:** skills.sh
- **GitHub:** https://github.com/google/agents-cli
- **제작자/조직:** Google
- **지원 Agent:** Codex, Claude Code, Antigravity 및 일반적인 coding agent. 저장소 README가 Codex/Claude Code를 명시하며 skills.sh도 Codex/Claude Code/Cursor 등 Agent Skills 호환 설치 흐름을 제공한다.
- **인기/트렌드 snapshot:** skills.sh Trending(24h) **#35**, 최근 24h 설치 **6.3K**, 누적 설치 **178.0K**. GitHub API 기준 **5,912 stars / 660 forks**. 저장소 마지막 push는 **2026-09-03**이며, 2026-09-12 조사 시점에도 repo metadata가 갱신되고 있다.
- **보안:** skills.sh에서 Gen Agent Trust Hub Pass, Socket Pass, Snyk Warn으로 표시. Snyk Warn의 구체 원인은 별도 audit 확인이 필요하다.

### 무엇을 해결하나
Google ADK 에이전트를 새로 만들거나 기존 프로젝트에 배포/CI/CD를 붙일 때, Agent가 직접 `agents-cli scaffold` 명령을 올바른 순서와 옵션으로 선택하도록 가이드한다. 핵심은 처음부터 인프라를 크게 만드는 대신 `--prototype`으로 빠르게 시작하고, 이후 `enhance`로 Cloud Run/GKE/Agent Runtime 및 CI/CD를 추가하는 단계적 흐름이다. 같은 저장소의 `google-agents-cli-workflow`, `adk-code`와 역할이 겹치지 않고 **프로젝트 뼈대/업그레이드/배포 준비**에 집중한다.

### 설치 및 사용
```bash
npx skills add https://github.com/google/agents-cli --skill google-agents-cli-scaffold
```

실제 CLI까지 사용하려면:
```bash
uv tool install google-agents-cli
# 또는 전체 setup
uvx google-agents-cli setup
```

요구사항: Python 3.11+, `uv`, Node.js. 로컬 개발은 AI Studio API key로도 가능하지만 Google Cloud 배포 기능은 Google Cloud 프로젝트/인증이 필요하다.

**예시 명령**
> `google-agents-cli-scaffold를 사용해서 고객 문의를 분류하는 ADK agent를 prototype 모드로 만들고, 동작 확인 후 Cloud Run 배포와 GitHub Actions CI/CD를 enhance로 추가해줘.`

**평가:** 오늘 24h 설치 증가가 강하고 실제 CLI와 Skill이 결합된 “Agent용 운영 도구”라는 점이 가치 있다. 다만 Google 생태계에 강하게 결합되며, Snyk audit가 Warn이므로 production 도입 전 audit 상세를 확인하는 편이 좋다.

**예시 명령**

- **플러그인 구조:** `skills/` + MCP servers(`.mcp.json`) + apps(`.app.json`)를 묶는 공식 plugin. `build-chatgpt-app`은 `openai-docs`를 먼저 사용하도록 강제하는 docs-first workflow다.

### 무엇을 해결하나
ChatGPT Apps SDK 앱은 MCP server, tool schema, widget resource, `structuredContent`, `_meta`, CSP, Apps bridge, ChatGPT 호환 API를 함께 맞춰야 해서 단순 코드 생성으로는 오래된 패턴이 섞이기 쉽다. 이 Skill은 먼저 현재 OpenAI 문서를 가져오고 앱 유형(`tool-only`, `vanilla-widget`, `react-widget`, `interactive-decoupled`, `submission-ready`)을 분류한 뒤 **공식 예제 → ext-apps 예제 → 최소 fallback scaffold** 순서로 출발점을 고른다. UI에는 MCP Apps bridge를 우선하고 `window.openai`는 필요한 ChatGPT 전용 확장에 한정하는 등, “지금의 공식 권장 구조”를 Agent가 지속적으로 따라가도록 만든다.

### 설치 및 사용
Codex에서:
```text
/plugins
```
을 열고 **OpenAI Developers** plugin을 설치한다. 공식 plugin manifest에 `build-chatgpt-app` Skill과 OpenAI developer docs/MCP 관련 구성이 포함돼 있다.

별도 파일 복사보다 공식 plugin 설치 방식을 우선하는 것이 현재 구조에 맞다.

**예시 명령**
> `build-chatgpt-app과 openai-docs를 사용해서 사내 재고를 검색하고 상세 정보를 widget으로 보여주는 ChatGPT App을 TypeScript MCP server + React widget 구조로 만들어줘. 먼저 tool schema와 CSP를 설계해줘.`

**평가:** **오늘의 Top Pick.** 공식 repo가 당일에도 업데이트되고 있고, Agent Skill이 단순 지침 파일을 넘어 **docs MCP + server + widget + plugin manifest**를 결합하는 방향을 보여준다. 단점은 OpenAI Apps SDK/ChatGPT App이라는 특정 플랫폼에 최적화되어 있다는 점이다.

**`build-chatgpt-app`** — 공식 문서를 매번 먼저 읽는 docs-first 구조, MCP Apps bridge 우선 설계, app archetype 분류, CSP/metadata/validation까지 하나의 반복 가능한 workflow로 묶었다. 단순 “코드 잘 써주는 Skill”보다 Agent가 빠르게 변하는 SDK 규약을 오래된 기억 대신 현재 문서에 고정시키는 구조가 기술적으로 더 중요하다.

### 오늘 보이는 공통 기술 흐름

오늘 후보들의 공통점은 Skill이 단순 prompt template에서 **실제 도구 실행과 검증 절차를 묶는 운영 계층**으로 이동하고 있다는 점이다. Google은 CLI/배포 lifecycle, OpenAI는 docs MCP + Apps bridge, Microsoft는 Playwright + debugger, 3ds Max는 MCP + 도메인 전문 지식, OpenClaw는 테스트/메모리 진단 절차를 결합한다. 즉 앞으로 Agent Skill의 경쟁력은 문장 자체보다 **특정 도구를 언제 어떤 순서로 실행하고, 어떤 증거로 완료를 판단하는지**를 얼마나 잘 패키징하느냐에 더 크게 좌우될 가능성이 높다.
