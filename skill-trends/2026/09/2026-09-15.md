### 내용 설명
`orca-cli`는 거대한 사용법을 `SKILL.md` 안에 복사해 두는 대신, **현재 실행 중인 Orca binary가 자기 버전에 맞는 reference를 제공하도록 하는 discovery stub**에 가깝다. Agent는 Orca가 관리하는 worktree, terminal, repository context, automation, worktree comment, 내장 browser 같은 실제 runtime 상태를 CLI로 읽고 조작하며, 여러 coding agent를 다른 worktree에 넘기는 handoff에도 같은 인터페이스를 사용한다.

이 구조의 중요한 점은 Skill 문서와 실행 binary의 버전이 따로 놀지 않게 한다는 것이다. 즉 정적인 prompt 지식보다 **실행 도구가 현재 계약의 source of truth**가 되고 Skill은 어떤 상황에서 그 도구를 써야 하는지와 안전한 진입점을 정의한다.

### 설치 및 사용
```bash
npx skills add https://github.com/stablyai/orca --skill orca-cli
```

추가 요구사항:
- 실제 제어 대상인 **Orca desktop/runtime와 Orca CLI**가 필요하다.
- `ORCA_CLI_COMMAND`가 있으면 그 값을 우선 사용하고, 개발 checkout에서는 `orca-dev`를 쓸 수 있다.
- **Linux에서 Orca-managed terminal 밖에서 bare `orca`를 실행하지 말 것.** `/usr/bin/orca`가 GNOME Orca screen reader로 해석될 수 있어 Skill은 이 경우 `orca-ide` 사용을 지시한다.
- Windows/PowerShell과 POSIX shell 모두를 고려해 실행 명령을 한 번 resolve한 뒤 같은 executable을 재사용하는 방식이다.

### 활용 예시
> 현재 Orca에서 열려 있는 worktree와 terminal 상태를 확인하고, 이 기능 작업을 별도 child worktree의 Codex에게 넘겨줘. 완료될 때까지 상태를 추적하되 기존 main worktree 파일은 직접 수정하지 마.

### 평가
**오늘 볼 가치:** 20만 회가 넘는 registry 설치 snapshot과 조사 당일에도 이어지는 저장소 활동이 함께 보이며, Agent Skill이 단순 지침 파일이 아니라 **실제 multi-agent 개발 runtime의 얇은 제어 계층**으로 바뀌는 흐름을 잘 보여준다.  
**주의:** 특정 Orca 환경에 강하게 결합되고, skills.sh의 **Snyk 감사가 Fail**이므로 감사 상세와 실행되는 CLI/권한 범위를 확인한 뒤 사용하는 편이 안전하다.

### 내용 설명
이 Skill은 TypeScript 기반 MCP 서버를 단순히 `tool()` 몇 개 만드는 수준에서 끝내지 않고 **MCP Apps까지 포함한 production lifecycle**로 다룬다. 먼저 프로젝트의 `mcp-use` 실제 설치 버전과 generated type을 source of truth로 확인하고, tools/resources/prompts/middleware, React View, OAuth를 필요한 reference만 열어 구현한 뒤 build/typecheck → server 실행 → client 연결 → tool 호출 → View render까지 실제 lifecycle을 검증한다.

특히 v1 지식을 무심코 재사용하지 못하게 하고, View-bound tool에는 `outputSchema`와 `structuredContent`를 맞추며, 요청별 identity/state를 module global에 두지 않는 등의 규칙이 들어 있다. Agent가 README 예제를 복사하는 대신 **현재 설치된 package contract를 읽고 구현하도록 강제**한다는 점이 핵심이다.

### 설치 및 사용
```bash
npx skills add https://github.com/mcp-use/mcp-use --skill mcp-apps-builder
```

새 프로젝트 scaffold 예:
```bash
npx create-mcp-use-app@latest
```

추가 요구사항:
- Node.js/npm 환경
- TypeScript 기반 `mcp-use` 프로젝트
- OAuth 기능을 쓸 경우 선택한 provider의 설정/credential
- interactive View를 만들면 React client lifecycle까지 실제로 검증해야 한다.

### 활용 예시
> `mcp-apps-builder` 기준으로 이 MCP 서버에 검색 tool과 결과를 렌더링하는 React View를 추가해줘. 먼저 설치된 mcp-use 버전과 타입을 확인하고, build만 통과했다고 끝내지 말고 실제 client 연결 → tool call → View render까지 검증해.

### 평가
**오늘 볼 가치:** MCP가 단순 tool 호출 규격을 넘어 **interactive App, 인증, 상태, 배포 전 검증**까지 넓어지는 흐름을 실무 수준으로 정리한다. ChatGPT/Claude용 MCP App을 만드는 개발자에게 특히 직접적이다.  
**주의:** API 변화가 빠른 영역이라 Skill 자체도 “설치된 package가 source of truth”라는 전제를 둔다. 또한 skills.sh Snyk 결과가 Warn이므로 dependency/실행 script를 검토해야 한다.

- **제작자:** axot
- **지원 Agent:** **Codex, Claude Code, OpenCode 및 cross-client Agent Skill**을 명시적으로 대상으로 한다.

### 인기 및 트렌드 지표
- SkillsMP source activity snapshot: **2026-08-28**.
- 최신 GitHub API: **0 Stars / 0 Forks**.
- GitHub 최근 push: **2026-09-02**.
- 누적 설치 수, 24시간 증가, 좋아요, 품질/보안 점수는 SkillsMP 페이지에서 확인되지 않아 미기재.

### 내용 설명
일반적인 MCP 연결은 client에 server를 등록하면서 많은 tool schema를 항상 context에 노출할 수 있다. `mcp-skill-authoring`은 반대로 **Skill이 선택된 뒤에만 공식 `@modelcontextprotocol/inspector` CLI로 MCP server를 시작/연결하고, 필요한 tool 하나의 live schema만 찾아 호출**하도록 Skill을 설계한다.

핵심은 “MCP를 없애는 것”이 아니라 **MCP의 실행 시점과 context 비용을 Skill 쪽에서 제어**하는 것이다. `tools/list` 전체를 모델에 던지지 않고 정확히 필요한 tool만 filter하고, `--tool-args-json`과 `--format json`으로 타입을 보존하며, write/delete/publish 같은 consequential call 직전에는 명시적 사용자 승인을 요구한다. raw JSON-RPC, `eval`, grep 기반 protocol parsing 같은 취약한 우회도 금지한다.

### 설치 및 사용
```bash
npx skills add https://github.com/axot/agent-skills --skill mcp-skill-authoring
```

생성되는 MCP-backed Skill의 핵심 도구:
```bash
npx @modelcontextprotocol/inspector@latest
```

추가 요구사항:
- Node.js/npm
- 연결하려는 MCP server의 stdio command 또는 remote HTTP URL
- 필요한 인증 정보는 environment variable이나 server의 auth store에 보관
- Inspector 최신 버전의 Node engine 요구사항과 CLI contract는 **작성 시점에 다시 확인**하도록 Skill이 명시한다.

### 활용 예시
> 이 사내 MCP 서버의 `search_documents` tool만 필요할 때 호출하는 Codex Skill을 만들어줘. MCP를 상시 등록해서 전체 schema를 context에 넣지 말고, Inspector로 필요할 때만 tool schema를 확인한 뒤 JSON 인자로 호출하도록 구성해.

### 평가
**오늘 볼 가치:** GitHub 인기 수치는 아직 거의 없지만, **Agent Skill과 MCP를 경쟁 관계가 아니라 lazy execution layer로 결합해 token 비용을 줄이는 구조**가 매우 독창적이다. MCP tool catalog가 커질수록 이 방식의 가치가 커질 수 있다.  
**주의:** adoption 신호가 매우 약하고 Inspector의 최신 CLI 동작에 의존하므로, 실제 server에 대해 `initialize`/`tools/list`/read-only call을 검증한 후 쓰는 것이 필수다.

- 최신 GitHub API: **1,128 Stars / 139 Forks**.

### 내용 설명
Coding Agent를 여러 개 쓰면 작업 기억이 `~/.codex/sessions`, `~/.claude/projects`, Cursor SQLite, OpenCode DB, Aider history 등 서로 다른 형식으로 흩어진다. CASS는 이를 하나의 로컬 index로 만들고 `cass search`, `view`, `expand`, `timeline`, `context` 같은 명령으로 과거 해결책과 작업 맥락을 다시 찾게 한다.

Agent용으로 특히 중요한 부분은 **robot mode**다. JSON/JSONL 출력, capability discovery, API schema introspection, structured error, field selection, `--max-tokens` 같은 token budget 옵션을 제공해 LLM이 TUI 화면을 억지로 파싱하지 않고 안정적인 machine interface로 검색한다. 즉 “메모리”를 모델 내부에 넣기보다 **과거 Agent 세션을 검색 가능한 외부 episodic store**로 취급한다.

### 설치 및 사용
Skill 설치:
```bash
npx skills add https://github.com/Dicklesworthstone/coding_agent_session_search --skill cass
```

CASS CLI도 별도로 필요하다. 프로젝트가 안내하는 예:
```bash
# Linux/macOS
curl -fsSL https://raw.githubusercontent.com/Dicklesworthstone/coding_agent_session_search/main/install.sh | bash -s -- --easy-mode --verify
```

PowerShell 예:
```powershell
irm https://raw.githubusercontent.com/Dicklesworthstone/coding_agent_session_search/main/install.ps1 | iex
```

설치 후 예:
```bash
cass index --full
cass search "authentication timeout" --robot --limit 10
cass context src/auth.ts --json
cass health --json
```

추가 요구사항/주의:
- 로컬 Agent history에 접근할 파일 권한이 필요하다.
- optional semantic search용 MiniLM model은 자동 다운로드되지 않는다.
- 원격 machine search를 쓰면 SSH/rsync 설정이 추가로 필요하다.
- 설치 script를 pipe로 실행하기 전에는 내용을 검토하는 편이 안전하다.

### 활용 예시
> CASS로 Codex와 Claude Code 과거 세션에서 `CloudFront VPC origin` 관련 해결 기록을 찾아줘. 결과는 `--robot`으로 받고 가장 관련도 높은 5개 세션의 원문 근거만 요약해. 과거 세션 파일은 수정하지 마.

### 평가
**오늘 볼 가치:** 저장소가 조사 당일에도 업데이트되고 있고, 여러 Agent를 병행할수록 커지는 “대화와 해결책이 도구별로 분산되는 문제”를 실제 검색 엔진으로 해결한다. 특히 machine-readable contract와 token budget 설계가 Agent 친화적이다.  
**주의:** 세션 기록에는 source code, prompt, 경로, credential 흔적 등 민감 정보가 섞일 수 있으므로 index 디렉터리와 remote sync 권한을 엄격히 관리해야 한다.

### 내용 설명
여러 Agent를 단순 fan-out하면 “누가 무엇을 수정했는지”, “어떤 branch가 merge 가능한지”, “어디서 막혔는지”가 금방 흐려진다. 이 Skill은 Agent를 팀원처럼 취급해 각 작업을 **owner, file scope, state, evidence, merge gate**가 있는 카드로 만들고 Backlog → Ready → Running → Review → Blocked/Merged 상태를 운영하게 한다.

핵심은 agent 수를 늘리는 것이 아니라 **parallel work를 merge 가능한 제품 상태로 수렴시키는 통제면(control pane)**을 만드는 것이다. branch/worktree 분리, handoff artifact, test/screenshot/log evidence, integrator 역할을 명시하며 “Agent soup”, 겹치는 write, board theater 같은 실패 패턴도 직접 금지한다.

### 설치 및 사용
AgentSkill.sh를 통한 설치:
```bash
npx @agentskill.sh/cli@latest setup
```
Agent 안에서:
```text
/learn @affaan-m/team-agent-orchestration
```

원 저장소에서 직접 설치하는 방식도 확인된다:
```bash
npx skills add https://github.com/affaan-m/ecc --skill team-agent-orchestration
```

추가 요구사항:
- Skill 자체는 특정 orchestrator를 강제하지 않는다.
- 실제 parallel execution을 하려면 사용하는 환경에 따라 worktree, tmux/Zellij, dmux, Hermes, Codex/Claude session 등의 실행 substrate가 필요할 수 있다.

### 활용 예시
> 이 기능을 API, 프런트엔드, 테스트 세 작업 카드로 나누고 각각 owner와 write scope를 정해줘. Agent들이 같은 파일을 동시에 수정하지 않게 worktree를 분리하고, 테스트와 diff review를 통과한 카드만 merge-ready로 표시해.

### 평가
**오늘 볼 가치:** multi-agent의 병목이 “Agent를 더 띄우는 것”에서 “충돌 없이 통합하는 운영 규칙”으로 이동하고 있음을 잘 보여준다. 매우 큰 원 저장소 adoption과 100/100 보안 감사도 신뢰 신호다.  
**주의:** 작은 작업에까지 Kanban/branch/gate를 강제하면 orchestration overhead가 실제 구현 비용보다 커질 수 있다. 작업 규모가 작으면 단일 Agent가 더 효율적이다.

## 6. `task-observer`

### 기본 정보
- **출처:** [ClaudeSkills.info](https://claudeskills.info/skills/rebelytics/one-skill-to-rule-them-all/)
- **GitHub:** [rebelytics/one-skill-to-rule-them-all](https://github.com/rebelytics/one-skill-to-rule-them-all)
- **제작자:** Eoghan Henn / rebelytics
- **지원 Agent:** 현재 canonical Skill은 Claude Cowork/Claude Code 중심으로 설계됐다. upstream은 OpenClaw/Hermes 사용 사례와 다른 Agent 호환 가능성을 언급하지만, **Codex 등에서는 Claude-centric activation 구조를 그대로 쓸 수 있다고 가정하면 안 된다**.

### 인기 및 트렌드 지표
- ClaudeSkills.info collection snapshot: **1 Skill / 6.5K total installs**.
- ClaudeSkills.info의 저장소 통계 cache는 최신 GitHub보다 뒤처져 있어, 현재 GitHub API를 별도로 확인했다.
- 최신 GitHub API: **2,670 Stars / 258 Forks**.
- GitHub 최근 push: **2026-09-11 (KST)**.
- License: **CC BY 4.0**.
- 좋아요/즐겨찾기 버튼은 있으나 정량 수치는 확인되지 않았고, 별도 품질/보안 점수도 확인되지 않아 미기재.

### 내용 설명
대부분의 Skill은 설치한 순간부터 정적인 문서가 된다. `task-observer`는 실제 multi-step 작업 중 사용자가 Agent를 교정한 지점, 반복되는 workflow, 누락된 규칙, 잘 작동한 방법을 **observation log**로 남기고, 이후 review에서 기존 Skill의 구체적 개선안 또는 새 Skill 후보로 승격한다.

중요한 점은 Agent가 마음대로 Skill을 자동 수정하지 않는다는 것이다. 관찰 → 구조화된 제안 → review/approval 순서를 두고, cross-cutting principle도 별도 축적한다. 자신의 activation/관찰 방식에서 발견된 문제까지 다시 기록하므로 **Skill library 자체를 피드백 루프로 관리하는 meta-skill**이라는 성격이 강하다.

### 설치 및 사용
Claude Code 기준 ClaudeSkills.info가 제공하는 명령:
```bash
npx skills add rebelytics/one-skill-to-rule-them-all --skill task-observer --agent claude-code
```

또는 collection 전체:
```bash
npx -y skills add rebelytics/one-skill-to-rule-them-all --agent claude-code
```

추가 요구사항:
- `SKILL.md`뿐 아니라 `references/`와 `scripts/`를 포함한 bundle을 유지해야 한다.
- observation log가 세션을 넘어 남을 **안정적인 persistent workspace**가 필요하다.
- description matching만으로는 항상 session start에 실행된다고 보장할 수 없어, Claude 환경에서는 `CLAUDE.md` instruction 또는 session-start hook을 함께 두도록 권장한다.
- Codex에 가져갈 경우 canonical 내용의 Claude-specific 개념과 activation rule을 검토해 맞게 변환해야 한다.

### 활용 예시
> 오늘 이 저장소 작업을 하면서 내가 반복해서 수정해 준 방식, 기존 Skill이 놓친 규칙, 새 Skill로 만들 만한 반복 workflow를 observation으로 기록해. 작업을 방해하지 말고 끝난 뒤 실제로 재사용 가치가 있는 항목만 개선 후보로 정리해줘.

### 평가
**오늘 볼 가치:** Agent Skill 생태계가 “Skill을 많이 설치하는 단계”에서 **실제 사용 경험을 기반으로 Skill을 지속 개선하는 운영 단계**로 넘어가고 있다는 신호다. 설치 규모와 GitHub 관심도도 단순 실험 수준을 넘어섰다.  
**주의:** 항상 켜 두면 observation log가 커지고 업무 맥락이 기록되므로 기밀 정보 정책이 필요하다. 작은 Skill 몇 개만 쓰는 환경에서는 내장 memory나 수동 수정이 더 단순할 수 있다.

### 🏆 오늘의 Top Pick

**`task-observer`**

개별 기능 하나를 더 추가하는 Skill이 아니라 **Skill 생태계 자체를 학습 가능한 시스템으로 바꾸는 feedback loop**를 제공한다는 점에서 독창성이 높다. 작업 중 생긴 correction과 workflow friction을 버리지 않고 관찰 → review → 개선으로 연결하며, 실제 사용자가 늘수록 Skill library의 품질이 누적될 수 있다는 점이 장기적으로 크다. 다만 Codex에서는 upstream의 Claude-centric activation을 그대로 복사하기보다 구조를 맞게 이식해야 한다.

### ⚡ Codex에서 바로 써볼 만한 것

**`cass`**

Skill 설치와 CASS CLI 설치 후 `cass index --full`만 해두면 Codex가 과거 Codex/Claude/OpenCode 등 여러 Agent 세션을 JSON 기반 robot mode로 바로 검색할 수 있다. 복잡한 MCP server나 API key 없이 로컬 기록을 재활용할 수 있고, `--max-tokens`, `--fields`, structured error가 있어 Codex가 다루기 좋은 형태다. 다만 session history의 민감 정보 취급 정책은 먼저 정해 두는 편이 좋다.

### 오늘 보이는 공통 기술 흐름

오늘은 **Skill이 정적인 지식 파일에서 runtime·memory·governance 계층으로 이동하는 흐름**이 뚜렷하다. `orca-cli`는 실제 agent runtime을 version-matched CLI로 제어하고, `mcp-skill-authoring`은 MCP를 필요할 때만 lazy-load해 context 비용을 줄이며, `cass`는 여러 Agent의 과거 실행을 외부 episodic memory로 검색한다. `team-agent-orchestration`은 parallel agent를 merge 가능한 팀 작업으로 수렴시키고, `task-observer`는 그 과정의 correction 자체를 다음 Skill 개선 데이터로 만든다. 좋은 Skill의 경쟁력이 단순 prompt 문구보다 **실행 가능한 도구 계약, context 효율, 관측 가능성, 승인 경계, 지속 학습 구조**에 더 가까워지고 있다.
