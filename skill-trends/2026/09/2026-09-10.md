### 활용 예시


### 무엇을 해결하나

긴 Agent 작업은 대화 컨텍스트가 압축되거나 세션이 끊기면 “왜 이 일을 하고 있었는지”가 흐려진다. 이 Skill은 컨텍스트 창을 RAM, 파일시스템을 디스크처럼 취급해 `task_plan.md`, `findings.md`, `progress.md`를 지속적인 작업 기억으로 사용한다.

핵심은 단순 TODO 파일이 아니라 lifecycle hook으로 계획을 다시 주입하고, 병렬 작업에서는 `PLAN_ID`와 `PWF_PLAN_ROOT`로 각 작업의 계획을 격리하는 점이다. 최근 v3 계열은 autonomous/gated 모드에서 매 tool-call 재주입을 줄이고, SHA-256 attestation 및 completion gate로 장시간 Agent 작업의 drift와 잘못된 종료를 줄이려 한다.

### 설치 및 사용

일반 Agent Skills 설치:

```bash
npx skills add https://github.com/OthmanAdi/planning-with-files --skill planning-with-files
```

Claude Code에서 `/plan-goal`, `/plan-loop`까지 사용하려면 plugin 설치 경로가 더 완전하다.

```text
/plugin marketplace add OthmanAdi/planning-with-files
/plugin install
```

주의: `npx skills add` 방식은 `SKILL.md`, scripts, templates는 설치하지만 plugin 전용 `commands/`의 `/plan-goal`, `/plan-loop`는 제공하지 않는다. Git/Bash 또는 PowerShell 스크립트 실행이 필요하며, plan attestation은 keyed signature가 아니라 SHA-256 무결성 체크이므로 공격자가 계획 파일과 attestation 모두를 쓸 수 있는 환경까지 방어하는 것은 아니다.

### 활용 예시

```text
이 리팩터링은 파일과 도구 호출이 많으니 planning-with-files를 사용해 계획을 디스크에 유지해줘. task_plan/findings/progress를 만들고, 각 단계가 끝날 때마다 기록한 뒤 컨텍스트 압축 후에도 같은 계획을 복구해 계속 진행해줘.
```

### 평가

**오늘 볼 가치:** 장시간 Agent의 핵심 문제인 context rot를 “더 큰 컨텍스트”가 아니라 **외부화된 상태 + 복구 규칙 + 완료 게이트**로 해결하려는 점이 기술적으로 가장 의미 있다. 설정이 단순 SKILL.md보다 복잡하고, hook/plan 파일을 프로젝트 운영 규칙으로 받아들여야 한다는 비용은 있다.

### 무엇을 해결하나

`impeccable`은 단순 “예쁜 UI 프롬프트”가 아니라 Agent에게 typography, hierarchy, spacing, motion, accessibility 등을 말할 수 있는 **공통 디자인 어휘**를 제공하고, `npx impeccable detect`라는 결정론적 detector로 코드/렌더링 결과를 검사한다. Agent의 주관적 미감만 믿지 않고 규칙 기반 검사와 실제 페이지 검증을 결합한다는 점이 특징이다.

또한 무한 self-review가 토큰과 시간을 낭비하는 문제를 막기 위해 **한 번에 desktop/mobile을 검사 → 한 번에 수정 → 최대 한 번 확인** 같은 bounded verification을 권장한다. 즉 “더 오래 고민하는 Agent”보다 “명확한 검사·종료 조건이 있는 Agent”를 지향한다.

### 설치 및 사용

공식 권장 자동 감지 설치:

```bash
npx impeccable install
```

범용 Agent Skills 설치도 가능하다.

```bash
npx skills add https://github.com/pbakaus/impeccable --skill impeccable
```

Codex에서는 일반 `/` 목록이 아니라 `/skills` 또는 `$`로 Skill을 확인하며, 프로젝트 설치 위치는 `.agents/skills/`이다. detector는 별도로 다음처럼 CI에서도 사용할 수 있다.

```bash
npx impeccable detect src/
```

### 활용 예시

```text
$impeccable audit 이 React 관리자 화면을 검토해줘. desktop/mobile을 한 번에 확인하고 접근성·타이포·간격·AI 특유의 반복 패턴을 고친 뒤, 한 번만 재검증하고 종료해줘.
```

### 평가

**오늘 볼 가치:** Agent 지침과 결정론적 정적/렌더링 검사를 묶어 **생성 → 검사 → 제한된 수정** 루프를 만든 점이 실무적이다. 이미 `frontend-design`류 Skill을 쓰는 팀이라면 역할이 겹칠 수 있으므로 전체를 중복 설치하기보다 detector/command 체계가 필요한지 판단하는 것이 좋다.

### 무엇을 해결하나

AI Agent는 오래된 프로젝트에 들어가면 학습 데이터에서 익힌 “요즘식” 구조를 덮어써 기존 팀의 암묵적 관례를 깨뜨리기 쉽다. `inherit-legacy-style`은 프로젝트 규모를 먼저 측정한 뒤 File Anatomy, State & Control Flow, Infrastructure, Error Handling 네 차원을 샘플링/전체 스캔하고, 강한 충돌만 사용자에게 하나씩 물어본다.

결과는 `.ai-style-rules.md`의 Golden Files, Naming/State 규칙, DONTs로 굳히며 이후에는 Git diff 기반 incremental sniff로 진화 로그를 추가한다. 즉 스타일을 단순 lint 규칙이 아니라 **실제 코드베이스에서 역추출한 Agent 행동 제약**으로 만드는 방식이다.

### 설치 및 사용

```bash
npx skills add https://github.com/affaan-m/ecc --skill inherit-legacy-style
```

필수 조건은 프로젝트 파일 Read/Write 권한이며 Git 사용이 권장된다. 실행 후 `.ai-style-rules.md`를 만들고, 사용자가 원하면 `CLAUDE.md` soft hook 또는 write/edit 전 hard hook을 구성할 수 있다.

### 활용 예시

```text
이 오래된 C# 프로젝트에 새 기능을 추가하기 전에 inherit-legacy-style을 실행해줘. 기존 코드의 파일 구조·상태 처리·공통 유틸 위치·예외 처리 관례를 추출하고, 충돌하는 관례만 하나씩 물어본 뒤 .ai-style-rules.md로 남겨줘.
```

### 평가

**오늘 볼 가치:** “AI가 기존 프로젝트를 자기 취향으로 현대화해 버리는 문제”를 구체적인 증거와 규칙 파일로 제어한다는 점이 독창적이다. 단, 잘못된 레거시 관례까지 그대로 보존할 위험이 있으므로 구조를 계승하되 버그/보안 결함은 별도 리뷰에서 분리해야 한다.

## 6. `deep-security-scan`

- **출처:** OpenAI 공식 Skill / Codex Security
- **원본 저장소:** https://github.com/openai/plugins
- **Skill 원본:** https://github.com/openai/plugins/blob/main/plugins/codex-security/skills/deep-security-scan/SKILL.md
- **제작자/조직:** OpenAI
- **지원 Agent:** **Codex / Codex Security 중심**. 일반 SKILL.md 소비 Agent가 문서를 읽을 수는 있지만 Codex Security 전용 capability가 없으면 전체 workflow를 그대로 실행할 수 없음

### 인기 및 트렌드 지표

- GitHub API 최신 snapshot: **6,184★ / 825 forks**
- 저장소 최근 push: **2026-09-09 02:57 KST**
- SkillsMP 과거 cache snapshot: **5,105★ / 698 forks**
- 공식 저장소 자체에는 이 Skill의 별도 Quality/Security 점수가 없음
- 제3자 Tessl snapshot은 Quality **61 / 72%**, Security에 **High 1건**을 표시했으나 이는 OpenAI 공식 보안 판정이 아닌 외부 정적 평가이므로 참고값으로만 취급

> 수치는 조사 당시 snapshot이다. 제3자 점수는 공식 평가와 구분해 기록했다.

### 무엇을 해결하나

일반 보안 스캔은 한 번의 discovery 결과가 모델의 우연성에 크게 좌우될 수 있다. `deep-security-scan`은 같은 범위를 여러 독립 worker가 각자 threat model을 만든 상태로 반복 탐색하게 하고, 후보를 의미적으로 병합한 뒤 하나의 canonical validation threat model로 **validation → attack-path analysis → canonical JSON → report**를 한 번 수행한다.

즉 “Agent를 여러 번 돌려 결과를 합친다”에서 끝나지 않고, 발견 단계만 variance-reduction을 위해 반복하고 최종 판단은 중앙화한다. PR/commit/diff 스캔용이 아니라 repository-wide 또는 scoped-path의 깊은 점검용이라는 경계도 명확하다.

### 설치 및 사용

Agent Skills 형식으로 가져올 수 있다.

```bash
npx skills add https://github.com/openai/plugins --skill deep-security-scan
```

다만 실제 실행은 Codex Security capability 및 해당 환경의 preflight가 준비되어 있어야 한다. 저장소 전체를 반복 discovery하므로 일반 보안 리뷰보다 모델/시간 사용량이 크다. 2026-08에는 한 사용자가 discovery artifact 누락으로 scan이 실패하면서 상당한 사용량이 소모됐다고 보고한 공개 이슈도 있어, 작은 변경에는 ordinary diff/security scan을 우선하는 편이 합리적이다.

### 활용 예시

```text
$deep-security-scan 이 저장소의 auth와 file-upload 경로만 scoped-path 대상으로 깊게 스캔해줘. 독립 discovery를 반복하고 후보를 병합한 뒤 validation과 attack-path 분석까지 완료해서 실제 악용 가능성이 있는 finding만 남겨줘.
```

### 평가

**오늘 볼 가치:** Agent 보안 스캔에서 가장 어려운 문제인 **발견 편차와 false-positive를 workflow 구조로 줄이는 공식 사례**다. 반면 계산량과 사용량이 큰 고비용 작업이며, 외부 scanner의 credential-handling 경고도 있으므로 실행 전 source/preflight를 확인하는 것이 좋다.
