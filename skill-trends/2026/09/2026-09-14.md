## 1. `google-agents-cli-deploy`

### 기본 정보
- 출처: [skills.sh](https://www.skills.sh/google/agents-cli/google-agents-cli-deploy)
- GitHub: [google/agents-cli](https://github.com/google/agents-cli)

- 지원 Agent: skills.sh 기준 Claude Code, Cursor, **Codex**, GitHub Copilot, Windsurf, Gemini, Cline, AMP, Antigravity, OpenClaw 등

### 인기 및 트렌드 지표
- skills.sh **Trending (24h) #1**
- Trending leaderboard 표시값: **17.8K**
- 누적 설치: **210.3K**
- GitHub: ★ **5,922**, Fork **660**
- GitHub 최근 push: **2026-09-03**
- 보안 감사: Gen Agent Trust Hub **Pass**, Socket **Pass**, Snyk **Warn**
- 좋아요/품질 점수: 해당 페이지에서 별도 수치 확인 불가

### 내용 설명
이 Skill은 Agent 코드를 작성하는 단계보다 한 단계 뒤인 **실제 배포와 운영**을 표준화한다. Agent Runtime, Cloud Run, GKE 중 어떤 대상을 선택할지 언어 지원·확장 방식·네트워크·비용 기준으로 나누고, `agents-cli deploy`를 통해 비밀값, 서비스 계정, VPC/PSC, DNS peering 같은 운영 설정까지 연결한다.

특히 단순 배포 명령 모음이 아니라 Terraform 기반 IaC, Workload Identity Federation, staging→production 승격, 로그/IAM 기반 장애 진단까지 하나의 절차로 묶는다. Agent 개발이 PoC를 넘어 운영 환경으로 이동하면서 가치가 커지는 유형이다.

### 설치 및 사용
```bash
npx skills add https://github.com/google/agents-cli --skill google-agents-cli-deploy
```

추가 요구사항:
```bash
uv tool install google-agents-cli
```

- `uv` 필요
- 실제 배포에는 Google Cloud 권한/프로젝트 설정 필요
- Cloud Run/GKE/Agent Runtime에 따라 Docker, Terraform, IAM 및 네트워크 설정이 추가될 수 있음

### 활용 예시
> 현재 Python ADK Agent를 분석해서 Agent Runtime과 Cloud Run 중 더 적합한 배포 대상을 선택하고, Terraform과 GitHub Actions WIF 기반 CI/CD까지 구성해줘.

### 평가
**오늘의 가장 강한 신호 중 하나.** 24시간 Trending #1이고, Agent 개발의 다음 병목인 배포·IaC·CI/CD를 직접 다룬다. 다만 Snyk 결과가 `Warn`이므로 설치 전 Skill과 의존 CLI의 실행 범위를 검토하는 것이 좋다.

### 내용 설명
`browser-use`는 단순 웹 검색 Skill이 아니라 **Chrome DevTools Protocol(CDP)을 통해 실제 브라우저를 조작**한다. 페이지의 accessibility tree와 DOM을 읽고 클릭·입력·탭 전환·스크롤·스크린샷·다운로드 같은 작업을 실행하며, 로컬 Chrome이나 Browser Use Cloud에 연결할 수 있다.

특히 "HTTP로 읽을 수 있으면 fetch를 쓰고, 상호작용이 필요할 때만 브라우저를 쓴다"는 구분이 Skill 안에 명확히 들어 있어 무조건 GUI 자동화로 가는 낭비를 줄인다. 브라우저 조작을 Agent의 일반 도구처럼 쓸 수 있게 만드는 점이 핵심이다.

### 설치 및 사용
```bash
npx skills add https://github.com/browser-use/browser-use --skill browser-use
```

진단:
```bash
browser-use --doctor
```

추가 요구사항/주의:
- 로컬 Chrome 사용 시 remote debugging/CDP 연결 필요
- Cloud browser 사용 시 Browser Use 인증/API Key가 필요할 수 있음
- 로그인, MFA, 동의 화면 등은 사람 확인이 필요한 구간이 존재

### 활용 예시
> 로컬 Chrome에 연결해서 내 테스트 사이트에 로그인된 현재 세션을 유지한 채 주문 생성 → 결제 직전까지의 UI 흐름을 클릭하면서 검증하고, 실패한 단계의 DOM 정보와 스크린샷을 남겨줘.

### 평가
**Codex에 실제 웹 조작 능력을 붙이려는 경우 즉시 체감 가치가 크다.** 단순 Playwright 스크립트 생성보다 Agent가 상태를 보면서 반복 작업한다는 점이 장점이며, 브라우저 권한과 로그인 세션을 다루므로 실행 범위 통제가 중요하다.

### 내용 설명

이 방식은 텍스트 상자와 도형을 개별 배치하는 전통적인 PowerPoint 자동화보다 시각 품질을 빠르게 높일 수 있지만, 결과 슬라이드가 이미지 중심이라 세밀한 요소 편집성은 떨어질 수 있다.

### 설치 및 사용
```bash
npx skills add https://github.com/bytedance/deer-flow --skill ppt-generation
```

주요 추가 요구사항:
- `image-generation` Skill
- Python 실행 환경
- 슬라이드별 이미지 생성 → `scripts/generate.py`를 이용한 PPTX 합성
- 이전 슬라이드를 reference image로 사용하므로 슬라이드 생성은 순차 실행 권장

### 활용 예시
> AI Agent 보안 아키텍처를 설명하는 8장짜리 16:9 발표자료를 dark-premium 스타일로 만들고, 모든 슬라이드가 같은 시각 언어를 유지하도록 직전 슬라이드를 reference로 사용해줘.

### 평가
**문서 생성 Skill이 '내용 작성'에서 '멀티모달 제작 파이프라인'으로 확장되는 사례다.** 시각 결과는 강하지만 슬라이드 내부 요소를 PowerPoint에서 세밀하게 재편집해야 하는 업무에는 적합성이 낮을 수 있다.

### 내용 설명
GitHub Security Advisory(GHSA)를 사람이 실수하기 쉬운 순서로 직접 처리하는 대신, **조회 → private fork PR 확인 → 안전한 JSON/Markdown payload 생성 → PATCH → 공개 → 재조회 검증** 순서를 Skill에 고정한다. `gh api`, `jq`, `npm`을 사용하고, 공개 전에 private fork의 열린 PR이 없는지 확인하며, `severity`와 `cvss_vector_string`을 같은 PATCH에 넣지 않는 등 실제 API의 함정을 명시한다.

특히 "publish action 전에 권한을 다시 확인"하고, 공개 설명에 내부 commit/PR 정보가 새지 않도록 제한하는 운영 guardrail이 들어 있다. 보안 업무 Skill이 단순 명령어 모음이 아니라 **절차적 안전장치**로 진화하는 사례다.

### 설치 및 사용

```bash
npx @agentskill.sh/cli@latest setup
```

AgentSkill.sh 내부 설치:
```text

```

Codex 수동 설치 경로:
```text

```

추가 요구사항:
- GitHub CLI `gh`
- `jq`
- `npm`
- GitHub Security Advisory를 읽거나 변경할 수 있는 저장소 권한

### 활용 예시
> GHSA-xxxx-xxxx-xxxx 상태를 먼저 읽고 private fork에 열린 PR이 없는지 검증한 뒤, 공개 전까지 필요한 필드만 안전하게 PATCH할 계획을 만들어줘. 실제 publish는 내가 승인한 뒤에만 실행해.

### 평가
**오늘 확인한 Skill 중 운영 안전성 측면에서 가장 잘 설계된 편이다.** 범용 Skill은 아니지만 보안 공지처럼 실수 비용이 큰 작업에서 Skill이 guardrail 역할을 하는 방향을 명확히 보여준다.

### 설치 및 사용
Claude Code용으로 페이지에 명시된 명령:
```bash
npx skills add anthropics/skills --skill web-artifacts-builder --agent claude-code
```

일반 설치 형식:
```bash
npx skills add https://github.com/anthropics/skills --skill web-artifacts-builder
```

추가 요구사항:
- Node.js **18+**
- Bash 실행 환경
- Vite / React / TypeScript / Tailwind / shadcn/ui
- 최종 bundle 과정에서 Parcel 및 html-inline 계열 의존성 사용

### 활용 예시
> 여러 화면과 상태 관리를 가진 내부 관리도구 프로토타입을 React로 만들고, 외부 서버 없이 전달할 수 있도록 모든 CSS와 JavaScript를 포함한 단일 `bundle.html`로 패키징해줘.

### 평가
**Agent 산출물을 '코드 묶음'이 아니라 바로 전달 가능한 단일 실행 Artifact로 바꾸는 흐름이 강점이다.** 다만 단순 HTML 한 장이면 오히려 이 scaffold가 과하다.

### 🏆 오늘의 Top Pick

**`google-agents-cli-deploy`**

Trending(24h) #1이라는 단기 신호뿐 아니라, Agent 개발에서 가장 현실적인 난관인 **배포 대상 선택 → IaC → 인증 → CI/CD → 관측/롤백**을 하나의 절차로 연결한다는 점이 크다. Agent Skill이 단순 코딩 보조에서 실제 운영 플랫폼의 runbook 역할로 확장되는 대표 사례다.

### ⚡ Codex에서 바로 써볼 만한 것

**`browser-use`**

`npx skills add ... --skill browser-use`로 Skill을 붙인 뒤 CDP 연결만 준비하면, Codex가 단순히 Playwright 코드를 작성하는 수준을 넘어 **현재 브라우저 상태를 읽고 반복적으로 클릭·입력·검증**하는 workflow로 넘어갈 수 있다. 시작 전 `browser-use --doctor`로 환경을 확인하는 편이 좋다.

### 오늘 보이는 공통 기술 흐름

오늘 후보들의 공통점은 **Skill이 '프롬프트 모음'에서 '운영 절차 + 실제 도구 + 안전 게이트'로 이동하고 있다는 것**이다. Google 배포 Skill은 Terraform/WIF/CI·CD를, browser-use는 CDP를, GHSA Maintainer는 GitHub API와 검증 순서를, PPT/Web Artifact Skill은 파일 생성 파이프라인을 직접 감싼다. 동시에 `multi-agent-review`처럼 한 모델의 판단을 그대로 실행하지 않고 여러 검토자와 판정 단계를 두는 패턴도 늘고 있다. 앞으로 좋은 Skill의 기준은 지식량보다 **실행 가능한 도구 체인, 실패 조건, 권한 경계, 검증 절차를 얼마나 명확하게 정의하느냐**에 더 가까워질 가능성이 크다.
