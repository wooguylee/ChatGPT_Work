### 무엇을 해결하나

AI 코딩 Agent는 버전이 올라가면서 JSON/JSONL 세션 schema, usage/rate-limit 필드, 저장 위치가 조용히 바뀔 수 있고, 이때 세션 뷰어나 분석기가 “에러 없이 새 세션만 못 찾는” 문제가 생긴다. 이 Skill은 단순 버전 비교가 아니라 **최신 CLI가 실제로 쓴 세션을 생성 → schema fingerprint 비교 → usage probe → discovery path contract 검증** 순으로 증거를 만든다. `supports_latest`, `blocked_stale_sample`, `format_drift_detected`, `monitoring_broken`처럼 원인을 분리하고, 실제 세션 없이 “최신 버전 지원”을 주장하지 못하게 하는 점이 특히 좋다.

### 설치 및 사용

```bash
npx skills add https://github.com/jazzyalex/agent-sessions --skill agent-session-format-check
```

Agent Sessions 저장소에서 주간 검사:

```bash
./scripts/agent_watch.py --mode weekly
```

Codex/Claude 업데이트 전 실제 세션 기반 prebump 검증:

```bash
./scripts/agent_watch.py --mode prebump --agent codex --agent claude
```

Agent Sessions 저장소 체크아웃과 Python 실행 환경이 필요하며, 실제 세션을 생성하는 Agent에는 각 CLI 설치 및 인증이 필요하다. raw session에는 경로·프롬프트가 들어갈 수 있으므로 fixture로 만들 때 redaction 규칙을 따라야 한다.

### 활용 예시

> “Codex와 Claude CLI가 최근 업데이트됐어. 두 Agent의 최신 세션 포맷, usage/rate-limit 파싱, 저장 경로 contract가 여전히 호환되는지 prebump 검증을 실행하고, drift가 있으면 어떤 key/type이 바뀌었는지 증거만 정리해줘. 자동 수정은 하지 마.”

### 평가

**오늘 볼 가치:** Agent 생태계가 빠르게 변하면서 “Agent가 쓴 기록 포맷의 호환성” 자체가 운영 문제로 커지고 있는데, 이를 실제 session evidence로 검증하는 드문 Skill이다.  
**주의:** 독립적인 범용 진단기라기보다 Agent Sessions 프로젝트의 호환성 체계에 깊이 결합되어 있다.

### 무엇을 해결하나

“Lighthouse 점수가 낮다”처럼 막연한 요청에 추측으로 답하지 않고 Chrome DevTools MCP를 통해 **실제 trace → Core Web Vitals → network waterfall → accessibility snapshot → codebase** 순서로 감사를 수행한다. 각 추천은 `hero.png 450KB를 WebP로 압축`처럼 측정 근거를 요구하고, 측정상 영향이 0ms인 render-blocking 항목은 괜히 수정하지 않도록 규칙화되어 있다. 특히 지표 threshold와 DevTools API가 바뀔 수 있으므로 web.dev/Chrome 문서를 최신 retrieval source로 우선하는 구조가 좋다.

### 설치 및 사용

Claude Code에서 확인된 설치 명령:

```bash
npx skills add cloudflare/skills --skill web-perf --agent claude-code
```

필수 MCP 예:

```json
"chrome-devtools": {
  "type": "local",
  "command": ["npx", "-y", "chrome-devtools-mcp@latest"]
}
```

페이지에는 Codex 탭도 제공되지만 이번 crawl에서 Codex 탭의 정확한 명령 문자열은 노출되지 않아 `--agent codex`로 임의 추정해 적지 않았다. 핵심 요구사항은 Chrome DevTools MCP이며, `navigate_page` 또는 `performance_start_trace`가 없으면 감사 시작 전에 중단하도록 설계되어 있다.

### 활용 예시

> “로컬에서 실행 중인 이 Vite 웹앱을 web-perf 절차로 감사해줘. 실제 trace로 LCP/CLS/TBT를 측정하고, 네트워크 병목과 접근성 문제를 확인한 뒤 예상 영향이 큰 수정 3개만 코드 위치와 함께 제안해줘.”

### 평가

**오늘 볼 가치:** 공식 Cloudflare Skill이면서 단순 체크리스트가 아니라 Chrome DevTools MCP의 실측 데이터를 강제해 Agent의 성능 조언을 검증 가능한 형태로 바꾼다.  
**주의:** Chrome DevTools MCP가 먼저 구성돼야 하며 브라우저 실행 환경이 없는 원격 Agent에서는 바로 쓰기 어렵다.

### 🏆 오늘의 Top Pick

**`add-codex`** — Codex를 외부 LLM 호출이나 MCP 하위 도구로 쓰는 것이 아니라, NanoClaw의 planning/tool orchestration/history/resume까지 담당하는 **교체 가능한 Agent provider**로 올리는 구조가 오늘 후보 중 기술적으로 가장 의미 있다. 특히 `codex app-server` + JSON-RPC + vault-only credential이라는 조합은 앞으로 멀티-Agent 런타임이 “모델 선택”보다 “Agent backend 선택”으로 발전하는 흐름을 잘 보여 준다.

### ⚡ Codex에서 바로 써볼 만한 것

**`prisma-client-api`** — `npx skills add https://github.com/prisma/skills --skill prisma-client-api` 한 줄로 설치할 수 있고 MCP, Docker, API Key 같은 추가 준비가 없다. Prisma 프로젝트에서 Codex가 오래된 API를 섞는 문제를 바로 줄일 수 있어 적용 비용 대비 효과가 가장 빠르다.

### 오늘의 흐름

오늘 후보들의 공통점은 Skill이 단순 프롬프트 모음에서 **실행 환경과 검증 절차를 가진 운영 레이어**로 이동하고 있다는 점이다. Tesseract는 로컬 미디어 엔진, `add-codex`는 교체 가능한 Agent runtime, `agent-session-format-check`는 CLI/session 호환성 검증, `web-perf`는 DevTools 실측을 연결한다. 동시에 Prisma/.NET처럼 변화가 빠르거나 관용 규칙이 많은 기술에서는 “최신 레퍼런스를 Agent 컨텍스트에 고정하는 Skill”도 대규모 사용을 유지하고 있어, 앞으로는 **도구 실행형 Skill + 최신 지식형 Skill**이 함께 개발 workflow의 기본 레이어가 될 가능성이 크다.
