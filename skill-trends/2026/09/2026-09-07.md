- **GitHub:** [designed-by-ai/skills](https://github.com/designed-by-ai/skills) / [`skills/design-mobile-apps/SKILL.md`](https://github.com/designed-by-ai/skills/blob/main/skills/design-mobile-apps/SKILL.md)
- **제작자/조직:** designed-by-ai / Sleek 연동 Skill
- **지원 Agent:** SKILL.md 호환 coding agent. Skill 자체가 요청 source 값으로 `codex`, `claude-code`, `cursor`, `chatgpt`, `openclaw` 등을 다루며 Codex/Claude Code workflow에 적용 가능하다.

### 인기 및 트렌드 지표

- skills.sh 누적 설치: **19.9K**.
- skills.sh First Seen: **1 day ago** — 매우 짧은 기간에 설치가 몰린 신규 후보다.
- skills.sh 보안 감사: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Pass**.
- GitHub 현재 snapshot: **1 Star / 0 Forks**.
- GitHub repo 생성: **2026-09-04**, 최근 push: **2026-09-06**.
- 별도 품질 점수·좋아요·정확한 24시간 증가량은 현재 상세 페이지에서 명확히 확인되지 않아 미기재.

### 무엇을 해결하나

Agent가 UI를 텍스트로만 제안하는 데서 끝나지 않고, **Sleek의 REST API**(`/api/v1/*`)에 자연어 설계 의도를 보내 실제 모바일 화면을 생성하고 결과를 스크린샷으로 확인하게 한다. 프로젝트 생성, 비동기 design run, screen/component 조회, screenshot 생성의 명시적 API 흐름을 제공하며, 구현 단계에서는 screenshot만 보는 대신 component HTML을 가져와 React Native·SwiftUI 등의 실제 코드 기준으로 사용하도록 한다. 즉 “디자인 조언 Skill”이 아니라 외부 디자인 시스템을 Agent의 실행 도구로 바꾸는 **service-client Skill**에 가깝다.

### 설치 및 사용

```bash
npx skills add https://github.com/designed-by-ai/skills --skill design-mobile-apps
```

필수 환경변수:

```bash
export SLEEK_API_KEY="..."
```

Windows PowerShell이라면:

```powershell
$env:SLEEK_API_KEY="..."
```

**추가 요구사항:** `SLEEK_API_KEY`, `https://sleek.design` 네트워크 접근. API key는 필요한 scope만 부여하는 것이 권장된다. 별도 MCP는 필수가 아니며 HTTP API를 직접 사용한다.

### 활용 예시

> 헬스장 회원용 모바일 앱을 설계해. 로그인, 오늘 운동, 기록, 결제 화면을 하나의 일관된 디자인 시스템으로 만들고 Sleek에서 각 화면 screenshot을 보여준 다음 React Native 구현에 필요한 component 구조를 정리해줘.

### 평가

**오늘 볼 가치:** 출시 직후 설치가 빠르게 늘었고, Agent Skill이 단순 지식 문서가 아니라 외부 SaaS의 실제 생성 API를 조작하는 방향으로 확장되는 흐름을 잘 보여준다.  
**주의:** GitHub 자체는 아직 1★ 수준의 매우 신생 repo이고 API Key/외부 서비스 의존성이 있으므로, 설치 수만으로 성숙도를 판단하면 안 된다.

### 인기 및 트렌드 지표

### 무엇을 해결하나

이 Skill은 Agent 개발을 “코드부터 쓰기”로 시작하지 못하게 하고 **Phase 0 요구사항/안전 제약 → reference recipe 조사 → scaffold → 구현 → behavior eval → deploy → publish → observability**의 lifecycle로 묶는다. 특히 `pytest`와 LLM behavior eval을 구분하고, `agents-cli eval`을 필수 phase로 두며, deployment 전에 평가 결과와 사용자 승인을 거치도록 한다. 내부적으로 `google-agents-cli-adk-code`, `-scaffold`, `-eval`, `-deploy`, `-observability` 같은 전문 Skill을 단계별로 다시 로드하는 **orchestrator Skill**이다.

> 중복 메모: 인덱스에 이미 있는 `google-agents-cli-adk-code`는 ADK Python 구현 패턴용 reference Skill이고, 이번 `google-agents-cli-workflow`는 전체 개발 lifecycle을 조율하는 별도 Skill이므로 단순 이름 변경/파생 중복으로 보지 않았다.

### 설치 및 사용

Skill 설치:

```bash
npx skills add https://github.com/google/agents-cli --skill google-agents-cli-workflow
```

실제 CLI 설치:

```bash
uv tool install google-agents-cli
agents-cli info
```

전체 Google skill suite를 구성하려면 공식 안내의 setup도 사용할 수 있다.

```bash
uvx google-agents-cli setup
```

**추가 요구사항:** `uv`, `google-agents-cli~=1.5.0`. Google Cloud에 deploy하는 단계에서는 해당 프로젝트/IAM/인증 설정이 추가로 필요하다.

### 활용 예시

> 고객 문의를 분류하고 내부 문서에서 근거를 찾아 답하는 Agent를 만들고 싶어. 바로 코딩하지 말고 google-agents-cli-workflow대로 요구사항과 안전 제약을 먼저 확정하고, prototype → eval → Cloud Run 배포까지 단계별로 진행해줘.

### 평가

**오늘 볼 가치:** Agent 개발이 “prompt + tool 몇 개”에서 **검증 가능한 SDLC**로 이동하는 흐름을 가장 명확하게 구현한다.  
**주의:** Google Cloud/ADK 쪽으로 workflow가 강하게 최적화되어 있어 다른 runtime만 쓰는 팀에는 일부 phase가 과할 수 있다.

### 무엇을 해결하나

이 Skill의 첫 질문은 “어떤 Agent framework를 쓸까?”가 아니라 **“이 문제가 정말 Agent여야 하는가?”**다. Agent가 필요하다고 판단된 뒤에도 workflow/FSM/DAG/loop 중 control flow를 선택하고, **MCP는 tool/data boundary, A2A는 agent handoff boundary**로 분리하며, state·schema·approval·eval·telemetry·rollback·kill switch를 production default로 둔다. 큰 reference를 progressive disclosure로 분리하고 graph engineering, autonomous loop, memory, protocol, observability를 필요한 순간에만 로드하는 구조도 실전 Agent 설계에 적합하다.

### 설치 및 사용

```bash
npx skills add https://github.com/vasilyu1983/AI-Agents-public --skill ai-agents
```

**추가 요구사항:** 핵심 architecture review는 별도 MCP/API Key 없이 사용할 수 있다. 다만 설계 결과에 따라 MCP/A2A, OpenTelemetry, 외부 model/provider 등이 후속 구현 의존성으로 생길 수 있다.

### 활용 예시

> 사내 문서 검색과 티켓 처리를 자동화하려고 해. 처음부터 multi-agent로 가정하지 말고 ai-agents 기준으로 workflow, single-agent, multi-agent 세 가지를 비교한 뒤 MCP/A2A 경계, 상태 모델, 평가 지표, 승인·rollback·kill switch까지 포함한 production architecture를 제안해줘.

### 평가

**오늘 볼 가치:** “Agent를 많이 붙이는 것”보다 **명시적 control flow와 운영 안전성**을 우선하는 최근 production-agent 사고방식을 잘 정리한다.  
**주의:** 저장소 자체 규모는 아직 85★로 작고, 일부 연구/보안 참고사항은 계속 변할 수 있으므로 중요한 주장과 버전은 1차 출처를 다시 확인해야 한다.

### 무엇을 해결하나

Coding Agent가 React/Next.js/Prisma 같은 library 질문에 오래된 training data로 답해 버리는 문제를 **Context7 MCP의 현재 문서 조회**로 바꾼다. 먼저 `resolve-library-id`로 정확한 공식 library/version을 찾고, 그 다음 `query-docs`로 사용자의 실제 질문에 맞는 문서와 code snippet을 가져오는 2단계 구조다. 최대 호출 횟수, official source 우선, version-aware 선택, query에 secret을 넣지 않는 규칙까지 명시해 단순 “웹 검색해”보다 재현성이 높다.

### 설치 및 사용

AgentSkill.sh를 쓰는 경우 먼저 CLI를 구성한다.

```bash
npx @agentskill.sh/cli@latest setup
```

그 뒤 AgentSkill의 `/learn`에서 `affaan-m/documentation-lookup`을 찾아 설치할 수 있다. 표준 skills CLI로 원본 ECC Skill을 직접 설치하는 방법도 단순하다.

```bash
npx skills add https://github.com/affaan-m/ECC --skill documentation-lookup
```

**추가 요구사항:** **Context7 MCP**가 Agent에 등록되어 있어 `resolve-library-id`, `query-docs` tool을 호출할 수 있어야 한다. 외부 문서 조회 query에 API key·token 같은 비밀값을 포함하면 안 된다.

### 활용 예시

> Next.js 최신 버전에서 middleware와 proxy 관련 권장 방식이 어떻게 바뀌었는지 Context7로 공식 문서를 먼저 확인하고, 내 기존 middleware.ts를 어떤 방식으로 바꾸는 게 맞는지 코드 예제로 설명해줘.

### 평가

### 무엇을 해결하나

단일 reviewer prompt 하나가 모든 관점을 동시에 보게 하는 대신, 이 Skill은 **review orchestrator** 역할만 맡는다. sibling `code-review-*` Skill마다 별도 subagent를 띄워 breaking change, change size, context, testing 관점 등을 병렬로 검토하고, 모든 finding을 파일 경로와 line number를 포함한 raw Markdown으로 합친다. 특히 “한 모델이 한 번 훑는 코드 리뷰”에서 “전문화된 reviewer ensemble”로 옮겨가는 구조를 OpenAI의 실제 Codex repository workflow에서 확인할 수 있다는 점이 중요하다.

### 설치 및 사용

orchestrator 설치:

```bash
npx skills add https://github.com/openai/codex --skill code-review
```

다만 이 Skill은 sibling reviewer들을 호출하도록 작성되어 있어 **orchestrator만 단독 설치하면 완전한 동작이 아니다.** 최소한 현재 공식 repo에 있는 reviewer set도 함께 설치하는 편이 맞다.

```bash
npx skills add https://github.com/openai/codex --skill code-review-breaking-changes
npx skills add https://github.com/openai/codex --skill code-review-change-size
npx skills add https://github.com/openai/codex --skill code-review-context
npx skills add https://github.com/openai/codex --skill code-review-testing
```

**추가 요구사항:** Codex의 subagent 실행 기능과 검토할 Git repository/PR context. Skill은 PR에 자동 comment를 남기지 않고 명시적으로 요청된 경우에만 comment하도록 설계되어 있다.

### 활용 예시

> 이 PR을 OpenAI code-review Skill set으로 최종 검토해. breaking change, 테스트 누락, context 상의 버그, 변경 크기를 각각 별도 reviewer로 분석하고 모든 finding을 파일/라인 근거와 함께 심각도 순으로 정리해줘. 아직 GitHub comment는 남기지 마.
