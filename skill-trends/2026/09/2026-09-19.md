### 설치 및 사용

```bash
npx skills add https://github.com/tenequm/skills --skill mpp
```

추가 요구사항:
- 선택한 언어에 맞는 MPP SDK(`mppx`, `pympp`, `mpp` 등)가 필요.
- 결제 rail에 따라 별도 wallet/provider 설정이 필요.
- SkillsMP metadata에는 주요 환경 변수로 `MPP_SECRET_KEY`가 표시됨.

### 활용 예시

> 이 Express API의 `/research` 엔드포인트를 HTTP 402 기반 유료 API로 바꾸고, Agent가 결제 후 자동으로 재시도할 수 있는 MPP 흐름을 구현해줘.

### 평가

**왜 오늘 볼 가치가 있나:** 설치 수보다 “Agent-to-Agent 경제”라는 방향성이 중요한 후보다. 아직 저장소 규모와 실제 채택이 작아 production 도입 전 프로토콜 안정성과 결제 보안 검토가 필요하다.

### 무엇을 해결하나

Coding Agent가 “코드를 만들었다 → 테스트 몇 개 통과했다 → 완료”로 끝내면 복잡한 작업에서 품질 저하를 놓치기 쉽다. `eval-harness`는 Eval-Driven Development(EDD) 관점에서 변경 전후를 공식 평가하고, capsule·gate·receipt 같은 검증 artefact를 남기도록 한다. 현재 ECC upstream에는 `scripts/eval-harness.js`와 `scripts/lib/eval-harness/`의 기계적 검증 유틸리티가 있고, 예제는 로컬·오프라인 임시 디렉터리에서 평가 흐름을 재현하도록 구성돼 있다.

### 설치 및 사용

AgentSkill.sh 방식:

```bash
npx @agentskill.sh/cli@latest setup
```

설정 후 Agent에서:

```text
/learn @affaan-m/eval-harness
```

AgentSkill.sh 배포본은 SKILL.md 중심이며, upstream ECC의 전체 eval utility를 그대로 활용하려면 Node.js와 ECC 저장소의 관련 script가 필요할 수 있다.

### 활용 예시

> 이 인증 모듈 리팩터링을 바로 승인하지 말고 eval-harness 방식으로 baseline, 변경 후 평가, 회귀 검증, 최종 evidence receipt까지 만들어서 통과 여부를 판단해줘.

### 평가

**왜 오늘 볼 가치가 있나:** Agent가 더 많은 코드를 자율적으로 바꿀수록 “생성 능력”보다 “검증을 강제하는 구조”가 중요해진다. 높은 보안 점수와 매우 활발한 upstream을 갖고 있으며, 단점은 단순 작업에는 평가 artefact가 오버헤드가 될 수 있다는 점이다.

**`aspnet-core`**

OpenAI 공식 curated Skill이고 `$skill-installer aspnet-core`로 설치할 수 있어 별도 MCP/API Key가 필요 없다. .NET 프로젝트라면 오래된 프레임워크 패턴을 피하고 현재 공식 권장 구조를 따르게 하는 효과를 바로 얻을 수 있다.

## 오늘 보이는 공통 흐름

오늘 후보들의 공통점은 Skill이 더 이상 “좋은 프롬프트 모음”에 머물지 않고 있다는 점이다. 배포 후 등록(`google-agents-cli-publish`), DB 운영 규칙(`supabase-postgres-best-practices`), 최신 API 지식(`claude-api`), 기계 간 결제(`mpp`), 공식 평가 절차(`eval-harness`), 프레임워크 공식 가이드(`aspnet-core`)처럼 **Agent의 행동을 특정 운영 규칙·프로토콜·검증 절차에 묶는 실행 지식층**으로 발전하는 흐름이 뚜렷하다.
