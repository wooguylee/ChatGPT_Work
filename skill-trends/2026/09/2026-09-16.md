### 무엇을 하는 Skill인가

TypeSafe는 LLM에게 긴 문장을 생성시키고 다시 파싱하는 방식 대신, **Choice/Noul/Score 같은 좁고 typed된 판단과 확률**을 프로그램의 작은 primitive처럼 쓰게 한다. 코드가 흐름과 실행을 계속 소유하고, 모델은 의미 해석이 필요한 지점에서만 판단을 제공하므로 routing, ranking, extraction, verification 같은 기능을 더 명시적인 계약으로 조립할 수 있다. Skill은 live docs를 source of truth로 삼고, typed output이 진실을 보장하는 것은 아니므로 실제 도메인 데이터에서 threshold와 정확도를 검증하도록 요구한다.

### 설치 및 사용

```bash
npx skills add https://github.com/typesafe-ai/skills --skill typesafe-ai
```

실제 TypeSafe API/SDK 통합 시에는 live docs의 현재 API 계약을 확인해야 하며, 웹앱에서는 API credentials를 서버 측에 보관해야 한다. JavaScript/Python SDK와 HTTP API 문서가 Skill에서 직접 안내된다.

### 활용 예시

```text
이 고객 문의를 billing / technical / sales 중 하나로 라우팅하고, 애매하면 사람이 검토하도록 TypeSafe Choice와 confidence 기준으로 구현해줘.
```

### 평가

생성형 LLM을 모든 곳에 넣는 대신 **작은 확률적 판단을 코드와 조합하는 구조**를 밀고 있다는 점이 독특하다. 다만 외부 TypeSafe 서비스 의존성이 생기므로 latency·cost·domain calibration을 실제 데이터로 검증해야 한다.

- **제작자/조직:** OpenAI
- **지원 Agent:** Codex용 `OpenAI Developers` plugin bundle

### 인기·트렌드 snapshot

- GitHub 직접 조회 (`openai/plugins`): **6,856 Stars / 895 Forks**
- 저장소 push snapshot: **2026-09-16**
- 공식 저장소 bundle이므로 SkillsMP/skills.sh식 설치 수·좋아요·품질/보안 점수는 별도로 확인되지 않음

### 무엇을 하는 Skill인가

OpenAI API가 실패했을 때 모든 `429`나 `403`을 같은 문제로 취급하지 않고, **HTTP 응답 자체가 오기 전 transport/network failure인지, 401 credential 문제인지, 429 quota exhaustion인지 ordinary rate limit인지, 403/model/project/org access 문제인지**를 먼저 분류한다. 그 뒤 API key 발급이 필요하면 `openai-platform-api-key`, 최신 문서 확인이 필요하면 `openai-docs`로 넘기도록 역할을 분리한다. 공식 eval 파일도 DNS 실패, invalid key 같은 케이스에서 올바른 skill activation과 routing을 검증한다.

### 설치 및 사용

이 Skill은 standalone `npx skills add` 명령을 공식 문서에서 확인하지 못했으므로 추측해서 적지 않는다. `openai/plugins`의 **OpenAI Developers plugin**에 포함된 Codex-facing skill로 사용하는 것이 확인된 경로다. 실제 API 호출을 재현할 때는 네트워크 접근과 유효한 OpenAI API credential이 필요할 수 있으며, key provisioning은 동봉된 `openai-platform-api-key` 흐름으로 분리돼 있다.

### 활용 예시

```text
Codex에서 OpenAI API 호출이 429로 실패해. quota 소진인지 일반 rate limit인지 구분하고, 가장 짧은 다음 조치만 알려줘.
```

### 평가

범용 디버깅 Skill보다 범위는 좁지만, **OpenAI가 직접 Codex용으로 실패 분류와 후속 routing을 정의**했다는 점 때문에 실무 신뢰도가 높다. 설치 방식은 현재 plugin bundle에 묶여 있어 독립 Skill처럼 한 줄 설치하기는 어렵다.
