### 내용 설명

Agent 성능은 모델 자체뿐 아니라 **무슨 정보를 언제, 얼마나 보여 주느냐**에 크게 좌우된다. 이 Skill은 긴 대화나 큰 코드베이스에서 모든 정보를 한꺼번에 밀어 넣는 대신, 작업에 필요한 규칙·결정·파일·상태를 적절한 크기로 유지하도록 프로젝트 컨텍스트를 설계하는 데 초점을 둔다. 컨텍스트가 너무 부족해 생기는 환각과, 너무 많아져 핵심을 놓치는 문제를 동시에 줄이려는 접근이다.

### 설치 및 사용

```bash
npx skills add https://github.com/addyosmani/agent-skills --skill context-engineering
```

- 별도 API Key는 필요하지 않는다.
- 기존 프로젝트의 `AGENTS.md`, 규칙 파일, 문서 구조와 함께 쓰면 효과가 크다.

**활용 예시**

> 이 저장소를 분석해서 Codex가 매번 읽어야 할 핵심 컨텍스트와 필요할 때만 불러와야 할 세부 컨텍스트를 나눠 주고, AGENTS.md 구조를 개선해줘.

**평가:** 설치 부담이 거의 없고 모든 코딩 Agent에 공통적으로 필요한 문제를 다룬다는 점이 강점이다. 다만 방법론적 Skill이라 프로젝트 문서가 부정확하면 자동으로 품질이 좋아지는 것은 아니다.

## 2. `deepeval`

- **출처:** skills.sh
- **원 저장소:** https://github.com/confident-ai/deepeval
- **제작자/조직:** Confident AI
- **지원 Agent:** SKILL.md를 읽는 코딩 Agent에서 활용 가능하며, 설치 명령은 `npx skills` 방식을 제공한다.

### 인기 및 트렌드 지표

- skills.sh 설치 수: **2.5K**
- skills.sh Hot: **#100**
- GitHub snapshot: **18,313 stars / 1,946 forks**
- 저장소 최근 push: **2026-09-16**
- 보안 감사: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Pass**
- 24시간 설치 증가/좋아요/별도 품질 점수: 확인 가능한 공개값 없음

### 내용 설명

LLM 기능을 만들 때 "대충 좋아 보인다"가 아니라 **테스트 케이스와 metric으로 품질을 반복 측정**하도록 만드는 Skill이다. Agent가 애플리케이션을 계측하고 평가 데이터셋과 pytest 기반 평가 suite를 만들며, 실패 케이스를 보고 다시 개선하는 폐쇄형 루프를 구성한다. 프롬프트·RAG·Agent 변경으로 품질이 회귀하는지를 CI처럼 관리하기 좋다.

### 설치 및 사용

```bash
npx skills add https://github.com/confident-ai/deepeval --skill deepeval
pip install deepeval
```

- Python **3.9+** 필요
- 모델 기반 metric이나 synthetic data를 쓰면 해당 provider credential이 필요할 수 있다.
- Confident AI의 hosted reporting/trace/online evaluation을 사용하려면 `deepeval login`이 필요하다.

**활용 예시**

> 이 RAG API에 대해 hallucination, answer relevancy, retrieval 품질을 검증하는 DeepEval pytest 테스트를 만들고, 실패 케이스를 재현 가능한 dataset으로 저장해줘.

**평가:** Agent/LLM 품질을 실제 회귀 테스트로 바꿔 주는 점이 매우 실무적이다. Python 의존성과 일부 고급 기능의 provider credential/hosted 서비스 의존은 고려해야 한다.

### 인기 및 트렌드 지표

- `openai/plugins` GitHub snapshot: **6,911 stars / 900 forks**
- 저장소 최근 push: **2026-09-16**
- SkillsMP 인덱스에 `ai-sdk` Skill이 독립 항목으로 등록
- 독립 Skill 설치 수/24시간 증가/좋아요/품질·보안 점수: 공개 확인 불가

### 내용 설명

Vercel AI SDK로 chat, streaming, structured output, tool calling, agent, MCP, embedding, reranking 등을 구현할 때 **학습 데이터에 남은 옛 API를 믿지 않고 설치된 패키지의 docs/source를 우선 확인**하도록 강제하는 Skill이다. 특히 `useChat` 같은 빠르게 바뀌는 API, provider별 model ID, typecheck 실패, Agent 구성에서 stale 예제를 피하는 데 초점이 있다. 내부적으로 `node_modules/ai/docs`, `node_modules/ai/src`, AI SDK 공식 문서와 현재 model 목록을 확인한 뒤 코드를 쓰는 절차를 명문화한다.

### 설치 및 사용

SkillsMP 방식:

```bash
npx skills add https://github.com/openai/plugins --skill ai-sdk
```

프로젝트에서 AI SDK가 없다면 Skill 지침에 따라 우선 핵심 패키지만 설치한다.

```bash
pnpm add ai
# 또는 npm install ai
```

- Provider가 필요할 때만 `@ai-sdk/openai`, `@ai-sdk/anthropic` 등 필요한 package를 추가한다.
- Skill은 현재 model ID를 메모리에서 추측하지 말고 공식 목록에서 확인하도록 요구한다.
- 변경 후 typecheck 수행을 기본 절차로 둔다.

**활용 예시**

> 이 Next.js API route를 AI SDK 최신 방식으로 바꿔줘. streaming + tool calling + structured output을 사용하고, 현재 설치된 `ai` 패키지 문서와 타입을 먼저 확인한 뒤 구현하고 typecheck까지 해줘.

**평가:** AI 앱 개발에서 API 변화 속도가 빠르다는 문제를 직접 해결하며 Agent/MCP/type safety까지 한 번에 다뤄 **오늘의 가장 범용적인 실전 가치가 높다**. 단, Vercel AI SDK 생태계에 초점이 있고 최신 API 검증 절차를 생략하면 Skill의 장점이 크게 줄어든다.

## 4. `ai-gateway`

- **출처:** SkillsMP
- **원 저장소:** https://github.com/vercel/vercel-plugin
- **Skill:** https://github.com/vercel/vercel-plugin/blob/main/skills/ai-gateway/SKILL.md
- **제작자/조직:** Vercel
- **지원 Agent:** `SKILL.md` 호환 Agent에서 사용 가능. Codex/Claude Code 등에서 skill manager 방식으로 설치할 수 있으며, 실제 coding-agent 연결 설정도 Skill 범위에 포함한다.

### 인기 및 트렌드 지표

- GitHub snapshot: **284 stars / 56 forks**
- 저장소 최근 push: **2026-09-15**
- SkillsMP source activity snapshot: 2026-09 초 활동 확인
- 독립 Skill 설치 수/24시간 증가/좋아요/품질·보안 점수: 공개 확인 불가

### 내용 설명

여러 LLM provider를 앱에서 직접 각각 연결하는 대신 **AI Gateway를 하나의 중간 계층으로 두어 인증, model routing, provider failover, BYOK, 예산, 사용량, 관측성을 통합**한다. Skill은 provider/model ID 형식, OIDC/API key 차이, fallback, spend control, coding-agent 연결 같은 실수하기 쉬운 설정을 검증 규칙으로 포함한다. 또한 AI SDK 코드가 감지되면 `ai-sdk` Skill로 이어지도록 설계되어 역할 분리가 분명하다.

### 설치 및 사용

```bash
npx skills add https://github.com/vercel/vercel-plugin --skill ai-gateway
```

프로젝트 요구에 따라:

```bash
pnpm add @ai-sdk/gateway
```

또는 Vercel CLI의 현재 `ai-gateway` 명령을 사용한다. 모델 목록·가격·CLI 옵션은 자주 바뀌므로 실행 시 공식 문서/CLI에서 재확인해야 한다.

- 인증은 상황에 따라 `AI_GATEWAY_API_KEY` 또는 `VERCEL_OIDC_TOKEN`을 사용한다.
- provider API key를 Gateway 요청용 key와 혼동하지 않도록 Skill 자체에 validation 규칙이 있다.

**활용 예시**

> OpenAI와 Anthropic을 직접 호출하는 이 Node.js 서비스를 Vercel AI Gateway 기반으로 바꾸고, provider fallback과 비용 추적을 추가해줘. 현재 가능한 model ID와 인증 방식부터 확인해줘.

**평가:** 멀티-provider 운영 복잡도를 크게 줄일 수 있다. 대신 Vercel Gateway에 운영 계층이 추가되므로 vendor 의존성과 비용/장애 경로를 함께 평가해야 한다.

- **출처:** OpenAI 공식 Codex plugin 저장소
- **Skill:** https://github.com/openai/plugins/blob/main/plugins/build-web-apps/skills/frontend-app-builder/SKILL.md
- **Plugin:** `plugins/build-web-apps`
- **저장소:** https://github.com/openai/plugins
- **제작자/조직:** OpenAI curated plugin collection
- **지원 Agent:** 공식적으로 Codex plugin workflow에 맞춰져 있음

### 인기 및 트렌드 지표

- Build Web Apps plugin version: **0.1.2**
- `openai/plugins` GitHub snapshot: **6,911 stars / 900 forks**
- 저장소 최근 push: **2026-09-16**
- 독립 Skill 설치 수/24시간 증가/좋아요/품질·보안 점수: 공개 확인 불가

### 내용 설명

일반적인 "프론트엔드 만들어줘" Skill보다 훨씬 강하게 **디자인을 먼저 만들고, 승인된 시안을 production spec으로 취급한 뒤, 구현 결과를 browser screenshot과 직접 비교**하도록 규정한다. Image Gen으로 전체 화면/섹션별 concept을 만들고, 디자인 토큰·typography·component family를 추출한 다음 React/Vite 등으로 구현하며, 마지막에는 accepted concept과 실제 browser 결과를 `view_image`로 비교할 때까지 완료로 보지 않는다. 디자인 Agent와 구현 Agent의 역할을 하나의 반복 workflow로 연결한 구조가 특징이다.

### 설치 및 사용

Codex에서는 OpenAI curated plugin marketplace의 **Build Web Apps** plugin을 설치해 사용하는 방식이 가장 자연스럽다. 소스 bundle은 다음 경로에 있다.

```text
openai/plugins/plugins/build-web-apps
```

Skill 단독 파일은:

```text
plugins/build-web-apps/skills/frontend-app-builder/SKILL.md
```

- Image Gen 사용이 기본 전제이며, 작은 기존 UI 수정은 예외로 둘 수 있다.
- 구현 검증에는 Codex Browser/built-in browser를 우선하고, 불가할 때 Playwright Chromium을 fallback으로 사용하도록 지침이 있다.
- 새 복잡한 UI는 별도 framework 요구가 없으면 React + Vite를 기본 선택으로 둔다.

**활용 예시**

> 이 제품 요구사항으로 관리자 대시보드를 새로 디자인해줘. 먼저 전체 화면과 주요 상태를 Image Gen concept으로 만들고, 승인된 디자인 시스템을 추출한 뒤 React로 구현해서 browser screenshot과 원본 concept이 맞을 때까지 수정해줘.

**평가:** Codex가 "코드는 되지만 화면은 평범한" 결과를 내는 문제를 해결하려는 공식 workflow라는 점이 독창적이다. 대신 이미지 생성·승인·browser 비교까지 수행하므로 단순 CRUD UI에는 다소 무거울 수 있다.
