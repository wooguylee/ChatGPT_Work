### 무엇을 해결하는가

“빌드가 성공했으니 프런트엔드도 정상”이라는 잘못된 완료 판단을 막기 위한 **렌더링 기반 QA loop**다. 변경 전 테스트 flow를 정의하고, Browser plugin이 있으면 이를 우선 사용해 URL/title, blank page, framework error overlay, console warning/error, screenshot, 실제 interaction을 확인한다. Browser plugin이 없을 때는 Playwright로 fallback하며, 수정 후 같은 interaction을 반복해 증거를 남기도록 강제한다.

특히 최종 응답도 Summary/Environment/Changes Verified/Checks/Interaction Loop/Evidence/Remaining Risk 형태의 QA 보고서로 만들도록 설계돼 있어, Agent가 “코드를 고쳤다”에서 끝나는 대신 **실제 사용자가 보는 결과를 검증한 뒤 완료 선언**하게 한다.

### 설치 및 사용

독립 Skill 설치:

```bash
npx skills add https://github.com/openai/plugins --skill frontend-testing-debugging
```

또는 Codex의 공식 **Build Web Apps** plugin에 포함된 Skill로 사용할 수 있다. OpenAI plugin 저장소의 marketplace entry에서 `build-web-apps`는 CODEX용으로 제공되며, Browser plugin이 있으면 우선 사용하고 없으면 기존 프로젝트의 Playwright를 활용한다.

추가 요구사항:

- Browser plugin 사용 가능 시 우선 사용
- fallback 시 Playwright가 프로젝트에 구성돼 있으면 이를 사용
- 새 브라우저 의존성을 무조건 설치하지 않고 기존 환경을 우선하도록 명시됨

### Agent 활용 예시

`localhost에서 실행 중인 대시보드의 검색 필터를 고친 뒤 frontend-testing-debugging workflow로 데스크톱과 모바일에서 실제 클릭까지 검증하고, 콘솔 오류와 screenshot evidence를 포함해 QA해줘.`

### 평가

오늘 후보 중 Codex 개발 workflow와 가장 직접 연결된 공식 Skill이다. **코드 변경 → 실제 브라우저 검증 → 증거 기반 완료 선언**을 기본 행동으로 만든다는 점이 중요하다. Browser plugin의 가용성에 따라 실행 경로가 달라질 수 있다는 점은 환경 의존성으로 봐야 한다.
