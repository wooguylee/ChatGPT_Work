### 인기 및 트렌드 지표

### 무엇을 해결하나

Archify는 “그림을 그려줘” 수준의 프롬프트 Skill이 아니라, 아키텍처·workflow·sequence·dataflow·lifecycle을 **typed JSON → validation → deterministic delivery → browser visual-check** 흐름으로 만드는 실행형 Skill이다. 실제 저장소 구조를 근거로 다이어그램을 만들 수 있고, Mermaid를 입력으로 받아 의미를 유지하면서 자체 JSON 구조로 다시 저작한다. 결과는 inline SVG를 포함한 self-contained HTML이며 light/dark, trace, PNG/JPEG/WebP/SVG/WebM export까지 지원한다.

특히 `validate`와 `deliver`를 분리해 “렌더가 됐다”와 “검증된 산출물이다”를 구분하는 점이 좋다. Agent가 흔히 만드는 보기 좋은데 사실관계나 배치가 틀린 다이어그램을 줄이는 구조다.

### 설치 및 사용

```bash
npx skills add https://github.com/tt-a1i/archify --skill archify
```

Skill 디렉터리 안에서 기본 점검과 생성 도구를 사용할 수 있다.

```bash
node bin/archify.mjs doctor
node bin/archify.mjs validate architecture candidate.json --quality showcase --json
node bin/archify.mjs deliver architecture candidate.json output.html --quality showcase --json
node bin/archify.mjs visual-check output.html --json
```

- **추가 요구사항:** Node.js. `visual-check`에는 실제 브라우저 실행 환경이 필요하다.
- 별도 MCP나 API Key는 필수가 아니다.

### 활용 예시

> “이 저장소의 인증 요청 흐름을 실제 코드를 근거로 분석해서 architecture와 sequence 다이어그램을 Archify HTML로 만들어줘. showcase validation을 통과시키고 마지막에 visual-check 결과도 요약해줘.”

### 평가

**오늘 가장 눈에 띄는 Skill.** 높은 24h Trending 신호와 큰 GitHub 관심도뿐 아니라, “Agent가 만든 시각화도 테스트 가능한 artifact여야 한다”는 방향을 잘 구현했다. 다만 단순한 5-node 플로차트에는 구조가 과하고, `visual-check`가 통과해도 미적 완성도는 별도 시각 검토가 필요하다.

### 무엇을 해결하나

이 Skill은 Neon의 Lakebase Postgres를 다룰 때 Agent가 자주 틀리는 연결 방식과 운영 규칙을 실행 순서로 고정한다. 예를 들어 일반 웹/serverless traffic은 pooled connection을 쓰고, migration·`pg_dump`·logical replication·`LISTEN/NOTIFY`는 direct connection을 써야 한다는 구분을 명시한다.

또한 Neon CLI 또는 MCP를 이용해 organization/project를 선택하고 connection string을 가져오며, branching·schema migration·autoscaling·scale-to-zero·instant restore·read replica까지 한 흐름으로 다룬다. 특히 production migration을 먼저 branch에서 검증하도록 유도해 Agent가 곧바로 운영 DB를 수정하는 위험을 줄인다.

### 설치 및 사용

원본 Skill은 **parent `neon` Skill을 먼저 사용**하라고 명시한다.

```bash
npx skills add neondatabase/agent-skills --skill neon
npx skills add https://github.com/neondatabase/agent-skills --skill neon-postgres
```

- **추가 요구사항:** 실제 조작 시 Neon 계정/프로젝트와 인증이 필요하다.
- 프로젝트 관리에는 **Neon CLI(기본)** 또는 **Neon MCP**를 사용할 수 있다.
- 애플리케이션에는 `pg`, `@neondatabase/serverless`, Drizzle 등 런타임에 맞는 driver/ORM이 추가될 수 있다.

### 활용 예시

> “이 프로젝트를 Neon에 연결해줘. dev용 Neon branch를 만들고, Next.js 서버리스 요청에는 pooled URL을, Drizzle migration에는 direct URL을 사용하도록 `.env`와 migration workflow를 안전하게 구성해줘.”

### 평가

누적 설치 수가 크고, 단순 API 설명이 아니라 **서버리스 DB 운영에서 실제 사고가 나는 지점**을 잘 짚는다. 다만 Neon 전용 Skill이고 skills.sh의 Snyk 결과가 **Warn**이므로 설치 전 현재 감사 상세를 확인하는 편이 좋다.

### 인기 및 트렌드 지표

- SkillsMP 검색 시 최근 등록/노출된 Skill로 확인됨.
- SkillsMP 공개 페이지에는 이 Skill의 누적 설치 수, 24h 증가, 품질 점수, 보안 점수가 제공되지 않아 기재하지 않았다.

### 무엇을 해결하나

`programmatic-codex`는 사람과의 interactive Codex 대화를 자동화하는 게 아니라, **Codex를 다른 workflow의 model worker로 호출**할 때 필요한 안전장치를 묶는다. bundled `scripts/codex.mjs` runner가 desktop-bundled executable을 우선 사용하고, 기본 read-only/ephemeral 실행, JSON event·usage capture, model mismatch 거부, credential redaction, schema-constrained response validation을 수행한다.

한 번 호출하는 작업뿐 아니라 batch 처리, concurrency 조절, 결과 샘플링, 실패 복구까지 별도 reference로 분리해 놓았다. “Codex login”, “ChatGPT access”, “OpenAI API key”를 서로 다른 인증으로 취급해 token을 잘못 재사용하지 못하게 하는 규칙도 실무적이다.

### 설치 및 사용

```bash
npx skills add https://github.com/swyxio/skills --skill programmatic-codex
```

설치 후 Skill 디렉터리의 runner를 Node로 호출한다. 실제 경로는 설치 위치에 맞춰야 한다.

```bash
node <skill-dir>/scripts/codex.mjs \
  --model "$CODEX_MODEL_ID" \
  --prompt 'Classify each input and return strict JSON.' \
  --input input.txt
```

- **추가 요구사항:** Node.js, 로그인된 Codex CLI 또는 해당 SDK workflow.
- API Key가 반드시 필요한 구조는 아니며, Codex 인증과 OpenAI API 인증을 의도적으로 분리한다.

### 활용 예시

> “이 폴더의 500개 로그 파일을 Codex로 병렬 분류하되 strict JSON schema로 결과를 저장하고, 실패한 파일만 재시도해줘. 처음에는 낮은 concurrency로 시작하고 실제 처리율을 보고 늘려줘.”

### 평가

Codex를 **도구가 아니라 조합 가능한 execution primitive**로 보는 흐름을 잘 보여준다. 반복/배치 자동화에는 매우 유용하지만, Codex를 다시 Codex에서 호출하는 형태는 사용량과 실행량이 빠르게 커질 수 있으므로 concurrency와 budget 제한이 필요하다.

또한 tool 간 동작 차이를 명시적으로 다룬다. 예를 들어 Claude Code의 `@import`는 Codex/Cursor가 그대로 읽지 않을 수 있으므로, 안전 규칙을 import에만 숨기지 말라고 경고한다. 긴 문서를 통째로 다시 쓰기보다 최소 diff를 제안하고, 사용자 확인 후 적용하도록 설계되어 있다.


### 활용 예시

### 평가

**Codex에 바로 적용하기 가장 쉬운 Skill.** 추가 인프라 없이 설치 한 번으로 현재 저장소의 Agent 품질을 개선할 수 있고, 단순 문체 교정보다 실제 실행 검증을 우선한다. 반대로 의도적으로 수정 전 사용자 확인을 요구하므로 완전 무인 자동수정 용도에는 덜 맞는다.

### 무엇을 해결하나

이 Skill의 핵심은 “무조건 전체 테스트”가 아니라 **변경된 surface를 먼저 증명하고, 필요한 만큼만 검증 범위를 넓히는 것**이다. `pnpm check:changed`, `pnpm test:changed`, targeted Vitest 등 가장 작은 증명을 우선하고, clean-machine·Docker·E2E·desktop·cross-platform이 필요한 경우에만 remote proof로 이동한다.

더 중요한 부분은 trust boundary다. 외부 contributor/fork 코드는 로컬에서 실행하지 않고 secretless fork CI 또는 sanitized AWS Crabbox를 사용하며, 원격 lease를 검토된 정확한 head SHA에 묶는다. 즉 테스트 Skill 안에 supply-chain threat model과 credential isolation이 들어가 있다.

### 설치 및 사용

AgentSkill.sh CLI 초기 설정:

```bash
npx @agentskill.sh/cli@latest setup
```

Agent 안에서:

```text
/learn @openclaw/openclaw-testing
```

OpenClaw 저장소에서 주로 쓰는 명령 예:

```bash
pnpm changed:lanes --json
pnpm check:changed
pnpm test:changed
pnpm verify
```

- **추가 요구사항:** OpenClaw 개발에는 Node.js/pnpm이 필요하다.
- CI 조사에는 `gh` CLI가 유용하다.
- untrusted/remote proof에는 상황에 따라 Crabbox, AWS 또는 Blacksmith Testbox가 추가된다.

### 활용 예시

> “이 PR의 diff를 기준으로 가장 작은 검증 경로를 선택해줘. 신뢰된 코드면 targeted local test부터 시작하고, fork에서 온 코드라면 로컬 실행 없이 secretless 또는 격리된 remote proof로 검증해줘.”

### 평가

테스트 선택과 보안을 한 Skill에 묶은 점이 독창적이다. OpenClaw처럼 초대형 Agent 프로젝트에는 매우 실용적이지만, 일반 작은 저장소에 그대로 가져오면 Crabbox/AWS 격리 절차가 과도할 수 있다.

## 6. openai-platform-api-key

- **지원 Agent:** **Codex local/app 전용**이라고 Skill에 명시되어 있다.

### 인기 및 트렌드 지표

- `openai/plugins` GitHub live snapshot: **5,307 stars / 760 forks**
- 최근 repository push: **2026-08-29 05:01 KST**

### 무엇을 해결하나

이 Skill은 OpenAI API를 쓰는 앱을 구현하는 Skill이 아니라, 그 전에 반드시 지나가는 **credential gate**다. `OPENAI_API_KEY`가 있는지 값을 출력하지 않고 확인하고, 기존 키 재사용과 새 키 생성 중 무엇을 할지 사용자에게 먼저 묻도록 강제한다. 사용자가 선택하기 전에는 API 구현·테스트·scaffold조차 진행하지 않는 hard stop이다.

신규 키를 만들 때는 OpenAI Platform connector를 통해 암호화된 형태로 전달하고, 로컬 저장 위치를 별도로 확인한 후 workspace 밖이나 symlink target을 거부한다. “Agent가 편의를 위해 `.env`를 읽어 키를 화면에 뿌리는 문제”를 프로세스 차원에서 차단한다.

### 설치 및 사용

공식 저장소에서 개별 Skill용 `npx skills add ...` 명령은 문서화되어 있지 않다. **Codex Plugin Directory의 `OpenAI Developers` plugin**을 설치하는 경로가 공식 방식이며 marketplace manifest상 설치 가능(`AVAILABLE`)하고 설치 시 인증(`ON_INSTALL`)한다.

- **추가 요구사항:** Codex local/app, OpenAI Developers plugin, OpenAI Platform connector 인증.
- 신규 키 생성 또는 secret write 전에 명시적 사용자 확인이 필요하다.
- 다른 AI provider를 명시한 작업에는 사용하지 않는다.

### 활용 예시

> “이 Node.js 프로젝트에 OpenAI Responses API를 붙여줘. 먼저 openai-platform-api-key 규칙대로 기존 `OPENAI_API_KEY`의 사용 가능 여부를 값 노출 없이 확인하고, 재사용할지 새 키를 만들지 나에게 선택받은 다음 구현을 시작해줘.”

### 평가

Agent가 secret을 다룰 때 **기능 구현보다 credential decision을 먼저 둔다**는 점에서 중요한 공식 패턴이다. 반면 이 Skill은 일부러 사람의 선택을 기다리도록 설계되어 있어 완전 무인 CI/배치에는 맞지 않는다.
