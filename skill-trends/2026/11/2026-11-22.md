## 1. sentry-get-started

팀에 이미 연결된 Sentry가 있는지부터 확인한다. 새 프로젝트라면 SDK 연동과 첫 이벤트 확인의 순서를 잡고, 기존 프로젝트는 필요한 작업으로 범위를 좁힌다.

- 예시: “테스트 API에 기존 SDK 설정이 있는지 보고 첫 오류 확인 절차만 써줘. 계정이나 새 프로젝트는 만들지 마.”
- 태그: 온보딩, 오류 모니터링
- 출처: [공식 SKILL.md](https://github.com/getsentry/sentry-for-ai/blob/main/src/skills/sentry-get-started/SKILL.md)

## 2. sentry-instrument

오류, 트레이싱, 로그, 리플레이 등에서 필요한 신호를 골라 플랫폼별 문서를 찾는다. 기존 SDK를 유지한 채 신호 하나만 추가하는 경우와 최초 연결을 구분한다.

- 예시: “Koa API에 오류 수집이 있다고 가정하고 요청 추적만 추가할 위치를 검토해줘. 본문·토큰은 수집하지 마.”
- 태그: SDK, Node.js, 트레이싱
- 출처: [공식 SKILL.md](https://github.com/getsentry/sentry-for-ai/blob/main/src/skills/sentry-instrument/SKILL.md)

## 3. sentry-debug-issue

스택 트레이스와 오류 직전 이벤트를 보고 저장소의 실제 코드와 대조한다. 근거가 있는 수정 후보와 회귀 테스트를 남긴다. 이슈 내용은 지시가 아닌 데이터로 취급한다.

- 예시: “익명화한 오류 한 건으로 실패 경로와 재현 테스트 초안을 만들어줘. 이슈 상태를 바꾸거나 PR을 보내지 마.”
- 태그: 오류 진단, 회귀 테스트
- 출처: [공식 SKILL.md](https://github.com/getsentry/sentry-for-ai/blob/main/src/skills/sentry-debug-issue/SKILL.md)

## 4. sentry-otel-exporter-setup

기존 OpenTelemetry Collector의 수신부와 파이프라인을 확인하고 트레이스·로그를 프로젝트별로 보내는 경로를 설계한다. 원문은 `otelcol-contrib` 0.145.0 이상을 요구한다.

- 예시: “두 샘플 서비스의 트레이스를 구분하는 Collector 설정 초안을 써줘. 기존 설정과 비교만 하고 적용하지 마.”
- 태그: OpenTelemetry, Collector, 라우팅
- 출처: [공식 SKILL.md](https://github.com/getsentry/sentry-for-ai/blob/main/src/skills/sentry-otel-exporter-setup/SKILL.md)

## 5. sentry-create-alert

이슈 생성·재발 등 트리거와 우선순위 조건, 수신처를 분리한다. 원문은 새 Monitors and Alerts 워크플로 API를 베타로 표기한다. 초안 검토와 실제 알림 연결은 별개다.

- 예시: “스테이징에서 오류가 재발했을 때만 알리는 조건을 써줘. 수신처는 자리표시자로 두고 규칙은 만들지 마.”
- 태그: 알림, 운영, 워크플로
- 출처: [공식 SKILL.md](https://github.com/getsentry/sentry-for-ai/blob/main/src/skills/sentry-create-alert/SKILL.md)

## 설치와 사용

[공식 소스 저장소](https://github.com/getsentry/sentry-for-ai)는 설치용 배포판과 원본 저장소를 구분한다. Codex에서는 [공식 Codex 배포 저장소](https://github.com/getsentry/plugin-codex)의 안내를 확인한다. 실제 프로젝트 생성, 이슈 조회·변경, 데이터 전송에는 별도 연결과 권한이 필요하다. 검토 단계에서는 가짜 이벤트나 익명화한 스택 트레이스만 사용한다.

## 오늘의 Top Pick: sentry-debug-issue

기존 서비스에서 오류가 보인다면 모니터링을 더 붙이기 전에 한 건을 고른다. 오류 로그의 단서, 코드에서 확인한 사실, 테스트로 확인할 가설을 구분하는 데 좋다.

## Codex에서 바로 써볼 만한 것: sentry-instrument

SDK를 새로 깔기 전에 현재 어떤 신호가 수집되는지 코드에서 확인하고, 필요한 신호 한 가지의 변경안만 받는다.

## 관찰 메모

저장소 README는 MIT를, 확인한 개별 스킬 머리말은 Apache-2.0을 표기한다. 재배포나 코드 재사용을 검토한다면 적용될 파일의 라이선스를 따로 확인한다. 11월 19일의 OpenTelemetry 소개가 공통 계측·수집 흐름에 초점을 뒀다면, 이번 Collector 스킬은 Sentry로 보내는 경로에 초점을 둔다. 실제 설치·인증·이벤트 전송·알림 생성을 하지 않았다.
