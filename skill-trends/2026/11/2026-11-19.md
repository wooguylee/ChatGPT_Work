## 1. opentelemetry

서비스 코드 또는 SDK가 관측 데이터를 만드는 단계다. 에이전트가 서비스 이름, OTLP 프로토콜·대상, 샘플링 지점을 구분해 설정하도록 돕는다. SDK 자동 계측 후 빠진 업무 구간만 직접 span으로 보완하는 편이 좋다.

- 예시: “Node API에서 요청 한 건의 trace가 스테이징 수집기까지 이어지는지 확인할 계획을 만들어줘. 본문과 자격증명은 수집하지 마.”
- 태그: OTLP, SDK, traces
- 출처: [공식 SKILL.md](https://github.com/grafana/skills/blob/main/skills/grafana-core/opentelemetry/SKILL.md) · 난이도 중급

## 2. alloy

앱을 계측하는 대신 이미 나온 데이터를 받거나 긁어 모아 목적지로 전달한다. 수신기와 내보내기 구성의 연결, 전송 전 가공, 구성 파일 검증을 한 흐름으로 다룬다. 검증 명령이 성공해도 수집 대상 연결이나 실제 전송까지 입증되지는 않는다.

- 예시: “스테이징용 모의 OTLP 입력에서 로그와 트레이스를 분리하는 Alloy 구성 초안을 써줘. 민감 필드 제거와 로컬 검증만 포함해줘.”
- 태그: collector, OTLP, relabeling
- 출처: [공식 SKILL.md](https://github.com/grafana/skills/blob/main/skills/grafana-core/alloy/SKILL.md) · 난이도 중급

## 3. beyla

eBPF 계측으로 지원 환경에서 코드 수정 없이 HTTP·gRPC 등의 관측 신호를 확보하는 방법을 다룬다. 코드 변경이 어려울 때 후보지만 커널·런타임·권한이 맞아야 하고, 업무 단계는 앱의 직접 계측이 더 적합할 수 있다. 운영 호스트에 광범위한 권한을 부여하기 전에 전용 테스트 환경에서 지원 조건을 확인한다.

- 예시: “운영 설정을 손대지 말고, 테스트 호스트가 Beyla를 쓸 수 있는지 확인 항목만 정리해줘. 필요한 권한과 SDK 대안을 구분해줘.”
- 태그: eBPF, Linux, auto-instrumentation
- 출처: [공식 SKILL.md](https://github.com/grafana/skills/blob/main/skills/grafana-core/beyla/SKILL.md) · 난이도 중상급

## 4. dashboarding

패널·변수·단위·집계 결과를 대시보드 JSON에서 맞추고, 배치와 데이터 소스가 의도대로 연결됐는지 검토하는 스킬이다. 적용을 요청받은 경우 저장 응답만 보지 말고 UID로 재조회해 실제 상태를 확인하는 절차가 있다.

- 예시: “기존 요청 지표로 스테이징 대시보드 초안을 만들어줘. 요청 수·오류율·p95 지연을 나란히 보여 주고 JSON만 생성해줘.”
- 태그: dashboard, panels, variables
- 출처: [공식 SKILL.md](https://github.com/grafana/skills/blob/main/skills/grafana-core/dashboarding/SKILL.md) · 난이도 초중급

## 5. alerting-irm

경보 규칙은 언제 발화할지, 알림 정책은 누가 받을지를 정한다. 오류율의 지속 조건부터 라벨 매칭, 음소거, 증상별 전달 경로까지 나눠 점검한다. Grafana의 Alerting과 온콜·인시던트 관리 기능 여부는 설치 환경을 확인해야 한다.

- 예시: “테스트 환경 오류율 경보 초안을 써줘. 오류율 분모가 작을 때와 데이터가 없을 때를 구분하고 실제 알림은 보내지 마.”
- 태그: alerts, SLO, notification routing
- 출처: [공식 SKILL.md](https://github.com/grafana/skills/blob/main/skills/grafana-core/alerting-irm/SKILL.md) · 난이도 중상급

## 설치와 사용

[Grafana 공식 설치 가이드](https://github.com/grafana/skills/blob/main/README.md)는 `npx skills add grafana/skills`를 안내한다. 모든 스킬이 필요하지 않다면 `--skill dashboarding`처럼 하나를 고를 수 있다. 스킬 설치는 에이전트에 지침을 추가하는 것이지 Grafana 서비스나 데이터 수집기를 배포하는 것이 아니다. 오늘 확인한 다섯 스킬의 원본 파일은 Apache-2.0을 표기한다. 운영 자격증명 없이 설정·대시보드 초안부터 만든 뒤, 필요한 경우에만 승인된 스테이징 환경에서 검증한다.

## 오늘의 Top Pick: alloy

지표와 로그는 들어오는데 트레이스만 사라질 때, 앱 코드부터 건드리기 전에 수집기의 입력·가공·전달 경계를 나눠 보는 게 유용하다. Alloy 스킬은 그 경계를 따라 설정을 읽고 검증하게 해 준다.

## Codex에서 바로 써볼 만한 것: dashboarding

기존 서비스에 어떤 지표와 단위가 있는지 먼저 대조한 뒤, 외부 시스템에 접속하지 않고도 검토 가능한 JSON 초안을 만들 수 있다.

## 관찰 메모

계측 도구를 켜는 것, 데이터를 전달하는 것, 화면을 만드는 것, 사람에게 알리는 것은 다른 작업이다. 각 단계의 검증을 분리하면 대시보드가 비어 있거나 알림이 오지 않을 때 원인 범위를 좁힐 수 있다. 공식 스킬과 설치 문서만 검토했으며 실제 설치·전송·배포·알림은 실행하지 않았다.
