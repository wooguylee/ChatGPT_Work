## 1. elasticsearch-index-design

본문 검색과 정확 일치, 집계, 정렬에 필요한 필드를 먼저 나눈다. 문서 제목을 검색과 정렬에 모두 쓴다면 검색용 `text`에 정렬용 `keyword` 하위 필드를 검토한다.

- 예시: “샘플 OCR 문서에서 본문 검색, 사건번호 정확 일치, 접수일 정렬에 쓸 매핑을 설계해줘. 운영 인덱스는 수정하지 마.”
- 태그: 매핑, OCR, 검색 설계
- 출처: [공식 SKILL.md](https://github.com/elastic/agent-skills/blob/main/skills/elasticsearch/elasticsearch-index-design/SKILL.md)

## 2. elasticsearch-search-relevance

특정 질의에 고정해야 하는 결과와 일반적인 품질 개선을 구분한다. 전자는 쿼리 규칙, 후자는 필드 가중치와 매칭 조건을 검토한다. 벡터·하이브리드 검색은 이 스킬 범위가 아니다.

- 예시: “문서 검색 질의 10개로 제목·본문 가중치 후보를 비교하고 상위 5개 결과의 평가 기준도 써줘.”
- 태그: 검색 평가, Query DSL, 관련도
- 출처: [공식 SKILL.md](https://github.com/elastic/agent-skills/blob/main/skills/elasticsearch/elasticsearch-search-relevance/SKILL.md)

## 3. elasticsearch-query-optimization

프로파일에서 비용이 큰 절을 찾아 수정 후보를 정하고 같은 조건에서 다시 측정한다. 정확 일치 조건을 필터로 옮길 때도 결과 집합과 순위가 달라졌는지 확인한다.

- 예시: “익명화한 프로파일과 매핑을 보고 가장 비싼 구절 하나를 찾아줘. 수정 전후 결과와 지연을 비교하는 계획도 적어줘.”
- 태그: 지연, 프로파일링, Query DSL
- 출처: [공식 SKILL.md](https://github.com/elastic/agent-skills/blob/main/skills/elasticsearch/elasticsearch-query-optimization/SKILL.md)

## 4. elasticsearch-cluster-health

노란색에서는 복제본, 빨간색에서는 기본 샤드의 미할당이 핵심이다. 직전에 노드가 떠났다는 사실과 현재 할당을 막는 원인을 구분한다. 자체 운영과 Elastic Cloud Hosted 대상이며 Serverless에는 해당하지 않는다.

- 예시: “내가 준 상태와 할당 설명으로 영향 범위와 가장 유력한 원인을 좁혀줘. 복구는 실행하지 마.”
- 태그: 장애 진단, 샤드, 읽기 전용
- 출처: [공식 SKILL.md](https://github.com/elastic/agent-skills/blob/main/skills/elasticsearch/elasticsearch-cluster-health/SKILL.md)

## 5. elasticsearch-anomaly-detection-explainer

초기 점수와 현재 점수를 나누고, 실제값·평소값·탐지 함수와 함께 본다. 나중에 더 큰 이상이 나타나 상대 점수가 재조정되는 현상과 탐지 작업의 생성·중단은 별개다.

- 예시: “샘플 이상 탐지 레코드에서 점수가 바뀐 이유와 증가·감소 중 어느 쪽이 탐지됐는지 설명해줘. 값이 없으면 추정하지 마.”
- 태그: 이상 탐지, 관측성, 결과 해석
- 출처: [공식 SKILL.md](https://github.com/elastic/agent-skills/blob/main/skills/elasticsearch/elasticsearch-anomaly-detection-explainer/SKILL.md)

## 설치와 사용

[공식 저장소](https://github.com/elastic/agent-skills)와 [Elastic 설치 문서](https://www.elastic.co/docs/explore-analyze/ai-features/agent-skills)를 확인했다. 예: `npx skills add elastic/agent-skills --skill elasticsearch-index-design`. 스킬 설치와 서비스 연결은 별개다. 원문은 실제 클러스터 작업에 `elastic` CLI를 사용한다. 이상 탐지 설정을 읽으려면 기능 지원과 `monitor_ml` 권한을 확인한다. 샘플 데이터 검토부터 시작한다면 실행 계정이나 클러스터 연결을 제공할 필요는 없다.

## 오늘의 Top Pick: elasticsearch-index-design

OCR 문서를 검색하는 화면이라면 사건번호와 본문은 요구 조건부터 다르다. 샘플 문서와 필드별 사용 방식을 같이 주면 인덱스를 만들기 전에 매핑을 검토할 수 있다.

## Codex에서 바로 써볼 만한 것: elasticsearch-query-optimization

익명화한 느린 쿼리, 매핑, 프로파일을 주고 변경 후보 한 가지와 재측정 기준을 요청한다. 운영 쿼리를 실행하지 않고도 비교 계획을 마련할 수 있다.

## 관찰 메모

공식 저장소는 Apache-2.0을 표시한다. 이미 소개한 `elasticsearch-esql`은 집계·로그 분석 경로이며 신규 항목에서 제외했다. 스킬 원문과 설치 안내를 검토했으며 실제 설치, 클러스터 연결, 쿼리 테스트 또는 운영 변경은 하지 않았다.
