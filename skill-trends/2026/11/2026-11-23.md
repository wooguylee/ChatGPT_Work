## 1. turnstile-spin

프런트엔드 위젯과 백엔드 Siteverify 검증이 모두 있어야 한다. 기존 위젯의 연결을 고치는 경우와 새 위젯을 만드는 경우를 구분한다.

- 예시: “샘플 React 신청 폼과 Koa 핸들러를 읽고 검증 실패 시 저장이 차단되는지 확인할 테스트를 써줘. 배포하거나 실제 토큰을 기록하지 마.”
- 태그: 폼, 입력 검증, 방어
- 출처: [공식 SKILL.md](https://github.com/cloudflare/skills/blob/main/skills/turnstile-spin/SKILL.md)

## 2. cloudflare-email-service

서비스가 보내는 거래성 메일과 들어온 메일의 전달은 다른 경로다. 코드 수정 전에 도메인의 발신 설정과 Worker 바인딩을 확인한다.

- 예시: “테스트 접수 확인 메일과 수신 전달의 설정 항목을 별도로 정리해줘. DNS를 바꾸거나 메일을 보내지 마.”
- 태그: 이메일, Workers, 전달
- 출처: [공식 SKILL.md](https://github.com/cloudflare/skills/blob/main/skills/cloudflare-email-service/SKILL.md)

## 3. basin

이벤트의 수신·변환, R2의 Iceberg 테이블 관리, 분석 SQL을 각각 Pipelines, Catalog, SQL로 나눈다. 예전 Data Platform 이름이 일부 API나 권한 표기에 남아 있을 수 있다.

- 예시: “합성 OCR 로그의 종류별 오류 건수를 집계할 데이터 흐름을 설계해줘. 테이블이나 비용 발생 리소스는 만들지 마.”
- 태그: R2, Iceberg, SQL
- 출처: [공식 SKILL.md](https://github.com/cloudflare/skills/blob/main/skills/basin/SKILL.md)

## 4. k2

보존 기간이 있는 이벤트 로그를 여러 구독자가 독립적으로 소비한다. 단순 비동기 작업 대기열과 목적이 다르다. 공식 문서는 Workers Paid 공개 베타로 안내한다.

- 예시: “가짜 접수 이벤트를 통계와 검수 시스템이 독립적으로 읽는 설계를 그려줘. 중복 처리 방지와 보존 기간을 검토하고 스트림은 만들지 마.”
- 태그: 이벤트 로그, 구독, 베타
- 출처: [공식 SKILL.md](https://github.com/cloudflare/skills/blob/main/skills/k2/SKILL.md)

## 5. sandbox-stable

기존 Worker가 쓰는 SDK 버전과 컨테이너 이미지 계열을 맞춘다. 안정판의 명령 완료 응답과 프리뷰의 프로세스 핸들을 같은 API로 다루지 않는다.

- 예시: “테스트 저장소의 패키지와 이미지 태그를 비교해 호환성만 확인해줘. 프리뷰로 이전하거나 명령을 실행하지 마.”
- 태그: 런타임, 컨테이너, 호환성
- 출처: [공식 SKILL.md](https://github.com/cloudflare/skills/blob/main/skills/sandbox-stable/SKILL.md)

## 설치와 사용

[공식 스킬 저장소](https://github.com/cloudflare/skills#installing)는 Codex용 플러그인 설치와 스킬만 사용하는 설치를 구분한다. 플러그인은 Cloudflare MCP도 함께 제공한다. 문서 검토만 하는 단계에서는 계정 연결이 필요하지 않다. 실제 적용 전에는 [Turnstile 서버 검증](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)과 [K2 이용 조건](https://developers.cloudflare.com/k2/)처럼 해당 제품의 최신 문서를 원문과 대조한다.

## 오늘의 Top Pick: turnstile-spin

신청 화면에 위젯이 보이는지보다 서버가 검증 실패 시 접수를 거절하는지가 중요하다. UI와 API를 나눠 점검하면 정상 화면을 보고 검증까지 끝났다고 착각하지 않는다.

## Codex에서 바로 써볼 만한 것: sandbox-stable

기존 프로젝트의 의존성 파일과 이미지 태그만 읽고 안정판과 프리뷰를 혼용하는지 확인한다. 패키지를 업데이트하지 않고도 문제 범위를 좁힐 수 있다.

## 관찰 메모

11월 17일에 소개한 Cloudflare CLI·개발 도구는 제외했다. Sandbox 프리뷰를 별도 항목으로 중복 소개하지 않았다. 원문과 제품 문서를 확인했으며 실제 설치, 인증, 메일 전송, 위젯 생성, 서비스 생성 또는 배포는 하지 않았다.
