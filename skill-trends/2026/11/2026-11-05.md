## 1. attach-db

**반복 분석에 필요한 연결 상태를 복원하기.**

- 원본: [SKILL.md](https://github.com/duckdb/duckdb-skills/blob/7feda8e01e22bc0886c86123f3884947e36d8c69/skills/attach-db/SKILL.md)
- 태그: `duckdb`, `schema-discovery`, `session-state`, `read-only`
- 난이도: 중급

### 무엇을 해주나

로컬 DuckDB 파일을 연결하고 테이블·열·행 수를 조사한 뒤, 다음 질의에서 연결을 복원할 SQL을 남긴다. 최대 20개 테이블의 구조와 행 수를 살피고 프로젝트별 state.sql에 ATTACH·USE를 추가하는 방식이다. 같은 자료를 여러 차례 분석할 때 연결을 매번 다시 설명하는 수고를 줄인다.

### 적용 전에 확인할 점

1. 원본 ATTACH에는 **READ_ONLY가 없다**. 조회용 사용이라면 [공식 ATTACH 문서](https://duckdb.org/docs/2.0/sql/statements/attach)를 따라 연결 모드를 명확히 한다. 존재하지 않는 경로를 새 DB 생성으로 자동 전환하지 않는다.
2. state.sql은 단순 메모가 아니라 [CLI의 -init](https://duckdb.org/docs/2.0/clients/cli/arguments)으로 **실행되는 SQL**이다. 기존 LOAD·매크로·secret 정의도 검토해야 한다. 저장 위치와 변경 범위를 정하고 비밀값을 코드 저장소에 넣지 않는다.
3. 중복 검사 예시의 RESOLVED_PATH는 치환해야 하는 자리표시자다. 실제 절대 경로, SQL 인용, 파일명에서 만든 별칭의 충돌을 확인한다. 프로젝트·홈 상태 파일이 모두 있으면 예시 코드에서는 홈 경로가 나중에 선택된다.
4. 테이블명만 사용한 탐색은 서로 다른 스키마의 동명 테이블을 혼동할 수 있다. [duckdb_tables](https://duckdb.org/docs/2.0/sql/meta/duckdb_table_functions) 목록이 비었다고 뷰까지 없는 빈 DB라고 단정하지 않는다.

**실용 프롬프트:** “합성 sales DB의 스키마로 읽기 전용 연결 계획을 만들어줘. 경로·별칭·스키마 이름을 명시하고 기존 state.sql을 실행하지 않은 상태에서 검토할 항목을 정리해. 실제 DB 생성·상태 파일 변경·확장 설치는 하지 마.”

**완료 기준:** 정확한 파일과 스키마가 선택되고, 상태 파일의 승인된 변경만 반영되어야 한다. 연결 성공을 데이터 품질 검증 완료로 표현하지 않는다.

## 2. query

**자연어 분석 질문을 재검토 가능한 SQL로 바꾸기.**

- 원본: [SKILL.md](https://github.com/duckdb/duckdb-skills/blob/7feda8e01e22bc0886c86123f3884947e36d8c69/skills/query/SKILL.md)
- 태그: `natural-language-sql`, `parquet`, `aggregation`, `resource-limits`
- 난이도: 중급

### 무엇을 해주나

SQL 또는 자연어 질문으로 연결된 DB와 CSV·Parquet 파일을 분석한다. 세션 모드에서는 스키마를 참고하고, 파일 경로나 --file이 있으면 메모리 DB를 쓰는 일회성 모드를 고른다. GROUP BY ALL, 열 제외·치환, 이름 기준 결합 등 DuckDB 문법을 활용해 반복 집계 질문을 짧은 SQL로 표현하도록 돕는다.

### 제한 설정과 실제 읽기 전용은 다르다

일회성 예시는 allowed_paths, 외부 접근 제한, 영구 secret 금지, 설정 잠금을 사용한다. 그러나 [공식 보안 문서](https://duckdb.org/docs/2.0/operations_manual/securing_duckdb/overview)는 이런 설정이 OS·컨테이너 격리를 대신하지 않는다고 설명한다. 허용 경로의 읽기와 쓰기를 구분하는 장치도 아니다. 원본 세션 모드에는 같은 제한이 없으며, 모드를 고르기 전 state.sql 검증 명령부터 실행한다. “파일 하나를 조회하니 기존 초기화 SQL은 실행되지 않는다”는 가정은 틀릴 수 있다.

[duckdb_tables의 estimated_size](https://duckdb.org/docs/2.0/sql/meta/duckdb_table_functions)는 **추정 행 수**다. 바이트 수가 아니므로 이 값으로 원문의 10GB 경고를 판단할 수 없다. LIMIT·집계는 출력량을 줄일 수 있어도 스캔 비용을 보장하지 않으며, 그룹 수가 많으면 집계 결과도 크다. 100행 초과 안내만으로 SQL에 실제 행 제한이 생기지는 않는다.

오류 처리 흐름에는 확장 설치와 문서 검색이 들어 있다. 읽기 요청을 새 소프트웨어 설치나 접근 범위 확대의 자동 허가로 취급하지 않는다. 재시도 전에 입력·SQL·권한 중 무엇이 바뀌는지도 확인한다.

**실용 프롬프트:** “합성 Parquet 스키마로 월별 확정 매출 SQL과 예상 결과를 작성해줘. 취소·NULL·중복을 처리하는 기준을 명시하고 출력은 100행 이하로 설계해. 기존 state.sql 실행, 네트워크, 파일 변경 없이 계획만 검토해.”

**완료 기준:** 질문의 기간·집계 정의와 SQL이 일치하고 표본 기대값과 결과를 대조해야 한다. 실행한 SQL·실제 출력 제한·누락 조건을 남기며 자연어로 그럴듯한 설명만 붙여 완료로 판단하지 않는다.

## 3. read-file

**파일을 열기 전에 구조부터 파악하기.**

- 원본: [SKILL.md](https://github.com/duckdb/duckdb-skills/blob/7feda8e01e22bc0886c86123f3884947e36d8c69/skills/read-file/SKILL.md)
- 태그: `data-exploration`, `file-format`, `duckdb`, `input-validation`
- 난이도: 중급

### 무엇을 해주나

CSV·JSON·Parquet·Excel·공간 파일을 DuckDB로 읽어 열 이름과 자료형, 전체 행 수, 앞부분 20행을 확인하는 스킬이다. 파일 확장자로 리더를 고르는 read_any 매크로를 제공하므로, 받은 데이터가 어떤 구조인지 빠르게 설명받을 때 출발점이 된다. 다만 ‘어떤 파일이든’이라는 설명을 지원 보증으로 읽어서는 안 된다. 다음 네 가지를 확인해야 한다.

### 적용 전에 확인할 점

1. 실제 내용이 아니라 파일명 끝부분으로 분기한다. .csv.gz나 쿼리 문자열이 붙은 URL은 표의 분기에 맞지 않아 blob 경로로 갈 수 있다. GeoJSON도 공간 리더가 아닌 JSON 리더로 보낸다.
2. .xls를 read_xlsx로 연결하는 예시는 공식 Excel 문서의 ‘.xls 미지원’과 충돌한다. .xlsx는 excel 확장이 필요하며 시트·헤더·추론 자료형을 확인해야 한다.
3. S3 credential_chain은 기존 프로필·역할 등의 자격 증명을 찾는 기능이다. 단순 파일 미리보기를 원격 계정 사용이나 확장 자동 설치의 포괄적 허가로 취급하지 말아야 한다.
4. 20행 제한은 표본 출력에만 적용된다. 별도의 count(*)는 전체 소스 작업이 될 수 있고, 표본만으로 결측·중복·분포를 단정할 수도 없다.

**실용 프롬프트:** “이 로컬 CSV 하나만 검사해 줘. 먼저 경로·크기·실제 형식과 필요한 확장을 알려 주고, 설치나 원격 접근 없이 스키마와 최대 20행만 확인해 줘. 전체 행 수 계산이 큰 스캔이면 먼저 물어보고, 민감한 열은 출력하지 마.”

**완료 기준:** 선택한 리더·시트·스키마가 실제 파일과 맞아야 한다. 표본 20행의 관찰과 전체 데이터의 품질 판정은 구분한다.

공식 근거: [Excel 지원 범위·자동 로드·시트 옵션](https://duckdb.org/docs/2.0/core_extensions/excel), [S3 자격 증명 체인](https://duckdb.org/docs/2.0/core_extensions/httpfs/s3api).

## 4. convert-file

**변환 전에 출력 경로를 보호하기.**

- 원본: [SKILL.md](https://github.com/duckdb/duckdb-skills/blob/7feda8e01e22bc0886c86123f3884947e36d8c69/skills/convert-file/SKILL.md)
- 태그: `conversion`, `parquet`, `copy`, `data-preservation`
- 난이도: 중급

### 무엇을 해주나

입력 파일을 CSV·Parquet·JSON·XLSX·GeoJSON 등으로 내보내는 작업을 DuckDB COPY 문으로 정리한 스킬이다. 출력 이름이 없으면 입력 확장자를 .parquet로 바꾸고(data.csv → data.parquet), JSON 배열과 줄 단위 JSON을 구분하며, 필요에 따라 압축이나 파티션 옵션도 제안한다. 반복되는 데이터 전달 형식 변환에 유용하지만, 원본 보존과 변환 후 검증은 사용자가 명시해야 한다.

### 적용 전에 확인할 점

1. COPY TO는 기존 단일 출력 파일을 오류 없이 덮어쓸 수 있다. 임시 파일 사용은 중단 시 손상을 줄일 뿐, 덮어쓰기를 막지 않는다. 입력이 이미 Parquet라면 기본 출력이 입력과 같아질 수 있으므로 두 경로가 다른지 먼저 확인해야 한다.
2. 확장자를 보고 정하는 출력 형식과 입력 리더의 실제 지원 범위는 별개다. 명시적인 FORMAT과 read_* 함수가 필요한지 점검하고, Excel·GDAL 출력을 위해 필요한 확장도 구분해야 한다.
3. 이름만 주면 find 결과 첫 파일을 고르는 예시는 동명 파일을 잘못 선택할 수 있다. 확정된 전체 경로를 사용하고 SQL·셸 인용도 안전하게 처리해야 한다.
4. 파일 크기와 ‘성공’ 메시지만으로 무손실 변환을 보장할 수 없다. 행 수, 자료형, 날짜·소수·NULL, 중첩 열의 표현을 다시 읽어 대조하고, 파티션 출력은 단일 파일과 다른 덮어쓰기 규칙으로 검토한다.

**실용 프롬프트:** “확정한 input.csv를 새 output_20261105.parquet로 변환하는 계획부터 보여 줘. 원본 수정과 기존 파일 덮어쓰기는 금지하고, 필요한 확장 설치는 먼저 물어봐. 실행이 허용되면 명시적 형식을 사용하고 결과를 다시 읽어 행 수·스키마 차이를 보고해 줘.”

**완료 기준:** 승인된 새 출력 파일을 다시 읽어 행 수·스키마·중요 값의 보존을 확인한다. 원본과 기존 출력의 변경 여부도 확인한다.

공식 근거: [COPY 덮어쓰기·동일 경로 경고·형식 옵션](https://duckdb.org/docs/2.0/sql/statements/copy), [Excel 확장](https://duckdb.org/docs/2.0/core_extensions/excel).

- 난이도: 중상급

### 무엇을 해주나

거리 계산, 점과 구역의 포함 관계, 주변 장소 탐색, 공간 파일 변환을 DuckDB spatial 확장으로 수행하도록 안내한다. 사용자 파일이 없으면 Overture Maps의 공개 S3 데이터를 제안하고, 먼저 bbox로 범위를 좁힌 뒤 공간 함수를 적용한다. 공간 분석을 일반 데이터 분석과 연결하는 출발점이지만, 원문에 명확한 함수 자료형 오류가 있어 그대로 실행하는 추천은 보류한다.

### 적용 전에 확인할 점

1. 좌표계와 축 순서는 별개다. 경위도에 평면 ST_Distance를 적용한 값을 미터로 해석하면 안 된다. CRS/SRID, 단위, geometry_always_xy 설정과 DuckDB 버전을 먼저 확인하고 필요한 좌표 변환을 설계해야 한다.
2. 원문의 ‘모든 spheroid 함수는 POINT_2D 전용’ 설명은 잘못됐다. 공식 서명에서 거리 함수는 POINT_2D를 받지만 면적 함수는 GEOMETRY·POLYGON_2D, 길이 함수는 GEOMETRY·LINESTRING_2D를 받는다. 폴리곤을 점으로 재구성하는 처방을 일반화해서는 안 된다.
3. bbox는 후보를 줄이는 필터이지 정확한 도시 경계나 반경 판정이 아니다. 특히 예시의 건물 수 집계는 경계 폴리곤 검사 없이 사각 범위만 쓰므로 ‘도시 전체 건물 수’로 발표하면 안 된다.
4. Overture 예시는 2026-03-18 릴리스를 고정 사용한다. 최신성이 필요하면 카탈로그를 다시 확인하고 공개 원격 조회·다운로드량·H3 커뮤니티 확장 설치를 별도 범위로 정한다.

**실용 프롬프트:** “내 로컬 점·구역 파일만 대상으로 분석 SQL을 검토해 줘. 먼저 버전·CRS·축 순서·단위를 확인하고, 경계 위 점 처리와 함수 입력 자료형을 설명해 줘. 원격 조회·설치·파일 쓰기는 하지 말고, 아직 실행 검증하지 않은 부분을 표시해 줘.”

**완료 기준:** 좌표계·단위·경계 조건·함수 자료형이 맞고 알려진 표본의 결과와 일치해야 한다. 지도에 점이 표시된다는 사실만으로 거리·포함 관계의 정확성을 판단하지 않는다.

공식 근거: [고정 함수 참조](https://github.com/duckdb/duckdb-skills/blob/7feda8e01e22bc0886c86123f3884947e36d8c69/skills/spatial/references/functions.md), [고정 Overture 참조](https://github.com/duckdb/duckdb-skills/blob/7feda8e01e22bc0886c86123f3884947e36d8c69/skills/spatial/references/overture.md), [공식 함수 서명](https://duckdb.org/docs/2.0/core_extensions/spatial/functions), [축 순서 변경·CRS 도입 설명](https://duckdb.org/2026/03/09/announcing-duckdb-150).

## 6. duckdb-docs

**설치된 엔진에 맞는 문서를 검색하고 근거를 남기기.**

- 원본: [SKILL.md](https://github.com/duckdb/duckdb-skills/blob/7feda8e01e22bc0886c86123f3884947e36d8c69/skills/duckdb-docs/SKILL.md)
- 태그: `documentation`, `bm25`, `ducklake`, `version-awareness`
- 난이도: 중급

### 무엇을 해주나

DuckDB·DuckLake 문서 검색 인덱스를 로컬에 복사하고 [FTS의 BM25](https://duckdb.org/docs/2.0/core_extensions/full_text_search)로 관련 문서 조각을 찾는다. 자연어에서 기술 용어를 추리고 최대 8개 결과와 출처를 바탕으로 답변한다. 오류 메시지나 함수 사용법을 모델의 기억에만 의존하지 않고 확인하는 데 적합하다.

README는 원격 HTTPS 질의를 기본으로 설명하지만, 고정한 SKILL.md의 실제 절차는 **로컬 캐시를 준비해 검색하는 방식**이다. httpfs·fts 설치, 캐시 디렉터리 생성, 원격 DB 복사·교체 단계가 포함된다. 준비되지 않은 환경에서 순수 읽기·완전 오프라인 도구라고 설명하면 안 된다. 캐시가 있어도 확장 설치 단계는 먼저 등장한다.

### 버전과 신선도 확인

- 원문은 DuckDB 문서 기본 필터를 lts, DuckLake는 stable로 지정한다. 그런데 DuckDB 문서와 블로그를 함께 검색하는 예시에는 stable이 들어 있다. 같은 원문 안의 불일치이므로 실제 인덱스의 version 값과 설치 엔진 버전을 확인해야 한다.
- 캐시 신선도는 로컬 파일 수정 시각을 정수 일수로 계산한다. “2일 이하”는 정확한 48시간 제한도, 원격 문서와 동기화되었다는 증거도 아니다.
- 검색어를 SQL 문자열에 직접 치환하는 예시는 따옴표 처리에 주의한다. [원격 READ_ONLY 연결](https://duckdb.org/docs/2.0/sql/statements/attach)과 로컬 캐시 생성·교체는 서로 다른 동작이다.
- 검색 결과가 없으면 용어·버전 필터를 바꿔 확인한다. 상위 8개 조각이 전체 문서 검토를 대신하지 않으며, 인덱스 내부 값·검색 정확도는 이번 조사에서 실행 확인하지 않았다.

**실용 프롬프트:** “현재 설치 버전에 맞는 arg_max 사용법의 조사 계획을 만들어줘. 캐시·문서 버전을 확인하는 단계와 설치·다운로드·파일 교체 단계를 구분해. 공식 출처를 표시하고 실제 검색이나 실행을 하지 않았다면 그렇게 밝혀줘.”

**완료 기준:** 인용한 문서 버전·링크와 답변의 함수 동작이 맞아야 한다. 캐시 생성 성공을 최신 문서의 완전한 검색이나 SQL 실행 성공으로 표현하지 않는다.

## 적용 순서와 설치 안내

**원본 읽기 → 대상·버전·권한 확정 → 합성 자료로 SQL 검토 → 승인된 좁은 범위 실행 → 실제 결과 재조회** 순서가 좋다. 이번 보고서는 문서 정적 검토이며 DuckDB 설치·확장 로드·SQL 실행·원격 데이터 조회·파일 변환·캐시 다운로드를 수행하지 않았다.

[공식 설치 안내](https://github.com/duckdb/duckdb-skills/blob/7feda8e01e22bc0886c86123f3884947e36d8c69/README.md)는 Claude Code에서 marketplace에 저장소를 추가하고 duckdb-skills plugin을 설치하는 방식이다. 당시 README의 Discover 등록은 예정으로 표시되어 있다. 설치는 여섯 파일만이 아니라 전체 묶음이며, 오늘 선정하지 않은 read-memories·install-duckdb·s3-explore도 포함한다. 대화 기록 접근이나 추가 기능 실행까지 함께 허용된 것으로 해석하지 않는다.

[install-duckdb 원문](https://github.com/duckdb/duckdb-skills/blob/7feda8e01e22bc0886c86123f3884947e36d8c69/skills/install-duckdb/SKILL.md)은 CLI가 없을 때 설치 방법을 안내하고 중단한다. 다른 Skill의 위임 문구만으로 자동 설치·오류 복구가 보장된다고 볼 수 없다. 필요한 CLI·확장·계정 접근을 따로 검토한다.

README의 공유 state.sql 설명도 개별 원문과 구분한다. attach-db·query에는 상태 파일 기록·실행이 있지만, 오늘 확인한 read-file·convert-file·spatial 원문에는 state.sql 단계가 없다. read-file·convert-file의 CREATE SECRET은 [기본 임시 secret](https://duckdb.org/docs/2.0/configuration/secrets_manager)이며 PERSISTENT를 지정하지 않으므로 그 예시만으로 자격 증명을 디스크에 영구 저장한다고 단정하지 않는다. 다만 기존 credential_chain이 어떤 계정·역할을 선택하는지는 확인해야 한다.

state.sql 단계가 없어도 [CLI 초기화 규칙](https://duckdb.org/docs/2.0/clients/cli/arguments)에 따라 기본 ~/.duckdbrc가 -c SQL보다 먼저 실행될 수 있다. 질의 안의 제한 설정만으로 초기화 동작까지 차단되지는 않는다. 설치 버전의 -no-init 지원 여부를 확인하고 초기화 파일도 검토한다.

### 🏆 오늘의 Top Pick

**query**: 별도 데이터 적재 없이 파일 집계와 자연어 질문을 연결하는 활용 폭이 크다. SQL을 먼저 검토하고 초기화 파일·출력 한도·실제 실행 격리를 명확히 하면 편의성과 재현성을 함께 얻기 좋다. 원문에 “sandboxed”라고 적혀 있다는 이유만으로 안전을 보증하지 않는다.

### ⚡ Codex에서 바로 써볼 만한 것

**convert-file의 합성 변환 검증 계획**: CSV의 NULL·날짜·소수·중첩 값이 Parquet 등 다른 형식으로 옮겨질 때 기대 스키마와 행 수를 비교하는 테스트를 설계하기 좋다. 기존 파일 덮어쓰기 없이 요청·검증 계약부터 만들 수 있다. Claude Code 전용 명령이 Codex에서 그대로 동작한다고 주장하는 추천은 아니다.
