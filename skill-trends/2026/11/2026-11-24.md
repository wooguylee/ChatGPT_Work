## 1. expo-web-to-native

Vite나 Next.js의 React 앱을 한 번에 변환하는 도구가 아니다. 먼저 모바일 앱의 틀을 만들고, 실제 사용 비중에 따라 화면을 옮기는 순서를 정한다.

- 예시: “기존 Vite 앱의 검색·상세·설정 화면을 나눠 모바일 이전 순서와 실기기 검증 항목을 제안해줘. 파일은 수정하지 마.”
- 태그: 마이그레이션, React, 모바일
- 출처: [공식 SKILL.md](https://github.com/expo/skills/blob/main/plugins/expo/skills/expo-web-to-native/SKILL.md)

## 2. expo-dom

웹용 차트나 편집기처럼 DOM에 의존하는 UI를 네이티브 앱의 WebView에서 실행한다. 앱 전체 이전을 계획하는 스킬과 달리 컴포넌트 경계, 전달할 값, 스크롤을 다룬다.

- 예시: “합성 데이터로 동작하는 Recharts 화면 하나만 옮길 때 데이터 전달과 중첩 스크롤을 확인할 항목을 써줘.”
- 태그: WebView, 차트, 점진적 이전
- 출처: [공식 SKILL.md](https://github.com/expo/skills/blob/main/plugins/expo/skills/expo-dom/SKILL.md)

## 3. expo-design-system

이미 있는 테마와 스타일 라이브러리를 먼저 찾고, 화면별 하드코딩으로 어긋난 값을 구분한다. 새 테마를 하나 더 얹는 대신 기존 토큰과 재사용 컴포넌트를 확장한다.

- 예시: “샘플 화면 세 개의 색상과 간격을 기존 테마와 대조해줘. 중복값을 표로 정리하고 코드 변경은 하지 마.”
- 태그: 디자인 토큰, UI, 읽기 전용 검토
- 출처: [공식 SKILL.md](https://github.com/expo/skills/blob/main/plugins/expo/skills/expo-design-system/SKILL.md)

## 4. expo-module

Expo Modules API에서 함수·이벤트·뷰를 TypeScript에 연결하는 흐름을 다룬다. 한 앱에 둘 로컬 모듈과 여러 앱에서 쓸 독립 패키지를 구분한다.

- 예시: “가짜 센서값을 반환하는 Android 전용 로컬 모듈의 TypeScript 인터페이스와 테스트 계획을 써줘. 새 권한은 추가하지 마.”
- 태그: Kotlin, Swift, 네이티브 모듈
- 출처: [공식 SKILL.md](https://github.com/expo/skills/blob/main/plugins/expo/skills/expo-module/SKILL.md)

## 5. expo-brownfield

웹 앱 이전이 아니라 이미 SwiftUI·UIKit이나 Kotlin으로 운영되는 앱에 기능을 하나씩 넣는 경로다. 기존 탐색 구조를 유지하고 별도 라이브러리 배포와 통합 빌드를 비교한다.

- 예시: “기존 Kotlin 테스트 앱에 React Native 설정 화면 하나를 넣는다고 가정하고 AAR과 Gradle 통합의 빌드 책임을 비교해줘.”
- 태그: Android, iOS, 기존 앱 통합
- 출처: [공식 SKILL.md](https://github.com/expo/skills/blob/main/plugins/expo/skills/expo-brownfield/SKILL.md)

## 설치와 사용

[Expo 공식 저장소](https://github.com/expo/skills#installation)는 Codex 플러그인 설치 `codex plugin add expo@openai-curated`와 별도의 스킬 설치를 안내한다. 플러그인에는 Expo MCP 설정도 포함된다. 코드를 읽어 이전 범위나 테스트 항목을 정하는 데 실제 앱 배포나 EAS 연결은 필요하지 않다.

## 오늘의 Top Pick: expo-web-to-native

기존 React 앱이 있다면 먼저 화면 목록을 쓰고 모바일에서 자주 쓰는 흐름을 고른다. 한 화면을 실행해 입력·탐색·오류 처리까지 확인한 뒤 다음 화면을 옮기는 편이, 빌드 성공만 보고 전체를 이전하는 것보다 위험이 작다.

## Codex에서 바로 써볼 만한 것: expo-design-system

이미 테마가 있다면 화면 몇 개의 하드코딩 값을 읽어 기존 토큰과 대조한다. 분석과 실제 디자인 변경을 분리하기 좋다.
