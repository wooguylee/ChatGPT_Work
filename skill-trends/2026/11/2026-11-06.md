## 1. data-designer

**요구사항을 재사용 가능한 합성 데이터 설계로 바꾸기.**

**태그:** 합성 데이터, 데이터 엔지니어링, 평가 데이터 · **난이도:** 중급 · **라이선스:** Apache-2.0

[공식 스킬](https://github.com/NVIDIA/skills/blob/9f98b1b2735b5ff4fd30cb2a88c0f3c54babdf9e/skills/data-designer/SKILL.md)은 자연어로 설명한 데이터셋을 NeMo Data Designer의 Python 설정으로 바꾸고, 검증과 소량 미리보기를 거쳐 개선하는 작업 절차다. 단순히 LLM에 표를 요청하는 대신 범주 샘플링, 열 사이의 의존성, 구조화 출력, 검증 규칙을 조합한다. 결과물은 PEP 723 의존성 정보를 포함하고 load_config_builder()를 제공하는 스크립트다. 같은 설계를 반복 사용하거나 생성 규모를 바꾸기 좋다.

예를 들어 실제 고객 기록 없이 한국어 배송 문의를 만들 수 있다. 배송 단계, 문의 유형, 말투를 서로 다른 축으로 정의하고 문의문·정답·분류 라벨을 생성한다. 먼저 작은 표본에서 라벨 일관성과 표현 다양성을 확인한 뒤 평가용 데이터로 확장하는 방식이다. 등장인물이 필요하다면 가상 인물만 사용하고, 지역별 person 데이터가 없는 경우 Faker 대체값이 인구통계적으로 정확하지 않다는 점을 표시한다. 그럴듯한 데이터와 대표성 있는 데이터는 별개다.

**사용 전 확인:** Python 3.11 이상과 data-designer 패키지, 사용 가능한 모델 별칭이 필요하다. [공식 제품 문서](https://docs.nvidia.com/nemo/datadesigner/getting-started/welcome)는 기본 제공자 사용 시 API 키 설정을 안내한다. 따라서 카드의 자격증명 “미지정”을 “불필요”로 해석하면 안 된다. 제품 문서의 builder·sampler·validate·preview·create 예시는 스킬의 핵심 API와 맞는다. 다만 설치 버전의 스키마를 직접 확인하도록 설계되어 있고, 패키지 버전을 고정하지 않으므로 모든 버전의 호환성을 보장하지 않는다.

[대화형 절차](https://github.com/NVIDIA/skills/blob/9f98b1b2735b5ff4fd30cb2a88c0f3c54babdf9e/skills/data-designer/workflows/interactive.md)는 최종 대량 생성을 사용자에게 맡긴다. 반면 [Autopilot](https://github.com/NVIDIA/skills/blob/9f98b1b2735b5ff4fd30cb2a88c0f3c54babdf9e/skills/data-designer/workflows/autopilot.md)은 행 수가 지정되면 생성까지 진행할 수 있다. 비용과 외부 전송 범위를 먼저 정해야 하는 중요한 차이다. 실제 데이터를 seed로 자동 제안하지 않는 제한은 유용하지만, 사용자가 제공한 seed가 프롬프트에 들어갈 경우 별도의 개인정보 검토가 필요하다.

[벤치마크](https://github.com/NVIDIA/skills/blob/9f98b1b2735b5ff4fd30cb2a88c0f3c54babdf9e/skills/data-designer/BENCHMARK.md)는 2026-10-29, 긍정 과제 하나를 에이전트별 한 번 수행한 결과다. 총 토큰은 약 20.95% 줄었지만 작은 표본의 자체 평가이며 데이터 품질이나 실제 업무 비용 절감을 입증하지 않는다. 전체 점수의 비교 가능한 baseline도 없다. 추천 용도는 평가 데이터 초안과 반복 가능한 생성 설정이며, 합성이라는 이유만으로 개인정보 안전성이나 학습 효과를 보장해서는 안 된다.

**실용 프롬프트:** “실제 고객 데이터 없이 한국어 배송 문의 평가표의 스키마와 생성 계획만 작성해 줘. 라벨 일관성·중복·표현 다양성 검사를 포함하고 API 호출·패키지 설치·대량 생성은 하지 마.”

**완료 기준:** 요구한 열·의존성·검증 규칙이 설정과 일치하고, 승인된 미리보기에서 라벨과 문장을 대조해야 한다. 합성 표본만으로 실제 고객 분포를 대표한다고 주장하지 않는다.

## 2. accelerated-computing-cudf

**pandas를 GPU로 옮기되 결과까지 확인하기.**

**태그:** 데이터 엔지니어링 · pandas · cuDF · GPU ETL · Dask | **난이도:** 중급, 분산 처리는 고급

NVIDIA 공식 스킬로, pandas 기반 분석을 GPU로 옮길 때 어떤 경로를 선택하고 무엇을 검증해야 하는지 안내한다. 기존 코드를 적게 바꾸려면 cudf.pandas, 조인·집계·결측값 처리의 동작을 직접 관리하려면 명시적 cuDF, GPU 메모리보다 큰 작업이라면 dask-cuDF를 선택한다. 단순한 import 교체보다 CPU/GPU 결과 비교를 구현 과정에 포함한다는 점이 실용적이다. 데이터 엔지니어가 Parquet 읽기, 상품 코드 조인, 일별 매출 집계를 이전할 때 특히 잘 맞는다.

**필요 환경:** 지원되는 NVIDIA GPU와 드라이버, 선택한 릴리스에 맞는 Python·CUDA·cuDF·RMM이 필요하다. 분산 작업에는 Dask-CUDA와 distributed 클러스터도 필요하다. 스킬이 추적하는 26.12.00은 개발 버전이므로 그대로 운영 설치 버전으로 간주하면 안 된다. 설치된 버전과 지원표를 먼저 확인하고 CUDA 주 버전에 맞는 wheel을 선택해야 한다. 로컬 합성 데이터 실습에는 외부 계정이나 API 키가 필요하지 않다.

**합성 데이터 활용 예:** 가짜 주문 백만 행에 상품 ID, 시각, 금액, 일부 결측값을 넣고 작은 상품표와 조인한 뒤 날짜별 합계를 만든다. 먼저 작은 표본을 pandas 기준 결과와 비교하고, 대표 크기에서 실행 시간과 메모리를 측정한다. cudf.pandas는 pandas를 가져오기 전에 활성화하고, `python -m cudf.pandas --profile demo.py`로 CPU fallback을 확인한다. nullable 정수, 정렬 순서, 조인 행 수, 부동소수점 허용오차도 별도 검증한다.

**원문에서 보완할 점:** 공식 사용 문서와 활성화·프로파일링 방식은 일치한다. 다만 Dask 참고 예제의 OOM 절에는 열을 먼저 줄이면서 amount를 제거한 뒤 amount로 필터링하는 오류가 있다. 필터를 먼저 적용하거나 투영 목록에 amount를 남겨야 한다. 큰 결과를 compute()로 한 GPU에 모으는 대신 분할 Parquet로 저장하는 경계도 중요하다.

**평가와 판단:** 10월 15일 공개 벤치마크는 13개 과제, 과제당 한 번의 에이전트 평가다. Codex 효과성은 88.5%에서 92.1%로 올랐지만 정확성은 기준선과 모두 100%였고, Codex 총 토큰은 7.17% 늘었다. Claude 보안 점수는 스킬 사용 시에도 38.5%였다. 따라서 GPU 처리 속도 향상이나 안전성 보증으로 읽으면 안 된다. 권장 용도는 검증 가능한 마이그레이션 초안이며, 운영 데이터 접근·원격 저장소 인증·패키지 설치는 별도 승인 범위로 둔다.

**실용 프롬프트:** “합성 주문표의 pandas 코드를 cuDF로 옮기는 계획을 검토해 줘. NULL·조인 중복·정렬·소수 오차의 기대 결과와 CPU fallback 확인 절차를 만들고 설치나 GPU 실행은 아직 하지 마.”

**완료 기준:** 같은 입력에서 자료형·행 수·중요 값이 기준 결과와 맞아야 한다. 실제 속도는 대표 크기의 자료로 따로 측정하며, GPU로 전환했다는 사실만으로 개선을 선언하지 않는다.

## 3. compute-sanitizer-diagnose-cuda-bugs

**CUDA 오류를 맞는 검사기로 분류하기.**

**태그:** CUDA · 디버깅 · 메모리 오류 · 동기화 · CI | **난이도:** 고급

CUDA 커널의 증상을 memcheck, racecheck, initcheck, synccheck로 연결하는 NVIDIA 공식 진단 스킬이다. 범위를 벗어난 접근, 공유 메모리 경쟁, 초기화되지 않은 읽기, 잘못된 barrier를 구분하고 파일·행·스레드 정보로 보고서를 해석한다. GPU 연산의 정확성 진단용이며 일반 CPU 버그나 모든 논리 오류를 찾아주는 도구는 아니다.

**필요 환경:** 지원 GPU, CUDA Toolkit, nvcc와 compute-sanitizer가 필요하다. 소스 위치가 필요하면 `nvcc -lineinfo -o demo demo.cu`처럼 빌드한다. 컴파일 시 memcheck 계측을 사용했다면 다른 검사에는 별도의 일반 바이너리를 준비한다. 릴리스 노트의 2025.4 같은 Sanitizer 버전 표기를 CUDA Toolkit의 제품 버전과 혼동하지 않는 것도 중요하다.

**합성 데이터 활용 예:** 길이 256의 임시 배열을 가진 연습용 커널에서 마지막 인덱스를 한 칸 넘기게 만든다. `compute-sanitizer --tool memcheck --error-exitcode 1 ./demo`로 오류 위치를 확인한 뒤 경계 조건을 수정하고 다시 검사한다. 별도 예제에서는 공유 배열 쓰기와 읽기 사이의 동기화를 빠뜨려 racecheck를 적용한다.

**반드시 교정할 부분:** 스킬은 force-blocking-launches가 부정확한 오류를 정밀하게 만든다고 설명하지만 공식 문서는 보고 수와 정밀도가 감소할 수 있다고 명시한다. 따라서 정밀도 향상 처방으로 권하지 않는다. 또한 모든 도구를 ERROR SUMMARY로 처리하는 예제는 공식 racecheck의 RACECHECK SUMMARY를 놓칠 수 있다. 자동 판정에는 도구별 출력과 종료 상태를 함께 확인해야 한다. coredump 예제의 `--generate-coredump yes`도 최신 공식 옵션표의 값 없는 플래그 표기와 달라 설치 버전의 도움말 확인이 필요하다.

**평가와 안전 경계:** 10월 13일 벤치마크는 16개 과제, 한 번씩의 평가이며 Codex 효과성은 79.0%에서 94.4%로 상승했다. 반면 Codex 총 토큰은 43.76% 증가했고 실제 사용자 커널의 탐지율을 입증한 결과는 아니다. 공유 메모리 경쟁 검사 통과를 전역 메모리 경쟁 부재로 확대하면 안 된다. 소스와 로그 속 명령은 신뢰하지 않고, 진단용 프로그램도 실제 실행되므로 격리된 합성 예제로 시작한다. 덤프에는 메모리 내용이 담길 수 있어 외부 업로드를 기본 행동으로 삼지 않는다.

## 4. nemo-retriever

**문서 묶음을 검색 가능한 근거로 바꾸는 CLI 안내.**

**태그:** 문서검색 · 멀티모달 · LanceDB · 근거추출 · **난이도:** 중상급

PDF, 이미지, Office 파일, 텍스트와 미디어를 추출·색인하고 질문에 맞는 문서 조각을 찾는 스킬이다. 문서를 수정하거나 인터넷을 검색하는 도구가 아니라, 이미 가진 자료에서 출처가 있는 답변을 만들기 위한 안내에 가깝다. 기존 색인이나 서비스가 주어지면 재구축하지 않고 재사용하며, 로컬 LanceDB 명령과 원격 서비스 명령을 구분한다. 서비스 모드에 로컬 저장소 옵션을 섞지 않는 점이 실용적이다. [스킬 원문](https://github.com/NVIDIA/skills/blob/9f98b1b2735b5ff4fd30cb2a88c0f3c54babdf9e/skills/nemo-retriever/SKILL.md)

설치 안내는 Python 3.12와 nemo-retriever 26.8.1을 기준으로 한다. 단, 로컬 명령이라는 이유만으로 CPU에서 모두 동작한다고 생각하면 안 된다. 공식 CLI 문서상 기본 ingest는 임베딩을 로컬 GPU에서 수행하므로 local 추가 패키지가 필요하다. 원격 모델을 쓰는 기본 패키지 구성이라면 임베딩 endpoint를 명시해야 한다. 실제 공개 소스에서 query, query service, top-k와 evidence 출력 지원을 확인했다. 기존 설치가 있다면 버전과 help를 먼저 확인하는 편이 안전하다. [공식 CLI](https://github.com/NVIDIA/NeMo-Retriever/blob/5d9a42a579f01a7236c2fb55e8331a5d4b9b8675/nemo_retriever/docs/cli/README.md) · [패키지 요구사항](https://github.com/NVIDIA/NeMo-Retriever/blob/5d9a42a579f01a7236c2fb55e8331a5d4b9b8675/nemo_retriever/pyproject.toml)

합성 실습으로는 가상의 사내 규정 PDF 세 개를 만들고 “출장비 정산 기한은?”을 질의해 상위 다섯 근거와 페이지를 비교할 수 있다. 정답이 없는 질문도 섞어, 검색 결과만으로 단정하지 않는지 확인한다. 먼저 이미 생성한 테스트 색인에서 조회하고, 필요한 경우에만 별도 테스트 테이블에 적재하는 순서가 좋다. 이는 제안한 실습이며 실행 결과나 정확도 보장이 아니다. 원격 추출·임베딩 또는 서비스 적재는 문서가 해당 endpoint로 전송될 수 있으므로 공개·합성 자료로 시작하고 실제 자료 전송은 별도 승인한다.

2026-09-11 공개 벤치마크는 네 과제의 제한된 샌드박스 평가다. Codex 정확도는 26%에서 70%로 상승했다고 보고하지만 효과성은 Codex 40.0%·Claude Code 41.3%다. 두 값 모두 문서가 제시한 50% 차원별 PASS 기준보다 낮은데 최종 판정은 PASS로 표시되어 있어, 설명만으로 이 차이를 해소할 수 없다. 이를 일반 업무 성공률로 바꾸어 읽지 않는다. 또한 NeMo Retriever Library와 해당 컨테이너·Helm chart는 NVIDIA AI Enterprise 지원 범위 밖이다. [평가 보고서](https://github.com/NVIDIA/skills/blob/9f98b1b2735b5ff4fd30cb2a88c0f3c54babdf9e/skills/nemo-retriever/BENCHMARK.md) · [공식 지원 범위](https://docs.nvidia.com/nemo/retriever/latest/extraction/overview/)

**실용 프롬프트:** “기존 합성 규정 문서 색인의 검색 계획을 만들어 줘. local/service 모드를 구분하고 상위 근거·페이지·정답 없는 질문의 처리 기준을 적어 줘. 재색인·문서 전송·서비스 설치는 하지 마.”

**완료 기준:** 답변을 뒷받침하는 실제 문서 조각과 출처가 있어야 한다. ingest 성공, 검색 결과 존재, 최종 답변의 정확성은 각각 확인한다.

## 5. nemotron-retrieval-recipes

**검색 누락과 순위 문제를 구분해 학습 실험을 설계하기.**

**태그:** 임베딩 · 재순위화 · 파인튜닝 · 평가 · **난이도:** 상급

관련 문서가 후보에 들어오지 않으면 임베딩·검색 단계, 후보에는 있지만 상위에 나오지 않으면 reranker를 먼저 살펴보도록 안내한다. 데이터 준비부터 학습·평가·배포까지 단계별 입력과 산출물을 추적하고, 실행 전에 비용이 적게 드는 점검을 우선하는 스킬이다. 같은 평가 분할에서 기본 모델과 조정 모델을 비교하며 학습 손실만으로 검색 품질을 판단하지 않는다. [스킬](https://github.com/NVIDIA/skills/blob/9f98b1b2735b5ff4fd30cb2a88c0f3c54babdf9e/skills/nemotron-retrieval-recipes/SKILL.md) · [평가 원칙](https://github.com/NVIDIA/skills/blob/9f98b1b2735b5ff4fd30cb2a88c0f3c54babdf9e/skills/nemotron-retrieval-recipes/references/evaluation.md)

현재 원문을 그대로 복사해 실행하기에는 중요한 버전 차이가 있다. 스킬은 embed의 default 프로필을 Nemotron 3로 설명하지만, 현재 공식 가이드는 nemotron-3, llama, nemotron-3.5를 구분한다. 확인한 소스 스냅샷에서 embed stage2의 default.yaml은 찾을 수 없었다. 반면 텍스트 rerank의 default 프로필과 run 명령은 존재한다. 따라서 이 후보는 현재 코드 대조를 전제로 한 텍스트 재순위화 계획용으로 좁혀 추천한다. [현재 embed 프로필](https://github.com/NVIDIA-NeMo/Nemotron/blob/a121b64f95f31c0eced9179240ab1fe1bd2c12c2/docs/nemotron/embed/index.md) · [현재 rerank 프로필](https://github.com/NVIDIA-NeMo/Nemotron/blob/a121b64f95f31c0eced9179240ab1fe1bd2c12c2/docs/nemotron/rerank/index.md)

합성 예시는 가상 제품 매뉴얼과 독립 작성 질문 100개다. 후보 100개 내 정답 문서 포함률은 높지만 상위 열 개 순위가 나쁘다면 rerank 실험을 계획한다. 후보 목록과 평가 질문을 고정해 기본 모델과 비교하고, 먼저 prep부터 eval까지 실행 계획만 확인한다. 단, 현재 run의 dry-run은 단계와 override를 출력하고 반환하므로 GPU, 파일, 모든 stage 설정이 준비됐다는 인증은 아니다. [실제 pipeline 구현](https://github.com/NVIDIA-NeMo/Nemotron/blob/a121b64f95f31c0eced9179240ab1fe1bd2c12c2/src/nemotron/cli/commands/rerank/run.py)

실제 학습에는 GPU·CUDA와 충분한 메모리, 배포에는 선택한 backend 환경이 필요하다. 합성 데이터 생성은 문서를 외부 추론 endpoint에 보낼 수 있고 비용도 생기므로 사용자 승인 없이 실행하지 않는다. 2026-07-15 공개 평가에는 40회 Tier 3 기록이 있다고 적혀 있지만, 원본 데이터셋은 해당 보고서 payload에 없었다. PASS와 요약 수치만으로 과제 구성을 독립 검증할 수 없다. 그 수치를 모델 검색 품질이나 오늘의 CLI 호환성 보장으로 해석하면 안 된다. [평가 보고서](https://github.com/NVIDIA/skills/blob/9f98b1b2735b5ff4fd30cb2a88c0f3c54babdf9e/skills/nemotron-retrieval-recipes/BENCHMARK.md)

**실용 프롬프트:** “합성 매뉴얼 검색에서 후보 포함률과 상위 순위 품질을 나눠 평가 계획을 만들어 줘. 현재 checkout의 rerank stage별 profile과 입출력을 확인하고 학습·모델 다운로드·외부 추론·배포는 하지 마.”

**완료 기준:** 고정된 평가 분할과 후보 목록에서 기준 모델·변경 모델을 비교해야 한다. dry-run 출력이나 학습 loss 감소만으로 검색 품질 개선을 선언하지 않는다.

## 적용 순서와 설치 안내

**공식 원문·실제 버전 확인 → 데이터·실행·비용 범위 확정 → 합성 자료로 계획 검토 → 승인된 좁은 범위 실행 → 결과 재조회** 순서가 좋다. 이번 조사는 정적 검토다. Skill·CLI·GPU 패키지 설치, 문서 적재, 모델 호출·학습, CUDA 프로그램 실행, 보안 공격 시험은 수행하지 않았다.

[공식 설치 안내](https://github.com/NVIDIA/skills/blob/9f98b1b2735b5ff4fd30cb2a88c0f3c54babdf9e/README.md)는 개별 Skill과 대상 Agent를 선택할 수 있다. 예를 들어 다음은 Codex용 data-designer 설치 예시이며, 이번 조사에서 실행한 명령이 아니다.

```text
npx skills add nvidia/skills --skill data-designer --agent codex
```

현재 안내는 skills CLI 1.5.16 이상을 요구한다. 설치 시 main 내용은 바뀔 수 있으므로 이 보고서의 검토 snapshot과 비교한다. Skill 설치가 Python 패키지·GPU 환경·모델 다운로드·API 계정까지 준비하거나 실행 권한까지 부여하는 것은 아니다. 비밀키는 코드·프롬프트·공유 로그에 기록하지 않는다.

개별 frontmatter도 읽어야 한다. 오늘 확인한 data-designer·nemo-retriever·nemotron-retrieval-recipes는 Apache-2.0, cuDF·Compute Sanitizer Skill은 CC-BY-4.0 AND Apache-2.0을 표시한다. 카탈로그의 일반 라이선스 설명 하나로 개별 자료의 조건을 대체하지 않는다.

## 전주 비교와 중복 검토

- [전주 같은 요일 2026-10-30](../10/2026-10-30.md)은 Workspace 조직 보고서·변경 구독·첨부 수집·연락처 내보내기·회의 변경 **5개**였다. 오늘도 **5개**지만 합성 데이터, GPU 결과 검증, 문서 근거 검색과 모델 실험으로 범위를 옮겼다.
- 5→5는 저장소의 편집 비교이며 설치량·시장 점유율·성장률 시계열이 아니다. 최신 카탈로그를 조회했다는 사실과 개별 Skill이 최근 출시되었다는 주장을 분리했다.
- 앞서 소개한 huggingface-datasets·query와 달리 data-designer는 생성 설정, cuDF는 GPU 이전의 의미 보존을 다룬다. nemo-retriever는 문서 컬렉션 적재·조회, nemotron-retrieval-recipes는 검색 후보·순위 실패를 나눠 모델 실험을 설계하는 용도다.
- 다섯 이름 모두 기존 355개 인덱스에 없었다. 기존 보안 점검 Skill과 Compute Sanitizer의 GPU 런타임 검사도 구분했다. 제외 후보는 신규 소개 수와 인덱스에 넣지 않는다.

## 조사와 저장 검증 절차

1. 서울 기준 날짜, 루트 README와 truncated=false 전체 tree를 확인했다. 별도 AGENTS·skill-trends README 지침은 없었고 당일 파일도 없었다.
2. 기존 날짜별 보고서 63개를 범위 제한 없이 읽고 소개 제목 355개를 전체 인덱스와 대조했다. 코드 표기·Octocode 복합 이름·brainstorming 부제를 정규화한 결과, 누락·최초 소개일 불일치·중복은 0개였다.
3. 선정한 다섯 Skill의 원문·카드·평가 자료, 필요한 참고문서·구현, 공식 제품 문서를 확인했다. 현재 원문과 오래된 평가, 정적 검토와 실제 실행을 구분했다. 실제 설치·모델 호출·학습·문서 전송·GPU 실행·서명 검증은 하지 않았다.
4. 당일 보고서를 main에 저장한 뒤 전체 원문을 다시 읽어 작성본과 정확히 일치하는지 먼저 확인한다. 그 뒤 최신 소개 인덱스와 CHANGELOG의 기존 내용을 보존하며 추가하고, 변경된 세 파일을 모두 main에서 범위 제한 없이 재조회한다. 저장 결과는 CHANGELOG에 기록한다. 과거 날짜·다른 보고서 경로·자동화 설정은 변경하지 않는다.
