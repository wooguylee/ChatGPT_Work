**난이도:** 중상급

### 무엇을 돕는가

Foundry 프로젝트의 배포·연결·데이터셋·에이전트를 Python 클라이언트로 다루는 지침이다. 기존 microsoft-foundry가 전체 서비스 선택·문서 탐색에 가까웠다면, 오늘은 **SDK 세대와 객체 수명, 클라이언트별 작업 범위를 정확히 나누는 구현 검토**에 초점을 맞춘다. [고정 원문](https://github.com/microsoft/skills/blob/2d08976b5f1c50457272ad3d20aa479d5d3ba937/.github/plugins/azure-sdk-python/skills/azure-ai-projects-py/SKILL.md)

### 실용 예시

**합성 요청문:** “가상의 Foundry 앱 설계에서 프로젝트 endpoint와 모델 deployment name을 분리해 줘. 현재 설치 버전에 맞는 AIProjectClient와 OpenAI 호환 클라이언트의 역할을 표로 정리하고, 배포 목록 조회만 하는 예제와 모의 테스트를 작성해. 에이전트 생성·데이터 업로드·추론·추적 전송은 실행하지 마.”

**완료 기준**
- endpoint·배포 이름·클라이언트 버전이 명시된다.
- 동기 또는 비동기 경로를 일관되게 사용하고 자원을 닫는다.
- 조회와 외부 생성·업로드·과금 호출을 구분한다.
- 권한 부족·빈 배포 목록·잘못된 endpoint를 성공 결과와 구분한다.

### 최신성 보완

원문에는 create_agent·threads/runs와 create_version 기반 설명이 섞여 있다. 현재 SDK main README는 **2.3.0 이상**을 기준으로 Responses·Conversations·Evaluations 및 버전형 에이전트 흐름을 설명한다. 따라서 원문의 예제를 하나의 최신 API로 조립하지 않는다. 메모리·red team 등도 현재는 .beta 하위 기능을 포함하므로 설치 버전의 API와 일치시켜야 한다. stable 패키지 안에도 preview 기능이 있고 별도 opt-in이 필요한 경우가 있다는 점도 확인한다. [현재 공식 SDK README](https://github.com/Azure/azure-sdk-for-python/blob/main/sdk/ai/azure-ai-projects/README.md)

main 문서는 배포된 패키지와 다를 수 있다. 이 보고서는 새 API의 설치·호출 성공을 주장하지 않으며, 원문의 전체 예제를 그대로 실행하기보다 버전 일치 검토용으로 추천한다.

## 2. azure-ai-contentunderstanding-py

**태그:** 멀티모달, 문서 추출, RAG, 오디오·영상, Python  
**난이도:** 중상급

### 무엇을 돕는가

문서·이미지·음성·영상에서 검색 가능한 텍스트와 구조화 정보를 추출하는 파이프라인을 설계한다. 문서 OCR만 다루는 기존 Document Intelligence 소개와 달리, 여러 매체를 공통 분석 흐름으로 연결하고 사용자 정의 필드 스키마를 구성하는 것이 핵심이다. prebuilt analyzer 선택, 장기 실행 작업의 결과 수집, 콘텐츠 종류별 후처리를 안내한다. [고정 원문](https://github.com/microsoft/skills/blob/2d08976b5f1c50457272ad3d20aa479d5d3ba937/.github/plugins/azure-sdk-python/skills/azure-ai-contentunderstanding-py/SKILL.md)

### 실용 예시

**합성 요청문:** “가상의 제품 설명서 PDF와 데모 영상에서 RAG 입력을 만드는 설계를 작성해. 문서는 페이지 근거, 영상은 시간 구간을 보존하고, 내용이 없는 결과·처리 실패·부분 결과를 구분해. 실제 파일 업로드나 Azure 자원 변경 없이 합성 응답 JSON으로 후처리 테스트를 만들어 줘.”

**완료 기준**
- 원문 위치와 추출 텍스트를 연결한다.
- 다중 contents·빈 contents를 처리하고 첫 항목만 있다고 가정하지 않는다.
- 필드 누락을 0이나 빈 문자열로 조용히 바꾸지 않는다.
- 작업 timeout과 재시도 범위, 중복 분석 비용을 명시한다.
- 추출 결과를 사실 검증 완료나 법적 문서 판정으로 취급하지 않는다.

### 최신성 보완

현재 공식 README는 GA SDK 1.1.0 / 서비스 API 2025-11-01과 preview SDK 1.2.0b3 / 2026-06-01-preview를 구분한다. 원문의 “모든 작업은 장기 실행” 설명은 최신 preview의 inline 분석까지 포괄하지 못한다. preview 기능을 쓰려면 패키지와 서비스 API를 함께 확인해야 한다. prebuilt·custom analyzer도 지원 지역·모델 배포·default mapping 준비가 필요하므로 패키지만 설치하면 동작한다고 가정하지 않는다. [공식 SDK README](https://github.com/Azure/azure-sdk-for-python/blob/main/sdk/contentunderstanding/azure-ai-contentunderstanding/README.md)

원문 custom 예제의 create_analyzer·result.fields와 입력 타입을 그대로 복사하지 않는다. 현재 main의 [공식 analyzer 생성 샘플](https://github.com/Azure/azure-sdk-for-python/blob/main/sdk/contentunderstanding/azure-ai-contentunderstanding/samples/sample_create_analyzer.py)은 begin_create_analyzer와 ContentAnalyzer 리소스, poller.result()를 사용한다. [공식 invoice 샘플](https://github.com/Azure/azure-sdk-for-python/blob/main/sdk/contentunderstanding/azure-ai-contentunderstanding/samples/sample_analyze_invoice.py)은 AnalysisInput·AnalysisResult 및 result.contents의 문서 객체 안 fields를 사용한다. 원문의 AnalyzeInput·AnalyzeResult와 구별하되 main 샘플 이름을 GA 모든 버전에 일반화하지 않는다. 설치한 버전의 반환 모델을 확인하고 콘텐츠별 필드를 읽어야 한다. URL 입력도 서비스가 자료를 가져가는 전송 방식이며, 비공개 문서를 편의상 공개 URL로 바꾸지 않는다. 인증·업로드·모델 배포는 별도 승인 대상이다.

## 3. azure-ai-voicelive-py

**태그:** 실시간 음성, WebSocket, VAD, 비동기 Python, 도구 호출  
**난이도:** 중상급

### 무엇을 돕는가

양방향 음성 스트림의 세션 설정, 발화 시작·종료 감지, 부분 응답, 중단 처리와 함수 호출을 연결한다. 음성을 텍스트로 바꾸는 단일 작업보다 **사용자가 끼어들었을 때 응답 생성과 재생을 함께 제어하는 대화 루프**가 핵심이다. [고정 원문](https://github.com/microsoft/skills/blob/2d08976b5f1c50457272ad3d20aa479d5d3ba937/.github/plugins/azure-sdk-python/skills/azure-ai-voicelive-py/SKILL.md)

### 실용 예시

**합성 요청문:** “녹음·네트워크 없이 가짜 이벤트로 음성 상담 UI 상태 머신을 만들어 줘. 사용자가 말하기 시작하면 현재 재생을 멈추고 응답 취소를 요청하도록 설계해. 늦게 도착한 이전 응답 조각과 새 응답을 구분하고, 도구 호출은 승인 전 실행하지 않는 테스트를 추가해.”

**완료 기준**
- 입력·생성·재생 상태를 각각 추적한다.
- 중단 후 오래된 음성 조각이 다시 재생되지 않는다.
- 연결 종료·오류·취소를 정상 완료와 구분한다.
- 함수 인자 형식과 허용 도구를 검증하고 부작용 작업은 별도로 승인한다.
- 원음·전사문을 기본 로그에 남기지 않으며 마이크 사용과 전송 동의를 구분한다.

### 최신성 보완

공식 SDK README는 1.0.0부터 async-only임을 명시하며, 확인한 main 문서는 1.3.0b1 preview 상태다. 원문의 공통 sync 템플릿을 Voice Live에 그대로 적용하지 않는다. 현재 예제 모델은 gpt-realtime이지만 원문에는 gpt-4o-realtime-preview가 있으므로 실제 지원 모델·지역·음성·설치 버전을 확인한다. [공식 SDK README](https://github.com/Azure/azure-sdk-for-python/blob/main/sdk/voicelive/azure-ai-voicelive/README.md)

응답 취소만으로 클라이언트 스피커 큐가 비워지는지는 별도 구현 문제다. 재연결 시 메시지·도구 호출 중복도 테스트해야 한다. 패키지의 API 키 지원과 Entra ID 권장 사항을 구분하며, 예제 속 자격증명 문자열은 실제 비밀정보를 코드에 넣어도 된다는 뜻이 아니다.

## 4. m365-agents-py

**태그:** Microsoft 365, Teams, Python, 메시지 라우팅, 인증, 스트리밍  
**난이도:** 중상급

### 무엇을 돕는가

모델 추론 자체보다 **여러 업무 채널에서 메시지를 받고, 인증된 요청을 적절한 handler로 보내고, 상태와 응답을 관리하는 앱 기반**을 다룬다. AgentApplication, aiohttp 호스팅, MSAL 인증, 스트리밍 종료 처리, Copilot Studio 연결을 안내한다. [고정 원문](https://github.com/microsoft/skills/blob/2d08976b5f1c50457272ad3d20aa479d5d3ba937/.github/plugins/azure-sdk-python/skills/m365-agents-py/SKILL.md)

### 실용 예시

**합성 요청문:** “외부 전송 없는 가짜 TurnContext로 /help와 /status handler를 테스트해 줘. 사용자·대화별 상태가 섞이지 않는지 확인하고, 인증 실패는 데이터 조회 handler에 들어가지 않게 해. 공개 서버·채널 등록·OAuth 동의·실제 메시지 전송은 하지 마.”

**완료 기준**
- 라우트 우선순위와 fallback 동작을 검증한다.
- 인증 실패·사용자 취소·handler 오류를 구분한다.
- 스트리밍 예외에서도 종료 처리를 수행한다.
- 개발용 MemoryStorage와 운영 영속 저장소를 구분한다.
- 전송 대상과 사용자 권한을 검증한 뒤에만 실제 응답을 보낸다.

### 최신성 보완

공식 핵심 라이브러리 문서는 underscore 형태의 microsoft_agents import와 라우팅·상태·인증 구조를 확인해 준다. 현재 main에는 새 Configuration 기반 연결 설정과 기존 방식의 호환 설명이 함께 있으므로 최신 문서의 모든 기능이 현재 설치 버전에 있다고 가정하지 않는다. [공식 Hosting Core README](https://github.com/microsoft/Agents-for-python/blob/main/libraries/microsoft-agents-hosting-core/readme.md)

릴리스 기록의 1.9.0은 **2026-10-19 출시**, 1.10.0은 **Unreleased**다. 후자의 JWT·연결 구성 변경을 이미 출시된 기능으로 소개하지 않는다. 1.9.0의 outbound host 검증 강화도 사용자 권한 확인이나 자료 전송 동의를 대신하지 않는다. [공식 변경 기록](https://github.com/microsoft/Agents-for-python/blob/main/changelog.md)

원문은 CopilotClient가 context manager를 구현하지 않는다고 별도로 명시한다. “모든 client에 async with”라는 일반 규칙보다 구체적인 클라이언트 계약을 우선한다. 민감도·AI 생성 라벨을 붙이는 것도 접근 제어나 정보 공개 허가와는 다르다.

## 적용 순서와 설치 안내

먼저 외부 호출 없는 코드 검토부터 시작한다. 사용하는 SDK 버전·실제 endpoint·인증 방식·데이터 전송 범위를 표로 만들고, 이 문서의 원문 보완 사항을 반영한다. 그다음 합성 자료와 모의 도구로 결과 파싱·오류·종료 경로를 시험한다. 실제 리소스 생성, 파일 업로드, 유료 모델 호출, 마이크 접근, 채널 게시와 권한 부여는 별도 승인 대상이다.

공식 README는 필요한 Skill만 선택해서 쓰라고 권한다. 전체 모음을 무조건 설치하지 않는다. 오늘 조사에서는 설치기를 실행하지 않았으며 Codex에서 실제 로딩·실행을 검증하지 않았다. 설치할 경우 검토한 commit의 개별 Skill과 필요한 참고 파일을 함께 검토하고, 조직에서 승인한 설치 절차를 따른다. SKILL.md에 쓰인 강한 지시문은 사용자 권한이나 보안 정책을 확장하지 않는다.

5. 과거 보고서를 새로 만들지 않으며 다른 경로·자동화 설정은 변경하지 않는다.
