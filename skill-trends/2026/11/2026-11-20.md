## 1. chdb-sql

별도 서버를 띄우지 않고 Python 프로세스 안에서 CSV·Parquet에 ClickHouse SQL을 실행하는 지침이다. 한 번만 조회할 때는 단일 쿼리, 임시 테이블을 여러 단계에서 재사용할 때는 Session을 구분한다.

- 예시: “샘플 OCR 결과 Parquet에서 문서 종류별 평균 신뢰도와 오류 건수를 집계하는 SQL을 작성해줘. 로컬 파일만 사용해.”
- 태그: Python, SQL, Parquet
- 출처: [공식 SKILL.md](https://github.com/ClickHouse/agent-skills/blob/main/skills/chdb-sql/SKILL.md)

## 2. chdb-datastore

익숙한 DataFrame 방식으로 필터·조인·집계를 작성하고 결과가 필요할 때 실행하는 경로다. SQL이 중심이면 `chdb-sql`이 더 직접적이다. 기존 pandas 파이프라인 전체를 바꾸기 전에 NULL 처리·결과 순서·자료형을 대표 데이터로 대조한다.

- 예시: “샘플 CSV와 Parquet의 조인·집계를 pandas와 DataStore로 각각 작성해줘. 결과 행 수, NULL, 정렬 결과를 먼저 대조하게 해줘.”
- 태그: Python, DataFrame, 지연 실행
- 출처: [공식 SKILL.md](https://github.com/ClickHouse/agent-skills/blob/main/skills/chdb-datastore/SKILL.md)

## 3. infra-clickhouse

`clickhousectl`로 로컬 ClickHouse 서버를 실행하고 스키마·시드·쿼리를 관리하는 흐름과, ClickHouse Cloud에 배포하는 흐름을 구분한다. 파일 한 번을 읽기 위한 임베디드 chDB와 달리 서버가 필요한 앱 통합 테스트에 맞다.

- 예시: “샘플 이벤트를 로컬 ClickHouse에 넣어 API 연동을 시험하는 계획을 만들어줘. 버전, 실제 리스닝 포트, 시드 재실행 조건을 적고 Cloud 서비스는 만들지 마.”
- 태그: ClickHouse, clickhousectl, 로컬 서버
- 출처: [공식 SKILL.md](https://github.com/ClickHouse/agent-skills/blob/main/skills/infra-clickhouse/SKILL.md) · [로컬 안내](https://github.com/ClickHouse/agent-skills/blob/main/skills/infra-clickhouse/ref/local.md)

## 4. infra-postgres

ClickHouse SQL 엔진이 아니라 실제 PostgreSQL을 대상으로 한다. 개발용 인스턴스는 Docker로 관리하며 기존 서비스가 포트를 사용 중이면 반환된 포트를 확인해야 한다. 관리형 서비스 생성·이전은 별도 경로다.

- 예시: “기존 DB에는 연결하지 말고 테스트용 Postgres 인스턴스 구성안을 써줘. 반환된 포트 확인, 앱 전용 역할, 연결 비밀을 저장소에 남기지 않는 방법을 포함해.”
- 태그: PostgreSQL, Docker, psql
- 출처: [공식 SKILL.md](https://github.com/ClickHouse/agent-skills/blob/main/skills/infra-postgres/SKILL.md) · [로컬 안내](https://github.com/ClickHouse/agent-skills/blob/main/skills/infra-postgres/ref/local.md)

## 5. clickhouse-architecture-advisor

이벤트의 유입량과 지연 목표, 자주 실행할 쿼리, 늦게 도착하는 이벤트를 기준으로 설계 후보를 비교한다. 이미 소개한 `clickhouse-best-practices`를 대체하지 않는다. 공식 문서 근거, 문서에서 도출한 판단, 경험칙을 구분하고 검증 지표를 붙이는 것이 차이다.

- 예시: “이벤트 수가 시간대마다 달라지는 분석 서비스를 설계해줘. 배치 적재와 사전 집계의 장단점을 비교하고, 공식 근거와 추론을 구분한 뒤 부하 테스트로 검증할 지표를 제시해.”
- 태그: OLAP, 적재, 보존, 사전 집계
- 출처: [공식 SKILL.md](https://github.com/ClickHouse/agent-skills/blob/main/skills/clickhouse-architecture-advisor/SKILL.md)

## 설치와 사용

[ClickHouse 공식 스킬 저장소](https://github.com/ClickHouse/agent-skills/blob/main/README.md)는 `npx skills add clickhouse/agent-skills` 또는 `clickhousectl skills`를 안내한다. 다섯 원문은 Apache-2.0을 표기한다. 스킬 설치와 실행 환경 준비는 별개다. chDB 스킬 원문은 Python 3.9 이상과 macOS 또는 Linux를 명시한다. Windows라면 네이티브 호환을 전제하지 말고 WSL의 Linux 환경에서 작은 샘플로 먼저 확인한다. Docker 기반 Postgres는 실행 중인 Docker가 별도로 필요하다.

## 오늘의 Top Pick: chdb-sql

여러 Parquet 파일에서 같은 집계를 반복한다면 테스트용 분석 서버를 운영하기 전에 로컬 Python에서 쿼리와 산출 형식부터 검증하기 좋다.

## Codex에서 바로 써볼 만한 것: clickhouse-architecture-advisor

기존 이벤트 샘플과 조회 요구만 주고 설계 선택지, 공식 출처, 가정을 구분한 문서를 만들 수 있다. 클라우드 자격증명이나 서비스 생성은 필요하지 않다.
