## 6. `babysit-pr`

- **출처:** OpenAI 공식 Codex GitHub — https://github.com/openai/codex/tree/main/.codex/skills/babysit-pr
- **GitHub:** https://github.com/openai/codex
- **제작자/조직:** OpenAI / Codex repository
- **지원 Agent:** 현재 확인되는 형태는 **Codex repository 내부 workflow**이며 다른 Agent에 대한 공식 지원은 확인하지 못했다.
- **Snapshot:** `openai/codex` GitHub API **119,198★ / 18,192 forks**, `updated_at=2026-08-27T23:57:05Z`, `pushed_at=2026-08-27T23:58:11Z`. 별도의 skills.sh/SkillsMP 설치·보안 점수는 확인되지 않는다.

### 무엇을 해결하나

PR을 만든 뒤 Agent가 한 번 상태를 보고 끝나는 것이 아니라 review comment, CI checks/workflow run, mergeability를 계속 polling하고 **PR이 merged/closed 되거나 사람 개입이 정말 필요할 때까지** 작업을 이어간다. `gh_pr_watch.py`가 JSON/JSONL action을 만들고 Agent가 실패 로그를 “branch-caused”와 “flaky/infra”로 분류한 뒤, 전자만 code fix→commit→push하고 후자는 정해진 retry budget 안에서만 재시도한다. 사람 review comment에는 임의로 답글을 달지 않고, thread resolve·PR state mutation에도 명시적인 안전 규칙을 둔 점이 단순 CI watcher와 다르다.

### 설치 및 사용

이 Skill은 현재 `openai/codex` 저장소의 **repo-internal Skill**로 확인되며, 공개 배포용 `npx skills add ... --skill babysit-pr` 명령은 공식 문서에서 확인되지 않았다. 가장 정확한 테스트 방법은 `openai/codex` repository 안에서 Skill과 script를 함께 사용하는 것이며, 다른 프로젝트로 옮길 경우 `.codex/skills/babysit-pr/` 전체 폴더와 상대 경로 참조를 함께 보존/조정해야 한다.

주요 script:

```bash
python3 .codex/skills/babysit-pr/scripts/gh_pr_watch.py --pr auto --once
python3 .codex/skills/babysit-pr/scripts/gh_pr_watch.py --pr auto --watch
python3 .codex/skills/babysit-pr/scripts/gh_pr_watch.py --pr auto --retry-failed-now
```

실사용에는 Python 3, GitHub CLI(`gh`) 인증, PR/Actions 조회 권한과 필요 시 branch push 권한이 필요하다.

### Agent에게 줄 예시

> `babysit-pr로 현재 PR을 계속 watch해줘. branch-caused CI 실패만 수정·commit·push하고, infra/flaky 실패는 retry budget 안에서만 재시도해. 사람 review comment에는 내 확인 없이 답글을 달지 마.`

### 평가

**왜 오늘 볼 가치가 있나:** “코드 생성 Skill”보다 한 단계 높은 **장시간 상태 감시 + 실패 분류 + 안전한 제한적 mutation + 재관찰**의 운영 패턴을 실제 Codex repository에서 볼 수 있다. 이는 Agent가 배포/리뷰 lifecycle까지 맡게 될 때 필요한 구조에 가깝다.  
**주의:** 재사용용 패키지가 아니라 repo 내부 Skill이라 설치성이 낮고, GitHub write 권한을 주는 순간 영향 범위가 커지므로 그대로 복사하기보다 권한·human interaction policy를 함께 가져와야 한다.

### 🏆 오늘의 Top Pick

**`copilot-sdk`**

Agent runtime을 단순한 대화형 CLI가 아니라 **제품 코드에서 호출 가능한 programmable runtime**으로 바꾸고, session·streaming·custom tools·MCP를 TypeScript/Python/Go/.NET에서 일관되게 다룬다는 점이 가장 큰 변화다. Technical Preview라는 단점은 명확하지만, Agent를 “사용”하는 단계에서 Agent 기능을 “제품에 내장”하는 단계로 넘어가는 흐름을 가장 잘 보여준다.

### ⚡ Codex에서 바로 써볼 만한 것

**`agent-browser`**

`npx skills add` + CLI/Chromium 설치 정도로 시작할 수 있고, Codex가 코드 수정 뒤 실제 브라우저에서 동작을 검증하는 루프를 바로 만들 수 있다. 오늘 기준 24시간 Trending #39, +6.3K 설치, 누적 742.4K라는 채택 신호도 강하다.

### 오늘 보이는 공통 흐름

오늘의 공통점은 Skill이 더 이상 “긴 프롬프트 파일”에 머물지 않는다는 것이다. `agent-browser`는 설치된 CLI에서 버전 일치 문서를 동적으로 공급하고, `copilot-sdk`는 runtime 자체를 앱에 내장하며, `define`은 요구사항을 실행 가능한 gate로 만들고, `babysit-pr`는 관찰→판단→수정→재관찰의 폐쇄 루프를 운영한다. 즉 Agent Skill 생태계가 **정적 지식 전달 → runtime/tool adapter → 검증 가능한 장기 workflow**로 이동하는 흐름이 뚜렷하다.
