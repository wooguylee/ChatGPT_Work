## 1. gh-issue-sync

- **출처 사이트:** [skills.sh](https://www.skills.sh/mitsuhiko/gh-issue-sync/gh-issue-sync)
- **GitHub:** [mitsuhiko/gh-issue-sync](https://github.com/mitsuhiko/gh-issue-sync)

- **지원 Agent:** Codex, Claude Code, OpenCode, Pi, Amp/generic Agent. 프로젝트/사용자 scope별 Skill 설치를 공식 CLI가 직접 지원한다.

### 인기 및 트렌드 지표

- skills.sh Hot: **#10**, 표에 **`41 +27`**로 표시됨.
- 누적 설치: **5.2K**.
- GitHub: **162 Stars / 13 Forks**.
- 최근 GitHub push: **2026-03-31**.
- skills.sh 보안 감사: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Warn**.
- 24시간 설치 증가 수치의 정확한 의미는 Hot 페이지의 `+27` 표기만으로 단정할 수 없어 별도 수치로 해석하지 않았다.
- 품질 점수·좋아요: 조사 시점 상세 페이지에서 별도 확인되지 않아 미기재.

### 무엇을 해결하나

GitHub Issues를 `.issues/open/`, `.issues/closed/` 아래의 **YAML front matter가 포함된 Markdown 파일**로 내려 받아 Agent가 일반 소스 파일처럼 검색·편집·diff할 수 있게 만든다. 원격 Issue를 매번 API로 직접 조작하는 대신 로컬에서 충분히 검토한 뒤 일괄 동기화할 수 있고, local/original/remote를 비교하는 **3-way conflict detection**으로 원격 변경과의 충돌을 감지한다. 새 이슈는 `T1` 같은 임시 ID로 로컬에서 만들고 push 시 실제 GitHub issue 번호로 치환할 수 있어 대량 이슈 정리 workflow에 잘 맞는다.

### 설치 및 사용

Skill만 설치하려면:

```bash
npx skills add https://github.com/mitsuhiko/gh-issue-sync --skill gh-issue-sync
```

실제 동기화 CLI는 GitHub CLI 인증이 필요한다.

```bash
gh auth login
curl -sSfL https://github.com/mitsuhiko/gh-issue-sync/releases/latest/download/install.sh | sh

gh-issue-sync init
gh-issue-sync pull
gh-issue-sync status
```

Go 환경이라면 다음도 가능하다.

```bash
go install github.com/mitsuhiko/gh-issue-sync/cmd/gh-issue-sync@latest
```

CLI 자체가 Agent별 Skill 파일도 만들어 준다.

```bash
gh-issue-sync write-skill --agent codex --scope project
gh-issue-sync write-skill --agent claude --scope project
gh-issue-sync write-skill --agent opencode --scope project
```

**추가 요구사항:** GitHub CLI(`gh`) 인증. GitHub Projects까지 동기화하면 `gh auth refresh -s project`로 scope가 추가로 필요할 수 있다.

### 활용 예시

> 이 저장소의 열린 이슈를 로컬로 pull한 뒤 중복·불명확한 이슈를 정리하고, 변경안을 `gh-issue-sync status`와 diff로 보여줘. 내가 승인하기 전에는 push하지 마.

### 평가

**오늘 볼 가치:** Issue tracker를 Agent가 가장 잘 다루는 형태인 “로컬 파일”로 바꿔 주는 실무적 접근이 돋보인다.  
**주의:** 현재 Hot 상승세와 별개로 GitHub의 최근 코드 push는 2026-03-31이므로 유지보수 활동을 함께 확인해야 하며, push는 실제 Issue를 변경하므로 승인 단계와 권한 제한이 중요하다.

- **지원 Agent:** Claude Code, GitHub Copilot 및 CLI/Skill을 사용할 수 있는 coding agent. Skill 설치 방식상 Codex에서도 활용 가능하다.

### 인기 및 트렌드 지표

- 누적 설치: **134.7K**.
- GitHub: **12,929 Stars / 700 Forks**.
- 최근 GitHub push: **2026-08-27**.
- skills.sh 보안 감사: **Gen Agent Trust Hub Pass / Socket Pass / Snyk Fail**.
- 24시간 설치 증가·현재 Trending 순위: 조사 시점 상세 페이지에서 명확히 확인되지 않아 미기재.
- 품질 점수·좋아요: 별도 확인되지 않아 미기재.

### 무엇을 해결하나

Microsoft는 이 CLI를 coding agent에 특히 잘 맞는 방식으로 설명하며, **CLI+SKILL이 큰 MCP tool schema나 전체 accessibility tree를 매번 context에 싣지 않아 token-efficient**하다는 점을 강조한다. Agent는 `open`, `click`, `fill`, `snapshot`, `find`, `console`, `requests`, `trace`, `video` 같은 목적별 명령만 호출하고, 필요한 시점에 스냅샷을 파일로 가져와 페이지 상태를 판단한다. named session, persistent profile, network mocking, trace와 dashboard까지 있어 단순 브라우저 제어를 넘어 개발·디버깅·E2E 검증 도구로 쓰기 좋다.

### 설치 및 사용

Skill 설치:

```bash
npx skills add https://github.com/microsoft/playwright-cli --skill playwright-cli
```

공식 CLI 설치와 Skill 구성:

```bash
npm install -g @playwright/cli@latest
playwright-cli --help
playwright-cli install --skills
```

간단한 시작 예:

```bash
playwright-cli open http://localhost:3000 --headed
playwright-cli snapshot
playwright-cli console
playwright-cli requests
```

**추가 요구사항:** Node.js 18 이상. 별도 MCP server나 API Key는 필요하지 않는다. 실계정·운영 서비스에 연결할 때는 브라우저 profile과 권한을 격리하는 편이 안전하다.

### 활용 예시

> 로컬 앱의 로그인 → 프로필 수정 → 로그아웃 E2E를 playwright-cli로 검증해. 실패하면 console, requests, trace 증거와 정확한 재현 절차를 남기고, 실제 외부 계정 데이터는 변경하지 마.

### 평가

**오늘 볼 가치:** Agent용 브라우저 자동화가 “무거운 상시 MCP context” 대신 “짧은 CLI 명령 + 필요 시 snapshot”으로 이동하는 흐름을 가장 잘 보여주는 Skill이다.  
**주의:** skills.sh의 Snyk 감사가 **Fail**로 표시되어 있으므로 감사 상세를 검토하고, 우선 테스트/스테이징 환경과 최소 권한 profile에서 사용해야 한다.

### 설치 및 사용

```bash
npx skills add https://github.com/vercel-labs/agent-skills --skill vercel-react-best-practices
```

**추가 요구사항:** 별도 API Key나 MCP는 필요하지 않는다. Node/npx 환경과 실제 React 또는 Next.js 코드베이스가 있으면 바로 활용 가능하다.

### 활용 예시

> 이 Next.js 페이지를 `vercel-react-best-practices` 기준으로 리뷰해. waterfall, barrel import, RSC 직렬화 비용을 우선순위대로 찾고 측정 가능한 근거가 있는 최소 수정 diff만 제안해줘.

### 평가

**오늘 볼 가치:** Vercel의 실제 React/Next.js 지식이 Agent가 소비하기 좋은 규칙 단위로 구조화되어 있어 코드 리뷰와 생성 단계 모두에 적용하기 쉽다.  
**주의:** 모든 규칙을 기계적으로 적용하면 버전·아키텍처에 맞지 않는 조기 최적화가 될 수 있으므로 profiler, bundle analyzer, 서버 지표 등 실제 측정과 함께 써야 한다.

### 무엇을 해결하나

Claude Code의 native Agent Teams를 단순히 “여러 Agent를 동시에 띄우기”가 아니라 **team lead, teammate별 독립 context, 공유 task list, dependency auto-unblock, peer-to-peer mailbox**를 사용하는 협업 패턴으로 정리한다. 핵심은 병렬화 자체보다 “teammate가 서로 소통해야 하는가?”를 기준으로 Agent Teams와 subagent/single session을 구분하고, 파일 충돌을 피하기 위해 역할별 소유 파일을 분리하는 것이다. 모든 팀에 `challenge_agent`를 넣어 다른 specialist의 가정을 반박·검증하게 하는 패턴도 특징적이다.

### 설치 및 사용

AgentSkill.sh의 `/learn` 기능을 쓰려면 먼저 CLI를 구성한다.

```bash
npx @agentskill.sh/cli@latest setup
```

그 뒤 Agent에서:

```text
/learn @jochenyang/agent-teams
```

AgentSkill.sh는 예를 들어 Codex에는 `~/.codex/skills/jochenyang/agent-teams/`, Claude Code에는 `~/.claude/skills/jochenyang/agent-teams/` 식의 설치 경로를 제공한다.

**추가 요구사항:** 실제 team spawning과 teammate 간 메시징은 **Claude Code의 native Agent Teams 기능이 가능한 환경**이 필요하다. 이 Skill 자체는 bash subprocess로 여러 Claude CLI를 흉내 내지 말라고 명시한다.

### 활용 예시

> Claude Code에서 auth 모듈을 security, performance, maintainability, challenge 역할로 나눠 병렬 리뷰해. 각 역할은 별도 파일에 findings를 쓰고 서로의 결론을 반박 검증한 뒤 하나의 최종 보고서로 합쳐줘.

### 평가

**오늘 볼 가치:** “무조건 multi-agent”가 아니라 **언제 팀을 쓰면 손해인지까지 명시한 orchestration 규칙**이 좋아, Agent 병렬 작업의 실제 비용과 충돌 문제를 현실적으로 다룬다.  
**주의:** teammate마다 독립 context window를 사용하므로 token 비용이 크게 늘고, 동일 파일을 동시에 수정하면 충돌이 쉽게 난다. 또한 핵심 기능은 Claude Code 전용 native capability에 가깝다.

### 무엇을 해결하나

PR의 CI가 빨갛게 떴을 때 Agent가 곧바로 코드를 바꾸게 하지 않고, 먼저 `gh`로 **실패한 check와 GitHub Actions 로그를 수집해 actionable failure를 요약**하도록 한다. 그 다음 수정 계획을 제안하고 **사용자가 명시적으로 승인한 뒤에만 구현**하는 evidence-first 흐름이라, 로그를 제대로 읽지 않은 채 추측으로 코드를 바꾸는 Agent 행동을 줄인다. OpenAI의 공식 curated Skill이라 Codex에서 GitHub 기반 개발 workflow의 기본 안전장치로 쓰기 좋다.

### 설치 및 사용

```bash
npx skills add https://github.com/openai/skills --skill gh-fix-ci
```

GitHub CLI 인증 확인:

```bash
gh auth login
gh auth status
```

**추가 요구사항:** GitHub CLI와 해당 저장소/Actions 로그를 읽을 수 있는 인증 scope. 외부 CI provider는 GitHub check에서 링크만 보이고 실제 로그 접근은 별도 인증이 필요할 수 있다.

### 활용 예시

> 현재 브랜치 PR의 실패한 GitHub Actions를 분석해 원인과 로그 증거를 요약하고 수정 계획만 제안해줘. 내가 승인하기 전에는 코드를 변경하지 마.

### 평가

**오늘 볼 가치:** 실패 → 로그 수집 → 근거 요약 → 계획 → 승인 → 수정의 흐름을 Skill로 강제한다는 점에서 Codex의 일상적인 CI debugging 품질을 바로 높일 수 있다.  
**주의:** 외부 CI 서비스의 세부 로그는 자동으로 읽지 못할 수 있으며, `gh` 인증과 scope를 최소 권한으로 관리해야 한다.
