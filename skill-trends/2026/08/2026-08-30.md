### 무엇을 해결하는가

Reddit 마케팅을 “관련 키워드에 무작정 답글 달기”가 아니라, **제품이 실제로 문제 해결에 도움이 되는 소수의 thread를 선별한 뒤 정체와 관계를 숨기지 않는 유용한 답변 초안을 만드는 작업**으로 바꾼다. 핵심 구조는 `(1) 제품 컨텍스트 확보 → (2) 적합한 대화 탐색 → (3) 도움 중심의 답변 작성`이며, 자동 게시보다 사람이 검토할 수 있는 draft 생성에 초점을 둔다. 설치 수가 매우 빠르게 늘고 있지만 GitHub 자체 신호는 아직 작은 매우 신생 Skill이라는 점이 특징이다.

### 설치 및 사용

```bash
npx skills add https://github.com/flowkit-labs/skills --skill reddit-automation
```

별도 MCP/API key가 설치 페이지에 필수 요구사항으로 명시되지는 않았다. 다만 실제 Reddit 탐색은 사용 중인 Agent의 웹 접근 능력/도구 정책에 영향을 받는다. **Snyk audit가 Warn**이므로 설치 전 원본 `SKILL.md`와 호출 범위를 검토하는 편이 좋다.

**Agent에게 줄 예시**

> 우리 SaaS는 소규모 팀의 GitHub PR 리뷰 시간을 줄여주는 도구야. 최근 Reddit에서 이 문제를 실제로 겪고 있는 thread를 찾아서, 광고처럼 보이지 않게 도움을 먼저 주고 우리와의 관계를 명확히 밝히는 답변 초안 3개를 만들어줘. 자동 게시하지는 마.

**오늘 볼 가치:** 24시간 설치 상승이 매우 강하고 “자동 홍보” 대신 **관련성·투명성·human review**를 워크플로에 넣은 점이 흥미롭다. 단, 신생 repo라 장기 신뢰 신호는 아직 약하다.

### 무엇을 해결하는가

`npx skills add`로 각 Agent 폴더에 따로 설치하면 **원본 source metadata, 업데이트 경로, 어느 Agent에 배포됐는지**가 흩어지기 쉽다. `manage-skills`는 `~/.skills-manager/skills/` 중앙 라이브러리와 SQLite metadata를 기준으로 Skill을 설치하고, agent별 deploy/undeploy, tags, presets, upstream check/update, 기존 skill adopt를 하나의 lifecycle로 묶는다. GUI와 `skills-manager-cli`가 같은 core/database를 사용해 사람과 Agent가 동일 상태를 다룬다는 점도 실무적으로 크다.

### 설치 및 사용

Skill 자체는 SkillsMP에서 다음처럼 설치할 수 있다.

```bash
npx skills add https://github.com/xingkongliang/skills-manager --skill manage-skills
```

하지만 이 Skill이 실제 작업을 수행하려면 **`skills-manager-cli`가 PATH에 있어야 한다.** 원 저장소에서 소스 설치 시:

```bash
npm install
npm run cli:install
# 내부적으로 cargo install --path src-tauri --bin skills-manager-cli --locked --force
```

개발 빌드에는 Node.js 18+, Rust toolchain, Tauri OS prerequisites가 필요하다. 공식 release의 standalone CLI binary를 PATH에 두는 방법도 제공한다.

대표 사용 예:

```bash
skills-manager-cli --json skills search "react performance" --limit 5
skills-manager-cli skills install vercel-labs/agent-skills@react-best-practices
skills-manager-cli skills deploy <skill> --agent claude_code --agent codex
skills-manager-cli skills check --all
skills-manager-cli skills update --all
```

**Agent에게 줄 예시**

> 현재 중앙 Skill 라이브러리에서 업데이트 가능한 항목을 먼저 dry/read-only 방식으로 확인하고, 변경된 Skill만 목록으로 보여줘. 내가 승인한 것만 업데이트한 뒤 Codex와 Claude Code에 배포 상태가 맞는지 확인해줘.

**오늘 볼 가치:** Skill이 늘어날수록 “무엇을 설치할까”보다 **버전·source·배포 대상·동기화 상태를 어떻게 관리할까**가 더 큰 문제가 된다. 최근 repo 활동과 4K+ Stars까지 있어 오늘 후보 중 생태계 운영 관점의 가치가 가장 높다.

- 24h 설치 증가·누적 설치·좋아요·품질/보안 점수: 공개 SkillsMP 페이지에서 확인 불가

### 무엇을 해결하는가

Slack, HubSpot, Salesforce, Google Workspace, Shopify 같은 SaaS를 Agent에 연결할 때 서비스마다 OAuth/token refresh/credential storage를 직접 구현하는 부담이 크다. 이 Skill은 그 인증 계층을 **Maton managed API gateway**로 넘기고, Agent는 `maton` CLI를 통해 읽기/쓰기 API를 호출하게 한다. 단순 instruction-only Skill이 아니라 외부 hosted auth/gateway에 의존하는 integration Skill이므로 생산성은 크지만 권한과 데이터 경계를 더 엄격히 봐야 한다.

### 설치 및 사용

Skill 설치:

```bash
npx skills add https://github.com/maton-ai/api-gateway-skill --skill api-gateway
```

추가 CLI:

```bash
npm install -g @maton/cli
# 또는 macOS
brew install maton-ai/cli/maton
```

권장 인증:

```bash
maton login --oauth
maton whoami --json
```

API key 수동 방식은 `maton login --interactive`이며, 문서상 credential은 OS keyring에 저장된다. `MATON_API_KEY` 환경변수도 가능하지만 장기 credential이 child process에 노출될 수 있어 권장도가 낮다. Maton account와 network access가 필수이고 계정당 10 requests/sec + 대상 API 자체 rate limit가 적용된다.

**Agent에게 줄 예시**

> 연결된 HubSpot에서 최근 7일간 생성된 deal을 읽기 전용으로 조회해서 stage별 개수를 요약해줘. 어떤 변경 API도 호출하지 말고, 먼저 사용할 endpoint와 필요한 scope를 보여줘.

**오늘 볼 가치:** Agent integration이 “각 SaaS별 MCP를 하나씩 붙이는 방식”에서 **managed auth gateway + 범용 호출 계층**으로도 확장되는 흐름을 보여준다. 단점은 Maton이라는 외부 서비스에 인증·가용성을 의존한다는 점이다.

### 무엇을 해결하는가

일반적인 “git log를 요약해서 changelog 써줘”는 merge/backport/direct commit을 놓치거나 PR 번호·기여자 attribution을 잘못 붙이기 쉽다. 이 Skill은 먼저 base tag와 target SHA를 고정하고 `git log --first-parent`로 범위를 감사한 뒤, 전용 `verify-release-notes.mjs`가 **완전한 contribution manifest/ledger**를 생성하도록 강제한다. 그 뒤 사용자 관심도 기준으로 release note를 grouping하므로 단순 글쓰기 지침보다 release engineering pipeline에 가깝다.

### 설치 및 사용

AgentSkill.sh 권장 설치 흐름:

```bash
npx @agentskill.sh/cli@latest setup
```

이후 Agent 안에서:

```text
/learn @openclaw/openclaw-changelog-update
```

programmatic 설치 시 AgentSkill API가 반환하는 `SKILL.md`를 platform path에 쓸 수 있으며 Codex 권장 경로는 `~/.codex/skills/openclaw/openclaw-changelog-update/SKILL.md`, Claude Code는 `~/.claude/skills/openclaw/openclaw-changelog-update/SKILL.md`다.

원본 workflow는 `git`, Node.js, OpenClaw repo 내부의 검증 script를 사용한다. 예:

```bash
git fetch --tags origin
git log --first-parent <base-tag>..<target-ref>
node .agents/skills/openclaw-changelog-update/scripts/verify-release-notes.mjs \
  --base <base-tag> --target <target-ref> --main-ref origin/main \
  --version <YYYY.M.PATCH> --manifest /tmp/openclaw-release-<YYYY.M.PATCH>.json \
  --write-ledger
```

**Agent에게 줄 예시**

> 다음 stable release changelog를 현재 validated Code SHA 기준으로 다시 만들어줘. 이전 draft를 신뢰하지 말고 base tag부터 first-parent history와 direct commit을 전부 감사한 뒤 manifest를 생성하고, 누락된 PR ref나 Thanks attribution이 없는지 검증해줘.

**오늘 볼 가치:** Skill이 단순 prompt template을 넘어 **release-critical 검증 절차 + deterministic script + git provenance**를 묶는 형태로 진화하고 있음을 잘 보여준다. 단, OpenClaw repo 구조와 release policy에 강하게 특화되어 그대로 다른 프로젝트에 적용하기는 어렵다.

### 무엇을 해결하는가

Agents SDK 예제를 단순 생성하는 데서 끝나지 않고, Codex에게 **요구사항 분류 → 현재 공식 docs 확인 → 최소 Agent 설계 → tool/sandbox 선택 → local smoke test → eval harness → Deployment Manager 배포**라는 전체 lifecycle을 준다. 기본은 Python/`uv`/`openai-agents`이며, workspace shell/file isolation이 필요한 경우에만 `SandboxAgent`를 쓰도록 경계를 둔다. 배포 시에는 OpenAI Cookbook의 Agents SDK Deployment Manager와 `/health`, `PORT`, local-docker 같은 deployability contract까지 확인한다.

### 설치 및 사용

OpenAI 공식 curated marketplace의 plugin name이 `openai-developers`이므로 Codex CLI에서:

```bash
codex plugin add openai-developers@openai-curated
```

이 plugin에 `agents-sdk` Skill이 포함되어 있다. Agents SDK 앱 실행에는 **`OPENAI_API_KEY`**가 필요하며, Skill은 같은 plugin의 `openai-platform-api-key` Skill을 credential gate로 사용하도록 지시한다.

Python prototype의 기본 방향:

```bash
uv add openai-agents
```

배포 요청 시 local Deployment Manager와 Docker가 필요할 수 있으며 기본 target은 `local-docker`다. Skill이 사용하는 공식 참고 자료는 [Agents guide](https://developers.openai.com/api/docs/guides/agents), [Sandbox Agents guide](https://developers.openai.com/api/docs/guides/agents/sandboxes), [Agent evals](https://developers.openai.com/api/docs/guides/agent-evals), [openai-agents-python](https://github.com/openai/openai-agents-python), [Deployment Manager](https://github.com/openai/openai-cookbook/tree/main/examples/agents_sdk/deployment_manager)다.

**Agent에게 줄 예시**

> 이 Python repo에 고객 문의를 분류하고 필요한 경우 내부 조회 function_tool을 호출하는 최소 Agents SDK 앱을 추가해줘. 우선 단일 Agent로 시작하고, 실제 agent path를 통과하는 eval 5개를 만든 뒤 local smoke test까지 통과시켜. 배포는 아직 하지 마.

**오늘 볼 가치:** OpenAI가 Skill을 단독 markdown으로만 배포하기보다 **plugin 안에 Skill + MCP/App/credential/deploy workflow를 묶는 방향**을 공식 repository에서 보여준다는 점이 중요하다. 단, 현재 공식 distribution은 Codex 중심이고 API 사용에는 별도 credential/비용이 따른다.

### 🏆 오늘의 Top Pick

**`manage-skills`**

Skill 수가 적을 때는 `npx skills add`만으로 충분하지만, 여러 Agent와 여러 프로젝트를 병행하면 source provenance, update, 배포 대상, preset, tag, backup/sync가 별도 운영 문제로 바뀐다. `manage-skills`는 이 문제를 중앙 library + SQLite metadata + shared Rust core + CLI/GUI로 해결하고, Codex/Claude Code/OpenCode/Hermes Agent 등을 한 상태 모델에서 다룬다. **4.2K+ Stars와 바로 전날까지의 활발한 push**도 단순 아이디어가 아니라 실제 사용되는 운영 계층이라는 신호다.

## 오늘 보이는 Skill 생태계 흐름

오늘 후보들의 공통점은 **Skill이 단순한 prompt 조각에서 ‘Agent capability 운영 계층’으로 이동하고 있다는 것**이다. `find-skills`는 발견, `manage-skills`는 lifecycle/deployment, `api-gateway`는 managed auth integration, `openclaw-changelog-update`는 deterministic release verification, OpenAI `agents-sdk`는 Skill을 plugin·credential·eval·deployment와 묶는다. 앞으로 경쟁력 있는 Skill은 “무엇을 하라고 설명하는 Markdown”보다 **상태·검증·권한·도구·배포 경계까지 정의하는 실행 가능한 운영 계약**에 가까워질 가능성이 크다.
