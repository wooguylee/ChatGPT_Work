### 설치 및 사용
```bash
npx skills add https://github.com/pedrohcgs/claude-code-my-workflow --skill blast-radius
```
별도 API Key나 MCP는 필요하지 않다. 다만 실제 consumer 실행을 위해 프로젝트의 테스트·빌드·스크립트 도구가 정상 구성되어 있어야 한다.

**활용 예시**
> 이 함수 반환값에 새 필드를 추가하기 전에 모든 consumer와 positional assumption을 찾고, 변경 후 각 consumer를 실제로 실행해서 기존 결과와 diff까지 검증해줘.

**평가:** 타입체크가 잡지 못하는 “조용한 계약 파괴”를 직접 겨냥해 일반 개발 workflow에 매우 잘 맞는다. 대형 multi-repo 시스템에서는 consumer 전수 실행과 SHA 재고정 때문에 시간이 늘어날 수 있다.

### 내용 설명
GateGuard는 Agent가 바로 Edit/Write/Bash를 실행하지 못하게 하고, 첫 시도에서 **DENY → 필요한 사실 조사 FORCE → 근거가 모이면 ALLOW**의 3단계를 거치게 하는 PreToolUse guardrail이다. 예를 들어 파일 수정 전에는 모든 importer, 영향받는 public symbol, 관련 data schema/date format을 찾게 하고, destructive Bash 전에는 변경/삭제 대상과 rollback 방법을 적게 한다. 단순히 “정말 확실해?”라고 자기평가를 시키는 대신 실제 Grep/Read 조사를 강제한다는 점이 차별점이다. upstream은 자체 A/B 테스트 두 건에서 gated agent 평균 9.0/10, ungated 6.75/10(+2.25)을 보고하지만 이는 **프로젝트 자체 benchmark**이므로 독립 검증 결과로 보기는 어렵다.

### 설치 및 사용
AgentSkill.sh 방식:
```bash
npx @agentskill.sh/cli@latest setup
```
그 뒤 Agent에서:
```text
/learn @affaan-m/gateguard
```
AgentSkill API가 안내하는 설치 위치 예시는 Codex `~/.codex/skills/affaan-m/gateguard/SKILL.md`, Claude Code `~/.claude/skills/affaan-m/gateguard/SKILL.md`다.

ECC의 hook/config까지 쓰는 패키지 방식:
```bash
pip install gateguard-ai
gateguard init
```
이 방식은 `.gateguard.yml`을 만들고 ECC의 `scripts/hooks/gateguard-fact-force.js` 계열 동작을 활용한다. 단, **PreToolUse hook의 실제 차단 semantics는 Agent runtime마다 다르므로** Codex에서는 동일한 강제력이 보장되지 않고 instruction-level Skill로 동작할 가능성을 고려해야 한다.

**활용 예시**
> 이 모듈을 수정하기 전에 모든 importer, 공개 인터페이스, 입력 데이터 schema를 실제로 확인하고, 근거가 모일 때까지 편집하지 마. 삭제성 명령이 필요하면 영향 범위와 rollback부터 보여줘.

**평가:** 2026-08-30에도 갱신된 활발한 프로젝트이고 “생각해보고 수정”이 아니라 **조사를 tool gate로 강제**한다는 점에서 오늘 후보 중 가장 구조적으로 새롭다. 다만 가장 강한 기능은 hook runtime에 의존한다.

이 Skill은 발견된 취약점을 하나씩 patch하는 대신, 여러 finding·incident·PoC·source evidence를 **invariant, trust boundary, control owner, dangerous capability** 기준으로 묶어 구조적 hardening 기회를 찾는다. 현재 구조 + 강한 local control을 baseline으로 두고 capability 축소, privilege separation, 중앙 정책 판단점, state machine redesign 같은 서로 다른 설계 옵션을 비교하며, 보안 효과뿐 아니라 성능·메모리·운영 복잡도·호환성·rollback까지 평가한다. evidence를 read-only canonical input으로 유지하고 hardening 분석과 실제 구현을 분리하며, 구현은 사용자가 옵션을 선택하고 명시적으로 요청한 뒤에만 진행한다.

### 설치 및 사용
현재 공식 `openai/plugins` marketplace에서 `codex-security` plugin의 skill로 제공된다.

Codex에서:
```text

```
→ **Codex official** marketplace → **codex-security** 설치/활성화.

별도 shell install 명령은 공식 metadata에서 확인되지 않아 추측해 적지 않는다. Plugin은 skills 외에도 app/MCP surface를 포함하며 authentication은 사용 시점(`ON_USE`)에 요구될 수 있다.

**활용 예시**
> 이 security finding 세트를 바로 고치지 말고 공통 원인을 만드는 trust boundary를 찾아 구조적 hardening 옵션들을 비교해줘. 각 옵션의 성능·호환성·운영비용·migration·rollback과 residual risk까지 포함해 제안서를 만들어줘.

**평가:** 단순 보안 체크리스트가 아니라 evidence → architectural diagnosis → options → trade-off → implementation handoff로 이어지는 공식적인 설계 workflow라는 점이 강하다. 단일·저위험 버그 하나를 고치는 상황에는 지나치게 무겁다.

### 🏆 오늘의 Top Pick

**gateguard**

이유: Agent 품질 문제를 더 긴 prompt로 해결하지 않고, **편집·명령 실행 직전에 실제 사실 수집을 강제하는 control plane**으로 바꾼 점이 가장 독창적이다. 2026-08-30까지 소스가 갱신되었고, import graph·schema·rollback을 확인하게 만드는 방식은 규모가 큰 코드베이스에서 hallucination성 수정과 파괴적 명령 위험을 동시에 줄일 가능성이 높다. 다만 upstream 자체 benchmark는 독립 검증이 아니며, hook 강제력은 Agent runtime별로 다르다는 점을 전제로 평가했다.

### 오늘 보이는 공통 흐름

오늘 후보들의 공통점은 Skill이 단순한 “좋은 코드를 써라” 지침에서 **행동을 구조화하고 검증을 강제하는 실행 프로토콜**로 이동하고 있다는 것이다. `gateguard`는 변경 전에 evidence를 강제하고, `blast-radius`는 변경 뒤 consumer 실행을 강제하며, `delegate-to-claude-code`는 모델 간 위임에 worktree·세션·독립 검증을 붙이고, OpenAI의 `codex-security`는 skills + app + MCP를 하나의 plugin bundle로 묶는다. 즉 앞으로의 Agent Skill 경쟁력은 prompt 문구 자체보다 **언제 어떤 tool을 쓰게 하고, 무엇을 증거로 남기며, 실패/중단/권한 경계를 어떻게 운영 절차로 만든느냐**에 더 크게 좌우될 가능성이 보인다.
