## 1. review-fix-address-bots

- **출처:** skills.sh
- **GitHub:** https://github.com/biw/skills
- **당시 지표:** Hot #4, 약 86 installs, 소규모 repo. 일부 보안 검사 Warn.

여러 AI reviewer가 diff, history, test 결과를 읽고 의견을 내되 직접 코드를 수정하지 못하게 합니다. Primary Agent 한 명만 실제 수정, Git 작업, PR 댓글, 최종 판단을 맡아 권한 충돌을 줄입니다.

### 설치

```bash
npx skills add https://github.com/biw/skills --skill review-fix-address-bots
```

**활용 예:** "이 PR을 여러 reviewer 관점에서 검토하되 reviewer는 코드를 건드리지 말고 최종 수정은 Codex 한 명만 수행해."

**왜 볼 가치가 있었나:** Multi-agent 환경에서 변경 권한과 책임을 분리하는 실용적인 패턴.

## 2. system-atlas

- **출처:** skills.sh
- **GitHub:** https://github.com/inkboard/system-atlas
- **당시 지표:** Hot #56, 당시 신규 상승, 약 14 installs, 주요 보안 감사 Pass.

시스템 구조를 하나의 데이터 소스로 관리하고 여기에서 사람이 보기 좋은 시각적 시스템 지도와 Agent가 읽기 좋은 `SYSTEM.md`를 동시에 생성하는 접근입니다. 아키텍처 그림과 문서가 서로 달라지는 문제를 줄이는 것이 목적입니다.

### 설치

```bash
npx skills add https://github.com/inkboard/system-atlas --skill system-atlas
```

**활용 예:** "Front → API → Queue → Worker → PostgreSQL 흐름을 Atlas로 만들고 결정사항과 미해결 질문도 같이 관리해."

**왜 볼 가치가 있었나:** 사람용 아키텍처 시각화와 Agent용 시스템 컨텍스트를 단일 원본으로 동기화.

## 3. observability-and-instrumentation

- **출처:** SkillsMP
- **GitHub:** https://github.com/addyosmani/agent-skills
- **당시 지표:** repo 약 86,779★ / 9,323 forks, 8월 초 업데이트.

기능을 만든 뒤 나중에 로그를 추가하는 대신 개발 초기부터 로그, 메트릭, 분산 트레이싱, 알림을 함께 설계하게 합니다. metrics는 문제가 있는지, trace는 어디인지, log는 왜 발생했는지를 설명하는 역할 분리를 강조합니다.

### 설치

```bash
npx skills add https://github.com/addyosmani/agent-skills --skill observability-and-instrumentation
```

**활용 예:** "새 Koa API의 결제 요청에 correlation ID, RED metrics, p95/p99 latency, structured log를 적용해 장애 요청을 끝까지 추적할 수 있게 해."

**왜 볼 가치가 있었나:** Agent 코딩의 완료 기준을 '테스트 통과'에서 '운영 중 설명 가능'까지 확장.

## 4. avoid-ai-writing

- **출처:** SkillsMP
- **GitHub:** https://github.com/conorbronsdon/avoid-ai-writing
- **당시 지표:** repo 약 3,041★ / 278 forks, 8월 중 업데이트.

과도한 강조, 반복적 문장 구조, 형식적 연결어 등 AI 글에서 자주 보이는 패턴을 찾아 최소 수정하는 Skill입니다. 패턴은 어디까지나 신호일 뿐 사람/AI를 판정하는 증거가 아니라고 명시하며, 원래 작성자의 technical/warm/blunt 같은 voice profile을 보존하는 방향입니다.

### 설치

```bash
npx skills add https://github.com/conorbronsdon/avoid-ai-writing --skill avoid-ai-writing
```

**활용 예:** "이 README의 technical voice는 유지하고 AI가 쓴 티가 강한 표현만 최소 수정해."

**왜 볼 가치가 있었나:** Agent 산출물을 다시 사람다운 문체로 다듬는 후처리 Skill 영역의 성장 사례.

## 5. spike

- **출처:** AgentSkill.sh
- **GitHub:** https://github.com/openclaw/openclaw
- **당시 지표:** Quality 92/100, Security 100/100.

정식 기능을 바로 구현하지 않고 가장 위험한 가정을 작은 실험으로 먼저 검증하는 Skill입니다. 결과를 VALIDATED / PARTIAL / INVALIDATED로 분류하고 실패한 실험도 중요한 증거로 취급합니다.

### 설치

```bash
npx skills add openclaw/openclaw --skill spike
```

**활용 예:** "PostgreSQL logical replication으로 NAS 두 대 이중화가 가능한지 정식 구축 전에 최소 spike로 장애 전환까지 검증해."

**왜 볼 가치가 있었나:** Codex가 수천 줄 구현부터 시작하는 것을 막고 가장 위험한 가설을 먼저 증명하게 함.

- **당시 지표:** OpenAI Skills repo 약 25.1K★, Skill 약 2.2K installs로 집계.

API 문서, OpenAPI, SDK, curl 예제를 읽고 Codex가 여러 프로젝트에서 반복 사용할 수 있는 안정적인 CLI를 만들도록 하는 Skill입니다. `--json`, exit code, read/write 명령 분리, 인증 처리, companion Skill 등 Agent 친화적인 CLI 계약을 강조합니다.

### 설치

```bash
npx skills add openai/skills --skill cli-creator
```

**활용 예:** "우리 사내 REST API 문서를 읽고 Codex가 어디서든 호출할 수 있는 `mycompany` CLI를 만들어. JSON 출력과 읽기/쓰기 명령 분리를 지원해."

**왜 볼 가치가 있었나:** 반복 내부 업무에서는 MCP보다 작고 디버깅하기 쉬운 CLI + Skill 조합이 더 적합할 수 있음을 보여줌.
